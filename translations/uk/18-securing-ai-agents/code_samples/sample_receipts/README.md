# Приклади квитанцій

Три попередньо згенеровані файли квитанцій для ознайомлення без запуску блокнота.

| Файл | Що це таке |
|---|---|
| `01_valid_receipt.json` | Дійсна підписана квитанція для виклику інструменту `lookup_flights`. Перевірка повертає True. |
| `02_tampered_receipt.json` | Та сама квитанція з одним полем, зміненим після підписання. Перевірка повертає False. |
| `03_chain_three_receipts.json` | Ланцюг із трьох дійсних квитанцій (пошук, резервування, бронювання) з `previous_receipt_hash`, що пов'язує кожну з попередньою. |

Приклади підписують канонічні байти JCS корисного навантаження безпосередньо за допомогою Ed25519.
SHA-256 залишається у використанні для дайджестів вмісту та посилань у ланцюжку квитанцій, а не як
додатковий передхеш перед підписанням.

## Перевірка прикладів

У блокноті описано перевірку у чотирьох розділах. Щоб перевірити ці приклади
безпосередньо, не проходячи оповідь блокнота:

```python
import json
from pathlib import Path

# Припускається, що ви завершили імпорти та допоміжні функції
# з розділів 1 та 2 файлу 18-signed-receipts.ipynb.

valid = json.loads(Path("01_valid_receipt.json").read_text())
print(f"Valid receipt: {verify_receipt(valid)}")        # Правда

tampered = json.loads(Path("02_tampered_receipt.json").read_text())
print(f"Tampered receipt: {verify_receipt(tampered)}")  # Хибно

chain = json.loads(Path("03_chain_three_receipts.json").read_text())
for r in verify_chain(chain):
    print(f"  Receipt {r['index']} ({r['tool']}): {'VALID' if r['overall_valid'] else 'INVALID'}")
```

## Як їх було згенеровано

Приклади використовують той самий код, що і блокнот, з одним фіксованим ключем підпису
та фіксованими часовими мітками для відтворюваності байтів. Щоб згенерувати повторно:

```bash
python3 generate_fixtures.py
```

(Сценарій знаходиться у `generate_fixtures.py` у цій директорії.)

## Що студенти дізнаються, переглядаючи сирий JSON

Ознайомлення з сирим форматом квитанції допомагає інтуїції, якої іноді не вистачає у клітинках блокнота.
Студенти, які швидко переглядають JSON, часто помічають:

1. Підпис — це непрозорий рядок у форматі base64url, але всі інші поля — звичайний читаємий JSON.
   Підпис не шифрує вміст; він лише підтверджує його.
2. `public_key` вбудовано у квитанцію. Аудитору нічого іншого не треба
   щоб перевірити (за умови довіри, що ключ дійсно належить заявленому
   видавцю; див. README уроку про інфраструктуру ідентичності).
3. Зміна одного символу в будь-якому полі, а потім порівняння цього файлу з
   `02_tampered_receipt.json`, робить механізм на рівні байтів більш наочним.
