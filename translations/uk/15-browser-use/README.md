# Створення агентів використання комп’ютера (CUA)

Агенти використання комп’ютера можуть взаємодіяти з вебсайтами так само, як і людина: відкриваючи браузер, оглядаючи сторінку і виконуючи найкращу наступну дію на основі побаченого. У цьому уроці ви створите агента автоматизації браузера, який шукає на Airbnb, витягує структуровані дані про оголошення та визначає найдешевше проживання у Стокгольмі.

Урок поєднує Browser-Use для навігації на основі ШІ, Playwright і протокол Chrome DevTools (CDP) для контролю браузера, Azure OpenAI для логіки з підтримкою зору, а також Pydantic для структурованого вилучення.

## Вступ

У цьому уроці буде розглянуто:

- Розуміння, коли агенти використання комп’ютера кращі за автоматизацію виключно через API
- Поєднання Browser-Use з Playwright і CDP для надійного управління життєвим циклом браузера
- Використання Azure OpenAI з оглядом і структурованим виводом Pydantic для вилучення даних оголошень із динамічних вебсторінок
- Визначення, коли застосовувати автоматизацію браузера на базі агента, актора або гібридну схему

## Цілі навчання

Після завершення цього уроку ви знатимете, як:

- Налаштувати Browser-Use з Azure OpenAI і Playwright
- Побудувати робочий процес автоматизації браузера, що навігує реальним сайтом і працює з динамічними елементами інтерфейсу
- Витягувати типізовані результати з видимого вмісту сторінки та перетворювати їх на бізнес-логіку
- Обирати між патернами агента і актора на основі передбачуваності завдання у браузері

## Приклад коду

У цьому уроці показано один ноутбук-туторіал:

- [15-browser-user.ipynb](./15-browser-user.ipynb): Запускає сесію Chrome через CDP, шукає оголошення Airbnb у Стокгольмі, витягує ціни з допомогою Browser-Use vision і повертає найдешевший варіант у вигляді структурованих даних.

## Вимоги

- Python 3.12+
- Налаштований розгортання Azure OpenAI у вашому середовищі
- Локально встановлений Chrome або Chromium
- Встановлені залежності Playwright
- Базове знайомство з async Python

## Налаштування

Встановіть пакети, що використовуються в ноутбуці:

```bash
pip install browser_use playwright python-dotenv
playwright install chromium
```

Встановіть змінні середовища Azure OpenAI, які використовуються в ноутбуці:

```bash
AZURE_OPENAI_ENDPOINT=...
AZURE_OPENAI_API_KEY=...
AZURE_OPENAI_CHAT_DEPLOYMENT_NAME=...
# Необов’язково: за замовчуванням використовується остання версія API, якщо не вказано
AZURE_OPENAI_API_VERSION=...
```

## Огляд архітектури

Ноутбук демонструє гібридний робочий процес автоматизації браузера:

1. Chrome запускається з увімкненим CDP, щоб і Playwright, і Browser-Use могли використовувати одну сесію браузера.
2. Агент Browser-Use вирішує завдання відкритої навігації, такі як відкриття Airbnb, закриття спливаючих вікон і пошук Стокгольма.
3. Активна сторінка оглядається за допомогою структурованої схеми Pydantic для вилучення назв оголошень, цін за ніч, оцінок і URL.
4. Логіка Python порівнює вилучені оголошення і виділяє найдешевший результат.

Цей підхід зберігає гнучке логічне мислення на основі зору, яким славиться Browser-Use, одночасно даючи вам детермінований контроль браузера, коли це потрібно.

## Основні висновки та найкращі практики

### Коли використовувати агента чи актора

| Сценарій | Використовувати агента | Використовувати актора |
|----------|--------------------|-------------------|
| Динамічні макети | Так, ШІ може адаптуватися до змін сторінки | Ні, крихкі селектори можуть ламатися |
| Відома структура | Ні, агент повільніший за прямий контроль | Так, швидко і точно |
| Пошук елементів | Так, природна мова працює добре | Ні, потрібні точні селектори |
| Управління часом | Ні, менш передбачуваний | Так, повний контроль над затримками і повторними спробами |
| Складні робочі процеси | Так, справляється з несподіваними станами UI | Ні, потребує явних гілок |

### Найкращі практики Browser-Use

1. Починайте з агента для дослідження і динамічної навігації.
2. Перейдіть до прямого контролю сторінки, коли взаємодія стає передбачуваною.
3. Використовуйте структуровані моделі виводу, щоб дані були валідованими та типобезпечними.
4. Додавайте затримки стратегічно після дій, що викликають видимі зміни інтерфейсу.
5. Робіть скріншоти під час ітерацій, щоб легше було налагоджувати помилки.
6. Очікуйте змін на сайтах і проектуйте запасні стратегії для спливаючих вікон і змін макетів.
7. Поєднуйте патерни агента і актора, щоб отримати і гнучкість, і точність.

### Приклади з реального життя

- Бронювання подорожей і моніторинг цін
- Порівняння цін в електронній комерції і перевірка наявності
- Структуроване вилучення з динамічних вебсайтів
- Тестування і верифікація UI з урахуванням зору
- Моніторинг і оповіщення сайтів
- Інтелектуальне заповнення форм у багатокрокових процесах

## Приклад із реального життя: Microsoft Project Opal

Агент, якого ви створите в цьому уроці, є невеликою локальною версією **агента використання комп’ютера (CUA)** — програми, що керує браузером так, як це зробила б людина. Microsoft втілює цю ідею для підприємств у вигляді **[Project Opal (Frontier)](https://support.microsoft.com/en-us/microsoft-365-copilot/get-started-with-project-opal-frontier)**, функціоналу Microsoft 365 Copilot.

З Project Opal ви описуєте завдання, і агент працює від вашого імені, використовуючи **використання комп’ютера на безпечному Windows 365 Cloud PC**, оперуючи у браузерних додатках, сайтах і даних вашої організації. Він працює **асинхронно у фоновому режимі**, і ви можете керувати роботою або взяти контроль у будь-який момент. Приклади завдань:

- Керування запитами на членство в групах безпеки
- Збирання та перевірка аудиторських доказів для ревізій відповідності
- Обробка IT-інцидентів (оновлення статусу заявок, призначення відповідальних, закриття дублікатів)
- Формування фінансового звіту з даних Excel

Opal є корисною ілюстрацією того, як виглядає **промисловий, надійний** агент використання комп’ютера — і підсилює концепції з попередніх уроків:

| Концепція в цьому курсі | Як це реалізовано в Project Opal |
|-----------------------------|-----------------------------|
| **Людина в циклі** (Урок 06) | Opal зупиняється для вводу облікових даних, конфіденційних даних або неоднозначних інструкцій, і ніколи не вводить паролі чи не надсилає форми без явного підтвердження. Ви можете *Взяти контроль* і *Повернути контроль* у процесі завдання. |
| **Надійні і безпечні агенти** (Уроки 06 і 18) | Працює в ізольованому Windows 365 Cloud PC, за замовчуванням лише браузер (інший доступ до комп’ютера заблокований через Intune), використовує *вашу* ідентичність, тому доступ до даних обмежений вашими правами, і веде лог кожної дії для аудиту. |
| **Планування та метакогніція** (Уроки 07 і 09) | Opal спочатку генерує план виконання, потім контролює своє мислення на кожному кроці і зупиняється при підозрілих діях. |
| **Повторно використовувані навички / інструменти** (Урок 04) | **Навички** дозволяють писати інструкції для повторюваних завдань (імпортованих із `.md` файлу або створених у Opal) і використовувати їх у різних розмовах. |

> **Доступність:** Project Opal наразі доступний користувачам у [програмі раннього доступу Frontier](https://adoption.microsoft.com/copilot/frontier-program/) з підпискою Microsoft 365 Copilot, і для нього має бути завершено налаштування адміністратором. Через експериментальний характер Frontier функції можуть змінюватися з часом.
