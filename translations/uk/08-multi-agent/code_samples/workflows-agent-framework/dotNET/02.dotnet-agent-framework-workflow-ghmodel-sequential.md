# ⏩ Послідовні робочі процеси агентів з Azure OpenAI (Responses API) (.NET)

## 📋 Поглиблений навчальний посібник з послідовної обробки

У цьому записнику демонструються **патерни послідовних робочих процесів** із використанням Microsoft Agent Framework для .NET та Azure OpenAI (Responses API). Ви навчитеся будувати складні покрокові процеси, в яких агенти виконуються у певному порядку, і кожен етап базується на результатах попереднього.

## 🎯 Навчальні цілі

### 🔄 **Архітектура послідовної обробки**
- **Лінійний дизайн робочого процесу**: Створення покрокових процесів із чіткими залежностями
- **Управління станом**: Підтримка контексту та потоку даних через послідовні етапи робочого процесу
- **Azure OpenAI (Responses API)**: Використання моделей Azure OpenAI у багатоступеневих .NET робочих процесах
- **Патерни виробничих конвеєрів**: Побудова виробничих систем послідовної обробки

### 🏗️ **Поглиблені послідовні патерни**
- **Обробка з контрольними точками (Stage-Gate)**: Виконання перевірок між етапами робочого процесу
- **Збереження контексту**: Підтримка стану та накопичених знань на всіх етапах
- **Передача помилок**: Коректна обробка збоїв у ланцюгах послідовної обробки
- **Оптимізація продуктивності**: Ефективне послідовне виконання з мінімальними накладними витратами

### 🏢 **Підприємницькі послідовні додатки**
- **Конвеєр обробки документів**: Багатоступенева аналітика, трансформація та перевірка документів
- **Робочі процеси контролю якості**: Послідовний перегляд, перевірка та затвердження
- **Конвеєр створення контенту**: Дослідження → Написання → Редагування → Перегляд → Публікація
- **Автоматизація бізнес-процесів**: Багатоступеневі бізнес-процеси з чіткими залежностями між етапами

<!-- Local Agent Framework References -->

<!-- Microsoft.Agents.AI.OpenAI.dll - Azure OpenAI (Responses API) integration -->
```

AZURE_OPENAI_DEPLOYMENT=gpt-4o-mini
```

**Управління конфігурацією:**
```csharp
// Load environment variables securely
Env.Load("../../../.env");
var azureEndpoint = Environment.GetEnvironmentVariable("AZURE_OPENAI_ENDPOINT");
var deployment = Environment.GetEnvironmentVariable("AZURE_OPENAI_DEPLOYMENT");
```

### 🏗️ **Архітектура послідовного робочого процесу**

```mermaid
graph TD
    A[Initial Input] --> B[Stage 1: Агент аналізу]
    B --> C[Контрольна точка 1]
    C --> D[Stage 2: Агент обробки]
    D --> E[Контрольна точка 2]
    E --> F[Stage 3: Агент перевірки]
    F --> G[Остаточний результат]
    
    H[Контекст стану] --> B
    H --> D
    H --> F
    
    I[Azure OpenAI (API відповідей)] --> B
    I --> D
    I --> F
```

**Основні компоненти:**
- **Послідовні агенти**: Спеціалізовані агенти для кожного етапу обробки
- **Контекст стану**: Підтримує накопичені дані та рішення на різних етапах
- **Контрольні точки**: Пункти перевірки між етапами для забезпечення якості та послідовності
- **Клієнт Azure OpenAI**: Сталій доступ до моделей ШІ на всіх етапах робочого процесу

## 🏢 **Переваги підприємницьких послідовних систем**

- **Журнали аудиту**: Повний облік рішень та трансформацій на кожному етапі

- **Оптимізація стану**: Мінімальна передача стану між етапами для кращої продуктивності
- **Паралельні групи етапів**: Кілька послідовних робочих процесів можуть виконуватися паралельно

### 🔒 **Безпека і відповідність**
- **Безпека на рівні етапів**: Різні політики безпеки для різних етапів обробки
- **Валідація даних**: Забезпечення цілісності даних і відповідності на кожній контрольній точці
- **Контроль доступу**: Гранульовані дозволи для різних етапів робочого процесу
- **Відповідність нормативним вимогам**: Виконання вимог регуляторів через структуровану обробку

### 📊 **Моніторинг і аналітика**
- **Метрики на рівні етапів**: Моніторинг продуктивності кожного етапу робочого процесу
- **Виявлення вузьких місць**: Визначення та оптимізація повільних етапів
- **Метрики якості**: Відстеження якості та рівня успіху на кожному етапі
- **Оптимізація процесу**: Постійне покращення на основі аналітики по етапах

## 💻 Запуск коду

Повна реалізація доступна у файлі `02.dotnet-agent-framework-workflow-ghmodel-sequential.cs`. Цей файл демонструє **трьохетапний робочий процес аналізу меблів**:

1. **Етап 1 - Агент продажів**: Аналізує зображення меблів і пропонує варіанти покупки
2. **Етап 2 - Агент ціноутворення**: Надає детальний розподіл цін та бюджетні варіанти
3. **Етап 3 - Агент комерційної пропозиції**: Генерує професійний документ з комерційною пропозицією у форматі Markdown

### 🏗️ **Архітектура робочого процесу**

```
Image Input → Sales Analysis → Price Estimation → Quote Generation → Final Output
```

Кожен агент:
- Отримує результат з попереднього етапу як контекст
- Розвиває попередній аналіз із спеціалізованою експертизою
- Підтримує неперервність робочого процесу за допомогою управління станом

### 📝 Очікуваний результат

Робочий процес:
1. **Агент продажів**: Визначає меблі на зображенні і надає рекомендації
2. **Агент ціноутворення**: Додає детальний аналіз цін з рівнями бюджету та рекомендаціями для покупок
3. **Агент комерційної пропозиції**: Генерує відформатований документ з комерційною пропозицією, що об’єднує всю інформацію

### 🔍 Розуміння потоку станів

Кожний агент у послідовності отримує:
- **Початковий ввід**: Початкове повідомлення користувача (зображення + текст)
- **Вивід попередніх агентів**: Всі відповіді попередніх агентів у історії розмови
- **Накопичений контекст**: Повний стан, який підтримується протягом усього робочого процесу

Це дозволяє виконувати складну багатоступеневу обробку, де кожен агент базується на всебічному контексті з усіх попередніх етапів.
