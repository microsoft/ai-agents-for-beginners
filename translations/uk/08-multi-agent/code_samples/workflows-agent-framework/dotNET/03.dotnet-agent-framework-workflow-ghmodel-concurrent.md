# ⚡ Паралельні робочі процеси агентів з Azure OpenAI (Responses API) (.NET)

## 📋 Підручник з високопродуктивної паралельної обробки

У цьому ноутбуці демонструються **паралельні патерни робочих процесів** із використанням Microsoft Agent Framework для .NET та Azure OpenAI (Responses API). Ви навчитеся створювати високопродуктивні робочі процеси паралельної обробки, які максимізують пропускну здатність, виконуючи декілька AI-агентів одночасно при збереженні координації та узгодженості даних.

## 🎯 Цілі навчання

### 🚀 **Основи паралельної обробки**
- **Паралельне виконання агентів**: Запуск кількох AI агентів одночасно для максимальної продуктивності
- **Async/Await патерни**: Використання асинхронної моделі програмування .NET для ефективної конкурентності
- **Azure OpenAI (Responses API)**: Координація кількох паралельних викликів Responses API Azure OpenAI
- **Управління ресурсами**: Ефективне управління ресурсами моделей AI у конкурентних операціях

### 🏗️ **Розвинена архітектура конкурентності**
- **Паралелізм на основі задач**: Використання .NET Task Parallel Library для оптимального конкурентного виконання
- **Патерни синхронізації**: Координація паралельних агентів із запобіганням станам гонитви
- **Балансування навантаження**: Ефективний розподіл роботи на доступну потужність паралельної обробки
- **Відмовостійкість**: Обробка збоїв окремих агентів без зупинки всього робочого процесу

### 🏢 **Паралельні підприємницькі застосунки**

## 💻 Запуск коду

Повна реалізація доступна у `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Цей файл демонструє **Fan-Out/Fan-In паралельний робочий процес** для планування подорожей:

### 🏗️ **Архітектура робочого процесу**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Основні компоненти:**

1. **ConcurrentStartExecutor**: Одночасна трансляція запиту користувача усім агентам
2. **Researcher Agent**: Паралельний аналіз напрямків і визначних місць
3. **Planner Agent**: Паралельне створення детальних планів подорожей
4. **ConcurrentAggregationExecutor**: Збір та об'єднання результатів від обох агентів

### 🎯 **Патерн Fan-Out/Fan-In**

Цей робочий процес демонструє класичний патерн **Fan-Out/Fan-In**:
- **Fan-Out**: Одне вхідне повідомлення транслюється одночасно кільком агентам
- **Паралельна обробка**: Кілька агентів працюють одночасно над одним завданням
- **Fan-In**: Результати від усіх агентів збираються та агрегуються в один вихід

### 🔍 Розуміння користувацьких виконавців (executors)

**ConcurrentStartExecutor:**
- Реалізує `IMessageHandler<string>` для прийому рядкового вхідного повідомлення
- Транслює повідомлення всім підключеним агентам
- Надсилає `TurnToken` для запуску паралельної обробки

**ConcurrentAggregationExecutor:**
- Реалізує `IMessageHandler<ChatMessage>` для отримання відповідей агентів
- Збирає повідомлення в потокобезпечному режимі
- Агрегує, коли всі очікувані відповіді отримані
- Повертає кінцевий результат через `context.YieldOutputAsync()`

### ⚡ Переваги продуктивності

**Паралельне vs послідовне:**
- Послідовно: Agent1 (30с) → Agent2 (30с) = **60 секунд всього**
- Паралельно: Agent1 (30с) || Agent2 (30с) = **30 секунд всього**

**Покращення пропускної здатності**: До N× швидше для N паралельних агентів (залежно від навантаження та ресурсів)

### 🛡️ Обробка помилок

Робочий процес легко обробляє збої окремих агентів:
- Якщо один агент виходить з ладу, інші продовжують роботу
- Агрегатор може впроваджувати тайм-аут логіку
- Часткові результати можуть повертатися за потреби
