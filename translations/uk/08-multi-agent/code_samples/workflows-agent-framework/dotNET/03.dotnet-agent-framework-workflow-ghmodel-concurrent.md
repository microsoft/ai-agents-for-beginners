# ⚡ Паралельні робочі процеси агентів з Azure OpenAI (Responses API) (.NET)

## 📋 Посібник з високопродуктивної паралельної обробки

У цьому нотатнику демонструються **патерни паралельних робочих процесів** із використанням Microsoft Agent Framework для .NET та Azure OpenAI (Responses API). Ви навчитеся будувати високопродуктивні, паралельні робочі процеси, які максимізують пропускну здатність за рахунок одночасного виконання кількох AI агентів з підтриманням координації та консистентності даних.

## 🎯 Навчальні цілі

### 🚀 **Основи паралельної обробки**
- **Паралельне виконання агентів**: запуск кількох AI агентів одночасно для максимальної продуктивності
- **Патерни Async/Await**: використання моделі асинхронного програмування .NET для ефективної конкуренції
- **Azure OpenAI (Responses API)**: координація множинних одночасних викликів Azure OpenAI Responses API
- **Управління ресурсами**: ефективне управління ресурсами AI моделей при паралельних операціях

### 🏗️ **Розширена архітектура конкурентності**
- **Паралелізм на основі задач (Task-Based Parallelism)**: використання бібліотеки Task Parallel Library .NET для оптимального паралельного виконання
- **Патерни синхронізації**: координація паралельних агентів з уникненням станів гонки
- **Балансування навантаження**: ефективний розподіл роботи по доступних паралельних потужностях
- **Відмовостійкість**: обробка збоїв окремих агентів без зупинки всього робочого процесу

### 🏢 **Паралельні додатки для підприємств**
- **Обробка великої кількості документів**: одночасна обробка декількох документів
- **Аналіз контенту в реальному часі**: паралельний аналіз вхідних потоків даних
- **Оптимізація пакетної обробки**: максимізація пропускної здатності при масштабній обробці даних
- **Мульти-модальний аналіз**: паралельна обробка різних типів та форматів контенту

## 💻 Запуск коду

Повна реалізація доступна у файлі `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Цей файл демонструє **паралельний робочий процес Fan-Out/Fan-In** для планування подорожей:

### 🏗️ **Архітектура робочого процесу**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Ключові компоненти:**

1. **ConcurrentStartExecutor**: одночасно транслює запит користувача всім агентам
2. **Агент-дослідник**: одночасно аналізує напрямки та атракції
3. **Агент-планувальник**: одночасно створює детальні плани подорожей
4. **ConcurrentAggregationExecutor**: збирає та об’єднує результати обох агентів

### 🎯 **Патерн Fan-Out/Fan-In**

Цей робочий процес демонструє класичний патерн **Fan-Out/Fan-In**:
- **Fan-Out**: одне вхідне повідомлення транслюється одночасно багатьом агентам
- **Паралельна обробка**: кілька агентів одночасно працюють над одним завданням
- **Fan-In**: результати всіх агентів збираються та агрегуються в один вихідний результат

### 🔍 Розуміння власних виконавців (executors)

**ConcurrentStartExecutor:**
- Реалізує `IMessageHandler<string>` для прийому рядкових вхідних даних
- Транслює повідомлення усім підключеним агентам
- Надсилає `TurnToken` для запуску паралельної обробки

**ConcurrentAggregationExecutor:**
- Реалізує `IMessageHandler<ChatMessage>` для прийому відповідей агентів
- Збирає повідомлення потокобезпечним способом
- Агрегує коли отримує всі очікувані відповіді
- Віддає кінцевий результат за допомогою `context.YieldOutputAsync()`

### ⚡ Переваги продуктивності

**Паралельно vs Послідовно:**
- Послідовно: Agent1 (30с) → Agent2 (30с) = **всього 60 секунд**
- Паралельно: Agent1 (30с) || Agent2 (30с) = **всього 30 секунд**

**Покращення пропускної здатності**: до N разів швидше для N паралельних агентів (залежить від навантаження та ресурсів)

### 🛡️ Обробка помилок

Робочий процес плавно обробляє відмови окремих агентів:
- Якщо один агент зазнає збою, інші продовжують обробку

- За необхідності можуть повертатися часткові результати
