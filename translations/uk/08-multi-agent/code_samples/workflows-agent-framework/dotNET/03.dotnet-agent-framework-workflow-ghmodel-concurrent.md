# ⚡ Паралельні робочі потоки агентів з Azure OpenAI (Responses API) (.NET)

## 📋 Посібник з високопродуктивної паралельної обробки

У цьому ноутбуці демонструються **патерни паралельного виконання робочих процесів** за допомогою Microsoft Agent Framework для .NET і Azure OpenAI (Responses API). Ви дізнаєтеся, як створювати високопродуктивні робочі процеси паралельної обробки, що максимізують пропускну здатність, виконуючи кілька агентів ШІ одночасно, зберігаючи при цьому координацію та узгодженість даних.

## 🎯 Цілі навчання

### 🚀 **Основи паралельної обробки**
- **Паралельне виконання агентів**: Одночасний запуск кількох агентів ШІ для максимальної продуктивності
- **Патерни Async/Await**: Використання асинхронної моделі програмування .NET для ефективної конкуренції
- **Azure OpenAI (Responses API)**: Координація кількох одночасних викликів API відповідей Azure OpenAI
- **Управління ресурсами**: Ефективне керування ресурсами моделей ШІ під час паралельних операцій

### 🏗️ **Розвинена архітектура паралельності**
- **Паралелізм на основі завдань**: Використання Task Parallel Library .NET для оптимального паралельного виконання
- **Патерни синхронізації**: Координація одночасних агентів з уникненням станів гонки
- **Балансування навантаження**: Ефективний розподіл роботи між доступними ресурсами для паралельної обробки
- **Відмовостійкість**: Обробка збоїв окремих агентів без зупинки всього робочого процесу

### 🏢 **Конкурентні корпоративні застосунки**
- **Обробка великої кількості документів**: Одночасна обробка кількох документів
- **Аналіз в реальному часі**: Паралельний аналіз вхідних потоків даних

## 💻 Запуск коду

Повна реалізація доступна у файлі `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Цей файл демонструє **Fan-Out/Fan-In паралельний робочий процес** для планування подорожей:

### 🏗️ **Архітектура робочого процесу**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Ключові компоненти:**

1. **ConcurrentStartExecutor**: Одночасно передає запит користувача всім агентам
2. **Агент-дослідник**: Паралельно аналізує напрямки та визначні пам’ятки
3. **Агент-планувальник**: Паралельно створює детальні плани подорожі
4. **ConcurrentAggregationExecutor**: Збирає та об’єднує результати обох агентів

### 🎯 **Патерн Fan-Out/Fan-In**

Цей робочий процес демонструє класичний патерн **Fan-Out/Fan-In**:
- **Fan-Out**: Один вхідний запит транслюється одночасно кільком агентам
- **Паралельна обробка**: Кілька агентів працюють одночасно над одним завданням
- **Fan-In**: Результати від усіх агентів збираються та агрегуються в єдиний вихід

### 🔍 Розуміння кастомних виконавців

**ConcurrentStartExecutor:**
- Реалізує `IMessageHandler<string>` для прийому рядкового вводу
- Транслює повідомлення всім підключеним агентам
- Відправляє `TurnToken` для запуску паралельної обробки

**ConcurrentAggregationExecutor:**
- Реалізує `IMessageHandler<ChatMessage>` для прийому відповідей агентів
- Збирає повідомлення потокобезпечним способом
- Агрегує їх, коли надходять всі очікувані відповіді
- Повертає фінальний результат за допомогою `context.YieldOutputAsync()`

### ⚡ Переваги продуктивності

**Паралельно проти послідовного:**
- Послідовно: Agent1 (30с) → Agent2 (30с) = **усього 60 секунд**
- Паралельно: Agent1 (30с) || Agent2 (30с) = **усього 30 секунд**

**Покращення пропускної здатності**: До N× швидше для N паралельних агентів (залежно від навантаження і ресурсів)
