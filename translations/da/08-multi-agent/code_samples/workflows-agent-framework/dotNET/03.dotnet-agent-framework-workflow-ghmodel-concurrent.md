# ⚡ Samtidige Agentarbejdsgange med Azure OpenAI (Responses API) (.NET)

## 📋 Tutorial i Højtydende Parallel Behandling

Denne notesbog demonstrerer **samtidige arbejdsgangsmønstre** ved hjælp af Microsoft Agent Framework for .NET og Azure OpenAI (Responses API). Du lærer, hvordan du bygger højtydende arbejdsgange til parallel behandling, der maksimerer gennemløb ved at køre flere AI-agenter samtidig, samtidig med at der opretholdes koordinering og datakonsistens.

## 💻 Kørsel af Koden

Den komplette implementering findes i `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Denne fil demonstrerer et **Fan-Out/Fan-In samtidigt arbejdsgangsmønster** til rejseplanlægning:

### 🏗️ **Arbejdsgangsarkitektur**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Nøglekomponenter:**

1. **ConcurrentStartExecutor**: Sender brugerforespørgslen til alle agenter samtidig
2. **Researcher Agent**: Analyserer destinationer og attraktioner samtidigt
3. **Planner Agent**: Opretter detaljerede rejseplaner parallelt
4. **ConcurrentAggregationExecutor**: Samler og sammenlægger resultater fra begge agenter

### 🎯 **Fan-Out/Fan-In Mønster**

Denne arbejdsgang demonstrerer det klassiske **Fan-Out/Fan-In** mønster:
- **Fan-Out**: Én inputbesked udsendes til flere agenter samtidigt
- **Samtidig Behandling**: Flere agenter arbejder parallelt på samme opgave
- **Fan-In**: Resultater fra alle agenter indsamles og aggregeres til ét output

### 🔍 Forståelse af Brugerdefinerede Executors

**ConcurrentStartExecutor:**
- Implementerer `IMessageHandler<string>` til at modtage strenginput
- Sender beskeder til alle tilkoblede agenter
- Sender `TurnToken` for at trigge samtidig behandling

**ConcurrentAggregationExecutor:**
- Implementerer `IMessageHandler<ChatMessage>` til at modtage agentresponser
- Samler beskeder på en trådsikker måde
- Aggregerer når alle forventede svar er modtaget
- Afsender endeligt output med `context.YieldOutputAsync()`

### ⚡ Ydelsesfordele

**Samtidig vs Sekventiel:**
- Sekventiel: Agent1 (30s) → Agent2 (30s) = **60 sekunder i alt**
- Samtidig: Agent1 (30s) || Agent2 (30s) = **30 sekunder i alt**

**Forbedret gennemløb**: Op til N× hurtigere for N samtidige agenter (afhænger af arbejdsbyrde og ressourcer)
