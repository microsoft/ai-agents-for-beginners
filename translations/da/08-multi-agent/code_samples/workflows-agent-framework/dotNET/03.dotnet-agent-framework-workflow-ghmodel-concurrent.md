# ⚡ Samtidige Agentarbejdsgange med Azure OpenAI (Responses API) (.NET)

## 📋 Tutorial til højtydende parallel behandling

Denne notesbog demonstrerer **samtidige arbejdsgangsmønstre** ved hjælp af Microsoft Agent Framework for .NET og Azure OpenAI (Responses API). Du lærer at opbygge højtydende, parallelle arbejdsgange, der maksimerer gennemløb ved at køre flere AI-agenter samtidigt, samtidig med at koordinering og datakonsistens opretholdes.

## 🎯 Læringsmål

### 🚀 **Grundlæggende i samtidighed**
- **Parallelt agentkørsel**: Kør flere AI-agenter samtidigt for maksimal ydeevne

## 💻 Kørsel af koden

Den komplette implementering findes i `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Denne fil demonstrerer en **Fan-Out/Fan-In samtidig arbejdsgang** til planlægning af rejser:

### 🏗️ **Arbejdsgangsarkitektur**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Nøglekomponenter:**

1. **ConcurrentStartExecutor**: Sender brugerens forespørgsel til alle agenter samtidigt
2. **Researcher Agent**: Analyserer destinationer og attraktioner samtidigt
3. **Planner Agent**: Opretter detaljerede rejseplaner samtidigt
4. **ConcurrentAggregationExecutor**: Indsamler og sammenlægger resultater fra begge agenter

### 🎯 **Fan-Out/Fan-In mønster**

Denne arbejdsgang demonstrerer det klassiske **Fan-Out/Fan-In** mønster:
- **Fan-Out**: Én indgangsbesked sendes til flere agenter samtidigt
- **Samtidig behandling**: Flere agenter arbejder parallelt på samme opgave
- **Fan-In**: Resultater fra alle agenter indsamles og føjes sammen til én output

### 🔍 Forståelse af brugerdefinerede executors

**ConcurrentStartExecutor:**
- Implementerer `IMessageHandler<string>` til at modtage tekstinput
- Sender meddelelser til alle tilknyttede agenter
- Sender `TurnToken` for at trigge samtidig behandling

**ConcurrentAggregationExecutor:**
- Implementerer `IMessageHandler<ChatMessage>` til at modtage agentresponser
- Indsamler meddelelser på en trådsikker måde
- Sammenlægger når alle forventede svar er modtaget
- Returnerer det endelige output via `context.YieldOutputAsync()`

### ⚡ Ydelsesfordele

**Samtidig vs Sekventiel:**
- Sekventiel: Agent1 (30s) → Agent2 (30s) = **60 sekunder i alt**
- Samtidig: Agent1 (30s) || Agent2 (30s) = **30 sekunder i alt**

**Gennemløbsforbedring**: Op til N× hurtigere for N samtidige agenter (afhængig af arbejdsbyrde og ressourcer)

### 🛡️ Fejlhåndtering

Arbejdsgangen håndterer individuelle agentfejl yndefuldt:
- Hvis én agent fejler, fortsætter de andre med behandling
- Sammenlægger kan implementere timeout-logik
- Delvise resultater kan returneres hvis nødvendigt
