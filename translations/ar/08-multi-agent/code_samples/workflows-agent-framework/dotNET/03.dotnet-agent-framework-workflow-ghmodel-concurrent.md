# ⚡ تدفقات عمل الوكلاء المتزامنة مع Azure OpenAI (واجهة برمجة التطبيقات للردود) (.NET)

## 📋 درس التكرار العالي الأداء والمعالجة المتوازية

يوضح هذا الدفتر أنماط **تدفق العمل المتزامن** باستخدام إطار عمل الوكلاء من مايكروسوفت لـ .NET وAzure OpenAI (واجهة برمجة التطبيقات للردود). ستتعلم كيفية بناء تدفقات عمل معالجة متوازية عالية الأداء تزيد من الإنتاجية عبر تنفيذ عدة وكلاء ذكاء صناعي في وقت واحد مع الحفاظ على التنسيق واتساق البيانات.

## 🎯 أهداف التعلم

### 🚀 **أساسيات المعالجة المتزامنة**
- **تنفيذ الوكلاء بالتوازي**: تنفيذ عدة وكلاء ذكاء صناعي في وقت واحد لتحقيق أقصى أداء
- **أنماط Async/Await**: الاستفادة من نموذج البرمجة غير المتزامنة في .NET لتحقيق تزامن فعال
- **Azure OpenAI (واجهة برمجة التطبيقات للردود)**: تنسيق العديد من الدعوات المتزامنة إلى واجهة برمجة التطبيقات للردود في Azure OpenAI
- **إدارة الموارد**: إدارة موارد نموذج الذكاء الصناعي بكفاءة عبر العمليات المتزامنة

### 🏗️ **هيكلية التزامن المتقدمة**
- **تنفيذ بالتوازي مع المهام**: استخدام مكتبة المهام المتوازية في .NET لتحقيق تنفيذ متزامن أمثل
- **أنماط التزامن**: تنسيق الوكلاء المتزامنين مع تجنب حالات التسابق
- **توزيع الحمل**: توزيع العمل بكفاءة عبر القدرات المتاحة للمعالجة المتزامنة
- **تحمل الأخطاء**: التعامل مع أخطاء الوكلاء الأفراد دون إيقاف تدفق العمل بأكمله

### 🏢 **تطبيقات الشركات المتزامنة**
- **معالجة وثائق بالحجم الكبير**: معالجة عدة وثائق في وقت واحد
- **تحليل المحتوى في الوقت الحقيقي**: التحليل المتزامن لتدفقات البيانات الواردة
- **تحسين المعالجة الدفعية**: زيادة الإنتاجية في عمليات معالجة البيانات على نطاق واسع

## 💻 تشغيل الكود

التنفيذ الكامل متوفر في `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. يوضح هذا الملف **تدفق عمل متزامن Fan-Out/Fan-In** لتخطيط السفر:

### 🏗️ **هيكلية تدفق العمل**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**المكونات الرئيسية:**

1. **ConcurrentStartExecutor**: يبث طلب المستخدم إلى جميع الوكلاء في الوقت نفسه
2. **وكيل الباحث**: يحلل الوجهات والمعالم بالتزامن
3. **وكيل المخطط**: ينشئ خطط السفر التفصيلية بالتزامن
4. **ConcurrentAggregationExecutor**: يجمع ويدمج النتائج من كلا الوكلاء

### 🎯 **نمط Fan-Out/Fan-In**

يعرض هذا التدفق النمط الكلاسيكي **Fan-Out/Fan-In**:
- **Fan-Out**: رسالة إدخال واحدة تُبث لعدة وكلاء في الوقت ذاته
- **المعالجة المتزامنة**: يعمل عدة وكلاء بالتوازي على نفس المهمة
- **Fan-In**: تُجمع نتائج كل الوكلاء وتندمج في إخراج واحد

### 📝 النتيجة المتوقعة

سيقوم تدفق العمل بـ:
1. **بث الطلب**: إرسال "خطط رحلة إلى سياتل في ديسمبر" إلى كلا الوكلاء
2. **المعالجة المتزامنة**: يعمل الوكلاء معاً في الوقت ذاته:
   - الباحث يتعرف على المعالم والتفاصيل
   - المخطط ينشئ جدول الرحلة واللوجستيات
3. **التجميع**: دمج كل الردود في إخراج شامل
4. **عرض النتائج**: عرض خطة السفر الموحدة بكل المعلومات

### 🔍 فهم المنفذين المخصصين

**ConcurrentStartExecutor:**
- ينفذ `IMessageHandler<string>` لقبول إدخال نصي
- يبث الرسائل إلى جميع الوكلاء المتصلين
- يرسل `TurnToken` لتحفيز المعالجة المتزامنة

**ConcurrentAggregationExecutor:**
- ينفذ `IMessageHandler<ChatMessage>` لتلقي ردود الوكلاء
- يجمع الرسائل بطريقة آمنة للخيوط
- يجمع النتائج عند وصول كل الردود المتوقعة
- ينتج الإخراج النهائي باستخدام `context.YieldOutputAsync()`

### ⚡ فوائد الأداء

**المتزامن مقابل المتسلسل:**
- المتسلسل: الوكيل1 (30ث) → الوكيل2 (30ث) = **60 ثانية إجمالاً**
- المتزامن: الوكيل1 (30ث) || الوكيل2 (30ث) = **30 ثانية إجمالاً**

**تحسين الإنتاجية**: أسرع حتى N أضعاف لوكلاء N متزامنين (حسب عبء العمل والموارد)
