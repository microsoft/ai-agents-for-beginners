# ⚡ سير عمل الوكلاء المتزامنين مع Azure OpenAI (واجهة برمجة التطبيقات للردود) (.NET)

## 📋 دليل المعالجة المتوازية عالية الأداء

يعرض هذا الدفتر **نماذج سير العمل المتزامنة** باستخدام إطار عمل الوكلاء من مايكروسوفت لـ .NET و Azure OpenAI (واجهة برمجة التطبيقات للردود). ستتعلم كيفية بناء سير عمل متوازي عالي الأداء يعزز الإنتاجية من خلال تنفيذ عدة وكلاء ذكاء اصطناعي في نفس الوقت مع الحفاظ على التنسيق واتساق البيانات.

## 🎯 أهداف التعلم

### 🚀 **أساسيات المعالجة المتزامنة**
- **تنفيذ الوكلاء بالتوازي**: تشغيل عدة وكلاء ذكاء اصطناعي في الوقت ذاته لتحقيق أقصى أداء
- **نماذج Async/Await**: الاستفادة من نموذج البرمجة غير المتزامنة في .NET لتحقيق الكفاءة في التزامن
- **Azure OpenAI (واجهة برمجة التطبيقات للردود)**: تنسيق عدة طلبات متزامنة إلى واجهة برمجة تطبيقات الردود في Azure OpenAI
- **إدارة الموارد**: إدارة موارد نموذج الذكاء الاصطناعي بفعالية عبر العمليات المتزامنة

### 🏗️ **هندسة التزامن المتقدمة**
- **المعالجات المتوازية المعتمدة على المهام**: استخدام مكتبة المهام في .NET لتنفيذ متزامن مثالي
- **نماذج التزامن**: تنسيق الوكلاء المتزامنين مع تجنب حالات السباق
- **توازن الحمل**: توزيع العمل بكفاءة عبر السعة المتزامنة المتاحة
- **التحمل للأخطاء**: التعامل مع فشل وكلاء فرديين دون إيقاف سير العمل بالكامل

### 🏢 **تطبيقات المؤسسة المتزامنة**
- **معالجة مستندات عالية الحجم**: معالجة عدة مستندات في نفس الوقت

## 💻 تشغيل الكود

التنفيذ الكامل متاح في `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. هذا الملف يعرض **سير عمل متزامن بنمط Fan-Out/Fan-In** لتخطيط السفر:

### 🏗️ **هندسة سير العمل**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**المكونات الأساسية:**

1. **ConcurrentStartExecutor**: يبث طلب المستخدم إلى جميع الوكلاء في الوقت ذاته
2. **وكيل الباحث**: يحلل الوجهات والمعالم بالتزامن
3. **وكيل المخطط**: ينشئ خطط سفر مفصلة بالتزامن
4. **ConcurrentAggregationExecutor**: يجمع ويدمج نتائج الوكلاء معاً

### 🎯 **نمط Fan-Out/Fan-In**

يعرض هذا سير العمل نمط **Fan-Out/Fan-In** الكلاسيكي:
- **Fan-Out**: يتم بث رسالة مدخل واحدة لعدة وكلاء في نفس الوقت
- **المعالجة المتزامنة**: يعمل عدة وكلاء بالتوازي على نفس المهمة
- **Fan-In**: يتم جمع نتائج جميع الوكلاء ودمجها في ناتج واحد

### 🎯 التطبيقات العملية

هذا النمط المتزامن مثالي لـ:
- **إنشاء المحتوى**: عدة كتاب يكتبون أقسام مختلفة في نفس الوقت
- **مراجعة الشفرات البرمجية**: عدة مراجعين يحللون الشفرات من أوجه مختلفة
- **بحث السوق**: تحليل متوازي لقطاعات سوق مختلفة
- **معالجة المستندات**: استخراج، تحليل، والتحقق المتزامن
- **التحليل متعدد المنظورات**: الحصول على وجهات نظر متنوعة على نفس المدخل

### 🔍 فهم المشغلات المخصصة

**ConcurrentStartExecutor:**
- ينفذ `IMessageHandler<string>` لقبول مدخل نصي
- يبث الرسائل إلى جميع الوكلاء المتصلين
- يرسل `TurnToken` لتحفيز المعالجة المتزامنة

**ConcurrentAggregationExecutor:**
- ينفذ `IMessageHandler<ChatMessage>` لاستقبال ردود الوكلاء
- يجمع الرسائل بطريقة آمنة للخيوط (thread-safe)
- يجمع النتائج عند وصول جميع الردود المتوقعة
- يعطي المخرجات النهائية باستخدام `context.YieldOutputAsync()`

### ⚡ فوائد الأداء

**المتزامن مقابل التسلسلي:**
- تسلسلي: وكيل1 (30ث) → وكيل2 (30ث) = **إجمالي 60 ثانية**
- متزامن: وكيل1 (30ث) || وكيل2 (30ث) = **إجمالي 30 ثانية**

**تحسين الإنتاجية**: أسرع حتى N× لوكلاء N متزامنين (حسب عبء العمل والموارد)

### 🛡️ التعامل مع الأخطاء

يتعامل سير العمل مع فشل الوكلاء الفرديين برقي:
- إذا فشل وكيل واحد، يستمر الآخرون في المعالجة
- يمكن للمجمع تطبيق منطق انتهاء المهلة
- يمكن إرجاع نتائج جزئية إذا لزم الأمر
