# عينات إيصالات

ثلاثة ملفات إيصالات مولدة مسبقًا للفحص دون تشغيل دفتر الملاحظات.

| الملف | ما هو |
|---|---|
| `01_valid_receipt.json` | إيصال موقع صالح لمكالمة أداة `lookup_flights`. إرجاع التحقق True. |
| `02_tampered_receipt.json` | نفس الإيصال مع تعديل حقل واحد بعد التوقيع. إرجاع التحقق False. |
| `03_chain_three_receipts.json` | سلسلة من ثلاثة إيصالات صالحة (بحث، حجز مؤقت، حجز) مع `previous_receipt_hash` يربط كل منها بالذي قبله. |

العينات توقع بايتات JCS الكنسي للحمولة مباشرة باستخدام Ed25519.
يستمر استخدام SHA-256 لهضم المحتوى وربط سلسلة الإيصالات، وليس كـ
خطوة تجزئة إضافية قبل التوقيع.

## التحقق من العينات

يمرر دفتر الملاحظات عملية التحقق في أربعة أقسام. للتحقق من هذه العينات
مباشرة دون المرور بسرد دفتر الملاحظات:

```python
import json
from pathlib import Path

# يفترض أنك أكملت الاستيرادات ودوال المساعدة
# من القسمين 1 و 2 من ملف 18-signed-receipts.ipynb.

valid = json.loads(Path("01_valid_receipt.json").read_text())
print(f"Valid receipt: {verify_receipt(valid)}")        # صحيح

tampered = json.loads(Path("02_tampered_receipt.json").read_text())
print(f"Tampered receipt: {verify_receipt(tampered)}")  # خطأ

chain = json.loads(Path("03_chain_three_receipts.json").read_text())
for r in verify_chain(chain):
    print(f"  Receipt {r['index']} ({r['tool']}): {'VALID' if r['overall_valid'] else 'INVALID'}")
```

## كيفية توليدها

تستخدم العينات نفس مسار الكود كدفتر الملاحظات، مع مفتاح توقيع ثابت
وطوابع زمنية ثابتة لإعادة إنتاج بايتات متطابقة. لإعادة التوليد:

```bash
python3 generate_fixtures.py
```

(السكريبت في `generate_fixtures.py` في هذا الدليل.)

## ما يتعلمه الطلاب من فحص JSON الخام

قراءة صيغة الإيصال الخام تبني الفهم الذي قد لا توفره خلايا دفتر الملاحظات دائماً.
الطلاب الذين يتصفحون JSON غالبًا ما يلاحظون:

1. التوقيع هو سلسلة غير شفافة مشفرة بـ base64url، لكن كل الحقول الأخرى هي JSON
   مقروءة بوضوح. التوقيع لا يشفر المحتوى؛ بل يشهد عليه.
2. يتم تضمين `public_key` في الإيصال. المدقق لا يحتاج لأي شيء آخر
   للتحقق (مع افتراض الثقة بأن المفتاح فعلاً يخص الجهة المصدرة المزعومة؛
   انظر ملف README للدورة حول بنية الهوية).
3. تعديل حرف واحد في أي حقل، ثم إعادة مقارنة هذا الملف مع
   `02_tampered_receipt.json` يجعل آلية التحقق على مستوى البايتات واضحة.
