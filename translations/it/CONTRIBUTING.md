# Contribuire

Questo progetto accoglie contributi e suggerimenti. La maggior parte dei contributi richiede che tu accetti un Accordo di Licenza per i Collaboratori (CLA) dichiarando di avere il diritto e di concederci effettivamente i diritti di utilizzare il tuo contributo. Per i dettagli, visita <https://cla.opensource.microsoft.com>.

Quando invii una pull request, un bot CLA determinerà automaticamente se è necessario fornire un CLA e decorerà la pull request di conseguenza. Segui le istruzioni fornite dal bot. Dovrai farlo solo una volta per tutti i repository che utilizzano il CLA Microsoft.

## Codice di Condotta

Questo progetto ha adottato il [Microsoft Open Source Code of Conduct](https://opensource.microsoft.com/codeofconduct/). Per maggiori informazioni, consulta le [FAQ sul Codice di Condotta](https://opensource.microsoft.com/codeofconduct/faq/) o contatta [opencode@microsoft.com](mailto:opencode@microsoft.com) per domande o commenti aggiuntivi.

## Linee guida per le pull request

- Mantieni ogni pull request focalizzata su una singola modifica logica.
- Testa i notebook e gli esempi di codice interessati prima di inviare.
- Aggiorna la documentazione della lezione pertinente quando aggiungi o modifichi un esempio.
- Modifica solo il contenuto sorgente in inglese. Le traduzioni sono gestite dal flusso di lavoro di traduzione automatica.
- Non inserire credenziali, file `.env`, file temporanei o artefatti di sviluppo generati.

## Ambito editoriale e prodotti di terze parti

Questo curriculum si concentra sulle tecnologie Microsoft e su standard aperti neutrali rispetto ai fornitori. I contributi devono avere uno scopo educativo chiaro e non devono essere principalmente destinati a introdurre o promuovere un prodotto commerciale di terze parti, un servizio ospitato, un router modello, un SDK, un server MCP o altre offerte specifiche di un fornitore.

Software open-source e dipendenze di terze parti possono essere citati quando sono necessari per spiegare uno standard aperto o uno scenario di interoperabilità, vengono presentati in modo neutrale e non sono centrati su un prodotto o endpoint ospitato di un fornitore. Se il tuo contributo proposto include un prodotto o servizio specifico di un fornitore, apri una issue e ottieni l'approvazione del manutentore prima di inviare una pull request.

I collaboratori devono rivelare eventuali rapporti lavorativi, di proprietà, di sponsorizzazione o altre affiliazioni rilevanti con un prodotto o servizio citato nel loro contributo. Non includere affermazioni non supportate su prezzi, prestazioni, sicurezza, privacy o comparazioni. Gli esempi eseguibili non devono trasmettere dati degli studenti né eseguire azioni pubbliche tramite un servizio esterno di terze parti per impostazione predefinita.
