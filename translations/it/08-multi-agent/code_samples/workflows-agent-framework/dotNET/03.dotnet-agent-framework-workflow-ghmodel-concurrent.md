## 💻 Esecuzione del Codice

L'implementazione completa è disponibile in `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Questo file dimostra un **flusso di lavoro concorrente Fan-Out/Fan-In** per la pianificazione di viaggi:

### 🏗️ **Architettura del Flusso di Lavoro**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Componenti Chiave:**

1. **ConcurrentStartExecutor**: Invia la richiesta utente a tutti gli agenti simultaneamente
2. **Agente Ricercatore**: Analizza destinazioni e attrazioni in parallelo
3. **Agente Pianificatore**: Crea piani di viaggio dettagliati in parallelo
4. **ConcurrentAggregationExecutor**: Raccoglie e fonde i risultati da entrambi gli agenti

### 🎯 **Schema Fan-Out/Fan-In**

Questo flusso di lavoro dimostra lo schema classico **Fan-Out/Fan-In**:
- **Fan-Out**: Un messaggio in ingresso viene trasmesso a più agenti simultaneamente
- **Elaborazione Concorrente**: Molti agenti lavorano in parallelo sullo stesso compito
- **Fan-In**: I risultati di tutti gli agenti sono raccolti e aggregati in un unico output

### 🔍 Comprendere gli Executor Personalizzati

**ConcurrentStartExecutor:**
- Implementa `IMessageHandler<string>` per accettare input stringa
- Invia messaggi a tutti gli agenti connessi
- Invia `TurnToken` per avviare l'elaborazione concorrente

**ConcurrentAggregationExecutor:**
- Implementa `IMessageHandler<ChatMessage>` per ricevere risposte dagli agenti
- Raccoglie messaggi in modo thread-safe
- Aggrega quando arrivano tutte le risposte previste
- Produce l'output finale usando `context.YieldOutputAsync()`

### ⚡ Benefici di Prestazioni

**Concorrente vs Sequenziale:**
- Sequenziale: Agente1 (30s) → Agente2 (30s) = **60 secondi totali**
- Concorrente: Agente1 (30s) || Agente2 (30s) = **30 secondi totali**

**Miglioramento del Throughput**: Fino a N× più veloce per N agenti concorrenti (a seconda del carico e delle risorse)

### 🛡️ Gestione degli Errori

Il flusso di lavoro gestisce con grazia i guasti di singoli agenti:
- Se un agente fallisce, gli altri continuano l'elaborazione
- L'aggregatore può implementare logica di timeout
- Possono essere restituiti risultati parziali se necessario
