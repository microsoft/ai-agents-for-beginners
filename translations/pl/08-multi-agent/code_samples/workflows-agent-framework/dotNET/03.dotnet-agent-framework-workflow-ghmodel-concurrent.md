# ⚡ Współbieżne przepływy pracy agentów z Azure OpenAI (Responses API) (.NET)

## 📋 Samouczek wysokowydajnego przetwarzania równoległego

Ten notatnik demonstruje **wzorce współbieżnych przepływów pracy** przy użyciu Microsoft Agent Framework dla .NET oraz Azure OpenAI (Responses API). Nauczysz się, jak budować wysokowydajne, równoległe przepływy pracy maksymalizujące przepustowość przez wykonywanie wielu agentów AI jednocześnie, przy zachowaniu koordynacji i spójności danych.

## 🎯 Cele nauki

- **Azure OpenAI (Responses API)**: Koordynuj wiele współbieżnych wywołań do Azure OpenAI Responses API
- **Zarządzanie zasobami**: Efektywnie zarządzaj zasobami modelu AI podczas operacji współbieżnych

- **Równoważenie obciążenia**: Efektywnie rozdzielaj pracę na dostępną współbieżną moc przetwarzania

## 💻 Uruchamianie kodu

Pełna implementacja dostępna jest w `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Plik ten demonstruje **współbieżny przepływ pracy Fan-Out/Fan-In** dla planowania podróży:

### 🏗️ **Architektura przepływu pracy**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Kluczowe komponenty:**

1. **ConcurrentStartExecutor**: Nadaje zapytanie użytkownika do wszystkich agentów jednocześnie
2. **Agent Researcher**: Równolegle analizuje miejsca i atrakcje
3. **Agent Planner**: Równolegle tworzy szczegółowe plany podróży
4. **ConcurrentAggregationExecutor**: Zbiera i scala wyniki od obu agentów

### 🎯 **Wzorzec Fan-Out/Fan-In**

Ten przepływ pracy demonstruje klasyczny wzorzec **Fan-Out/Fan-In**:
- **Fan-Out**: Jedna wiadomość wejściowa jest rozgłaszana do wielu agentów jednocześnie
- **Współbieżne przetwarzanie**: Wielu agentów pracuje równolegle nad tym samym zadaniem
- **Fan-In**: Wyniki od wszystkich agentów są zbierane i agregowane w pojedynczy wynik

### 🔍 Zrozumienie niestandardowych executorów

**ConcurrentStartExecutor:**
- Implementuje `IMessageHandler<string>` do przyjmowania wejścia tekstowego
- Rozgłasza wiadomości do wszystkich połączonych agentów
- Wysyła `TurnToken`, aby wywołać współbieżne przetwarzanie

**ConcurrentAggregationExecutor:**
- Implementuje `IMessageHandler<ChatMessage>` do odbioru odpowiedzi agentów
- Zbiera wiadomości w sposób bezpieczny dla wątków
- Agreguje, gdy nadejdą wszystkie oczekiwane odpowiedzi
- Zwraca wynik końcowy przy użyciu `context.YieldOutputAsync()`

### ⚡ Korzyści wydajnościowe

**Współbieżne vs sekwencyjne:**
- Sekwencyjne: Agent1 (30s) → Agent2 (30s) = **60 sekund łącznie**
- Współbieżne: Agent1 (30s) || Agent2 (30s) = **30 sekund łącznie**

**Poprawa przepustowości**: Nawet N× szybsze dla N współbieżnych agentów (zależnie od obciążenia i zasobów)

### 🛡️ Obsługa błędów

Przepływ pracy łagodnie obsługuje awarie pojedynczych agentów:
- Jeśli jeden agent ulegnie awarii, pozostali kontynuują przetwarzanie
- Agregator może implementować logikę timeoutów
- W razie potrzeby można zwrócić wyniki częściowe
