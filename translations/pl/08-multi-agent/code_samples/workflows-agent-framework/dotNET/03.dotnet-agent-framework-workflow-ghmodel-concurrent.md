# ⚡ Równoczesne przepływy pracy agentów z Azure OpenAI (API odpowiedzi) (.NET)

## 📋 Poradnik przetwarzania równoległego o wysokiej wydajności

Ten notatnik demonstruje **wzorce równoczesnych przepływów pracy** z wykorzystaniem Microsoft Agent Framework dla .NET oraz Azure OpenAI (API odpowiedzi). Nauczysz się budować wysokowydajne, równoległe przepływy pracy, które maksymalizują przepustowość, wykonując wiele agentów AI jednocześnie, przy jednoczesnym zachowaniu koordynacji i spójności danych.

## 💻 Uruchamianie kodu

Pełna implementacja dostępna jest w pliku `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Ten plik demonstruje **przepływ pracy równoczesnej Fan-Out/Fan-In** do planowania podróży:

### 🏗️ **Architektura przepływu pracy**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Kluczowe komponenty:**

1. **ConcurrentStartExecutor**: Równocześnie rozsyła żądanie użytkownika do wszystkich agentów
2. **Agent Badacz**: Analizuje cele podróży i atrakcje równocześnie
3. **Agent Planista**: Równocześnie tworzy szczegółowe plany podróży
4. **ConcurrentAggregationExecutor**: Zbiera i scala wyniki obu agentów

### 🎯 **Wzorzec Fan-Out/Fan-In**

Ten przepływ pracy demonstruje klasyczny wzorzec **Fan-Out/Fan-In**:
- **Fan-Out**: Jedna wiadomość wejściowa jest rozsyłana jednocześnie do wielu agentów
- **Przetwarzanie równoczesne**: Wielu agentów pracuje równolegle nad tym samym zadaniem
- **Fan-In**: Wyniki od wszystkich agentów są zbierane i agregowane do pojedynczego wyniku

### 🔍 Zrozumienie niestandardowych Executorów

**ConcurrentStartExecutor:**
- Implementuje `IMessageHandler<string>` do przyjmowania wejścia tekstowego
- Rozsyła wiadomości do wszystkich połączonych agentów
- Wysyła `TurnToken` aby uruchomić przetwarzanie równoczesne

**ConcurrentAggregationExecutor:**
- Implementuje `IMessageHandler<ChatMessage>` do odbierania odpowiedzi agentów
- Zbiera wiadomości w sposób bezpieczny dla wątków
- Agreguje, gdy nadejdą wszystkie oczekiwane odpowiedzi
- Zwraca końcowy rezultat przy pomocy `context.YieldOutputAsync()`

### ⚡ Korzyści wydajnościowe

**Równoczesne vs Sekwencyjne:**
- Sekwencyjne: Agent1 (30s) → Agent2 (30s) = **łącznie 60 sekund**
- Równoczesne: Agent1 (30s) || Agent2 (30s) = **łącznie 30 sekund**

**Poprawa przepustowości**: Nawet N razy szybciej dla N agentów równoczesnych (w zależności od obciążenia i zasobów)

### 🛡️ Obsługa błędów

Przepływ pracy łagodnie radzi sobie z awariami pojedynczych agentów:
- Jeśli jeden agent zawiedzie, pozostali kontynuują przetwarzanie
- Agregator może stosować logikę limitu czasu
- Wyniki częściowe mogą być zwracane w razie potrzeby
