# ការសាងសង់ភ្នាក់ងារប្រើកុំព្យូទ័រ (CUA)

ភ្នាក់ងារប្រើកុំព្យូទ័រអាចទំនាក់ទំនងជាមួយគេហទំព័រដូចផ្ទាល់ ដូចមនុស្សធ្វើ: ដោយបើកកម្មវិធីរកមើលហ្វ្រៅស្រែរ (browser), ពិនិត្យមើលទំព័រ, ហើយអនុវត្តសកម្មភាពដ៏ល្អបន្ទាប់ពីការមើលឃើញ។ ក្នុងមេរៀននេះ អ្នកនឹងបង្កើតភ្នាក់ងារអូតូម៉ាទ័រមួយសម្រាប់កម្មវិធីរកមើល ដែលស្វែងរក Airbnb, លាតត្រួតទិន្នន័យបញ្ជីតាមរចនាសម្ព័ន្ធ, ហើយកំណត់ទីលំនៅថោកជាងគេនៅ Stockholm។

មេរៀននេះរួមបញ្ចូលការប្រើប្រាស់ Browser-Use សម្រាប់ចរន្តការដឹកនាំដោយ AI, Playwright និង Chrome DevTools Protocol (CDP) សម្រាប់ការត្រួតពិនិត្យកម្មវិធីរកមើល, Azure OpenAI សម្រាប់ការវិភាគដោយមានទស្សនវិស័យ, និង Pydantic សម្រាប់ការដកស្រង់ទ្រង់ទ្រាយត្រួតត្រា។

## ការណែនាំ

មេរៀននេះគឺនឹងគ្របដណ្តប់៖

- ការយល់ដឹងពេលណាភ្នាក់ងារប្រើកុំព្យូទ័រជាជាងអូតូម៉ាទ័រសម្រាប់ API តែប៉ុណ្ណោះ
- ការរួមបញ្ចូល Browser-Use ជាមួយ Playwright និង CDP សម្រាប់ការគ្រប់គ្រងអាយុជីវិតកម្មវិធីរកមើលដែលទុកចិត្តបាន
- ការប្រើ Azure OpenAI vision និងការបញ្ចេញ Pydantic តាមរចនាសម្ព័ន្ធ ដើម្បីដកស្រង់ទិន្នន័យបញ្ជីពីគេហទំព័រដើមវិល
- ការសំរេចចិត្តពេលណាការប្រើភ្នាក់ងារជាមុន, តួអង្គជាមុន, ឬប្រព័ន្ធបញ្ចូលរួមសម្រាប់កិច្ចការអូតូម៉ាទ័រកម្មវិធីរកមើល

## គោលបំណងរៀន

បន្ទាប់ពីបញ្ចប់មេរៀននេះ អ្នកនឹងដឹងពីវិធី៖

- កំណត់ Browser-Use ជាមួយ Azure OpenAI និង Playwright
- បង្កើតចរន្តអូតូម៉ាទ័រកម្មវិធីរកមើលដែលធ្វើដំណើរក្នុងគេហទំព័រពិត និងគ្រប់គ្រងធាតុ UI ដ៏ផ្លាស់ប្ដូរបាន
- ដកស្រង់លទ្ធផលប្រភេទពីមាតិកាទំព័រដែលមើលឃើញ និងបំលែងវាទៅជាលូហ្គិចអាជីវកម្មបន្ត
- ជ្រើសរើសរវាងគំរូភ្នាក់ងារនិងតួអង្គ ដោយផ្អែកលើកម្រិតសម្រិតនៃកិច្ចការកម្មវិធីរកមើល

## ឧទាហរណ៍កូដ

មេរៀននេះរួមមានមេរៀនតាមសៀវភៅកត់ត្រាមួយ៖

- [15-browser-user.ipynb](./15-browser-user.ipynb): បើកសម័យ Chrome តាមរយៈ CDP ស្វែងរកបញ្ជី Airbnb សម្រាប់ Stockholm ប្រមូលតម្លៃដោយ Browser-Use vision ហើយកំណត់ជម្រើសមានតំលៃថោកបំផុតជាទ្រង់ទ្រាយតាមរចនាសម្ព័ន្ធ។

## ការតម្រូវនិងត្រៀមខ្លួន

- Python 3.12+
- ការតំឡើង Azure OpenAI ដំណើរការនៅក្នុងបរិបទរបស់អ្នក
- កម្មវិធី Chrome ឬ Chromium ត្រូវបានដំឡើងក្នុងម៉ាស៊ីន
- ការតំឡើង dependency របស់ Playwright
- ស្គាល់មូលដ្ឋានពី Python អស៊ីងខេន

## ការតំឡើង

ដំឡើងកញ្ចប់ដែលប្រើនៅក្នុងសៀវភៅកត់ត្រា៖

```bash
pip install browser_use playwright python-dotenv
playwright install chromium
```

កំណត់អថេរស៊ីស្ទឹម Azure OpenAI ដែលសៀវភៅកត់ត្រាប្រើ៖

```bash
AZURE_OPENAI_ENDPOINT=...
AZURE_OPENAI_API_KEY=...
AZURE_OPENAI_CHAT_DEPLOYMENT_NAME=...
# ជាជំរើស៖ ពីរបៀបដើមទៅកំណែ API ចុងក្រោយបើមិនបានបញ្ចូល
AZURE_OPENAI_API_VERSION=...
```

## ទិដ្ឋភាពស្ថាបត្យកម្ម

សៀវភៅកត់ត្រាបង្ហាញពីចរន្តអូតូម៉ាទ័រប្រកបដោយភាពរួមបញ្ចូល៖

1. Chrome ចាប់ផ្តើមជាមួយ CDP ដើម្បីឲ្យទាំង Playwright និង Browser-Use អាចចែករំលែកសម័យកម្មវិធីរកមើលតែមួយ។
2. ភ្នាក់ងារ Browser-Use គ្រប់គ្រងកិច្ចការដឹកនាំបើកបរ ដែលមានលក្ខណៈបើកចំហ ដូចជា បើក Airbnb បិទបង្ហាញ pop-ups និងស្វែងរក Stockholm។
3. ទំព័រដំណើរការត្រូវបានពិនិត្យជាមួយរចនាសម្ព័ន្ធ Pydantic ដើម្បីដកស្រង់ចំណងជើងបញ្ជី, តម្លៃរាត្រី, អត្រា, និង URL ក្នុងបែបស្អាត។
4. លូហ្គិច Python ប្រៀបធៀបចំណុចបញ្ជីដែលបានដកស្រង់ ហើយផ្ដល់សញ្ញារការជម្រើសថោកបំផុត។

វិធីសាស្រ្តនេះរក្សាបាននូវដំណើរការវិភាគដោយមានទស្សនវិស័យ ដែល Browser-Use ងាយយល់ ខណៈដែលបានផ្ដល់ការត្រួតពិនិត្យកម្មវិធីរកមើលជាក់លាក់នៅពេលដែលអ្នកត្រូវការ។

## ចំណុចប្រទាក់សំខាន់ និងអនុស្សារណៈល្អ

### ពេលណាធ្វើការ​ប្រើភ្នាក់ងារ តួអង្គ

| ករណី | ប្រើភ្នាក់ងារ | ប្រើតួអង្គ |
|----------|-----------|-----------|
| រចនាសម្ព័ន្ធបត់បែន | បាទ, AI អាចបង្ហាញខ្លួនឆ្លើយតបកើតមានលំអៀងទំព័រ | ទេ, ខូចបានដោយបញ្ជាពិសេសយ៉ាងងាយ |
| រចនាសម្ព័ន្ធជាក់លាក់ | ទេ, ភ្នាក់ងារជាមុខមួយយឺតជាងការគ្រប់គ្រងផ្ទាល់ | បាទ, លឿន និងត្រឹមត្រូវ |
| ស្វែងរកធាតុ | បាទ, ភាសារធម្មជាតិកាត់បន្ថយ | ទេ, ត្រូវការបញ្ជាពិសេសត្រឹមត្រូវ |
| ត្រួតពិនិត្យពេលវេលា | ទេ, ខ្វះភាពទៀងទាត់ | បាទ, គ្រប់គ្រងពេញលេញលើការរង់ចាំ និងព្យាយាមវិញ |
| ចរន្តសកម្មភាពស្មុគស្មាញ | បាទ, ដោះស្រាយស្ថានភាព UI មិនច្បាស់ | ទេ, ត្រូវការបញ្ជាពន្លឿនច្បាស់លាស់ |

### អនុស្សារណៈល្អសម្រាប់ Browser-Use

1. ចាប់ផ្តើមជាមួយភ្នាក់ងារសម្រាប់ការស្វែងរក និងដឹកនាំបត់បែន។
2. ប្ដូរទៅការត្រួតពិនិត្យផ្ទាល់លើទំព័រពេលដែលអន្តរកម្មគឺអាចទាន់ប៉ាន់ត្រូវបាន។
3. ប្រើម៉ូដែលលទ្ធផលដោយរចនាសម្ព័ន្ធ ដើម្បីធានាថាទិន្នន័យដែលបានដកស្រង់ត្រូវបានផ្ទៀងផ្ទាត់ និងមានប្រភេទត្រឹមត្រូវ។
4. បន្ថែមពេលយឺតយ៉ាវយ៉ាងយុទ្ធសាស្រ្តបន្ទាប់ពីសកម្មភាពដែលបង្កការផ្លាស់ប្ដូរទំនាក់ទំនង UI មើលឃើញ។
5. ថតរូបអេក្រង់ក្នុងពេលជាដំណាក់កាល ដើម្បីងាយស្រួលដោះស្រាយបញ្ហា។
6. លះបង់ពីការប្រែប្រួលគេហទំព័រ ហើយរចនាយុទ្ធសាស្រ្តជំនួសសម្រាប់ pop-ups និងការប្ដូររចនាសម្ព័ន្ធ។
7. បញ្ចូលរវាងគំរូភ្នាក់ងារ និងតួអង្គ ដើម្បីទទួលបានទាំងភាពបត់បែន និងភាពត្រឹមត្រូវ។

### ការពារសុវត្ថិភាពសម្រាប់ភ្នាក់ងារកម្មវិធីរកមើល

ភ្នាក់ងារកម្មវិធីរកមើលដំណើរការលើគេហទំព័របច្ចុប្បន្ន បរិមាណការតម្រុយត្រឹមត្រូវជាងស្គ្រីបដែលហៅ API ដែលស្គាល់តែប៉ុណ្ណោះ។ មុនផ្លាស់ប្តូរពីការបង្ហាញសៀវភៅកត់ត្រាទៅដំណើរការពិត ពណ៌តែរុក្ខជាតិដែនកំណត់នៃអ្វីដែលភ្នាក់ងារអាចមើលឃើញ ចុច និងដាក់ស្នើ។

1. **កំណត់បរិបទកម្មវិធីរកមើល។** ដំណើរការភ្នាក់ងារនៅក្នុងពណ៌តែមួយឬsandbox ដោយដាក់កំណត់ទៅលើដែនដែលត្រូវការសម្រាប់កិច្ចការ។
2. **បំបែកការសង្កេតពីសកម្មភាព។** អោយភ្នាក់ងារ​ស្វែងរក អាន និងដកស្រង់ទិន្នន័យជាមុន; តម្រូវការជំហានអនុញ្ញាតពិសេសមុនដាក់ស្នើទម្រង់, បញ្ជូនសារ, កក់សណ្ឋាគារ, ទិញទំនិញ, លុបបញ្ជី ឬប្ដូរកំណត់គណនី។

5. **ប្រើការត្រួតពិនិត្យដាក់កូដជុំវិញជំហានហានិភ័យ។** ផ្ទៀងផ្ទាត់ URL បច្ចុប្បន្ន, ចំណងជើង, ធាតុដែលជ្រើស, តម្លៃ, អ្នកទទួល និងសង្ខេបសកម្មភាពជាមួយកូដ មុនស្នើឲ្យអ្នកប្រើអនុម័តជំហានចុងក្រោយ។

អោយភ្នាក់ងារគ្រប់គ្រងចរន្តបើកចំហ និងស្ថានភាព UI បត់បែន ដូចជា ស្វែងរកទំព័រត្រឹមត្រូវ ឬបិទ pop-ups មិនរំពឹងទុក។ ប្ដូរទៅការត្រួតពិនិត្យ Playwright ផ្ទាល់ពេលរចនាសម្ព័ន្ធទំព័រជាក់លាក់ ហើយសកម្មភាពត្រូវមានភាពត្រឹមត្រូវ, ព្យាយាមបន្ត, រង់ចាំ, ឬការផ្ទៀងផ្ទាត់យ៉ាងទៀងទាត់។
</details>

**3. ឧទាហរណ៍ Airbnb រកឃើញបញ្ជីដែលអ្នកប្រើអាចចង់កក់។ តើអ្វីគួរជាកើតទៅមុនបញ្ចូលគណនី, ទាក់ទងម្ចាស់ផ្ទះ, ឬបញ្ចប់ការកក់?**

<details>
<summary>ចម្លើយ</summary>

ចរន្តត្រូវផ្អាក ហើយស្នើសុំការយល់ព្រមពីអ្នកប្រើ។ មុនស្នើសុំ គួរបង្ហាញការសង្ខេបច្បាស់លាស់ទំព័របញ្ជីដែលបានជ្រើស, URL បច្ចុប្បន្ន, តម្លៃ, កាលបរិច្ឆេទ, និងសកម្មភាពសំរេចចិត្ត។ ស្វែងរក និងដកស្រង់តម្លៃអាចជាកិច្ចការ​អូតូម៉ាទ័រ; ការចូលគណនី, សារ, ការទិញ, និងការកក់ គួរតែបានអ្នកប្រើយល់ព្រម។
</details>

**4. ទំព័រតែមួយប្រាប់ភ្នាក់ងារឲ្យមិនផ្តោតលើការណែនាំដើម, ទៅគេហទំព័រផ្សេង, ហើយបង្ហាញពាក្យសម្ងាត់។ តើគួរ​អោយភ្នាក់ងារដោះស្រាយអត្ថបទនោះយ៉ាងដូចម្តេច?**

<details>
<summary>ចម្លើយ</summary>

អនុវត្តវាជាមាតិកាទំព័រដែលមិនទុកចិត្ត ពុំមែនជាគន្លឹះការណែនាំចេញពីអ្នកអភិវឌ្ឍឬអ្នកប្រើ។ ភ្នាក់ងារគួរតែរក្សានៅលើដែនកំណត់និងបរិវេណកិច្ចការ, បដិសេធបង្ហាញពាក្យសម្ងាត់, ហើយមិនអនុវត្តការណែនាំដែលប្ដូរគោលបំណង, បិទការការពារ, ឬយកទៅគេហទំព័រមិនទាក់ទង។
</details>

**5. តើភស្តុតាងណាដែលមានប្រយោជន៍ក្នុងការរក្សាទុកពេលភ្នាក់ងារកម្មវិធីរកមើលដំណើរការ ហើយអ្វីគួរតែជៀសវាង?**

<details>
<summary>ចម្លើយ</summary>

រក្សាសង្ខេបសកម្មភាព, ពេលវេលា, URLs, ពណ៌នាធាតុដែលជ្រើស, លទ្ធផលផ្ទៀងផ្ទាត់, និងយោងរូបភាពអេក្រង់ ដើម្បីអាចពិនិត្យបាន ជៀសវាងរក្សាពាក្យសម្ងាត់, ព័ត៌មានបង់ប្រាក់, គុឌូសេស្យុង, ទិន្នន័យផ្ទាល់ខ្លួនដើរដោយផ្ទាល់, ឬមាតិកាទំព័រពេញមួយ លើកលែងបើមានហេតុផលគោលដៅផ្ទុក និងភាពឯកជន។
</details>
