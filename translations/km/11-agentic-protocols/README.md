# ការប្រើប្រាស់ប្រព័ន្ធ Agentic Protocols (MCP, A2A និង NLWeb)

[![Agentic Protocols](../../../translated_images/km/lesson-11-thumbnail.b6c742949cf1ce2a.webp)](https://youtu.be/X-Dh9R3Opn8)

> _(ចុចលើរូបភាពខាងលើដើម្បីមើលវីដេអូរបស់មេរៀននេះ)_

នៅពេលដែលការប្រើប្រាស់ភ្នាក់ងារ AI កំពុងលូតលាស់ ក៏ការតម្រូវការប្រព័ន្ធតំបន់តម្រុយ សុវត្ថិភាព និងគាំទ្រការបង្កើតស្នាដៃច្នៃប្រឌិតបើកក៏កើតមានដូចគ្នា។ ក្នុងមេរៀននេះ យើងនឹងរៀបរាប់ពីប្រព័ន្ធ ៣ ប្រព័ន្ធដែលមានគោលបំណងបំពេញតម្រូវការនេះ - Model Context Protocol (MCP), Agent to Agent (A2A) និង Natural Language Web (NLWeb)។

## ការណែនាំ

ក្នុងមេរៀននេះ យើងនឹងគ្របដណ្តប់៖

• របៀបដែល **MCP** អនុញ្ញាតឲ្យភ្នាក់ងារ AI ទទួលបានឧបករណ៍ និងទិន្នន័យខាងក្រៅដើម្បីបញ្ចប់ភារកិច្ចរបស់អ្នកប្រើប្រាស់។

• របៀបដែល **A2A** អាចអនុញ្ញាតឲ្យមានការទំនាក់ទំនង និងសហការណ៍រវាងភ្នាក់ងារដែលខុសគ្នា។

• របៀបដែល **NLWeb** នាំយកចំណុចប្រទាក់ភាសាធម្មជាតិទៅគេហទំព័រណាមួយ ដើម្បីឲ្យភ្នាក់ងារ AI អាចរកឃើញ និងបន្តភាពជាមួយមាតិកា។

## គោលបំណងសិក្សា

• **កំណត់** គោលបំណងសំខាន់ និងអត្ថប្រយោជន៍នៃ MCP, A2A និង NLWeb នៅក្នុងបរិបទភ្នាក់ងារ AI។

• **ពន្យល់** របៀបដែលប្រព័ន្ធនីមួយៗជួយងាយស្រួលក្នុងការទំនាក់ទំនង និងអន្តរកម្មរវាង LLMs, ឧបករណ៍ និងភ្នាក់ងារផ្សេងៗ។

• **ទទួលស្គាល់** តួនាទីឯកសារនៃប្រព័ន្ធនីមួយៗក្នុងការសាងសង់ប្រព័ន្ធ agentic ស្មុគស្មាញ។

## Model Context Protocol

**Model Context Protocol (MCP)** ជាស្តង់ដា​បើក ដែលផ្តល់វិធីសាស្រ្តថ្នាក់ស្តង់ដារដើម្បីឲ្យកម្មវិធីផ្តល់បរិបទ និងឧបករណ៍ទៅ LLMs។ វាអាចធ្វើឲ្យមាន "អភ្ជាប់សាកល" ដល់ប្រភពទិន្នន័យ និងឧបករណ៍ផ្សេងៗដែលភ្នាក់ងារ AI អាចភ្ជាប់បានយ៉ាងទៀងទាត់។

មកមើលគ្រឿងផ្សំរបស់ MCP អត្ថប្រយោជន៍ប្រៀបធៀបទៅនឹងការប្រើ API ត្រង់ និងឧទាហរណ៍ពីរបៀបដែលភ្នាក់ងារ AI អាចប្រើម៉ាស៊ីនមេ MCP។

### គ្រឿងផ្សំមូលដ្ឋានរបស់ MCP

MCP ប្រតិបត្តិលើស្ថ معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم معم المع ಮಾಡು ವ್ಯಾಪರಂ಺@@

• **Hosts** គឺជាកម្មវិធី LLM (ដូចជា​កម្មវិធីកំណែបង្ហាញកូដ VSCode) ដែលចាប់ផ្តើមការតភ្ជាប់ទៅម៉ាស៊ីនមេ MCP។

• **Clients** គឺជា​គ្រឿងផ្សំក្នុងកម្មវិធី host ដែលរក្សាការតភ្ជាប់មួយទៅមួយជាមួយម៉ាស៊ីនមេ។

• **Servers** គឺជាកម្មវិធីតូចៗដែលបង្ហាញសមត្ថភាពជាក់លាក់។

រួមបញ្ចូលនៅក្នុងប្រព័ន្ធមាន primitive ដ៏សំខាន់ ៣ ដែលជាសមត្ថភាពរបស់ម៉ាស៊ីនមេ MCP៖

• **Tools**៖ ជាការប្រតិបត្ដិច្បាស់លាស់ ឬមុខងារដែលភ្នាក់ងារ AI អាចហៅដើម្បីអនុវត្តសកម្មភាពមួយ។ ដូចជា សេវាអាកាសធាតុអាចបង្ហាញឧបករណ៍ "យកព័ត៌មានអាកាសធាតុ" ឬម៉ាស៊ីនមេ e-commerce អាចបង្ហាញឧបករណ៍ "ទិញផលិតផល"។ ម៉ាស៊ីនមេ MCP វាស់ឈ្មោះ, ពណ៌នា, និងស្កេមា input/output របស់ឧបករណ៍មួយៗនៅក្នុងបញ្ជីសមត្ថភាព។

• **Resources**៖ ជាទិន្នន័យអានប៉ុណ្ណោះ ឬឯកសារដែលម៉ាស៊ីនមេ MCP អាចផ្តល់ និង clients អាចទាញយកបានដោយផ្អែកលើតម្រូវការ។ ឧទាហរណ៍មាន៖ ខ្លឹមសារឯកសារ, កំណត់ត្រាខ្ទង់ទិន្នន័យ, ឬឯកសារចុះកំណត់ហេតុ។ ធនធានអាចជាអត្ថបទ (ដូចជា កូដ ឬ JSON) ឬករណីទាំងពីរ (រូបភាព ឬ PDF)។

• **Prompts**៖ ជាគំរូដែលបានកំណត់ម្តងហើយផ្តល់អនុសាសន៍សម្រាប់សកម្មភាពស្មុគស្មាញជាង។

### អត្ថប្រយោជន៍នៃ MCP

MCP ផ្តល់អត្ថប្រយោជន៍ដ៏សំខាន់សម្រាប់ភ្នាក់ងារ AI៖

• **ការរកឧបករណ៍ប្រែប្រួល**៖ ភ្នាក់ងារអាចទទួលបានបញ្ជីឧបករណ៍ដែលមានពីម៉ាស៊ីនមេជាទំនើប ដោយមានពណ៌នាផ្លូវការរបស់វា។ វាបែកខុសពី API ប្រពៃណី ដែលជាទូទៅតម្រូវឲ្យកែសម្រួលកូដស្ថિરដើម្បីបញ្ចូលចូល, មានន័យថា​ ការផ្លាស់ប្តូរ API តម្រូវឲ្យកែសម្រួលកូដ។ MCP ផ្តល់វិធី "ភ្ជាប់លើស្រេចមួយដង" ឲ្យមានភាពបត់បែនខ្ពស់ជាង។

• **អត្ថិភាពក្រោម LLM ផ្សៗ**៖ MCP ធ្វើការ​តាមរយៈ LLMs ខុសៗគ្នា ឲ្យមានភាពបត់បែនក្នុងការប្ដូរម៉ូដែលគោលដៅសម្រាប់វាយតម្លៃលទ្ធផលល្អ។

• **សុវត្ថិភាពស្តង់ដារ**៖ MCP រួមបញ្ចូលវិធីសាស្រ្តសម្គាល់តាមស្តង់ឌារបង្កើនសមត្ថភាពពេលបន្ថែមចូលដំណើរការម៉ាស៊ីនមេ MCP បន្ថែមទៀត។ វាសាមញ្ញជាងការគ្រប់គ្រងកូនសោ និងប្រភេទសម្គាល់គណនីមួយចំនួនសម្រាប់ API ប្រពៃណីផ្សេងៗ។

### ឧទាហរណ៍ MCP

![MCP Diagram](../../../translated_images/km/mcp-diagram.e4ca1cbd551444a1.webp)

ស្រមៃថាអ្នកប្រើប្រាស់ចង់បញ្ជូនការកក់សំបុត្រយន្តហោះដោយប្រើជំនួយករណ៍ AI ដែលដំណើរការដោយ MCP។

1. **ការតភ្ជាប់**: ជំនួយករណ៍ AI (client MCP) តភ្ជាប់ទៅម៉ាស៊ីនមេ MCP ដែលផ្តល់ដោយក្រុមហ៊ុនអាកាសចរណ៍។

2. **ការរកឧបករណ៍**: client សួរម៉ាស៊ីនមេ MCP របស់ក្រុមហ៊ុនអាកាសចរណ៍ថា "តើអ្នកមានឧបករណ៍អ្វីខ្លះ?" ម៉ាស៊ីនមេឆ្លើយតបជាមួយឧបករណ៍ទាំងនេះដូចជា "ស្វែងរកសំបុត្រយន្តហោះ" និង "បញ្ជូនការកក់សំបុត្រយន្តហោះ"។

3. **ហៅឧបករណ៍**: អ្នកបន្ទាប់សុំឲ្យជំនួយករណ៍ AI "ស្វែងរកសំបុត្រយន្តហោះពី Portland ទៅ Honolulu" ជំនួយករណ៍ AI ដោយប្រើ LLM របស់ខ្លួន កំណត់ថាត្រូវហៅឧបករណ៍ "ស្វែងរកសំបុត្រយន្តហោះ" ហើយផ្ញើប៉ារ៉ាម៉ែត្រ (ទីតាំងប្រភព, ទីតាំងគោលដៅ) ទៅម៉ាស៊ីនមេ MCP។

4. **អនុវត្តន៍ និងការឆ្លើយតប**: ម៉ាស៊ីនមេ MCP ដែលដំណើរការជាខ្សែប្រយោវ បង្កើតការហៅទៅ API ការកក់ក្នុងក្រុមហ៊ុនអាកាសចរណ៍។ បន្ទាប់មកទទួលបានព័ត៌មានយន្តហោះ (ទិន្នន័យ JSON) ហើយផ្ញើវិញទៅជំនួយករណ៍ AI។

5. **ចរន្តអន្តរកម្មបន្ថែម**: ជំនួយករណ៍ AI បង្ហាញជម្រើសសំបុត្រយន្តហោះ។ នៅពេលអ្នកជ្រើសយន្តហោះជាក់លាក់ ឧបករណ៍អាចហៅឧបករណ៍ "បញ្ជូនការកក់សំបុត្រយន្តហោះ" លើម៉ាស៊ីនមេ MCP ដដែល បញ្ចប់ការកក់។

## ប្រព័ន្ធ Agent-to-Agent (A2A)

ខណៈពេល MCP ផ្តោតលើការតភ្ជាប់ LLM ទៅឧបករណ៍ ប្រព័ន្ធ **Agent-to-Agent (A2A)** ធ្វើទៅលើជំហានបន្ថែមដោយអនុញ្ញាតឲ្យមានការទំនាក់ទំនង និងសហការណ៍រវាងភ្នាក់ងារ AI ផ្សេងៗ។ A2A តភ្ជាប់ភ្នាក់ងារ AI ពីអង្គការណា មជ្ឈមណ្ឌល និងបច្ចេកវិទ្យាផ្សេងៗគ្នា ដើម្បីបញ្ចប់ភារកិច្ចរួម។

យើងនឹងពិនិត្យគ្រឿងផ្សំនិងអត្ថប្រយោជន៍របស់ A2A ជាមួយឧទាហរណ៍ពីរបៀបដែលវាអាចប្រើបានក្នុងកម្មវិធីកក់ដំណើរយន្តហោះរបស់យើង។

### គ្រឿងផ្សំមូលដ្ឋានរបស់ A2A

A2A ផ្តោតលើការអនុញ្ញាតឲ្យភ្នាក់ងារទំនាក់ទំនង និងសហការជាមួយគ្នាបំពេញភារកិច្ចរងនៃអ្នកប្រើ។ អង្គភាពនីមួយៗនៃប្រព័ន្ធនេះ មានដូចជា៖

#### កាតភ្នាក់ងារ (Agent Card)

ដូចជាដែលម៉ាស៊ីនមេ MCP ចែករំលែកបញ្ជីឧបករណ៍ កាតភ្នាក់ងារមាន៖
- ឈ្មោះភ្នាក់ងារ។
- **ការពិពណ៌នាអំពីភារកិច្ចទូទៅ** ដែលវាកំពុងបំពេញ។
- **បញ្ជីជំនាញជាក់លាក់** ជាមួយការពិពណ៌នាដើម្បីជួយភ្នាក់ងារផ្សេងៗ (ឬអ្នកប្រើប្រាស់មនុស្ស) ឲ្យយល់ថាពេលណា និងហេតុអ្វីក្នុងការហៅភ្នាក់ងារនោះ។
- **URL ចុងបញ្ចប់បច្ចុប្បន្ន** នៃភ្នាក់ងារ។
- **កំណែកំណត់និងសមត្ថភាព** នៃភ្នាក់ងារ ដូចជា ចម្លើយបញ្ជូនតាមចរន្ត និងការជូនដំណឹងបញ្ចេញ។

#### អ្នកអនុវត្តភ្នាក់ងារ (Agent Executor)

អ្នកអនុវត្តភ្នាក់ងារទទួលបន្ទុកក្នុងការផ្ញើបរិបទនៃការជជែករបស់អ្នកប្រើទៅភ្នាក់ងារពីចម្ងាយ។ ភ្នាក់ងារពីចម្ងាយត្រូវការនេះដើម្បីយល់ពីភារកិច្ចដែលត្រូវបញ្ចប់។ នៅក្នុងម៉ាស៊ីនមេ A2A ភ្នាក់ងារប្រើ LLM របស់ខ្លួនដើម្បីបកស្រាយសំណើដែលមកដល់ និងអនុវត្តភារកិច្ចដោយប្រើឧបករណ៍នៅក្នុង។

#### សារព័ត៌មាន (Artifact)

ពេលភ្នាក់ងារពីចម្ងាយបញ្ចប់ភារកិច្ចដែលបានស្នើ អ្នកផលិតកម្មក៏បង្កើតសារព័ត៌មានដែលមានលទ្ធផលកិច្ចការរបស់ភ្នាក់ងារ ការពិពណ៌នាអំពីអ្វីដែលបានបំពេញ និង​អត្ថបទបរិបទដែលបានផ្ញើតាមប្រព័ន្ធ។ បន្ទាប់ពីផ្ញើសារព័ត៌មាន ហេតុការណ៍ភ្ជាប់ជាមួយភ្នាក់ងារពីចម្ងាយត្រូវបានបិទរហូតដល់ត្រូវការក្រោយម្តងទៀត។

#### ជួរអ៊ីវិន (Event Queue)

ឧបករណ៍នេះប្រើសម្រាប់ប្រតិបត្ដិការការអាប់ដេត និងផ្ញើសារ។ វាពិសេសសម្រាប់ការផលិត ជួយការពារមិនឲ្យការតភ្ជាប់រវាងភ្នាក់ងារត្រូវបានបិទមុនពេលភារកិច្ចត្រូវបានបញ្ចប់ ជាពិសេសពេលវេលាបំពេញភារកិច្ចអាចយូរ។

### អត្ថប្រយោជន៍នៃ A2A

• **ការសហការកើនឡើង**៖ វាអនុញ្ញាតឲ្យភ្នាក់ងារពីអ្នកផ្គត់ផ្គង់ និងវេទិការផ្សេងៗគ្នាចែករំលែកបរិបទ និងធ្វើការក្នុងរួម ជួយបង្កើតស្វ័យប្រវត្តិភាពទាំងមូលតាមរយៈប្រព័ន្ធដែលមិនភ្ជាប់គ្នាទេតាមផ្ទាល់។

• **ភាពបត់បែនក្នុងការជ្រើសរើសម៉ូដែល**៖ ភ្នាក់ងារ A2A នីមួយៗអាចជ្រើសរើស LLM ដែលខ្លួនប្រើសម្រាប់បម្រើសំណើររបស់ខ្លួន ឲ្យមានកំណត់ត្រាឬម៉ូដែលកែប្រែខុសៗគ្នា ស្ថិតខុសពីការតភ្ជាប់ LLM តែមួយជាមួយក្នុងគ្រោងការជាមួយ MCP អ្នកណាមួយ។

• **សម្គាល់អ្នកប្រើប្រាស់បញ្ចូលក្នុងប្រព័ន្ធ**៖ ការសម្គាល់អ្នកប្រើប្រាស់បានបញ្ចូលចូលក្នុងប្រព័ន្ធដោយផ្ទាល់ នៅក្នុងប្រព័ន្ធ A2A ដែលផ្តល់សុវត្ថិភាពខ្ពស់សម្រាប់អន្តរកម្មរវាងភ្នាក់ងារ។

### ឧទាហរណ៍ A2A

![A2A Diagram](../../../translated_images/km/A2A-Diagram.8666928d648acc26.webp)

មកពង្រីកសេណារីយ៉ូ ការកក់ដំណើរយន្តហោះរបស់យើង ប៉ុន្តេលពេលនេះប្រើ A2A។

1. **សំណើអ្នកប្រើទៅភ្នាក់ងារច្រើន**៖ អ្នកប្រើប្រាស់អន្តរាគមន៍ជាមួយ "ភ្នាក់ងារដំណើរយន្តហោះ" នៃ A2A client/agent ដូចជា "សូមបញ្ជូនដំណើរទៅ Honolulu សប្តាហ៍ក្រោយ រួមទាំងសំបុត្រយន្តហោះ សណ្ឋាគារ និងរថយន្តជួល"។

2. **ការត្រួតពិនិត្យដោយភ្នាក់ងារដំណើរ**: ភ្នាក់ងារដំណើរយន្តហោះទទួលសំណើស្មុគស្មាញនេះ។ វាប្រើ LLM ដើម្បីដោះស្រាយភារកិច្ច ហើយសម្រេចថាត្រូវចូលរួមជាមួយភ្នាក់ងារពិសេសផ្សេងទៀត។

3. **ការទំនាក់ទំនងរវាងភ្នាក់ងារ**: ភ្នាក់ងារដំណើរយន្តហោះប្រើប្រព័ន្ធ A2A តភ្ជាប់ទៅភ្នាក់ងារចុងក្រោយ ដូចជា "ភ្នាក់ងារអាកាសចរណ៍", "ភ្នាក់ងារសណ្ឋាគារ" និង "ភ្នាក់ងារជួលរថយន្ត" ដែលបង្កើតដោយក្រុមហ៊ុនផ្សេងៗគ្នា។

4. **ការចាក់បញ្ជាភារកិច្ច**: ភ្នាក់ងារដំណើរយន្តហោះផ្ញើភារកិច្ចជាក់លាក់ទៅភ្នាក់ងារពិសេសតាមការបញ្ជា (ដូចជា "ស្វែងរកសំបុត្រយន្តហោះទៅ Honolulu", "បញ្ជូនការកក់សណ្ឋាគារ" និង "ជួលរថយន្ត")។ ភ្នាក់ងារពិសេសនីមួយៗ ប្រើ LLM របស់ខ្លួន និងឧបករណ៍ផ្ទៃក្នុង (ដែលអាចជាម៉ាស៊ីនមេ MCP ផ្ទាល់ខ្លួន) ដើម្បីបំពេញភារកិច្ចនីមួយៗ។

5. **ការឆ្លើយតបរួមមួយ**: បន្ទាប់ពីភ្នាក់ងារចុងក្រោយទាំងអស់បញ្ចប់ភារកិច្ចរបស់ពួកគេ ភ្នាក់ងារដំណើរយន្តហោះបង្រួមលទ្ធផល (ព័ត៌មានយន្តហោះ, ការបញ្ជាក់សណ្ឋាគារ, ការ​ជួលរថយន្ត) ហើយផ្ញើការឆ្លើយតបរចនាប័ទ្មជជែកតាមសេណារីយ៉ូនៅទៅអ្នកប្រើប្រាស់។

## Natural Language Web (NLWeb)

គេហទំព័រ បានក្លាយជាវិធីសំខាន់សម្រាប់អ្នកប្រើប្រាស់ក្នុងការទទួលបានព័ត៌មាន និងទិន្នន័យទូទាំងអ៊ីនធឺណិតរយៈពេលវែង។

យើងសូមមើលគ្រឿងផ្សំនៃ NLWeb អត្ថប្រយោជន៍របស់វា និងឧទាហរណ៍ពីរបៀបដែល NLWeb ដំណើរការនៅក្នុងកម្មវិធីដំណើរត្រូវរបស់យើង។

### គ្រឿងផ្សំនៃ NLWeb

- **កម្មវិធី NLWeb (កូដសេវាកម្មមូលដ្ឋាន)**៖ ប្រព័ន្ធដែលដំណើរការសំណួរភាសាធម្មជាតិ។ វាតភ្ជាប់ផ្នែកផ្សេងៗនៃវេទិកាដើម្បីបង្កើតចម្លើយ។ អ្នកអាចគិតថាវាជាគ្រឿងចង្ក្រានដែលផ្គត់ផ្គង់លក្ខណៈភាសាធម្មជាតិនៃគេហទំព័រ។

- **ប្រព័ន្ធ NLWeb Protocol**៖ ជាប្រមាញ់ច្បាប់មូលដ្ឋានសម្រាប់អន្តរកម្មភាសាធម្មជាមួយគេហទំព័រ។ វាផ្ញើចម្លើយជាទ្រង់ទ្រាយ JSON (ជាច្រើនប្រើ Schema.org)។ គោលបំណងរបស់វាគឺបង្កើតមូលដ្ឋានសាមញ្ញសម្រាប់ “វែប AI” ដូចដដែល HTML ធ្វើអោយអាចចែករំលែកឯកសារបានអនឡាញ។

- **ម៉ាស៊ីនមេ MCP (ចុងបញ្ចប់ Model Context Protocol)**៖ ចំណុចប្រទាក់ NLWeb គ្រប់គ្រងការងារជាម៉ាស៊ីនមេ MCP ផងដែរ។ នេះមានន័យថាវាអាចចែករំលែកឧបករណ៍ (ដូចជា របៀប "ask") និងទិន្នន័យជាមួយប្រព័ន្ធ AI ផ្សេងៗ។ ប្រសិនបើអនុវត្ត ប្រព័ន្ធនេះធ្វើឲ្យមាតិកា និងសមត្ថភាពគេហទំព័រអាចប្រើបានសម្រាប់ភ្នាក់ងារ AI ឲ្យវាត្រូវបញ្ចូលជាផ្នែកមួយនៃ “ប្រព័ន្ធជំនួយភ្នាក់ងារ”។

- **ម៉ូដែល embedding**៖ ម៉ូដែលទាំងនេះប្រើសម្រាប់បំលែងមាតិកាគេហទំព័រជារូបបួសលេខគេហៅ vectors (embeddings)។ វេកទ័រទាំងនេះចាប់យកអត្ថន័យ ដូច្នេះកុំព្យូទ័រអាចប្រៀបធៀប និងស្វែងរកបាន។ វាទុកក្នុងមូលដ្ឋានទិន្នន័យឯកទេស ហើយអ្នកប្រើអាចជ្រើសរើសម៉ូដែល embedding ដែលចង់ប្រើ។

- **មូលដ្ឋានទិន្នន័យវ៉ែតទ័រ (កិច្ចការចាប់យក)**៖ មូលដ្ឋានទិន្នន័យនេះថតរក្សាផ្សារ embedding នៃមាតិកាគេហទំព័រ។ នៅពេលមានសំណួរ NLWeb ត្រួតពិនិត្យមូលដ្ឋានវ៉ែតទ័រដើម្បីស្វែងរកព័ត៌មានដែលពាក់ព័ន្ធយ៉ាងឆាប់រហ័ស។ វាផ្តល់បញ្ជីចម្លើយដែលមានលំដាប់តាមការភ្ជាប់នៃតំណាងប្រៀបធៀប។ NLWeb ប្រើជាមួយប្រព័ន្ធផ្ទុកវ៉ែតទ័រផ្សេងៗដូចជា Qdrant, Snowflake, Milvus, Azure AI Search និង Elasticsearch។

### NLWeb ជាឧទាហរណ៍

![NLWeb](../../../translated_images/km/nlweb-diagram.c1e2390b310e5fe4.webp)

សូមពិចារណាគេហទំព័រកក់ដំណើរយន្តហោះរបស់យើងម្តងទៀត ប៉ុន្តេលំដាប់នេះវាដំណើរការដោយ NLWeb។

1. **ការបញ្ចូលទិន្នន័យ**: បញ្ជីផលិតផលដែលមានរួច (ដូចជាសារបញ្ជាក់សំបុត្រយន្តហោះ, ពណ៌នាសណ្ឋាគារ, ផ្នែកទេសចរណ៍) ត្រូវបានរៀបចំដោយប្រើ Schema.org ឬបញ្ចូលតាម feed RSS។ ឧបករណ៍ NLWeb របស់វាដកយកទិន្នន័យរចនាសម្ព័ន្ធនេះ បង្កើត embeddings ហើយផ្ទុកវាទៅក្នុងមូលដ្ឋានទិន្នន័យវ៉ែតទ័រផ្សេងៗទាំងក្នុងឬក្រៅ។

2. **សំនួរភាសាធម្មជាតិ (មនុស្ស)**: អ្នកប្រើចូលមើលគេហទំព័រ ហើយទ្វេរៀគ្រប់គ្រងមិនចាំបាច់ប្រើម៉ឺនុយ ប៉ុន្តែវាយសំណួរចូលក្នុងចំណុចជជែក៖ "សូមស្វែងរកសណ្ឋាគារដែលសមស្របសម្រាប់គ្រួសារនៅ Honolulu មានអាងហែលទឹក សម្រាប់សប្តាហ៍ក្រោយ"។

3. **ដំណើរការ NLWeb**: កម្មវិធី NLWeb ទទួលយកសំណួរនេះ។ វាផ្ញើសំណួរនេះទៅ LLM សម្រាប់យល់ អញ្ជើញ ផងដែរត្រួតពិនិត្យមូលដ្ឋានវ៉ែតទ័ររបស់វាសម្រាប់សារបញ្ជាក់សណ្ឋាគារដែលពាក់ព័ន្ធ។

4. **លទ្ធផលត្រឹមត្រូវ**: LLM ជួយបកស្រាយលទ្ធផលស្វែងរកពីមូលដ្ឋានទិន្នន័យ កំណត់ចំណត្ដីល្អបំផុត ដោយផ្អែកលើលក្ខខណ្ឌ "សមស្របសម្រាប់គ្រួសារ", "អាងហែលទឹក", និង "Honolulu" ហើយរៀបចំបញ្ជីចម្លើយនៅក្នុងភាសាធម្មជាតិ។ ចំណុចសំខាន់គឺចម្លើយយោងទៅលើសណ្ឋាគារពិតពីបញ្ជីគេហទំព័រពិត មិនបង្កើតព័ត៌មានរឹតលេចឡើយ។

5. **អន្តរកម្មភ្នាក់ងារ AI**: ព្រោះ NLWeb ធ្វើការជាម៉ាស៊ីនមេ MCP ភ្នាក់ងារ AI ដំណើរយន្តហោះខាងក្រៅអាចភ្ជាប់ទៅលើវេបសាយ NLWeb នេះផងដែរ។ ភ្នាក់ងារ AI អាចប្រើវិធីការ `ask` នៅ MCP ដើម្បីសួរព័ត៌មានលើគេហទំព័រតាមផ្លូវ ត្រឹមត្រូវ៖ `ask("តើមានភោជនីយដ្ឋានស៊ីស végétarianនៅតំបន់ Honolulu ដែលសណ្ឋាគារណែនាំទេ?")`។ វ៉ែតទ័រ NLWeb នឹងដំណើរការសំណួរនេះ ប្រើប្រាស់មូលដ្ឋានទិន្នន័យអំពីភោជនីយដ្ឋាន (បើមាន) ហើយផ្ញើចម្លើយ JSON រចនាសម្ព័ន្ធត្រឡប់វិញ។
