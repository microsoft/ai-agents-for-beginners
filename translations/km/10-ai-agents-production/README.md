# អ្នកតំណាង AI នៅក្នុងការផលិត៖ ការតាមដានភាពយល់ដឹង និងការវាយតម្លៃ

[![AI Agents in Production](../../../translated_images/km/lesson-10-thumbnail.2b79a30773db093e.webp)](https://youtu.be/l4TP6IyJxmQ?si=reGOyeqjxFevyDq9)

នៅពេលដែលអ្នកតំណាង AI ផ្លាស់ប្តូរពីគំរូសាកល្បងទៅជាកម្មវិធីក្នុងពិភពពិត សមត្ថភាពក្នុងការយល់ដឹងអំពីអាកប្បកិរិយារបស់ពួកវា តាមដានការសម្តែងរបស់ពួកវា និងវាយតម្លៃលទ្ធផលរបស់ពួកវាដោយជាក់លាក់ក្លាយទៅជារឿងសំខាន់។

## គោលដៅការសិក្សា

បន្ទាប់ពីបញ្ចប់មេរៀននេះ អ្នកនឹងស្គាល់របៀប/យល់ដោយច្បាស់ពី៖
- គំនិតមូលដ្ឋាននៃការតាមដានភាពយល់ដឹង និងការវាយតម្លៃអ្នកតំណាង
- បច្ចេកទេសសម្រាប់បង្កើនកម្រិតសម្តែង ការចំណាយ និងប្រសិទ្ធភាពរបស់អ្នកតំណាង
- អ្វីខ្លះ និងរបៀបវាយតម្លៃអ្នកតំណាង AI របស់អ្នកយ៉ាងមានប្រព័ន្ធ
- របៀបគ្រប់គ្រងការចំណាយពេលដាក់បញ្ចូលអ្នកតំណាង AI ទៅឧបករណ៍ផលិត
- របៀបដាក់ឧបករណ៍អ្នកតំណាងដែលបានបង្កើតជាមួយ Microsoft Agent Framework

គោលបំណងគឺផ្តល់ចំណេះដឹងដល់អ្នក ដើម្បីបម្លែងអ្នកតំណាង "ប្រអប់ខ្មៅ" របស់អ្នក ទៅជាប្រព័ន្ធតំបន់ចែង មិនស្មុគស្មាញ និងអាចទុកចិត្តបាន។

_**សម្គាល់៖** វាសំខាន់ណាស់ក្នុងការដាក់បញ្ចូលអ្នកតំណាង AI ដែលមានសុវត្ថិភាព និងអាចទុកចិត្តបាន។ សូមពិនិត្យមេរៀន [ការបង្កើតអ្នកតំណាង AI ដែលអាចទុកចិត្តបាន](../06-building-trustworthy-agents/README.md) ផងដែរ។_

## ការតាមដាននិងពេលវេលា

ឧបករណ៍តាមដានភាពយល់ដឹង ដូចជា [Langfuse](https://langfuse.com/) ឬ [Microsoft Foundry](https://learn.microsoft.com/en-us/azure/ai-foundry/what-is-azure-ai-foundry) ជាទូទៅបង្ហាញការផ្អែករបស់អ្នកតំណាងជារូបភាពរំកិលនិងពេលវេលា។

- **ការរំកិល** បង្ហាញពីភារកិច្ចជាប្រភេទមួយទាំងមូលរបស់អ្នកតំណាងពីដើមដល់ចប់ (ដូចជា ការដោះស្រាយសំណួររបស់អ្នកប្រើប្រាស់)។
- **ពេលវេលា** គឺជាជំហាននិច្ចនិច្ចមួយៗនៅក្នុងការរំកិល (ដូចជា ការហៅម៉ូដែលភាសា ឬការទាញយកទិន្នន័យ)។

![​ដើមឈើពេលវេលានៅ Langfuse](https://langfuse.com/images/cookbook/example-autogen-evaluation/trace-tree.png)

បើគ្មានការតាមដានភាពយល់ដឹង អ្នកតំណាង AI អាចមានអារម្មណ៍ដូចជា "ប្រអប់ខ្មៅ" - ស្ថានភាពខាងក្នុង និងគំនិតស្មារតីរបស់វាមានភាពមិនច្បាស់លាស់ ដែលធ្វើឲ្យរឿងធ្វើឲ្យពិបាក់ស្មារ ឬធ្វើអោយលំបាកក្នុងការបញ្ជ្រាបបញ្ហាឬបង្កើនសមត្ថភាព។ ជាមួយការតាមដានភាពយល់ដឹង អ្នកតំណាងក្លាយទៅជាប្រអប់កញ្ចក់ មានភាពច្បាស់លាស់ដែលមានសារៈសំខាន់សម្រាប់ការសាងសង់ការទុកចិត្ត និងធានាថាពួកវាធ្វើប្រតិបត្តិការដូចដែលបានគ្រោង។

## ហេតុអ្វីបានជា ការតាមដានភាពយល់ដឹង មានសារៈសំខាន់នៅបរិយាកាសផលិតកម្ម

ការបញ្ជូនអ្នកតំណាង AI ទៅបរិយាកាសផលិតកម្មនាំឲ្យមានបញ្ហានិងតម្រូវការថ្មីៗ។ ការតាមដានភាពយល់ដឹងមិនមែនជារឿង "ល្អសម្រាប់មាន" ទេ ប៉ុន្តែជាចំណុះសារៈសំខាន់៖

*   **ការត្រួតពិនិត្យកំហុស និងវិភាគមូលហេតុ**៖ នៅពេលអ្នកតំណាងបរាជ័យ ឬបញ្ចេញលទ្ធផលមិនបានរំពឹងទុក ឧបករណ៍តាមដានផ្តល់ការរំកិលដែលចាំបាច់ដើម្បីកំណត់ប្រភពកំហុស។ វាមានសារៈសំខាន់ជាពិសេសក្នុងអ្នកតំណាងស្មុគស្មាញដែលអាចពាក់ព័ន្ធនឹងការហៅ LLM ច្រើន ប្រើឧបករណ៍ និងហេតុផលលក្ខខណ្ឌ។
*   **ការគ្រប់គ្រងភាពយឺត និងការចំណាយ**៖ អ្នកតំណាង AI ជាញឹកញាប់ពឹងផ្អែកលើ LLM និង API ខាងក្រៅផ្សេងទៀតដែលគិតតម្លៃតាមតូកិន ឬការហៅ។ ការតាមដានផ្តល់ឱ្យមានការតាមដានមួលខែប្រហែលនៃការហៅទាំងនេះ ជួយកំណត់ប្រតិបត្តិការដែលយឺត ឬថ្លៃកម្ចីពេក។ វាផ្តល់ឱកាសឲ្យក្រុមឲ្យបង្កើតស.prompt ផ្លាស់ប្តូរ រើសម៉ូដែលមានប្រសិទ្ធភាព ឬប្ដូរគន្លងការងារ ដើម្បីគ្រប់គ្រងការចំណាយប្រតិបត្តិការ និងធានាបទពិសោធន៍អ្នកប្រើល្អ។
*   **ការទុកចិត្ត សុវត្ថិភាព និងការអនុវត្តតាមច្បាប់**៖ នៅក្នុងកម្មវិធីជាច្រើន វាសំខាន់ក្នុងការធានាថាអ្នកតំណាងដើរតួដោយសុវត្ថិភាព និងផ្អែកលើសីលធម៌។ ការតាមដានផ្តល់ខ្សែសង្វាក់ត្រួតពិនិត្យកម្មវិធីនិងសំឡេងចិត្តអ្នកតំណាង។ វាអាចប្រើសម្រាប់រកឃើញ និងកាត់បន្ថយបញ្ហាដូចជា ការជំរុញបញ្ហា ការបង្កើតខ្លឹមសារបានផ្ទាល់ខ្លួន ឬការកាន់កាប់ព័ត៌មានផ្ទាល់ខ្លួន (PII) មិនបានត្រឹមត្រូវ។ ឧទាហរណ៍ អ្នកអាចពិនិត្យការរំកិលដើម្បីយល់ច្បាស់ថា ហេតុអ្វីបានជាអ្នកតំណាងផ្តល់ចម្លើយមួយ ឬប្រើឧបករណ៍មួយ។
*   **លំហូរកែប្រែបន្តអស្វីយ៍**៖ ទិន្នន័យតាមដានភាពយល់ដឹងជាគ្រឹះសម្រាប់ដំណើរការអភិវឌ្ឍជារយៈពេល។ ដោយតាមដានសមត្ថភាពអ្នកតំណាងនៅក្នុងពិភពពិត ក្រុមអាចកំណត់តំបន់ដែលត្រូវធ្វើឲ្យប្រសើរ មានការប្រមូលទិន្នន័យសម្រាប់បង្វឹកម៉ូដែល និងផ្ទៀងផ្ទាត់ឥទ្ធិពលនៃការផ្លាស់ប្តូរ។ វាបង្កើតលំហូរប្រតិកម្ម ដែលពីទស្សន៍ការពិតក្នុងការវាយតម្លៃលើអ៊ីនធឺណែតជួយដឹកនាំការសាកសម្រួល និងកែប្រែក្រៅបណ្ដាញ ដែលនាំឲ្យសមត្ថភាពអ្នកតំណាងប្រសើរឡើងជាបន្តបន្ទាប់។

## តួអង្គសំខាន់ៗដែលត្រូវតាមដាន

ដើម្បីតាមដាននិងយល់ពីអាកប្បកិរិយារៃយន្ត អ្នកគួរតាមដានតួអង្គនិងសញ្ញាបានច្រើន។ ទោះជាតួអង្គជាក់លាក់អាចប្រែប្រួលទៅតាម​គោលបំណងរបស់អ្នកតំណាង ក៏មានតួអង្គខ្លះដែលមានសារៈសំខាន់ទូទៅ។

នេះគឺជាកត្តាជាទូទៅដែលឧបករណ៍តាមដានភាពយល់ដឹងតាមដាន៖

**ពេលវេលា៖** តើអ្នកតំណាងឆ្លើយតបយ៉ាងលឿនដល់ណា? ពេលរង់ចាំយូរមានប្រសិទ្ធភាពប៉ះពាល់អាកប្បកិរិយាអ្នកប្រើ។ អ្នកគួរវាស់ពេលវេលាសម្រាប់ភារកិច្ចនិងជំហានបុគ្គលដោយតាមដានការរត់អ្នកតំណាង។ ឧទាហរណ៍ អ្នកតំណាងដែលចំណាយ ២០ វិនាទីសម្រាប់ការហៅម៉ូដែលទាំងមូលអាចត្រូវបានលឿនឡើងជាមួយម៉ូដែលដែលលឿនជាងឬរត់ការហៅម៉ូដែលជារួម।

**ចំណាយ៖** តើតម្លៃក្នុងមួយដំណើរការអ្នកតំណាងជាអ្វី? អ្នកតំណាង AI ពឹងលើការហៅ LLM ដែលគិតតម្លៃតាមតូកិន ឬ API ខាងក្រៅ។ ការប្រើឧបករណ៍ជាញឹកញាប់ ឬការបញ្ចូលពាក្យច្រើនបង្កើនការចំណាយយ៉ាងឆាប់រហ័ស។ ឧទាហរណ៍ ប្រសិនបើអ្នកតំណាងហៅ LLM ចំនួន៥ដងសម្រាប់ការកែលម្អគុណភាពស្រាល អ្នកត្រូវវាយតម្លៃថាតម្លៃនេះមានតម្លៃសមរម្យឬអត់ ឬអ្នកអាចកាត់បន្ថយចំនួនការហៅ ឬប្រើម៉ូដែលថោកជាង។ ការតាមដានក្នុងពេលប្រាកដអាចជួយកំណត់កំណើតបូកបន្ថែមមិនរំពឹងទុក (ដូចជា កំហុសបង្កើតរង្វិល API លើសកំណត់)។

**កំហុសសំណើរ៖** តើមានចំនួនប៉ុន្មានសំណើរដែលអ្នកតំណាងបរាជ័យ? វាអាចរួមបញ្ចូលកំហុស API ឬការហៅឧបករណ៍បរាជ័យ។ ដើម្បីធ្វើឲ្យអ្នកតំណាងរឹងមាំប្រឆាំងគ្នានៅក្នុងកម្មវិធីផលិត អ្នកអាចដាក់ទំព័រផ្ទុកជំនួស ឬការព្យាយាមម្ដងទៀត។ ឧ. ប្រសិនបើអ្នកផ្គត់ផ្គង់ LLM A បរាជ័យ អ្នកប្តូរទៅ LLM B ជាជំនួស។

**មតិយោបល់អ្នកប្រើ៖** ការអនុវត្តការវាយតម្លៃដោយផ្ទាល់ពីអ្នកប្រើផ្តល់ព័ត៌មានមានតម្លៃ។ វាអាចរួមបញ្ចូលការវាយតម្លៃច្បាស់លាស់ (👍អំណោយចិត្ត/👎មិនពេញចិត្ត, ⭐1-5ផ្លូវ) ឬមតិយោបល់អត្ថបទ។ មតិយោបល់អវិជ្ជមានជាប់ទៀងទាត់គួរតែជំរុញអ្នកព្រមានថា អ្នកតំណាងមិនដំណើរការតាមដែលបានប្រាថ្នា។

**មតិយោបល់អ្នកប្រើដែលមិនច្បាស់លាស់៖** អាកប្បកិរិយាអ្នកប្រើផ្តល់មតិយោបល់អនាមិក ទោះបីគ្មានការវាយតម្លៃច្បាស់លាស់ក៏ដោយ។ វាអាចចូលរួមការផ្លាស់ប្តូរសំណួរបន្ទាន់ ការសួរឡើងវិញជាច្រើនដង ឬចុចប៊ូតុងព្យាយាមម្ដងទៀត។ ឧ. ប្រសិនបើអ្នកឃើញអ្នកប្រើសួរសំណួរដដែលជាបន្តបន្ទាប់ នេះជាសញ្ញាថាអ្នកតំណាងមិនដំណើរការតាមការរំពឹងទុក។

**ភាពត្រឹមត្រូវ៖** តើអ្នកតំណាងផ្តល់លទ្ធផលត្រឹមត្រូវ ឬលទ្ធផលដែលគួរឱ្យចង់បានយ៉ាងឆាប់រហ័សប៉ុនណា? ការកំណត់ភាពត្រឹមត្រូវប្រែប្រួលតាមការ (ដូចជា ត្រឹមត្រូវក្នុងការដោះស្រាយបញ្ហា, ត្រឹមត្រូវក្នុងការទាញយកព័ត៌មាន, ភាពពេញចិត្តអ្នកប្រើ) ជំហានដំបូងគឺកំណត់ថា តើជោគជ័យសម្រាប់អ្នកតំណាងរបស់អ្នកមានទ្រង់ទ្រាយយ៉ាងដូចម្តេច។ អ្នកអាចតាមដានភាពត្រឹមត្រូវតាមការត្រួតពិនិត្យស្វ័យប្រវត្តិ ពិន្ទុការវាយតម្លៃ ឬស្លាកបញ្ចប់ភារកិច្ច។ ឧទាហរណ៍ កំណត់ការរំកិលជាទីតាំង "ជោគជ័យ" ឬ "បរាជ័យ"។

**តួអង្គវាយតម្លៃស្វ័យប្រវត្តិ៖** អ្នកអាចក៏ដាក់ឧបករណ៍វាយតម្លៃស្វ័យប្រវត្តិបានផង។ ឧទាហរណ៍ អ្នកអាចប្រើ LLM ដើម្បីវាយតម្លូវលទ្ធផលរបស់អ្នកតំណាង ខាងលើដូចជា ប្រសិទ្ធភាព ត្រឹមត្រូវ ឬមិនមែន។ មានបណ្ណាល័យប្រភពបើកជាច្រើនជួយអ្នកវាយតម្លៃក្ដីលម្អិតផ្សេងៗនៃអ្នកតំណាង។ ឧ. [RAGAS](https://docs.ragas.io/) សម្រាប់អ្នកតំណាង RAG ឬ [LLM Guard](https://github.com/protectai/llm-guard) សម្រាប់រកភាសាអាក្រក់ ឬការជំរុញបញ្ហា។

ក្នុងការអនុវត្ត ការរួមបញ្ចូលនៃតួអង្គទាំងនេះផ្តល់ការឆ្លើយតបល្អបំផុតលើសុខភាពអ្នកតំណាង AI។ នៅក្នុងជំពូកនេះ [សៀវភៅគំរូ](./code_samples/10-expense_claim-demo.ipynb) យើងនឹងបង្ហាញអ្នកថាតួអង្គទាំងនេះហាក់ដូចម្ដេច ក្នុងគំរូពិត ប៉ុន្តាមុនណា យើងនឹងរៀនពីរបៀបធ្វើដំណើរការវាយតម្លៃទូទៅ។

## ដាក់ឧបករណ៍ឲ្យអ្នកតំណាងរបស់អ្នក

ដើម្បីប្រមូលទិន្នន័យការតាមដាន អ្នកត្រូវតែដាក់ឧបករណ៍កូដរបស់អ្នក។ គោលបំណងគឺដាក់ឧបករណ៍កូដអ្នកតំណាងដើម្បីបញ្ចេញការរំកិល និងតួអង្គដែលអាចចាប់យក ពន្លឿន និងបង្ហាញដោយវេទិកាតាមដានភាពយល់ដឹង។

**OpenTelemetry (OTel):** [OpenTelemetry](https://opentelemetry.io/) គឺជាស្តង់ដារសំខាន់របស់ឧស្សាហកម្មសម្រាប់ការតាមដាន LLM។ វាផ្តល់ឧបករណ៍ API, SDK និងឧបករណ៍សម្រាប់បង្កើត ប្រមូល និងនាំចេញទិន្នន័យតេលេមិច។

មានបណ្ណាល័យការដាក់ឧបករណ៍ជាច្រើនដែលបិទស្រទាប់អ្នកតំណាងដែលមានស្រាប់ ហើយធ្វើឲ្យវាងាយស្រួលក្នុងការនាំចេញ OpenTelemetry spans ទៅឧបករណ៍តាមដានភាពយល់ដឹង។ Microsoft Agent Framework ចូលរួមជាមួយ OpenTelemetry ដោយមានផ្ទាល់។ ខាងក្រោមជាគំរូនៅក្នុងការដាក់ឧបករណ៍អ្នកតំណាង MAF៖

```python
from agent_framework.observability import get_tracer, get_meter

tracer = get_tracer()
meter = get_meter()

with tracer.start_as_current_span("agent_run"):
    # Agent execution is traced automatically
    pass
```

សៀវភៅគំរូ [example notebook](./code_samples/10-expense_claim-demo.ipynb) ក្នុងជំពូកនេះនឹងបង្ហាញរបៀបដាក់ឧបករណ៍ក្នុងអ្នកតំណាង MAF របស់អ្នក។

**ការបង្កើត Span ដោយដៃ:** ខណ:ដែលបណ្ណាល័យដាក់ឧបករណ៍ផ្តល់ជាបរិមាណល្អ ប៉ុន្តាក៏មានករណីដែលត្រូវការព័ត៌មានលំអិត ឬផ្ទាល់ខ្លួនបន្ថែម។ អ្នកអាចបង្កើត spans ដោយដៃដើម្បីបញ្ចូលតុល្យភាពកម្មវិធីបុគ្គល។ ជាអ្វីដែលសំខាន់ជាងគេ គេចង្អុលថាពួកវាអាចបន្ថែមទ្រព្យសម្បត្តិឈ្មោះផ្ទាល់ខ្លួន (ហៅថា តាក ឬមេតាដាតា) ជាគ្រឿងបន្ថែមដោយស្វ័យប្រវត្តិ ឬដោយដៃ។ ទ្រព្យសម្បត្តិទាំងនេះអាចរួមបញ្ចូលទិន្នន័យជាក់លាក់អាជីវកម្ម ការគណនាផ្នែកកណ្តាល ឬបរិបទផ្សេងៗដែលអាចមានប្រយោជន៍សម្រាប់ត្រួតពិនិត្យកំហុសឬវិភាគដូចជា `user_id`, `session_id`, ឬ `model_version`។

ឧទាហរណ៍ការបង្កើតការរំកិល និងពេលវេលាដោយដៃជាមួយ [Langfuse Python SDK](https://langfuse.com/docs/sdk/python/sdk-v3):

```python
from langfuse import get_client
 
langfuse = get_client()
 
span = langfuse.start_span(name="my-span")
 
span.end()
```

## ការវាយតម្លៃអ្នកតំណាង

ការតាមដានផ្តល់ជាមาต្រយោគ ប៉ុន្តែការវាយតម្លៃគឺជាដំណើរការវិភាគទិន្នន័យនោះ (និងបំពេញតេស្ត) ដើម្បីកំណត់ពីបរិមាណការសម្តែងរបស់អ្នកតំណាង AI និងរបៀបដែលវាអាចត្រូវបានកែប្រែ។ និយាយផ្សេងទៀត ពេលដែលអ្នកមានការរំកិលនិងតួអង្គទាំងនេះ អ្នកប្រើវាដើម្បីវាយតម្លៃអ្នកតំណាង និងធ្វើសេចក្តីសម្រេចចិត្តយ៉ាងដូចម្តេច?

ការវាយតម្លៃធម្មតាមានសារៈសំខាន់ ដោយសារអ្នកតំណាង AI ជាញឹកញាប់មិនទទួលបានលទ្ធផលដូចគ្នា ហើយអាចប្លែកផ្លាស់ប្តូរ (តាមរយៈកម្មវិធីបន្ថែម ឬការផ្លាស់ប្តូរអាកប្បកិរិយាម៉ូដែល) – គ្មានការវាយតម្លៃ អ្នកនឹងមិនដឹងថា អ្នកតំណាង "ឆ្លាត" របស់អ្នកកំពុងធ្វើកិច្ចការជាល្អ ឬត្រូវបានធ្លាក់ក្រោមឡើងវិញឬអត់។

មានប្រភេទការវាយតម្លៃពីរ​សម្រាប់​អ្នក​តំណាង AI ៖ **ការវាយតម្លៃតាមអ៊ិនធឺណិត** និង **ការវាយតម្លៃក្រៅអ៊ិនធឺណិត**។ ទាំងពីរមានតម្លៃ ហើយពួកវាដំណើរការជាមួយគ្នា។ យើងភាគច្រើនចាប់ផ្តើមជាមួយការវាយតម្លៃក្រៅអ៊ិនធឺណិត ដោយជាជំហានតិចតួចបំផុតមុនដាក់បញ្ចូលអ្នកតំណាងណាមួយ។

### ការវាយតម្លៃក្រៅអ៊ិនធឺណិត

![ធាតុទិន្នន័យក្នុង Langfuse](https://langfuse.com/images/cookbook/example-autogen-evaluation/example-dataset.png)

នេះពាក់ព័ន្ធនឹងការវាយតម្លៃអ្នកតំណាងក្នុងបរិដ្ឋានដែលត្រូវបានគ្រប់គ្រង ពាណិជ្ជកម្មជាធម្មតាមានការប្រើប្រាស់ឈុតទិន្នន័យសាកល្បង មិនមែនសំណួរអ្នកប្រើផ្ទាល់។

ឧទាហរណ៍ ប្រសិនបើអ្នកបានបង្កើតអ្នកតំណាងដោះស្រាយបញ្ហាគណិតវិទ្យា ពួកអ្នកអាចមាន[ឈុតទិន្នន័យសាកល្បង](https://huggingface.co/datasets/openai/gsm8k) របស់បញ្ហា១០០ខុសគ្នាដែលមានចម្លើយដឹងជាមុន។ ការវាយតម្លៃក្រៅអ៊ិនធឺណិតភាគច្រើនធ្វើឡើងក្នុងដំណើរការអភិវឌ្ឍ (និងអាចជាផ្នែកនៃដំណើរការជាប់រួម CI/CD) ដើម្បីពិនិត្យកែប្រែឬការពារ​ការធ្លាក់ប្រសិទ្ធភាព។ ចំណាប់អារម្មណ៍គឺវា **អាចធ្វើឡើងឡើងទៀត និងអ្នកអាចទទួលបានតួអង្គភាពត្រឹមត្រូវច្បាស់ចំពោះការមានផែនដីពិត**។ អ្នកអាចដាក់សំណួរអ្នកប្រើប្រាស់និងវាស់ការឆ្លើយតបរបស់អ្នកតំណាងប្រឆាំងនឹងចម្លើយល្អឬប្រើតួអង្គវាយតម្លៃស្វ័យប្រវត្តិដូចបានពិពណ៌នា។

បញ្ហាសំខាន់ជាមួយការវាយតម្លៃក្រៅអ៊ិនធឺណិត គឺធានាថា ឈុតទិន្នន័យសាកល្បងរបស់អ្នកគ្រប់គ្រាន់ និងនៅមានសារៈសំខាន់ – អ្នកតំណាងអាចសម្យដោយល្អលើឈុតសាកល្បងថេរ តែប៉ះការសំណួរផ្ទាល់ខ្លួនមានភាពខុសគ្នាខ្លាំងនៅក្នុងការផលិត។ ដូច្នេះ អ្នកគួរប្រមូលឈុតសាកល្បងដែលធ្វើបច្ចុប្បន្នភាពជាមួយករណីគម្លាតថ្មីៗ និងគំរូដែលបង្ហាញពីស្ថានភាពពិភពពិត។ ការរួមបញ្ចូលរវាងករណី "សាកល្បងឈក់ផ្សែង" តូចៗ និងឈុតវាយតម្លៃធំៗមានប្រយោជន៍៖ ឈុតតូចសម្រាប់ពិនិត្យរហ័ស និងឈុតធំសម្រាប់មាត្រដ្ឋានសមត្ថភាពទូលំទូលាយ។

### ការវាយតម្លៃតាមអ៊ិនធឺណិត

![ទិដ្ឋភាពទូទៅតួអង្គតាមដានភាពយល់ដឹង](https://langfuse.com/images/cookbook/example-autogen-evaluation/dashboard.png)

នេះជាការវាយតម្លៃអ្នកតំណាងក្នុងបរិដ្ឋានជាក់ស្តែង ពេលប្រើប្រាស់ពិតប្រាកដនៅផលិតកម្ម។ ការវាយតម្លៃតាមអ៊ិនធឺណិតជាប់នឹងកំណត់សមត្ថភាពអ្នកតំណាងលើការប្រាស្រ័យទាក់ទងជាមួយអ្នកប្រើប្រាស់ពិតប្រាកដ ហើយវិភាគលទ្ធផលជាបន្តបន្ទាប់។

ឧទាហរណ៍ អ្នកអាចតាមដានអត្រាជោគជ័យ ពិន្ទុភាពពេញចិត្តអ្នកប្រើ ឬតួអង្គផ្សេងៗលើចរាចរណ៍ផ្ទាល់។ អត្ថប្រយោជន៍នៃការវាយតម្លៃតាមអ៊ិនធឺណិតគឺវា **ចាប់យកអ្វីដែលអ្នកអាចមិនរំពឹងទុកនៅក្នុងបរិយាកាសមន្ទីរពិសោធន៍** – អ្នកអាចឃើញការបម្លាស់ប្ដូរម៉ូដែលជាលំដាប់ពេល (បើសមត្ថភាពអ្នកតំណាងខូចចុះពេលប្លង់ទិន្នន័យបញ្ចូលផ្លាស់ប្ដូរ) និងចាប់បានសំណួរឬស្ថានការណ៍មិនរំពឹងទុកដែលមិនមាននៅក្នុងទិន្នន័យសាកល្បងរបស់អ្នក។ វាបង្ហាញរូបភាពពិតប្រាកដពីរបៀបដែលអ្នកតំណាងមានអាកប្បកិរិយានៅលើទីផ្សារ។

ការវាយតម្លៃតាមអ៊ិនធឺណិតជាធម្មតាចូលរួមការប្រមូលមតិយោបល់អ្នកប្រើយ៉ាងច្បាស់និងលាក់ បញ្ចូលការប្រតិបត្តិតេស្តស្រដៀង ឬអេ/ប៊ី តេស្ត (ដែលកំណត់ថាវគ្មិនថ្មីរត់លើបណ្ដាញជាគូរ ដើម្បីប្រៀបធៀបទៅនឹងវគ្មិនចាស់)។ បញ្ហានៃការប្រមូលស្លាក ឬពិន្ទុសម្រាប់អន្តរកម្មបែបនេះគ្រាន់តែពិបាក – អ្នកអាចពឹងផ្អែកលើមតិយោបល់អ្នកប្រើ ឬមាត្រដ្ឋានក្រោយ (ដូចជា អ្នកប្រើបានចុចលទ្ធផលឬអត់)។

### ការលាយបញ្ចូលពីរនេះ

ការវាយតម្លៃតាមអ៊ិនធឺណិត និងក្រៅអ៊ិនធឺណិត មិនមែនជាផ្ទុយពីគ្នាទេ; ពួកវាជាជំនួយគ្នាយ៉ាងខ្លាំង។ ចំណេះដឹងពីការតាមដានតាមអ៊ិនធឺណិត (ឧ. ប្រភេទសំណួរថ្មីៗដែលអ្នកតំណាងឆ្លើយតបមិនបានល្អ) អាចប្រើសម្រាប់បន្ថែមនិងធ្វើឲ្យឈុតទិន្នន័យសាកល្បងក្រៅអ៊ិនធឺណិតកាន់តែប្រសើរ។ ផ្ទុយមកវិញ អ្នកតំណាងដែលសម្តែងល្អនៅក្នុងសាកល្បងក្រៅអ៊ិនធឺណិត បន្ទាប់មកអាចដាក់បញ្ចូល ដោយមានការត្រួតពិនិត្យតាមអ៊ិនធឺណិតជំនួយ។

ពិតប្រាកដ ក្រុមជាច្រើនដំណើរការលំហូរ៖

_វាយតម្លៃក្រៅអ៊ិនធឺណិត -> ដាក់បញ្ចូល -> តាមដានតាមអ៊ិនធឺណិត -> ប្រមូលករណីបរាជ័យថ្មី -> បន្ថែមទៅឈុតទិន្នន័យក្រៅអ៊ិនធឺណិត -> កែលម្អអ្នកតំណាង -> ថយវិញ_។

## ការគ្រប់គ្រងការចំណាយ

នេះជាយុទ្ធសាស្ត្រចម្លងពីការគ្រប់គ្រងការចំណាយក្នុងការដាក់បញ្ចូលអ្នកតំណាង AI ទៅផលិតកម្ម៖

**ការប្រើម៉ូដែលតូចបន្ថែម:** ម៉ូដែលភាសាតូច (SLMs) អាចធ្វើបានល្អលើករណីប្រើប្រភេទហ្សែនដែលជាក់លាក់មួយចំនួន និងនឹងកាត់បន្ថយការចំណាយបានយ៉ាងហោចណាស់។ ដូចដែលបានกล่าวពីមុន ការសាងសង់ប្រព័ន្ធវាយតម្លៃដើម្បីកំណត់និងប្រៀបធៀបការសម្តែងប្រាប់ ប្រៀបធៀបនឹងម៉ូដែលធំធេងគឺជាវិធីល្អបំផុតដើម្បីយល់ថា SLM នឹងអាចបំពេញការងារបានល្អប៉ុនណានៅលើករណីប្រើរបស់អ្នក។ យកចិត្តទុកដាក់ក្នុងការប្រើ SLM សម្រាប់ភារកិច្ចដែលសាមញ្ញដូចជាការបែងចែកបំណង ឬការដកយកប៉ារ៉ាម៉ែត្រ ទៅវិញទៅមករក្សាទុកម៉ូដែលធំសម្រាប់ការត្រួតពិនិត្យដំណើរការដ៏ស្មុគស្មាញ។

**ការប្រើម៉ូដែលរ៉ូតែ:** វិធីសាស្ត្រដូចគ្នានេះគឺការប្រើម៉ូដែលនិងទំហំជាច្រើនប្រភេទ។ អ្នកអាចប្រើ LLM/SLM ឬមុខងារ serverless ដើម្បីរ៉ូតការស្នើសុំផ្អែកលើភាពស្មុគស្មាញទៅលើម៉ូដែលសមស្របបំផុត។ នេះក៏ជួយកាត់បន្ថយការចំណាយខ្លាំងណាស់ ខណៈពេលដែលធានាប្រសិទ្ធភាពលើភារកិច្ចត្រឹមត្រូវ។ ឧទាហរណ៍ រ៉ូតសំណួរងាយៗទៅម៉ូដែលតូចដែលរហ័ស ហើយប្រើម៉ូដែលធំដែលតម្លៃថ្លៃសម្រាប់ភារកិច្ចត្រួតពិនិត្យស្មុគស្មាញតែប៉ុណ្ណោះ។

**ការកាន់ជំរូវការឆ្លើយតប:** ការសម្គាល់សំណើជាទូទៅនិងភារកិច្ច ហើយផ្តល់ចម្លើយជាមុនគឺជាវិធីល្អក្នុងការកាត់បន្ថយបរិមាណសំណើដូចគ្នា។ អ្នកអាចអនុវត្តន៍ចរន្ត ដើម្បីសម្គាល់ថាសំណើមានស្រដៀងទៅនឹងសំណើកាន់ជំរូវរបស់អ្នកប៉ុណ្ណា ដោយប្រើម៉ូដែល AI ហេតុផលសាមញ្ញជាងនេះ។ វិធីសាស្ត្រនេះអាចកាត់បន្ថយចំណាយយ៉ាងខ្លាំងសម្រាប់សំណួរដែលសួរញឹកញាប់ ឬដំណើរការស្រាលៗ។
