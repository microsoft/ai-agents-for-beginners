# អ្នកប្រតិបត្តិ AI ក្នុងផលិតកម្ម: ចំណុចដែលអាចមើលឃើញ និងការវាយតម្លៃ

[![AI Agents in Production](../../../translated_images/km/lesson-10-thumbnail.2b79a30773db093e.webp)](https://youtu.be/l4TP6IyJxmQ?si=reGOyeqjxFevyDq9)

នៅពេលដែលអ្នកប្រតិបត្តិ AI ផ្លាស់ប្តូរពីគំរូសាកល្បងទៅជាកម្មវិធីពិតប្រាកដនៅក្នុងពិភពជាក់ស្តែង, ការរួមចំណេះដឹងអំពីរបៀបដំណើរការ, ការត្រួតពិនិត្យការអនុវត្ត និងការវាយតម្លៃលទ្ធផលយ៉ាងមានរបៀបកណ្តាលក្លាយជារឿងសំខាន់។

## គោលបំណងការសិក្សា

បន្ទាប់ពីបញ្ចប់មេរៀននេះអ្នកនឹងបានដឹងរបៀប / ព្រមមានបទពិសោធន៍៖
- គំនិតមូលដ្ឋានអំពីការមើលឃើញនិងការវាយតម្លៃអ្នកប្រតិបត្តិ
- បច្ចេកទេសសម្រាប់បង្កើនការអន្ដរាគមន៍, ការចំណាយ និងប្រសិទ្ធភាពរបស់អ្នកប្រតិបត្តិ
- តើអ្វី និងរបៀបវាយតម្លៃអ្នកប្រតិបត្តិ AI របស់អ្នកយ៉ាងមានរបៀប
- របៀបគ្រប់គ្រងការចំណាយពេលបញ្ចូនអ្នកប្រតិបត្តិ AI ទៅក្នុងផលិតកម្ម
- របៀបបំពាក់ឧបករណ៍វាស់វែងសម្រាប់អ្នកប្រតិបត្តិដែលបង្កើតដោយMicrosoft Agent Framework

គោលបំណងគឺផ្ដល់ចំណេះដឹងដើម្បីបំលែងអ្នកប្រតិបត្តិ "ប្រអប់ខ្មៅ" របស់អ្នកទៅជាប្រព័ន្ធដែលច្បាស់លាស់, អាចគ្រប់គ្រងបាន និងគួរឱ្យទុកចិត្ត។

_**ចំណាំ:** វាសំខាន់ក្នុងការផ្ទុកបញ្ចូលអ្នកប្រតិបត្តិ AI ដែលមានសុវត្ថិភាព និងទុកចិត្តបាន។ សូមពិនិត្យមេរៀន [ការសាងសង់អ្នកប្រតិបត្តិ AI ដ៏ទុកចិត្តបាន](../06-building-trustworthy-agents/README.md) ផងដែរ។_

## បន្ទាត់តាមដាន និងការពង្រីក

ឧបករណ៍មើលឃើញដូចជា [Langfuse](https://langfuse.com/) ឬ [Microsoft Foundry](https://learn.microsoft.com/en-us/azure/ai-foundry/what-is-azure-ai-foundry) តែងតែបង្ហាញការប្រតិបត្តិអ្នកប្រតិបត្តិជាបន្ទាត់តាមដាន និងការពង្រីក។

- **បន្ទាត់តាមដាន** សំដៅលើភារការដំណើរការជាសរុបរបស់អ្នកប្រតិបត្តិចាប់ចាប់ពីដំណើរការដល់ការសម្រេច (ដូចជាការដោះស្រាយសំណួរជម្រាបអ្នកប្រើ)។
- **ការពង្រីក** មានន័យថាជជំហាននីមួយៗក្នុងបន្ទាត់តាមដាន (ដូចជាការហៅម៉ូដែលភាសា ឬការទាញយកទិន្នន័យ)។

ដោយគ្មានការមើលឃើញ អ្នកប្រតិបត្តិ AI អាចមានអារម្មណ៍ដូចជាប្រអប់ខ្មៅ — ស្ថានភាពខាងក្នុង និងហេតុផលរបស់វាមិនច្បាស់លាស់ បង្កើតការលំបាកក្នុងការវិភាគបញ្ហា ឬបង្កើនប្រសិទ្ធភាព។ ជាមួយការមើលឃើញអ្នកប្រតិបត្តិក្លាយជាប្រអប់កែវ ផ្ដល់នូវភាពច្បាស់លាស់ ដែលសំខាន់សម្រាប់បង្កើតការទុកចិត្ត និងធ្វើឲ្យដំណើរការត្រូវបានគេគ្រប់គ្រងតាមបំណង។

## ហេតុផលដែលការមើលឃើញមានសារៈសំខាន់នៅបរិស្ថានផលិតកម្ម

ការផ្លាស់ប្តូរអ្នកប្រតិបត្តិ AI ទៅបរិស្ថានផលិតកម្ម បង្កើតបញ្ហា និងតម្រូវការថ្មីៗ។ ការមើលឃើញមិនមែនគ្រាន់តែជាចំណង់ចំណូលចិត្តទេ ប៉ុន្តែជាចំណុចសំខាន់មួយ៖

*   **ការដោះស្រាយបញ្ហា និងវិភាគមូលហេតុ៖** នៅពេលដែលអ្នកប្រតិបត្តិបរាជ័យ ឬផលិតលទ្ធផលមិនរំពឹងទុក ឧបករណ៍មើលឃើញផ្ដល់បន្ទាត់តាមដានដែលចាំបាច់ ដើម្បីកំណត់ប្រភពកំហុស។ វាសំខាន់ពិសេសនៅក្នុងអ្នកប្រតិបត្តិតំបន់ស្មុគស្មាញដែលអាចមានការហៅ LLMs ច្រើនការប្រើប្រាស់ឧបករណ៍ និងហេតុផលលក្ខខណ្ឌ។
*   **ការ​គ្រប់គ្រងពេលពន្យាចរ និងការចំណាយ៖** អ្នកប្រតិបត្តិ AI ជាញឹកញាប់ពឹងផ្អែកលើ LLM និង API ខាងក្រៅ ដែលគិតថ្លៃជាបន្តបន្ទាប់ដោយជាតុកិន ឬក៏ដោយការហៅ។ ការមើលឃើញអនុញ្ញាតឲ្យតាមដានការហៅទាំងនេះយ៉ាងច្បាស់ បង្កើតឱកាសសម្រាប់រកឃើញប្រតិបត្តិការដែលយឺត ឬមានថ្លៃច្រើនពេក។ វាជួយក្រុមការងារបង្កើនប្រសិទ្ធភាពការបញ្ជូន, ជ្រើសរើសម៉ូដែលមានប្រសិទ្ធភាពខ្ពស់ ឬធ្វើការកែសម្រួលការរចនាវិធីសាស្រ្ត ដើម្បីគ្រប់គ្រងការចំណាយប្រតិបត្តិការ និងធានាបាននូវបទពិសោធន៍ប្រើប្រាស់ល្អ។
*   **ការទុកចិត្ត, សុវត្ថិភាព និងការអនុលោមគោលនយោបាយ៖** នៅក្នុងកម្មវិធីជាច្រើន វាសំខាន់ក្នុងការធានាថាអ្នកប្រតិបត្តិមានអាកប្បកិរិយាសុវត្ថិ និងត្រឹមត្រូវតាមច្បាប់។ ការមើលឃើញផ្ដល់ប្រវត្តិការត្រួតពិនិត្យសកម្មភាព និងសេចក្ដីសម្រេចរបស់អ្នកប្រតិបត្តិ។ វាអាចប្រើសម្រាប់រកឃើញ និងកាត់បន្ថយបញ្ហា ដូចជាការវាយប្រហារដោយបញ្ចូលសេចក្ដីបញ្ជា (prompt injection), ការបង្កើតមាតិកាដែលមានគ្រោះថ្នាក់, ឬការគ្រប់គ្រងមិនល្អនូវព័ត៌មានផ្ទាល់ខ្លួន (PII)។ ឧទាហរណ៍ អ្នកអាចពិនិត្យបន្ទាត់តាមដាន ដើម្បីយល់ថាតើហេតុអ្វីបានជា អ្នកប្រតិបត្តិបានផ្តល់ចម្លើយមួយ ឬប្រើឧបករណ៍ជាក់លាក់មួយ។
*   **វដ្តកែលម្អបន្តរបន្ត:** ទិន្នន័យមើលឃើញគឺជាគ្រឹះសម្រាប់ដំណើរការអភិវឌ្ឍន៍ស្ទាក់ស្ទើរ។ តាមដានរបៀបដែលអ្នកប្រតិបត្តិធ្វើការ នៅក្នុងពិភពជាក់ស្តែង ក្រុមការងារអាចកំណត់តំបន់ដែលត្រូវបានឱ្យកែលម្អ បញ្ចូលទិន្នន័យសម្រាប់កែសម្រួលម៉ូដែល ឬផ្ទៀងផ្ទាត់ផលប៉ះពាល់នៃការផ្លាស់ប្ដូរ។ វាបង្កើតវដ្តបិទ ដែលព័ត៌មានផលិតកម្មពីការវាយតម្លៃលើបណ្ដាញធ្វើឲ្យមានការសាកល្បង និងកែលម្អក្រៅបណ្ដាញ បណ្ដាលអោយមានប្រសិទ្ធភាពអ្នកប្រតិបត្តិល្អឡើងជាដំណាក់កាល។

## អត្រានៅសំខាន់ដែលត្រូវតាមដាន

ដើម្បីត្រួតពិនិត្យនិងយល់ដឹងអំពីអាកប្បកិរិយា អ្នកប្រតិបត្តិ មានតម្រូវការតាមដានសញ្ញានិងវិមាត្រជាច្រើន។ ទោះបីវិមាត្រពិសេសអាចប្រែប្រួលទៅតាមគោលបំណងនៃអ្នកប្រតិបត្តិ ក៏យ៉ាងណាក៏ដោយ មានខ្លះដែលមានសារៈសំខាន់ទូទៅ។

នេះជាវិមាត្រដែលឧបករណ៍មើលឃើញជាច្រើនតាមដាន៖

**ពេលយឺត:** តើអ្នកប្រតិបត្តិឆ្លើយតបបានរហូតដល់កម្រិតណា? ពេលរង់ចាំយូរពេកប៉ះពាល់អវិជ្ជមានដល់បទពិសោធន៍អ្នកប្រើ។ អ្នកគួរវាស់ពេលយឺតសម្រាប់ភារការនិងជំហាននីមួយៗដោយតាមដានការប្រតិបត្តិរបស់អ្នកប្រតិបត្តិ។ ឧទាហរណ៍ អ្នកប្រតិបត្តិដែលចំណាយ 20 វិនាទីសម្រាប់ហៅម៉ូដែលទាំងអស់អាចត្រូវបានបើកលឿនជាងមុនដោយប្រើម៉ូដែលលឿន ឬហៅម៉ូដែលជាច្រើននៅពេលតែមួយ។

**ការចំណាយ:** តើតម្លៃសម្រាប់រាល់ការប្រតិបត្តិជាអ្នកប្រតិបត្តិមានប៉ុន្មាន? អ្នកប្រតិបត្តិ AI ពឹងផ្អែកលើការហៅ LLM ដែលគិតតម្លៃដោយជាតុកិន ឬ API ខាងក្រៅ។ ការប្រើឧបករណ៍ជាញឹកញាប់ ឬបញ្ចូលគំនិតជាច្រើនអាចបង្កើនការចំណាយយ៉ាងឆាប់រហ័ស។ ឧទាហរណ៍ ប្រសិនបើអ្នកប្រតិបត្តិហៅ LLM ៥ដង ដើម្បីស្តារកម្រិតគុណភាពតិចតួច អ្នកត្រូវវាយតម្លៃថាតម្លៃនេះមានតុល្យភាពឬទេ ឬអាចកាត់បន្ថយការហៅ ឬប្រើម៉ូដែលថ្លៃថោកជាង។ ការត្រួតពិនិត្យពេលជាក់ស្តែងក៏ជួយរកឃើញការកើនឡើងគ្មានការរំពឹងទុក (ឧ. បញ្ហាកូដជួយបង្កាលំនឹងការហៅ API ច្រើនពេក)។

**កំហុសសំណើរ:** តើតាមប៉ុន្មានសំណើរដែលអ្នកប្រតិបត្តិបរាជ័យ? វាអាចរួមបញ្ចូលកំហុស API ឬការហៅឧបករណ៍ដែលបរាជ័យ។ ដើម្បីធ្វើឲ្យអ្នកប្រតិបត្តិរបស់អ្នករឹងមាំជាងមុននៅក្នុងផលិតកម្ម អ្នកអាចកំណត់ការជំនួស ឬព្យាយាមឡើងវិញ។ ឧ. ប្រសិនបើអ្នកផ្គត់ផ្គង់ LLM A ផ្អាក អ្នកអាចផ្លាស់ទៅប្រើ LLM B ជាការពារបម្រុងទុក។

**មតិយោបល់ពីអ្នកប្រើ:** ការអនុវត្តការវាយតម្លៃដោយផ្ទាល់ពីអ្នកប្រើផ្តល់ចំណេះដឹងដ៏មានតម្លៃ។ វា​អាចរួមបញ្ចូលការវាយតម្លៃច្បាស់លាស់ (👍ថ្ពាល់-ឡើង/👎ចុះ, ⭐1-5 ផ្កាយ) ឬមតិយោបល់អក្សរ។ មតិយោបល់អវិជ្ជមានជាប់ជាស្នងគួរឱ្យរំខាន ព្រោះវាជាសញ្ញាថាអ្នកប្រតិបត្តិមិនដំណើរការយ៉ាងគ្រប់គ្រាន់។

**មតិយោបល់មិនច្បាស់លាស់ពីអ្នកប្រើ:** អាកប្បកិរិយាអ្នកប្រើផ្តល់មតិយោបល់ផ្នែកក្រោយទោះបីមិនមានការវាយតម្លៃច្បាស់លាស់ក៏ដោយ។ វាអាចរួមបញ្ចូលការសរសេរសំណួរឡើងវិញភ្លាមៗ, សំណួរដដែលឬចុចប៊ូតុងលើកឡើងវិញ។ ឧ. ប្រសិនបើអ្នកឃើញអ្នកប្រើសួរសំណួរដដែលជាច្រើន អ្នកត្រូវដឹងថា អ្នកប្រតិបត្តិមិនដំណើរការត្រូវតាមការរំពឹងទុក។

**ភាពត្រឹមត្រូវ:** តើអ្នកប្រតិបត្តិផលិតលទ្ធផលត្រឹមត្រូវ ឬមានតម្លៃជាប្រចាំដល់កម្រិតណា? ការបកស្រាយភាពត្រឹមត្រូវប្រែប្រួល (ឧ. ការដោះស្រាយបញ្ហាត្រឹមត្រូវ, ការយកព័ត៌មានបានត្រឹមត្រូវ, ការពេញចិត្តរបស់អ្នកប្រើ)។ ជំហានដំបូងគឺកំណត់ថា តើជោគជ័យសម្រាប់អ្នកប្រតិបត្តិរបស់អ្នកមានទ្រង់ទ្រាយយ៉ាងដូចម្តេច។ អ្នកអាចតាមដានភាពត្រឹមត្រូវតាមការត្រួតពិនិត្យស្វ័យប្រវត្តិ, ពិន្ទុវាយតម្លៃ, ឬការសម្គាល់បញ្ចប់ភារកិច្ច។ ឧ. កំណត់បន្ទាត់តាមដានជាចំណាត់ថ្នាក់ "ជោគជ័យ" ឬ "បរាជ័យ"។

**វិមាត្រវាយតម្លៃស្វ័យប្រវត្តិ:** អ្នកអាចកំណត់ការវាយតម្លៃស្វ័យប្រវត្តិផងដែរ។ ឧ. អ្នកអាចប្រើ LLM ដើម្បីផ្តល់ពិន្ទុលទ្ធផល​របស់អ្នកប្រតិបត្តិ ដូចជា មើលថាវាជួយ, ត្រឹមត្រូវ ឬ អត់មែន។ មានបណ្ណាល័យចំនួនមួយដែលជួយអ្នកផ្តល់ពិន្ទុបែបផ្សេងៗរបស់អ្នកប្រតិបត្តិ។ ឧ. [RAGAS](https://docs.ragas.io/) សម្រាប់អ្នកប្រតិបត្តិ RAG ឬ [LLM Guard](https://llm-guard.com/) សម្រាប់រកភាសាដែលអាចមានគ្រោះថ្នាក់ ឬការវាយប្រហារបញ្ចូលសេចក្ដីបញ្ជា។

ក្នុងការអនុវត្ត វិមាត្រចម្រុះទាំងនេះផ្ដល់ការងារគ្រប់គ្រងល្អបំផុតសម្រាប់សុខភាពអ្នកប្រតិបត្តិ AI។ នៅក្នុងជំពូកនេះ [កំណត់ត្រាឧទាហរណ៍](./code_samples/10-expense_claim-demo.ipynb), យើងនឹងបង្ហាញអ្នកពីរបៀបដែលវិមាត្រទាំងនេះមើលទៅនៅក្នុងឧទាហរណ៍ជាក់ស្តែង ប៉ុន្តែមុននឹងនោះ យើងនឹងរៀនពីរបៀបធម្មតារបស់លំហាត់វាយតម្លៃ។

## បំពាក់ឧបករណ៍វាស់វែង

ដើម្បីប្រមូលទិន្នន័យតាមដាន អ្នកត្រូវការបំពាក់ឧបករណ៍កូដរបស់អ្នក។ គោលបំណងគឺបំពាក់កូដអ្នកប្រតិបត្តិដើម្បីបញ្ចេញបន្ទាត់តាមដាន និងវិមាត្រដែលអាចត្រូវបានចាប់យក ដំណើរការ និងបង្ហាញតាមវេទិកាមើលឃើញ។

**OpenTelemetry (OTel):** [OpenTelemetry](https://opentelemetry.io/) បានក្លាយជាស្តង់ដារក្នុងឧស្សាហកម្មសម្រាប់មើលឃើញ LLMs។ វាផ្ដល់កំណត់ API, SDK និងឧបករណ៍សម្រាប់បង្កើត ប្រមូល និងនាំចេញទិន្នន័យទំនាក់ទំនង។

មានបណ្ណាល័យបំពាក់ឧបករណ៍ជាច្រើនដែលបញ្ចូលគ្រឿងចក្រអ្នកប្រតិបត្តិជាប់ផ្លូវ និងធ្វើឱ្យងាយស្រួលក្នុងការនាំចេញការពង្រីក OpenTelemetry ទៅឧបករណ៍មើលឃើញមួយ។ Microsoft Agent Framework ផ្ទុកទៅជាមួយ OpenTelemetry ដោយដើមលក្ខណៈ។ ខាងក្រោមជាឧទាហរណ៍នៃការបំពាក់ឧបករណ៍ជាមួយអ្នកប្រតិបត្តិ MAF៖

```python
from agent_framework.observability import get_tracer, get_meter

tracer = get_tracer()
meter = get_meter()

with tracer.start_as_current_span("agent_run"):
    # ការអនុវត្តភ្នាក់ងារត្រូវបានតាមដានដោយស្វ័យប្រវត្តិ
    pass
```

កំណត់ត្រាឧទាហរណ៍ [example notebook](./code_samples/10-expense_claim-demo.ipynb) នៅក្នុងជំពូកនេះ នឹងបង្ហាញអ្នកពីរបៀបបំពាក់ឧបករណ៍អ្នកប្រតិបត្តិ MAF របស់អ្នក។

**ការបង្កើតការពង្រីកដោយដៃ:** ទោះបីបណ្ណាល័យបំពាក់ឧបករណ៍ផ្ដល់មូលដ្ឋានល្អ វាតែងតែមានករណីដែលត្រូវការព័ត៌មានលម្អិត ឬផ្ទាល់ខ្លួនបន្ថែម។ អ្នកអាចបង្កើតការពង្រីកដោយដៃដើម្បីបន្ថែមហេតុផលកម្មវិធីបោងផ្សេងៗ។ ជាសំខាន់ ពួកវាអាចផ្ដល់សម្បត្តិដ៏ផ្ទាល់ខ្លួន (ដែលគេហៅថាការតាក់ឬមេតាឌាតា) ទៅលើការពង្រីកដែលបង្កើតដោយស្វ័យប្រវត្តិ ឬដៃ។ សម្បត្តិទាំងនេះអាចរួមបញ្ចូលទិន្នន័យជាក់លាក់អាជីវកម្ម, ការគណនាវគ្គមធ្យម, ឬបរិបទណាមួយដែលអាចមានប្រយោជន៍សម្រាប់ការវិភាគ ឬការដោះស្រាយបញ្ហា ដូចជា `user_id`, `session_id`, ឬ `model_version`។

ឧទាហរណ៍នៃការបង្កើតបន្ទាត់តាមដាន និងការពង្រីកដោយដៃជាមួយ [Langfuse Python SDK](https://langfuse.com/docs/sdk/python/sdk-v3):

```python
from langfuse import get_client
 
langfuse = get_client()
 
span = langfuse.start_span(name="my-span")
 
span.end()
```

## ការវាយតម្លៃអ្នកប្រតិបត្តិ

ការមើលឃើញផ្ដល់វិមាត្រ ហើយការវាយតម្លៃជាដំណើរការវិភាគទិន្នន័យនោះ (និងអនុវត្តសាកល្បង) ដើម្បីកំណត់ថា តើអ្នកប្រតិបត្តិ AI បំពេញការងារយ៉ាងល្អ និងរបៀបដែលវាអាចកែលម្អបានយ៉ាងណា។ មានន័យថា បន្ទាប់ពីអ្នកមានបន្ទាត់តាមដាន និងវិមាត្រ ការប្រើវានៅក្នុងការវាយតម្លៃអ្នកប្រតិបត្តិ និងធ្វើសេចក្ដីសម្រេចយ៉ាងដូចម្តេច?

ការវាយតម្លៃធម្មតាគឺសំខាន់ ព្រោះអ្នកប្រតិបត្តិ AI ជាញឹកញាប់មិនមែនលទ្ធផលច្បាស់លាស់ និងអាចបែបផែនបាន (តាមរយៈការអាប់ដេត ឬការផ្លាស់ប្ដូរការប្រព្រឹត្តិម៉ូដែល) – គ្មានការវាយតម្លៃ អ្នកនឹងមិនដឹងថា “អ្នកប្រតិបត្តិឆ្លាត” របស់អ្នកដំណើរការយ៉ាងល្អឬបរាជ័យទេ។

មានចំណាត់ថ្នាក់ពីរនៃការវាយតម្លៃសម្រាប់អ្នកប្រតិបត្តិ AI៖ **ការវាយតម្លៃលើបណ្ដាញ** និង **ការវាយតម្លៃក្រៅបណ្ដាញ**។ ទាំងពីរបានមានតម្លៃ ហើយពួកវាបំពេញគ្នា។ យើងធម្មតាចាប់ផ្តើមជាមួយការវាយតម្លៃក្រៅបណ្ដាញ ព្រោះនេះគឺជាជំហានអប្បបរមាក្នុងការបញ្ចូនអ្នកប្រតិបត្តិ។

### ការវាយតម្លៃក្រៅបណ្ដាញ

![Dataset items in Langfuse](https://langfuse.com/images/cookbook/example-autogen-evaluation/example-dataset.png)

នេះពាក់ព័ន្ធនឹងការវាយតម្លៃអ្នកប្រតិបត្តិក្នុងបរិស្ថានត្រួតពិនិត្យ ជាទូរទាត់តាមប្រើកំណត់ត្រាសាកល្បង មិនមែនសំណួរពីអ្នកប្រើជាក់ស្តែងនោះទេ។ អ្នកប្រើប្រាស់ឈ្មោះ dataset ដែលបានរៀបចំ ដើម្បីដឹងថាអ្វីជាលទ្ធផលរំពឹងទុក ឬអាកប្បកិរិយាត្រឹមត្រូវ ហើយបន្ទាប់មកដំណើរការអ្នកប្រតិបត្តិរបស់អ្នកលើបណ្ដាញនោះ។

ឧទាហរណ៍ ប្រសិនបើអ្នកបានបង្កើតអ្នកប្រតិបត្តិបញ្ហាចំនួនគណិតវិទ្យាដោយពាក្យ សូមមាន [test dataset](https://huggingface.co/datasets/gsm8k) ដែលមានបញ្ហា ១០០ ដំណោះស្រាយដែលបានដឹងច្បាស់។ ការវាយតម្លៃក្រៅបណ្ដាញ តែងតែធ្វើនៅពេលអភិវឌ្ឍន៍ (ហើយអាចជាផ្នែកមួយនៃបណ្ដារការងារ CI/CD) ដើម្បីពិនិត្យភាពកែលម្អ ឬការការពារបញ្ហាថយក្រោយ។ អត្ថប្រយោជន៍គឺវា **អាចធ្វើម្ដងទៅម្ដងបាន និងអ្នកអាចទទួលបានវិមាត្រផ្ទាល់ត្រឹមត្រូវព្រោះអ្នកមានច្បាស់ពីលទ្ធផលពិតប្រាកដ**។ អ្នកអាចសមែនរៀបចំសំណួរអ្នកប្រើ ហើយវាស់តម្លៃចម្លើយនៃអ្នកប្រតិបត្តិស្របតាមចម្លើយល្អឬប្រើវិមាត្រស្វ័យប្រវត្តិតามខាងលើ។

ការលំបាកសំខាន់ជាមួយការវាយតម្លៃក្រៅបណ្ដាញ គឺធានាថាបណ្ដុំទិន្នន័យសាកល្បងរបស់អ្នកគ្រប់គ្រាន់ និងនៅសម័យទាន់ - អ្នកប្រតិបត្តិអាចធ្វើបានល្អលើកំណត់ត្រាស៊ែតថេរមួយ ប៉ុន្តែនឹងប្រទះសំណួរផ្សេងយ៉ាងខ្លាំងនៅទីផ្សារ។ ដូច្នេះ អ្នកគួរតែរក្សាបណ្ដុំសាកល្បងបណ្ដុះបណ្ដាលជាមួយករណីមួយចំនួនថ្មី និងឧទាហរណ៍ដែលបង្ហាញពីស្ថានការណ៍ពិតប្រាកដ។ ការរួមបញ្ចូលករណីតូចៗ “សាកល្បងបាញ់ផ្សែង” និងឧទាហរណ៍ធំៗសម្រាប់វាស់តម្លៃធំទូលាយគឺមានប្រយោជន៍៖ បណ្ដុំតូចសម្រាប់ពិនិត្យយ៉ាងលឿន និងធំសម្រាប់វិមាត្រប្រសិទ្ធភាពទូលាយ។

### ការវាយតម្លៃលើបណ្ដាញ

![Observability metrics overview](https://langfuse.com/images/cookbook/example-autogen-evaluation/dashboard.png)

នេះបង្ហាញពីការវាយតម្លៃអ្នកប្រតិបត្តិក្នុងបរិស្ថានបច្ចុប្បន្ន ជាក់ស្តែង តាមឱ្យប្រើនៅក្នុងផលិតកម្មពិតប្រាកដ។ ការ វាយតម្លៃលើបណ្ដាញរួមបញ្ចូលការត្រួតពិនិត្យការអនុវត្តរបស់អ្នកប្រតិបត្តិលើការប្រាស្រ័យអ្នកប្រើពិត និងវិភាគលទ្ធផលជាប្រចាំ។

ឧទាហរណ៍ អ្នកអាចតាមដានអត្រាជោគជ័យ ពិន្ទុការពេញចិត្តអ្នកប្រើ ឬវិមាតិរផ្សេងៗលើចរាចរណ៍ផ្ទាល់។ អត្ថប្រយោជន៍នៃការវាយតម្លៃលើបណ្ដាញគឺវា **ចាប់បានរឿងដែលអ្នកប្រហែលជាមិនរំពឹងទុកនៅក្នុងលំហបច្ចេកទេស** - អ្នកអាចមើលឃើញការប្រែប្រួលម៉ូដែលឆាប់ៗ (ប្រសិនបើប្រសិទ្ធភាពអ្នកប្រតិបត្តិកាន់តែខ្សោយពេលបម្លែងបញ្ចូល) និងចាប់ផ្តើមវិចារណាអំពីសំណួរដែលមិនបញ្ចូលក្នុងទិន្នន័យសាកល្បង។ វាបង្ហាញរូបភាពពិតប្រាកដពីរបៀបដែលអ្នកប្រតិបត្តិដំណើរការនៅក្នុងវាលពិតប្រាកដ។

ការវាយតម្លៃលើបណ្ដាញតែងតែកាន់តែច្រើនប្រមូលមតិយោបល់ច្បាស់លាស់ និងមិនច្បាស់លាស់ ព្រមទាំងអាចប្រតិបត្តិពិសោធន៍មុខងារ shadow ឬការប្រៀបធៀប A/B (ដែលនៅពេលអ្នកប្រតិបត្តិចាស់រត់ជាមួយអ្នកប្រតិបត្តិថ្មី)។ បញ្ហាក្រោមនេះគឺគ្មានការវាយតម្លៃ ឬសញ្ញាទង់ល្អសំរាប់ចំនួរពិតប្រាកដ ហើយប្រហែលជាត្រូវពឹងផ្អែកលើមតិយោបល់អ្នកប្រើ ឬវិមាត្រចុចលើលទ្ធផល។

### ការរួមបញ្ចូលគ្នាទាំងពីរ

ការវាយតម្លៃលើបណ្ដាញ និងក្រៅបណ្ដាញមិនមែនជារបស់ផ្ទួនដោយគ្នា ទេ ប៉ុន្តែល្អដើម្បីបំពេញគ្នា។ ចំណេះដឹងពីការត្រួតពិនិត្យលើបណ្ដាញ (ឧ. ប្រភេទសំណួរអ្នកប្រើថ្មី ដែលអ្នកប្រតិបត្តិកម្មចាប់បានកម្រិតស្ទាក់ស្ទើរ) អាចប្រើដើម្បីបន្ថែមនិងបង្កើនគុណភាព dataset ការវាយតម្លៃក្រៅបណ្ដាញ។ ផ្ទុយទៅវិញ អ្នកប្រតិបត្តិដែលមានប្រសិទ្ធភាពល្អនៅក្នុងការវាយតម្លៃក្រៅបណ្ដាញ អាចត្រូវបានបញ្ចូនភ្លាមៗ និងត្រូវបានតាមដានលើបណ្ដាញ។

ជារឿងពិត គ្រប់ក្រុមការងារមានចរិតសង្កេតចលនា៖

_វាយតម្លៃក្រៅបណ្ដាញ -> បញ្ចូនដាក់ប្រើ -> ត្រួតពិនិត្យលើបណ្ដាញ -> ប្រមូលករណីបរាជ័យថ្មីៗ -> បន្ថែមទៅ dataset ក្រៅបណ្ដាញ -> កែប្រែអ្នកប្រតិបត្តិ -> ធ្វើម្ដងទៀត_។

## ការគ្រប់គ្រងការចំណាយ


នេះជាយន្តការមួយចំនួនសម្រាប់គ្រប់គ្រងថ្លៃដើមនៃការចេញផ្សាយភ្នាក់ងារ AI ទៅផលិតកម្ម៖

**ការប្រើម៉ូដែលតូច៖** ម៉ូដែលភាសាតូច (SLMs) អាចបង្ហាញសមត្ថភាពល្អក្នុងករណីប្រើប្រាស់ភ្នាក់ងារក្នុងខ្លះ និងនឹងបន្ថយថ្លៃដើមយ៉ាងច្រើន។ ដូចដែលបានរៀបរាប់ពីមុន ការបង្កើតប្រពន្ធ័វាយតម្លៃដើម្បីកំណត់ និងប្រៀបធៀបទៅនឹងសមត្ថភាពជាមួយម៉ូដែលធំនៅលើ គឺជាវិធីល្អបំផុតដើម្បីយល់ពីរបៀបដែល SLMs អាចបំពេញការងាររបស់អ្នក។ សូមពិចារណាប្រើបម្រៃ SLM សម្រាប់ផ្នែកមានភាពសាមញ្ញដូចជា ការតម្រៀបចេតនា ឬការដកយកប៉ារ៉ាម៉ែត្រ ខណៈដែលរក្សាម៉ូដែលធំសម្រាប់ការគិតសំឡេងស្មុគស្មាញ។

**ការប្រើម៉ូដែលរ៉ោតឺរ៖** យន្តការដូចគ្នារបស់ការប្រើម៉ូដែល និងទំហំនានា។ អ្នកអាចប្រើ LLM/SLM ឬមុខងារមិនរុំលើសថេរ (serverless function) ដើម្បីរៀបចំសំណើតាមផ្អែកលើភាពស្មុគស្មាញទៅម៉ូដែលសមស្របបំផុត។ វានឹងជួយកាត់បន្ថយថ្លៃដើម ហើយនៅពេលដដែលធានាសមត្ថភាពលើភារកិច្ចត្រឹមត្រូវផងដែរ។ ជាឧទាហរណ៍ រៀបចំសំណួរងាយទៅម៉ូដែលតូច លឿន និងប្រើម៉ូដែលធំ គួរតែសំរាប់ការគិតស្មុគស្មាញ។

**ការតួនាទីឆ្លើយតប៖** ការស្វែងរកសំណើសំខាន់ៗនិងភារកិច្ច និងផ្តល់ចម្លើយ មុនពេលវាចូលដំណើរការផ្នែកភ្នាក់ងាររបស់អ្នក ជាវិធីល្អដើម្បីកាត់បន្ថយបរិមាណសំណើស្រដៀងគ្នា។ អ្នកអាចបង្កើតដំណើរការជួយក្នុងការកំណត់ថាសំណើស្រដៀងគ្នាប៉ុណ្ណា ជាមួយម៉ូដែល AI មូលដ្ឋាន។ យន្តការនេះអាចកាត់បន្ថយថ្លៃដើមយ៉ាងច្រើនសម្រាប់សំណួរញឹកញាប់ឬផ្សាយដំណើរការសាមញ្ញ។
