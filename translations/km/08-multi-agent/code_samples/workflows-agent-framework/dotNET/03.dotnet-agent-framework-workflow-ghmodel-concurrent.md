# ⚡ លំហាត់កម្មវិធីភ្នាក់ងារសម័យមួយទៀតជាមួយ Azure OpenAI (Responses API) (.NET)

## 📋 មេរៀនដំណើរការតម្រង់កំលាំងខ្ពស់

សៀវភៅកំណត់ត្រានេះបង្ហាញពី **លំនាំការងារសម័យមួយទៀត** ប្រើប្រាស់ Microsoft Agent Framework សម្រាប់ .NET និង Azure OpenAI (Responses API)។ អ្នកនឹងរៀនពីរបៀបកសាងលំហាត់កម្មវិធីដំណើរការតម្រង់ដែលមានកំលាំងខ្ពស់ ដើម្បីអតិបរមាប្រសិទ្ធភាព ជាមួយការអនុវត្តភ្នាក់ងារផ្នែក AI ច្រើនក្នុងពេលតែមួយ ដោយផ្តោតលើការសម្របសម្រួល និងភាពរឹងមាំនៃទិន្នន័យ។

## 🎯 គោលបំណងការរៀន

### 🚀 **មូលដ្ឋាននៃដំណើរការសម័យមួយទៀត**
- **ការបញ្ចូលភ្នាក់ងារច្រើនធ្វើការសម័យមួយ**: ដំណើរការភ្នាក់ងារផ្នែក AI ច្រើនក្នុងពេលតែមួយ ដើម្បីបំលែងកម្រិតអតិបរមា
- **លំនាំ Async/Await**: ប្រើប្រាស់គំរូកម្មវិធី async របស់ .NET សម្រាប់ដំណើរការសម័យមួយមានប្រសិទ្ធភាព
- **Azure OpenAI (Responses API)**: សម្របសម្រួលការហៅ API ជាច្រើនទ្រង់ទ្រាយសម័យមួយអស់ទៅកាន់ Azure OpenAI Responses API
- **ការគ្រប់គ្រងធនធាន**: គ្រប់គ្រងធនធានម៉ូដែល AI ដោយប្រកបដោយប្រសិទ្ធភាពជារួមក្នុងបរិបទដំណើរការសម័យមួយ

### 🏗️ **ស្ថាបត្យកម្មភាពសម័យមួយទៀតកម្រិតខ្ពស់**
- **ការបញ្ចូលបន្ទាប់បន្សំដោយកិច្ចការ**: ប្រើប្រាស់ .NET Task Parallel Library សម្រាប់ដំណើរការសម័យមួយយ៉ាងខ្ពស់
- **លំនាំសម្របសម្រួល**: សម្របសម្រួលភ្នាក់ងារសម័យមួយ ដើម្បីចៀសវាងបញ្ហា race conditions
- **ការបែងចែកផ្ទុកការងារ**: ចែកចាយកិច្ចការយ៉ាងមានប្រសិទ្ធភាពលើសមត្ថភាពដំណើរការសម័យមួយ
- **ការ​ទប់ទល់​ខូចខាត**: ដោះស្រាយបញ្ហាខូចខាតនៃភ្នាក់ងារតែមួយដោយមិនបញ្ឈប់ដំណើរការទាំងមូល

### 🏢 **កម្មវិធីសម័យមួយទៀតសម្រាប់សហគ្រាស**
- **ដំណើរការឯកសារច្រើន**: ដំណើរការឯកសារច្រើនក្នុងពេលតែមួយ
- **វិភាគមេឌៀពេលវេលាផ្ទាល់**: វិភាគទិន្នន័យដែលចូលមកក្នុងរបៀបសម័យមួយ
- **បច្ចុប្បន្នភាព Batch Processing**: បំពេញតម្រូវការចេញឯកសារចំនួនធំបំផុត
- **វិភាគច្រើនទ្រង់ទ្រាយ**: ដំណើរការតម្រង់សម័យទីមួយនៃប្រភេទមេឌៀនិងទ្រង់ទ្រាយផ្សេងៗគ្នា

## 💻 រត់កូដ

ការអនុវត្តពេញលេញមាននៅក្នុង `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`។ ឯកសារនេះបង្ហាញលំហាត់កម្មវិធី **Fan-Out/Fan-In concurrent workflow** សម្រាប់ផែនការធ្វើដំណើរ៖

### 🏗️ **ស្ថាបត្យកម្មលំហាត់ឯកសារ**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**ធាតុសំខាន់ៗ:**

1. **ConcurrentStartExecutor**: ផ្ញើស្នើរសុំអ្នកប្រើទៅភ្នាក់ងារទាំងអស់ជាលំដាប់
2. **Researcher Agent**: វិភាគចំណុចទេសចរណ៍ និងទាក់ទាញយ៉ាងសម័យមួយ
3. **Planner Agent**: បង្កើតផែនការធ្វើដំណើរយ៉ាងសម័យមួយ
4. **ConcurrentAggregationExecutor**: ប្រមូលវា និងរួមបញ្ចូលលទ្ធផលពីភ្នាក់ងារទាំងពីរ

### 🎯 **លំនាំ Fan-Out/Fan-In**

លំហាត់កម្មវិធីនេះបង្ហាញលំនាំចាស់ **Fan-Out/Fan-In**៖
- **Fan-Out**: សារចូលមួយត្រូវបានផ្សាយទៅភ្នាក់ងារច្រើនក្នុងពេលតែមួយ
- **ដំណើរការសម័យមួយ**: ភ្នាក់ងារច្រើនធ្វើការនៅលើកិច្ចការតម្រង់មួយដដែល
- **Fan-In**: លទ្ធផលពីភ្នាក់ងារទាំងអស់ត្រូវបានប្រមូល និងរួមបញ្ចូលទៅជាoutput តែមួយ

### 🔍 យល់ដឹងអំពី Custom Executors

**ConcurrentStartExecutor:**
- អនុវត្ត `IMessageHandler<string>` ដើម្បីទទួល string មក
- ផ្សាយសារ​ទៅភ្នាក់ងារទាំងអស់ដែលបានភ្ជាប់
- ផ្ញើ `TurnToken` ដើម្បីចាប់ផ្តើមដំណើរការសម័យមួយ

**ConcurrentAggregationExecutor:**
- អនុវត្ត `IMessageHandler<ChatMessage>` ក្នុងការទទួលចម្លើយពីភ្នាក់ងារ
- ប្រមូលសារយ៉ាងមានសុវត្ថិភាពនៅក្នុង thread
- រួមបញ្ចូលចម្លើយពេលមានចម្លើយជំរៅ
- ផ្ទេរវិញលទ្ធផលចុងក្រោយដោយប្រើ `context.YieldOutputAsync()`

### ⚡ អត្ថប្រយោជន៍កម្រិតប្រសិទ្ធភាព

**សម័យមួយបន្តបន្ទាប់ ទល់នឹង សម័យមួយនៅក្នុងពេលតែមួយ:**
- អនុវត្តបន្តបន្ទាប់: Agent1 (30s) → Agent2 (30s) = **60 វិនាទីសរុប**
- សម័យមួយនៅក្នុងពេលតែមួយ: Agent1 (30s) || Agent2 (30s) = **30 វិនាទីសរុប**

**ការកែលម្អ throughput**: លឿនប្រហែល N ដងសម្រាប់ភ្នាក់ងារ N នាក់សម័យមួយ (អាស្រ័យលើភារកិច្ច និងធនធាន)
