# ⚡ សន្ទស្សន៍កម្មវិធីប្រតិបត្ដិការរួម (Concurrent Agent Workflows) ជាមួយ Azure OpenAI (Responses API) (.NET)

## 📋 មេរៀនស្តីពីការប្រតិបត្ដិការដោយសម្រមែងល្បឿនលឿន (High-Performance Parallel Processing Tutorial)

សៀវភៅក៍នេះបង្ហាញពី **គំរូសម្ព័ន្ធលំនាំប្រតិបត្ដិកម្មរួម** ដោយប្រើ Microsoft Agent Framework សម្រាប់ .NET និង Azure OpenAI (Responses API)។ អ្នកនឹងរៀនពីវិធីសាងសង់ប្រតិបត្ដិការកម្មវិធីដែលមានប្រសិទ្ធភាពខ្ពស់ ធ្វើការជាប្រព័ន្ធរ_parallel_ ដើម្បីបង្កើនទិន្នផលឲ្យច្រើន ដោយអនុវត្តហត្ថកម្ម AI agents ច្រើនជាមួយគ្នានៅពេលតែមួយ ខណៈដែលរក្សាការសម្របសម្រួល និងភាពស្មោះត្រង់ទិន្នន័យ។

## 🎯 គោលបំណងរៀន

### 🚀 **មូលដ្ឋានប្រតិបត្ដិការរ_parallel_**
- **ការប្រតិបត្ដិការអាជីវករ Agent ជាប្រព័ន្ធរ_parallel_**: ដំណើរការអាជីវករ AI ពហុរូបក្នុងពេលតែមួយសម្រាប់ប្រសិទ្ធភាពអតិបរិមា
- **គំរូ Async/Await**: ប្រើម៉ូដែលកម្មវិធី async របស់ .NET សម្រាប់ប្រតិបត្ដិការរ_parallel_ យ៉ាងមានប្រសិទ្ធភាព
- **Azure OpenAI (Responses API)**: សម្របសម្រួលការហៅ API Responses Azure OpenAI ជាច្រើនដងក្នុងពេលតែមួយ
- **ការគ្រប់គ្រងធនធាន**: គ្រប់គ្រងធនធានម៉ូដែល AI យ៉ាងមានប្រសិទ្ធភាពក្នុងប្រតិបត្ដិការរ_parallel_

### 🏗️ **ស្ថាបត្យកម្មប្រតិបត្ដិការរ_parallel_ ជំនាញខ្ពស់**
- **Task-Based Parallelism**: ប្រើបណ្ណាល័យ Task Parallel របស់ .NET សម្រាប់ប្រតិបត្ដិការរ_parallel_ យ៉ាងល្អបំផុត
- **គំរូសម្របសម្រួល Synchronization**: រីករាយការប្រតិបត្ដិការរ_parallel_ ដោយជៀសវាងបញ្ហាហឹងហែកមុខ
- **ការ​តម្រឹម​ការងារ Load Balancing**: ចែកចាយការងារយ៉ាងមានប្រសិទ្ធភាពក្នុងសមត្ថភាពការប្រតិបត្ដិការរ_parallel_
- **ការជាប់ទ្រាំកំហុស Fault Tolerance**: ដោះស្រាយករណីទប់ស្កាត់ពេលអាជីវករមួយបរាជ័យដោយមិនបញ្ឈប់ការ

### 🏢 **កម្មវិធីសហគ្រាសប្រតិបត្ដិការរ_parallel_**
- **កំណត់ឯកសារកម្មវិធីច្រើនដង**: ដំណើរការឯកសារច្រើនក្នុងពេលតែមួយ
- **វិភាគមាតិកាពេលវេលាពិតប្រាកដ**: វិភាគបណ្តាញទិន្នន័យចូលបានរួមគ្នាយ៉ាងក្រអូប
- **បង្កើនប្រសិទ្ធភាពការប្រតិបត្ដិការជាទំរង់ក្នុងបុចណតា**: ដំណើរការបានលឿនក្នុងកម្រាស់ទិន្នន័យធំ
- **វិភាគមូលដ្ឋានមុខម៉ូដ (Multi-Modal Analysis)**: ដំណើរការប្រព័ន្ធរ_parallel_ នៃមាតិកាប្រភេទ និងទ្រង់ទ្រាយផ្សេងៗ

- **ការកំណត់ប្រសិទ្ធភាពដោយបន្ទាត់ Linear Performance Scaling**: បន្ថែមអាជីវកររ_parallel_ មួយច្រើនសម្រាប់បន្ថែមទិន្នផល

## 💻 រត់កូដ

ការអនុវត្តពេញលេញមាននៅក្នុង `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`។ ឯកសារនេះបង្ហាញពី **Fan-Out/Fan-In concurrent workflow** សម្រាប់គម្រោងធ្វើដំណើរ៖

### 🏗️ **ស្ថាបត្យកម្ម Workflow**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**សមាសភាគសំខាន់ៗ៖**

1. **ConcurrentStartExecutor**: ផ្សាយសំណើររបស់អ្នកប្រើទៅកាន់អាជីវករទាំងអស់នៅពេលតែមួយ
2. **Researcher Agent**: ធ្វើវិភាគទិសដៅ និងទីកន្លែងទាក់ទាញជាប្រព័ន្ធរ_parallel_
3. **Planner Agent**: បង្កើតផែនការធ្វើដំណើរយ៉ាងលម្អិតជាប្រព័ន្ធរ_parallel_
4. **ConcurrentAggregationExecutor**: ប្រមូល និងបញ្ចូលលទ្ធផលពីអាជីវករទាំងពីរ

### 🎯 **គំរូ Fan-Out/Fan-In**

ប្រតិបត្ដិការនេះបង្ហាញពីគំរូ **Fan-Out/Fan-In** ដ៏ល្បី៖
- **Fan-Out**: សារបញ្ចូលមួយត្រូវបានផ្សាយទៅអាជីវករច្រើនជាសម័យកាល
- **ប្រតិបត្ដិការរ_parallel_**: អាជីវករច្រើនធ្វើការងារដូចគ្នាប្រព័ន្ធរ_parallel_
- **Fan-In**: លទ្ធផលពីអាជីវករទាំងអស់ត្រូវបានប្រមូល និងបញ្ចូលជា​ផលចេញតែមួយ

### 🎯 កម្មវិធីពិភពលោកពិត

គំរូ concurrent នេះសមរម្យសម្រាប់៖
- **បង្កើតមាតិកា**: អ្នកនិពន្ធជាច្រើនបង្កើតផ្នែកផ្សេងៗនៅពេលតែមួយ
- **ពិនិត្យកូដ**: អ្នកពិនិត្យជាច្រើនវាយតម្លៃកូដពីចំណុចទស្សន៍ផ្សេងៗ
- **ស្រាវជ្រាវទីផ្សារ**: វិភាគរ_parallel_ ជំនួបផ្សេងៗគ្នានៅទីផ្សារ
- **ការកែតម្រូវឯកសារ**: ការដកស្រង់ វិភាគ និងផ្ទៀងផ្ទាត់ជាប្រព័ន្ធរ_parallel_
- **វិភាគច្រើនមุมទស្សន៍**: ទទួលបានទស្សនៈខុសគ្នា​នៅលើសារបញ្ចូលដូចគ្នា

### 🔍 យល់ដឹងអំពី Custom Executors

**ConcurrentStartExecutor:**
- អនុវត្ត `IMessageHandler<string>` ដើម្បីទទួល string input
- ផ្សាយសារទៅអាជីវករទាំងអស់ដែលបានភ្ជាប់
- ផ្ញើ `TurnToken` ដើម្បីបញ្ជាពេលប្រតិបត្ដិការរ_parallel_

**ConcurrentAggregationExecutor:**
- អនុវត្ត `IMessageHandler<ChatMessage>` ដើម្បីទទួលចម្លើយពីអាជីវករ
- ប្រមូលសារជារបៀប thread-safe
- បញ្ចូលនៅពេលចម្លើយទាំងអស់ចូល
- ផ្តល់លទ្ធផលចុងក្រោយដោយប្រើ `context.YieldOutputAsync()`

### ⚡ អត្ថប្រយោជន៍សមត្ថភាព

**Concurrent ប្រៀបធៀបនឹង Sequential:**
- Sequential: Agent1 (30s) → Agent2 (30s) = **60 វិនាទីសរុប**
- Concurrent: Agent1 (30s) || Agent2 (30s) = **30 វិនាទីសរុប**

**ការកែលម្អ Throughput**: ល្បឿនឡើងដល់ N ដងសម្រាប់ អាជីវករ concurrent N (អាស្រ័យលើបន្ទុកការងារនិងធនធាន)
