## Pull request guidelines

- Make sure each pull request fokus on one logical change.
- Test affected notebooks and code samples before you submit am.
- Update the correct lesson documentation when you add or change example.
- Edit English source content only. Translations dey done by the automated translation workflow.
- No put credentials, `.env` files, temporary files, or generated development artifacts inside commit.

## Editorial scope and third-party products

Dis curriculum focus on Microsoft technologies and vendor-neutral open standards. Contributions suppose get clear educational purpose and dem no suppose mainly dey try introduce or promote third-party commercial product, hosted service, model router, SDK, MCP server, or other vendor-specific offering.

Open-source software and third-party dependencies fit talk about if dem necessary to explain open standard or interoperability scenario, dem show am neutrally, and e no be only to promote vendor product or hosted endpoint. If your contribution get vendor-specific product or service, open issue and get approvement from maintainer before you submit pull request.

Contributors suppose talk about any relevant work, ownership, sponsorship, or other link with product or service wey dem talk about for their contribution. No put unsupported pricing, performance, security, privacy, or comparison claims. Runnable examples no suppose carry learner data or do public actions through external third-party service by default.
