# एजेंटिक प्रोटोकॉल्स वापरणे (MCP, A2A आणि NLWeb)

[![एजेंटिक प्रोटोकॉल्स](../../../translated_images/mr/lesson-11-thumbnail.b6c742949cf1ce2a.webp)](https://youtu.be/X-Dh9R3Opn8)

> _(या धड्याचा व्हिडिओ पाहण्यासाठी वरील प्रतिमा क्लिक करा)_

AI एजंटचा वापर वाढत असताना, मानकीकरण, सुरक्षा सुनिश्चित करणाऱ्या व मुक्त नवकल्पना समर्थित प्रोटोकॉलची गरज देखील वाढत आहे. या धड्यात, आपण ही गरज पूर्ण करण्यासाठी तीन प्रोटोकॉलस पाहणार आहोत - मॉडेल कॉन्टेक्स्ट प्रोटोकॉल (MCP), एजंट टू एजंट (A2A) आणि नॅचरल लँग्वेज वेब (NLWeb).

## परिचय

या धड्यात आपण काय शिकणार आहोत:

• **MCP** कसे AI एजंट्सना बाह्य साधने आणि डेटा वापरून वापरकर्त्यांच्या कार्ये पूर्ण करण्यास मदत करते.

• **A2A** कसे वेगवेगळ्या AI एजंट्समधील संवाद आणि सहयोग सक्षम करते.

• **NLWeb** कसे कोणत्याही वेबसाइटला नॅचरल लँग्वेज इंटरफेसेस देते ज्याने AI एजंट्सना सामग्री शोधणे आणि संवाद साधणे शक्य होते.

## शिक्षण उद्दिष्टे

• AI एजंट्सच्या संदर्भात MCP, A2A, आणि NLWeb चा मुख्य उद्देश आणि फायदे ओळखणे.

• प्रत्येक प्रोटोकॉल कसा LLMs, साधने, आणि इतर एजंट्स यांच्यात संवाद आणि संवाद साधण्यात मदत करतो ते स्पष्ट करणे.

• गुंतागुंतीच्या एजेंटिक सिस्टम्स तयार करण्यात प्रत्येक प्रोटोकॉलची वेगळी भूमिका ओळखणे.

## मॉडेल कॉन्टेक्स्ट प्रोटोकॉल

**मॉडेल कॉन्टेक्स्ट प्रोटोकॉल (MCP)** हे एक खुलं मानक आहे जे अनुप्रयोगांना LLMs ला संदर्भ आणि साधने देण्याचा मानकीकृत मार्ग पुरवतो. यामुळे AI एजंट्सना वेगवेगळ्या डेटा स्त्रोतांशी आणि साधनांशी एकसारख्या पद्धतीने जोडता येते.

चला MCP चे घटक, थेट API वापरापेक्षा ते कसे फायदेशीर आहे, आणि AI एजंट MCP सर्व्हर कसा वापरू शकतो याचा एक उदाहरण पाहूया.

### MCP चे मुख्य घटक

MCP **क्लायंट-सरव्हर आर्किटेक्चर** वर कार्य करते आणि मुख्य घटक आहेत:

• **होस्ट्स** म्हणजे LLM अनुप्रयोग (उदा. VSCode सारखा कोड एडिटर) जे MCP सर्व्हरशी कनेक्शन सुरू करतात.

• **क्लायंट्स** हा होस्ट अनुप्रयोगातील कंपोनेंट असतो जो सरव्हरसह एक ते एक कनेक्शन राखतो.

• **सरव्हर्स** हे हलके प्रोग्राम आहेत जे विशिष्ट क्षमता प्रदर्शित करतात.

प्रोटोकॉलमध्ये तीन मुख्य प्राथमिक गोष्टी अंतर्भूत आहेत ज्यात MCP सर्व्हरच्या क्षमता आहेत:

• **साधने (Tools)** : हे AI एजंट वापरू शकणारे स्वतंत्र कृती किंवा फंक्शन्स आहेत. उदाहरणार्थ, हवामान सेवा "get weather" साधन देऊ शकते, किंवा ई-कॉमर्स सर्व्हर "purchase product" साधन देऊ शकतो. MCP सर्व्हर प्रत्येक साधनाचे नाव, वर्णन, आणि इनपुट/आउटपुट स्कीमा जाहिर करतो.

• **स्रोत्रे (Resources)** : ही वाचन-फक्त डेटा आयटम किंवा दस्तऐवज आहेत जे MCP सर्व्हर प्रदान करू शकतो, आणि क्लायंट त्यांना हवी तेव्हा घेऊ शकतात. उदाहरणे म्हणजे फाइल सामग्री, डेटाबेस नोंदी किंवा लॉग फाइल्स. स्रोत्रे टेक्स्ट (कोड किंवा JSON सारखे) किंवा बायनरी (इमेजेस किंवा PDFs सारखे) असू शकतात.

• **प्रॉम्प्ट्स (Prompts)** : या पूर्वनिर्धारित टेम्प्लेट्स असतात जे सूचित प्रॉम्प्ट्स पुरवतात, ज्याने अधिक गुंतागुंतीच्या कार्यप्रवाहाला मदत होते.

### MCP चे फायदे

MCP AI एजंटसाठी महत्त्वाचे फायदे देते:

• **डायनॅमिक टूल शोध**: एजंट एका सर्व्हरकडून उपलब्ध साधनांची यादी आणि त्या साधनांचे वर्णन डायनॅमिकली मिळवू शकतात. पारंपरिक API मध्ये अनेकदा स्थिर कोडिंगची गरज असते, ज्यामुळे API बदलल्यास कोड अपडेट करावा लागतो. MCP "एकदाच एकत्रीकरण" प्रदान करते, ज्यामुळे जास्त लवचिकता येते.

• **विविध LLM मध्ये इंटरोपरेबिलिटी**: MCP वेगवेगळ्या LLMs मध्ये कार्य करते, त्यामुळे सुधारित कामगिरीसाठी मुख्य मॉडेल बदलण्याचा लवचिकता मिळतो.

• **मानकीकृत सुरक्षा**: MCP मध्ये मानक प्रमाणीकरण पद्धत समाविष्ट आहे, ज्यामुळे अतिरिक्त MCP सर्व्हरमध्ये प्रवेश जोडताना स्केलेबिलिटी सुधारते. हे पारंपरिक API मध्ये वेगवेगळ्या की आणि प्रमाणीकरण प्रकार व्यवस्थापित करण्यापेक्षा सोपे आहे.

### MCP चे उदाहरण

![MCP Diagram](../../../translated_images/mr/mcp-diagram.e4ca1cbd551444a1.webp)

विचार करा की वापरकर्ता MCP सह एका AI सहाय्यकाद्वारे फ्लाइट बुक करू इच्छित आहे.

1. **कनेक्शन**: AI सहाय्यक (MCP क्लायंट) विमानसेवा पुरवठादाराने दिलेल्या MCP सर्व्हरशी कनेक्ट होतो.

2. **साधन शोध**: क्लायंट विमानसेवा MCP सर्व्हरशी विचारतो, "कुठती साधने उपलब्ध आहेत?" सर्व्हर "search flights" आणि "book flights" सारखी साधने परत करतो.

3. **साधन वापर**: तुम्ही AI सहाय्यकाला म्हणता, "कृपया पोर्टलंड ते होनोलूलू फ्लाइट शोधा." AI सहाय्यक आपल्या LLM चा वापर करून निवडतो की "search flights" साधन कॉल करायचे आणि अनुकूल पॅरामीटर्स MCP सर्व्हरला पाठवतो.

4. **अंमलबजावणी आणि प्रतिसाद**: MCP सर्व्हर, एक रॅपर म्हणून कार्य करत, विमानसेवेच्या अंतर्गत बुकिंग API कॉल करतो. नंतर फ्लाइट माहिती (उदा. JSON डेटा) प्राप्त करून AI सहाय्यकाला परत करतो.

5. **पुढील संवाद**: AI सहाय्यक फ्लाइट पर्याय सादर करतो. तुम्ही फ्लाइट निवडल्यानंतर सहाय्यक "book flight" साधन कॉल करून बुकिंग पूर्ण करतो.

## एजंट-टू-एजंट प्रोटोकॉल (A2A)

जेव्हा MCP LLMs आणि साधनांना जोडण्यावर लक्ष केंद्रित करते, तेव्हां **एजंट-टू-एजंट (A2A) प्रोटोकॉल** वेगळी AI एजंट्समधील संवाद आणि सहयोग सक्षम करतो. A2A वेगवेगळ्या संस्थांतील, वातावरणातील, आणि तंत्रसाहित्याच्या भिन्न AI एजंट्सना जोडतो जेणेकरून ते सामायिक काम पूर्ण करू शकतात.

आपण A2A चे घटक आणि फायदे पाहणार आहोत, तसेच प्रवास अनुप्रयोगातील उदाहरण देखील पाहणार आहोत.

### A2A चे मुख्य घटक

A2A एजंट्समधील संवाद सक्षम करण्यावर आणि वापरकर्त्याच्या उपकार्य पूर्ण करण्यासाठी सहयोग करण्यावर लक्ष केंद्रित करते. प्रोटोकॉलचा प्रत्येक भाग यामध्ये योगदान देतो:

#### एजंट कार्ड

जसे MCP सर्व्हर साधनांची यादी शेअर करतो, तसेच एजंट कार्डमध्ये असते:
- एजंटचे नाव.
- तो जे सामान्य कार्ये पूर्ण करतो याचे वर्णन.
- विशिष्ट कौशलांची यादी आणि त्यांचे वर्णन जे इतर एजंट्सना (किंवा माणसांना) हे समजण्यासाठी मदत करतात की त्या एजंटला कधी आणि का कॉल करावे.
- एजंटचा सध्याचा एंडपॉईंट URL.
- एजंटचे आवृत्ती आणि क्षमता जसे की स्ट्रिमिंग प्रतिक्रिया आणि पुष नोटिफिकेशन्स.

#### एजंट एक्झिक्युटर

एजंट एक्झिक्युटर **वापरकर्त्याच्या चॅटचा संदर्भ दूरसंचार एजंटकडे पास करण्यासाठी जबाबदार आहे**, कारण दूरसंचार एजंटाला कार्य समजण्यासाठी हा संदर्भ आवश्यक असतो. A2A सर्व्हरमध्ये, एजंट स्वतःचा LLM वापरून येणाऱ्या विनंत्या पार्स करतो आणि अंतर्गत साधने वापरून कार्ये पार पाडतो.

#### आर्टिफॅक्ट

एकदा दूर एजंट ने विनंती केलेले काम पूर्ण केले की त्याचे काम आर्टिफॅक्ट म्हणून तयार केले जाते. एक आर्टिफॅक्ट मध्ये **एजंटच्या कामाचा परिणाम**, **पूर्ण केलेल्या कामाचे वर्णन**, आणि प्रोटोकॉलद्वारे पाठवलेला **टेक्स्ट संदर्भ** असतो. आर्टिफॅक्ट पाठवल्यानंतर, दूरसंचार एजंटशी कनेक्शन बंद केले जाते जोपर्यंत पुन्हा आवश्यक नाही.

#### इव्हेंट क्यू

हा घटक **अपडेट्स हाताळण्यासाठी आणि संदेश पाठवण्यासाठी** वापरला जातो. उत्पादनातील एजंटिक सिस्टम्ससाठी हा महत्त्वाचा आहे कारण तो एजंट्समधील कनेक्शन कार्य पूर्ण होण्याअगोदर बंद होण्यापासून रोखतो, विशेषत: जेव्हा कार्य पूर्ण होण्यासाठी अधिक वेळ लागू शकतो.

### A2A चे फायदे

• **सुध्द सहयोग**: विविध विक्रेत्या आणि प्लॅटफॉर्म्सचे एजंट्स संवाद साधु शकतात, संदर्भ सामायिक करू शकतात, आणि एकत्र काम करू शकतात ज्याने पारंपरिकपणे वेगळ्या सिस्टम्समधील स्वयंचलितता सुलभ होते.

• **मॉडेल निवड लवचिकता**: प्रत्येक A2A एजंट त्याचे गरजेप्रमाणे कोणता LLM वापरायचा हे ठरवू शकतो, ज्यामुळे एजंटनिहाय अनुकूल मॉडेल वापरण्याचा पर्याय मिळतो, काही MCP परिस्थितींतील एका LLM कनेक्शनच्या तुलनेत.

• **बंदिस्त प्रमाणीकरण**: प्रमाणीकरण A2A प्रोटोकॉलमध्ये थेट अंतर्भूत आहे, ज्यामुळे एजंट संवादासाठी मजबूत सुरक्षा प्रदान होते.

### A2A उदाहरण

![A2A Diagram](../../../translated_images/mr/A2A-Diagram.8666928d648acc26.webp)

आपल्या प्रवास बुकिंग सिनिअरियोलाही यावेळेस A2A वापरून विस्तृत करूया.

1. **वापरकर्ता विनंती मल्टी-एजंटला**: वापरकर्ता "Travel Agent" A2A क्लायंट/एजंटशी संवाद साधतो, कदाचित असे म्हणतो, "कृपया पुढील आठवड्यासाठी होनोलूलू साठी संपूर्ण प्रवास बुक करा, ज्यात उड्डाणे, हॉटेल, आणि भाड्याने कार आहे".

2. **Travel Agent द्वारे समन्वय**: Travel Agent या गुंतागुंतीची विनंती प्राप्त करतो. तो त्याचा LLM वापरून कार्याचा विचार करतो आणि समजतो की इतर तज्ञ एजंट्सशी संवाद साधावा लागेल.

3. **एजंट्समधील संवाद**: Travel Agent नंतर A2A प्रोटोकॉल वापरून खालील एजंट्सशी, जसे "Airline Agent," "Hotel Agent," आणि "Car Rental Agent" ज्यांना भिन्न कंपन्या तयार केल्या आहेत, कनेक्ट होतो.

4. **कार्य सौंपणे**: Travel Agent या तज्ञ एजंट्सना विशिष्ट कार्ये पाठवतो (उदा., "Hोनोलूलू साठी उड्डाण शोधा," "हॉटेल बुक करा," "कार भाड्याने घ्या"). प्रत्येक एजंट त्याचे स्वतःचे LLM आणि साधने वापरून आपले काम पूर्ण करतो.

5. **समेकित प्रतिसाद**: सर्व एजंट्स आपले काम पूर्ण केल्यावर Travel Agent परिणाम (फ्लाइट तपशील, हॉटेल पुष्टी, कार भाड्याने बुकिंग) संकलित करून वापरकर्त्याला संवाद शैलीतील विस्तृत प्रतिसाद पाठवतो.

## नॅचरल लँग्वेज वेब (NLWeb)

वेबसाइट्स इंटरनेटवरील माहिती आणि डेटासाठी वापरकर्त्यांचा मुख्य प्रवेशद्वार असतात.

चला NLWeb चे घटक, फायदे, आणि आमच्या प्रवास अनुप्रयोगाद्वारे NLWeb कसे कार्य करते ते पाहूया.

### NLWeb चे घटक

- **NLWeb एप्लिकेशन (मुख्य सेवा कोड)**: नॅचरल लँग्वेज प्रश्न प्रक्रिया करणारी प्रणाली. ती प्लॅटफॉर्मचे वेगवेगळे भाग जोडून प्रतिसाद तयार करते. तुम्ही याला वेबसाइटच्या नॅचरल लँग्वेज वैशिष्ट्यांना बळकट करणारे इंजिन समजू शकता.

- **NLWeb प्रोटोकॉल**: वेबसाइटशी नॅचरल लँग्वेज संवादासाठी मूलभूत नियम संच. ते JSON स्वरूपात (अनेकदा Schema.org वापरून) प्रतिसाद पाठवते. हे "AI वेब" साठी साधी पाया तयार करते, जसे HTML कागद ऑनलाइन शेअर करण्यास सक्षम करते.

- **MCP सर्व्हर (मॉडेल कॉन्टेक्स्ट प्रोटोकॉल एंडपॉईंट)**: प्रत्येक NLWeb सेटअप एका **MCP सर्व्हर** सुद्धा आहे. याचा अर्थ तो AI सिस्टम्ससोबत साधने (उदा., "ask" पद्धत) आणि डेटा शेअर करू शकतो. प्रत्यक्षात, यामुळे वेबसाइटची सामग्री आणि क्षमताएं AI एजंट्ससाठी वापरता येतात, आणि वेबसाइट "एजंट परिसंस्था" चा भाग बनते.

- **एम्बेडिंग मॉडेल्स**: वेब सामग्रीचे संख्यात्मक प्रतिनिधित्व करणारे व्हेक्टर (एम्बेडिंग) तयार करण्यासाठी वापरले जातात. हे व्हेक्टर संगणकांना तुलना आणि शोध करण्यास मदत करतात. ते एक खास डेटाबेसमध्ये संग्रहित केले जातात, आणि वापरकर्ते कोणते एम्बेडिंग मॉडेल वापरायचे ते निवडू शकतात.

- **व्हेक्टर डेटाबेस (रिट्रीवल मेकॅनिझम)**: वेबसाइट सामग्रीचे एम्बेडिंग संग्रहित करणारा डेटाबेस. एखादा प्रश्न विचारला की NLWeb व्हेक्टर डेटाबेसमध्ये शोध घेतो आणि वेगाने संबंधित माहिती शोधून समानतेनुसार क्रमवारी लावलेली उत्तरांची यादी देतो. NLWeb वेगवेगळ्या व्हेक्टर स्टोरेज सिस्टम्ससह कार्य करतो जसे Qdrant, Snowflake, Milvus, Azure AI Search, आणि Elasticsearch.

### उदाहरणाद्वारे NLWeb

![NLWeb](../../../translated_images/mr/nlweb-diagram.c1e2390b310e5fe4.webp)

परत आपल्या प्रवास बुकिंग वेबसाइटकडे पाहूया, पण यावेळी ती NLWeb द्वारा समर्थित आहे.

1. **डेटा इन्टेक्शन**: प्रवास वेबसाइटचा विद्यमान उत्पादन कॅटलॉग (उदा., फ्लाइट यादी, हॉटेल वर्णने, टूर पॅकेजेस) Schema.org वापरून फॉरमॅट केला जातो किंवा RSS फीड्सद्वारे लोड केला जातो. NLWeb ची साधने या संरचित डेटाचा वापर करून एम्बेडिंग तयार करतात आणि त्यांना स्थानिक किंवा दूरस्थ व्हेक्टर डेटाबेस मध्ये संग्रहित करतात.

2. **नॅचरल लँग्वेज क्वेरी (माणूस)**: एक वापरकर्ता वेबसाइटला भेट देतो आणि मेनू न वापरता चॅट इंटरफेस मध्ये टाइप करतो: "मला पुढील आठवड्यासाठी होनोलूलू मधील कुटुंब-मैत्रीपूर्ण हॉटेल जेथे स्विमिंग पूल आहे, शोधा".

3. **NLWeb प्रक्रिया**: NLWeb एप्लिकेशन ही क्वेरी प्राप्त करतो. तो क्वेरी समजून घेण्यासाठी LLM कडे पाठवतो आणि त्याच वेळी संबंधित हॉटेल यादी शोधण्यासाठी त्याचा व्हेक्टर डेटाबेस तपासतो.

4. **अचूक परिणाम**: LLM शोध परिणाम समजावून सांगण्यात मदत करतो, "कुटुंब-मैत्रीपूर्ण", "पूल", आणि "होनोलूलू" निकषांवर आधारित सर्वोत्तम जुळणी ओळखतो, आणि नॅचरल लँग्वेज प्रतिसाद तयार करतो. महत्त्वाचे म्हणजे, प्रतिसाद प्रत्यक्ष वेबसाइटच्या कॅटलॉगमधील हॉटेलांकडे निर्देश करतो, बनावट माहिती नाही.

5. **AI एजंट संवाद**: NLWeb हे MCP सर्व्हर म्हणून काम करतो, त्यामुळे बाह्य AI प्रवास एजंटसुद्धा या वेबसाइटच्या NLWeb इंस्टेंसशी कनेक्ट होऊ शकतो. AI एजंट नंतर `ask` MCP पद्धत वापरून थेट वेबसाइटला प्रश्न विचारू शकतो: `ask("Are there any vegan-friendly restaurants in the Honolulu area recommended by the hotel?")`. NLWeb हे प्रक्रिया करतो, त्याचा रेस्टॉरंट माहितीचा डेटाबेस वापरून (जर लोड केला असेल तर), आणि संरचित JSON प्रतिसाद परत करतो.
