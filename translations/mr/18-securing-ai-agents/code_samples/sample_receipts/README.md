# नमुना रिसिप्ट फिक्स्चर्स

नोटबुक चालविण्याशिवाय तपासणीसाठी तीन पूर्वनिर्मित रिसिप्ट फाइल्स.

| फाइल | ते काय आहे |
|---|---|
| `01_valid_receipt.json` | `lookup_flights` टूल कॉलसाठी वैध सही असलेली रिसिप्ट. पडताळणी True परत करते. |
| `02_tampered_receipt.json` | सही झाल्यानंतर एक फील्ड बदललेली तीच रिसिप्ट. पडताळणी False परत करते. |
| `03_chain_three_receipts.json` | तीन वैध रिसिप्ट्सची साखळ (search, hold, book) ज्यात `previous_receipt_hash` वापरून प्रत्येक मागील रिसिप्टशी जोडले जाते. |

फिक्स्चर्स थेट पेलोडच्या canonical JCS बाइट्सवर Ed25519 ने सही करतात.
SHA-256 सामग्री डाइजेस्ट्स आणि रिसिप्ट-चेन लिंकसाठी वापरले जाते,
सही करण्यापूर्वी अतिरिक्त प्री-हॅश म्हणून नाही.

## नमुन्यांची पडताळणी करणे

नोटबुक चार विभागांत पडताळणीची माहिती देते. या फिक्स्चर्स थेट पडताळणीसाठी,
नोटबुकचा अभ्यास न करता खालीलप्रमाणे:

```python
import json
from pathlib import Path

# समजते की आपण आयात आणि सहाय्यक फंक्शन्स पूर्ण केले आहेत
# 18-signed-receipts.ipynb च्या विभाग 1 आणि 2 मधून.

valid = json.loads(Path("01_valid_receipt.json").read_text())
print(f"Valid receipt: {verify_receipt(valid)}")        # बरोबर

tampered = json.loads(Path("02_tampered_receipt.json").read_text())
print(f"Tampered receipt: {verify_receipt(tampered)}")  # चुकीचे

chain = json.loads(Path("03_chain_three_receipts.json").read_text())
for r in verify_chain(chain):
    print(f"  Receipt {r['index']} ({r['tool']}): {'VALID' if r['overall_valid'] else 'INVALID'}")
```

बाइट-रिप्रोडकिबिलिटीसाठी ठराविक टाईमस्टॅम्पसह. पुनरुत्पादित करण्यासाठी:

```bash
python3 generate_fixtures.py
```

## विद्यार्थ्यांना raw JSON तपासून काय शिकायला मिळते

raw रिसिप्ट फॉरमॅट वाचल्याने त्या अंतर्ज्ञानाची निर्मिती होते, जी नोटबुकमधील
सेल्स कधी कधी देत नाहीत. JSON स्किम करणारे विद्यार्थी सहसा लक्ष देतात:

1. सही एक अस्पष्ट base64url स्ट्रिंग आहे, पण बाकीचे सर्व फील्ड्स स्पष्ट
   वाचता येणारे JSON आहेत. सही सामग्री एन्क्रिप्ट करत नाही; ती फक्त पुष्टी करते.
2. `public_key` रिसिप्टमध्ये समाविष्ट आहे. ऑडिटरला पडताळणीसाठी दुसऱ्या काही गोष्टींची गरज नाही
   (फक्त हे विश्वास ठेवा की की खरोखरच घोषित जारी करणाऱ्याची आहे; identity infrastructure विषयी
   साठी README पाहा).
3. कोणत्याही फील्डचा एकच अक्षर बदलून, मग `02_tampered_receipt.json` सोबत पुन्हा तुलना केल्यास,
   बाइट-स्तरीय यंत्रणा ठोस होते.
