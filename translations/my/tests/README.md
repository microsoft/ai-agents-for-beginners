# အေးဂျင့် ဆွဲမိုးစမ်းသပ်မှုများ

ဒီဖိုလ်ဒါဟာသင်တန်းမှာတည်ဆောက်ထားတဲ့ **ဆွဲမိုးစမ်းသပ်မှု ကတ်တလော့များ** ကို သိမ်းဆည်းထားသည်။
ဆွဲမိုးစမ်းသပ်မှုဆိုသည်မှာ **တပ်ဆင်ပြီးသား Microsoft Foundry အစီအစဉ်တွင် အိမ်ခံထားသော
အေးဂျင့်** သို့မဟုတ်၊ ရရှိနိုင်မှု၊ တုံ့ပြန်မှုရှိမှုနှင့် အခြေခံအမြင်ပေးမှုများကိုလိုက်နာနေမှုတို့ကို စစ်ဆေးသည့် စရိတ်သက်သာပြီး၊ အရှိန်လျင်မြန်သော စစ်ဆေးမှုတစ်ခုဖြစ်သည်။
၎င်းသည် ပထမဆုံးတံခါးတစ်ခုဖြစ်ပြီး [နိဒီယာ ၁၀](../10-ai-agents-production/README.md) နှင့်
[နိဒီယာ ၁၆](../16-deploying-scalable-agents/README.md) တွင်သင်ကြားသည့် ပြီးပြည့်စုံသောကျွမ်းကျင်မှုလုပ်ငန်းစဉ်အစားထိုးမှုမဟုတ်ပါ။


ကတ်တလော့များကို [AI ဆွဲမိုးစမ်းသပ်မှု](https://github.com/marketplace/actions/ai-smoke-test)
GitHub Action မှ [`.github/workflows/smoke-test.yml`](../../../.github/workflows/smoke-test.yml)
အလုပ်စဉ်ဖြင့် အသုံးပြုသည်။

## ကိစ္စကို ပြုလုပ်ပုံ

၁။ **သင်တန်းအေးဂျင့်ကို** Microsoft Foundry တွင် အိမ်ခံအေးဂျင့်အဖြစ် တပ်ဆင်ပါ (တပ်ဆင်မှုလုပ်ငန်းစဉ်ကို နိဒီယာ ၁၆ တွင် ကြည့်ပါ)။ **အေးဂျင့်နာမည်** နှင့် သင်၏
   **Foundry စီမံကိန်း အဆုံးအမျိုးအစား** ကို မှတ်ထားပါ။
၂။ repository secrets (Settings → Secrets and variables → Actions) တွင် အောက်ပါများကို ထည့်သွင်းပါ။
   `AZURE_CLIENT_ID`, `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID`။ ဖက်ဒရေးတက်အသိမှတ်ပြုမှုပိုင်ခွင့်သည် **Foundry စီမံကိန်း အတွင်း Azure AI အသုံးပြုသူ** အခန်းကဏ္ဍရှိရမည်။
၃။ **Actions** တညျက, **ဆွဲမိုးစမ်းသပ်မှု အိမ်ခံအေးဂျင့်များ** ကို လုပ်ဆောင်ပြီး သင်တန်းအတွက်
   `tests_file` ကို ရွေးချယ်ပြီး `agent_name` နှင့် `project_endpoint` ကို နှိုင်းယှဉ်၍ ဖြည့်သွင်းပါ။

## မည်သည့်သင်ခန်းစာများတွင် smoke test များ ရှိသနည်း?

Smoke test များသည် သင့်တင်သွင်းသော **agent တစ်ဦး** ၏စာသားဖြေကြားချက်များကို
သိထားသော အကြောင်းအရာနှင့် နှိုက်ယှဉ်စစ်ဆေးနိုင်သည့် သင်ခန်းစာများတွင် အထူးသီးသန့် သုံးစွဲသည်။
အယူအဆဆိုင်ရာ သင်ခန်းစာများ၊ တော့ကြောင်းတွင်သာအလုပ်လုပ်သော သင်ခန်းစာများ သို့မဟုတ် သွေးသွားစွာ ဖန်တီးမှု ထုတ်ပေးမှုများ ပါဝင်သော သင်ခန်းစာများကို ရည်ရွယ်၍ မပါဝင်ပါ:

- **သင်ခန်းစာ ၁၇ (ဒေသတွင်း AI Agent များ ဖန်တီးခြင်း)** သည် Foundry Local ဖြင့် သင့်ကွန်ပျူတာပေါ်တွင် ပြီးပြင်းစွာ အလုပ်လုပ်ပြီး
  Foundry Responses endpoint မထုတ်ပေးသဖြင့် ဒီလုပ်ဆောင်ချက်မသက်ဆိုင်ပါ။ Notebook ကို ဒေသတွင်းတွင် ပြေးဆွဲ၍ အတည်ပြုပေးပါ။
- ဒီဇိုင်းနမူနာနှင့် သီအိုရီ သင်ခန်းစာများ (02, 03, 06, 07, 09, 12) တွင် တစ်ခုချင်း Deploy ပြုလုပ်နိုင်သည့်
  agent မပါဝင်သည့်အတွက် smoke test မပြုလုပ်ပါ။




ကတ်တလော့တစ်ခုစီမှာ top-level `tests` array ပါသည့် JSON စာရွက်စာတမ်းတစ်ခုဖြစ်သည်။ အမျိုးအစားတစ်ခုစီက POST လုပ်ပြီး
တစ်ခုစီသော prompt တစ်ခုကို တင်သွင်းပြီး ဖြေကြားချက်ပေါ်မှာ အတည်ပြုချက်များထည့်သွင်းသည်။

| Field | အဓိပ္ပာယ် |
|-------|---------|
| `id` | မှတ်တမ်းတွင် ထုတ်ပြသသော ထူးခြားသောခြေလှမ်း အသိအမှတ်ပြုနံပါတ်။ |
| `description` | လူသားဖတ်ရှုနိုင်သော ရည်ရွယ်ချက်။ |
| `prompt` | မက်ဆေ့ချ်ကို ဗဟိုအေးဂျင့္ထံ ပို့သည်။ |
| `assertions.status` | မျှော်မှန်းထားသော HTTP အခြေအနေ (ပုံမှန်အားဖြင့် 200)။ |
| `assertions.contains_any` | တုံ့ပြန်ချက်တွင် ဤခွဲစိတ်စကားလုံးများ တစ်ခုခု ပါဝင်ပါက အောင်မြင်သည်။ |
| `assertions.contains_all` | တုံ့ပြန်ချက်တွင် ကော်မလုံးခွဲစိတ်စကားလုံးတစ်ခုချင်းစီ ပါဝင်ပါက အောင်မြင်သည်။ |
| `assertions.contains_none` | တုံ့ပြန်ချက်တွင် ဤခွဲစိတ်စကားလုံးများ မပါဝင်ပါက အောင်မြင်သည်။ |
| `save_response_id_as` | နောက်ပိုင်းအဆင့်များတွင် အလျောက်သုံးရန် တုံ့ပြန်ချက် ID ကို သိမ်းဆည်းပါ။ |
| `use_previous_response_id` | သိမ်းဆည်းထားသော တုံ့ပြန်ချက် ID နှင့် ဆက်စပ် ပတ်သက်သော ဒီအဆင့်ကို ပို့ပါ။ |

အတည်ပြုချက်များမှာ အက္ခရာအကြီးအကျယ် မသက်ဆိုင်သော ခွဲစိတ်စကားလုံး စစ်ဆေးချက်များ ဖြစ်သည်။ ကြည့်ပါ
[action documentation](https://github.com/marketplace/actions/ai-smoke-test) မှာ
ပြည့်စုံသော စံပုံစံ၊ Foundry မှ စီမံခန့်ခွဲသော စကားပြောမှုအရင်းအမြစ်များပါဝင်သည်။
