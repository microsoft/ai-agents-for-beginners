# ကွန်ပျူတာ အသုံးပြုမှု ကိုယ်စားလှယ်များ (CUA) တည်ဆောက်ခြင်း

ကွန်ပျူတာ အသုံးပြုမှု ကိုယ်စားလှယ်များသည် လူတစ်ဦးကဲ့သို့ ဝဘ်ဆိုဒ်များနှင့် ဆက်သွယ်နိုင်ကြသည်။ ဘရောက်ဇာတစ်ခုဖွင့်ခြင်း၊ စာမျက်နှာကို စစ်ဆေးခြင်းနှင့် မြင်တွေ့သမျှမှ မျှော်မှန်းချက်အကောင်းဆုံး လုပ်ဆောင်ချက်ကို ရယူခြင်းဖြင့်ဖြစ်သည်။ ဒီသင်ခန်းစာတွင်၊ Airbnb ကို ရှာဖွေပြီး၊ စနစ်တကျ စာရင်းသွင်းထားသော ဒေတာများကို ထုတ်ယူခြင်းနှင့် စတော့ခ်ဟോမ်ရှိ အစျေးသာဆုံး နေရာကို ဖော်ထုတ်နိုင်သော ဘရောက်ဇာအလိုအလျောက်လုပ်ဆောင်မှု ကိုယ်စားလှယ်တစ်ဦးကို တည်ဆောက်မှာဖြစ်သည်။

သင်ခန်းစာသည် AI ရှာဖွေရေးအတွက် Browser-Use ကိုပေါင်းစပ်အသုံးပြုခြင်း၊ ဘရောက်ဇာထိန်းချုပ်မှုအတွက် Playwright နှင့် Chrome DevTools Protocol (CDP)၊ မျက်စိမြင်အရ အာရုံနှင့် ဆင်ခြင်မှုအတွက် Azure OpenAI နှင့် စနစ်တကျ ထုတ်ယူရန် Pydantic တို့ကို ပေါင်းစပ်ထားသည်။

## မိတ်ဆက်

ဒီသင်ခန်းစာမှာ ကြည့်ရှုမယ့်အချက်တွေက:

- ကွန်ပျူတာအသုံးပြုမှုကိုယ်စားလှယ်များသည် API ဖန်ဆင်းမှုထက် ဘယ်အချိန်ပိုသင့်တော်ကြောင်းနားလည်ခြင်း
- ကြာရှည်ခံဘရောက်ဇာနေရာထိန်းချုပ်မှုအတွက် Browser-Use နှင့် Playwright၊ CDP ပေါင်းစပ်အသုံးပြုခြင်း
- အပြောင်းအလဲရှိသော ဝဘ်စာမျက်နှာများမှ စာရင်းသွင်းမှုဒေတာများကို Azure OpenAI မျက်စိမြင်နဲ့ Pydantic စနစ်တကျထုတ်ယူခြင်း
- ကိုယ်စားလှယ်-ဦးစားပေး၊ တာဝန်ခံ-ဦးစားပေး သို့မဟုတ် ဟိုက်ဘရီဒ် ဘရောက်ဇာအလိုအလျှောက်လုပ်ဆောင်မှုလမ်းစဉ် ဘယ်အချိန်သုံးရမလဲဆုံးဖြတ်ခြင်း

## သင်ယူရမည့်ရည်ရွယ်ချက်များ

ဒီသင်ခန်းစာပြီးဆုံးတဲ့အချိန်မှာ သင်မှာ သိရှိနားလည်နိုင်မှာက:

- Azure OpenAI နဲ့ Playwright ဖြင့် Browser-Use ကို ပြင်ဆင်ခြင်း
- လက်တွေ့ရှိသော ဝဘ်ဆိုဒ်တစ်ခုကို ကူးသန်းရောက်ရှိပြီး အပြောင်းအလဲရှိ UI ပစ္စည်းများကို ကိုင်တွယ်တတ်သော ဘရောက်ဇာအလိုအလျောက်လုပ်ဆောင်မှု လမ်းစဉ်တည်ဆောက်ခြင်း
- မြင်တွေ့နိုင်သော စာမျက်နှာအကြောင်းအရာမှ ဝေါဟာရခံ ထုတ်လွှင့်သောရလဒ်များကို ရယူပြီး အောက်မှစီးပွားရေး အလုပ်စဉ်သို့ ပြောင်းလဲခြင်း
- ဘရောက်ဇာလုပ်ငန်းတာဝန်သည် မည်သို့ ခန့်မှန်းနိုင်မလဲ ပေါ်မူတည်ပြီး ကိုယ်စားလှယ်နှင့် တာဝန်ခံ ပုံစံများကို ရွေးချယ်ခြင်း

## ကိုဒ် နမူနာ

ဒီသင်ခန်းစာတွင် စာအုပ်တစ်အုပ် ပါဝင်သည်၊

- [15-browser-user.ipynb](./15-browser-user.ipynb): CDP ဖြင့် Chrome session တစ်ခု စတင်တည်ဆောက်ကာ Stockholm စာရင်းများအတွက် Airbnb ရှာကာ၊ Browser-Use မျက်စိမြင်နည်းဖြင့်စျေးနှုန်းများကို ထုတ်ယူပြီး အစျေးသက်သာဆုံး ရွေးချယ်ချက်ကို စနစ်တကျ ဒေတာအဖြစ် ပြန်လည်ပေးပို့သည်။

## လိုအပ်သော အစိတ်အပိုင်းများ

- Python 3.12+
- သင့်ပတ်ဝန်းကျင်တွင် Azure OpenAI ဖွဲ့စည်းထည့်သွင်းထားမှု
- Chrome သို့မဟုတ် Chromium ကို ဒေသခံတွင် တပ်ဆင်ထားရန်
- Playwright ပါဝင်ပစ္စည်းများ တပ်ဆင်ထားရန်
- async Python ကို အခြေခံအသိပညာရှိခြင်း

## စတင်ပြင်ဆင်ခြင်း

စာအုပ်အတွင်းအသုံးပြုသည့် ပက်ကေ့ဂျ်များကို တပ်ဆင်ပါ:

```bash
pip install browser_use playwright python-dotenv
playwright install chromium
```

စာအုပ်တွင် အသုံးပြုသော Azure OpenAI ပတ်ဝန်းကျင်အပတ်အစ်များကို သတ်မှတ်ပါ:

```bash
AZURE_OPENAI_ENDPOINT=...
AZURE_OPENAI_API_KEY=...
AZURE_OPENAI_CHAT_DEPLOYMENT_NAME=...
# ရွေးချယ်စရာ: ဖြုတ်ထားလျှင် နောက်ဆုံးဆုံးအပ်တဲ့ API ဗားရှင်းကို အသုံးပြုမည်။
AZURE_OPENAI_API_VERSION=...
```

## နည်းပညာဗွီဇရှင်း

စာအုပ်တွင် ဟိုက်ဘရီဒ် ဘရောက်ဇာအလိုအလျောက်လုပ်ဆောင်မှု လမ်းစဉ်ကို ပြသထားသည်:

1. CDP ကို အပေါ်တွင် အခွင့်အရေးပြုထားသော Chrome ကို စတင်တည်ဆောက်ကာ Playwright နှင့် Browser-Use နှစ်ခုလုံး သိသာသော browser session တစ်ခုမှာ အတူတကွအလုပ်လုပ်နိုင်သည်။
2. Browser-Use ကိုယ်စားလှယ်တစ်ဦးသည် Airbnb ဖွင့်ခြင်း၊ pop-up များ ပိတ်ပေးခြင်း၊ Stockholm ရှာဖွေခြင်းကဲ့သို့ အဆုံးမဲ့သွားလာမှု လုပ်ငန်းတာဝန်များကို ကိုင်တွယ်ပြုလုပ်သည်။
3. လက်ရှိ စာမျက်နှာကို Pydantic စနစ်တကျ schema အသုံးပြုကာ စာရင်းပုံစံခေါင်းစဉ်များ၊ တစ်နေ့တည်း စျေးနှုန်းများ၊ ရရှိနိုင်မှုနှုန်း နှင့် URL များကို ထုတ်ယူသည်။
4. Python လျှို့ဝှက်ချက်သည် ထုတ်ယူထားသည့် စာရင်းများကို နှိုင်းယှဉ်ပြီး အစျေးသက်သာဆုံး ရလဒ်ကို ထင်ဟပ်သည်။

ဒီနည်းလမ်းသည် Browser-Use ၏ သဘာဝသဘာဝ မျက်စိမြင်အရ အာရုံနှင့် ဆင်ခြင်မှုကို ထိန်းသိမ်းထားပြီး သင့်ကို လိုအပ်သည့်အခါတွင် ကွယ်လွန်သော browser ထိန်းချုပ်မှုဖြစ်စေသည်။

## အဓိကသင်ခန်းစာများနှင့် ကောင်းမွန်သော လေ့လာသင်ကြားနည်းများ

### ကိုယ်စားလှယ် နှင့် တာဝန်ခံ ကို ဘယ်အချိန်သုံးရမလဲ

| အခြေအနေ | ကိုယ်စားလှယ်သုံးရန် | တာဝန်ခံသုံးရန် |
|----------|---------------------|-------------------|
| အပြောင်းအလဲရှိ ပုံစံ | ဟုတ်ကဲ့၊ AI က စာမျက်နှာအပြောင်းအလဲများကို ဖြေရှင်းနိုင်သည် | မဟုတ်ပါ၊ ချို့ယွင်းသည့် selectors ဖြစ်နိုင်သည် |
| သိရှိထားသော ဖွဲ့စည်းမှု | မဟုတ်ပါ၊ ကိုယ်စားလှယ်နဲ့ တိုက်ရိုက်ထိန်းချုပ်ခြင်းထက် များနည်းသည် | ဟုတ်ကဲ့၊ မြန်ဆန်ပြီး တိကျသည် |
| အရာများ ရှာဖွေခြင်း | ဟုတ်ကဲ့၊ သဘာဝဘာသာဖြင့် ကောင်းမွန်သည် | မဟုတ်၊ တိကျသော selector များ လိုအပ်သည် |
| အချိန်ထိန်းချုပ်မှု | မဟုတ်ပါ၊ မကြာခဏခန့်မှန်းခက် | ဟုတ်ကဲ့၊ စောင့်ဆိုင်းမှုနှင့် ထပ်မံကြိုးစားရန် အပြည့်အဝ ထိန်းချုပ်နိုင်သည် |
| အဆင့်မြင့် လုပ်ငန်းစဉ်များ | ဟုတ်ကဲ့၊ မထင်မှတ်ထားသော UI အနေအထားများကို ကိုင်တွယ်နိုင်သည် | မဟုတ်၊ သီးခြားခြေလှမ်းများ လိုအပ်သည် |

### Browser-Use ကောင်းမွန်သောလေ့လာမှုနည်းလမ်းများ

1. သွားရောက်လေ့လာမှုနှင့် အပြောင်းအလဲရှိသော လမ်းညွှန်မှုအတွက် ကိုယ်စားလှယ်ဖြင့် စတင်ပါ။
2. လုပ်ဆောင်မှုပိုမိုခန့်မှန်းနိုင်လာသည့်အခါ တိုက်ရိုက် စာမျက်နှာထိန်းချုပ်မှုသို့ ပြောင်းပါ။
3. ထုတ်ယူထားသော ဒေတာများအား စနစ်တကျ သက်မှတ်ထားသော ပုံစံများဖြင့် အသုံးပြုပါ။
4. မြင်တွေ့ရသော UI ပြောင်းလဲမှုများ ပြဿနာဖြစ်နေသော လုပ်ဆောင်ချက်များနောက်တွင် အချိန်နှောင့်နှေးမှုများ ထည့်သွင်းပါ။
5. ပြဿနာဖြစ်ပွားမှုများကို လွယ်ကူစွာခွဲခြားစစ်ဆေးနိုင်ရန် လည်ပတ်စဥ်တွင် ဓာတ်ပုံရိုက်ယူပါ။
6. ဝဘ်ဆိုဒ်များ၏ ပြောင်းလဲမှုများကို မျှော်လင့်ပြီး pop-up များနဲ့ ပုံစံပြောင်းလဲမှုများအတွက် မျှော်လင့်ချက်နည်းလမ်းများ အတော်လေးတည်ဆောက်ပါ။
7. ကိုယ်စားလှယ်နှင့် တာဝန်ခံ ပုံစံများကို ပေါင်းစပ်အသုံးပြုခြင်းဖြင့် သာယာမှုနှင့် တိကျမှန်ကန်မှုကို လိုက်လျောညီထွေ ဖြစ်စေပါ။

### ဘရောက်ဇာကိုယ်စားလှယ်များအတွက် ဘေးကင်းရေး လမ်းညွှန်ချက်များ

ဘရောက်ဇာ ကိုယ်စားလှယ်များသည် တိုက်ရိုက် လက်တွေ့ရှိသော ဝဘ်ဆိုဒ်များအပေါ်မှာ လည်ပတ်လျက်ရှိလို့ တစ်သင်ကြားမှတစ်ကိုယ်ရေ API ခေါ်ဆိုမှုများနှင့် ကွာခြားသော သတ်မှတ်ကန့်သတ်ချက်များလိုအပ်သည်။ စမ်းသပ်ရေး မှ စနစ်တကျ Workflow ကူးပြောင်းခြင်းမပြုမီ တွေ့မြင်၊ နှိပ်သည်နှင့် စာတင်သည်တို့ကို နှိုင်းယှဉ်သတ်မှတ်ပါ။

1. **ဘရောက်ဇာ ပတ်ဝန်းကျင်ကို သတ်မှတ်ပါ။** ကိုယ်စားလှယ်ကို ထိပ်တန်း browser profile သို့ sandbox တစ်ခုတွင် လည်ပတ်စေပြီး လုပ်ငန်းအတွက်လိုအပ်သော domain များသာ အကန့်အသတ်ထားပါ။
2. **ကြည့်ရှုမှုနှင့် လုပ်ဆောင်မှုကို ခြားနားစေပါ။** ကိုယ်စားလှယ်အား စာတင်သည်၊ ဖတ်တယ်၊ ဒေတာယူသည်တို့ကို အရင်လုပ်ပေးပါ၊ ပုံစံတင်ခြင်း၊ သတင်းပို့ခြင်း၊ ခရီးသည့်စာရင်းပို့ခြင်း၊ အဝယ်လုပ်ခြင်း၊ မှတ်တမ်းဖျက်ခြင်း သို့မဟုတ် အကောင့်ပြင်ဆင်ခြင်းများကို အသုံးပြုသူ က အတည်ပြုပါမှ ဆက်လုပ်ပါ။
3. **လျှို့ဝှက်ချက်များကို စာရင်းနှင့် စနစ်ထဲ မထည့်ပါနှင့်။** စကားဝှက်၊ ငွေပေးချေမှုအသေးစိတ်၊ session cookies သို့မဟုတ် ကိုယ်ရေးအချက်အလက်များအား မော်ဒယ် ထဲမှာ မထည့်ပါနှင့်။ အသုံးပြုသူကို အမှတ်အသား မှတဆင့် လက်မှတ်ရေးထိုးခြင်းနှင့် အချက်အလက်များကို ဖျက်ပစ်ခြင်းဖြင့် ကာကွယ်ပါ။
4. **စာမျက်နှာ အကြောင်းအရာကို မယုံကြည့်ရသောအကြောင်းအရာအဖြစ် သတ်မှတ်ပါ။** ဝဘ်ဆိုဒ်တစ်ခုတွင် ကိုယ်စားလှယ်ကို အားဖြည့်ရန် မရည်ရွယ်သော လမ်းညွှန်ချက်များပါနိုင်သည်။ ကိုယ်စားလှယ်သည် မူလ ရည်ရွယ်ချက်ပြောင်းရန်၊ ဒေတာဖော်ထွက်ရန်၊ အန္တရာယ်ကာကွယ်ရေး မရှိရန် သို့မဟုတ် မသက်ဆိုင်သော ဝဘ်ဆိုဒ်သို့ သွားရန် ပြောသောစာသားများကို ပယ်ဖျက်သင့်သည်။
5. **အန္တရာယ်ရှိသော လုပ်ဆောင်ချက်များအတွက် သေချာသည့် စစ်ဆေးချက်များ ဖန်တီးပါ။** လစ်လပ်နေသော URL၊ စာမျက်နှာခေါင်းစဉ်၊ ရွေးချယ်ထားသည့်အရာ၊ စျေးနှုန်း၊ လက်ခံသူနှင့် လုပ်ဆောင်ချက်အကျဉ်းကို ကုဒ်ဖြင့် အတည်ပြုရန် သုံးပါ။
6. ** ငွေကြေးကန့်သတ်မှုများနှင့် ရပ်တန့်မှု သတ်မှတ်ချက်များ သတ်မှတ်ပါ။** လုပ်ဆောင်ချက်၊ ထပ်မံကြိုးစားမှုများ၊ tab များနှင့် ကြာချိန်များအား အကန့်အသတ်ထားပါ။ စာမျက်နှာအနေအထား မရှင်းလင်းချေမှုမရှိသောအခါ ရပ်တန့်ပြီး ဆက်လက်နှိပ်မှု မလုပ်ပါနှင့်။
7. **အသုံးဝင်သက်သေများသာ မှတ်တမ်းတင်ပါ၊ မလိုအပ်သော အချက်အလက်များ မမှတ်တမ်းတင်ပါနှင့်။** လုပ်ဆောင်ချက်အကျဉ်း၊ အချိန်မှတ်တမ်း၊ URL များ၊ ရွေးထားသော အရာ၏ ဖော်ပြချက်များ၊ ဓာတ်ပုံ ရည်ညွှန်းချက်များကို သိမ်းဆည်းပြီး မလိုအပ်သော ကိုယ်ရေးအချက်အလက်များကို သိမ်းဆည်းခြင်းမှရှောင်ကြဉ်ပါ။

Airbnb ဥပမာတွင်၊ လုံခြုံနေရာကောင်းသော မူလတည်ရှိမှုမှာ စာရင်းများ ရှာဖွေကာ စျေးနှုန်းများ ထုတ်ယူခြင်းဖြစ်သည်။ အကောင့်ဝင်ခြင်း၊ ဟုတ်သူတစ်ဦးအား ဆက်သွယ်ခြင်း သို့မဟုတ် ကမ်းလှမ်းမှုများ ပြီးဆုံးခြင်းတို့ကို အသုံးပြုသူ သဘောတူညီချက် ခံရပါမည်။

### လက်တွေ့ ကမ္ဘာအတွင်း အသုံးပြုမှုနမူနာများ

- ခရီးသွားစာရင်းချုပ်ခြင်းနှင့် စျေးနှုန်းကြည့်ရှုခြင်း
- အီလက်ထရွန်နစ် ကုန်များ စျေးနှုန်းနှိုင်းယှဉ်ခြင်းနှင့် ရရှိနိုင်မှု စစ်ဆေးခြင်း
- အပြောင်းအလဲရှိ ဝဘ်ဆိုဒ်များမှ စနစ်တကျ ထုတ်ယူခြင်း
- မျက်နှာပြင် သေချာစွာ စမ်းသပ်ခြင်းနှင့် မှန်ကန်မှုအတည်ပြုခြင်း
- ဝဘ်ဆိုဒ် မော်နီတာလုပ်ခြင်းနှင့် သတိပေးခြင်း
- အဆင့်မြင့် အဆင့် များဖြတ်ပြီး ဖောင်များကို သိပ္ပံနည်းဖြင့် ဖြည့်တင်းခြင်း

## လက်တွေ့ ကမ္ဘာအတွင်း နမူနာ - Microsoft Project Opal

ဒီသင်ခန်းစာတွင် သင်တည်ဆောက်မယ့် ကိုယ်စားလှယ်သည် **ကွန်ပျူတာ အသုံးပြုမှု ကိုယ်စားလှယ် (CUA)** ဟူသော ဗမာဖိုင်နည်းဖြင့် ဘရောက်ဇာကို လူတစ်ဦးကဲ့သို့ လမ်းညွှန်ပေးသည့် ပရိုဂရမ် ဂုဏ်သင့်ပြုထားသော ဒေသခံဗားရှင်းတစ်ခုဖြစ်သည်။ Microsoft သည် Microsoft 365 Copilot တွင် **[Project Opal (Frontier)](https://support.microsoft.com/en-us/microsoft-365-copilot/get-started-with-project-opal-frontier)** ကို သက်ဆိုင်ရာလုပ်ငန်းအသုံးပြုသူများအတွက် တင်ဆက်ပေးနေသည်။

Project Opal ဖြင့် သင့်ရဲ့ တာဝန်ကို ရေးဖော်၍ ကိုယ်စားလှယ်သည် သင့်အစား **Windows 365 Cloud PC အတွင်း စနစ်တကျပုံစံဖြင့် ကွန်ပျူတာအသုံးပြုမှုများကို အွန်လိုင်းပေါ်မှာ လုပ်ဆောင်သည်။** အဖွဲ့အစည်း၏ ဘရောက်ဇာအခြေခံသော အသုံးပြုမှုများ၊ဆိုက်များနှင့် ဒေတာများကို ကိုင်တွယ်လျက်ရှိသည်။ ၎င်းသည် **နောက်ခံတွင် အဆက်မပြတ် ပြုလုပ်လျက်ရှိပြီး** သင်သည် လမ်းညွှန် hoặc တာဝန်ယူအုပ်ချုပ်နိုင်သည်။ နမူနာအလုပ်များမှာ:

- လုံခြုံရေးအဖွဲ့ဝင်များ ဦးရေ စီမံခန့်ခွဲခြင်း
- သက်ဆိုင်ရာ သေချာမှုစစ်ဆေးချက်များ စုဆောင်း၍ လက်မှတ်ရေးထိုးခြင်း
- IT ပျက်ကွက်မှုများ လျင်မြန်စွာ ဖြေရှင်းခြင်း (ဘလော့ဂ် များအခြေခံ ဂရုစိုက်မှု၊ ပိုင်ဆိုင်သူ ထားရှိခြင်း၊ အတူတူ မျှဝေခြင်း)
- Excel ဒေတာများကို ငွေကြေးပိတ်သိမ်းစာတမ်းတစ်ခုအဖြစ် စုဆောင်းခြင်း

> **ရရှိနိုင်မှု:** Project Opal သည် မိုက်ခရိုဆော့ 365 Copilot အသုံးပြုခွင့် ရရှိထားသည့် Frontier early access program အသုံးပြုသူများအတွက် ရရှိနိုင်ပြီး၊ သင့် စီမံခန့်ခွဲသူမှ တပ်ဆင်မှု ပြီးစီးထားရမည်။ Frontier အသွင်အပြင်အသစ် ဖြစ်သည့်အတွက် လာမည့် အချိန်အတွင်း၊ လုပ်ဆောင်ချက်များ ပြောင်းလဲနိုင်သည်။

## အတွေးအခေါ် စစ်ဆေးမှု

နောက်သင်ခန်းစာသို့ ပြောင်းရွှေ့မီ သင့်ရဲ့ နားလည်မှုကို စမ်းသပ်ပါ။

**1. ဘရောက်ဇာအခြေခံ ကွန်ပျူတာအသုံးပြုမှု ကိုယ်စားလှယ်သည် API သာဖြင့် လည်ပတ်မှုထက် ဘယ်အချိန်ပိုမိုသင့်တော်သနည်း?**

<details>
<summary>ဖြေကြားချက်</summary>

လုပ်ငန်းတာဝန်မှာ ဝဘ် UI တွင် တွေ့မြင်ရသောအရာများပေါ် မူတည်သည်၊ လိုအပ်သော API ကို ဖော်ပြခြင်း မရှိသည် သို့မဟုတ် စာမျက်နှာ အလျင်အမြန် ပြောင်းလဲသည့်အခါ ဘရောက်ဇာကိုယ်စားလှယ်ကို အသုံးပြုပါ။ ကော်နက် API ရှိပါက API ကို ပိုမြန်၊ စမ်းသပ်ရလွယ်ကူပြီး လုံခြုံမှုပိုမိုကောင်းသဖြင့် ဦးစားပေး သုံးစွဲပါ။
</details>

**2. ဟိုက်ဘရီဒ် လုပ်ငန်းစဉ်တွင် ဘယ်အစိတ်အပိုင်းများကို ကိုယ်စားလှယ် က ကိုင်တွယ်ပြီး ဘယ်အစိတ်အပိုင်းများကို တိုက်ရိုက် Playwright ကုဒ်က ကိုင်တွယ်သင့်သနည်း?**

<details>
<summary>ဖြေကြားချက်</summary>

ကိုယ်စားလှယ်အား အဆုံးမဲ့ သွားလာမှုနှင့် အပြောင်းအလဲ UI အနေအထားများကို ကိုင်တွယ်စေပါ။ ဥပမာ - မွန်ရာစာမျက်နှာရှာခြင်း သို့မဟုတ် မမျှော်လင့်ထားသော Pop-up များ ပိတ်ခြင်း။ စာမျက်နှာ ဖွဲ့စည်းမှုပေါ်မူတည်၍ တိကျမှု၊ ထပ်မံကြိုးစား၊ စောင့်ဆိုင်းမှုများလိုအပ်သည့်အခါ တိုက်ရိုက် Playwright ထိန်းချုပ်မှုသို့ ပြောင်းပါ။
</details>

**3. Airbnb နမူနာသည် အသုံးပြုသူ လက်မှတ်ရေးထိုးလိုနိုင်သည့် စာရင်းတစ်ခုကို ရှာသည်။ Workflow မှာ ဝင်ရောက်ခြင်း၊ အိမ်ရှင်ဆက်သွယ်ခြင်း သို့မဟုတ် အတည်ပြုခြင်းမပြုမီ ဘာတွေဖြစ်သင့်သနည်း?**

<details>
<summary>ဖြေကြားချက်</summary>

အသုံးပြုသူထံမှ ထောက်ခံချက်တစ်ခု ရလာသည်အထိ workflow ကို ရပ်ပါ။ မေးခွန်းမေးခြင်း၌ ရွေးချယ်ထားသော စာရင်း၊ လက်ရှိ URL၊ စျေးနှုန်း၊ နေ့စွဲများနှင့် ရည်ရွယ်ချက်များ အကျဉ်းချုပ်ကို ပြပါ။ ရှာဖွေမှုနှင့် စျေးနှုန်း ထုတ်ယူမှုသည် ကိုယ်တိုင်ပြုလုပ်နိုင်သော်လည်း အကောင့်ဝင်ခြင်း၊ သတင်းပို့ခြင်း၊ ဝယ်ယူမှုနှင့် လက်မှတ်ရေးထိုးခြင်းများအား အသုံးပြုသူ သဘောတူညီချက်လိုအပ်သည်။
</details>

**4. ဝဘ်စာမျက်နှာတစ်ခုသည် ကိုယ်စားလှယ်အား မူလညွှန်ကြားချက်များကို မလိုက်နာရန်၊ အခြားဆိုဒ်သို့ သွားရန်နှင့် သိမ်းဆည်းထားသော လျှို့ဝှက်ချက်များ ဖော်ထုတ်ရန် ပြောသည်။ ကိုယ်စားလှယ်သည် ဤစာသားအား မည်သို့ လုပ်ဆောင်သင့်သနည်း?**

<details>
<summary>ဖြေကြားချက်</summary>

ရုပ်သိမ်းမယ့် စာမျက်နှာ အကြောင်းအရာအဖြစ် ထောက်ခံပါ၊ ဖန်တီးသူ သို့မဟုတ် အသုံးပြုသူ၏ လမ်းညွှန်ချက်အဖြစ် မယူပါနှင့်။ ကိုယ်စားလှယ်သည် ခွင့်ပြုထားသော domain နှင့် လုပ်ငန်းလုပ်ရုံတွင်သာ နေရှိရမည်၊ လျှို့ဝှက်ချက်များ ဖော်ထုတ်ရန် မလိုလားပါနှင့်၊ ရည်ရွယ်ချက်ကို ပြောင်းရန်၊ အန္တရာယ်ကာကွယ်ခြင်း အားဖြုတ်ရန် သို့မဟုတ် မသက်ဆိုင်သောဆိုဒ်သို့ သွားရန် ကုဒ်အချက်များကို လိုက်နာခြင်းမှ ရှောင်ရွှားပါ။
</details>

**5. ဘရောက်ဇာ ကိုယ်စားလှယ် လည်ပတ်ရာတွင် သက်သေခံရန် အသုံးဝင်သောအချက်များက ဘာတွေလဲ၊ မသိမ်းဆည်းသင့်သောအချက်များက ဘာတွေလဲ?**

<details>
<summary>ဖြေကြားချက်</summary>

လုပ်ဆောင်ချက်အကျဉ်း၊ အချိန်မှတ်တမ်းများ၊ URL များ၊ ရွေးချယ်ထားသော အချက်အလက်ဖော်ပြချက်များ၊ သက်မှတ်ချက်ရလဒ်များ၊ဓာတ်ပုံ ရှိငံ့ချက်များကို သိမ်းဆည်းပါ။ စကားဝှက်၊ ငွေပေးချေမှုအသေးစိတ်များ၊ session cookie များ၊ ကိုယ်ရေးဖြစ်သော ဒေတာများ၊ စာမျက်နှာ အကြောင်းအရာအပြည့်အစုံတို့ကို စိတ်ကူးထားသော မှတ်တမ်းနှင့် လုံခြုံရေးအကြောင်းတရား မရှိသေးပဲ မသိမ်းဆည်းပါနှင့်။
</details>
