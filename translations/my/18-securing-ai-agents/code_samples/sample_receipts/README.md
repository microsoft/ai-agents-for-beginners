# နမူနာ လက်ခံလွှာ ဖိုင်များ

နိုတ်ဘုတ်မဖွင့်ဘဲ စစ်ဆေးနိုင်ရန် ကြိုတင် ထုတ်လုပ်ထားသော လက်ခံလွှာဖိုင်သုံးခု။

| ဖိုင် | ၎င်းသည် ဘာလဲ |
|---|---|
| `01_valid_receipt.json` | `lookup_flights` ကိရိယာခေါ်ဆိုမှုအတွက် မှန်ကန်စွာ လက်မှတ်ထိုးထားသော လက်ခံလွှာတစ်စောင်။ အတည်ပြုချက် True ပြန်ပေးသည်။ |
| `02_tampered_receipt.json` | လက်မှတ်ထိုးပြီးနောက် သီးခြားနယ်နေရာတစ်ခု ပြင်ဆင်ထားသည့် အတူတူ လက်ခံလွှာ။ အတည်ပြုချက် False ဖြစ်သည်။ |
| `03_chain_three_receipts.json` | တစ်ခုချင်းစီကို ယခင်ထက် ချိတ်ဆက်ထားသည့် မတူညီသော လက်ခံလွှာ သုံးခု (ရှာဖွေမှု, ထိန်းသိမ်းမှု, စာအုပ်) ဖြစ်ပြီး `previous_receipt_hash` ဖြင့် ချိတ်ဆက်ထားသည်။ |

၎င်း ဖိုင်များသည် payload ၏ canonical JCS bytes ကို တိုက်ရိုက် Ed25519 ဖြင့် လက်မှတ်ထိုးသည်။
SHA-256 ကို အကြောင်းအရာတုံ့ပြောင်းမှုများနှင့် လက်ခံလွှာစဉ်ချိတ်ဆက်မှုများအတွက်သာ အသုံးပြုပြီး
လက်မှတ်ထိုးခြင်းမပြုမီ အပို pre-hash အဖြစ် မအသုံးပြုပါ။

## နမူနာများကို အတည်ပြုခြင်း

နိုတ်ဘုတ်သည် အတည်ပြုခြင်းကို အပိုင်းလေးပိုင်းဖြင့် ရွေ့ဆိုင်းပြသသည်။ 
ဤဖိုင်များကို နိုတ်ဘုတ်ဇာတ်လမ်းမဖြတ်ဘဲ တိုက်ရိုက် အတည်ပြုရန် -

```python
import json
from pathlib import Path

# Assumes you have completed the imports and helper functions
# from sections 1 and 2 of 18-signed-receipts.ipynb.

valid = json.loads(Path("01_valid_receipt.json").read_text())
print(f"Valid receipt: {verify_receipt(valid)}")        # True

tampered = json.loads(Path("02_tampered_receipt.json").read_text())
print(f"Tampered receipt: {verify_receipt(tampered)}")  # False

chain = json.loads(Path("03_chain_three_receipts.json").read_text())
for r in verify_chain(chain):
    print(f"  Receipt {r['index']} ({r['tool']}): {'VALID' if r['overall_valid'] else 'INVALID'}")
```

## ၎င်းတို့ကို အဘယ်လို ထုတ်လုပ်ခဲ့ပါသလဲ

ဖိုင်များသည် နိုတ်ဘုတ်နှင့် အတူတူသော ကုဒ်လမ်းကြောင်းကို အသုံးပြုသည်၊ တစ်ခုတည်းသော အတည်ပြုလက်မှတ် key နှင့် ဘိုင်ထုတ်နံပါတ်များကို ပြုပြင်ထားသည်။
ပြန်လည်ထုတ်လုပ်ရန် -

```bash
python3 generate_fixtures.py
```

(ဒီ ဖိုင်၌ `generate_fixtures.py` တွင် စက္ကန့်ရေးထားသည်)

## ကျောင်းသားများသည် raw JSON ကို စစ်ဆေးရာတွင် သင်ယူနိုင်သည်များ

raw လက်ခံလွှာ ပုံစံကို ဖတ်ခြင်းသည် နိုတ်ဘုတ်ရှိ အခွက်များမပေးနိုင်သည့် သဘောတရားကို တည်ဆောက်ပေးသည်။
JSON ကို အလျင်မြန်စွာ ကြည့်ရှုသူများ သတိပြုမိကြရသည် -

1. လက်မှတ်သည် တောက်ပသော base64url စာကြောင်းဖြစ်သော်လည်း ကျန်သော နယ်မြေများအားလုံးသည် ရိုးရှင်းသော
   ဖတ်ရှုနိုင်သော JSON ဖြစ်သည်။ လက်မှတ်သည် အကြောင်းအရာကို 암호화 ​​မလုပ်ပဲ ထောက်ခံသည်။
2. `public_key` သည် လက်ခံလွှာအတွင်းတွင် ပေါင်းထည့်ထားသည်။ စစ်ဆေးသူတစ်ဦးသည် 
   အခြားအရာ မလိုအပ်ပဲ အတည်ပြုနိုင်သည် (key သည် ထုတ်ပေးသူ ပိုင်ဆိုင်မှုကို ယုံကြည်ခြင်း အပေါ် မူတည်သည့်အနေဖြင့်)၊
   ထုတ်လွှင့်သူ အထောက်အထား များအတွက် README မှ သင်ခန်းစာကို ကြည့်ပါ။
3. နယ်မြေ အချက်အလက် တစ်ခုစီကို တည်းဖြတ်ပြီးနောက် ၎င်းဖိုင်နှင့်
   `02_tampered_receipt.json` ကိုပြန်လည်နှိုင်းယှဉ်ခြင်းသည် byte အဆင့်စနစ်ကို ထင်မြင်ရလှသည်။
