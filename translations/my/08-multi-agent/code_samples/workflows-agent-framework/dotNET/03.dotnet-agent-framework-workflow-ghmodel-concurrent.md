# ⚡ Azure OpenAI (Responses API) (.NET) နှင့် အတူ မျှတသော Agent Workflow များ

## 📋 မြန်နှုန်းမြင့် တပြိုင်နက်လုပ်ငန်းစဉ် သင်ခန်းစာ

ဒီ notebook သည် Microsoft Agent Framework အတွက် .NET နှင့် Azure OpenAI (Responses API) ကိုသုံးပြီး **မျှတသော workflow ပုံစံများ** ကိုဖော်ပြသည်။ သင်သည် အမြင့်ဆုံး စွမ်းဆောင်ရည် ရရှိစေရန်အတွက် AI agent များစွာတပြိုင်နက် လုပ်ဆောင်ချက်များကို စဉ်ဆက်မပြတ်ပြီး ပူးပေါင်းညှိနှိုင်းမှုနှင့်ဒေတာတည်ငြိမ်မှုကို ထိန်းသိမ်းကာ တပြိုင်နက်လုပ်ငန်းစဉ်များကို တည်ဆောက်နည်းကို သင်ယူမည်ဖြစ်သည်။

## 🎯 သင်ယူလိုသည်များ

### 🚀 **မျှတသော လုပ်ငန်းလုပ်နည်း မူလတန်းများ**
- **တပြိုင်နက် Agent ဆောင်ရွက်မှု**: အမြင့်ဆုံး စွမ်းဆောင်ရည်အတွက် AI agent များစွာတပြိုင်နက် လည်ပတ်ခြင်း
- **Async/Await ပုံစံများ**: အကျိုးရှိစွာ မျှတသော လုပ်ငန်းစဉ်များအတွက် .NET ရဲ့ async programming မော်ဒယ်ကို အသုံးပြုခြင်း
- **Azure OpenAI (Responses API)**: Azure OpenAI Responses API သို့ မျှတစွာ ခေါ်ဆိုမှုများကို ညှိနှိုင်းခြင်း
- **အရင်းအမြစ် စီမံခန့်ခွဲမှု**: မျှတသော လည်ပတ်မှုများနှင့် AI မော်ဒယ်အရင်းအမြစ်များကို ထိရောက်စွာ စီမံခြင်း

### 🏗️ **အဆင့်မြင့် မျှတသော စာချုပ်ဖွဲ့စည်းမှု**
- **Task-Based Parallelism**: မျှတစွာ အကောင်အထည်ဖော်ရန် .NET Task Parallel Library ကိုအသုံးပြုခြင်း
- **Synchronization ပုံစံများ**: ပြိုင်ဆိုင်မှုအခြေအနေများမှကာကွယ်ကာ မျှတသော Agent များကို ညှိနှိုင်းခြင်း
- **Load Balancing**: ရရှိနိုင်သမျှ concurrent အင်အားထဲတွင် အလုပ်များကို ထိရောက်စွာ ဖြန့်ဝေခြင်း
- **Fault Tolerance**: Agent တစ်ဦးချင်းစီ၏ မအောင်မြင်မှုများကို workflow အားလုံးကို ထိခိုက်စေခြင်းမရှိစေရန် လက်ခံခြင်း

### 🏢 **စီးပွားရေးအတွက် concurrent applications များ**
- **အမြင့် volume စာရွက်စာတမ်းများလုပ်ငန်းစဉ်**: အတူတကွ စာရွက်စာတမ်းများကို ဆောင်ရွက်ခြင်း
- **အချိန်နှင့်တပြိုင်နက် အကြောင်းအရာ စိစစ်ခြင်း**: ရောက်ရှိလာသော ဒေတာစီးဆင်းမှုများကို မျှတစွာ စိစစ်ခြင်း
- **စုစုပေါင်း စီမံခန့်ခွဲမှု အလားအလာများ ထိန်းသိမ်းခြင်း**: အကျယ်အဝန်း ကြီးမားသော ဒေတာလုပ်ငန်းစဉ်များတွင် throughput အများဆုံးရရှိစေရန်
- **မြိုလည်းအမျိုးမျိုး စိစစ်ခြင်း**: အကြောင်းအရာအမျိုးအစားနှင့် ဖော်แมတ် မတူညီသော ပေါင်းစပ်လုပ်ငန်းစဉ်များ

## 🎨 **Concurrent Workflow ဒီဇိုင်း ပုံစံများ**

### 🔍 **တပြိုင်နက် သုတေသနနှင့် စိစစ်ခြင်း**
```
Research Topic → Concurrent Research Agents → Result Synthesis → Final Report
```

### 📊 **အရင်းအမြစ်စုံ ဒေတာလုပ်ငန်းစဉ်**
```
Data Sources → Parallel Processing Agents → Data Integration → Unified Output
```


### 🔄 **Fan-Out/Fan-In လုပ်ငန်းစဉ်**
```
Single Input → Multiple Concurrent Processors → Result Aggregation → Single Output
```

## 🏢 **စီးပွားရေး စွမ်းဆောင်ရည် အကျိုးကျေးဇူးများ**

### ⚡ **Throughput နှင့် အသွင်အပြင်တိုးမြှင့်မှု**
- **တန်းလိုက် စွမ်းဆောင်ရည် တိုးတက်မှု**: မျှတသော agent များ ပေါင်းထည့်ခြင်းဖြင့် throughput တိုးပွားအောင်လုပ်ခြင်း
- **အရင်းအမြစ် အသုံးပြုမှု**: ရရှိနိုင်သည့် AI မော်ဒယ်စွမ်းအားအပြည့်အဝ အသုံးချခြင်း
- **လုပ်ငန်းစဉ် အချိန် ဖြတ်တောက်မှု**: တပြိုင်နက် အကောင်အထည်ဖော်မှုဖြင့် အချိန်ချုပ်ချောင်းခြင်း
- **ယူနပြန်သုံးစွဲမှု**: လုပ်ငန်းပမာဏအပေါ်မူတည်၍ မျှတသော agent အရေအတွက်ကို လိုက်လျောညီထွေစွာ ပြောင်းလဲနိုင်ခြင်း

### 🛡️ **ယုံကြည်စိတ်ချမှုနှင့် ပြန်လည်လုံခြုံမှု**
- **စွန့်စားမှု သီးခြားထိန်းသိမ်းမှု**: Agent တစ်ယောက်ချင်း မအောင်မြင်ခြင်းသည် အခြား မျှတသော လုပ်ငန်းစဉ်များကို ခြိမ်းခြောက်မှု မရှိစေခြင်း
- **နူးညံ့သော ကျဆင်းမှု**: အင်အားလျော့ချနေချိန်တွင် စနစ်တဝှမ်း လည်ပတ်ရပ်နားခြင်း မဖြစ်စေပါ
- **အမှား ပြန်လည်သတ်မှတ်ခြင်း**: မအောင်မြင်သော မျှတသောလုပ်ငန်းစဉ်များအတွက် အလိုအလျောက် ထပ်မံကြိုးစားခြင်း
- **အလုပ်ခွဲဝေမှု**: ရရှိနိုင်သော agent များအကြား အလုပ်များကို တန်းတူ ခွဲခြားပေးခြင်း

### 📊 **စွမ်းဆောင်ရည်စောင့်ကြည့်မှု**
- **Concurrent အကောင်အထည်ဖော်မှု အချက်အလက်များ**: တပြိုင်နက်လုပ်ငန်းစဉ်များအားလုံး၏ စွမ်းဆောင်ရည်ကို ထိန်းသိမ်းခြင်း
- **အရင်းအမြစ် အသုံးပြုမှု သုံးသပ်ခြင်း**: CPU၊ အသံမှတ်ဧရိယာ နှင့် ကွန်ရက်အသုံးပြုမှုကို စောင့်ကြည့်ခြင်း

- **ပိုးလမ်းများ ဖော်ထုတ်ခြင်း**: စွမ်းဆောင်ရည် ကန့်သတ်ချက်များကို ရှာဖွေပြီး ဖြေရှင်းခြင်း

## 💻 ကုဒ်ကို လည်ပတ်ခြင်း

အပြည့်အစုံ အကောင်အထည်ဖော်ချက်ကို `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs` တွင် ရနိုင်သည်။ ဒီဖိုင်သည် ခရီးသွားစီမံချက်အတွက် **Fan-Out/Fan-In concurrent workflow** ကို ဖော်ပြသည်။

### 🏗️ **Workflow စာမူဖွဲ့စည်းမှု**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**အဓိက အစိတ်အပိုင်းများ:**

1. **ConcurrentStartExecutor**: အသုံးပြုသူ အပ်ဒိတ်ကို Agent များအားလုံးသို့ တပြိုင်နက် ပေးပို့ပေးသည်
2. **Researcher Agent**: နေရာများနှင့် ဆွဲဆောင်မှုပိုင်းကို concurrent ပုံစံစစ်ဆေးသည်
3. **Planner Agent**: ခရီးစဉ်အကြမ်းဖျဉ်းကို concurrent ပုံစံဖြင့် ပြုလုပ်သည်
4. **ConcurrentAggregationExecutor**: အဆိုပါ agent နှစ်ဦး၏ ရလဒ်များကိုစုဆောင်း၍ ပေါင်းစပ်ပေးသည်

### 🎯 **Fan-Out/Fan-In ပုံစံ**

ဒီ workflow သည် အရိုးရှင်းဆုံး **Fan-Out/Fan-In** ပုံစံကို ဖော်ပြသည်။
- **Fan-Out**: တစ်ခုသော input စာတိုက်ကို မျိုးစုံသော agent များသို့ တပြိုင်နက် ပေးပို့ခြင်း
- **Concurrent Processing**: ညီမျှသော လုပ္ငန္းအေြခာင့္ရႈ မွ ကို တပြိုင္နက္တြင္ စဳံုခင္းျခင္း
- **Fan-In**: အားလုံးသော agent များမှ ရလာသော အဖြေများကိုစုဆောင်းပြီး ထုတ်လွှင့်ခြင်း

### 📝 မျှော်မှန်းထားသော ထုတ်လွှင့်ချက်

Workflow သည်:
1. **တစ်ပြိုင်နက် မှာတင်ပို့မှု**: "Plan a trip to Seattle in December" ကို agent နှစ်ဦးသို့ တပြိုင်နက် ပေးပို့သည်
2. **Concurrent Processing**: agent နှစ်ဦးသည် တပြိုင်နက်လုပ်ဆောင်သည် -
   - Researcher သည် ဆွဲဆောင်မှုများနှင့် အသေးစိတ်များကို ဖော်ထုတ်သည်
   - Planner သည် ခရီးစဉ်နှင့် ထောက်ပံ့ရေးအစီအစဉ်များ ပြုလုပ်သည်
3. **Aggregation**: နှစ်ဦးအဖြေများကို စုပေါင်းပြီး အပြည့်အစုံ ထုတ်လွှင့်သည်
4. **ရလဒ်ပြခြင်း**: စုစုပေါင်း ခရီးစဉ်အစီအစဉ်ကို ပြသသည်

### 🔧 ခြုံငုံ ပြင်ဆင်မှု ရွေးချယ်စရာများ

**Agent များ ပိုထည့်ရန်:**
```csharp
// Create additional specialized agents
AIAgent budgetAgent = azureClient.GetChatClient(deployment).AsAIAgent(
    name: "Budget-Agent", instructions: "Calculate travel costs...");

// Add to fan-out
var workflow = new WorkflowBuilder(startExecutor)
    .AddFanOutEdge(startExecutor, targets: [researcherAgent, plannerAgent, budgetAgent])
    .AddFanInBarrierEdge(sources: [researcherAgent, plannerAgent, budgetAgent], target: aggregationExecutor)
    .WithOutputFrom(aggregationExecutor)
    .Build();

// Update aggregation count
if (this._messages.Count == 3) { ... }
```

**Agent ညွှန်ကြားချက် ပြောင်းလဲရန်:**
```csharp
const string ResearcherAgentInstructions = "Your custom instructions for research...";
const string PlanAgentInstructions = "Your custom instructions for planning...";
```

**လုပ်ငန်းပေးပို့မှု ပြောင်းလဲရန်:**
```csharp

    workflow,

```

### 🎯 အလုပ်လုပ်ကွက်အမှန်တကယ် သုံးနိုင်မှုများ

ဒီ concurrent ပုံစံသည် အထူးသင့်လျော်သည် -
- **အကြောင်းအရာ ဖန်တီးမှု**: များစွာသော စာရေးဆရာများ ကွဲပြားသော အပိုင်းများကို တပြိုင်နက် ဖန်တီးခြင်း
- **ကုဒ် သုံးသပ်ခြင်း**: ကြည့်ရှုရန်သူများ မပြိုကွက်သော ထွက်ပေါက်များအတွက် ကွဲပြားသော မြင်ကွင်းများ အခြေခံ၍ သုံးသပ်ခြင်း
- **စျေးကွက် သုတေသန**: မတူညီသော စျေးကွက်ပိုင်းများကို parallel စိစစ်ခြင်း
- **စာရွက်စာတမ်း လုပ်ငန်းစဉ်**: concurrent ကိုယ်စားသွင်းခြင်း၊ စိစစ်ခြင်းနှင့် အတည်ပြုခြင်း
- **မြင်ကြည့်အမြင် မတူညီခြင်း**: တူညီသော input အပေါ် မတူညီသော ရှုမြင်ချက်များ ရယူခြင်း

### 🔍 Custom Executor များ ကို နားလည်ခြင်း

**ConcurrentStartExecutor:**
- `IMessageHandler<string>` interface ကို အကောင်အထည်ဖော်၍ string input ကို လက်ခံသည်
- ဆက်သွယ်နေသော agent များအားလုံးသို့ မက်ဆေ့ခ််များ ပေးပို့သည်
- concurrent လုပ်ငန်းဆောင်တာများကို စတင်ရန် `TurnToken` ကို ပေးပို့သည်

**ConcurrentAggregationExecutor:**
- `IMessageHandler<ChatMessage>` interface ကို အကောင်အထည်ဖော်၍ agent ရမှတ်များ လက်ခံသည်
- မက်ဆေ့ခ််များကို thread-safe နည်းဖြင့် စုဆောင်းသည်
- မျှော်မှန်းထားသော အဖြေများ ပြည့်စုံလာသည်နှင့် တွဲဆက် စုစည်းသည်
- `context.YieldOutputAsync()` ကို သုံး၍ နောက်ဆုံး ထုတ်လွှင့်ချက် ထုတ်ပေးသည်

### ⚡ စွမ်းဆောင်ရည် အကျိုးကျေးဇူးများ

** concurrent နှင့် တန်းလိုက် သုံးသပ်ခြင်း:**

- ဆက်တိုက်လုပ်ဆောင်ခြင်း: Agent1 (30 စက္ကန့်) → Agent2 (30 စက္ကန့်) = **စုစုပေါင်း 60 စက္ကန့်**
- တပြိုင်နက်လုပ်ဆောင်ခြင်း: Agent1 (30 စက္ကန့်) || Agent2 (30 စက္ကန့်) = **စုစုပေါင်း 30 စက္ကန့်**

**အမြန်နှုန်းတိုးတက်မှု**: N ပြိုင်စစ်ဆေးဖော်ရွေများအတွက် N ဆမြန်ဆန်ခြင်း (လုပ်ငန်းနှုန်းနှင့် အရင်းအမြစ်ပေါ်မူတည်သည်)

### 🛡️ အမှားကိုင်တွယ်မှု

workflow သည် တစ်ခုချင်းစီသော ഏဂျင့် အက်စ်လပ်များကို သေချာစွာ ကိုင်တွယ်ပေးသည်။
- တစ်ဦးချင်းအက်စ်လပ်ကျရှုံးပါက၊ အခြားများသည် ဆက်လက်လုပ်ဆောင်ပြုလုပ်သည်။
- Aggregator သည် timeout မူဝါဒကို ထည့်သွင်းနိုင်သည်။
- လိုအပ်ပါက အပို ဆောင်ရွက်ချက်များ ပြန်လည်ပေးပို့နိုင်သည်။

### 📊 အဆင့်မြင့် လုပ်ဆောင်ချက်များ

**အက်စ်လပ်ရေတွက် ပြောင်းလဲနိုင်မှု:**
aggregation logic ကို agent အရေအတွက် မတူညီခြင်းကို ထောက်ပံ့ရန် ပြင်ဆင်ပါ။

```csharp
private int _expectedAgentCount;
private readonly List<ChatMessage> _messages = [];

public override ValueTask HandleAsync(ChatMessage message, IWorkflowContext context, CancellationToken cancellationToken = default)
{
    this._messages.Add(message);
    if (this._messages.Count == _expectedAgentCount)
    {
        // Process aggregation
    }
    
    return ValueTask.CompletedTask;
}
```

ဒီ တပြိုင်နက် workflow ပုံစံက အမြင့်ဆုံး တည်ဆောက်နိုင်သော၊ တိုးချဲ့နိုင်သော AI agent စနစ်များဆောက်ရန် အဓိကဖြစ်ပါသည်!
