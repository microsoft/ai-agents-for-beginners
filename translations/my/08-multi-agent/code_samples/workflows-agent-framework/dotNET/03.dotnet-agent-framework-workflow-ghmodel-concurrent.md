- **Async/Await ပုံစံများ**: .NET ရဲ့ async programming မော်ဒယ်ကို ကောင်းမွန်စွာ အသုံးပြုခြင်း

- **ညှိနှိုင်းခြင်း ပုံစံများ**: 병렬 agent များကို ညှိနှိုင်းပြီး ဖောက်အရွက် မဖြစ်အောင် စီမံခြင်း
- **အလုပ် ချိန်ညှိခြင်း**: ရရှိနိုင်သော 병렬 စွမ်းအားအရ အလုပ်များကို ထိရောက်စွာ ဖြန့်ဝေခြင်း
- **အမှားခံနိုင်ရည်**: တစ်ဦးချင်း agent ပျက်ကွက်မှုများကို စဉ်ဆက်မပြတ် အလုပ်လုပ်စေခြင်း

## 💻 ကုဒ်ကို အလုပ်လုပ်ပုံ

ပြည့်စုံတဲ့ လုပ်ဆောင်မှုကို `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs` ဖိုင်ထဲမှာ ရနိုင်ပါတယ်။ ဒီဖိုင်မှာ ခရီးစဉ် စီမံရန်အတွက် **Fan-Out/Fan-In concurrent workflow** ကို ပြသထားပါတယ်။

### 🏗️ **Workflow ဖွဲ့စည်းပုံ**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**အဓိကပစ္စည်းအစိတ်အပိုင်းများ:**

1. **ConcurrentStartExecutor**: အသုံးပြုသူရဲ့ တောင်းဆိုမှုကို agent များအားလုံးကို တပြိုင်နက် ပေးပို့သည်
2. **Researcher Agent**: နေရာများနှင့် ဆွဲဆောင်မှုများကို concurrent အနေဖြင့် ခွဲခြမ်းစိတ်ဖြာသည်
3. **Planner Agent**: အသေးစိတ် ခရီးစဉ်များကို concurrent အနေဖြင့် ဖန်တီးသည်
4. **ConcurrentAggregationExecutor**: နှစ်ခုလုံးရဲ့ ရလဒ်များကို စုဆောင်းပြီး ပေါင်းစည်းသည်

### 🎯 **Fan-Out/Fan-In ပုံစံ**

ဒီ workflow က ရိုးရာ **Fan-Out/Fan-In** ပုံစံကို ပြသပါတယ်။
- **Fan-Out**: တစ်ခု input message အား အများအတွက် agent များတွင် တပြိုင်နက် ပေးပို့သည်
- **Concurrent လုပ်ဆောင်မှု**: အများအတွက် agent များက တူညီသော တာဝန်ကို 병렬 လုပ်ဆောင်နေကြသည်
- **Fan-In**: အားလုံးရဲ့ တုံ့ပြန်ချက်များကို စုဆောင်းပြီး တစ်ခု output အဖြစ် ပေါင်းစည်းသည်

   - Researcher က ဆွဲဆောင်မှုများနှင့် အသေးစိတ်ကို သတ်မှတ်သည်
   - Planner က ခရီးစဉ်နှင့် စီမံကိန်းများကို ဖန်တီးသည်
3. **Aggregation**: နှစ်ဦးရဲ့ တုံ့ပြန်ချက်ကို ပေါင်းစည်း၍ အပြည့်အစုံ output ပေးသည်
4. **ရလဒ်ပြသမှု**: ခရီးစဉ်အစီအစဉ်ကို အချက်အလက်အပြည့်အစုံနှင့် ပြသသည်

### 🔧 ကိုယ်ပိုင် ပြင်ဆင်မှု ရွေးချယ်စရာများ

**Agent များ ပိုမို ထည့်ပါ:**
```csharp
// Create additional specialized agents

    .WithOutputFrom(aggregationExecutor)
    .Build();

```

**Agent အသွင်ပြင်ဆင်ချက်များ ပြင်ဆင်ပါ:**

**တာဝန် ပြောင်းလဲပါ:**

### 🎯 လက်တွေ့အသုံးဝင်မှုများ

ဒီ concurrent ပုံစံက အတွက် တော်တော်အသင့်လျော်ပါတယ်:
- **Content ဖန်တီးမှု**: တိုးごူး စာရေးသူများက တပြိုင်နက် အပိုင်းအစ အသီးသီး ဖန်တီးခြင်း
- **ကုဒ် စစ်ဆေးမှု**: အမျိုးမျိုးသော မြင်ကွင်းများမှ မျှဝေပြီး ကုဒ်ကို ခွဲခြမ်းစိတ်ဖြာခြင်း
- **စျေးကွက် သုတေသန**: အမျိုးမျိုးသော စျေးကွက်ပိုင်းများအတွက် 병렬 ခွဲခြမ်းစိတ်ဖြာခြင်း
- **စာရွက် စီမံခြင်း**: concurrent အနေဖြင့် ထုတ်ယူခြင်း၊ ခွဲခြမ်းစိတ်ဖြာခြင်း နှင့် မှတ်သားခြင်း
- **အမြင် မျိုးစုံ ခွဲခြမ်းစိတ်ဖြာမှု**: တစ်ခုသော input ကို မျိုးစုံမြင်ကွင်းများဖြင့် ဆန်းစစ်ခြင်း

### 🔍 ကိုယ်ပိုင် Executor များ နားလည်ခြင်း

**ConcurrentStartExecutor:**
- `IMessageHandler<string>` ကို အကောင်အထည် ဖော်ပြီး string input ကို လက်ခံသည်
- ချိတ်ဆက်ထားသော agent အားလုံးကို မက်ဆေ့ခ်် ပေးပို့သည်
- concurrent လုပ်ဆောင်မှုကို စတင်ရန် `TurnToken` ပေးပို့သည်

**ConcurrentAggregationExecutor:**
- `IMessageHandler<ChatMessage>` ကို အကောင်အထည်ဖော်ကာ agent ရဲ့ တုံ့ပြန်ချက်များကို လက်ခံသည်
- မက်ဆေ့ခ််များကို thread-safe နည်းဖြင့် စုဆောင်းသည်
- စောင့်ထားသော တုံ့ပြန်ချက်အားလုံး ရောက်ရှိသောအခါ စုစည်းသည်
- `context.YieldOutputAsync()` ကို အသုံးပြုပြီး နောက်ဆုံး output ကို return လုပ်သည်

### ⚡ စွမ်းဆောင်ရည် အကျိုးအမြတ်များ

**Concurrent နှင့် Sequential ကြား ကြာခြားချက်:**
- Sequential: Agent1 (30s) → Agent2 (30s) = **စုစုပေါင်း 60 စက္ကန့်**
- Concurrent: Agent1 (30s) || Agent2 (30s) = **စုစုပေါင်း 30 စက္ကန့်**

**Throughput တိုးတက်မှု**: N concurrent agent များအတွက် N ဆအထိ မြန်ဆန်မှု (အလုပ်အမာနှင့် ရင်းမြစ် ပမာဏပေါ် မူတည်ပြီး)

### 🛡️ အမှား ကိုင်တွယ်ခြင်း

workflow သည် agent တစ်ဦးချင်း ရှုပ်ရှင်းမှုများကို သေသေချာချာ ကိုင်တွယ်ပါသည်-
- agent တစ်ဦး ပျက်ကွက်ပါက အခြားများ ဆက်လက်တပြိုင်နက် လုပ်ဆောင်သည်
- Aggregator မှ သတ်မှတ်ထားသော အချိန်မှီ မရောက်ရှိမှု သတ်မှတ်ချက်များကို အကောင်အထည်ဖော်နိုင်သည်
- လိုအပ်သည်ဆိုပါက အပိုင်းအစ ရလဒ်များကို ပြန်လည်ပေးပို့နိုင်သည်

### 📊 တိုးတက်သော အင်္ဂါရပ်များ

**အတိုးအကျယ် ပြောင်းလဲသည့် Agent အရေအတွက်:**
ဤ aggregation logic ကို အတိုးအကျယ် ပြောင်းလဲနိုင်သည့် agent အရေအတွက် မဟာဗျူဟာအဖြစ် ပြင်ဆင်နိုင်သည်-

```csharp
private int _expectedAgentCount;
private readonly List<ChatMessage> _messages = [];

public async ValueTask HandleAsync(ChatMessage message, IWorkflowContext context)
{
    this._messages.Add(message);
    if (this._messages.Count == _expectedAgentCount)
    {
        // Process aggregation
    }
}
```

ဒီ concurrent workflow ပုံစံက အမြန်နှုန်းမြင့်၊ တိုးချဲ့နိုင်သော AI agent စနစ်များ တည်ဆောက်ရာမှာ အရေးပါတဲ့ ပါဝင်ပစ္စည်း ဖြစ်သည်။
