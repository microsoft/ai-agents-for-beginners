# ⚡ Паралелни работни процеси с агенти в Azure OpenAI (Responses API) (.NET)

## 📋 Урок за високопроизводителна паралелна обработка

Този бележник демонстрира **паралелни модели на работни процеси** с помощта на Microsoft Agent Framework за .NET и Azure OpenAI (Responses API). Ще научите как да изграждате високопроизводителни, паралелни работни процеси, които максимизират пропускателната способност чрез едновременно изпълнение на множество AI агенти, като същевременно поддържат координация и съгласуваност на данните.

## 💻 Стартиране на кода

Пълната реализация е налична в `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Този файл демонстрира **Fan-Out/Fan-In паралелен работен процес** за планиране на пътувания:

### 🏗️ **Архитектура на работния процес**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Ключови компоненти:**

1. **ConcurrentStartExecutor**: Излъчва заявката на потребителя към всички агенти едновременно
2. **Researcher Agent**: Паралелно анализира дестинации и атракции
3. **Planner Agent**: Създава подробни планове за пътувания паралелно
4. **ConcurrentAggregationExecutor**: Събира и обединява резултатите от двата агента

### 🎯 **Модел Fan-Out/Fan-In**

Този работен процес демонстрира класическия модел **Fan-Out/Fan-In**:
- **Fan-Out**: Един входящ сигнал се излъчва към множество агенти едновременно
- **Паралелна обработка**: Множество агенти работят паралелно по една и съща задача
- **Fan-In**: Резултатите от всички агенти се събират и обединяват в един изход

### 📝 Очакван резултат

Работният процес ще:
1. **Излъчване на заявка**: Изпраща "Планирай пътуване до Сиатъл през декември" до двата агента
2. **Паралелна обработка**: Двата агента работят едновременно:
   - Изследователят идентифицира атракции и детайли

3. **Агрегация**: Обединява двата отговора в цялостен изход
4. **Показване на резултатите**: Извежда обединения план за пътуване с цялата информация

### 🎯 Приложения в реалния свят

Този паралелен модел е идеален за:
- **Създаване на съдържание**: Множество автори работят едновременно върху различни раздели
- **Преглед на код**: Множество рецензенти анализират кода от различни гледни точки
- **Пазарни проучвания**: Паралелен анализ на различни пазарни сегменти
- **Обработка на документи**: Паралелно извличане, анализ и валидиране
- **Мултиперспективен анализ**: Получаване на различни гледни точки към един и същ вход

### 🔍 Разбиране на персонализирани изпълнители

**ConcurrentStartExecutor:**
- Имплементира `IMessageHandler<string>` за приемане на вход от тип string
- Излъчва съобщения към всички свързани агенти
- Изпраща `TurnToken`, за да активира паралелна обработка

**ConcurrentAggregationExecutor:**
- Имплементира `IMessageHandler<ChatMessage>` за приемане на отговори от агенти
- Събира съобщения по безопасен за нишки начин
- Агрегира, когато получи всички очаквани отговори
- Връща финалния изход с `context.YieldOutputAsync()`

### ⚡ Ползи от производителността

**Паралелно срещу последователно:**
- Последователно: Агент1 (30s) → Агент2 (30s) = **общо 60 секунди**
- Паралелно: Агент1 (30s) || Агент2 (30s) = **общо 30 секунди**

**Подобрение в пропускателната способност**: До N × по-бързо за N паралелни агенти (в зависимост от натоварването и ресурсите)

### 🛡️ Обработка на грешки

Работният процес обработва отделни повреди на агенти по плавен начин:
- Ако един агент се провали, другите продължават обработката
- Агрегаторът може да реализира timeout логика
- Частични резултати могат да бъдат върнати при необходимост
