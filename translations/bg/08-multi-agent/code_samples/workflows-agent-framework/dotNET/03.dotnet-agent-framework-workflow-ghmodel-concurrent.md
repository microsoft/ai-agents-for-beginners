# ⚡ Паралелни работни процеси с агенти с Azure OpenAI (Responses API) (.NET)

## 📋 Урок за високо-производителна паралелна обработка

Този бележник демонстрира **модели на едновременни работни процеси** с използване на Microsoft Agent Framework за .NET и Azure OpenAI (Responses API). Ще научите как да изграждате високо-производителни, паралелни работни процеси, които максимизират пропускателната способност чрез изпълнение на множество AI агенти едновременно, като същевременно поддържат координация и консистентност на данните.

## 💻 Стартиране на кода

Пълната имплементация е налична в `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Този файл демонстрира **Fan-Out/Fan-In паралелен работен процес** за планиране на пътуване:

### 🏗️ **Архитектура на работния процес**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Ключови компоненти:**

1. **ConcurrentStartExecutor**: Разпраща потребителската заявка към всички агенти едновременно
2. **Researcher Agent**: Анализира дестинациите и атракциите едновременно
3. **Planner Agent**: Създава подробни планове за пътуване едновременно
4. **ConcurrentAggregationExecutor**: Събира и слива резултатите от двата агента

### 🎯 **Fan-Out/Fan-In модел**

Този работен процес демонстрира класическия **Fan-Out/Fan-In** модел:
- **Fan-Out**: Един входящо съобщение се изпраща до множество агенти едновременно
- **Паралелна обработка**: Множество агенти работят паралелно по една и съща задача
- **Fan-In**: Резултатите от всички агенти се събират и агрегирани в един изход

### 📝 Очакван изход

Работният процес ще:
1. **Изпрати заявката**: Изпраща "Планирай пътуване до Сиатъл през декември" и до двата агента
2. **Паралелна обработка**: Двата агента работят едновременно:
   - Изследователят идентифицира атракции и детайли
   - Планировчикът създава маршрут и логистика
3. **Агрегация**: Комбинира двата отговора в изчерпателен изход
4. **Показване на резултатите**: Извежда обединения план за пътуване с цялата информация

### 🔍 Разбиране на потребителските изпълнители

**ConcurrentStartExecutor:**
- Изпълнява `IMessageHandler<string>` за приемане на входящ текст
- Излъчва съобщения до всички свързани агенти
- Изпраща `TurnToken` за задействане на паралелна обработка

**ConcurrentAggregationExecutor:**
- Изпълнява `IMessageHandler<ChatMessage>` за получаване на отговорите на агентите
- Събира съобщения по нишка-безопасен начин
- Извършва агрегация, когато пристигнат всички очаквани отговори
- Връща крайния резултат със `context.YieldOutputAsync()`

### ⚡ Ползи от производителността

**Паралелно срещу последователно:**
- Последователно: Agent1 (30с) → Agent2 (30с) = **общо 60 секунди**
- Паралелно: Agent1 (30с) || Agent2 (30с) = **общо 30 секунди**

**Подобрение в пропускателната способност**: До N× по-бързо за N едновременни агенти (в зависимост от натоварването и ресурсите)
