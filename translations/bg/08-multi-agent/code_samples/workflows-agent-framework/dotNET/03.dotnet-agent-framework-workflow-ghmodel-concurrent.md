## 💻 Стартиране на кода

Пълната имплементация е налична в `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Този файл демонстрира **Fan-Out/Fan-In паралелен работен поток** за планиране на пътуване:

### 🏗️ **Архитектура на работния поток**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Основни компоненти:**

1. **ConcurrentStartExecutor**: Излъчва заявката на потребителя към всички агенти едновременно
2. **Researcher Agent**: Анализира дестинации и атракции паралелно
3. **Planner Agent**: Създава подробни планове за пътуване паралелно
4. **ConcurrentAggregationExecutor**: Събира и слива резултатите от двамата агенти

### 🎯 **Шаблон Fan-Out/Fan-In**

Този работен поток демонстрира класическия **Fan-Out/Fan-In** модел:
- **Fan-Out**: Едно входящо съобщение се излъчва към множество агенти едновременно
- **Паралелна обработка**: Множество агенти работят паралелно по една и съща задача
- **Fan-In**: Резултатите от всички агенти се събират и обединяват в един изход

Работният поток ще:

### 🎯 Приложения в реалния свят

Този паралелен модел е идеален за:
- **Създаване на съдържание**: Множество автори създават различни секции едновременно
- **Преглед на код**: Множество прегледачи анализират кода от различни гледни точки
- **Пазарно изследване**: Паралелен анализ на различни пазарни сегменти
- **Обработка на документи**: Паралелно извличане, анализ и валидиране
- **Многостранен анализ**: Получаване на разнообразни гледни точки върху един и същ вход

### 🔍 Разбиране на персонализирани изпълнители

**ConcurrentStartExecutor:**
- Имплементира `IMessageHandler<string>` за приемане на текстови вход
- Излъчва съобщения до всички свързани агенти
- Изпраща `TurnToken` за задействане на паралелна обработка

**ConcurrentAggregationExecutor:**
- Имплементира `IMessageHandler<ChatMessage>` за приемане на отговори от агенти
- Събира съобщения по нишково-безопасен начин
- Агрегира, когато всички очаквани отговори са получени
- Връща окончателния изход с `context.YieldOutputAsync()`

### ⚡ Предимства за производителността

**Паралелно срещу последователно:**
- Последователно: Агент1 (30с) → Агент2 (30с) = **общо 60 секунди**
- Паралелно: Агент1 (30с) || Агент2 (30с) = **общо 30 секунди**

**Подобрение на пропускателната способност**: До N× по-бързо за N паралелни агенти (в зависимост от натоварване и ресурси)

### 🛡️ Обработка на грешки

Работният поток обработва отказите на отделни агенти елегантно:
- Ако един агент се провали, другите продължават работа
- Агрегаторът може да имплементира таймаут логика
- Частични резултати могат да бъдат върнати при нужда
