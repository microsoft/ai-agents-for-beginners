# ⏩ Последователни агентни работни потоци с Azure OpenAI (Responses API) (.NET)

## 📋 Ръководство за усъвършенствана последователна обработка

Тази тетрадка демонстрира **последователни модели на работни потоци** с помощта на Microsoft Agent Framework за .NET и Azure OpenAI (Responses API). Ще се научите как да изграждате сложни, стъпка по стъпка обработващи линии, при които агентите изпълняват в определен ред, като всяка стъпка се основава на резултатите от предходната.

## 🎯 Учебни цели

### 🔄 **Архитектура на последователна обработка**
- **Линеен дизайн на работния поток**: Създаване на стъпка по стъпка обработващи линии с ясни зависимости
- **Управление на състоянието**: Поддържане на контекст и поток на данни през етапите на последователния работен поток
- **Azure OpenAI (Responses API)**: Използване на модели Azure OpenAI в многостадийни .NET работни потоци
- **Модели за корпоративни потоци**: Изграждане на готови за продукция системи за последователна обработка

### 🏗️ **Усъвършенствани модели за последователна обработка**
- **Обработка с етапни контролни точки**: Прилагане на валидиращи проверки между етапите
- **Запазване на контекста**: Поддържане на състоянието и акумулирани знания през всички етапи
- **Пропагиране на грешки**: Овладяване на неизправности плавно в последователни вериги за обработка
- **Оптимизация на производителността**: Ефективно последователно изпълнение с минимални разходи

### 🏢 **Корпоративни последователни приложения**
- **Поток за обработка на документи**: Многостадийна обработка на документи с анализ, трансформация и валидиране
- **Работни потоци за контрол на качеството**: Последователен преглед, валидиране и одобряващи процеси
- **Поток за производство на съдържание**: Изследване → Писане → Редактиране → Преглед → Публикуване
- **Автоматизация на бизнес процеси**: Многостъпкови бизнес работни потоци с ясни зависимости на етапите

### 🏗️ **Архитектура на последователния работен поток**

```mermaid
graph TD
    A[Initial Input] --> B[Stage 1: Анализатор]
    B --> C[Контролен пункт 1]
    C --> D[Stage 2: Обработващ агент]
    D --> E[Контролен пункт 2]
    E --> F[Stage 3: Валидиращ агент]
    F --> G[Краен резултат]
    
    H[Контекст на състоянието] --> B
    H --> D
    H --> F
    
    I[Azure OpenAI (Responses API)] --> B
    I --> D
    I --> F
```

**Ключови компоненти:**
- **Последователни агенти**: Специализирани агенти за всеки етап от обработката
- **Контекст на състоянието**: Поддържа акумулирани данни и решения през етапите
- **Контролни точки**: Валидиращи точки между етапите за осигуряване на качество и консистентност
- **Клиент на Azure OpenAI**: Последователен достъп до AI модела на всички етапи от потока

## 💻 Изпълнение на кода

Пълната имплементация е налична в `02.dotnet-agent-framework-workflow-ghmodel-sequential.cs`. Този файл демонстрира **триетапен работен поток за анализ на мебели**:

1. **Етап 1 - Търговски агент**: Анализира изображения на мебели и предлага покупки
2. **Етап 2 - Агента за цени**: Предоставя детайлни ценови разбивки и бюджетни опции
3. **Етап 3 - Агента за оферти**: Генерира професионален документ с оферта в Markdown формат

### 🏗️ **Архитектура на работния поток**

```
Image Input → Sales Analysis → Price Estimation → Quote Generation → Final Output
```

Всеки агент:
- Получава изхода от предходния етап като контекст
- Надгражда предишния анализ със специализирана експертиза
- Поддържа непрекъснатост на работния поток чрез управление на състоянието

### 🚀 Стартиране на примера

**Изисквания:**
- Поставете изображение на мебел в `../imgs/home.png` (или обновете променливата `imgPath`)
- Конфигурирайте вашия `.env` файл с вашия Azure OpenAI крайна точка и разгръщане, след което влезте с `az login`

```bash
# Направете скрипта изпълним (Unix/Linux/macOS)
chmod +x 02.dotnet-agent-framework-workflow-ghmodel-sequential.cs

# Стартирайте последователния работен процес
./02.dotnet-agent-framework-workflow-ghmodel-sequential.cs
```

Или в Windows:
```powershell
dotnet run 02.dotnet-agent-framework-workflow-ghmodel-sequential.cs
```

### 📝 Очакван изход

Работният поток ще:
1. **Търговски агент**: Идентифицира мебели във изображението и дава препоръки
2. **Агента за цени**: Добавя детайлен ценови анализ с бюджетни нива и препоръки за пазаруване
3. **Агента за оферти**: Генерира форматиран документ с оферта, съчетаващ цялата информация

Крайният изход ще бъде изчерпателна, професионална оферта за мебели, базирана на анализ на изображението.

### 🎯 Приложения в реалния свят

Този последователен модел е идеален за:
- **Електронна търговия**: Анализ на продукти → Определяне на цени → Създаване на оферти
- **Недвижими имоти**: Анализ на имоти → Оценка → Създаване на обяви
- **Застраховане**: Анализ на искове → Оценка → Създаване на оферти
- **Създаване на съдържание**: Изследване → Писане → Редактиране → Публикуване

### 🔍 Разбиране на потока на състоянието

Всеки агент в последователността получава:
- **Първоначален вход**: Първоначалното съобщение от потребителя (изображение + текст)
- **Изходи на предишни агенти**: Всички отговори на агенти в хода на разговора
- **Акумулиран контекст**: Пълно състояние, поддържано през целия работен поток

Това позволява сложна многостадийна обработка, където всеки агент надгражда върху обширния контекст от всички предишни етапи.
