# 🔄 Основни работни потоци на агенти с Azure OpenAI (Responses API) (.NET)

## 📋 Уроци по оркестрация на работни потоци

Тази тетрадка показва как да създадете усъвършенствани **работни потоци на агенти** с помощта на Microsoft Agent Framework за .NET и Azure OpenAI (Responses API). Ще научите как да създавате многоетапни бизнес процеси, където AI агенти си сътрудничат за изпълнение на сложни задачи чрез структурирани оркестрационни модели.

## 🎯 Учебни цели

### 🏗️ **Основи на архитектурата на работния поток**
- **Workflow Builder**: Проектиране и оркестрация на сложни многоетапни AI процеси
- **Координация на агенти**: Координиране на множество специализирани агенти в работните потоци
- **Azure OpenAI (Responses API)**: Използване на Azure OpenAI Responses API в работните потоци
- **Визуален дизайн на работния поток**: Създаване и визуализация на структури на работните потоци за по-добро разбиране

### 🔄 **Модели за оркестрация на процеси**
- **Последователна обработка**: Свързване на множество задачи на агенти в логическа последователност
- **Управление на състоянието**: Поддържане на контекст и потока на данни през етапите на работния поток
- **Обработка на грешки**: Изпълнение на надеждно възстановяване от грешки и устойчивост на работния поток
- **Оптимизация на производителността**: Проектиране на ефективни работни потоци за корпоративни операции в голям мащаб

### 🏢 **Корпоративни приложения на работни потоци**
- **Автоматизация на бизнес процеси**: Автоматизация на сложни организационни работни потоци
- **Поток за производство на съдържание**: Редакционни работни потоци с етапи на преглед и одобрение
- **Автоматизация на обслужване на клиенти**: Многоетапно разрешаване на клиентски запитвания
- **Работни потоци за обработка на данни**: ETL потоци с AI-задвижвана трансформация

## ⚙️ Изисквания и настройка

### 📦 **Необходими NuGet пакети**

Този демонстрационен работен поток използва няколко ключови .NET пакета:

```xml
<!-- Core AI Framework -->
<PackageReference Include="Microsoft.Extensions.AI" Version="9.9.0" />

<!-- Azure OpenAI (Responses API) -->
<PackageReference Include="Azure.AI.OpenAI" Version="2.1.0" />
<PackageReference Include="Azure.Identity" Version="1.13.1" />

<!-- Agent Framework (Local Development) -->
<!-- Microsoft.Agents.AI.dll - Core agent abstractions -->
<!-- Microsoft.Agents.AI.OpenAI.dll - Azure OpenAI (Responses API) integration -->

<!-- Configuration and Environment -->
<PackageReference Include="DotNetEnv" Version="3.1.1" />
```

### 🔑 **Конфигурация на Azure OpenAI**

**Настройка на средата (.env файл):**
```env
AZURE_OPENAI_ENDPOINT=https://<your-resource>.openai.azure.com
AZURE_OPENAI_DEPLOYMENT=gpt-4o-mini
```

**Достъп до Azure OpenAI:**
1. Създайте ресурс Azure OpenAI в Azure портала
2. Разположете модел (например `gpt-4o-mini`) и отбележете името на разполагането
3. Влезте с `az login` и конфигурирайте променливите на средата както е показано по-горе

### 🏗️ **Преглед на архитектурата на работния поток**

```mermaid
graph TD
    A[Конструктор на работни процеси] --> B[Регистър на агентите]
    B --> C[Двигател за изпълнение на работни процеси]
    C --> D[Agent 1: Генератор на съдържание]
    C --> E[Agent 2: Ревизор на съдържание] 
    D --> F[Резултати от работния процес]
    E --> F
    G[Azure OpenAI (Responses API)] --> D
    G --> E
```

**Ключови компоненти:**
- **WorkflowBuilder**: Основен оркестрационен двигател за проектиране на работни потоци
- **AIAgent**: Индивидуални специализирани агенти с конкретни възможности
- **Azure OpenAI Клиент**: Интеграция с Azure OpenAI Responses API
- **Изпълнителен контекст**: Управлява състоянието и потока на данни между етапите на работния поток

## 💻 Стартиране на кода

Пълната реализация е налична в `01.dotnet-agent-framework-workflow-ghmodel-basic.cs`. Този файл демонстрира:

1. **Конфигурация на средата** - Зареждане на конфигурацията на Azure OpenAI от `.env` файл
2. **Настройка на Azure OpenAI клиент** - Конфигуриране на клиента за използване на Azure OpenAI Responses API
3. **Създаване на агенти** - Дефиниране на специализирани агенти (Front Desk и Concierge)
4. **Workflow Builder** - Създаване на многоагентен работен поток с последователна обработка
5. **Изпълнение на работния поток** - Стартиране на работния поток с поточно извеждане на резултати

### 🚀 Стартиране на примера

```bash
# Направете скрипта изпълним (Unix/Linux/macOS)
chmod +x 01.dotnet-agent-framework-workflow-ghmodel-basic.cs

# Стартирайте работния процес
./01.dotnet-agent-framework-workflow-ghmodel-basic.cs
```

Или в Windows:
```powershell
dotnet run 01.dotnet-agent-framework-workflow-ghmodel-basic.cs
```

### 📝 Очакван изход

Работният поток ще:
1. Приеме заявката ви за пътуване ("Искам да отида в Париж")
2. Агентът Front Desk предоставя първоначална препоръка
3. Агентът Concierge преглежда и усъвършенства препоръката
4. Крайният изход показва пълния поток от разговора

### 🔧 Персонализация

Можете да персонализирате работния поток чрез:
- Промяна на инструкциите към агентите, за да се промени тяхното поведение
- Добавяне на повече агенти за създаване на сложни многоетапни работни потоци
- Промяна на съобщението на потребителя за тестване на различни сценарии
- Регулиране на връзките в работния поток за създаване на различни модели на изпълнение
