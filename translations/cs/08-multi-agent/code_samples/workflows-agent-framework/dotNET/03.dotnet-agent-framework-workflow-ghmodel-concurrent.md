## 💻 Spuštění kódu

Kompletní implementace je dostupná v `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Tento soubor ukazuje **Fan-Out/Fan-In souběžné workflow** pro plánování cest:

### 🏗️ **Architektura workflow**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Klíčové komponenty:**

1. **ConcurrentStartExecutor**: Současně vysílá uživatelský požadavek všem agentům
2. **Researcher Agent**: Paralelně analyzuje destinace a atrakce
3. **Planner Agent**: Paralelně vytváří detailní cestovní plány
4. **ConcurrentAggregationExecutor**: Sbírá a spojuje výsledky od obou agentů

### 🎯 **Vzorec Fan-Out/Fan-In**

Toto workflow demonstruje klasický vzor **Fan-Out/Fan-In**:
- **Fan-Out**: Jeden vstupní požadavek je současně vysílán více agentům
- **Souběžné zpracování**: Více agentů pracuje paralelně na stejné úloze
- **Fan-In**: Výsledky všech agentů jsou sesbírány a agregovány do jednoho výstupu

### 📝 Očekávaný výstup

Workflow provede:
1. **Zaslání požadavku**: Pošle "Naplánuj výlet do Seattlu v prosinci" oběma agentům
2. **Souběžné zpracování**: Oba agenti pracují současně:
   - Researcher identifikuje atrakce a detaily

3. **Agregace**: Spojí obě odpovědi do komplexního výstupu

### 🔍 Porozumění vlastním executorům

**ConcurrentStartExecutor:**
- Implementuje `IMessageHandler<string>` pro přijímání vstupních řetězců
- Vysílá zprávy všem připojeným agentům
- Posílá `TurnToken` pro spuštění souběžného zpracování

**ConcurrentAggregationExecutor:**
- Implementuje `IMessageHandler<ChatMessage>` pro přijímání odpovědí agentů
- Sbírá zprávy vlákny bezpečným způsobem
- Agreguje výsledky, když dorazí všechny očekávané odpovědi
- Vrací finální výstup pomocí `context.YieldOutputAsync()`

### ⚡ Přínosy výkonu

**Souběžné vs sekvenční:**
- Sekvenční: Agent1 (30s) → Agent2 (30s) = **60 sekund celkem**
- Souběžné: Agent1 (30s) || Agent2 (30s) = **30 sekund celkem**

**Zvýšení propustnosti**: Až N× rychleji pro N souběžných agentů (závisí na zatížení a zdrojích)

### 🛡️ Zpracování chyb

Workflow elegantně zvládá selhání jednotlivých agentů:
- Pokud jeden agent selže, ostatní pokračují v práci
- Aggregátor může implementovat logiku timeoutu
- Částečné výsledky lze vrátit, pokud je to potřeba
