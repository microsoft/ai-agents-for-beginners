## 💻 Spuštění kódu

Kompletní implementace je dostupná v `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Tento soubor demonstruje **Fan-Out/Fan-In souběžný workflow** pro plánování cest:

### 🏗️ **Architektura Workflow**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Klíčové komponenty:**

1. **ConcurrentStartExecutor**: Současně vysílá uživatelskou žádost všem agentům
2. **Researcher Agent**: Souběžně analyzuje destinace a atrakce
3. **Planner Agent**: Souběžně vytváří detailní cestovní plány
4. **ConcurrentAggregationExecutor**: Shromažďuje a slučuje výsledky od obou agentů

### 🎯 **Vzor Fan-Out/Fan-In**

Tento workflow demonstruje klasický vzor **Fan-Out/Fan-In**:
- **Fan-Out**: Jedna vstupní zpráva je současně vysílána více agentům
- **Souběžné zpracování**: Více agentů pracuje paralelně na stejné úloze
- **Fan-In**: Výsledky od všech agentů jsou shromážděny a agregovány do jednoho výstupu

### 📝 Očekávaný výstup

Workflow provede:
1. **Vysílání žádosti**: Pošle "Naplánuj cestu do Seattlu v prosinci" oběma agentům
2. **Souběžné zpracování**: Oba agenti pracují současně:
   - Researcher identifikuje atrakce a detaily
   - Planner vytváří itinerář a logistiku
3. **Agregace**: Kombinuje oba odpovědi do komplexního výstupu
4. **Zobrazení výsledků**: Ukažte sloučený cestovní plán se všemi informacemi

### 🔍 Porozumění vlastním executorům

**ConcurrentStartExecutor:**
- Implementuje `IMessageHandler<string>` pro přijetí vstupu typu string
- Vysílá zprávy všem připojeným agentům
- Odesílá `TurnToken` pro spuštění souběžného zpracování

**ConcurrentAggregationExecutor:**
- Implementuje `IMessageHandler<ChatMessage>` pro přijímání odpovědí od agentů
- Shromažďuje zprávy bezpečně ve vlákně
- Agreguje, když dorazí všechny očekávané odpovědi
- Vrací konečný výstup pomocí `context.YieldOutputAsync()`

### ⚡ Výhody výkonu


**Současné vs Sekvenční:** 

- Sekvenční: Agent1 (30s) → Agent2 (30s) = **60 sekund celkem**
- Současné: Agent1 (30s) || Agent2 (30s) = **30 sekund celkem**

**Zlepšení propustnosti**: Až N× rychlejší pro N současných agentů (v závislosti na zatížení a zdrojích)

### 🛡️ Zpracování chyb

Pracovní postup jemně řeší selhání jednotlivých agentů:
- Pokud jeden agent selže, ostatní pokračují v zpracování
- Agregátor může implementovat logiku timeoutu
- V případě potřeby lze vrátit částečné výsledky
