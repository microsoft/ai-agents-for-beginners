## 💻 Spuštění kódu

Kompletní implementace je dostupná v `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Tento soubor ukazuje **Fan-Out/Fan-In současný workflow** pro cestovní plánování:

### 🏗️ **Architektura pracovního toku**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Klíčové součásti:**

1. **ConcurrentStartExecutor**: Současně vysílá uživatelský požadavek všem agentům
2. **Researcher Agent**: Současně analyzuje destinace a atrakce
3. **Planner Agent**: Současně vytváří podrobné cestovní plány
4. **ConcurrentAggregationExecutor**: Sbírá a slučuje výsledky od obou agentů

### 🎯 **Vzorec Fan-Out/Fan-In**

Tento workflow demonstruje klasický vzorec **Fan-Out/Fan-In**:
- **Fan-Out**: Jedna vstupní zpráva je současně vysílána více agentům
- **Současné zpracování**: Více agentů pracuje paralelně na stejné úloze
- **Fan-In**: Výsledky všech agentů jsou shromážděny a agregovány do jednoho výstupu

### 📝 Očekávaný výstup

Workflow:
1. **Broadcast požadavek**: Pošle "Naplánuj výlet do Seattlu v prosinci" oběma agentům
2. **Současné zpracování**: Oba agenti pracují současně:
   - Researcher identifikuje atrakce a detaily
   - Planner vytváří itinerář a logistiku
3. **Agregace**: Kombinuje obě odpovědi do komplexního výstupu
4. **Zobrazení výsledků**: Ukáže sloučený cestovní plán se všemi informacemi

### 🔍 Pochopení vlastních executorů

**ConcurrentStartExecutor:**
- Implementuje `IMessageHandler<string>` pro přijímání vstupu typu string
- Vysílá zprávy všem připojeným agentům
- Posílá `TurnToken` pro spuštění současného zpracování

**ConcurrentAggregationExecutor:**
- Implementuje `IMessageHandler<ChatMessage>` pro příjem odpovědí agentů
- Sbírá zprávy vláknově bezpečně
- Agreguje, když dorazí všechny očekávané odpovědi
- Poskytuje konečný výstup pomocí `context.YieldOutputAsync()`

### ⚡ Výhody výkonu

**Současné vs Sekvenční:**

- Sekvenční: Agent1 (30s) → Agent2 (30s) = **celkem 60 sekund**
- Souběžný: Agent1 (30s) || Agent2 (30s) = **celkem 30 sekund**

**Zlepšení propustnosti**: Až N× rychlejší pro N souběžných agentů (v závislosti na zátěži a zdrojích)

### 🛡️ Zpracování chyb

Pracovní postup elegantně zpracovává jednotlivé selhání agentů:
- Pokud jeden agent selže, ostatní pokračují ve zpracování
- Seskupovač může implementovat logiku timeoutu
- Částečné výsledky lze vrátit, pokud je to potřeba

### 📊 Pokročilé funkce

**Dynamický počet agentů:**
Upravte logiku seskupování tak, aby podporovala proměnlivý počet agentů:

```csharp
private int _expectedAgentCount;
private readonly List<ChatMessage> _messages = [];

public override ValueTask HandleAsync(ChatMessage message, IWorkflowContext context, CancellationToken cancellationToken = default)
{
    this._messages.Add(message);
    if (this._messages.Count == _expectedAgentCount)
    {
        // Process aggregation
    }
    
    return ValueTask.CompletedTask;
}
```
