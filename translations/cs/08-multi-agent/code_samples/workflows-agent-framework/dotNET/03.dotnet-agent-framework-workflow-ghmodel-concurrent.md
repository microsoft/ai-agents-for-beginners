# ⚡ Současné pracovní postupy agentů s Azure OpenAI (Responses API) (.NET)

## 📋 Návod na vysoce výkonné paralelní zpracování

Tento poznámkový blok ukazuje **vzorové současné pracovní postupy** pomocí Microsoft Agent Framework pro .NET a Azure OpenAI (Responses API). Naučíte se vytvářet vysoce výkonné, paralelní pracovní postupy, které maximalizují propustnost prováděním více AI agentů současně při zachování koordinace a konzistence dat.

## 💻 Spuštění kódu

Kompletní implementace je k dispozici v `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Tento soubor demonstruje **Fan-Out/Fan-In současný pracovní postup** pro plánování cest:

### 🏗️ **Architektura pracovního postupu**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Klíčové komponenty:**

1. **ConcurrentStartExecutor**: Odesílá uživatelský požadavek všem agentům současně
2. **Researcher Agent**: Paralelně analyzuje destinace a atrakce
3. **Planner Agent**: Vytváří podrobné cestovní plány současně
4. **ConcurrentAggregationExecutor**: Sbírá a slučuje výsledky od obou agentů

### 🎯 **Fan-Out/Fan-In vzor**

Tento pracovní postup ukazuje klasický vzor **Fan-Out/Fan-In**:
- **Fan-Out**: Jedna vstupní zpráva je současně vysílána více agentům
- **Souběžné zpracování**: Více agentů pracuje paralelně na stejném úkolu
- **Fan-In**: Výsledky všech agentů jsou shromážděny a sloučeny do jedné odpovědi

Pracovní postup:
1. **Broadcast požadavku**: Odeslat "Naplánuj cestu do Seattlu v prosinci" oběma agentům

### 🔍 Porozumění vlastním vykonavatelům

**ConcurrentStartExecutor:**
- Implementuje `IMessageHandler<string>` pro příjem řetězcového vstupu
- Vysílá zprávy všem připojeným agentům
- Posílá `TurnToken` k zahájení souběžného zpracování

**ConcurrentAggregationExecutor:**
- Implementuje `IMessageHandler<ChatMessage>` pro příjem odpovědí agentů
- Sbírá zprávy vláknotvorně bezpečným způsobem
- Provádí agregaci, jakmile dorazí všechny očekávané odpovědi
- Vrací finální výstup pomocí `context.YieldOutputAsync()`

### ⚡ Výhody výkonu

**Souběžné vs Sekvenční:**
- Sekvenční: Agent1 (30s) → Agent2 (30s) = **60 sekund celkem**
- Souběžné: Agent1 (30s) || Agent2 (30s) = **30 sekund celkem**

**Zlepšení propustnosti**: Až N× rychlejší pro N souběžných agentů (v závislosti na zátěži a zdrojích)

### 🛡️ Zpracování chyb

Pracovní postup elegantně zvládá selhání jednotlivých agentů:
- Pokud jeden agent selže, ostatní pokračují v zpracování
- Agregátor může implementovat logiku timeoutu
- Jsou možné návraty částečných výsledků, pokud je potřeba

### 📊 Pokročilé funkce

**Dynamický počet agentů:**
Upravte logiku agregace tak, aby podporovala proměnný počet agentů:

```csharp
private int _expectedAgentCount;
private readonly List<ChatMessage> _messages = [];

public override async ValueTask HandleAsync(List<ChatMessage> message, IWorkflowContext context, CancellationToken cancellationToken = default)
{
    this._messages.AddRange(message);
    if (this._messages.Count == _expectedAgentCount)
    {
        // Process aggregation
    }
}
```
