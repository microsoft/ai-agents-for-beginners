# ⏩ Sequentiële Agent Workflows met Azure OpenAI (Responses API) (.NET)

## 📋 Geavanceerde Tutorial voor Sequentiële Verwerking

Deze notitieboek demonstreert **sequentiële workflowpatronen** met behulp van het Microsoft Agent Framework voor .NET en Azure OpenAI (Responses API). Je leert hoe je geavanceerde, stapsgewijze verwerkingspijplijnen bouwt waarbij agenten in een specifieke volgorde uitvoeren, waarbij elke fase voortbouwt op de resultaten van de vorige fase.

## 🎯 Leerdoelen

### 🔄 **Architectuur voor Sequentiële Verwerking**
- **Lineaire Workflow Ontwerp**: Maak stapsgewijze verwerkingspijplijnen met duidelijke afhankelijkheden
- **Statusbeheer**: Onderhoud context en gegevensstroom over sequentiële workflowfases heen
- **Azure OpenAI (Responses API)**: Maak gebruik van Azure OpenAI-modellen in multi-stage .NET workflows
- **Enterprise Pipeline Patronen**: Bouw productieklaar sequentiële verwerkingssysteem

### 🏗️ **Geavanceerde Sequentiële Patronen**
- **Stage-Gate Verwerking**: Implementeer validatie-checkpoints tussen workflowfases
- **Context Behoud**: Behoud status en opgebouwde kennis over alle fases heen
- **Foutpropagatie**: Handel fouten netjes af in sequentiële verwerkingsketens
- **Prestatieoptimalisatie**: Efficiënte sequentiële uitvoering met minimale overhead

### 🏢 **Enterprise Sequentiële Toepassingen**
- **Documentverwerkingspijplijn**: Multi-stage documentanalyse, transformatie en validatie
- **Kwaliteitsborgingsworkflows**: Sequentiële beoordeling, validatie en goedkeuringsprocessen
- **Contentproductiepijplijn**: Onderzoek → Schrijven → Redigeren → Beoordeling → Publicatie

## 💻 De Code Uitvoeren

De volledige implementatie is beschikbaar in `02.dotnet-agent-framework-workflow-ghmodel-sequential.cs`. Dit bestand demonstreert een **driefasen meubelanalyse-workflow**:

1. **Fase 1 - Sales Agent**: Analyseert meubelafbeeldingen en geeft aankoopvoorstellen
2. **Fase 2 - Prijsagent**: Biedt gedetailleerde prijsoverzichten en budgetopties
3. **Fase 3 - Offerte Agent**: Genereert een professioneel offertedocument in Markdown-formaat

### 🏗️ **Workflow Architectuur**

```
Image Input → Sales Analysis → Price Estimation → Quote Generation → Final Output
```

Elke agent:
- Ontvangt de output van de vorige fase als context
- Bouwt voort op eerdere analyse met gespecialiseerde expertise
- Behoudt workflowcontinuïteit via statusbeheer

### 🚀 Het Voorbeeld Uitvoeren

**Vereisten:**
- Plaats een afbeelding van een meubelstuk op `../imgs/home.png` (of pas de variabele `imgPath` aan)
- Configureer je `.env` bestand met je Azure OpenAI-endpoint en deployment, log vervolgens in met `az login`

```bash
# Maak het script uitvoerbaar (Unix/Linux/macOS)
chmod +x 02.dotnet-agent-framework-workflow-ghmodel-sequential.cs

# Voer de sequentiële workflow uit
./02.dotnet-agent-framework-workflow-ghmodel-sequential.cs
```

Of op Windows:
```powershell
dotnet run 02.dotnet-agent-framework-workflow-ghmodel-sequential.cs
```

### 📝 Verwachte Output

De workflow zal:
1. **Sales Agent**: Meubelstukken in de afbeelding identificeren en aanbevelingen geven
2. **Prijsagent**: Gedetailleerde prijzanalyse toevoegen met budgetniveaus en winkeladviezen
3. **Offerte Agent**: Een geformatteerd offertedocument genereren met alle gesynthetiseerde informatie

De uiteindelijke output zal een uitgebreide, professionele meubelofferte zijn op basis van de afbeeldingsanalyse.

### 🔍 Begrip van Statusstroom

Elke agent in de reeks ontvangt:
- **Originele Invoer**: Het initiële gebruikersbericht (afbeelding + tekst)
- **Uitvoeren van voorgaande agenten**: Alle voorgaande agentreacties in het gespreksgeschiedenis
- **Opgehoopte Context**: Volledige status onderhouden gedurende de workflow

Dit maakt geavanceerde multi-stage verwerking mogelijk waarbij elke agent voortbouwt op een uitgebreide context van alle voorgaande fases.
