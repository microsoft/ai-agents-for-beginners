## 📋 Tutorial voor Hoogwaardige Parallelle Verwerking

## 💻 Code uitvoeren

De volledige implementatie is beschikbaar in `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Dit bestand demonstreert een **Fan-Out/Fan-In gelijktijdige workflow** voor reisplanning:

### 🏗️ **Workflow architectuur**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Belangrijke componenten:**

1. **ConcurrentStartExecutor**: Zendt de gebruikersaanvraag tegelijk naar alle agents
2. **Researcher Agent**: Analyseert bestemmingen en attracties gelijktijdig
3. **Planner Agent**: Maakt gelijktijdig gedetailleerde reisplannen
4. **ConcurrentAggregationExecutor**: Verzamelt en voegt resultaten van beide agents samen

### 🎯 **Fan-Out/Fan-In patroon**

Deze workflow demonstreert het klassieke **Fan-Out/Fan-In** patroon:
- **Fan-Out**: Eén inputbericht wordt tegelijk naar meerdere agents uitgezonden
- **Gelijktijdige verwerking**: Meerdere agents werken parallel aan dezelfde taak
- **Fan-In**: Resultaten van alle agents worden verzameld en samengevoegd tot één output

### 🔍 Aangepaste executors begrijpen

**ConcurrentStartExecutor:**
- Implementeert `IMessageHandler<string>` om stringinput te accepteren
- Zendt berichten uit naar alle verbonden agents
- Verstuurt `TurnToken` om gelijktijdige verwerking te activeren

**ConcurrentAggregationExecutor:**
- Implementeert `IMessageHandler<ChatMessage>` om agentreacties te ontvangen
- Verzamelt berichten op een thread-veilige manier
- Voert aggregatie uit als alle verwachte reacties binnen zijn
- Geeft finale output terug via `context.YieldOutputAsync()`

### ⚡ Prestatiewinst

**Gelijktijdig versus sequentieel:**
- Sequentieel: Agent1 (30s) → Agent2 (30s) = **60 seconden totaal**
- Gelijktijdig: Agent1 (30s) || Agent2 (30s) = **30 seconden totaal**

**Doorvoerverbetering**: Tot N× sneller voor N gelijktijdige agents (afhankelijk van workload en resources)

### 🛡️ Foutafhandeling

De workflow handelt individuele agentfouten elegant af:
- Als één agent faalt, gaat de verwerking door met de andere
- Aggregator kan timeout-logica implementeren
- Eventueel kunnen gedeeltelijke resultaten worden geretourneerd
