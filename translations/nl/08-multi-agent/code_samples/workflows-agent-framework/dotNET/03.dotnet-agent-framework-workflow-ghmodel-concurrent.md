## 💻 Code Uitvoeren

De volledige implementatie is beschikbaar in `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Dit bestand demonstreert een **Fan-Out/Fan-In gelijktijdige workflow** voor reisplanning:

### 🏗️ **Workflow Architectuur**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Belangrijke Componenten:**

1. **ConcurrentStartExecutor**: Zendt het gebruikersverzoek gelijktijdig naar alle agenten
2. **Researcher Agent**: Analyseert bestemmingen en attracties parallel
3. **Planner Agent**: Maakt gedetailleerde reisplannen parallel
4. **ConcurrentAggregationExecutor**: Verzamelt en voegt resultaten van beide agenten samen

### 🎯 **Fan-Out/Fan-In Patroon**

Deze workflow illustreert het klassieke **Fan-Out/Fan-In** patroon:
- **Fan-Out**: Eén invoerbericht wordt gelijktijdig uitgezonden naar meerdere agenten
- **Gelijktijdige Verwerking**: Meerdere agenten werken parallel aan dezelfde taak
- **Fan-In**: Resultaten van alle agenten worden verzameld en samengevoegd tot één output

### 🔍 Begrip van Aangepaste Executors

**ConcurrentStartExecutor:**
- Implementeert `IMessageHandler<string>` om stringinvoer te accepteren
- Zendt berichten uit naar alle verbonden agenten
- Stuurt `TurnToken` om gelijktijdige verwerking te starten

**ConcurrentAggregationExecutor:**
- Implementeert `IMessageHandler<ChatMessage>` om agentantwoorden te ontvangen
- Verzamelt berichten op een thread-veilige manier
- Aggregateert wanneer alle verwachte antwoorden zijn binnengekomen
- Geeft de uiteindelijke output terug via `context.YieldOutputAsync()`

### ⚡ Prestatievoordelen

**Gelijktijdig versus Sequentieel:**
- Sequentieel: Agent1 (30s) → Agent2 (30s) = **60 seconden totaal**
- Gelijktijdig: Agent1 (30s) || Agent2 (30s) = **30 seconden totaal**

**Doorvoerverbetering**: Tot N× sneller voor N gelijktijdige agenten (afhankelijk van workload en resources)

### 🛡️ Foutafhandeling

De workflow gaat netjes om met individuele agentfouten:
- Als één agent faalt, gaan andere door met verwerken
- Aggregator kan timeoutlogica implementeren
- Gedeeltelijke resultaten kunnen teruggegeven worden indien nodig
