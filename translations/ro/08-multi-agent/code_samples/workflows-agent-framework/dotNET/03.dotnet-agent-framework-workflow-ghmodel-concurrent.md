## 💻 Rularea codului

Implementarea completă este disponibilă în `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Acest fișier demonstrează un **flux de lucru concurent Fan-Out/Fan-In** pentru planificarea călătoriilor:

### 🏗️ **Arhitectura fluxului de lucru**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Componente cheie:**

1. **ConcurrentStartExecutor**: Transmite cererea utilizatorului tuturor agenților simultan
2. **Researcher Agent**: Analizează destinațiile și atracțiile în paralel
3. **Planner Agent**: Creează planuri detaliate de călătorie în paralel
4. **ConcurrentAggregationExecutor**: Colectează și combină rezultatele ambilor agenți

### 🎯 **Modelul Fan-Out/Fan-In**

Acest flux de lucru demonstrează modelul clasic **Fan-Out/Fan-In**:
- **Fan-Out**: Un mesaj de intrare este transmis mai multor agenți simultan
- **Procesare concurentă**: Mai mulți agenți lucrează în paralel la aceeași sarcină
- **Fan-In**: Rezultatele tuturor agenților sunt colectate și agregate într-un singur output

### 📝 Ieșire așteptată

Fluxul de lucru va:
1. **Transmitere cerere**: Trimite "Planificați o călătorie la Seattle în decembrie" ambilor agenți
2. **Procesare concurentă**: Ambii agenți lucrează simultan:
   - Researcher identifică atracții și detalii
   - Planner creează itinerariul și logistica
3. **Agregare**: Combină răspunsurile ambilor agenți într-un output cuprinzător
4. **Afișare rezultate**: Arată planul de călătorie combinat cu toate informațiile

### 🔍 Înțelegerea executorilor personalizați

**ConcurrentStartExecutor:**
- Implementează `IMessageHandler<string>` pentru a accepta intrări de tip string
- Transmite mesaje tuturor agenților conectați
- Trimite `TurnToken` pentru a declanșa procesarea concurentă

**ConcurrentAggregationExecutor:**
- Implementează `IMessageHandler<ChatMessage>` pentru a primi răspunsuri de la agenți
- Colectează mesajele într-un mod thread-safe
- Agregează când sosesc toate răspunsurile așteptate
- Returnează output-ul final folosind `context.YieldOutputAsync()`

### ⚡ Beneficii de performanță

**Concurent vs Secvențial:**
- Secvențial: Agent1 (30s) → Agent2 (30s) = **60 de secunde total**
- Concurent: Agent1 (30s) || Agent2 (30s) = **30 de secunde total**

**Îmbunătățire prinput**: De până la N× mai rapid pentru N agenți concurenți (în funcție de încărcare și resurse)

### 🛡️ Gestionarea erorilor

Fluxul de lucru gestionează grațios eșecurile agenților individuali:
- Dacă un agent eșuează, ceilalți continuă procesarea
- Agregatorul poate implementa logica de timeout
- Se pot returna rezultate parțiale, dacă este nevoie
