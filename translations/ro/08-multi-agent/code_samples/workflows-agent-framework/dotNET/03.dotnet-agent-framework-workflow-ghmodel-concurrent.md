## 💻 Rularea Codului

Implementarea completă este disponibilă în `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Acest fișier demonstrează un **flux de lucru concurent Fan-Out/Fan-In** pentru planificarea călătoriilor:

### 🏗️ **Arhitectura Fluxului de Lucru**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Componente Cheie:**

1. **ConcurrentStartExecutor**: Difuzează cererea utilizatorului către toți agenții simultan
2. **Researcher Agent**: Analizează destinațiile și atracțiile în paralel
3. **Planner Agent**: Creează planuri de călătorie detaliate simultan
4. **ConcurrentAggregationExecutor**: Colectează și combină rezultatele ambilor agenți

### 🎯 **Model Fan-Out/Fan-In**

Acest flux demonstrează modelul clasic **Fan-Out/Fan-In**:
- **Fan-Out**: Un mesaj de intrare este difuzat către multiple agenți simultan
- **Procesare Concurentă**: Mai mulți agenți lucrează paralel la aceeași sarcină
- **Fan-In**: Rezultatele de la toți agenții sunt colectate și agregate într-un singur output

### 📝 Output Așteptat

Fluxul va:
1. **Difuzare Cerere**: Trimite "Planifică o călătorie la Seattle în decembrie" ambilor agenți
2. **Procesare Concurentă**: Ambii agenți lucrează simultan:
   - Researcher identifică atracții și detalii
   - Planner creează itinerar și logistică
3. **Agregare**: Combină ambele răspunsuri într-un output cuprinzător
4. **Afișare Rezultate**: Afișează planul de călătorie combinat cu toate informațiile

### 🔍 Înțelegerea Executorilor Personalizați

**ConcurrentStartExecutor:**
- Implementează `IMessageHandler<string>` pentru a accepta input de tip string
- Difuzează mesaje către toți agenții conectați
- Trimite `TurnToken` pentru a declanșa procesarea concurentă

**ConcurrentAggregationExecutor:**
- Implementează `IMessageHandler<ChatMessage>` pentru a primi răspunsurile agenților
- Colectează mesajele în mod thread-safe
- Agregă când toate răspunsurile așteptate au sosit
- Returnează output-ul final folosind `context.YieldOutputAsync()`

### ⚡ Beneficii de Performanță

**Concurent vs Secvențial:**
- Secvențial: Agent1 (30s) → Agent2 (30s) = **60 de secunde în total**
- Concurent: Agent1 (30s) || Agent2 (30s) = **30 de secunde în total**

**Îmbunătățire a debitului**: Până la N× mai rapid pentru N agenți concurenți (în funcție de sarcină și resurse)

### 🛡️ Gestionarea Erorilor

Fluxul gestionează grațios eșecurile agenților individuali:
- Dacă un agent eșuează, ceilalți continuă procesarea
- Aggregatorul poate implementa logica de timeout
- Rezultate parțiale pot fi returnate dacă este nevoie

### 📊 Funcționalități Avansate

```csharp
public override ValueTask HandleAsync(ChatMessage message, IWorkflowContext context, CancellationToken cancellationToken = default)
{
    this._messages.Add(message);
    if (this._messages.Count == _expectedAgentCount)
    {
        // Process aggregation
    }
    
    return ValueTask.CompletedTask;
}
```
