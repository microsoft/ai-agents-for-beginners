## 📋 Tutorial de procesare paralelă de înaltă performanță

Veți învăța cum să construiți fluxuri de lucru de procesare paralelă, de înaltă performanță, care maximizează debitul prin execuția simultană a mai multor agenți AI, menținând în același timp coordonarea și consistența datelor.

## 💻 Rularea codului

Implementarea completă este disponibilă în `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Acest fișier demonstrează un **flux de lucru concurent Fan-Out/Fan-In** pentru planificarea călătoriilor:

### 🏗️ **Arhitectura fluxului de lucru**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Componente cheie:**

1. **ConcurrentStartExecutor**: Difuzează cererea utilizatorului către toți agenții simultan
2. **Agentul Cercetător**: Analizează destinațiile și atracțiile în paralel
3. **Agentul Planificator**: Creează detalii despre planurile de călătorie simultan
4. **ConcurrentAggregationExecutor**: Colectează și combină rezultatele ambilor agenți

### 🎯 **Modelul Fan-Out/Fan-In**

Acest flux de lucru ilustrează modelul clasic **Fan-Out/Fan-In**:
- **Fan-Out**: Un mesaj de intrare este difuzat către mai mulți agenți simultan
- **Procesare concurentă**: Mai mulți agenți lucrează în paralel la aceeași sarcină
- **Fan-In**: Rezultatele tuturor agenților sunt colectate și agregate într-un singur output

### 📝 Rezultatul așteptat

Fluxul de lucru va:
1. **Trimite cererea**: "Planifică o călătorie la Seattle în decembrie" către ambii agenți
2. **Procesare concurentă**: Ambii agenți lucrează simultan:

   - Planificatorul creează itinerariul și logistica

### 🔍 Înțelegerea executorilor personalizați

**ConcurrentStartExecutor:**
- Implementează `IMessageHandler<string>` pentru a accepta input de tip string
- Difuzează mesaje către toți agenții conectați
- Trimite `TurnToken` pentru a declanșa procesarea concurentă

**ConcurrentAggregationExecutor:**
- Implementează `IMessageHandler<ChatMessage>` pentru a primi răspunsuri de la agenți
- Colectează mesajele într-un mod thread-safe
- Agregă când sosesc toate răspunsurile așteptate
- Emite output-ul final folosind `context.YieldOutputAsync()`

### ⚡ Beneficii de performanță

**Concurent vs Secvențial:**
- Secvențial: Agent1 (30s) → Agent2 (30s) = **60 de secunde total**
- Concurent: Agent1 (30s) || Agent2 (30s) = **30 de secunde total**

**Îmbunătățire a debitului**: De până la N× mai rapid pentru N agenți concurenți (în funcție de volum și resurse)

### 🛡️ Gestionarea erorilor

Fluxul de lucru gestionează grațios eșecurile agenților individuali:
- Dacă unul dintre agenți eșuează, ceilalți continuă procesarea
- Agregatorul poate implementa logică de timeout
- Pot fi returnate rezultate parțiale dacă este necesar

### 📊 Funcționalități avansate

**Număr dinamic de agenți:**
Modifică logica de agregare pentru a suporta un număr variabil de agenți:

```csharp
private int _expectedAgentCount;
private readonly List<ChatMessage> _messages = [];

public override async ValueTask HandleAsync(List<ChatMessage> message, IWorkflowContext context, CancellationToken cancellationToken = default)
{
    this._messages.AddRange(message);
    if (this._messages.Count == _expectedAgentCount)
    {
        // Process aggregation
    }
}
```
