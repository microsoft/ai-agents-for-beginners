# Contribution

Ce projet accepte les contributions et suggestions. La plupart des contributions nécessitent que vous acceptiez un Accord de Licence de Contributeur (CLA) déclarant que vous avez le droit, et que vous accordez effectivement, les droits de nous permettre d'utiliser votre contribution. Pour plus de détails, visitez <https://cla.opensource.microsoft.com>.

Lorsque vous soumettez une pull request, un bot CLA déterminera automatiquement si vous devez fournir un CLA et décorera la pull request en conséquence. Suivez les instructions fournies par le bot. Vous n'aurez besoin de le faire qu'une seule fois pour les dépôts utilisant le CLA Microsoft.

## Code de conduite

Ce projet a adopté le [Code de conduite open source Microsoft](https://opensource.microsoft.com/codeofconduct/). Pour plus d'informations, consultez la [FAQ du Code de conduite](https://opensource.microsoft.com/codeofconduct/faq/) ou contactez [opencode@microsoft.com](mailto:opencode@microsoft.com) pour toute question ou commentaire supplémentaire.

## Directives pour les pull requests

- Gardez chaque pull request centrée sur un seul changement logique.
- Testez les notebooks et exemples de code concernés avant de soumettre.
- Mettez à jour la documentation de la leçon concernée lors de l'ajout ou la modification d'un exemple.
- Modifiez uniquement le contenu source en anglais. Les traductions sont maintenues par le processus automatique de traduction.
- Ne validez pas de fichiers de type credentials, `.env`, fichiers temporaires ou artefacts de développement générés.

## Portée éditoriale et produits tiers

Ce cursus se concentre sur les technologies Microsoft et les standards ouverts neutres. Les contributions doivent avoir un objectif éducatif clair et ne doivent pas avoir pour but principal d’introduire ou promouvoir un produit commercial tiers, service hébergé, routeur modèle, SDK, serveur MCP ou autre offre spécifique à un fournisseur.

Les logiciels open source et dépendances tierces peuvent être référencés lorsqu’ils sont nécessaires pour expliquer un standard ouvert ou un scénario d’interopérabilité, qu’ils sont présentés de manière neutre et ne sont pas centrés sur un produit ou un point de terminaison hébergé par un fournisseur. Si votre contribution proposée inclut un produit ou service spécifique à un fournisseur, ouvrez un problème (issue) et obtenez l’approbation d’un mainteneur avant de soumettre une pull request.

Les contributeurs doivent divulguer tout emploi pertinent, propriété, parrainage ou autre affiliation avec un produit ou service référencé dans leur contribution. N’incluez pas d’affirmations non prises en charge sur le prix, les performances, la sécurité, la confidentialité ou les comparatifs. Les exemples exécutables ne doivent pas transmettre de données apprenant ni effectuer d’actions publiques via un service tiers externe par défaut.
