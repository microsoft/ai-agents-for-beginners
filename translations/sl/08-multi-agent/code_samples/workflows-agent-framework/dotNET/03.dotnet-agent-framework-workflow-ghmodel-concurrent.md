# ⚡ Vzporedni delovni tokovi agentov z Azure OpenAI (Responses API) (.NET)

## 📋 Vadnica za vzporedno visoko zmogljivo procesiranje

Ta zvezek prikazuje **vzorec vzporednega delovnega toka** z uporabo Microsoft Agent Framework za .NET in Azure OpenAI (Responses API). Naučili se boste, kako zgraditi visoko zmogljive delovne tokove vzporednega procesiranja, ki maksimizirajo prepustnost, tako da več AI agentov izvaja hkrati ob ohranjanju usklajenosti in skladnosti podatkov.

## 🎯 Cilji učenja

### 🚀 **Osnove vzporednega procesiranja**
- **Vzporedno izvajanje agentov**: Hkratno izvajanje več AI agentov za največjo zmogljivost
- **Async/Await vzorci**: Izkoristite asinkroni programerski model .NET za učinkovito vzporednost
- **Azure OpenAI (Responses API)**: Usmerjanje več vzporednih klicev na Azure OpenAI Responses API
- **Upravljanje virov**: Učinkovito upravljanje virov AI modela preko vzporednih operacij

### 🏗️ **Napredna arhitektura vzporednosti**
- **Vzporednost na osnovi opravil**: Uporaba .NET Task Parallel Library za optimalno vzporedno izvajanje
- **Vzorci sinhronizacije**: Uskladitev vzporednih agentov ob izogibanju tekmovalnim pogojem
- **Uravnoteženje obremenitve**: Učinkovita razporeditev dela med razpoložljivo vzporedno procesno zmogljivostjo
- **Odpornost na napake**: Obvladovanje posameznih napak agentov brez ustavitve celotnega delovnega toka

### 🏢 **Vzporedne aplikacije za podjetja**
- **Visokozmogljivo procesiranje dokumentov**: Sočasna obdelava več dokumentov
- **Analiza vsebine v realnem času**: Vzporedna analiza vhodnih podatkovnih tokov
- **Optimizacija obdelave v serijah**: Maksimizacija prepustnosti za obsežne podatkovne operacije
- **Večmodalna analiza**: Vzporedno procesiranje različnih vrst in formatov vsebine

## 💻 Zagon kode

Celotna implementacija je na voljo v `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Ta datoteka prikazuje **Fan-Out/Fan-In vzporedni delovni tok** za načrtovanje potovanj:

### 🏗️ **Arhitektura delovnega toka**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Ključne komponente:**

1. **ConcurrentStartExecutor**: Hkrati pošlje uporabniško zahtevo vsem agentom
2. **Researcher Agent**: Vzporedno analizira destinacije in znamenitosti
3. **Planner Agent**: Sočasno ustvarja podrobne načrte potovanj
4. **ConcurrentAggregationExecutor**: Zbira in združuje rezultate obeh agentov

### 🎯 **Vzorec Fan-Out/Fan-In**

Ta delovni tok prikazuje klasični vzorec **Fan-Out/Fan-In**:
- **Fan-Out**: Ena vhodna sporočila se hkrati oddajo mnogim agentom
- **Vzorec vzporednega procesiranja**: Več agentov vzporedno dela na istem opravilu
- **Fan-In**: Rezultati vseh agentov se zbirajo in združujejo v en izhod

### 📝 Pričakovani izhod

Delovni tok bo:
1. **Oddaja zahteve**: Poslal "Načrtuj potovanje v Seattle decembra" obema agentoma

### 🔍 Razumevanje po meri izdelanih executorjev

**ConcurrentStartExecutor:**
- Implementira `IMessageHandler<string>` za sprejem vhodnih nizov
- Oddaja sporočila vsem povezanih agentov
- Pošlje `TurnToken` za sprožitev vzporednega procesiranja

**ConcurrentAggregationExecutor:**
- Implementira `IMessageHandler<ChatMessage>` za prejemanje odgovorov agentov
- Zbira sporočila na varnem za niti način
- Združuje odgovore, ko prispejo vsi pričakovani
- Oddaja končni izhod z uporabo `context.YieldOutputAsync()`

### ⚡ Prednosti zmogljivosti

**Vzporedno proti zaporednemu:**
- Zaporedno: Agent1 (30s) → Agent2 (30s) = **60 sekund skupaj**
- Vzporedno: Agent1 (30s) || Agent2 (30s) = **30 sekund skupaj**

**Izboljšanje prepustnosti**: do N-krat hitreje za N vzporednih agentov (odvisno od obremenitve in virov)

### 🛡️ Obdelava napak

Delovni tok graciozno upravlja z napakami posameznih agentov:
- Če en agent odpove, drugi nadaljujejo z obdelavo
- Agregator lahko implementira časovne omejitve
- Delne rezultate je mogoče vrniti po potrebi
