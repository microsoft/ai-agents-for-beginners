## 💻 Zaženite kodo

Celotna implementacija je na voljo v `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Ta datoteka prikazuje **Fan-Out/Fan-In sočasni delovni tok** za potovalno načrtovanje:

### 🏗️ **Arhitektura delovnega toka**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Ključne komponente:**

1. **ConcurrentStartExecutor**: Sočasno pošlje uporabniški zahtevek vsem agentom
2. **Researcher Agent**: Sočasno analizira destinacije in atrakcije
3. **Planner Agent**: Sočasno ustvarja podrobne potovalne načrte
4. **ConcurrentAggregationExecutor**: Zbere in združi rezultate obeh agentov

### 🎯 **Vzorec Fan-Out/Fan-In**

Ta delovni tok prikazuje klasični **vzorec Fan-Out/Fan-In**:
- **Fan-Out**: En vhodni podatek se pošlje več agentom hkrati
- **Sočasna obdelava**: Več agentov vzporedno dela na isti nalogi
- **Fan-In**: Rezultati vseh agentov se zberejo in združijo v en izhodni rezultat

### 🔍 Razumevanje prilagojenih izvrševalcev

**ConcurrentStartExecutor:**
- Uresničuje `IMessageHandler<string>` za sprejem niza kot vhod
- Pošilja sporočila vsem povezanih agentom
- Pošlje `TurnToken`, da sproži sočasno obdelavo

**ConcurrentAggregationExecutor:**
- Uresničuje `IMessageHandler<ChatMessage>` za prejema odgovorov agentov
- Zbira sporočila na varen način (thread-safe)
- Združuje, ko prispejo vsi pričakovani odgovori
- Vrne končni izhod z `context.YieldOutputAsync()`

### ⚡ Prednosti zmogljivosti

**Sočasno vs zaporedno:**
- Zaporedno: Agent1 (30s) → Agent2 (30s) = **60 sekund skupno**
- Sočasno: Agent1 (30s) || Agent2 (30s) = **30 sekund skupno**

**Izboljšanje prehodnosti**: Do N-krat hitreje za N sočasnih agentov (odvisno od obremenitve in virov)

### 🛡️ Obravnava napak

Delovni tok nežno obravnava posamezne napake agentov:
- Če eden od agentov ne uspe, ostali nadaljujejo obdelavo
- Agregator lahko implementira logiko časovne omejitve
- Po potrebi lahko vrne delne rezultate
