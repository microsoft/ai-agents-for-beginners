# ⚡ Sočasni delovni tokovi agentov z Azure OpenAI (Responses API) (.NET)

## 📋 Vadnica za vzporedno visokozmogljivo procesiranje

Ta zvezek prikazuje **vzorce sočasnih delovnih tokov** z uporabo Microsoft Agent Framework za .NET in Azure OpenAI (Responses API). Naučili se boste, kako zgraditi visokozmogljive vzporedne delovne tokove, ki maksimirajo prepustnost z izvajanjem več AI agentov istočasno ob hkratnem vzdrževanju koordinacije in doslednosti podatkov.

## 💻 Zaženite kodo

Celotna izvedba je na voljo v `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Ta datoteka prikazuje **Fan-Out/Fan-In sočasni delovni tok** za načrtovanje potovanja:

### 🏗️ **Arhitektura delovnega toka**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Ključne sestavine:**

1. **ConcurrentStartExecutor**: Hkrati oddaja uporabniško zahtevo vsem agentom
2. **Agent raziskovalec**: Sočasno analizira destinacije in znamenitosti
3. **Agent načrtovalec**: Sočasno ustvarja podrobne potovalne načrte
4. **ConcurrentAggregationExecutor**: Zbira in združuje rezultate obeh agentov

### 🎯 **Vzorec Fan-Out/Fan-In**

Ta delovni tok prikazuje klasični **vzorec Fan-Out/Fan-In**:
- **Fan-Out**: Ena vhodna sporočila se hkrati oddajo več agentom
- **Sočasno procesiranje**: Več agentov istočasno dela na isti nalogi
- **Fan-In**: Rezultati vseh agentov so zbrani in združeni v en sam izhod

### 📝 Pričakovani izhod

Delovni tok bo:
1. **Oddaja zahteve**: Poslati »Načrtuj potovanje v Seattle decembra« obema agentoma
2. **Sočasna obdelava**: Oba agenta delata hkrati:
   - Raziskovalec prepozna znamenitosti in podrobnosti

Ta vzorec sočasnosti je idealen za:

- **Tržne raziskave**: Vzporedna analiza različnih tržnih segmentov

### 🔍 Razumevanje prilagojenih izvrševalcev

**ConcurrentStartExecutor:**
- Implementira `IMessageHandler<string>` za sprejem nizov
- Oddaja sporočila vsem povezanih agentom
- Pošlje `TurnToken` za sprožitev sočasnega procesiranja

**ConcurrentAggregationExecutor:**
- Implementira `IMessageHandler<ChatMessage>` za prejem odgovorov agentov
- Zbira sporočila na niti varnem načinu
- Združuje, ko prispejo vsi pričakovani odgovori
- Daje končni izhod z uporabo `context.YieldOutputAsync()`

### ⚡ Prednosti zmogljivosti

**Sočasno vs Zaporedno:**
- Zaporedno: Agent1 (30s) → Agent2 (30s) = **60 sekund skupno**
- Sočasno: Agent1 (30s) || Agent2 (30s) = **30 sekund skupno**

**Izboljšanje prepustnosti**: Do N× hitreje za N sočasnih agentov (odvisno od obremenitve in virov)

### 🛡️ Upravljanje napak

Delovni tok elegantno obravnava napake posameznih agentov:
- Če eden od agentov odpove, ostali nadaljujejo z obdelavo
- Agregator lahko izvaja logiko preteka časa
- Povratni delni rezultati so možni, če je potrebno
