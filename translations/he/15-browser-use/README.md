# בניית סוכני שימוש במחשב (CUA)

סוכני שימוש במחשב יכולים לתקשר עם אתרי אינטרנט באותה הדרך שאדם היה עושה זאת: על ידי פתיחת דפדפן, בדיקת הדף, ונטילת הפעולה הבאה הטובה ביותר ממה שהם רואים. בשיעור זה, תבנה סוכן אוטומציה לדפדפן שמחפש ב-Airbnb, מחלץ נתוני רשימות במבנה, ומזהה את השהייה הזולה ביותר בסטוקהולם.

השיעור משלב שימוש בדפדפן המונחה בינה מלאכותית לניווט, Playwright ופרוטוקול Chrome DevTools (CDP) לבקרת הדפדפן, Azure OpenAI לראייה והסקה, ו-Pydantic לחילוץ במבנה.

## מבוא

שיעור זה יכסה:

- הבנת מתי סוכני שימוש במחשב הם מתאימים יותר מאוטומציה מבוססת API בלבד
- שילוב של Browser-Use עם Playwright ו-CDP לניהול אמין של מחזור חיים של הדפדפן
- שימוש בראייה של Azure OpenAI ופלט מובנה של Pydantic לחילוץ נתוני רשימות מדפי אינטרנט דינמיים
- קבלת החלטות מתי להשתמש בזרימת עבודה אוטומציה לדפדפן שמבוססת על סוכן, על שחקן, או היברידית

## מטרות למידה

לאחר סיום שיעור זה, תדע כיצד:

- להגדיר את Browser-Use עם Azure OpenAI ו-Playwright
- לבנות זרימת עבודה אוטומציה בדפדפן שמנווטת באתר אמתית ומטפלת ברכיבי ממשק משתמש דינמיים
- לחלץ תוצאות ממוסמנות מתוכן גלוי בדף ולהפכן ללוגיקה עסקית המשך
- לבחור בין דפוסי סוכן או שחקן בהתבסס על מידת החיזוי של משימת הדפדפן

## דוגמת קוד

בשיעור זה יש מדריך פנקס אחד:

- [15-browser-user.ipynb](./15-browser-user.ipynb): מפעיל מושב כרום דרך CDP, מחפש ב-Airbnb רשימות לסטוקהולם, מחלץ מחירים עם ראיית Browser-Use, ומחזיר את האפשרות הזולה ביותר כנתונים במבנה.

## דרישות מוקדמות

- Python 3.12+
- פריסה של Azure OpenAI מוגדרת בסביבת העבודה שלך
- Chrome או Chromium מותקן במחשב המקומי
- תלותיות Playwright מותקנות
- היכרות בסיסית עם Python אסינכרוני

## הגדרה

התקן את החבילות שבהן משתמש הפנקס:

```bash
pip install browser_use playwright python-dotenv
playwright install chromium
```

הגדר את משתני הסביבה של Azure OpenAI שבהם משתמש הפנקס:

```bash
AZURE_OPENAI_ENDPOINT=...
AZURE_OPENAI_API_KEY=...
AZURE_OPENAI_CHAT_DEPLOYMENT_NAME=...
# אופציונלי: ברירת המחדל היא לגרסת ה-API העדכנית ביותר כאשר לא מצוין
AZURE_OPENAI_API_VERSION=...
```

## סקירת ארכיטקטורה

הפנקס מדגים זרימת עבודה היברידית של אוטומציה בדפדפן:

1. כרום מתחיל עם CDP מופעל כך שגם Playwright וגם Browser-Use יכולים לשתף את אותו מושב דפדפן.
2. סוכן Browser-Use מטפל במשימות ניווט פתוחות כמו פתיחת Airbnb, סגירת חלונות קופצים, וחיפוש לסטוקהולם.
3. הדף הפעיל נבדק עם סכמת Pydantic במבנה לחילוץ כותרות רשימות, מחירי לילה, דירוגים וכתובות URL.
4. לוגיקת Python משווה את הרשימות שחולצו ומדגישה את התוצאה הזולה ביותר.

גישה זו שומרת על ההסקה הגמישה מבוססת ראייה ש-Browser-Use טוב בה, ועדיין נותנת לך שליטה דטרמיניסטית על הדפדפן כשאתה צריך.

## מסקנות עיקריות ונהלים מומלצים

### מתי להשתמש בסוכן לעומת שחקן

| תרחיש | שימוש בסוכן | שימוש בשחקן |
|----------|-----------|-----------|
| מבנים דינמיים | כן, בינה מלאכותית יכולה להסתגל לשינויים בדף | לא, בוחרים שבירים יכולים להינזק |
| מבנה ידוע | לא, סוכן איטי יותר מבקרת ישירה | כן, מהיר ומדויק |
| מציאת אלמנטים | כן, שפה טבעית עובדת טוב | לא, דרושים בוחרים מדויקים |
| בקרת תזמון | לא, פחות צפוי | כן, שליטה מלאה על המתנות וניסיונות חוזרים |
| זרימות עבודה מורכבות | כן, מטפל במצבי ממשק בלתי צפויים | לא, דורש הסתעפויות מפורשות |

### נהלים מומלצים לשימוש ב-Browser-Use

1. התחל עם סוכן לחקירה וניווט דינמי.
2. עבור לשליטה ישירה בדף כשהאינטראקציה הופכת לצפוייה.
3. השתמש במודלים לפלט במבנה כך שהנתונים שחולצו יהיו מאומתים ובטוחים מסוג.
4. הוסף השהיות באסטרטגיה אחרי פעולות שמפעילות שינויים גלויים בממשק.
5. צלם צילומי מסך תוך כדי איטרציה כדי להקל על איתור תקלות.
6. צפה ששינויים באתרי אינטרנט יתרחשו ועצב אסטרטגיות גיבוי לחלונות קופצים ולהסטות מבנה.
7. שלב דפוסי סוכן ושחקן לקבלת גם גמישות וגם דיוק.

### יישומים מעשיים

- הזמנת נסיעות ומעקב מחירים
- השוואת מחירים ובדיקות זמינות בקמעונאות מקוונת
- חילוץ במבנה מאתרים דינמיים
- בדיקות וידוא ממשק משתמש ערניים לראייה
- ניטור אתר אינטרנט והתראות
- מילוי טפסים חכם בזרימות מרובות שלבים

## דוגמה מעשית: Microsoft Project Opal

הסוכן שתבנה בשיעור זה הוא גרסה קטנה ומקומית של **סוכן שימוש במחשב (CUA)** — תוכנה שמניעה דפדפן כמו אדם. מיקרוסופט מביאה את אותה הרעיון לפרויקטים ארגוניים עם **[Project Opal (Frontier)](https://support.microsoft.com/en-us/microsoft-365-copilot/get-started-with-project-opal-frontier)**, יכולת ב-Microsoft 365 Copilot.

עם Project Opal, אתה מתאר משימה והסוכן עובד מטעמך באמצעות **שימוש במחשב על מחשב ענן Windows 365 מאובטח**, הפועל על פני יישומים, אתרים ונתונים מבוססי דפדפן בארגון שלך. הוא פועל **באופן אסינכרוני ברקע**, ואתה יכול לכוון את העבודה או לקחת שליטה בכל עת. דוגמאות לעבודות כוללות:

- ניהול בקשות חברות בקבוצות אבטחה
- איסוף ואימות ראיות ביקורת לסקירות עמידה בתקנים
- טיפול בתקריות IT (עדכון סטטוס כרטיסים, הקצאת בעלים, סגירת כפילויות)
- הרכבת נתוני Excel למצגת סגירה פיננסית

Opal הוא מקור מידע שימושי לגבי איך נראה **סוכן שימוש במחשב ברמת ייצור, אמין** — והוא מחזק מושגים משיעורים קודמים:

| מושג בקורס זה | איך Project Opal מיישם אותו |
|------------------------|-----------------------------|
| **אדם בלולאה** (שיעור 06) | Opal עוצר להזנת פרטי התחברות, נתונים רגישים או הוראות לא ברורות, ואינו מזין סיסמאות או שולח טפסים ללא אישור מפורש. אתה יכול *לנהל שליטה* ו*להחזיר שליטה* באמצע המשימה. |
| **סוכנים אמינים ומאובטחים** (שיעורים 06 ו-18) | פועל במחשב ענן Windows 365 מבודד, דפדפן בלבד כברירת מחדל (גישה אחרת למחשב חסומה, מאוכפת דרך Intune), משתמש בזהות שלך כך שניגש רק למה שאתה מורשה, ורושם כל פעולה עבור ביקורת. |
| **תכנון ומטה-קוגניציה** (שיעורים 07 ו-09) | Opal מייצר תחילה תוכנית למשימה, ואז מנטר את ההסקה העצמיות בכל שלב ועוצר אם מזהה פעילות חשודה. |
| **יכולות / כלים לשימוש חוזר** (שיעור 04) | **כישורים** מאפשרים לך לכתוב הוראות לעבודות חוזרות (מיובאות מקובץ `.md` או נכתבות ב-Opal) ולשימוש חוזר בשיחות. |

> **זמינות:** פרויקט Opal זמין כיום למשתמשים בתוכנית הגישה המוקדמת [Frontier](https://adoption.microsoft.com/copilot/frontier-program/) עם מנוי ל-Microsoft 365 Copilot, ומנהל המערכת שלך חייב להשלים את ההגדרה. מאחר שזו תכונה ניסיונית של Frontier, היכולות יכולות להשתנות לאורך זמן.
