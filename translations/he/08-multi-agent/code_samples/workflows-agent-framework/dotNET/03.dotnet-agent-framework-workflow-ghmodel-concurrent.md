# ⚡ זרימות עבודה של סוכנים מקבילים עם Azure OpenAI (Responses API) (.NET)

## 📋 מדריך לעיבוד מקבילי בעל ביצועים גבוהים

פנקס זה מדגים **תבניות זרימת עבודה מקבילה** באמצעות Microsoft Agent Framework ל-.NET ו-Azure OpenAI (Responses API). תלמד איך לבנות זרימות עבודה לעיבוד מקבילי בעל ביצועים גבוהים שממקסמות תפוקה על ידי הרצה בו-זמנית של סוכנים רבים תוך שמירה על תיאום ועקביות נתונים.

## 💻 הרצת הקוד

המימוש המלא זמין בקובץ `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. קובץ זה מדגים **זרימת עבודה מקבילה Fan-Out/Fan-In** לתכנון טיולים:

### 🏗️ **ארכיטקטורת זרימת העבודה**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**רכיבים עיקריים:**

1. **ConcurrentStartExecutor**: משדר את בקשת המשתמש לכל הסוכנים במקביל
2. **סוכן חוקר**: מנתח יעדים ואטרקציות בו-זמנית
3. **סוכן מתכנן**: יוצר תוכניות טיול מפורטות במקביל
4. **ConcurrentAggregationExecutor**: אוסף וממזג תוצאות משני הסוכנים

### 🎯 **תבנית Fan-Out/Fan-In**

זרימת העבודה מדגימה את תבנית ה-**Fan-Out/Fan-In** הקלאסית:
- **Fan-Out**: הודעת קלט אחת משודרת למספר סוכנים במקביל
- **עיבוד מקבילי**: סוכנים רבים עובדים במקביל על אותו משימה
- **Fan-In**: התוצאות מכל הסוכנים נאספות ומאוגדות לפלט יחיד

    .Build();

### 🔍 הבנת מפעילים מותאמים אישית

**ConcurrentStartExecutor:**
- מממש את `IMessageHandler<string>` לקבלת קלט מחרוזת
- משדר הודעות לכל הסוכנים המחוברים
- שולח `TurnToken` כדי להפעיל עיבוד מקבילי

**ConcurrentAggregationExecutor:**
- מממש את `IMessageHandler<ChatMessage>` לקבלת תגובות סוכן
- אוסף הודעות בצורה בטוחה לתהליכים
- מאגד כאשר נמשכות כל התגובות הצפויות
- מחזיר פלט סופי באמצעות `context.YieldOutputAsync()`

### ⚡ הטבות ביצועים

**מקבילי לעומת רציף:**
- רציף: Agent1 (30 שניות) → Agent2 (30 שניות) = **60 שניות בסך הכל**
- מקבילי: Agent1 (30 שניות) || Agent2 (30 שניות) = **30 שניות בסך הכל**

**שיפור בתפוקה**: עד פי N× מהיר יותר עבור N סוכנים מקבילים (תלוי בעומס העבודה ובמשאבים)
