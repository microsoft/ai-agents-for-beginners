# ⚡ זרימות עבודה של סוכנים מקבילות עם Azure OpenAI (Responses API) (.NET)

## 📋 מדריך לעיבוד מקבילי בעלי ביצועים גבוהים

פנקס עבודה זה מציג **תבניות זרימות עבודה במקביל** באמצעות Microsoft Agent Framework ל-.NET ו-Azure OpenAI (Responses API). תלמדו כיצד לבנות זרימות עבודה לעיבוד מקבילי וביצועים גבוהים שממקסמות את התפוקה על ידי ביצוע בו-זמני של סוכני AI מרובים תוך שמירה על תיאום ואחידות נתונים.

## 💻 הרצת הקוד

המימוש המלא זמין בקובץ `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. קובץ זה מדגים **זרימת עבודה מקבילה Fan-Out/Fan-In** לתכנון נסיעות:

### 🏗️ **ארכיטקטורת זרימת העבודה**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**רכיבים מרכזיים:**

1. **ConcurrentStartExecutor**: משדר את בקשת המשתמש לכל הסוכנים בו-זמנית
2. **Researcher Agent**: מנתח יעדים ואטרקציות במקביל
3. **Planner Agent**: יוצר תוכניות נסיעה מפורטות במקביל
4. **ConcurrentAggregationExecutor**: אוסף וממזג תוצאות משני הסוכנים

### 🎯 **תבנית Fan-Out/Fan-In**

זרימת עבודה זו ממחישה את התבנית הקלאסית **Fan-Out/Fan-In**:
- **Fan-Out**: הודעת קלט אחת משודרת למספר סוכנים בו-זמנית
- **עיבוד מקבילי**: מספר סוכנים עובדים במקביל על אותה משימה
- **Fan-In**: איסוף ותיאום של תוצאות כל הסוכנים לפלט אחד

### 🔍 הבנת Executors מותאמים אישית

**ConcurrentStartExecutor:**
- מממש את `IMessageHandler<string>` לקבלת מחרוזת קלט
- משדר הודעות לכל הסוכנים המחוברים
- שולח `TurnToken` להנעת עיבוד מקבילי

**ConcurrentAggregationExecutor:**
- מממש את `IMessageHandler<ChatMessage>` לקבלת תגובות סוכן
- אוסף הודעות בצורה בטוחה לתהליכים
- מבצע אגרגציה כשהגיעו כל התגובות הצפויות
- מחזיר את הפלט הסופי באמצעות `context.YieldOutputAsync()`

### ⚡ יתרונות ביצועים

**מקבילי לעומת סידורי:**
- סידורי: סוכן1 (30 שניות) → סוכן2 (30 שניות) = **60 שניות בסך הכל**
- מקבילי: סוכן1 (30 שניות) || סוכן2 (30 שניות) = **30 שניות בסך הכל**

**שיפור בתפוקה**: עד פי N מהיר יותר עבור N סוכנים במקביל (תלוי בעומס ובמשאבים)
