# ⚡ Súbežné pracovné postupy agentov s Azure OpenAI (Responses API) (.NET)

## 📋 Návod na vysoko výkonné paralelné spracovanie

## 💻 Spustenie kódu

Kompletná implementácia je k dispozícii v `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Tento súbor ukazuje **Fan-Out/Fan-In súbežný pracovný postup** na plánovanie cesty:

### 🏗️ **Architektúra pracovného postupu**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Kľúčové komponenty:**

1. **ConcurrentStartExecutor**: Súčasne vysiela požiadavku používateľa všetkým agentom
2. **Researcher Agent**: Paralelne analyzuje destinácie a atrakcie
3. **Planner Agent**: Paralelne vytvára podrobné cestovné plány
4. **ConcurrentAggregationExecutor**: Zhromažďuje a zlúči výsledky od oboch agentov

### 🎯 **Vzor Fan-Out/Fan-In**

Tento pracovný postup demonštruje klasický **Fan-Out/Fan-In** vzor:
- **Fan-Out**: Jeden vstupný odkaz je súčasne vysielaný viacerým agentom
- **Súbežné spracovanie**: Viacerí agenti pracujú paralelne na rovnakej úlohe
- **Fan-In**: Výsledky všetkých agentov sa zhromaždia a zlúčia do jedného výstupu

Pracovný postup bude:
1. **Broadcast požiadavky**: Poslať "Naplánuj cestu do Seattlu v decembri" obom agentom

### 🔍 Pochopenie vlastných executorov

**ConcurrentStartExecutor:**
- Implementuje `IMessageHandler<string>`, aby prijímal reťazcový vstup
- Vysiela správy všetkým pripojeným agentom
- Posiela `TurnToken` na spustenie súbežného spracovania

**ConcurrentAggregationExecutor:**
- Implementuje `IMessageHandler<ChatMessage>`, aby prijímal odpovede agentov
- Zhromažďuje správy vláknovo-bezpečným spôsobom
- Agreguje po príchode všetkých očakávaných odpovedí
- Výsledný výstup odovzdáva pomocou `context.YieldOutputAsync()`

### ⚡ Výkonnostné výhody

**Súbežné vs Sekvenčné:**
- Sekvenčné: Agent1 (30s) → Agent2 (30s) = **celkovo 60 sekúnd**
- Súbežné: Agent1 (30s) || Agent2 (30s) = **celkovo 30 sekúnd**

**Zlepšenie priepustnosti**: Až N× rýchlejšie pre N súbežných agentov (závisí od záťaže a zdrojov)

### 🛡️ Zvládanie chýb

Pracovný postup elegantne spracúva zlyhania jednotlivých agentov:
- Ak jeden agent zlyhá, ostatní pokračujú v spracovaní
- Agregátor môže implementovať logiku timeoutu
- V prípade potreby môžu byť vrátené čiastočné výsledky

### 📊 Pokročilé funkcie
