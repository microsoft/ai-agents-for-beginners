## 💻 Spustenie kódu

Kompletná implementácia je dostupná v súbore `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Tento súbor demonštruje **Fan-Out/Fan-In paralelný pracovný postup** pre plánovanie ciest:

### 🏗️ **Architektúra pracovného postupu**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Kľúčové komponenty:**

1. **ConcurrentStartExecutor**: Súčasne vysiela používateľskú požiadavku všetkým agentom
2. **Výskumný agent**: Paralelne analyzuje destinácie a atrakcie
3. **Plánovací agent**: Paralelne vytvára podrobné cestovné plány
4. **ConcurrentAggregationExecutor**: Zhromažďuje a spája výsledky od oboch agentov

### 🎯 **Fan-Out/Fan-In vzor**

Tento pracovný postup demonštruje klasický **Fan-Out/Fan-In** vzor:
- **Fan-Out**: Jedna vstupná správa sa súčasne vysiela viacerým agentom
- **Súbežné spracovanie**: Viac agentov pracuje paralelne na tej istej úlohe
- **Fan-In**: Výsledky od všetkých agentov sú zhromaždené a agregované do jedného výstupu

### 🔍 Porozumenie vlastných executorov

**ConcurrentStartExecutor:**
- Implementuje `IMessageHandler<string>` na prijímanie reťazcových vstupov
- Vysiela správy všetkým pripojeným agentom
- Posiela `TurnToken` na spustenie paralelného spracovania

**ConcurrentAggregationExecutor:**
- Implementuje `IMessageHandler<ChatMessage>` na prijímanie odpovedí agentov
- Zhromažďuje správy bezpečne pre viaceré vlákna
- Agreguje keď prídu všetky očakávané odpovede
- Vracia konečný výstup cez `context.YieldOutputAsync()`

### ⚡ Výhody výkonu

**Paralelné vs sekvenčné:**
- Sekvenčné: Agent1 (30s) → Agent2 (30s) = **60 sekúnd celkovo**
- Paralelné: Agent1 (30s) || Agent2 (30s) = **30 sekúnd celkovo**

**Zlepšenie priepustnosti**: Až N× rýchlejšie pre N paralelných agentov (závisí od záťaže a zdrojov)

### 🛡️ Spracovanie chýb

Pracovný postup elegantne spracováva zlyhania jednotlivých agentov:
- Ak jeden agent zlyhá, ostatní pokračujú v spracovaní
- Aggregátor môže implementovať časový limit
- Môžu sa vrátiť čiastočné výsledky ak je to potrebné
