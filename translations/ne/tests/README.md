# एजेन्ट स्मोक टेस्टहरू

यो फोल्डरले तपाईंले कोर्समा बनाउने एजेन्टहरूको लागि **स्मोक-टेस्ट क्याटालगहरू** समेट्छ।
स्मोक टेस्ट भनेको एक सस्तो, छिटो जाँच हो जसले यो सुनिश्चित गर्छ कि **परिनियोजित Microsoft Foundry होस्ट गरिएको
एजेन्ट** पहुँचयोग्य, प्रतिक्रिया दिइरहेको, र यसका सबैभन्दा आधारभूत प्रॉम्प्ट
अपेक्षाहरूलाई पालना गरिरहेको छ। यो पहिलो द्वार हो — [Lesson 10](../10-ai-agents-production/README.md) र
[Lesson 16](../16-deploying-scalable-agents/README.md) मा सिकाउने सम्पूर्ण मूल्यांकन
पाइपलाइनको विकल्प होइन।

ती क्याटालगहरूलाई [AI Smoke Test](https://github.com/marketplace/actions/ai-smoke-test)
GitHub एक्सनले [`.github/workflows/smoke-test.yml`](../../../.github/workflows/smoke-test.yml)
workflow मार्फत उपभोग गर्दछ।

## कसरी चलाउने

1. पाठको एजेन्टलाई Microsoft Foundry मा होस्ट गरिएको एजेन्टको रूपमा परिनियोजन गर्नुहोस् (विस्तृत
   प्रक्रिया लागि Lesson 16 हेर्नुहोस्)। **एजेन्ट नाम** र तपाईंको
   **Foundry प्रोजेक्ट अन्त्यबिन्दु** नोट गर्नुहोस्।
2. यी भण्डारण गुप्त सूचनाहरू थप्नुहोस् (Settings → Secrets and variables → Actions):
   `AZURE_CLIENT_ID`, `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID`। फेडेरेटेड
   पहिचानलाई **Foundry प्रोजेक्ट स्कोप** मा **Azure AI User** को भूमिका आवश्यक पर्छ।
3. **Actions** ट्याबबाट, **Smoke-test hosted agents** चलाउनुहोस् र पाठको लागि
   `tests_file` छान्नुहोस्, त्यसपछि मिल्ने `agent_name` र
   `project_endpoint` प्रदान गर्नुहोस्।

## कुन पाठहरूमा स्मोक टेस्टहरू छन्?

स्मोक टेस्टहरू तिनी पाठहरूसँग सम्बन्धित छन् जहाँ तपाईंले **एजेन्ट परिनियोजन गर्नुहुन्छ** जसका पाठ प्रतिक्रियाहरूलाई
ज्ञात सामग्रीसंग मिलाएर परीक्षण गर्न सकिन्छ। तिनी पाठहरू जुन सैद्धान्तिक छन्, केवल स्थानीय रूपमा चल्छन्,
वा जुन गैर-नियतात्मक सिर्जनात्मक आउटपुट उत्पादन गर्छन् ती जानबुझेर बाहिर राखिएका छन्:

- **Lesson 17 (Creating Local AI Agents)** तपाईंको कार्यस्थानमा पूर्ण रूपमा Foundry Local सँग चल्छ र
  Foundry Responses अन्त्यबिन्दु उपलब्ध गराउँदैन, त्यसैले यो
  क्रिया लागू हुँदैन। यसलाई नोटबुक स्थानीय रूपमा चलाएर प्रमाणित गर्नुहोस्।
- Design-pattern र सिद्धान्त पाठहरू (02, 03, 06, 07, 09, 12) स्मोक-टेस्टका लागि कुनै एक मात्र
  परिनियोजित एजेन्ट पठाउँदैनन्।

## क्याटालग स्कीमा (द्रुत सन्दर्भ)

प्रत्येक क्याटालग एउटा JSON कागजात हो जसको शीर्ष स्तरमा `tests` एरे हुन्छ। प्रत्येक प्रविष्टिले
एउटा प्रॉम्प्ट POST गर्दछ र प्रतिक्रियामा नतिजा परिक्षण गर्दछ:

| क्षेत्र | अर्थ |
|-------|---------|
| `id` | लगमा छापिने अनन्य चरण पहिचानकर्ता। |
| `description` | मानव-पठनीय उद्देश्य। |
| `prompt` | एजेन्टलाई पठाइएको सन्देश। |
| `assertions.status` | अपेक्षित HTTP स्थिति (पूर्वनिर्धारित 200)। |
| `assertions.contains_any` | यदि प्रतिक्रिया यी कुनै उपस्ट्रिंगहरू समावेश गर्छ भने पास। |
| `assertions.contains_all` | यदि प्रतिक्रिया प्रत्येक उपस्ट्रिंग समावेश गर्छ भने पास। |
| `assertions.contains_none` | यदि प्रतिक्रिया यी कुनै उपस्ट्रिंगहरू समावेश गर्दैन भने पास। |
| `save_response_id_as` | पछि बहु-कदमका लागि प्रतिक्रिया आईडी भण्डारण गर्नुहोस्। |
| `use_previous_response_id` | यो टर्न बचत गरिएको प्रतिक्रिया आईडीमा जोड्ने रूपमा पठाउनुहोस्। |

दावीहरू केस-इन्सेन्सिटिभ उपस्ट्रिंग चेकहरू हुन्। पूर्ण स्कीमा सहित Foundry-प्रबन्धित कुराकानी स्रोतहरूको लागि
[क्रिया दस्तावेज](https://github.com/marketplace/actions/ai-smoke-test) हेर्नुहोस्।
फुल स्किमा, फाउन्ड्री-प्रबन्धित कुराकानी स्रोतहरू सहित।
