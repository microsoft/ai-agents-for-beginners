# ⚡ Azure OpenAI (Responses API) सँग समानान्तर एजेन्ट वर्कफ्लोहरू (.NET)

## 📋 उच्च-प्रदर्शन समानान्तर प्रोसेसिङ ट्युटोरियल

यस नोटबुकले माइक्रोसफ्ट एजेन्ट फ्रेमवर्क फर .NET र Azure OpenAI (Responses API) प्रयोग गरेर **समानान्तर वर्कफ्लो नमूनाहरू** प्रस्तुत गर्दछ। तपाईंले कसरी उच्च-प्रदर्शन, समानान्तर प्रक्रिया गर्ने वर्कफ्लोहरू निर्माण गर्ने सिक्नुहुनेछ जसले अधिकतम थ्रूपुटका लागि एकैचोटि धेरै AI एजेन्टहरू सञ्चालन गर्छन् र समन्वय तथा डाटा स्थिरता कायम राख्दछ।

## 🎯 सिकाइ लक्ष्यहरू

### 🚀 **समानान्तर प्रोसेसिङको आधारभूत कुरा**
- **समानान्तर एजेन्ट कार्यान्वयन**: अधिकतम प्रदर्शनका लागि एकैचोटि धेरै AI एजेन्टहरू चलाउनुहोस्
- **Async/Await ढाँचा**: कुशल समकालिकताका लागि .NET को async प्रोग्रामिङ मोडेलको उपयोग गर्नुहोस्
- **Azure OpenAI (Responses API)**: Azure OpenAI Responses API मा धेरै समानान्तर कलहरू समन्वय गर्नुहोस्
- **स्रोत व्यवस्थापन**: समानान्तर कार्यहरूको लागि AI मोडल स्रोतहरूको कुशल व्यवस्थापन गर्नुहोस्

### 🏗️ **उन्नत समकालिकता वास्तुकला**
- **टास्क-आधारित समानान्तरता**: उत्तम समानान्तर कार्यान्वयनका लागि .NET Task Parallel Library प्रयोग गर्नुहोस्
- **सिन्क्रोनाइजेसन ढाँचा**: प्रतिस्पर्धा अवस्थाहरूबाट बच्ने गरी समकालीन एजेन्टहरू समन्वय गर्नुहोस्
- **लोड ब्यालेन्सिङ**: उपलब्ध समानान्तर प्रोसेसिङ क्षमतामा कार्यहरू कुशलतापूर्वक वितरण गर्नुहोस्
- **गल्ती सहिष्णुता**: सम्पूर्ण वर्कफ्लो रोकिन नदिई व्यक्तिगत एजेन्ट असफलतालाई व्यवस्थापन गर्नुहोस्

### 🏢 **उद्यम समानान्तर अनुप्रयोगहरू**
- **उच्च-आकृति कागजात प्रोसेसिङ**: धेरै कागजातहरू एकैचोटि प्रोसेस गर्नुहोस्
- **रियल-टाइम सामग्री विश्लेषण**: आउने डाटा स्ट्रिमहरूको समानान्तर विश्लेषण
- **ब्याच प्रोसेसिङ अनुकूलन**: ठूलो-पैमाने डाटा प्रोसेसिङ अपरेशनको लागि थ्रूपुट अधिकतम गर्नुहोस्
- **बहु-मोडल विश्लेषण**: फरक सामग्री प्रकार र ढाँचाहरूको समानान्तर प्रोसेसिङ

## 💻 कोड चलाउने तरिका

पूर्ण कार्यान्वयन `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs` मा उपलब्ध छ। यो फाइलले यात्रा योजना बनाउनको लागि **फ्यान-आउट/फ्यान-इन समानान्तर वर्कफ्लो** देखाउँछ:

### 🏗️ **वर्कफ्लो वास्तुकला**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**मुख्य कम्पोनेन्टहरू:**

1. **ConcurrentStartExecutor**: प्रयोगकर्ता अनुरोध सबै एजेन्टहरूलाई एकैचोटि प्रसारण गर्दछ
2. **Researcher Agent**: गन्तव्यहरू र आकर्षणहरू समानान्तर विश्लेषण गर्दछ
3. **Planner Agent**: विस्तृत यात्रा योजना समानान्तर बनाउँछ
4. **ConcurrentAggregationExecutor**: दुबै एजेन्टका परिणामहरू संकलन र एकीकृत गर्छ

### 🎯 **फ्यान-आउट/फ्यान-इन ढाँचा**

यो वर्कफ्लोले पारंपरिक **फ्यान-आउट/फ्यान-इन** ढाँचालाई देखाउँछ:
- **फ्यान-आउट**: एउटा इनपुट सन्देश एकैचोटि धेरै एजेन्टहरूलाई प्रसारण गरिन्छ
- **समानान्तर प्रोसेसिङ**: धेरै एजेन्टहरू एकै कार्यमा समानान्तर काम गर्छन्
- **फ्यान-इन**: सबै एजेन्टका परिणामहरू संकलन गरिन्छ र एउटै उत्पादनमा एकीकृत गरिन्छ

- **बजार अनुसन्धान**: फरक बजार खण्डहरूको समानान्तर विश्लेषण

### 🔍 अनुकूलित कार्यान्वयनहरू बुझ्न

**ConcurrentStartExecutor:**
- `IMessageHandler<string>` कार्यान्वयन गरेर स्ट्रिङ इनपुट स्वीकार्छ
- जडित सबै एजेन्टहरूमा सन्देश प्रसारित गर्दछ
- समानान्तर प्रोसेसिङ सुरु गर्न `TurnToken` पठाउँछ

**ConcurrentAggregationExecutor:**
- एजेन्ट प्रतिक्रियाहरू प्राप्त गर्न `IMessageHandler<ChatMessage>` कार्यान्वयन गर्दछ
- थ्रेड-सेफ तरिकाले सन्देश संकलन गर्दछ
- सबै अपेक्षित प्रतिक्रियाहरू आएपछि संकलन गर्दछ
- `context.YieldOutputAsync()` प्रयोग गरेर अन्तिम आउटपुट दिन्छ

### ⚡ प्रदर्शन लाभहरू

**समानान्तर बनाम अनुक्रमिक:**
- अनुक्रमिक: Agent1 (30 सेकेण्ड) → Agent2 (30 सेकेण्ड) = **कुल 60 सेकेण्ड**
- समानान्तर: Agent1 (30 सेकेण्ड) || Agent2 (30 सेकेण्ड) = **कुल 30 सेकेण्ड**

**थ्रूपुट सुधार**: N समानान्तर एजेन्टहरूको लागि N× सम्म तेज (कार्यभार र स्रोतहरूमा निर्भर गर्दछ)
