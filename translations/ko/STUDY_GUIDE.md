강의를 대체하기 위한 것이 아닙니다. 어디서 시작할지, 각 강의에서 무엇을
찾아야 할지, 그리고 아이디어를 연결하여 작은 작업 가능한 에이전트
데모를 만드는 방법을 결정하는 데 도움이 됩니다.

처음이라면 간단하게 시작하세요:

1. [코스 설정](./00-course-setup/README.md)을 읽으세요.
2. 01-06 강의를 순서대로 완료하세요.
3. 학습하면서 하나의 작은 데모 아이디어를 마음에 두세요.
4. 각 강의 후에 이렇게 물어보세요: "내 에이전트가 이전에는 할 수 없었던 무엇을 이제 할 수 있지?"


## 마음에 두기 좋은 간단한 데모

에이전트를 배우는 좋은 방법은 강의 전체에서 한 가지 데모 아이디어를 따라가는 것입니다.

예제 데모: **코스 도우미 에이전트**.

사용자는 이렇게 요청합니다:

> "에이전트가 도구를 어떻게 사용하는지 배우고 싶어요. 올바른 강의를 찾아서, 먼저 읽어야 할 내용을 요약해주고, 짧은 연습 과제를 주세요."


일반 챗봇은 이미 알고 있는 내용에 답변할 수 있습니다. 에이전트는 이보다 더 많은 일을 할 수 있습니다:

1. **코스 파일을 읽거나 검색해서** 올바른 강의를 찾습니다.
2. **도구를 사용해** 강의 링크, 예제, 참고 자료를 가져옵니다.
3. **하나의 긴 답변 대신에** 짧은 학습 경로를 계획합니다.
4. 현재 대화의 **맥락을 사용해** 학습자의 목표에 집중합니다.

5. 애플리케이션이 메모리를 지원하면, **유용한 선호도를 기억합니다**.
6. 사용자에게 일어난 일을 이해시키기 위해 **추적, 인용, 로그를 보여줍니다**.
7. 위험한 행동이나 민감한 데이터를 사용하기 전에 **안전장치를 적용합니다**.

각 수업을 공부할 때 이 데모로 돌아와서 질문해 보세요: 이 수업이 추가하는 새로운 기능은 무엇일까요?


## 목표로 하는 것

강의를 마칠 때쯤에는 다음 부분들을 결합한 에이전트 시스템을 설명하고 만들 수 있어야 합니다:


|------|------------------------|-------------|
| 모델 | 사용자의 요청을 해석하는 추론 엔진 | 학습자가 도구 사용법에 관한 수업을 원한다는 것을 이해함 |
| 도구 | 에이전트가 사용할 수 있는 함수, API, 파일, 브라우저, 또는 서비스 | 저장소를 검색하거나 수업 내용을 가져옴 |
| 지식 | 답변 기반이 되는 문서나 데이터 | 강의 README 파일과 수업 자료 |
| 컨텍스트 | 다음 모델 호출에 포함되는 정보 | 사용자의 목표와 도구 결과 |
| 메모리 | 나중에 사용하기 위해 저장된 정보 | 학습자가 실습 위주의 Python 예제를 선호함 |
| 계획 | 큰 목표를 더 작은 단계로 나누기 | 수업을 찾고, 요약하며, 연습을 제안함 |
| 조율 | 도구, 단계, 혹은 에이전트 간 작업 분배 | 계획자가 검색 도구를 호출하고, 이어서 요약기를 호출함 |
| 신뢰 | 안전성, 보안, 평가, 관찰 가능성 | 도구 호출을 기록하고 고영향 작업 전에는 허락을 구함 |


## 모델과 공급자

이 강의 코드 샘플은 <strong>Microsoft Agent Framework (MAF)</strong>를 사용하며, 앞으로 권장되는 API인 <strong>Azure OpenAI Responses API</strong>를 대상으로 합니다. 이 API는 챗 완성, 도구 호출, 멀티모달 입력, 상태 기반 대화를 단일 API 표면에서 통합합니다. **Microsoft Foundry** 프로젝트(`FoundryChatClient`)를 통해 연결하거나 Azure OpenAI에 직접(`OpenAIChatClient`) 연결할 수 있습니다.

강의를 진행하면서 몇 가지 공급자 옵션이 있습니다:

- **Microsoft Foundry / Azure OpenAI (Responses API)** — 강의 전반에 걸쳐 사용되는 주요 경로입니다. 키가 필요 없는 Entra ID 인증을 위해 `az login`로 로그인하세요.
- **Foundry Local** — OpenAI 호환 API를 통해 온디바이스에서 모델을 완전히 실행합니다(클라우드 없음, API 키 없음). 오프라인 또는 비용 없이 실험하기에 이상적입니다. [코스 설정](./00-course-setup/README.md)을 참조하세요.
- **MiniMax** — 대규모 컨텍스트 모델을 제공하는 OpenAI 호환 공급자로, 대체용 드롭인으로 사용할 수 있습니다.

> **참고:** GitHub Models는 사용 중단 예정(2026년 7월 종료)이며 Responses API를 지원하지 않습니다. 샘플은 Azure OpenAI / Microsoft Foundry를 사용하도록 업데이트되었습니다.

## 초보자 친화적 용어로 정리한 핵심 아이디어

### 도구

도구는 에이전트가 모델 바깥에서 작업을 수행하기 위해 호출할 수 있는 무언가입니다. 좋은 도구는
명확한 이름, 한정된 역할, 타입이 지정된 입력, 예측 가능한 출력, 그리고 실패해도 안전한 방식을 갖추고 있습니다.


코스 헬퍼 데모에서는 도구가 다음과 같을 수 있습니다:

- `search_lessons(query)`
- `read_lesson(path)`
- `create_practice_task(topic)`

### RAG와 지식

RAG는 에이전트가 추측하는 대신 출처 자료에서 답변할 수 있게 도와줍니다. 이
과정에서 그 출처 자료는 수업 README, 코드 샘플, 또는 수업에서 연결된 외부
리소스가 될 수 있습니다.

답변이 문서, 데이터 또는 현재 프로젝트 파일에 근거해야 할 때 RAG를 사용하세요.
