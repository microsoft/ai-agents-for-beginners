# ⚡ Párhuzamos ügynök munkafolyamatok az Azure OpenAI-val (Responses API) (.NET)

## 📋 Nagyteljesítményű párhuzamos feldolgozás oktatóanyag

Ez a jegyzetfüzet bemutatja a **párhuzamos munkafolyamat mintákat** a Microsoft Agent Framework .NET-hez és az Azure OpenAI-hoz (Responses API). Megtanulod, hogyan építs fel magas teljesítményű, párhuzamos feldolgozási munkafolyamatokat, amelyek maximális áteresztőképességet érnek el azáltal, hogy egyszerre több MI ügynököt futtatsz, miközben megőrzik az együttműködést és az adatkonzisztenciát.

## 💻 Kód futtatása

A teljes megvalósítás megtalálható a `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs` fájlban. Ez a fájl egy **Fan-Out/Fan-In párhuzamos munkafolyamatot** mutat be az utazástervezéshez:

### 🏗️ **Munkafolyamat architektúra**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Fő összetevők:**

1. **ConcurrentStartExecutor**: Egyszerre sugározza a felhasználói kérést az összes ügynöknek
2. **Researcher Agent**: Párhuzamosan elemzi az úticélokat és látványosságokat
3. **Planner Agent**: Párhuzamosan készít részletes utazási terveket
4. **ConcurrentAggregationExecutor**: Összegyűjti és egyesíti mindkét ügynök eredményeit

### 🎯 **Fan-Out/Fan-In minta**

Ez a munkafolyamat bemutatja a klasszikus **Fan-Out/Fan-In** mintát:
- **Fan-Out**: Egy bemeneti üzenet egyszerre sugározódik több ügynöknek
- **Párhuzamos feldolgozás**: Több ügynök dolgozik párhuzamosan ugyanazon a feladaton
- **Fan-In**: Az összes ügynök eredménye összegyűjtésre és egyesítésre kerül egyetlen kimenetté

### 🔍 Egyedi végrehajtók megértése

**ConcurrentStartExecutor:**
- Megvalósítja az `IMessageHandler<string>` felületet string bemenet fogadására
- Üzenetek sugárzása az összes kapcsolódott ügynöknek
- Küld egy `TurnToken`-t a párhuzamos feldolgozás elindításához

**ConcurrentAggregationExecutor:**
- Megvalósítja az `IMessageHandler<ChatMessage>` felületet az ügynök válaszok fogadására
- Szálbiztos módon gyűjti az üzeneteket
- Összesít, amikor megérkeznek az összes várt válaszok
- A végső kimenetet a `context.YieldOutputAsync()` segítségével adja vissza

### ⚡ Teljesítmény előnyök

**Párhuzamos vs soros:**
- Soros: Agent1 (30 mp) → Agent2 (30 mp) = **összesen 60 másodperc**
- Párhuzamos: Agent1 (30 mp) || Agent2 (30 mp) = **összesen 30 másodperc**

**Áteresztőképesség javulás**: N× gyorsabb akár N párhuzamos ügynök esetén (a munkaterheléstől és erőforrásoktól függően)
