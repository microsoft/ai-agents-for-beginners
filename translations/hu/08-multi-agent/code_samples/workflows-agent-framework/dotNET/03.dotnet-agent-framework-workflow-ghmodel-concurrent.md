# ⚡ Párhuzamos ügynök munkafolyamatok az Azure OpenAI (Responses API) használatával (.NET)

## 📋 Nagy teljesítményű párhuzamos feldolgozás bemutató

Ez a jegyzetfüzet bemutatja a **párhuzamos munkafolyamat mintákat** a Microsoft Agent Framework .NET-hez és az Azure OpenAI (Responses API) segítségével. Megtanulod, hogyan építs magas teljesítményű, párhuzamos feldolgozó munkafolyamatokat, amelyek maximalizálják az áteresztőképességet több AI ügynök egyidejű futtatásával, miközben fenntartják az koordinációt és az adatok konzisztenciáját.

## 🎯 Tanulási célok

### 🚀 **Párhuzamos feldolgozás alapjai**
- **Párhuzamos ügynök futtatás**: Több AI ügynök egyidejű futtatása a maximális teljesítményért

- **Azure OpenAI (Responses API)**: Több párhuzamos hívás koordinálása az Azure OpenAI Responses API-hoz

## 💻 A kód futtatása

A teljes megvalósítás megtalálható a `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs` fájlban. Ez a fájl egy **Fan-Out/Fan-In párhuzamos munkafolyamatot** mutat be az utazástervezéshez:

### 🏗️ **Munkafolyamat architektúra**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Kulcs komponensek:**

1. **ConcurrentStartExecutor**: Egyidejűleg sugározza a felhasználói kérést az összes ügynöknek
2. **Researcher Agent**: Párhuzamosan elemzi az úti célokat és látnivalókat
3. **Planner Agent**: Párhuzamosan készíti el a részletes utazási terveket
4. **ConcurrentAggregationExecutor**: Összegyűjti és egyesíti mindkét ügynök eredményeit

### 🎯 **Fan-Out/Fan-In minta**

Ez a munkafolyamat a klasszikus **Fan-Out/Fan-In** mintát demonstrálja:
- **Fan-Out**: Egy bemenő üzenet egyszerre több ügynöknek továbbítva
- **Párhuzamos feldolgozás**: Több ügynök párhuzamosan dolgozik ugyanazon a feladaton
- **Fan-In**: Az összes ügynöktől származó eredmény összegyűjtve és egyesítve egyetlen kimenetté

### 🔍 Egyéni végrehajtók megértése

**ConcurrentStartExecutor:**
- Implementálja az `IMessageHandler<string>`-et szöveges bemenet fogadására
- Üzenetek sugárzása az összes csatlakoztatott ügynöknek
- `TurnToken` küldése a párhuzamos feldolgozás elindításához

**ConcurrentAggregationExecutor:**
- Implementálja az `IMessageHandler<ChatMessage>`-t az ügynök válaszok fogadására
- Szálbiztos módon gyűjti az üzeneteket
- Összegzi, amikor megérkeznek az összes várt válaszok
- A végső kimenetet a `context.YieldOutputAsync()`-val adja vissza

### ⚡ Teljesítmény előnyök

**Párhuzamos vs Soros:** 

- Szekvenciális: Agent1 (30 mp) → Agent2 (30 mp) = **összesen 60 másodperc**
- Egyidejű: Agent1 (30 mp) || Agent2 (30 mp) = **összesen 30 másodperc**

**Átbocsátás javítása**: Akár N× gyorsabb N egyidejű ügynök esetén (munkaterheléstől és erőforrásoktól függően)
