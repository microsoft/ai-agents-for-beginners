# ⚡ Azure OpenAI (Responses API) کے ساتھ متوازی ایجنٹ ورک فلو (.NET)

## 📋 ہائی پرفارمنس متوازی پراسیسنگ ٹیوٹوریل

یہ نوٹ بک Microsoft Agent Framework for .NET اور Azure OpenAI (Responses API) کا استعمال کرتے ہوئے **متوازی ورک فلو پیٹرنز** کی مثال دیتی ہے۔ آپ سیکھیں گے کہ کیسے اعلیٰ کارکردگی، متوازی پراسیسنگ ورک فلو تیار کیے جائیں جو متعدد AI ایجنٹس کو بیک وقت چلا کر تھروپٹ کو زیادہ سے زیادہ کرتے ہیں جبکہ ہم آہنگی اور ڈیٹا کی مطابقت کو برقرار رکھتے ہیں۔

## 🎯 سیکھنے کے مقاصد

### 🚀 **متوازی پراسیسنگ کے بنیادی اصول**
- **متوازی ایجنٹ ایکزیکیوشن**: زیادہ سے زیادہ کارکردگی کے لیے متعدد AI ایجنٹس کو بیک وقت چلائیں
- **Async/Await پیٹرنز**: موثر متوازی کاری کے لیے .NET کی غیرہم وقتی پروگرامنگ ماڈل کا استعمال کریں
- **Azure OpenAI (Responses API)**: Azure OpenAI Responses API کو متوازی کالز کے ذریعے مربوط کریں
- **وسائل کا انتظام**: متوازی آپریشنز کے دوران AI ماڈل وسائل کو مؤثر طریقے سے مینیج کریں

### 🏗️ **جدید متوازی فن تعمیر**
- **ٹاسک پر مبنی متوازی کاری**: بہترین متوازی عمل درآمد کے لیے .NET ٹاسک پیریلل لائبریری استعمال کریں
- **ہم آہنگی کے پیٹرنز**: مقابلہ کی حالتوں سے بچتے ہوئے متوازی ایجنٹس کا ہم آہنگی کریں
- **لوڈ بیلنسنگ**: دستیاب متوازی پراسیسنگ صلاحیت کے مطابق کام کو مؤثر طریقے سے تقسیم کریں
- **فالٹ ٹولرنس**: پورے ورک فلو کو روکے بغیر انفرادی ایجنٹ کی ناکامیوں کو سنبھالیں

### 🏢 **انٹرپرائز متوازی ایپلیکیشنز**
- **ہائی والیوم ڈاکیومنٹ پراسیسنگ**: متعدد دستاویزات کو بیک وقت پراسیس کریں
- **حقیقی وقت میں مواد کا تجزیہ**: آنے والے ڈیٹا سٹریمز کا متوازی تجزیہ
- **بیچ پراسیسنگ کی اصلاح**: بڑے پیمانے پر ڈیٹا پراسیسنگ آپریشنز کے لیے تھروپٹ کو زیادہ سے زیادہ کریں
- **کثیرالشکل تجزیہ**: مختلف قسم کے مواد اور فارمیٹس کی متوازی پراسیسنگ

## 💻 کوڈ چلانا

مکمل عمل در آمد `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs` فائل میں دستیاب ہے۔ یہ فائل سفر کی منصوبہ بندی کے لیے **فین-آؤٹ/فین-ان متوازی ورک فلو** کی مثال دیتی ہے:

### 🏗️ **ورک فلو فن تعمیر**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**اہم اجزاء:**

1. **ConcurrentStartExecutor**: صارف کی درخواست کو ایک ساتھ تمام ایجنٹس کو نشر کرتا ہے
2. **Researcher Agent**: منزلوں اور سیاحتی مقامات کا متوازی تجزیہ کرتا ہے
3. **Planner Agent**: تفصیلی سفر کے منصوبے متوازی طور پر تیار کرتا ہے
4. **ConcurrentAggregationExecutor**: دونوں ایجنٹس سے حاصل شدہ نتائج کو جمع اور ضم کرتا ہے

### 🎯 **فین-آؤٹ/فین-ان پیٹرن**

یہ ورک فلو کلاسیکی **فین-آؤٹ/فین-ان** پیٹرن کو ظاہر کرتا ہے:
- **فین-آؤٹ**: ایک ان پٹ پیغام کو بیک وقت متعدد ایجنٹس کو نشر کیا جاتا ہے
- **متوازی پراسیسنگ**: متعدد ایجنٹس ایک ہی کام پر متوازی طور پر کام کرتے ہیں
- **فین-ان**: تمام ایجنٹس سے حاصل شدہ نتائج کو جمع کرکے ایک واحد آؤٹ پٹ میں تبدیل کیا جاتا ہے

### 🔍 حسب ضرورت ایگزیکیوٹرز کی تفہیم

**ConcurrentStartExecutor:**
- `IMessageHandler<string>` کو نافذ کرتا ہے تاکہ سٹرنگ ان پٹ قبول کرے
- تمام جڑے ہوئے ایجنٹس کو پیغامات نشر کرتا ہے
- متوازی پراسیسنگ کو شروع کرنے کے لیے `TurnToken` بھیجتا ہے

**ConcurrentAggregationExecutor:**
- `IMessageHandler<ChatMessage>` کو نافذ کرتا ہے تاکہ ایجنٹ کے جوابات وصول کرے
- دھاگہ محفوظ طریقے سے پیغامات جمع کرتا ہے
- جب تمام متوقع جوابات آ جائیں تو اجتماع کرتا ہے
- `context.YieldOutputAsync()` کا استعمال کرتے ہوئے آخری نتیجہ دیتا ہے

### ⚡ کارکردگی کے فوائد

**متوازی بمقابلہ تسلسل:**
- تسلسل: ایجنٹ1 (30 سیکنڈ) → ایجنٹ2 (30 سیکنڈ) = **کل 60 سیکنڈ**
- متوازی: ایجنٹ1 (30 سیکنڈ) || ایجنٹ2 (30 سیکنڈ) = **کل 30 سیکنڈ**

**تھروپٹ میں بہتری**: N متوازی ایجنٹس کے لیے N× تک تیز (کام کے بوجھ اور وسائل پر منحصر)
