# ⚡ Azure OpenAI (Responses API) کے ساتھ متوازی ایجنٹ ورک فلو (ڈاٹ نیٹ)

## 📋 اعلیٰ کارکردگی متوازی پروسیسنگ ٹیوٹوریل

یہ نوٹ بُک Microsoft Agent Framework برائے .NET اور Azure OpenAI (Responses API) استعمال کرتے ہوئے **متوازی ورک فلو پیٹرنز** کی مثال پیش کرتا ہے۔ آپ سیکھیں گے کہ کیسے اعلیٰ کارکردگی والے، متوازی پروسیسنگ ورک فلو تعمیر کیے جائیں جو متعدد AI ایجنٹس کو بیک وقت چلانے کے ذریعے زیادہ سے زیادہ تھرو پُٹ حاصل کریں، ساتھ ہی کوآرڈینیشن اور ڈیٹا کی مطابقت کو بھی برقرار رکھیں۔

## 🎯 تعلیمی مقاصد

### 🚀 **متوازی پروسیسنگ کے اصول**
- **متوازی ایجنٹ اجرا**: زیادہ سے زیادہ کارکردگی کے لیے متعدد AI ایجنٹس کو بیک وقت چلائیں
- **Async/Await پیٹرنز**: مؤثر متوازی کاری کے لیے .NET کے اسینک پروگرامنگ ماڈل کا استعمال کریں
- **Azure OpenAI (Responses API)**: Azure OpenAI Responses API کو متعدد متوازی کالز کے لیے ہم آہنگ کریں
- **وسائل کا انتظام**: متوازی آپریشنز کے دوران AI ماڈل کے وسائل کو مؤثر طریقے سے سنبھالیں

### 🏗️ **جدید متوازی فن تعمیر**
- **ٹاسک پر مبنی متوازی کاری**: مثالی متوازی اجرا کے لیے .NET Task Parallel Library کا استعمال کریں
- **ہم آہنگی کے پیٹرنز**: متوازی ایجنٹس کو ہم آہنگ کریں اور ریس کنڈیشنز سے بچیں
- **لوڈ بیلنسنگ**: دستیاب متوازی پروسیسنگ صلاحیت میں مؤثر طریقے سے کام تقسیم کریں
- **خرابی برداشت کرنا**: ہر ایجنٹ کی فیلیر کو پورے ورک فلو کو روکے بغیر سنبھالیں

### 🏢 **انٹرپرائز متوازی ایپلیکیشنز**
- **بلند حجم دستاویزات کی پروسیسنگ**: متعدد دستاویزات کو ایک ساتھ پروسیس کریں
- **ریئل ٹائم مواد کا تجزیہ**: آنے والے ڈیٹا سٹریمز کا متوازی تجزیہ
- **بیچ پروسیسنگ کی اصلاح**: بڑے پیمانے پر ڈیٹا پروسیسنگ آپریشنز کے لیے تھرو پُٹ زیادہ سے زیادہ کریں
- **کئی طریقے کا تجزیہ**: مختلف مواد کی اقسام اور فارمیٹس کی متوازی پروسیسنگ

## 💻 کوڈ چلانا

مکمل امپلیمینٹیشن `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs` میں دستیاب ہے۔ یہ فائل سفر کی منصوبہ بندی کے لیے **فین آؤٹ/فین اِن متوازی ورک فلو** کی مثال دیتی ہے:

### 🏗️ **ورک فلو فن تعمیر**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**اہم جزوات:**

1. **ConcurrentStartExecutor**: صارف کی درخواست کو ایک ساتھ تمام ایجنٹس کو نشر کرتا ہے
2. **Researcher Agent**: مقامات اور سیاحتی جگہوں کا متوازی تجزیہ کرتا ہے
3. **Planner Agent**: تفصیلی سفر کی منصوبہ بندی متوازی طور پر تیار کرتا ہے
4. **ConcurrentAggregationExecutor**: دونوں ایجنٹس کے نتائج کو جمع اور یکجا کرتا ہے

### 🎯 **فین آؤٹ/فین اِن پیٹرن**

یہ ورک فلو کلاسیکی **فین آؤٹ/فین اِن** پیٹرن کی مثال ہے:
- **فین آؤٹ**: ایک ان پٹ پیغام بیک وقت متعدد ایجنٹس کو نشر کیا جاتا ہے
- **متوازی پروسیسنگ**: متعدد ایجنٹس ایک ہی کام پر متوازی طور پر کام کرتے ہیں
- **فین اِن**: تمام ایجنٹس کے نتائج جمع کر کے ایک واحد آؤٹ پٹ تیار کیا جاتا ہے

یہ متوازی پیٹرن مثالی ہے:

- **کوڈ کا جائزہ**: متعدد جائزہ کار مختلف زاویوں سے کوڈ کا تجزیہ کر رہے ہوں

- **دستاویزات کی پروسیسنگ**: متوازی اخذ، تجزیہ، اور تصدیق
- **کثیر نقطہ نظر تجزیہ**: ایک ہی ان پٹ پر مختلف آراء حاصل کرنا

### 🔍 کسٹم ایکزیکیوٹرز کو سمجھنا

**ConcurrentStartExecutor:**
- `IMessageHandler<string>` کو نافذ کرتا ہے تاکہ سٹرنگ ان پٹ قبول کرے
- تمام جڑے ہوئے ایجنٹس کو پیغامات نشر کرتا ہے
- متوازی پروسیسنگ شروع کرنے کے لیے `TurnToken` بھیجتا ہے

**ConcurrentAggregationExecutor:**
- `IMessageHandler<ChatMessage>` کو نافذ کرتا ہے تاکہ ایجنٹ کے جوابات وصول کرے
- تھریڈ-سیف انداز میں پیغامات جمع کرتا ہے
- جب تمام متوقع جوابات آ جائیں تو نتائج کا اجتماع کرتا ہے
- `context.YieldOutputAsync()` کے ذریعے حتمی آؤٹ پٹ دیتا ہے

### ⚡ کارکردگی کے فوائد

**متوازی بمقابلہ سلسلہ وار:**
- سلسلہ وار: ایجنٹ1 (30سیکنڈ) → ایجنٹ2 (30سیکنڈ) = **کل 60 سیکنڈ**
- متوازی: ایجنٹ1 (30سیکنڈ) || ایجنٹ2 (30سیکنڈ) = **کل 30 سیکنڈ**

**تھرو پُٹ میں بہتری**: N متوازی ایجنٹس کے لیے N× تیز تر (کام کے بوجھ اور وسائل کے مطابق)
