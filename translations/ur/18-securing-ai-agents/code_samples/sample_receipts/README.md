# نمونہ رسید کے فکسچر

تین پیشگی تیار شدہ رسید فائلیں بغیر نوٹ بُک چلائے جانچ کے لیے۔

| فائل | یہ کیا ہے |
|---|---|
| `01_valid_receipt.json` | ایک درست دستخط شدہ رسید `lookup_flights` ٹول کال کے لیے۔ تصدیق درست (True) واپس کرتی ہے۔ |
| `02_tampered_receipt.json` | وہی رسید جس کے ایک فیلڈ کو دستخط کے بعد تبدیل کیا گیا ہو۔ تصدیق غلط (False) واپس کرتی ہے۔ |
| `03_chain_three_receipts.json` | تین درست رسیدوں کی زنجیر (تلاش، ہولڈ، بک) جس میں `previous_receipt_hash` ہر ایک کو پہلے سے منسلک کرتا ہے۔ |

فکسچر پے لوڈ کے canonical JCS بائٹس کو براہِ راست Ed25519 سے دستخط کرتے ہیں۔
SHA-256 مواد کے ہضم اور رسید-زنجیر روابط کے لیے استعمال ہوتا ہے، لیکن دستخط سے پہلے اضافی pre-hash کے طور پر نہیں۔


## نمونوں کی تصدیق کرنا

نوٹ بُک تصدیق کو چار حصوں میں سمجھاتا ہے۔ ان فکسچر کو براہِ راست نوٹ بُک کی وضاحت کے بغیر تصدیق کرنے کے لیے:


```python
import json
from pathlib import Path

# فرض کرتا ہے کہ آپ نے امپورٹس اور معاون افعال مکمل کر لیے ہیں
# سیکشن 1 اور 2 سے 18-signed-receipts.ipynb کے

valid = json.loads(Path("01_valid_receipt.json").read_text())
print(f"Valid receipt: {verify_receipt(valid)}")        # سچ

tampered = json.loads(Path("02_tampered_receipt.json").read_text())
print(f"Tampered receipt: {verify_receipt(tampered)}")  # غلط

chain = json.loads(Path("03_chain_three_receipts.json").read_text())
for r in verify_chain(chain):
    print(f"  Receipt {r['index']} ({r['tool']}): {'VALID' if r['overall_valid'] else 'INVALID'}")
```

## یہ کیسے تیار کیے گئے تھے

فکسچر نوٹ بُک کے کوڈ راستے کو استعمال کرتے ہیں، ایک مقررہ دستخطی کلید
اور مقررہ ٹائم اسٹیمپس کے ساتھ تاکہ بائٹ کی دوبارہ پیداوار ہو سکے۔ دوبارہ تیار کرنے کے لیے:

```bash
python3 generate_fixtures.py
```

(اسکرپٹ اس ڈائریکٹری میں `generate_fixtures.py` پر ہے۔)

## طلبہ خام JSON معائنہ کر کے کیا سیکھتے ہیں

رسید کے خام فارمیٹ کو پڑھنا وہ فہم پیدا کرتا ہے جو نوٹ بُک کی خلیے ہمیشہ فراہم نہیں کرتے۔ وہ طلبہ جو JSON کو جھلک کر دیکھتے ہیں اکثر نوٹ کرتے ہیں:


1. دستخط ایک مبہم base64url سٹرنگ ہے، لیکن ہر دوسرے فیلڈ میں سیدھی
   پڑھائی جانے والی JSON ہوتی ہے۔ دستخط مواد کو خفیہ نہیں کرتا؛ بلکہ اس کی تصدیق کرتا ہے۔
2. `public_key` رسید میں شامل ہے۔ ایک آڈیٹر کو تصدیق کے لیے کسی اور چیز کی ضرورت نہیں،
   شرط یہ ہے کہ کلید واقعی دعویٰ شدہ جاری کنندہ کی ہو؛ شناختی انفراسٹرکچر پر سبق کا README دیکھیں۔
3. کسی بھی فیلڈ کے ایک کردار کو تبدیل کرنا، پھر اس فائل کو
   `02_tampered_receipt.json` سے دوبارہ موازنہ کرنا، بائٹ سطح کے طریقہ کار کو واضح کرتا ہے۔
