# نمونہ رسید کے فکسچر

تین پہلے سے تیار شدہ رسید کی فائلیں بغیر نوٹ بک چلائے معائنہ کے لیے۔

| فائل | یہ کیا ہے |
|---|---|
| `01_valid_receipt.json` | `lookup_flights` ٹول کال کے لیے ایک جائز دستخط شدہ رسید۔ تصدیق True لوٹاتی ہے۔ |
| `02_tampered_receipt.json` | دستخط کے بعد ایک فیلڈ میں تبدیلی کے ساتھ وہی رسید۔ تصدیق False لوٹاتی ہے۔ |
| `03_chain_three_receipts.json` | تین جائز رسیدوں کی زنجیر (تلاش، ہولڈ، بک) جس میں `previous_receipt_hash` ہر ایک کو پچھلی سے مربوط کرتا ہے۔ |

فکسچر بائٹس کے کاننیکل JCS پیلوڈ کو براہ راست Ed25519 سے دستخط کرتے ہیں۔
SHA-256 مواد کے خلاصوں اور رسید زنجیر کے روابط کے لیے استعمال ہوتا رہتا ہے، دستخط سے پہلے اضافی pre-hash کے طور پر نہیں۔


## نمونوں کی تصدیق کرنا

نوٹ بک چار حصوں میں تصدیق کا عمل دکھاتی ہے۔ ان فکسچر کی تصدیق براہ راست بغیر نوٹ بک کھولے کرنے کے لیے:


```python
import json
from pathlib import Path

# فرض کریں کہ آپ نے درآمدات اور معاون افعال مکمل کر لیے ہیں
# سیکشن 1 اور 2 سے 18-signed-receipts.ipynb کا۔

valid = json.loads(Path("01_valid_receipt.json").read_text())
print(f"Valid receipt: {verify_receipt(valid)}")        # درست

tampered = json.loads(Path("02_tampered_receipt.json").read_text())
print(f"Tampered receipt: {verify_receipt(tampered)}")  # غلط

chain = json.loads(Path("03_chain_three_receipts.json").read_text())
for r in verify_chain(chain):
    print(f"  Receipt {r['index']} ({r['tool']}): {'VALID' if r['overall_valid'] else 'INVALID'}")
```

## یہ کیسے بنائے گئے تھے

فکسچر وہی کوڈ راستہ استعمال کرتے ہیں جو نوٹ بک، ایک مقررہ دستخطی کلید اور مقررہ وقتِ نشان کے ساتھ تاکہ بائٹ سطح پر دوبارہ پیداوار ممکن ہو۔ دوبارہ بنانے کے لیے:


```bash
python3 generate_fixtures.py
```

(اسکرپٹ اسی ڈائریکٹری میں `generate_fixtures.py` پر ہے۔)

## طلباء کیا سیکھتے ہیں جب وہ خام JSON کا معائنہ کرتے ہیں

خام رسید کے فارمیٹ کو پڑھنا اس بصیرت کو پیدا کرتا ہے جو نوٹ بک کے خلیے ہمیشہ فراہم نہیں کرتے۔ جو طلباء JSON کو جھلک کر دیکھتے ہیں اکثر نوٹ کرتے ہیں:


1. دستخط ایک مبہم base64url اسٹرنگ ہے، لیکن باقی تمام فیلڈز عام قابلِ فہم JSON ہیں۔ دستخط مواد کو خفیہ نہیں کرتا؛ بلکہ اس کی تصدیق کرتا ہے۔
2. `public_key` رسید میں شامل ہے۔ آڈیٹر کو تصدیق کے لیے کچھ اور نہیں چاہیے (شرط یہ ہے کہ کلید واقعی اس دعویٰ کنندہ کی ہے؛ شناختی ڈھانچے کے بارے میں سبق کی README دیکھیں)۔
3. کسی بھی فیلڈ کے ایک حرف میں تبدیلی کرنا، پھر اس فائل کی موازنہ `02_tampered_receipt.json` سے کرنا، بائٹ سطح کے طریقہ کار کو واضح کرتا ہے۔
