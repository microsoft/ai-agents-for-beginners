# மாதிரிப் பிரியல் கோப்புகள்

நோட்புக் இயக்காமல் ஆய்வு செய்ய முன்பே உருவாக்கப்பட்ட மூன்று பிரியல் கோப்புகள்.

| கோப்பு | அது என்ன |
|---|---|
| `01_valid_receipt.json` | ஒரு `lookup_flights` கருவி அழைப்பிற்கான சரியான கையெழுத்திடப்பட்ட ரசீது. சரிபார்ப்பு True ஐ 반환 செய்கிறது. |
| `02_tampered_receipt.json` | கையெழுத்திடுவதற்குப் பிறகு ஒரு களத்தில் மாற்றம் செய்யப்பட்ட அதே ரசீது. சரிபார்ப்பு False ஐ 반환 செய்கிறது. |
| `03_chain_three_receipts.json` | மூன்று செல்லுபடியாகும் ரசீது (தேடு, பொறுப்பு, புத்தகம்) ஒன்றின் பின்னையே அடுத்ததை இணைக்கும் `previous_receipt_hash` கொண்டு ஒரு தொடர். |

பிக்சர்களானவை வெள்ளிப்புள்ளிகளின் canonical JCS பைட்டுகளுடன் நேரடியாக Ed25519 மூலம் கையொப்பமிடுகின்றன.
SHA-256 உள்ளடக்க டைஜஸ்ட்களுக்கும் ரசிப்பு-சேனைக் காட்சிகளுக்கும் பயன்படுத்தப்படுகிறது, கையொப்பமிடுவதற்கு முன்னர் கூடுதல் முன்-ஹாஷ் ஆக அல்ல.


## மாதிரிகள் சரிபார்த்தல்

`18-signed-receipts.ipynb` இல், முதலில் Setup மற்றும் பிரிவுகள் 1 முதல் 3 வரை இயக்கவும்.
பிரிவு 3 `verify_chain` ஐ வரையறுக்கிறது; பிரிவுகள் 1 மற்றும் 2 மட்டும் போதுமானதல்ல.
பின்னர் பின்வரும் தொகுதியை புதிய செல்லில் இயக்கவும், நோட்புக் வேலைDirectory
`18-securing-ai-agents/code_samples`ஆக அமைக்கப்பட்டிருக்கும். கீழுள்ள ஃபிக்சர் பாதைகள் அந்த கோப்புறைத் தொடர்புடையவை.


```python
import json
from pathlib import Path

fixture_dir = Path("sample_receipts")

# This fixture key is pinned by the verifier, outside the receipt under test.
FIXTURE_ISSUER_PUBLIC_KEY = "11qYAYKxCrfVS_7TyWQHOg7hcvPapiMlrwIaaPcHURo"
fixture_trusted_public_keys = {FIXTURE_ISSUER_PUBLIC_KEY}

valid = json.loads((fixture_dir / "01_valid_receipt.json").read_text())
print(
    f"Valid receipt: {verify_receipt(valid, fixture_trusted_public_keys)}"
)  # True

tampered = json.loads((fixture_dir / "02_tampered_receipt.json").read_text())
print(
    f"Tampered receipt: {verify_receipt(tampered, fixture_trusted_public_keys)}"
)  # False

chain = json.loads((fixture_dir / "03_chain_three_receipts.json").read_text())
for r in verify_chain(chain, fixture_trusted_public_keys):
    print(f"  Receipt {r['index']} ({r['tool']}): {'VALID' if r['overall_valid'] else 'INVALID'}")
```

### ஜூபிடரைக் பயன்படுத்தாமல் எடுத்துக்காட்டைக் கண்காணித்தல்

ரெப்போசிடரி ரூட்டில் இருந்து, பாடدرسத்தின் சார்புகளை நிறுவி இயக்கவும்:

```bash
python -m pip install -r 18-securing-ai-agents/code_samples/requirements.txt
python -m unittest discover -s 18-securing-ai-agents/code_samples -p test_signed_receipts.py -v
```

இந்த சோதனைகள் நோட்ட்புக் இன் பைத்தான் எடுத்துக்காட்டுக்களையும் மேலே உள்ள சரியான README பகுதியையும் இயக்குகின்றன.
மேலும் அவை நிரூபிப்பவர்கள் மூலம் மாற்றம் செய்யப்பட்டவை மற்றும் பின்வைக்கப்படாத விசைகளை நிராகரிக்கப்படுகிறதா என்பதை பரிசோதிக்கின்றன.
இந்த சோதனைகள் நோட்ட்புக்கின் `%pip` அமைப்பு செல்ஐ தவிர்க்கின்றன ஏனெனில் சார்புகளைக் தனிப்படியாக நிறுவப்படுகின்றன.
அவை நோட்ட்புக் அல்லது ஃபிக்ஸ்சர்களை மாற்றவில்லை.

## மாணவர்கள் க خام JSON ஐ பரிசோதித்தல் மூலம் என்ன கற்கிறார்கள்

خام ரசீது வடிவத்தை வாசிப்பது குறிப்பேடு செல்கள் எப்போதும் வழங்காத
கருத்துக்களை உருவாக்குகிறது. JSON ஐ தாளமாய்ப் பார்ப்பவர்கள் பொதுவாக கவனிப்பார்கள்:

1. கையொப்பம் ஒரு மறைக்கப்பட்ட base64url சரம், ஆனால் மற்ற எல்லா புலங்களும் தெளிவான
   வாசிக்கக்கூடிய JSON ஆகும். கையொப்பம் உள்ளடக்கத்தை மறைக்கவில்லை; அது அதற்கு சான்றளிக்கிறது.
2. `public_key` ரசீதத்தில் உட்படப்பட்டுள்ளதால்,
   தன்னம்பிக்கை சரிபார்க்கும் போதுமானது, ஆனால் வெளியீட்டாளரின் நம்பிக்கை அல்ல. ஒரு கண்காணிப்பாளர்
   அதை ரசீதின் வெளியில் பிணைக்கப்பட்ட விசையுடன் அல்லது நம்பகமான பதிவு மூலம் தீர்மானிக்கப்பட்ட விசையுடன் ஒப்பிட வேண்டும்.
3. எந்த ஒரு புலத்தின் ஒரு எழுத்தையும் மாற்றி, பின்னர் இந்த கோப்பை
   `02_tampered_receipt.json` உடன் மீண்டும் ஒப்பிட்டல், பைத்திய நிலை இயந்திரத்தை தெளிவாக காட்டுகிறது.
