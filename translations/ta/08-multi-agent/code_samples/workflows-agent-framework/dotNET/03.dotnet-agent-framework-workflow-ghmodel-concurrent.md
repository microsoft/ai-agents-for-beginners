# ⚡ Azure OpenAI (Responses API) உடன் ஒரே நேரத்தில் ஏஜென்ட் வேலைபட்டறைகள் (.NET)

## 📋 உயர் செயல்திறன் ஒரே நேரம் பணிபுரிதல் பயிற்சி

இந்த நோட்புக் .NET மற்றும் Azure OpenAI (Responses API) இற்கான Microsoft Agent Framework பயன்படுத்தி **ஒரே நேரம் பணிபுரிதல் குறிப்பு ஒழுங்குக்கட்டமைப்புகளை** காட்டுகிறது. ஒரே நேரத்தில் பல AI ஏஜென்ட்களை இயக்கி ஒருங்கிணைப்பு மற்றும் தரவு சீரமைவு நிர்ணயிக்கும் போது அதிகபட்ச வாயுமாற்றத்தை பெறுவதற்கான உயர் செயல்திறன், ஒரே நேரம் பணிபுரிதல் வேலைபட்டறைகள் கட்டமைப்பதை நீங்கள் கற்றுக்கொள்ளப்போகிறீர்கள்.

## 🎯 கற்கை நோக்கங்கள்

- **பண்பிரித்து ஏஜென்ட் செயலாக்கம்**: அதிகபட்ச செயல்திறனுக்காக பல AI ஏஜென்ட்களை ஒரே நேரத்தில் இயக்குக
- **Async/Await கொள்கைகள்**: .NET இன் async நிரலாக்க மாடலை திறம்பட பயன்படுத்தி ஒரே நேரம் செயல்படுத்துக
- **Azure OpenAI (Responses API)**: Azure OpenAI Responses APIக்கு பல இணையான அழைப்புகளை ஒருங்கிணைப்பு செய்தல்
- **வள மேலாண்மை**: ஒரே நேரடி இயக்கங்களில் AI மாதிரி வளங்களை திறம்பட நிர்வகிப்பது

### 🏗️ **மேம்பட்ட ஒரே நேரம் பணிபுரிதல் கட்டமைப்பு**

- **தோல்வி சகிப்புத்தன்மை**: ஒட்டுமொத்த வேலைசெயலில் நிறுத்தமின்றி தனிப்பட்ட ஏஜென்ட் தோல்விகளை கையாள்தல்

### 🏢 **சாதாரண ஒரே நேரம் பயன்பாடுகள்**

## 💻 குறியீட்டை இயக்குவது

முழு அமல்பாடு `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs` இல் கிடைக்கிறது. இந்த கோப்பு பயணத் திட்டமிடலுக்கான **Fan-Out/Fan-In ஒரே நேரல் வேலைபட்டறை** காட்டுகிறது:

### 🏗️ **வேலைபட்டறை கட்டமைப்பு**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**முக்கிய கூறுகள்:**

1. **ConcurrentStartExecutor**: பயனர் கோரிக்கையை எல்லா ஏஜென்ட்களுக்கும் ஒரே நேரத்தில் பிரசாரம் செய்கிறது
2. **Researcher Agent**: இடங்கள் மற்றும் ஈர்ப்புகளைக் கருத்து கொண்டு ஒரே நேரம் பகுப்பாய்வு செய்கிறது
3. **Planner Agent**: விரிவான பயணத் திட்டங்களை ஒரே நேரம் உருவாக்குகிறது
4. **ConcurrentAggregationExecutor**: இரு ஏஜென்ட்களின் முடிவுகளை சேகரித்து இணைக்கிறது

### 🎯 **Fan-Out/Fan-In வடிவமைப்பு**

இந்த வேலைபட்டறை பாரம்பரிய **Fan-Out/Fan-In** வடிவமைப்பை வெளிப்படுத்துகிறது:
- **Fan-Out**: ஒரு உள்ளீட்டு செய்தி ஒரே நேரத்தில் பல ஏஜென்ட்களுக்கு பிரசாரம் செய்யப்படுகிறது
- **ஒரே நேரம் செயலாக்கம்**: பல ஏஜென்ட் ஒரே பணி மீது இணைந்து பணிபுரிகிறார்கள்
- **Fan-In**: அனைத்து ஏஜென்ட் முடிவுகளும் சேகரிக்கப்பட்டு ஒன்றன் படியாக வெளிப்படுத்தப்படுகின்றன

   - திட்டமிடும் ஏஜென்ட் பயண அட்டவணை மற்றும் லாஜிஸ்டிக்ஸ் உருவாக்குகிறது
3. **தொகுப்பு**: இரு பதில்களையும் விரிவான வெளியீட்டாக இணைக்கிறது
4. **முடிவுகளை காட்டு**: அனைத்து தகவல்களுடன் இணைந்த பயணத் திட்டத்தைக் காட்டும்

### 🔧 தனிப்பயன் அமைப்புகள்

### 🎯 உண்மையான உலக பயன்பாடுகள்

இந்த ஒரே நேர முறை:
- **உள்ளடக்கம் உருவாக்கல்**: பல எழுத்தாளர்கள் ஒரே நேரத்தில் வெவ்வேறு பகுதிகளை உருவாக்குதல்
- **குறியீடு மதிப்பாய்வு**: பல மதிப்பாய்வாளர்கள் வெவ்வேறு பார்வைகளில் குறியீட்டை பகுப்பாய்வு செய்தல்
- **சந்தை ஆராய்ச்சி**: பல சந்தைப் பகுதிகளை ஒரே நேரம் பகுப்பாய்வு செய்தல்
- **ஆவணம் செயலாக்கம்**: ஒரே நேரம் எடுக்கல், பகுப்பாய்வு மற்றும் சரிபார்ப்பு
- **பல பார்வை பகுப்பாய்வு**: ஒரே உள்ளீட்டில் வேறுபட்ட பார்வைகளைப் பெறுதல்

### 🔍 தனிப்பயன் நிறைவேற்றிகளைக் கற்றுக்கொள்ளுதல்

**ConcurrentStartExecutor:**
- `IMessageHandler<string>` ஐ செயல்படுத்தி தொடர் உரையை ஏற்றுக்கொள்கிறது
- இணைக்கப்பட்ட அனைத்து ஏஜென்ட்களுக்கும் செய்திகளை பிரசாரம் செய்கிறது
- ஒரே நேர செயல்பாடு தொடங்க `TurnToken` ஐ அனுப்புகிறது

**ConcurrentAggregationExecutor:**
- `IMessageHandler<ChatMessage>` ஐ செயல்படுத்தி ஏஜென்ட் பதில்களை பெறுகிறது
- செய்திகளை சரியான முறையில் சேகரிக்கிறது
- எல்லா எதிர்பார்க்கப்பட்ட பதில்களும் வந்தவுடன் ஒன்றிணைக்கிறது
- `context.YieldOutputAsync()` மூலம் இறுதியான வெளியீட்டை வழங்குகிறது

### ⚡ செயல்திறன் நன்மைகள்

**ஒரே நேரம் vs தொடர்ச்சி:**
- தொடர்ச்சி: Agent1 (30s) → Agent2 (30s) = **மொத்தம் 60 விநாடிகள்**
- ஒரே நேரம்: Agent1 (30s) || Agent2 (30s) = **மொத்தம் 30 விநாடிகள்**

**வாயுமாற்ற மேம்பாடு**: N ஒரே நேர ஏஜென்ட்களுக்கு N மடங்கு வேகமானது (பணிச்சுமை மற்றும் வளங்கள் பொறுத்தது)

### 🛡️ பிழை கையாள்தல்

வேலைபட்டறை தனிப்பட்ட ஏஜென்ட் தோல்விகளை மென்மையாக கையாள்கிறது:
- ஒரு ஏஜென்ட் தோல்வியடித்தால் மற்றவை செயல்பட தொடர்கின்றன
- தொகுப்பாளர் நேரவரிசை (timeout) முறை செய்தல்
- தேவையானால் பாகத்திருப்ப முடிவுகளை வழங்கலாம்
