## 📋 Tutorial de Processamento Paralelo de Alto Desempenho

## 💻 Executando o Código

A implementação completa está disponível em `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Este arquivo demonstra um **workflow concorrente Fan-Out/Fan-In** para planejamento de viagens:

### 🏗️ **Arquitetura do Fluxo de Trabalho**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Componentes-Chave:**

1. **ConcurrentStartExecutor**: Transmite a requisição do usuário para todos os agentes simultaneamente
2. **Agente Pesquisador**: Analisa destinos e atrações concorrentemente
3. **Agente Planejador**: Cria planos de viagem detalhados paralelamente
4. **ConcurrentAggregationExecutor**: Coleta e mescla resultados dos dois agentes

### 🎯 **Padrão Fan-Out/Fan-In**

Este fluxo demonstra o clássico padrão **Fan-Out/Fan-In**:
- **Fan-Out**: Uma mensagem de entrada é transmitida para múltiplos agentes simultaneamente
- **Processamento Concorrente**: Múltiplos agentes trabalham em paralelo na mesma tarefa
- **Fan-In**: Resultados de todos os agentes são coletados e agregados em uma saída única

### 📝 Saída Esperada

O fluxo irá:
1. **Transmitir Requisição**: Enviar "Planeje uma viagem para Seattle em dezembro" para ambos os agentes
2. **Processamento Concorrente**: Ambos os agentes trabalham simultaneamente:
   - Pesquisador identifica atrações e detalhes
   - Planejador cria roteiros e logística
3. **Agregação**: Combinar ambas as respostas em uma saída abrangente
4. **Exibir Resultados**: Mostrar o plano de viagem unificado com todas as informações

### 🔍 Entendendo Executors Personalizados

**ConcurrentStartExecutor:**
- Implementa `IMessageHandler<string>` para aceitar entrada do tipo string
- Transmite mensagens para todos os agentes conectados
- Envia `TurnToken` para disparar processamento concorrente

**ConcurrentAggregationExecutor:**
- Implementa `IMessageHandler<ChatMessage>` para receber respostas dos agentes
- Coleta mensagens de forma thread-safe
- Agrega quando todas as respostas esperadas chegam
- Produz a saída final usando `context.YieldOutputAsync()`

### ⚡ Benefícios de Performance

**Concorrente vs Sequencial:**
- Sequencial: Agent1 (30s) → Agent2 (30s) = **60 segundos no total**
- Concorrente: Agent1 (30s) || Agent2 (30s) = **30 segundos no total**

**Melhoria no throughput**: Até N× mais rápido para N agentes concorrentes (dependendo da carga e recursos)

### 🛡️ Tratamento de Erros

O fluxo trata falhas individuais de agentes com suavidade:
- Se um agente falhar, os outros continuam processando
- O agregador pode implementar lógica de timeout
- Resultados parciais podem ser retornados se necessário

### 📊 Recursos Avançados

**Contagem Dinâmica de Agentes:**
Modifique a lógica de agregação para suportar contagem variável de agentes:

```csharp
private int _expectedAgentCount;
private readonly List<ChatMessage> _messages = [];

public override async ValueTask HandleAsync(List<ChatMessage> message, IWorkflowContext context, CancellationToken cancellationToken = default)
{
    this._messages.AddRange(message);
    if (this._messages.Count == _expectedAgentCount)
    {
        // Process aggregation
    }
}
```
