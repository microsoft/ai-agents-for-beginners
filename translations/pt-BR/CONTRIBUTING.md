# Contribuindo

Este projeto aceita contribuições e sugestões. A maioria das contribuições exige que você concorde com um Acordo de Licença de Contribuinte (CLA) declarando que você tem o direito e realmente concede a nós os direitos de usar sua contribuição. Para mais detalhes, visite <https://cla.opensource.microsoft.com>.

Quando você enviar um pull request, um bot CLA determinará automaticamente se você precisa fornecer um CLA e decorará o pull request conforme apropriado. Siga as instruções fornecidas pelo bot. Você precisará fazer isso apenas uma vez entre os repositórios que usam o CLA da Microsoft.

## Código de Conduta

Este projeto adotou o [Código de Conduta de Código Aberto da Microsoft](https://opensource.microsoft.com/codeofconduct/). Para mais informações, veja as [Perguntas Frequentes sobre o Código de Conduta](https://opensource.microsoft.com/codeofconduct/faq/) ou entre em contato com [opencode@microsoft.com](mailto:opencode@microsoft.com) para dúvidas ou comentários adicionais.

## Diretrizes para pull requests

- Mantenha cada pull request focado em uma única alteração lógica.
- Teste os notebooks e exemplos de código afetados antes de enviar.
- Atualize a documentação da lição relevante ao adicionar ou alterar um exemplo.
- Edite somente o conteúdo fonte em inglês. As traduções são mantidas pelo fluxo de trabalho automático de tradução.
- Não faça commit de credenciais, arquivos `.env`, arquivos temporários ou artefatos gerados para desenvolvimento.

## Escopo editorial e produtos de terceiros

Este currículo foca em tecnologias Microsoft e padrões abertos neutros a fornecedores. As contribuições devem servir a um propósito educacional claro e não devem ter como objetivo principal introduzir ou promover um produto comercial de terceiros, serviço hospedado, roteador modelo, SDK, servidor MCP ou outra oferta específica de fornecedor.

Software de código aberto e dependências de terceiros podem ser referenciados quando necessários para explicar um padrão aberto ou cenário de interoperabilidade, serem apresentados de forma neutra e não serem centrados em um produto ou ponto de extremidade hospedado de um fornecedor. Caso sua contribuição proponha incluir um produto ou serviço específico de fornecedor, abra um problema e obtenha aprovação dos mantenedores antes de enviar um pull request.

Contribuidores devem divulgar qualquer emprego, propriedade, patrocínio ou outra afiliação relevante com um produto ou serviço referenciado em sua contribuição. Não inclua reivindicações de preço, desempenho, segurança, privacidade ou comparativas sem suporte. Exemplos executáveis não devem transmitir dados dos aprendizes nem realizar ações públicas através de serviço externo de terceiros por padrão.
