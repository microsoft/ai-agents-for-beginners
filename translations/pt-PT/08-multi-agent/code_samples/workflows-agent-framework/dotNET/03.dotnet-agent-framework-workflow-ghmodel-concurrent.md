## 💻 Execução do Código

A implementação completa está disponível em `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Este ficheiro demonstra um **fluxo de trabalho concorrente Fan-Out/Fan-In** para planeamento de viagens:

### 🏗️ **Arquitetura do Fluxo de Trabalho**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Componentes Principais:**

1. **ConcurrentStartExecutor**: Transmite a solicitação do utilizador a todos os agentes simultaneamente
2. **Agente de Pesquisa**: Analisa destinos e atrações simultaneamente
3. **Agente Planeador**: Cria planos de viagem detalhados concorrentemente
4. **ConcurrentAggregationExecutor**: Recolhe e funde resultados de ambos os agentes

### 🎯 **Padrão Fan-Out/Fan-In**

Este fluxo de trabalho demonstra o clássico padrão **Fan-Out/Fan-In**:
- **Fan-Out**: Uma mensagem de entrada é transmitida a múltiplos agentes simultaneamente
- **Processamento Concorrente**: Múltiplos agentes trabalham em paralelo na mesma tarefa
- **Fan-In**: Resultados de todos os agentes são recolhidos e agregados numa única saída

### 🔍 Compreender Executors Personalizados

**ConcurrentStartExecutor:**
- Implementa `IMessageHandler<string>` para aceitar input em string
- Transmite mensagens a todos os agentes ligados
- Envia `TurnToken` para desencadear processamento concorrente

**ConcurrentAggregationExecutor:**
- Implementa `IMessageHandler<ChatMessage>` para receber respostas dos agentes
- Recolhe mensagens de forma thread-safe
- Agrega quando todas as respostas esperadas chegam
- Produz saída final com `context.YieldOutputAsync()`

### ⚡ Benefícios de Desempenho

**Concorrente vs Sequencial:**
- Sequencial: Agent1 (30s) → Agent2 (30s) = **60 segundos no total**
- Concorrente: Agent1 (30s) || Agent2 (30s) = **30 segundos no total**

**Melhoria de rendimento**: Até N× mais rápido para N agentes concorrentes (dependendo da carga e recursos)

### 🛡️ Gestão de Erros

O fluxo de trabalho lida com falhas individuais de agentes de forma graciosa:
- Se um agente falhar, os outros continuam a processar
- O agregador pode implementar lógica de timeout
- Resultados parciais podem ser devolvidos se necessário
