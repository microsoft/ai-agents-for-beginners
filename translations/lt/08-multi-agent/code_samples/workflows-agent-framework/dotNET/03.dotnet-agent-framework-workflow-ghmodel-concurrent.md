# ⚡ Kelių agentų darbo srautai su Azure OpenAI (Responses API) (.NET)

## 📋 Aukšto našumo lygiagretus apdorojimo vadovas

Ši užrašų knygutė demonstruoja **kelių darbo srautų modelius**, naudojant Microsoft Agent Framework .NET aplinkai ir Azure OpenAI (Responses API). Išmoksite kurti aukšto našumo, lygiagrečius darbo srautus, kurie maksimaliai padidina pralaidumą vykdydami kelis AI agentus vienu metu, išlaikant koordinaciją ir duomenų nuoseklumą.

## 🎯 Mokymosi tikslai

### 🚀 **Lygiagretaus apdorojimo pagrindai**
- **Kelių agentų vykdymas vienu metu**: Paleiskite kelis AI agentus vienu metu didžiausiam našumui
- **Async/Await modeliai**: Naudokite .NET asinchroninio programavimo modelį efektyviam lygiagretumui
- **Azure OpenAI (Responses API)**: Koordinuokite kelis vienu metu vykdomus kvietimus Azure OpenAI Responses API
- **Išteklių valdymas**: Efektyviai valdykite AI modelio išteklius lygiagrečiose operacijose

### 🏗️ **Išplėstinė lygiagrečios architektūros kūrimas**
- **Užduočiai pagrįstas lygiagretumas**: Naudokite .NET Task Parallel Library optimaliam lygiagretumui
- **Sinchronizacijos modeliai**: Koordinuokite lygiagrečius agentus vengdami lenktynių sąlygų
- **Darbo paskirstymas**: Efektyviai paskirstykite darbą esamai lygiagrečios apdorojimo talpai
- **Atsparumas gedimams**: Tvarkykite atskirus agentų gedimus nenutraukiant viso darbo srauto

### 🏢 **Įmonių lygiagretios programos**
- **Daug dokumentų apdorojimas vienu metu**: Apdorokite kelis dokumentus vienu metu
- **Realaus laiko turinio analizė**: Lygiagretus įeinančių duomenų srautų analizavimas
- **Partijų apdorojimo optimizavimas**: Maksimalus pralaidumas didelio masto duomenų operacijose
- **Daugiarūšių analizė**: Lygiagretus skirtingų turinio tipų ir formatų apdorojimas

## 💻 Kodo paleidimas

Pilnas įgyvendinimas yra faile `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Šis failas demonstruoja **Fan-Out/Fan-In lygiagretų darbo srautą** kelionių planavimui:

### 🏗️ **Darbo srauto architektūra**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Pagrindinės sudedamosios dalys:**

1. **ConcurrentStartExecutor**: Vienu metu transliuoja vartotojo užklausą visiems agentams
2. **Researcher Agent**: Lygiagrečiai analizuoja kelionių tikslus ir lankytinas vietas
3. **Planner Agent**: Lygiagrečiai kuria detalias kelionės schemas
4. **ConcurrentAggregationExecutor**: Surenka ir apjungia rezultatų du iš agentų

### 🎯 **Fan-Out/Fan-In Modelis**

Šis darbo srautas demonstruoja klasikinius **Fan-Out/Fan-In** principus:
- **Fan-Out**: Vienas įvesties pranešimas siunčiamas keliems agentams vienu metu
- **Lygiagretus apdorojimas**: Keli agentai lygiagrečiai atlieka tą pačią užduotį
- **Fan-In**: Visų agentų rezultatai surenkami ir apjungiami į vieną išvestį

### 🎯 Realiosios pasaulio taikymai

Šis lygiagretaus darbo srauto modelis idealiai tinka:
- **Turinio kūrimui**: Daug rašytojų vienu metu kuria skirtingas sekcijas
- **Kodo peržiūrai**: Keli recenzentai analizuoja kodą iš skirtingų perspektyvų
- **Rinkos tyrimams**: Lygiagretus skirtingų rinkos segmentų analizavimas
- **Dokumentų apdorojimui**: Lygiagretus duomenų išgavimas, analizė ir tikrinimas
- **Daugiaperspektyvinė analizė**: Gauti įvairiapusiškas nuomones apie tą patį įvestį

### 🔍 Supratimas apie pasirinktinius vykdytojus

**ConcurrentStartExecutor:**
- Įgyvendina `IMessageHandler<string>` priimti tekstinę įvestį
- Transliuoja pranešimus visiems prijungtiems agentams
- Siunčia `TurnToken` inicijuoti lygiagretų apdorojimą

**ConcurrentAggregationExecutor:**
- Įgyvendina `IMessageHandler<ChatMessage>` priimti agentų atsakymus
- Saugo pranešimus saugiai tarp gijų
- Atliekama agregacija, kai gaunami visi laukiamieji atsakymai
- Pateikia galutinį rezultatą naudodamas `context.YieldOutputAsync()`

### ⚡ Našumo privalumai

**Lygiagretus vs Sekvencinis:**
- Sekvencinis: Agentas1 (30s) → Agentas2 (30s) = **iš viso 60 sekundžių**
- Lygiagretus: Agentas1 (30s) || Agentas2 (30s) = **iš viso 30 sekundžių**

**Pralaidumo pagerėjimas**: Iki N kartų greičiau N lygiagrečių agentų atveju (priklauso nuo darbo krūvio ir išteklių)

### 🛡️ Klaidų tvarkymas

Darbo srautas sklandžiai tvarko atskirus agentų gedimus:
- Jei vienas agentas sugenda, kiti tęsia apdorojimą
- Agregatorius gali įgyvendinti laiko limitų logiką
- Jei reikia, grąžinami daliniai rezultatai
