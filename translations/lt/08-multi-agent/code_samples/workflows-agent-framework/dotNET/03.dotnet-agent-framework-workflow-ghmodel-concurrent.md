# ⚡ Lygiagretūs agentų darbo srautai su Azure OpenAI (Responses API) (.NET)

## 📋 Aukšto našumo lygiagretaus apdorojimo pamoka

Ši užrašinė demonstruoja **lygiagrečius darbo srauto modelius** naudojant Microsoft Agent Framework for .NET ir Azure OpenAI (Responses API). Sužinosite, kaip kurti aukšto našumo, lygiagrečius darbo srautus, kurie maksimaliai padidina pralaidumą vykdant kelis AI agentus vienu metu, išlaikant koordinaciją ir duomenų nuoseklumą.

## 🎯 Mokymosi tikslai

### 🚀 **Lygiagretaus apdorojimo pagrindai**
- **Agentų lygiagretus vykdymas**: paleiskite kelis AI agentus vienu metu maksimaliai našumui
- **Async/Await modeliai**: naudokite .NET asinchroninio programavimo modelį efektyviam lygiagretumui
- **Azure OpenAI (Responses API)**: koordinuokite kelis vienu metu vykdomus skambučius Azure OpenAI Responses API
- **Išteklių valdymas**: efektyviai valdykite AI modelių išteklius lygiagrečiuose veiksmuose

### 🏗️ **Išplėstinė lygiagretumo architektūra**
- **Užduočių pagrindu veikiantis lygiagretumas**: naudokite .NET Task Parallel Library optimaliam lygiagretumui
- **Sinchronizavimo modeliai**: koordinuokite lygiagrečius agentus išvengdami lenktynių sąlygų
- **Krūvio balansavimas**: efektyviai paskirstykite darbą tarp turimos lygiagrečios apdorojimo galios
- **Atsparumas gedimams**: tvarkykite atskirus agentų gedimus nesustabdant viso darbo srauto

### 🏢 **Įmonių lygiagretios programos**
- **Didelio kiekio dokumentų apdorojimas**: apdorokite kelis dokumentus vienu metu
- **Realaus laiko turinio analizė**: lygiagreti įeinančių duomenų srautų analizė
- **Partijų apdorojimo optimizavimas**: maksimalus pralaidumas didelio masto duomenų apdorojimo operacijoms
- **Daugiakanalė analizė**: lygiagretus skirtingų turinio tipų ir formatų apdorojimas

## 💻 Kodo paleidimas

Pilna įgyvendinimo versija yra faile `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Šis failas demonstruoja **Fan-Out/Fan-In lygiagretaus darbo srauto** modelį kelionių planavimui:

### 🏗️ **Darbo srauto architektūra**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Pagrindinės dalys:**

1. **ConcurrentStartExecutor**: vienu metu perduoda vartotojo užklausą visiems agentams
2. **Researcher Agent**: lygiagrečiai analizuoja kelionės vietas ir lankytinas vietas
3. **Planner Agent**: lygiagrečiai kuria detalius kelionės planus
4. **ConcurrentAggregationExecutor**: surenka ir sujungia abiejų agentų rezultatus

### 🎯 **Fan-Out/Fan-In modelis**

Šis darbo srautas demonstruoja klasikinius **Fan-Out/Fan-In** modelio principus:
- **Fan-Out**: vienas įvesties pranešimas vienu metu perduodamas keliems agentams
- **Lygiagretus apdorojimas**: keli agentai vienu metu dirba prie tos pačios užduoties
- **Fan-In**: visi agentų atsakymai surenkami ir sudedami į vieną išvestį

### 🎯 Realūs panaudojimo atvejai

Šis lygiagretaus darbo srauto modelis idealiai tinka:
- **Turinio kūrimas**: keli rašytojai vienu metu kuria skirtingas dalis
- **Kodo peržiūra**: keli peržiūrėtojai analizuoja kodą iš skirtingų perspektyvų
- **Rinkos tyrimai**: lygiagretūs skirtingų rinkos segmentų analizavimai
- **Dokumentų apdorojimas**: lygiagretus išgavimas, analizė ir patikra
- **Daugiaperspektyvinė analizė**: įvairių požiūrių gavimas į tą patį įvestį

### 🔍 Supratimas apie tinkintus vykdytojus

**ConcurrentStartExecutor:**
- Įgyvendina `IMessageHandler<string>`, kad priimtų tekstinę įvestį
- Transliuoja pranešimus visiems prijungtiems agentams
- Išsiunčia `TurnToken`, kad paleistų lygiagretų apdorojimą

**ConcurrentAggregationExecutor:**
- Įgyvendina `IMessageHandler<ChatMessage>`, kad gautų agentų atsakymus
- Renkasi pranešimus saugiai naudodamas daugiagijį metodą
- Apjungia, kai atvyksta visi tikėtini atsakymai
- Grąžina galutinį rezultatą naudodamas `context.YieldOutputAsync()`

### ⚡ Našumo privalumai

**Lygiagretus vs Sekvencinis:**
- Sekvencinis: Agent1 (30s) → Agent2 (30s) = **iš viso 60 sekundžių**
- Lygiagretus: Agent1 (30s) || Agent2 (30s) = **iš viso 30 sekundžių**

**Pralaidumo padidėjimas**: iki N kartų greičiau, kai yra N lygiagrečių agentų (priklauso nuo darbo ir išteklių)

### 🛡️ Klaidų valdymas

Darbo srautas sklandžiai tvarko atskirus agentų gedimus:
- Jei vienas agentas sugenda, kiti tęsia apdorojimą
- Sugrupuotojas gali įgyvendinti laiko apribojimo logiką
- Jei reikia, galima grąžinti dalinius rezultatus
