# ⚡ Lygiagretūs agentų darbų srautai su Azure OpenAI (Atsakymų API) (.NET)

## 📋 Aukšto našumo lygiagretaus apdorojimo vadovas

Šis užrašų knygelės pavyzdys demonstruoja **lygiagrečių darbo srautų modelius**, naudojant Microsoft agentų karkasą .NET ir Azure OpenAI (Atsakymų API). Sužinosite, kaip sukurti aukšto našumo lygiagrečius darbo srautus, kurie maksimizuoja pralaidumą vykdant kelis AI agentus vienu metu, užtikrinant koordinavimą ir duomenų nuoseklumą.

## 🎯 Mokymosi tikslai

### 🚀 **Lygiagretaus apdorojimo pagrindai**
- **Lygiagretus agentų paleidimas**: Vienu metu vykdykite keletą AI agentų maksimaliai našumui
- **Async/Await modeliai**: Naudokite .NET asinchroninį programavimo modelį efektyviam lygiagrečiui darbui
- **Azure OpenAI (Atsakymų API)**: Koordinuokite kelis lygiagrečius kvietimus į Azure OpenAI Atsakymų API
- **Išteklių valdymas**: Efektyviai valdykite AI modelių išteklius vykdant lygiagrečias operacijas

### 🏗️ **Pažangi lygiagrečios architektūros kūrimas**
- **Užduočių lygiagretumas**: Naudokite .NET užduočių lygiagrečiosios biblioteką optimaliai lygiagretiai vykdyti
- **Sinchronizavimo modeliai**: Koordinuokite lygiagretus agentų darbą vengiant sąlygių lenktynių
- **Krovio paskirstymas**: Efektyviai paskirstykite darbą tarp prieinamų lygiagrečių apdorojimo pajėgumų
- **Gedimų tolerancija**: Tvarkykite atskirus agentų gedimus nepertraukiant viso darbo srauto

### 🏢 **Įmonių lygiagretios programos**
- **Didesnio tūrio dokumentų apdorojimas**: Vienu metu apdorokite kelis dokumentus
- **Realaus laiko turinio analizė**: Lygiagretus gaunamų duomenų srautų analizavimas
- **Partijų apdorojimo optimizavimas**: Maksimalus pralaidumas didelio masto duomenų apdorojimo operacijoms
- **Multimodalinė analizė**: Lygiagretus skirtingų turinio tipų ir formatų apdorojimas

## 💻 Kodo paleidimas

Pilna įgyvendinimo versija yra `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Šis failas demonstruoja **Fan-Out/Fan-In lygiagretaus darbo srauto** pavyzdį kelionių planavimui:

### 🏗️ **Darbo srauto architektūra**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Svarbūs komponentai:**

1. **ConcurrentStartExecutor**: Vienu metu perduoda vartotojo užklausą visiems agentams
2. **Researcher Agent**: Lygiagrečiai analizuoja kelionės tikslus ir lankytinas vietas
3. **Planner Agent**: Lygiagrečiai kuria išsamius kelionių planus
4. **ConcurrentAggregationExecutor**: Surenka ir sujungia rezultatus iš abiejų agentų

### 🎯 **Fan-Out/Fan-In modelis**

Šis darbo srautas demonstruoja klasikinį **Fan-Out/Fan-In** modelį:
- **Fan-Out**: Vienas įvesties pranešimas vienu metu perduodamas keliems agentams
- **Lygiagretus apdorojimas**: Keli agentai dirba lygiagrečiai prie to paties uždavinio
- **Fan-In**: Visi agentų rezultatai surenkami ir sujungiami į vieną išvestį

### 🔍 Supratimas apie specialius vykdytojus

**ConcurrentStartExecutor:**
- Įgyvendina `IMessageHandler<string>`, kad priimtų tekstinę įvestį
- Transliuoja pranešimus visiems prijungtiems agentams
- Siunčia `TurnToken`, kad inicijuotų lygiagrečią apdorojimą

**ConcurrentAggregationExecutor:**
- Įgyvendina `IMessageHandler<ChatMessage>`, kad priimtų agentų atsakymus
- Surenka pranešimus saugiai daugiagysliu būdu
- Agreguoja, kai atvyksta visi tikėtini atsakymai
- Pateikia galutinį rezultatą naudojant `context.YieldOutputAsync()`

### ⚡ Našumo privalumai

**Lygiagretus vs Sekvencinis vykdymas:**
- Sekvencinis: Agentas1 (30s) → Agentas2 (30s) = **60 sekundžių iš viso**
- Lygiagretus: Agentas1 (30s) || Agentas2 (30s) = **30 sekundžių iš viso**

**Pralaidumo pagerėjimas**: Iki N kartų greičiau už N lygiagrečių agentų (priklauso nuo darbo krūvio ir išteklių)

### 🛡️ Klaidų tvarkymas

Darbo srautas sklandžiai tvarko atskirus agentų gedimus:
- Jei vienas agentas sugenda, kiti toliau apdoroja
- Agregatorius gali įgyvendinti laiko limitų logiką
- Esant poreikiui gali grąžinti dalinius rezultatus
