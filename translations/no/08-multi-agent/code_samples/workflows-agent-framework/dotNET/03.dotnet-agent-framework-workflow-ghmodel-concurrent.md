# ⚡ Parallelle Agentarbeidsflyter med Azure OpenAI (Responses API) (.NET)

## 📋 Veiledning for høyytelses parallellbehandling

Denne notatboken demonstrerer **parallell arbeidsflytmønstre** ved bruk av Microsoft Agent Framework for .NET og Azure OpenAI (Responses API). Du vil lære hvordan du bygger høyytelses arbeidsflyter for parallell behandling som maksimerer gjennomstrømning ved å kjøre flere AI-agenter samtidig samtidig som koordinering og datakonsistens opprettholdes.

## 💻 Kjøre koden

Fullstendig implementering er tilgjengelig i `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Denne filen demonstrerer en **Fan-Out/Fan-In parallell arbeidsflyt** for reiseplanlegging:

### 🏗️ **Arbeidsflytarkitektur**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Hovedkomponenter:**

1. **ConcurrentStartExecutor**: Sender brukerens forespørsel til alle agenter samtidig
2. **Researcher Agent**: Analyserer destinasjoner og attraksjoner parallelt
3. **Planner Agent**: Lager detaljerte reiseplaner parallelt
4. **ConcurrentAggregationExecutor**: Samler og slår sammen resultater fra begge agenter

### 🎯 **Fan-Out/Fan-In-mønster**

Denne arbeidsflyten demonstrerer det klassiske **Fan-Out/Fan-In**-mønsteret:
- **Fan-Out**: Ett innmeldingssignal sendes til flere agenter samtidig
- **Samtidig behandling**: Flere agenter jobber parallelt på samme oppgave
- **Fan-In**: Resultater fra alle agenter samles og aggregeres til ett utdata

### 🔍 Forstå egendefinerte utførere

**ConcurrentStartExecutor:**
- Implementerer `IMessageHandler<string>` for å akseptere streng-inndata
- Sender meldinger til alle tilkoblede agenter
- Sender `TurnToken` for å trigge samtidige prosesser

**ConcurrentAggregationExecutor:**
- Implementerer `IMessageHandler<ChatMessage>` for å motta agentrespons
- Samler meldinger på en trådsikker måte
- Aggregerer når alle forventede svar er mottatt
- Gir endelig utdata ved hjelp av `context.YieldOutputAsync()`

### ⚡ Ytelsesfordeler

**Samtidig vs sekvensiell:**
- Sekvensiell: Agent1 (30s) → Agent2 (30s) = **60 sekunder totalt**
- Samtidig: Agent1 (30s) || Agent2 (30s) = **30 sekunder totalt**

**Gjennomstrømningsforbedring**: Opptil N× raskere for N samtidige agenter (avhengig av arbeidsmengde og ressurser)

### 🛡️ Feilhåndtering

Arbeidsflyten håndterer individuelle agentfeil på en smidig måte:
- Hvis en agent feiler, fortsetter de andre prosesseringen
- Aggregatoren kan implementere timeout- logikk
- Delvise resultater kan returneres om nødvendig
