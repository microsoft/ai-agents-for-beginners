# ⚡ Samtidige agentarbeidsflyter med Azure OpenAI (Responses API) (.NET)

## 📋 Veiledning for høyytelses parallellbehandling

Denne notatblokken demonstrerer **samtidige arbeidsflytmønstre** ved bruk av Microsoft Agent Framework for .NET og Azure OpenAI (Responses API). Du vil lære hvordan du bygger høyytelses, parallelle arbeidsflyter som maksimerer gjennomstrømning ved å kjøre flere AI-agenter samtidig samtidig som koordinasjon og datakonsistens opprettholdes.

## 💻 Kjøre koden

Den komplette implementasjonen finnes i `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Denne filen demonstrerer en **Fan-Out/Fan-In samtidig arbeidsflyt** for reiseplanlegging:

### 🏗️ **Arbeidsflytarkitektur**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Nøkkelkomponenter:**

1. **ConcurrentStartExecutor**: Sender brukerens forespørsel til alle agenter samtidig
2. **Researcher Agent**: Analyserer reisemål og attraksjoner samtidig
3. **Planner Agent**: Lager detaljerte reiseplaner samtidig
4. **ConcurrentAggregationExecutor**: Samler og slår sammen resultater fra begge agenter

### 🎯 **Fan-Out/Fan-In-mønster**

Denne arbeidsflyten demonstrerer det klassiske **Fan-Out/Fan-In**-mønsteret:
- **Fan-Out**: En inngangs melding sendes ut til flere agenter samtidig
- **Samtidig behandling**: Flere agenter jobber parallelt på samme oppgave
- **Fan-In**: Resultater fra alle agenter samles og aggregeres til ett output

### 🔍 Forstå tilpassede utdrivere

**ConcurrentStartExecutor:**
- Implementerer `IMessageHandler<string>` for å akseptere strenginput
- Sender meldinger til alle tilkoblede agenter
- Sender `TurnToken` for å utløse samtidig behandling

**ConcurrentAggregationExecutor:**
- Implementerer `IMessageHandler<ChatMessage>` for å motta agentrespons
- Samler meldinger på en trådsikker måte
- Agregerer når alle forventede svar er mottatt
- Leverer endelig output ved bruk av `context.YieldOutputAsync()`

### ⚡ Ytelsesfordeler

**Samtidig vs Sekvensiell:**
- Sekvensiell: Agent1 (30s) → Agent2 (30s) = **60 sekunder totalt**
- Samtidig: Agent1 (30s) || Agent2 (30s) = **30 sekunder totalt**

**Forbedret gjennomstrømning**: Opptil N× raskere for N samtidige agenter (avhengig av arbeidsmengde og ressurser)

### 🛡️ Feilhåndtering

Arbeidsflyten håndterer individuelle agentfeil på en smidig måte:
- Hvis én agent feiler, fortsetter de andre behandlingen
- Aggregatoren kan implementere tidsavbruddslogikk
- Delvise resultater kan returneres om nødvendig
