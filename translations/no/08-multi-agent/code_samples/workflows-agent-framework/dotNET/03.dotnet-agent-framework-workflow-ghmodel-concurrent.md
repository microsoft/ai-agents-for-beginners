# ⚡ Samtidige agentarbeidsflyter med Azure OpenAI (Responses API) (.NET)

## 📋 Veiledning for høyytelses parallell prosessering

Denne notatblokken demonstrerer **samtidige arbeidsflytmønstre** ved bruk av Microsoft Agent Framework for .NET og Azure OpenAI (Responses API). Du vil lære hvordan du bygger høyytelses, parallellprosessende arbeidsflyter som maksimerer gjennomstrømning ved å kjøre flere AI-agenter samtidig, samtidig som du opprettholder koordinering og datakonsistens.

## 🎯 Læringsmål

### 🚀 **Grunnleggende om samtidige prosesser**
- **Parallell agentutførelse**: Kjør flere AI-agenter samtidig for maksimal ytelse
- **Async/Await-mønstre**: Utnytt .NETs asynkrone programmeringsmodell for effektiv samtidighet
- **Azure OpenAI (Responses API)**: Koordiner flere samtidige kall til Azure OpenAI Responses API
- **Ressursstyring**: Effektiv styring av AI-modellressurser på tvers av samtidige operasjoner

### 🏗️ **Avansert arkitektur for samtidighet**

- **Lastbalansering**: Fordel arbeid effektivt på tilgjengelig samtidige prosesseringskapasitet
- **Feiltoleranse**: Håndter individuelle agentfeil uten å stoppe hele arbeidsflyten

### 🏢 **Samtidige bedriftsapplikasjoner**

## 💻 Kjøre koden

Den fullstendige implementeringen er tilgjengelig i `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Denne filen demonstrerer en **Fan-Out/Fan-In samtidig arbeidsflyt** for reiseplanlegging:

### 🏗️ **Arbeidsflytarkitektur**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Nøkkelkomponenter:**

1. **ConcurrentStartExecutor**: Sender brukerforespørselen til alle agenter samtidig
2. **Forskeragent**: Analyserer reisemål og attraksjoner parallelt
3. **Planleggeragent**: Lager detaljerte reiseplaner parallelt
4. **ConcurrentAggregationExecutor**: Samler inn og slår sammen resultater fra begge agenter

### 🎯 **Fan-Out/Fan-In-mønster**

Denne arbeidsflyten demonstrerer det klassiske **Fan-Out/Fan-In**-mønsteret:
- **Fan-Out**: Én inngangsmelding kringkastes til flere agenter samtidig
- **Samtidig behandling**: Flere agenter jobber parallelt med samme oppgave
- **Fan-In**: Resultater fra alle agenter samles og aggregeres til én enkelt utgang

Arbeidsflyten vil:

### 🔍 Forstå egendefinerte executors

**ConcurrentStartExecutor:**
- Implementerer `IMessageHandler<string>` for å akseptere strenginput
- Kringkaster meldinger til alle tilkoblede agenter
- Sender `TurnToken` for å trigge samtidig behandling

**ConcurrentAggregationExecutor:**
- Implementerer `IMessageHandler<ChatMessage>` for å motta agentrespons
- Samler meldinger på trådsikker måte
- Aggregerer når alle forventede svar er mottatt
- Returnerer endelig utgang via `context.YieldOutputAsync()`

### ⚡ Ytelsesfordeler

**Samtidig vs Sekvensiell:**
- Sekvensiell: Agent1 (30s) → Agent2 (30s) = **60 sekunder totalt**
- Samtidig: Agent1 (30s) || Agent2 (30s) = **30 sekunder totalt**

**Forbedret gjennomstrømning**: Opptil N× raskere for N samtidige agenter (avhengig av arbeidsmengde og ressurser)

### 🛡️ Feilhåndtering

Arbeidsflyten håndterer individuelle agentfeil på en grasiøs måte:
- Hvis én agent feiler, fortsetter de andre behandlingen
- Aggregatoren kan implementere tidsavbruddslogikk
- Delvise resultater kan returneres etter behov
