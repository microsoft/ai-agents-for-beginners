# ⚡ Alur Kerja Agen Konkuren dengan Azure OpenAI (Responses API) (.NET)

## 📋 Tutorial Pemrosesan Paralel Berkinerja Tinggi

Notebook ini menunjukkan **pola alur kerja konkuren** menggunakan Microsoft Agent Framework untuk .NET dan Azure OpenAI (Responses API). Anda akan belajar cara membangun alur kerja pemrosesan paralel berkinerja tinggi yang memaksimalkan throughput dengan menjalankan beberapa agen AI secara simultan sambil mempertahankan koordinasi dan konsistensi data.

## 🎯 Tujuan Pembelajaran

### 🚀 **Dasar-Dasar Pemrosesan Konkuren**
- **Eksekusi Agen Paralel**: Menjalankan beberapa agen AI secara simultan untuk performa maksimal
- **Pola Async/Await**: Memanfaatkan model pemrograman async .NET untuk konkurensi yang efisien
- **Azure OpenAI (Responses API)**: Koordinasi beberapa panggilan konkuren ke Azure OpenAI Responses API
- **Manajemen Sumber Daya**: Mengelola sumber daya model AI secara efisien di operasi konkuren

### 🏗️ **Arsitektur Konkuren Tingkat Lanjut**
- **Paralelisme Berbasis Task**: Menggunakan Task Parallel Library .NET untuk eksekusi konkuren optimal
- **Pola Sinkronisasi**: Koordinasi agen konkuren sekaligus menghindari kondisi balapan
- **Load Balancing**: Mendistribusikan pekerjaan secara efisien di kapasitas pemrosesan konkurensi yang tersedia
- **Toleransi Kesalahan**: Menangani kegagalan agen individu tanpa menghentikan seluruh alur kerja

### 🏢 **Aplikasi Konkuren Enterprise**
- **Pemrosesan Dokumen Volume Tinggi**: Memproses banyak dokumen secara simultan
- **Analisis Konten Real-Time**: Analisis konkuren aliran data masuk
- **Optimasi Pemrosesan Batch**: Memaksimalkan throughput untuk operasi pemrosesan data skala besar
- **Analisis Multi-Modal**: Pemrosesan paralel tipe dan format konten berbeda

## 💻 Menjalankan Kode

Implementasi lengkap tersedia di `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. File ini menunjukkan **alur kerja konkuren Fan-Out/Fan-In** untuk perencanaan perjalanan:

### 🏗️ **Arsitektur Alur Kerja**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Komponen Utama:**

1. **ConcurrentStartExecutor**: Menyiarkan permintaan pengguna ke semua agen secara simultan
2. **Researcher Agent**: Menganalisis destinasi dan atraksi secara konkuren
3. **Planner Agent**: Membuat rencana perjalanan rinci secara konkuren
4. **ConcurrentAggregationExecutor**: Mengumpulkan dan menggabungkan hasil dari kedua agen

### 🎯 **Pola Fan-Out/Fan-In**

Alur kerja ini menunjukkan pola klasik **Fan-Out/Fan-In**:
- **Fan-Out**: Satu pesan input disiarkan ke beberapa agen secara simultan
- **Pemrosesan Konkuren**: Beberapa agen bekerja paralel pada tugas yang sama
- **Fan-In**: Hasil dari semua agen dikumpulkan dan digabung menjadi output tunggal

### 🔍 Memahami Eksekutor Kustom

**ConcurrentStartExecutor:**
- Mengimplementasikan `IMessageHandler<string>` untuk menerima input string
- Menyiarkan pesan ke semua agen yang terhubung
- Mengirim `TurnToken` untuk memicu pemrosesan konkuren

**ConcurrentAggregationExecutor:**
- Mengimplementasikan `IMessageHandler<ChatMessage>` untuk menerima respons agen
- Mengumpulkan pesan secara thread-safe
- Melakukan agregasi saat semua respons yang diharapkan tiba
- Menghasilkan output akhir menggunakan `context.YieldOutputAsync()`

### ⚡ Manfaat Kinerja

**Konkuren vs Berurutan:**
- Berurutan: Agent1 (30s) → Agent2 (30s) = **60 detik total**
- Konkuren: Agent1 (30s) || Agent2 (30s) = **30 detik total**

**Peningkatan throughput**: Hingga N× lebih cepat untuk N agen yang konkuren (tergantung beban kerja dan sumber daya)

### 🛡️ Penanganan Kesalahan

Alur kerja menangani kegagalan agen individu dengan anggun:
- Jika satu agen gagal, yang lain tetap memproses
- Agregator dapat mengimplementasikan logika timeout
- Hasil parsial dapat dikembalikan jika diperlukan
