# ⚡ گردش‌های کاری همزمان عامل‌ها با Azure OpenAI (Responses API) (.NET)

## 📋 آموزش پردازش موازی با کارایی بالا

این دفترچه نمونه **الگوهای گردش کاری همزمان** را با استفاده از چارچوب عامل مایکروسافت برای .NET و Azure OpenAI (Responses API) نشان می‌دهد. شما یاد می‌گیرید چگونه گردش‌های کاری با پردازش موازی و کارایی بالا بسازید که با اجرای همزمان چندین عامل هوش مصنوعی، حداکثر توان عملیاتی را به دست آورند و در عین حال هماهنگی و انسجام داده‌ها حفظ شود.

## 💻 اجرای کد

پیاده‌سازی کامل در فایل `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs` موجود است. این فایل نمونه یک **گردش کاری همزمان Fan-Out/Fan-In** برای برنامه‌ریزی سفر را نشان می‌دهد:

### 🏗️ **معماری گردش کاری**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**اجزای کلیدی:**

1. **ConcurrentStartExecutor**: درخواست کاربر را به تمام عامل‌ها همزمان پخش می‌کند
2. **Researcher Agent**: به‌طور همزمان مقاصد و جاذبه‌ها را تحلیل می‌کند
3. **Planner Agent**: طرح‌های سفر دقیق را به‌صورت همزمان ایجاد می‌کند
4. **ConcurrentAggregationExecutor**: نتایج هر دو عامل را جمع‌آوری و ترکیب می‌کند

### 🎯 **الگوی Fan-Out/Fan-In**

این گردش کاری الگوی کلاسیک **Fan-Out/Fan-In** را نشان می‌دهد:
- **Fan-Out**: یک پیام ورودی به چندین عامل به صورت همزمان پخش می‌شود
- **پردازش همزمان**: چندین عامل به‌طور پارالل روی یک کار کار می‌کنند
- **Fan-In**: نتایج تمام عامل‌ها جمع‌آوری و در یک خروجی واحد تجمیع می‌شود

گردش کاری انجام می‌دهد:
1. **ارسال درخواست**: ارسال "برنامه‌ریزی سفر به سیاتل در دسامبر" به هر دو عامل
2. **پردازش همزمان**: هر دو عامل به‌طور همزمان کار می‌کنند:
   - محقق جاذبه‌ها و جزئیات را شناسایی می‌کند

3. **تجمیع**: هر دو پاسخ ترکیب شده به یک خروجی جامع تبدیل می‌شود
4. **نمایش نتایج**: طرح سفر ترکیب‌شده با همه اطلاعات نمایش داده می‌شود

### 🔍 درک مجریان سفارشی

**ConcurrentStartExecutor:**
- پیاده‌سازی `IMessageHandler<string>` برای پذیرش ورودی رشته‌ای
- پیام‌ها را به تمام عامل‌های متصل پخش می‌کند
- ارسال `TurnToken` برای تحریک پردازش همزمان

**ConcurrentAggregationExecutor:**
- پیاده‌سازی `IMessageHandler<ChatMessage>` برای دریافت پاسخ‌های عامل‌ها
- جمع‌آوری پیام‌ها به صورت امن در برابر تداخل رشته‌ها
- تجمیع زمان دریافت تمام پاسخ‌های مورد انتظار
- خروجی نهایی را با استفاده از `context.YieldOutputAsync()` ارائه می‌دهد

### ⚡ مزایای عملکرد

**همزمان در مقابل متوالی:**
- متوالی: عامل1 (۳۰ ثانیه) → عامل2 (۳۰ ثانیه) = **۶۰ ثانیه کل**
- همزمان: عامل1 (۳۰ ثانیه) || عامل2 (۳۰ ثانیه) = **۳۰ ثانیه کل**

**بهبود توان عملیاتی**: تا N برابر سریع‌تر برای N عامل همزمان (بسته به بار کاری و منابع)
