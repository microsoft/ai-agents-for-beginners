# ⚡ جریان‌های کاری همزمان عامل‌ها با Azure OpenAI (API پاسخ‌ها) (.NET)

## 📋 آموزش پردازش موازی پرکارایی

این دفترچه کار، **الگوهای جریان کاری همزمان** را با استفاده از Microsoft Agent Framework برای .NET و Azure OpenAI (API پاسخ‌ها) نشان می‌دهد. شما یاد می‌گیرید چگونه جریان‌های کاری پردازش موازی و پرکارایی بسازید که با اجرای چندین عامل هوش مصنوعی به طور همزمان، توان عملیاتی را به حداکثر می‌رسانند و در عین حال هماهنگی و ثبات داده‌ها حفظ شود.

## 💻 اجرای کد

پیاده‌سازی کامل در `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs` موجود است. این فایل یک **جریان کاری همزمان Fan-Out/Fan-In** برای برنامه‌ریزی سفر را نشان می‌دهد:

### 🏗️ **معماری جریان کاری**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**اجزای کلیدی:**

1. **ConcurrentStartExecutor**: درخواست کاربر را به تمام عامل‌ها همزمان پخش می‌کند
2. **عامل محقق**: به‌طور همزمان مقاصد و جاذبه‌ها را تحلیل می‌کند
3. **عامل برنامه‌ریز**: برنامه‌های سفر دقیق را به‌طور همزمان ایجاد می‌کند
4. **ConcurrentAggregationExecutor**: نتایج هر دو عامل را جمع‌آوری و ادغام می‌کند

### 🎯 **الگوی Fan-Out/Fan-In**

این جریان کاری الگوی کلاسیک **Fan-Out/Fan-In** را نشان می‌دهد:
- **Fan-Out**: یک پیام ورودی به طور همزمان به چند عامل پخش می‌شود
- **پردازش همزمان**: چند عامل به موازات هم روی یک کار کار می‌کنند
- **Fan-In**: نتایج تمام عامل‌ها جمع‌آوری و به خروجی واحدی ادغام می‌شوند

### 📝 خروجی مورد انتظار

جریان کاری موارد زیر را انجام می‌دهد:
1. **پخش درخواست**: ارسال "برنامه‌ریزی سفر به سیاتل در دسامبر" به هر دو عامل
2. **پردازش همزمان**: هر دو عامل به طور همزمان کار می‌کنند:

3. **تجمیع**: ترکیب هر دو پاسخ در خروجی جامع

### 🔍 درک اجرایی‌های سفارشی

**ConcurrentStartExecutor:**
- پیاده‌سازی `IMessageHandler<string>` برای دریافت ورودی رشته‌ای
- پیام‌ها را به تمام عامل‌های متصل پخش می‌کند
- ارسال `TurnToken` برای راه‌اندازی پردازش همزمان

**ConcurrentAggregationExecutor:**
- پیاده‌سازی `IMessageHandler<ChatMessage>` برای دریافت پاسخ عامل‌ها
- جمع‌آوری پیام‌ها به صورت Thread-safe
- زمانی که تمام پاسخ‌های انتظار رفته برسند، تجمع را انجام می‌دهد
- خروجی نهایی را با `context.YieldOutputAsync()` ارائه می‌دهد

### ⚡ مزایای عملکرد

**همزمان در مقابل متوالی:**
- متوالی: Agent1 (30 ثانیه) → Agent2 (30 ثانیه) = **مجموع ۶۰ ثانیه**
- همزمان: Agent1 (30 ثانیه) || Agent2 (30 ثانیه) = **مجموع ۳۰ ثانیه**

**بهبود توان عملیاتی**: تا N برابر سریع‌تر برای N عامل همزمان (بسته به بار کاری و منابع)

### 🛡️ مدیریت خطا

جریان کاری شکست‌های هر عامل را به‌خوبی مدیریت می‌کند:

- تجمع‌کننده می‌تواند منطق تایم‌اوت پیاده‌سازی کند
- در صورت نیاز امکان بازگرداندن نتایج جزئی وجود دارد
