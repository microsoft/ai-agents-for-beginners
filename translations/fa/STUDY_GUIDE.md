# عوامل هوش مصنوعی برای مبتدیان - راهنمای مطالعه

از این راهنما به عنوان یک همراه عملی در طول پیشرفت در دوره استفاده کنید. این راهنما
برای جایگزینی درس‌ها طراحی نشده است. این کمک می‌کند تا تصمیم بگیرید از کجا شروع کنید،
به دنبال چه چیزی در هر درس بگردید و چگونه ایده‌ها را به یک دموی کوچک عامل کاری متصل کنید.


اگر این اولین بار است که اینجا هستید، ساده شروع کنید:

۱. [راه‌اندازی دوره](./00-course-setup/README.md) را بخوانید.
۲. درس‌های ۰۱ تا ۰۶ را به ترتیب کامل کنید.
۳. یک ایده کوچک دمو در ذهن داشته باشید هنگام یادگیری.
۴. بعد از هر درس، بپرسید: «حالا عامل من چه کاری می‌تواند انجام دهد که قبلاً نمی‌توانست؟»


## یک دمو ساده برای به خاطر سپردن

یک راه خوب برای یادگیری عوامل، دنبال کردن یک ایده دمو در طول دوره است.

دمو مثال: **عامل دستیار دوره**.

کاربر می‌پرسد:

> «می‌خواهم یاد بگیرم عوامل چگونه از ابزارها استفاده می‌کنند. درس‌های مناسب را پیدا کن، خلاصه کن
> از چه چیزی باید اول بخوانم، و یک تمرین کوتاه به من بده.»

یک چت‌بات معمولی می‌تواند از دانسته‌های قبلی پاسخ دهد. یک عامل می‌تواند بیشتر انجام دهد:

۱. **خواندن یا جستجوی فایل‌های دوره** برای یافتن درس‌های درست.
۲. **استفاده از ابزارها** برای بازیابی لینک‌های درس، مثال‌ها یا مطالب پشتیبانی.
۳. **برنامه‌ریزی** یک مسیر یادگیری کوتاه به جای دادن یک پاسخ طولانی.
۴. **استفاده از زمینه** گفتگو برای متمرکز ماندن روی هدف یادگیرنده.

۵. **به خاطر سپردن ترجیحات مفید** اگر برنامه از حافظه پشتیبانی می‌کند.
۶. **نمایش ردپاها، استنادها، یا لاگ‌ها** تا کاربر بفهمد چه اتفاقی افتاده است.
۷. **اجرای محافظ‌ها** قبل از انجام اقدامات ریسک‌دار یا استفاده از داده‌های حساس.

هر بار که درس را می‌آموزید، به این دمو برگردید و بپرسید: این درس چه قابلیت جدیدی اضافه می‌کند؟


## آنچه در حال ساخت آن هستید

تا پایان دوره، باید قادر باشید سامانه‌های عاملی بسازید و توضیح دهید که این اجزا را ترکیب می‌کنند:

## مدل‌ها و ارائه‌دهندگان

نمونه‌های کد دوره از **Microsoft Agent Framework (MAF)** استفاده می‌کنند و هدف آنها **Azure OpenAI Responses API** است — API پیشنهادی برای آینده که ترکیب چت کامل، فراخوانی ابزارها، ورودی چندحالته و گفتگوهای حالت‌دار را در یک سطح API ارائه می‌دهد. شما یا از طریق یک پروژه **Microsoft Foundry** (با `FoundryChatClient`) یا مستقیم به Azure OpenAI (با `OpenAIChatClient`) متصل می‌شوید.

هنگام گذراندن درس‌ها، چند گزینه ارائه‌دهنده دارید:

- **Microsoft Foundry / Azure OpenAI (Responses API)** — مسیر اصلی که در تمام درس‌ها استفاده می‌شود. با `az login` برای احراز هویت بدون کلید Entra ID وارد شوید.
- **Foundry Local** — اجرای کامل مدل‌ها به صورت محلی از طریق API سازگار با OpenAI (بدون ابر، بدون کلید API). ایده‌آل برای آزمایش آفلاین یا رایگان. به [راه‌اندازی دوره](./00-course-setup/README.md) مراجعه کنید.
- **MiniMax** — یک ارائه‌دهنده سازگار با OpenAI با مدل‌های با حافظه‌ بلند، قابل استفاده به عنوان جایگزین.

> **توجه:** GitHub Models منسوخ شده (تا ژوئیه ۲۰۲۶ بازنشسته می‌شود) و از Responses API پشتیبانی نمی‌کند. نمونه‌ها به Azure OpenAI / Microsoft Foundry به‌روزرسانی شده‌اند.

## ایده‌های کلیدی به زبان ساده برای مبتدی‌ها

### ابزارها

ابزار چیزی است که عامل می‌تواند برای انجام کار خارجی به مدل فراخوانی کند. یک ابزار خوب
نامی واضح، کاری محدود، ورودی‌های تایپ‌شده، خروجی قابل پیش‌بینی و راه ایمنی برای
خطا دارد.

برای نمونه آموزشی دوره، یک ابزار ممکن است:

- `search_lessons(query)`
- `read_lesson(path)`
- `create_practice_task(topic)`

### RAG و دانش

RAG به عامل کمک می‌کند که از متن‌های منبع به جای حدس زدن پاسخ دهد. در این
دوره، آن منابع می‌توانند فایل‌های README درس‌ها، نمونه کد یا منابع خارجی باشند که
از درس‌ها لینک شده‌اند.

وقتی پاسخ باید بر اساس اسناد، داده‌ها یا فایل‌های پروژه کنونی باشد، از RAG استفاده کنید.


### برنامه‌ریزی

برنامه‌ریزی وقتی مفید است که درخواست بیش از یک مرحله داشته باشد. برنامه‌ها را کوتاه و
به اندازه‌ای قابل مشاهده نگه دارید که یک توسعه‌دهنده یا کاربر بتواند آن‌ها را بررسی کند.

برای نمونه، یک برنامه ممکن است این باشد:

۱. یافتن درس‌های مرتبط با استفاده از ابزار.
۲. خلاصه کردن مرتبط‌ترین درس‌ها.
۳. پیشنهاد یک تمرین.

### زمینه

زمینه همان چیزی است که مدل در حال حاضر می‌بیند. زمینه خیلی کم ممکن است باعث شود عامل
جزئیات مهم را از دست بدهد. زمینه خیلی زیاد ممکن است عامل را کندتر، پرهزینه‌تر
یا راحت‌تر گیج کند.

مهندسی زمینه خوب یعنی انتخاب اطلاعات درست برای فراخوان مدل بعدی.


### حافظه

حافظه اطلاعاتی است که برای بعد ذخیره می‌شود. همه چیز را ذخیره نکنید. فقط اطلاعاتی را ذخیره کنید
که مفید، ایمن و آسان برای به‌روزرسانی یا حذف باشد.

برای مثال، به خاطر سپردن اینکه "یادگیرنده مثال‌های پایتون را ترجیح می‌دهد" ممکن است مفید باشد.
به خاطر سپردن داده‌های شخصی حساس معمولاً مناسب نیست.

### ارزیابی و مشاهده‌پذیری

ارزیابی می‌پرسد: آیا عامل کار درست را انجام داد؟

مشاهده‌پذیری می‌پرسد: آیا می‌توانیم ببینیم چگونه اتفاق افتاد؟

برای عوامل در تولید، پیگیری تماس‌های مدل، تماس‌های ابزار، زمینه بازیابی شده،
تأخیر، هزینه، خطاها و بازخورد کاربران را انجام دهید.

### اعتماد و امنیت

عوامل قابل اعتماد نیاز به چیزی فراتر از یک مطلع مفید دارند. از ابزارهای با کمترین دسترسی،
تأیید انسان برای اقدام‌های با تأثیر زیاد، حذف داده‌ها در صورت نیاز، و ثبت یا
رسید برای اقدام‌هایی که باید ممیزی شوند، استفاده کنید.

## یک روش بازبینی ۱۵ دقیقه‌ای

این روش را پس از هر درس استفاده کنید:

۱. **درس را در یک جمله خلاصه کنید.**
۲. **توانایی جدید عامل را نام ببرید.** مثلاً: استفاده از ابزار، بازیابی،
   برنامه‌ریزی، حافظه، مشاهده‌پذیری یا امنیت.
۳. **آن را به دمو کمک‌یار دوره اضافه کنید.** چه تغییراتی حالا در دمو رخ می‌دهد؟
۴. **خطر را بیابید.** اگر این توانایی به اشتباه استفاده شود چه مشکلی ممکن است ایجاد شود؟
۵. **یک سؤال آزمایشی بنویسید.** چگونه بررسی می‌کنید که عامل رفتار مناسبی دارد؟

## خودآزمایی سریع

پیش از ادامه، سعی کنید به این سوالات پاسخ دهید:

۱. یک عامل چه کاری می‌تواند انجام دهد که یک چت‌بات عادی به تنهایی نمی‌تواند؟
۲. عامل شما ابتدا به چه ابزاری نیاز دارد، و چرا؟
۳. منبع دانش باید پاسخ عامل را بر چه اساسی قرار دهد؟
۴. چه زمینه‌ای باید در فراخوان بعدی مدل گنجانده شود؟

۵. عامل چه چیزهایی را باید به خاطر بسپارد و از ذخیره‌سازی چه مواردی باید اجتناب کند؟
۶. عامل چه زمانی باید برای گرفتن تأیید انسان درخواست کند؟
۷. چه گزارش‌ها، ردپاها یا رسیدهایی به شما کمک می‌کند بعداً عامل را اشکال‌زدایی یا حسابرسی کنید؟


## تمرین پیشنهادی پایان‌نامه  

در پایان دوره، یک عامل کوچک بسازید که به یادگیرنده کمک می‌کند در این  
مخزن ناوبری کند.  

نسخه حداقلی:  

- یک موضوع را از کاربر بپذیرد.  
- مرتبط‌ترین درس‌ها را پیدا کند.  
- خلاصه‌ای از آنچه باید اول خوانده شود ارائه دهد.  
- یک تمرین عملی پیشنهاد دهد.  
- فایل‌ها یا لینک‌های درس استفاده شده را نشان دهد.  

نسخه پیشرفته:  

- زبان برنامه‌نویسی مورد علاقه یادگیرنده را به خاطر بسپارد.  
- قبل از پاسخ دادن، از یک برنامه ساده استفاده کند.  
- قبل از پاسخ نهایی یک مرحله خودخوانی اضافه کند.  
- تماس با ابزارها و منابع بازیابی شده را ثبت کند.  
- قبل از باز کردن مرورگر یا وظایف خودکار سازی رابط کاربری، تأیید بخواهد.  

این به شما روشی کوچک اما واقعی برای تمرین ابزارها، RAG، برنامه‌ریزی،  
زمینه، حافظه، قابلیت مشاهده و اعتماد در یک پروژه ارائه می‌دهد.
