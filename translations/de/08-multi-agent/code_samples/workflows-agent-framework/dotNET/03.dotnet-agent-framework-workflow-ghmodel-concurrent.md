# ⚡ Gleichzeitige Agenten-Workflows mit Azure OpenAI (Responses API) (.NET)

## 📋 Tutorial zur Hochleistungs-Parallelen Verarbeitung

Dieses Notebook zeigt **gleichzeitige Workflow-Muster** mit dem Microsoft Agent Framework für .NET und Azure OpenAI (Responses API). Sie lernen, wie Sie hochleistungsfähige, parallele Workflows erstellen, die den Durchsatz maximieren, indem mehrere KI-Agenten gleichzeitig ausgeführt werden, während Koordination und Datenkonsistenz aufrechterhalten bleiben.

## 💻 Ausführung des Codes

Die vollständige Implementierung befindet sich in `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Diese Datei demonstriert einen **Fan-Out/Fan-In gleichzeitigen Workflow** zur Reiseplanung:

### 🏗️ **Workflow-Architektur**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Kernkomponenten:**

1. **ConcurrentStartExecutor**: Überträgt die Benutzeranfrage gleichzeitig an alle Agenten
2. **Researcher Agent**: Analysiert Ziele und Sehenswürdigkeiten parallel
3. **Planner Agent**: Erstellt detaillierte Reisepläne parallel
4. **ConcurrentAggregationExecutor**: Sammelt und fasst Ergebnisse beider Agenten zusammen

### 🎯 **Fan-Out/Fan-In-Muster**

Dieser Workflow demonstriert das klassische **Fan-Out/Fan-In**-Muster:
- **Fan-Out**: Eine Eingabenachricht wird gleichzeitig an mehrere Agenten gesendet
- **Gleichzeitige Verarbeitung**: Mehrere Agenten arbeiten parallel an derselben Aufgabe
- **Fan-In**: Ergebnisse aller Agenten werden gesammelt und zu einer einzigen Ausgabe zusammengeführt

### 🔍 Verständnis von benutzerdefinierten Executoren

**ConcurrentStartExecutor:**
- Implementiert `IMessageHandler<string>` zur Annahme von String-Eingaben
- Sendet Nachrichten an alle verbundenen Agenten
- Sendet `TurnToken` zur Auslösung der gleichzeitigen Verarbeitung

**ConcurrentAggregationExecutor:**
- Implementiert `IMessageHandler<ChatMessage>` zum Empfang von Agentenantworten
- Sammelt Nachrichten threadsicher
- Führt Aggregation durch, wenn alle erwarteten Antworten eingegangen sind
- Gibt die finale Ausgabe über `context.YieldOutputAsync()` zurück

### ⚡ Leistungsvorteile

**Gleichzeitig vs. Sequenziell:**
- Sequenziell: Agent1 (30s) → Agent2 (30s) = **60 Sekunden gesamt**
- Gleichzeitig: Agent1 (30s) || Agent2 (30s) = **30 Sekunden gesamt**

**Durchsatzverbesserung**: Bis zu N× schneller für N gleichzeitige Agenten (abhängig von Arbeitslast und Ressourcen)

### 🛡️ Fehlerbehandlung

Der Workflow behandelt Ausfälle einzelner Agenten elegant:
- Wenn ein Agent ausfällt, verarbeiten die anderen weiter
- Aggregator kann eine Timeout-Logik implementieren
- Teilweise Ergebnisse können bei Bedarf zurückgegeben werden
