# ⚡ Gleichzeitige Agenten-Workflows mit Azure OpenAI (Responses API) (.NET)

## 📋 Tutorial zur Hochleistungs-Parallelverarbeitung

Dieses Notebook demonstriert **gleichzeitige Workflow-Muster** mit dem Microsoft Agent Framework für .NET und Azure OpenAI (Responses API). Sie lernen, wie man leistungsstarke, parallele Verarbeitungs-Workflows erstellt, die den Durchsatz maximieren, indem mehrere KI-Agenten gleichzeitig ausgeführt werden, dabei jedoch Koordination und Datenkonsistenz beibehalten werden.

## 💻 Ausführung des Codes

Die vollständige Implementierung ist in `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs` verfügbar. Diese Datei demonstriert einen **Fan-Out/Fan-In gleichzeitigen Workflow** zur Reiseplanung:

### 🏗️ **Workflow-Architektur**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Wichtigste Komponenten:**

1. **ConcurrentStartExecutor**: Sendet die Benutzeranfrage gleichzeitig an alle Agenten
2. **Researcher Agent**: Analysiert Ziele und Attraktionen gleichzeitig
3. **Planner Agent**: Erstellt detaillierte Reisepläne gleichzeitig
4. **ConcurrentAggregationExecutor**: Sammelt und fasst Ergebnisse beider Agenten zusammen

### 🎯 **Fan-Out/Fan-In Muster**

Dieser Workflow zeigt das klassische **Fan-Out/Fan-In** Muster:
- **Fan-Out**: Eine Eingabenachricht wird gleichzeitig an mehrere Agenten ausgestrahlt
- **Gleichzeitige Verarbeitung**: Mehrere Agenten arbeiten parallel an derselben Aufgabe
- **Fan-In**: Ergebnisse aller Agenten werden gesammelt und zu einer einzigen Ausgabe aggregiert

### 📝 Erwartete Ausgabe

Der Workflow wird:
1. **Anfrage aussenden**: "Plane eine Reise nach Seattle im Dezember" an beide Agenten senden
2. **Gleichzeitige Verarbeitung**: Beide Agenten arbeiten gleichzeitig:
   - Researcher identifiziert Attraktionen und Details

3. **Aggregation**: Beide Antworten zu einer umfassenden Ausgabe zusammenführen

### 🔍 Verstehen von benutzerdefinierten Executors

**ConcurrentStartExecutor:**
- Implementiert `IMessageHandler<string>` für die Annahme von String-Eingaben
- Sendet Nachrichten an alle verbundenen Agenten
- Sendet `TurnToken` zur Auslösung der gleichzeitigen Verarbeitung

**ConcurrentAggregationExecutor:**
- Implementiert `IMessageHandler<ChatMessage>` zum Empfang von Agentenantworten
- Sammelt Nachrichten thread-sicher
- Aggregiert, wenn alle erwarteten Antworten eingetroffen sind
- Gibt finale Ausgabe mit `context.YieldOutputAsync()` zurück

### ⚡ Leistungsvorteile

**Gleichzeitig vs. sequentiell:**
- Sequentiell: Agent1 (30s) → Agent2 (30s) = **60 Sekunden insgesamt**
- Gleichzeitig: Agent1 (30s) || Agent2 (30s) = **30 Sekunden insgesamt**

**Durchsatzverbesserung**: Bis zu N× schneller für N gleichzeitige Agenten (abhängig von Arbeitslast und Ressourcen)

### 🛡️ Fehlerbehandlung

Der Workflow geht elegant mit einzelnen Agentenfehlern um:
- Wenn ein Agent ausfällt, arbeiten die anderen weiter
- Aggregator kann Timeout-Logik implementieren
- Teilweise Ergebnisse können bei Bedarf zurückgegeben werden
