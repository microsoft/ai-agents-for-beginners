# ⚡ Samanaikaiset agenttityönkulut Azure OpenAI:n (Responses API) kanssa (.NET)

## 📋 Suorituskykyinen rinnakkaiskäsittelyopas

Tämä muistikirja esittelee **samanaikaiset työnkulkujen mallit** käyttäen Microsoft Agent Frameworkia .NET:lle ja Azure OpenAI:ta (Responses API). Opit rakentamaan suorituskykyisiä, rinnakkaisia työnkulkuja, jotka maksimoivat läpimenon suorittamalla useita tekoälyagentteja samanaikaisesti samalla, kun koordinaatio ja tiedon eheys säilyvät.

## 🎯 Oppimistavoitteet

### 🚀 **Samanaikaisen käsittelyn perusteet**
- **Rinnakkainen agenttien suoritus**: Suorita useita tekoälyagentteja samanaikaisesti maksimaalisen suorituskyvyn saavuttamiseksi
- **Async/Await-mallit**: Hyödynnä .NET:n asynkronista ohjelmointimallia tehokkaaseen samanaikaisuuteen
- **Azure OpenAI (Responses API)**: Koordinoi useita samanaikaisia kutsuja Azure OpenAI Responses API:in
- **Resurssien hallinta**: Hallitse tehokkaasti tekoälymallien resursseja samanaikaisten operaatioiden aikana

### 🏗️ **Edistynyt samanaikaisuusarkkitehtuuri**
- **Tehtäväpohjainen rinnakkaisuus**: Käytä .NET Task Parallel Librarya optimaaliseen samanaikaiseen suorittamiseen
- **Synkronointimallit**: Koordinoi samanaikaisia agentteja välttäen kilpajuoksuongelmat
- **Kuorman tasapainotus**: Jaa työtehtävät tehokkaasti käytettävissä olevalle samanaikaisten prosessointiresurssille
- **Vikatoleranssi**: Käsittele yksittäisten agenttien virheitä pysäyttämättä koko työnkulkua

### 🏢 **Yrityksen samanaikaiset sovellukset**
- **Laajamittainen asiakirjojen käsittely**: Käsittele useita asiakirjoja samanaikaisesti
- **Reaaliaikainen sisällön analyysi**: Saapuvien datavirtojen samanaikainen analyysi
- **Eräprosessoimisen optimointi**: Maksimoi läpimeno suuressa mittakaavassa tapahtuvissa tietojenkäsittelyoperaatioissa
- **Monimuotoinen analyysi**: Rinnakkainen käsittely erilaisten sisältötyyppien ja -muotojen kanssa

## 💻 Koodin suorittaminen

Täydellinen toteutus löytyy tiedostosta `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Tämä tiedosto esittelee **Fan-Out/Fan-In** samanaikaisen työnkulun matkasuunnitteluun:

### 🏗️ **Työnkulkuarkkitehtuuri**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Keskeiset osat:**

1. **ConcurrentStartExecutor**: Lähettää käyttäjän pyynnön kaikille agenteille samanaikaisesti
2. **Researcher Agent**: Analysoi kohteita ja nähtävyyksiä rinnakkain
3. **Planner Agent**: Laatii yksityiskohtaisia matkasuunnitelmia samanaikaisesti
4. **ConcurrentAggregationExecutor**: Kerää ja yhdistää molempien agenttien tulokset

### 🎯 **Fan-Out/Fan-In-malli**

Tämä työnkulku havainnollistaa klassista **Fan-Out/Fan-In** mallia:
- **Fan-Out**: Yksi syöteviesti lähetetään samanaikaisesti useille agenteille
- **Samanaikainen prosessointi**: Useat agentit työskentelevät rinnakkain saman tehtävän parissa
- **Fan-In**: Kaikkien agenttien tulokset kerätään ja yhdistetään yhdeksi tulosteeksi

### 🔍 Mukautetut suorittajat (executors)

**ConcurrentStartExecutor:**
- Toteuttaa `IMessageHandler<string>` vastaanottaakseen merkkijonosyötteen
- Lähettää viestejä kaikille kytketyille agenteille
- Lähettää `TurnToken`-merkin onnistuneen samanaikaisuuden käynnistämiseen

**ConcurrentAggregationExecutor:**
- Toteuttaa `IMessageHandler<ChatMessage>` vastaanottaakseen agenttien vastauksia
- Kerää viestit säikeiturvallisesti
- Yhdistää tulokset, kun kaikki odotetut vastaukset ovat saapuneet
- Tuottaa lopputuloksen `context.YieldOutputAsync()` avulla

### ⚡ Suorituskykyedut

**Samanaikainen vs peräkkäinen:**
- Peräkkäinen: Agentti1 (30s) → Agentti2 (30s) = **yhteensä 60 sekuntia**
- Samanaikainen: Agentti1 (30s) || Agentti2 (30s) = **yhteensä 30 sekuntia**

**Läpimenon parannus**: Jopa N-kertaista nopeutusta N:lle samanaikaiselle agentille (kuormituksen ja resurssien mukaan)
