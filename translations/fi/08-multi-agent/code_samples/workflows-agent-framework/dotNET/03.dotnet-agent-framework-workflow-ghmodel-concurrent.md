# ⚡ Samanaikaiset agenttien työnkulut Azure OpenAI:n (Responses API) kanssa (.NET)

## 📋 Korkean suorituskyvyn rinnakkaisprosessoinnin opetusohjelma

Tämä muistikirja esittelee **samanaikaisia työnkulkujen malleja** käyttäen Microsoft Agent Frameworkia .NET:lle ja Azure OpenAI:tä (Responses API). Opit luomaan korkean suorituskyvyn rinnakkaisprosessointityönkulkuja, jotka maksimoivat läpimenon suorittamalla useita tekoälyagentteja samanaikaisesti pitäen samalla koordinoinnin ja tietojen yhdenmukaisuuden.

## 🎯 Oppimistavoitteet

### 🚀 **Samanaikaisen prosessoinnin perusteet**
- **Agenttien rinnakkaissuoritus**: Suorita useita tekoälyagentteja samanaikaisesti maksimaalisen suorituskyvyn saavuttamiseksi
- **Async/Await-mallit**: Hyödynnä .NET:n async-ohjelmointimallia tehokasta samanaikaisuutta varten
- **Azure OpenAI (Responses API)**: Koordinoi useita samanaikaisia kutsuja Azure OpenAI Responses API:lle
- **Resurssien hallinta**: Hallitse tehokkaasti tekoälymallin resursseja samanaikaisten toimien välillä

### 🏗️ **Edistynyt samanaikaisarkkitehtuuri**
- **Tehtäväpohjainen rinnakkaisuus**: Käytä .NET Task Parallel Libraryä optimaaliseen samanaikaiseen suorittamiseen
- **Synkronointimallit**: Koordinoi samanaikaisia agenteja välttäen kilpailutilanteet
- **Kuormantasapaino**: Jaa työ tehokkaasti käytettävissä olevan rinnakkaisen prosessointikapasiteetin kesken
- **Vikasietoisuus**: Käsittele yksittäisiä agenttien toimintahäiriöitä pysäyttämättä koko työnkulkua

### 🏢 **Yritysmaailman samanaikaiset sovellukset**
- **Suuren volyymin asiakirjakäsittely**: Käsittele useita asiakirjoja samanaikaisesti
- **Reaaliaikainen sisältöanalyysi**: Saapuvien tietovirtojen samanaikainen analysointi
- **Eräprosessien optimointi**: Maksimoi läpimeno suurissa tietojenkäsittelyoperaatioissa
- **Monimodaalinen analyysi**: Erilaisten sisältötyyppien ja -muotojen rinnakkainen käsittely

## 💻 Koodin suoritus

Täydellinen toteutus löytyy tiedostosta `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Tämä tiedosto esittelee **Fan-Out/Fan-In**-samanaikaisen työnkulun matkasuunnittelulle:

### 🏗️ **Työnkulun arkkitehtuuri**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Keskeiset komponentit:**

1. **ConcurrentStartExecutor**: Lähettää käyttäjän pyynnön kaikille agenteille samanaikaisesti
2. **Researcher Agent**: Analysoi kohteet ja nähtävyydet samanaikaisesti
3. **Planner Agent**: Laatii yksityiskohtaiset matkasunnitelmat samanaikaisesti
4. **ConcurrentAggregationExecutor**: Kerää ja yhdistää molempien agenttien tulokset

### 🎯 **Fan-Out/Fan-In -malli**

Tämä työnkulku osoittaa klassisen **Fan-Out/Fan-In**-mallin:
- **Fan-Out**: Yksi syöteviesti lähetetään useille agenteille samanaikaisesti
- **Samanaikainen prosessointi**: Useat agentit käsittelevät tehtävää rinnakkain
- **Fan-In**: Kaikkien agenttien tulokset kerätään ja yhdistetään yhdeksi tulosteeksi

### 🔍 Mukautettujen suorittimien ymmärtäminen

**ConcurrentStartExecutor:**
- Toteuttaa `IMessageHandler<string>` vastaanottaakseen merkkijonosyötteen
- Lähettää viestit kaikille yhdistetyille agenteille
- Lähettää `TurnToken`-signaalin käynnistämään samanaikaisen prosessoinnin

**ConcurrentAggregationExecutor:**
- Toteuttaa `IMessageHandler<ChatMessage>` vastaanottaakseen agenttien vastauksia
- Kerää viestit säikeiturvallisesti
- Yhdistää kun kaikki odotetut vastaukset ovat saapuneet
- Tuottaa lopputuloksen `context.YieldOutputAsync()` avulla

### ⚡ Suorituskykyedut

**Samanaikainen vs Peräkkäinen:**
- Peräkkäinen: Agentti1 (30s) → Agentti2 (30s) = **60 sekuntia yhteensä**
- Samanaikainen: Agentti1 (30s) || Agentti2 (30s) = **30 sekuntia yhteensä**

**Läpimenon parannus**: Jopa N-kertainen nopeutus N samanaikaisella agentilla (riippuen työkuormasta ja resursseista)
