# ⚡ Samanaikaiset agenttityönkulut Azure OpenAI:n (Responses API) kanssa (.NET)

## 📋 Korkean suorituskyvyn rinnakkaisprosessointiohje

Tämä muistikirja demonstroi **samanaikaisia työnkulkujen malleja** käyttäen Microsoft Agent Frameworkia .NET:lle ja Azure OpenAI:ta (Responses API). Opit rakentamaan korkean suorituskyvyn rinnakkaisia työnkulkuja, jotka maksimoivat läpimenon suorittamalla useita tekoälyagentteja samanaikaisesti säilyttäen samalla koordinoinnin ja tietojen johdonmukaisuuden.

## 🎯 Oppimistavoitteet

### 🚀 **Samanaikaisen prosessoinnin perusteet**
- **Rinnakkainen agenttien suoritus**: Suorita useita tekoälyagentteja samanaikaisesti maksimaaliseen suorituskykyyn
- **Async/Await-mallit**: Hyödynnä .NET:n asynkronista ohjelmointimallia tehokkaaseen samanaikaisuuteen
- **Azure OpenAI (Responses API)**: Koordinoi useita samanaikaisia kutsuja Azure OpenAI Responses API:lle
- **Resurssien hallinta**: Hallitse tehokkaasti tekoälymallien resursseja samanaikaisten toimintojen välillä

### 🏗️ **Edistynyt samanaikaisrakenteinen arkkitehtuuri**
- **Tehtäväpohjainen parallellisuus**: Käytä .NET Task Parallel Librarya optimaaliseen samanaikaiseen suorittamiseen
- **Synkronointimallit**: Koordinoi samanaikaisia agentteja välttäen kilpajuoksutilanteita
- **Kuormantasapaino**: Jaa työkuorma tehokkaasti käytettävissä olevan rinnakkaisen prosessointikapasiteetin kesken
- **Vikansietokyky**: Käsittele yksittäiset agenttien virheet pysäyttämättä koko työnkulkua

### 🏢 **Yritysten samanaikaiset sovellukset**
- **Suuri määrä asiakirjoja**: Käsittele useita asiakirjoja samanaikaisesti
- **Reaaliaikainen sisällön analyysi**: Saapuvien tietovirtojen samanaikainen analysointi
- **Eräprosessoinnin optimointi**: Maksimoi läpimeno suurissa tietojenkäsittelyoperaatioissa
- **Monimuotoinen analyysi**: Erilaisten sisältötyyppien ja -formaattien rinnakkainen käsittely

## 💻 Koodin suoritus

Täysi toteutus löytyy tiedostosta `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Tämä tiedosto demonstroi **Fan-Out/Fan-In samanaikaisen työnkulun** matkasuunnittelua varten:

### 🏗️ **Työnkulun arkkitehtuuri**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Keskeiset osat:**

1. **ConcurrentStartExecutor**: Lähettää käyttäjän pyynnön kaikille agenteille samanaikaisesti
2. **Researcher Agent**: Analysoi kohteita ja nähtävyyksiä rinnakkain
3. **Planner Agent**: Laatii yksityiskohtaiset matkasunnitelmat samanaikaisesti
4. **ConcurrentAggregationExecutor**: Kerää ja yhdistää molempien agenttien tulokset

### 🎯 **Fan-Out/Fan-In-malli**

Tämä työnkulku demonstroi klassista **Fan-Out/Fan-In** -mallia:
- **Fan-Out**: Yksi sisääntuloviesti lähetetään samanaikaisesti useille agenteille
- **Samanaikainen prosessointi**: Useat agentit työskentelevät rinnakkain saman tehtävän parissa
- **Fan-In**: Kaikkien agenttien tulokset kerätään ja yhdistetään yhdeksi lähdöksi

### 🔍 Mukautettujen suorittajien ymmärtäminen

**ConcurrentStartExecutor:**
- Toteuttaa `IMessageHandler<string>`, hyväksyy merkkijonosyötteen
- Lähettää viestit kaikille yhdistetyille agenteille
- Lähettää `TurnToken`-merkin aktivointiin samanaikaiseen prosessointiin

**ConcurrentAggregationExecutor:**
- Toteuttaa `IMessageHandler<ChatMessage>`, vastaanottaa agenttien vastaukset
- Kerää viestit säikeiden turvallisesti
- Yhdistää vastaukset, kun kaikki odotetut vastaukset on saatu
- Tuottaa lopullisen tuloksen käyttäen `context.YieldOutputAsync()`

### ⚡ Suorituskyvyn hyödyt

**Samanaikainen vs peräkkäinen:**
- Peräkkäinen: Agentti1 (30s) → Agentti2 (30s) = **60 sekuntia yhteensä**
- Samanaikainen: Agentti1 (30s) || Agentti2 (30s) = **30 sekuntia yhteensä**

**Läpimenon parannus**: Jopa N-kertainen nopeus N samanaikaisella agentilla (riippuen kuormituksesta ja resursseista)
