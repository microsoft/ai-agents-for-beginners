# Примери фактура

Три унапред генерисане фактуре за преглед без покретања свеске.

| Датотека | О чему се ради |
|---|---|
| `01_valid_receipt.json` | Валуидирана потписана фактура за позив алата `lookup_flights`. Верификација враћа True. |
| `02_tampered_receipt.json` | Иста фактура са једним пољем изменјеним након потписа. Верификација враћа False. |
| `03_chain_three_receipts.json` | Низ од три валидне фактуре (претрага, резервација, књига) са `previous_receipt_hash` који сваки повезује са претходним. |

Примери потписују канонске JCS бајтове оптерећења директно Ed25519.
SHA-256 се и даље користи за дигест садржаја и линкове ланца фактура, не као
додатни претходни хеш пре потписа.

## Верификација примера

Свеска пролази кроз верификацију у четири дела. Да бисте директно проверили ове примере
без покретања наратива свеске:

```python
import json
from pathlib import Path

# Подразумева се да сте завршили увозе и помоћне функције
# из секција 1 и 2 фајла 18-signed-receipts.ipynb.

valid = json.loads(Path("01_valid_receipt.json").read_text())
print(f"Valid receipt: {verify_receipt(valid)}")        # Тачно

tampered = json.loads(Path("02_tampered_receipt.json").read_text())
print(f"Tampered receipt: {verify_receipt(tampered)}")  # Нетачно

chain = json.loads(Path("03_chain_three_receipts.json").read_text())
for r in verify_chain(chain):
    print(f"  Receipt {r['index']} ({r['tool']}): {'VALID' if r['overall_valid'] else 'INVALID'}")
```

## Како су ово генерисане

Примери користе исти код као и свеска, са једним фиксним кључем за потписивање
и фиксним временским ознакама ради репродуктивности бајтова. За регенерисање:

```bash
python3 generate_fixtures.py
```

(Скрипта се налази у `generate_fixtures.py` у овом директоријуму.)

## Шта студенти уче прегледом сировог JSON-а

Читање сировог формата фактуре гради интуицију коју ћелије у свесци понекад
не пруже. Студенти који прегледају JSON често примећују:

1. Потпис је нејасан base64url низ, али сва остала поља су обичан
   читљив JSON. Потпис не шифрује садржај; он га потврђује.
2. `public_key` је уграђен у фактуру. Рачуноводавац не треба ништа друго
   за верификацију (под условом да верује да кључ заиста припада наведеном
   издаваоцу; видети README лекције о инфраструктури идентитета).
3. Измена једног знака у било ком пољу и поновно поређење са
   `02_tampered_receipt.json` конкретно осликава механизм на нивоу бајтова.
