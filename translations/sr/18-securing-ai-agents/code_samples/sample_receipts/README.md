# Пример фајлова рачуна

Три унапред генерисана фајла рачуна за преглед без покретања нотебока.

| Фајл | Шта је то |
|---|---|
| `01_valid_receipt.json` | Валидациони потписан рачун за позив алата `lookup_flights`. Верификација враћа True. |
| `02_tampered_receipt.json` | Исти рачун са једним пољем измењеним након потписивања. Верификација враћа False. |
| `03_chain_three_receipts.json` | Ланац од три важећа рачуна (претрага, задржавање, резервација) са `previous_receipt_hash` који сваки повезује са претходним. |

Фајлови директно потписују canonical JCS бајтове на товару помоћу Ed25519.
SHA-256 остаје у употреби за садржајне дигесте и везу ланца рачуна, не као
додатни пре-хај дигест пре потписивања.

## Верификовање примера

Нотебок води кроз верификацију у четири одељка. Да бисте директно проверили ове фајлове
без покретања нотебока:

```python
import json
from pathlib import Path

# Претпоставља се да сте завршили увозе и помоћне функције
# из секција 1 и 2 из 18-signed-receipts.ipynb.

valid = json.loads(Path("01_valid_receipt.json").read_text())
print(f"Valid receipt: {verify_receipt(valid)}")        # Тачно

tampered = json.loads(Path("02_tampered_receipt.json").read_text())
print(f"Tampered receipt: {verify_receipt(tampered)}")  # Нетачно

chain = json.loads(Path("03_chain_three_receipts.json").read_text())
for r in verify_chain(chain):
    print(f"  Receipt {r['index']} ({r['tool']}): {'VALID' if r['overall_valid'] else 'INVALID'}")
```

## Како су генерисани

Фајлови користе исти код као и нотебок, са једним фиксним кључем за потпис
и фиксним временским ознакама ради репродукције бајтова. За регенерацију:

```bash
python3 generate_fixtures.py
```

(Скрипта се налази у `generate_fixtures.py` у овом директоријуму.)

## Шта студенти уче из прегледа сировог JSON-а

Читање сировог формата рачуна гради интуицију коју ћелије у нотебоку
понекад не пружају. Студенти који брзо прегледају JSON често примете:

1. Потпис је непрозирни base64url низ, али свака друга поља су обичан 
   читљив JSON. Потпис не шифрује садржај; он га сведочи.
2. `public_key` је уграђен у рачун. Ревизор не треба ништа више
   за верификацију (под условом да верује да кључ заиста припада наведеном
   издавачу; видети README примерка о инфраструктури идентитета).
3. Измена једног знака у било ком пољу, па упоређивање овог фајла са
   `02_tampered_receipt.json`, чини механизам на нивоу бајтова конкретним.
