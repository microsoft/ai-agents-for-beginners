# ⚡ Конкурентни токови рада агената са Azure OpenAI (Responses API) (.NET)

## 📋 Туторијал за паралелну обраду велике изведбе

Овај нотебоок демонстрира **конкурентне шаблоне токова рада** користећи Microsoft Agent Framework за .NET и Azure OpenAI (Responses API). Научићете како да направите високоизвршне, паралелне токове рада који максимизирају пропусни опсег извршавањем више AI агената истовремено, при чему се одржава координација и конзистентност података.

## 🎯 Циљеви учења

### 🚀 **Основе конкуретне обраде**
- **Паралелно извршавање агената**: Покретање више AI агената истовремено за максималне перформансе
- **Async/Await обрасци**: Коришћење .NET асинхроног програмског модела за ефикасну конкуренцију
- **Azure OpenAI (Responses API)**: Координација више конкурентних позива ка Azure OpenAI Responses API-ју
- **Управљање ресурсима**: Ефикасно управљање ресурсима AI модела у вишеоперативним задацима

### 🏗️ **Напредна архитектура конкуренције**
- **Задаци засновани на паралелизму**: Користите .NET Task Parallel Library за оптимално конкурентно извршавање
- **Обрасци синхронизације**: Координирајте конкурентне агенте избегавајући трке за ресурсе
- **Расподела оптерећења**: Ефикасна расподела посла по расположивом капацитету за паралелну обраду
- **Отпорност на грешке**: Обрада појединачних губитака агената без заустављања целокупног тока рада

### 🏢 **Пословне конкурентне апликације**
- **Обрада великог броја докумената**: Обрада више докумената истовремено

- **Оптимизација пакетне обраде**: Максимизирање пропусног опсега за велике операције обраде података

## 💻 Покретање кода

Комплетна имплементација је доступна у `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Овај фајл демонстрира **Fan-Out/Fan-In конкурентни ток рада** за планирање путовања:

### 🏗️ **Архитектура тока рада**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Кључне компоненте:**

1. **ConcurrentStartExecutor**: Истовремено прослеђује кориснички захтев свим агентима
2. **Researcher Agent**: Анализира дестинације и атракције конкурентно
3. **Planner Agent**: Креира детаљне планове путовања истовремено
4. **ConcurrentAggregationExecutor**: Прикупља и спаја резултате оба агента

### 🎯 **Fan-Out/Fan-In образац**

Овај ток рада демонстрира класични **Fan-Out/Fan-In** образац:
- **Fan-Out**: Једна улазна порука се истовремено шаље више агената
- **Конкурентна обрада**: Више агената ради паралелно на истом задатку
- **Fan-In**: Резултати свих агената се прикупљају и интегришу у један излаз

### 📝 Очекивани резултат

Ток рада ће:
1. **Проследити захтев**: Послати "Планирај путовање за Сијетл у децембру" обема агентима
2. **Конкурентна обрада**: Оба агента раде истовремено:

### 🔍 Разумевање прилагођених извршитеља

**ConcurrentStartExecutor:**
- Имплементира интерфејс `IMessageHandler<string>` за прихват улазних порука као string
- Прослеђује поруке свим повезаним агентима
- Слање `TurnToken` за покретање конкурентне обраде

**ConcurrentAggregationExecutor:**
- Имплементира интерфејс `IMessageHandler<ChatMessage>` за пријем одговора агената
- Прикупља поруке на безбедан начин за више нити
- Агрегира резултате када стигну сви очекивани одговори
- Пружа коначни излаз користећи `context.YieldOutputAsync()`

### ⚡ Предности перформанси

**Конкурентно наспрам секвенцијалног:**
- Секвенцијално: Agent1 (30s) → Agent2 (30s) = **укупно 60 секунди**
- Конкурентно: Agent1 (30s) || Agent2 (30s) = **укупно 30 секунди**

**Побољшање пропусности**: До Н пута брже за Н конкурентних агената (у зависности од оптерећења и ресурса)

### 🛡️ Руководење грешкама

Ток рада на пристојан начин обрађује појединачне падове агената:
- Ако један агент падне, други настављају обраду
- Агрегатор може применити логику тајмаута
- Делимични резултати се могу вратити по потреби
