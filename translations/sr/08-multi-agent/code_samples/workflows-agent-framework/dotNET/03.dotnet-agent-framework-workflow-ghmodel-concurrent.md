# ⚡ Конкурентни агенцијски радни токови са Azure OpenAI (Responses API) (.NET)

## 📋 Туторијал за високопродуктивну паралелну обраду

Овај нотебук демонстрира **шаблоне конкурената у радним токовима** користећи Microsoft Agent Framework за .NET и Azure OpenAI (Responses API). Научићете како да креирате високопродуктивне, паралелне радне токове који максимизирају пропусни опсег извршавањем више AI агената истовремено, уз одржавање координације и конзистентности података.

## 💻 Покретање кода

Комплетна имплементација доступна је у `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Овај фајл демонстрира **Fan-Out/Fan-In конкурентни радни ток** за планирање путовања:

### 🏗️ **Архитектура радног тока**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Кључне компоненте:**

1. **ConcurrentStartExecutor**: Истовремено емитује захтев корисника свим агентима
2. **Researcher Agent**: Истовремено анализира дестинације и атракције
3. **Planner Agent**: Паралелно креира детаљне планове путовања
4. **ConcurrentAggregationExecutor**: Прикупља и спаја резултате оба агента

### 🎯 **Fan-Out/Fan-In образац**

Овај радни ток демонстрира класични **Fan-Out/Fan-In** образац:
- **Fan-Out**: Једна улазна порука се истовремено емитује више агената
- **Конкурентна обрада**: Више агената ради паралелно на истом задатку
- **Fan-In**: Резултати свих агената се прикупљају и агрегирају у један излаз

### 🎯 Примена у стварном свету

Овај конкурентни образац је идеалан за:
- **Креирање садржаја**: Више писаца истовремено креира различите секције
- **Преглед кода**: Више рецензената анализира код из различитих перспектива
- **Истраживање тржишта**: Паралелна анализа различитих сегмената тржишта
- **Обрада докумената**: Конкурентно издвајање, анализа и валидација
- **Мултиперспективска анализа**: Прикупљање различитих гледишта на исти унос

### 🔍 Разумевање прилагођених извршитеља

**ConcurrentStartExecutor:**
- Имплементира `IMessageHandler<string>` за прихватање улазних стрингова
- Емитује поруке свим повезаним агентима
- Шаље `TurnToken` за покретање конкурентне обраде

**ConcurrentAggregationExecutor:**
- Имплементира `IMessageHandler<ChatMessage>` за пријем одговора агената
- Прикупља поруке на сигуран начин за тредове
- Агрегира када стигну сви очекивани одговори
- Враћа коначни излаз користећи `context.YieldOutputAsync()`

### ⚡ Добробити перформанси

**Конкурентно насупрот секвенцијалном:**
- Секвенцијално: Agent1 (30s) → Agent2 (30s) = **укупно 60 секунди**
- Конкурентно: Agent1 (30s) || Agent2 (30s) = **укупно 30 секунди**

**Побољшање пропусности**: До Н× брже за Н конкурентних агената (у зависности од оптерећења и ресурса)

### 🛡️ Руковање грешкама

Радни ток успешно рукова појединачним кваровима агената:
- Ако један агент падне, остали настављају обраду
- Агрегатор може имплементирати логику истека времена
- Делимични резултати могу бити враћени ако је потребно
