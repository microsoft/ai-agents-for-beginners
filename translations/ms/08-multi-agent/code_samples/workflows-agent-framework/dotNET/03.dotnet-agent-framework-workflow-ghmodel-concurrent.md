# ⚡ Aliran Kerja Ejen Serentak dengan Azure OpenAI (Responses API) (.NET)

## 📋 Tutorial Pemprosesan Selari Berprestasi Tinggi

Nota ini menunjukkan **corak aliran kerja serentak** menggunakan Bingkai Ejen Microsoft untuk .NET dan Azure OpenAI (Responses API). Anda akan mempelajari cara membina aliran kerja pemprosesan selari berprestasi tinggi yang memaksimumkan hasil dengan melaksanakan beberapa ejen AI secara serentak sambil mengekalkan koordinasi dan konsistensi data.

Pelaksanaan lengkap tersedia dalam `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Fail ini menunjukkan **aliran kerja serentak Fan-Out/Fan-In** untuk perancangan perjalanan:

### 🏗️ **Seni Bina Aliran Kerja**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Komponen Utama:**

1. **ConcurrentStartExecutor**: Menyiarkan permintaan pengguna kepada semua ejen serentak
2. **Ejen Penyelidik**: Menganalisis destinasi dan tarikan secara serentak
3. **Ejen Perancang**: Mencipta pelan perjalanan terperinci secara serentak
4. **ConcurrentAggregationExecutor**: Mengumpul dan menggabungkan keputusan dari kedua-dua ejen

### 🎯 **Corak Fan-Out/Fan-In**

Aliran kerja ini menunjukkan corak klasik **Fan-Out/Fan-In**:
- **Fan-Out**: Satu mesej input disiarkan ke beberapa ejen serentak
- **Pemprosesan Serentak**: Beberapa ejen bekerja selari pada tugasan yang sama
- **Fan-In**: Keputusan daripada semua ejen dikumpul dan digabungkan ke dalam satu output

### 🔍 Memahami Pelaksana Tersuai

**ConcurrentStartExecutor:**
- Melaksanakan `IMessageHandler<string>` untuk menerima input rentetan
- Menyiarkan mesej ke semua ejen yang bersambung
- Menghantar `TurnToken` untuk mencetuskan pemprosesan serentak

**ConcurrentAggregationExecutor:**
- Melaksanakan `IMessageHandler<ChatMessage>` untuk menerima maklum balas ejen
- Mengumpul mesej secara selamat dalam benang
- Mengagregat apabila semua maklum balas dijangka tiba
- Menghasilkan output akhir menggunakan `context.YieldOutputAsync()`

### ⚡ Manfaat Prestasi

**Serentak vs Berurutan:**
- Berurutan: Ejen1 (30s) → Ejen2 (30s) = **60 saat keseluruhan**
- Serentak: Ejen1 (30s) || Ejen2 (30s) = **30 saat keseluruhan**

**Peningkatan hasil**: Sehingga N× lebih pantas untuk N ejen serentak (bergantung pada beban kerja dan sumber)

### 🛡️ Pengendalian Ralat

Aliran kerja mengendalikan kegagalan ejen individu dengan teratur:
- Jika satu ejen gagal, yang lain terus memproses
- Pengagregat boleh melaksanakan logik tamat masa
- Keputusan separa boleh dipulangkan jika perlu
