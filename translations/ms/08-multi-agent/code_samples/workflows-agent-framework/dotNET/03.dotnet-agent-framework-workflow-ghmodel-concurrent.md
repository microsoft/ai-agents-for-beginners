# ⚡ Aliran Kerja Ejen Serentak dengan Azure OpenAI (Responses API) (.NET)

## 📋 Tutorial Pemprosesan Selari Berprestasi Tinggi

Notebook ini menunjukkan **corak aliran kerja serentak** menggunakan Microsoft Agent Framework untuk .NET dan Azure OpenAI (Responses API). Anda akan belajar cara membina aliran kerja pemprosesan selari berprestasi tinggi yang memaksimumkan keluaran dengan menjalankan pelbagai ejen AI secara serentak sambil mengekalkan penyelarasan dan konsistensi data.

## 🎯 Objektif Pembelajaran

### 🚀 **Asas Pemprosesan Serentak**
- **Pelaksanaan Ejen Selari**: Jalankan pelbagai ejen AI secara serentak untuk prestasi maksimum
- **Corak Async/Await**: Manfaatkan model pengaturcaraan async .NET untuk kecekapan serentak
- **Azure OpenAI (Responses API)**: Selaraskan pelbagai panggilan serentak ke Azure OpenAI Responses API
- **Pengurusan Sumber**: Urus sumber model AI dengan cekap merentas operasi serentak

### 🏗️ **Seni Bina Serentak Lanjutan**
- **Pemprosesan Selari Berasaskan Tugas**: Gunakan Task Parallel Library .NET untuk pelaksanaan serentak optimum
- **Corak Penyelarasan**: Selaraskan ejen serentak sambil mengelakkan keadaan perlumbaan
- **Pengimbangan Beban**: Agihkan kerja dengan cekap merentas kapasiti pemprosesan serentak yang tersedia
- **Ketahanan Ralat**: Tangani kegagalan ejen individu tanpa menghentikan keseluruhan aliran kerja

### 🏢 **Aplikasi Serentak Perusahaan**
- **Pemprosesan Dokumen Berjumlah Tinggi**: Proses pelbagai dokumen secara serentak
- **Analisis Kandungan Masa Nyata**: Analisis serentak aliran data masuk
- **Pengoptimuman Pemprosesan Kumpulan**: Maksimumkan keluaran untuk operasi pemprosesan data skala besar
- **Analisis Multi-Mod**: Pemprosesan selari jenis dan format kandungan berbeza

### 🏗️ **Seni Bina Aliran Kerja**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Komponen Utama:**

1. **ConcurrentStartExecutor**: Menyiarkan permintaan pengguna kepada semua ejen serentak
2. **Ejen Penyelidik**: Menganalisis destinasi dan tarikan secara serentak
3. **Ejen Perancang**: Membina rancangan perjalanan terperinci secara serentak
4. **ConcurrentAggregationExecutor**: Mengumpul dan menggabungkan keputusan dari kedua-dua ejen

### 🎯 **Corak Fan-Out/Fan-In**

Aliran kerja ini menunjukkan corak klasik **Fan-Out/Fan-In**:
- **Fan-Out**: Satu mesej input disiarkan kepada pelbagai ejen serentak
- **Pemprosesan Serentak**: Pelbagai ejen bekerja selari pada tugasan yang sama
- **Fan-In**: Keputusan dari semua ejen dikumpul dan digabungkan menjadi output tunggal

### 🔍 Memahami Pelaksana Khusus

**ConcurrentStartExecutor:**
- Melaksanakan `IMessageHandler<string>` untuk menerima input jenis string
- Menyiarkan mesej ke semua ejen yang disambungkan
- Menghantar `TurnToken` untuk mencetuskan pemprosesan serentak

**ConcurrentAggregationExecutor:**
- Melaksanakan `IMessageHandler<ChatMessage>` untuk menerima respons ejen
- Mengumpul mesej secara selamat tanpa konflik
- Menggabungkan apabila semua respons dijangka tiba
- Menghasilkan output akhir menggunakan `context.YieldOutputAsync()`

### ⚡ Manfaat Prestasi

**Serentak vs Berturutan:**
- Berturutan: Ejen1 (30s) → Ejen2 (30s) = **60 saat jumlah**
- Serentak: Ejen1 (30s) || Ejen2 (30s) = **30 saat jumlah**

**Penambahbaikan keluaran**: Sehingga N× lebih pantas untuk N ejen serentak (bergantung pada beban kerja dan sumber)

### 🛡️ Pengendalian Ralat

Aliran kerja mengendalikan kegagalan ejen individu dengan baik:
- Jika satu ejen gagal, yang lain terus memproses
- Penggabung boleh melaksanakan logik tamat masa
- Keputusan separa boleh dikembalikan jika perlu
