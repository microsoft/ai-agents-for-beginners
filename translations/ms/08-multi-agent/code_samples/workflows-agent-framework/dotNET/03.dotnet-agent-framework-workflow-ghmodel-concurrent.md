# ⚡ Aliran Kerja Ejen Serentak dengan Azure OpenAI (Respons API) (.NET)

## 📋 Tutorial Pemprosesan Selari Berprestasi Tinggi

Notebook ini menunjukkan **corak aliran kerja serentak** menggunakan Microsoft Agent Framework untuk .NET dan Azure OpenAI (Respons API). Anda akan belajar bagaimana membina aliran kerja pemprosesan selari berprestasi tinggi yang memaksimumkan hasil dengan melaksanakan beberapa ejen AI secara serentak sambil mengekalkan koordinasi dan konsistensi data.

## 🎯 Objektif Pembelajaran

### 🚀 **Asas Pemprosesan Serentak**
- **Pelaksanaan Ejen Selari**: Jalankan beberapa ejen AI secara serentak untuk prestasi maksimum
- **Corak Async/Await**: Manfaatkan model pengaturcaraan async .NET untuk keserentakan yang cekap
- **Azure OpenAI (Respons API)**: Koordinasi pelbagai panggilan serentak ke Azure OpenAI Responses API
- **Pengurusan Sumber**: Urus sumber model AI dengan cekap merentas operasi serentak

### 🏗️ **Reka Bentuk Senibina Keserentakan Lanjutan**
- **Tugas Berasaskan Paralelisme**: Gunakan Perpustakaan Tugas Paralel .NET untuk pelaksanaan serentak yang optimum
- **Corak Penyegerakan**: Koordinasi ejen serentak sambil mengelakkan keadaan perlumbaan
- **Pengagihan Beban**: Edarkan kerja dengan cekap merentas kapasiti pemprosesan serentak yang tersedia
- **Ketahanan Kesilapan**: Urus kegagalan ejen individu tanpa menghentikan keseluruhan aliran kerja

### 🏢 **Aplikasi Serentak Perusahaan**
- **Pemprosesan Dokumen Jumlah Tinggi**: Proses beberapa dokumen secara serentak
- **Analisis Kandungan Masa Nyata**: Analisis serentak aliran data masuk

### 🏗️ **Senibina Aliran Kerja**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Komponen Utama:**

1. **ConcurrentStartExecutor**: Menyiarkan permintaan pengguna kepada semua ejen secara serentak
2. **Ejen Penyelidik**: Menganalisis destinasi dan tarikan secara serentak
3. **Ejen Perancang**: Mencipta pelan perjalanan terperinci secara serentak
4. **ConcurrentAggregationExecutor**: Mengumpul dan menggabungkan keputusan dari kedua-dua ejen

### 🎯 **Corak Fan-Out/Fan-In**

Aliran kerja ini menunjukkan corak klasik **Fan-Out/Fan-In**:
- **Fan-Out**: Satu mesej input disiarkan kepada berbilang ejen secara serentak
- **Pemprosesan Serentak**: Berbilang ejen bekerja selari pada tugasan yang sama
- **Fan-In**: Keputusan daripada semua ejen dikumpul dan digabungkan menjadi output tunggal

### 🔍 Memahami Pelaksana Tersuai

**ConcurrentStartExecutor:**
- Melaksanakan `IMessageHandler<string>` untuk menerima input rentetan
- Menyiarkan mesej kepada semua ejen yang disambungkan
- Menghantar `TurnToken` untuk mencetuskan pemprosesan serentak

**ConcurrentAggregationExecutor:**
- Melaksanakan `IMessageHandler<ChatMessage>` untuk menerima respons ejen
- Mengumpul mesej secara selamat daripada benang
- Menggabungkan apabila semua respons yang dijangka tiba
- Menghasilkan output akhir menggunakan `context.YieldOutputAsync()`

### ⚡ Manfaat Prestasi

**Serentak vs Bersiri:**
- Bersiri: Agent1 (30s) → Agent2 (30s) = **60 saat jumlah**
- Serentak: Agent1 (30s) || Agent2 (30s) = **30 saat jumlah**

**Penambahbaikan Hasil**: Sehingga N× lebih pantas untuk N ejen serentak (bergantung pada beban kerja dan sumber)

### 🛡️ Pengendalian Ralat

Aliran kerja mengendalikan kegagalan ejen individu dengan baik:
- Jika satu ejen gagal, ejen lain terus memproses
- Penggabung boleh melaksanakan logik tamat masa
- Keputusan separa boleh dikembalikan jika perlu
