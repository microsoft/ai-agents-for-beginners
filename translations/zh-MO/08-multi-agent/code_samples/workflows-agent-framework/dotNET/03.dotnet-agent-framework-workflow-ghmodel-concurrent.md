## 💻 運行程式碼

完整實作位於 `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`。該檔展示一個旅遊規劃的<strong>Fan-Out/Fan-In 並行工作流</strong>：

### 🏗️ <strong>工作流架構</strong>

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**主要組件：**

1. **ConcurrentStartExecutor**：同時向所有代理廣播用戶請求
2. **Researcher Agent**：同時分析目的地和景點
3. **Planner Agent**：同時創建詳細旅遊計畫
4. **ConcurrentAggregationExecutor**：收集並合併兩個代理結果

### 🎯 **Fan-Out/Fan-In 模式**

此工作流展示經典的 **Fan-Out/Fan-In** 模式：
- **Fan-Out**：一則輸入訊息同時廣播到多個代理
- <strong>並行處理</strong>：多個代理並行處理相同任務
- **Fan-In**：收集所有代理結果並彙總為單一輸出

### 🔍 理解自訂執行器

**ConcurrentStartExecutor：**
- 實作 `IMessageHandler<string>` 以接受字串輸入
- 向所有連接的代理廣播訊息
- 發送 `TurnToken` 以觸發並行處理

**ConcurrentAggregationExecutor：**
- 實作 `IMessageHandler<ChatMessage>` 以接收代理回應
- 確保以執行緒安全方式收集訊息
- 當所有預期回應到齊時進行彙總
- 使用 `context.YieldOutputAsync()` 產出最終結果

### ⚡ 效能優勢

**並行 vs 順序：**
- 順序：Agent1 (30秒) → Agent2 (30秒) = **共 60 秒**
- 並行：Agent1 (30秒) || Agent2 (30秒) = **共 30 秒**

<strong>吞吐量提升</strong>：N 個併發代理可提升達 N× 速度（視負載與資源而定）

### 🛡️ 錯誤處理

工作流優雅處理單一代理失敗：
- 若一個代理失敗，其他代理繼續運作
- 聚合器可實現逾時邏輯
- 必要時可返回部分結果
