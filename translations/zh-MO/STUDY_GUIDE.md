# 初學者的 AI 代理人 - 學習指南

使用此指南作為您課程進程中的實用夥伴。它
不設計為取代課程內容。它幫助您決定從哪開始，應該
在每節課中尋找什麼，以及如何將想法連結成一個小型可運作的代理人
示範。

如果您是第一次接觸這裡，請從簡單開始：

1. 閱讀 [課程設置](./00-course-setup/README.md)。
2. 按順序完成第01至06課。
3. 學習時記著一個小型示範想法。
4. 每節課後，都問自己：「我的代理人現在能做什麼，是以前不能做的？」


## 一個簡單的示範讓你記住

學習代理人的好方法是貫穿整個課程跟隨一個示範想法。

示例示範：<strong>一個課程助手代理人</strong>。

使用者問：

> 「我想學習代理人如何使用工具。找出合適的課程，總結我
> 應該先讀什麼，並給我一個簡短的練習任務。」

一個普通的聊天機械人可以根據其已知回答。代理人能做得更多：

1. <strong>閱讀或搜尋課程檔案</strong>，找到適合的課程。
2. <strong>使用工具</strong>，檢索課程連結、範例或支援資料。
3. <strong>規劃</strong> 一條短期學習路徑，而不是給出一個長答案。
4. <strong>利用當前對話的上下文</strong>，保持專注於學習者的
   目標。
5. <strong>記住有用的偏好設定</strong>，如果應用程序支援記憶功能。
6. **展示追蹤、引用或日誌**，讓使用者明白發生了什麼。
7. **在採取風險行動或使用敏感資料前，設定防護措施**。

當您學習每節課時，回來看看這個示範並問自己：這節課會增加什麼新能力？


## 您正在建構的目標

課程結束時，您應該能說明並建立結合以下部分的代理人系統：


|------|------------------------|-------------|
| 模型 | 解釋使用者請求的推理引擎 | 理解學習者想要關於工具使用的課程 |
| 工具 | 代理人可使用的功能、API、檔案、瀏覽器或服務 | 搜尋程式庫或檢索課程內容 |
| 知識 | 用於支撐答案的文件或數據 | 課程 README 檔與課程材料 |
| 上下文 | 包含在下一次模型調用中的信息 | 使用者目標和工具結果 |
| 記憶 | 保存以供將來使用的信息 | 學習者偏好有實戰 Python 範例 |
| 規劃 | 把較大目標拆解成較小步驟 | 找課程、總結課程、建議練習 |
| 編排 | 在工具、步驟或代理人之間分配工作 | 規劃者呼叫搜尋工具，再呼叫總結器 |
| 信任 | 安全性、保護、評估與可觀察性 | 記錄工具呼叫，並在高影響操作前徵求同意 |


## 模型與提供者

課程範例程式碼使用 **Microsoft Agent Framework (MAF)**，目標為 **Azure OpenAI Responses API** — 這是未來推薦使用的 API，結合了聊天補全、工具呼叫、多模態輸入和有狀態對話於一個單一 API 界面。您可以通過 **Microsoft Foundry** 專案（使用 `FoundryChatClient`）或直接連接到 Azure OpenAI（使用 `OpenAIChatClient`）。


在進行課程的過程中，您有幾個提供者選擇：

- **Microsoft Foundry / Azure OpenAI (Responses API)** — 是課程中主要使用的路徑。使用 `az login` 進行無密鑰 Entra ID 認證。
- **Foundry Local** — 透過與 OpenAI 兼容的 API 完全在設備上運行模型（無需雲端，無需 API 金鑰）。非常適合離線或免費試驗。請參見 [課程設置](./00-course-setup/README.md)。
- **MiniMax** — 一個支持大上下文模型的 OpenAI 兼容提供者，可作為即插即用的替代方案。

> **注意：**GitHub Models 已被棄用（2026 年 7 月退休），且不支持 Responses API。範例已更新為改用 Azure OpenAI / Microsoft Foundry。

## 初學者友善術語中的關鍵概念

### 工具

工具是代理可以呼叫以在模型外進行工作的東西。一個好的工具
有清晰的名稱、狹窄的職責、類型化的輸入、可預測的輸出，以及一個安全的
失敗方式。

對於課程助手示範，一個工具可能是：

- `search_lessons(query)`
- `read_lesson(path)`
- `create_practice_task(topic)`

### RAG 與知識

RAG 幫助代理從來源資料中回答問題，而不是猜測。在本
課程中，該來源資料可能是課程的 README、程式碼範例或外部
資源連結。

當答案應基於文件、數據或當前專案檔案時，請使用 RAG。


### 規劃

當請求包含多個步驟時，規劃非常有用。保持計劃短且
足夠清楚，讓開發者或使用者能檢查。

對示範來說，一個計劃可能是：

1. 查找與工具使用相關的課程。
2. 彙總最相關的課程內容。
3. 推薦一個實踐任務。

### 上下文

上下文是模型當下看到的資訊。上下文過少可能讓代理
遺漏重要細節。上下文過多則可能使代理變慢、成本增加，
或更容易混淆。

良好的上下文工程是為下一次模型呼叫挑選適當資訊。


### 記憶

記憶是為以後保存的信息。不要保存所有東西。僅在資訊有用、安全、
且易於更新或刪除時才保存。

例如，記住「學習者偏好 Python 範例」可能有用。
記住敏感個人資料通常則不應。

### 評估與可觀察性

評估問：代理做了正確的事嗎？

可觀察性問：我們能看到它是怎麼做的嗎？

對於生產環境代理，記錄模型呼叫、工具呼叫、檢索的上下文、
延遲、成本、失敗和使用者回饋。

### 信任與安全

可信的代理不只是有個有用的提示。使用最小權限工具、
對高影響行動採取人工批准、需要時進行資料篡改，以及對必須審核的
行動保留日誌或憑證。

## 15 分鐘複習流程

在每課後使用此流程：

1. **用一句話總結課程。**
2. **說出新的代理能力。** 例如：工具使用、檢索、
   規劃、記憶、可觀察性或安全性。
3. **將其加入課程助手示範。** 示範現在有什麼變化？
4. **找出風險。** 若濫用此能力可能出什麼問題？
5. **寫一個測試問題。** 如何檢查代理表現良好？

## 快速自我檢查

在繼續之前，試著回答以下問題：

1. 代理能做什麼是一般聊天機器人自己做不到的？
2. 你的代理第一個需要什麼工具？為什麼？
3. 代理的答案應基於什麼知識來源？
4. 下一次模型呼叫應該包含什麼上下文？

5. 代理應該記住甚麼，應避免存取甚麼？
6. 代理應該在甚麼時候尋求人類批准？
7. 甚麼樣的日誌、踪跡或收據能幫助您日後除錯或審計代理？


## 建議的畢業專案練習

在課程結束時，建立一個小型代理，幫助學習者瀏覽這個
倉庫。

最低版本：

- 接受使用者輸入的主題。
- 找出最相關的課程。
- 總結先閱讀的內容。
- 建議一個動手練習任務。
- 顯示使用過的課程檔案或連結。

延伸版本：

- 記住學習者偏好的程式語言。
- 回答前先使用簡單的計劃。
- 在最終回應前加入自我檢查步驟。
- 紀錄工具呼叫和檢索來源。
- 在開啟瀏覽器或使用介面自動化任務前請求確認。

這讓你在一個專案中，有一個小而實際的方法來練習工具、RAG、計劃、
上下文、記憶、可觀察性和信任。
