# ⚡ Kasabay-sabay na Mga Daloy ng Trabaho ng Ahente gamit ang Azure OpenAI (Responses API) (.NET)

## 📋 Tutorial sa Mataas na Pagganap na Parallel Processing

Ipinapakita ng notebook na ito ang **kasabay-sabay na mga pattern ng daloy ng trabaho** gamit ang Microsoft Agent Framework para sa .NET at Azure OpenAI (Responses API). Matututuhan mo kung paano bumuo ng mataas na pagganap, parallel na mga daloy ng trabaho na nagpapalaki ng throughput sa pamamagitan ng pagsasagawa ng maraming mga AI agent nang sabay-sabay habang pinananatili ang koordinasyon at pagkakapare-pareho ng datos.

## 💻 Pagpapatakbo ng Code

Ang kumpletong implementasyon ay makikita sa `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Ipinapakita ng file na ito ang isang **Fan-Out/Fan-In concurrent workflow** para sa pagpaplano ng paglalakbay:

### 🏗️ **Arkitektura ng Daloy ng Trabaho**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Pangunahing Mga Komponent:**

1. **ConcurrentStartExecutor**: Ipinapadala ang kahilingan ng user sa lahat ng agent nang sabay-sabay
2. **Researcher Agent**: Kasabay-sabay na nagsusuri ng mga destinasyon at atraksyon
3. **Planner Agent**: Kasabay-sabay na gumagawa ng detalyadong plano ng paglalakbay
4. **ConcurrentAggregationExecutor**: Nangongolekta at nagsasama-sama ng mga resulta mula sa parehong agent

### 🎯 **Fan-Out/Fan-In Pattern**

Ipinapakita ng workflow na ito ang klasikong **Fan-Out/Fan-In** na pattern:
- **Fan-Out**: Isang input message ang ipinalalaganap sa maraming agent nang sabay-sabay
- **Concurrent Processing**: Maraming agent ang nagtatrabaho nang parallel sa iisang gawain
- **Fan-In**: Kolektahin at pagsamahin ang mga resulta mula sa lahat ng agent sa isang output

### 🔍 Pag-unawa sa Custom Executors

**ConcurrentStartExecutor:**
- Nagpapatupad ng `IMessageHandler<string>` para tumanggap ng string input
- Nagpapadala ng mga mensahe sa lahat ng nakakonektang agent
- Nagpapadala ng `TurnToken` para simulan ang kasabay-sabay na pagproseso

**ConcurrentAggregationExecutor:**
- Nagpapatupad ng `IMessageHandler<ChatMessage>` para tumanggap ng mga tugon ng agent
- Nangongolekta ng mga mensahe sa thread-safe na paraan
- Nagsasama-sama kapag dumating na lahat ng inaasahang tugon
- Nagbibigay ng pangwakas na output gamit ang `context.YieldOutputAsync()`

### ⚡ Mga Benepisyo sa Performance

**Kasabay-sabay vs Sunod-sunod:**
- Sunod-sunod: Agent1 (30s) → Agent2 (30s) = **60 segundo lahat-lahat**
- Kasabay-sabay: Agent1 (30s) || Agent2 (30s) = **30 segundo lahat-lahat**

**Pagbuti sa Throughput**: Hanggang sa N× na mas mabilis para sa N kasabay-sabay na agent (depende sa workload at resources)

### 🛡️ Paghawak ng Error

Ang daloy ng trabaho ay maayos na humaharap sa pagkabigo ng indibidwal na agent:
- Kung isang agent ay mabigo, nagpapatuloy ang iba sa pagproseso
- Maaaring mag-implementa ng timeout logic ang aggregator
- Puwedeng ibalik ang partial results kung kinakailangan
