# ⚡ Sabayang Workflow ng Ahente gamit ang Azure OpenAI (Responses API) (.NET)

## 📋 Tutorial sa Mataas na Pagganap ng Parallel Processing

Ipinapakita ng notebook na ito ang **mga pattern ng sabayang workflow** gamit ang Microsoft Agent Framework para sa .NET at Azure OpenAI (Responses API). Matututuhan mo kung paano bumuo ng mataas na pagganap, parallel processing workflows na nagpapalaki ng throughput sa pamamagitan ng pagsasagawa ng maraming AI agent nang sabay-sabay habang pinapanatili ang koordinasyon at konsistensi ng datos.

## 💻 Patakbuhin ang Code

Ang kompletong implementasyon ay makikita sa `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Ipinapakita ng file na ito ang **Fan-Out/Fan-In sabayang workflow** para sa pagpaplano ng biyahe:

### 🏗️ **Arkitektura ng Workflow**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Pangunahing Mga Bahagi:**

1. **ConcurrentStartExecutor**: Pinapadala ang kahilingan ng user sa lahat ng ahente nang sabay-sabay
2. **Researcher Agent**: Sinasaliksik ang mga destinasyon at atraksyon nang sabay
3. **Planner Agent**: Gumagawa ng detalyadong mga plano sa paglalakbay nang sabay
4. **ConcurrentAggregationExecutor**: Kinokolekta at pinagsasama ang mga resulta mula sa parehong mga ahente

### 🎯 **Fan-Out/Fan-In Pattern**

Ipinapakita ng workflow na ito ang klasikong **Fan-Out/Fan-In** pattern:
- **Fan-Out**: Isang input message ang ipinapadala sa maraming ahente nang sabay
- **Concurrent Processing**: Maraming ahente ang nagtatrabaho nang parallel sa parehong gawain
- **Fan-In**: Kinokolekta at pinagsasama ang mga resulta mula sa lahat ng ahente sa isang output

### 🔍 Pag-unawa sa Custom Executors

**ConcurrentStartExecutor:**
- Nagpapatupad ng `IMessageHandler<string>` upang tanggapin ang string input
- Nagpapadala ng mga mensahe sa lahat ng nakakonektang ahente
- Nagpapadala ng `TurnToken` para pasimulan ang sabayang pagpoproseso

**ConcurrentAggregationExecutor:**
- Nagpapatupad ng `IMessageHandler<ChatMessage>` upang tumanggap ng mga sagot ng ahente
- Nangongolekta ng mga mensahe sa ligtas na pamamaraan para sa threads
- Nagsasama-sama kapag dumating na ang lahat ng inaasahang sagot
- Nagbibigay ng panghuling output gamit ang `context.YieldOutputAsync()`

### ⚡ Mga Benepisyo sa Performance

**Concurrent vs Sequential:**
- Sequential: Agent1 (30s) → Agent2 (30s) = **60 segundo kabuuan**
- Concurrent: Agent1 (30s) || Agent2 (30s) = **30 segundo kabuuan**

**Pagbuti sa Throughput**: Hanggang N× na mas mabilis para sa N sabayang ahente (depende sa workload at resources)

### 🛡️ Paghawak ng Error

Maayos na pinangangasiwaan ng workflow ang mga pagkabigo ng indibidwal na ahente:
- Kapag pumalya ang isang ahente, nagpapatuloy ang iba pang pagpoproseso
- Maaaring mag-implementa ang aggregator ng timeout logic
- Maaaring ibalik ang mga partial na resulta kung kinakailangan
