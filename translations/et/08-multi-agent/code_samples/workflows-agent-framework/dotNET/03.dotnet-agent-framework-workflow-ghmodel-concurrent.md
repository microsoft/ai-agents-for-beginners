# ⚡ Kõrge paralleelsusega agenditöövood Azure OpenAI-ga (Responses API) (.NET)

## 📋 Kõrge jõudlusega paralleeltöötluse juhend

See märkmik demonstreerib **samakõrgusel töötavate töövoomustrite** kasutamist Microsoft Agent raamistikuga .NET jaoks ja Azure OpenAI (Responses API). Õpid, kuidas ehitada kõrge jõudlusega paralleeltöötluse töövooge, mis maksimeerivad läbilaset, käivitades mitu tehisintellekti agenti samaaegselt ja säilitades samal ajal koordineerimise ning andmete järjepidevuse.

## 🎯 Õpieesmärgid

### 🚀 **Samakõrgusel töötamise alused**
- **Agendite paralleelne töö**: Käivita mitu tehisintellekti agenti samaaegselt maksimaalse jõudluse saavutamiseks
- **Async/Await mustrid**: Kasuta .NET-i asünkroonset programmeerimismudelit tõhusa samaaegse töö jaoks
- **Azure OpenAI (Responses API)**: Koordineeri mitu samaaegset kutsumist Azure OpenAI Responses API-le
- **Ressursside haldamine**: Haldada tõhusalt tehisintellekti mudelite ressursse samaaegsete toimingute vahel

### 🏗️ **Täpsem samaaegsuse arhitektuur**
- **Tööde baasil paralleelsus**: Kasuta .NET Task Parallel Library optimaalseks samaaegseks täitmiseks
- **Sünkroniseerimise mustrid**: Koordineeri samaaegseid agente, vältides võistlusstaatuseid
- **Koormuse tasakaalustamine**: Jaota tööd tõhusalt olemasoleva samaaegse töötlusvõime piires
- **Rikke taluvus**: Käsitle üksikute agentide tõrkeid ilma kogu töövoogu peatamata

### 🏢 **Ettevõtte samaaegsed rakendused**
- **Suurte dokumentide mahu töötlemine**: Töötle samaaegselt mitut dokumenti
- **Reaalajas sisuanalüüs**: Sissetulevate andmevoogude samaaegne analüüs

### 🏗️ **Töövoo arhitektuur**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Põhikomponendid:**

1. **ConcurrentStartExecutor**: Edastab kasutaja päringu kõigile agentidele samaaegselt
2. **Uurija agent**: Analüüsib sihtkohti ja vaatamisväärsusi samaaegselt
3. **Plaaneerija agent**: Koostab üksikasjalikke reisiplaane samaaegselt
4. **ConcurrentAggregationExecutor**: Kogub ja ühendab mõlema agendi tulemused

### 🎯 **Fan-Out/Fan-In muster**

See töövoog demonstreerib klassikalist **Fan-Out/Fan-In** mustrit:
- **Fan-Out**: Üks sisendsõnum levitatakse samaaegselt mitmele agendile
- **Samaealine töötlus**: Mitmed agendid töötavad paralleelselt sama ülesandega
- **Fan-In**: Kõigi agendite tulemused kogutakse ja koondatakse üheks väljundiks

### 🔍 Kohandatud täitjate mõistmine

**ConcurrentStartExecutor:**
- Rakendab `IMessageHandler<string>` vormindust string sisendi vastuvõtmiseks
- Levitatab sõnumeid kõigile ühendatud agentidele
- Saadab `TurnToken` samaaegse töötluse käivitamiseks

**ConcurrentAggregationExecutor:**
- Rakendab `IMessageHandler<ChatMessage>` agendi vastuste vastuvõtmiseks
- Kogub sõnumeid niidi-turvalisel viisil
- Kogub kokku, kui kõik oodatavad vastused saabuvad
- Tagastab lõpliku väljundi kasutades `context.YieldOutputAsync()`

### ⚡ Jõudluse eelised

**Samaaegne vs järjestikune:**
- Järjestikune: Agent1 (30s) → Agent2 (30s) = **kokku 60 sekundit**
- Samaealine: Agent1 (30s) || Agent2 (30s) = **kokku 30 sekundit**

**Läbilaskevõime paranemine**: Kuni N korda kiirem N samaaegse agendi puhul (sõltuvalt töökoormusest ja ressurssidest)
