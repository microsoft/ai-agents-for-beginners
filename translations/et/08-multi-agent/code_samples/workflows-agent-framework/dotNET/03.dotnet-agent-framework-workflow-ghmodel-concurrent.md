# ⚡ Koostööagentide töövood Azure OpenAI-ga (Responses API) (.NET)

## 📋 Kõrge jõudlusega paralleeltöötluse juhend

See märkmik demonstreerib **ühina töötavate töövoo mustreid** Microsoft Agent Frameworki .NET-i jaoks ja Azure OpenAI (Responses API) abil. Õpid, kuidas luua kõrge jõudlusega paralleelseid töövooge, mis maksimeerivad läbilaskevõimet, lastes mitmel tehisintellekti agendil samaaegselt töötada, säilitades samal ajal koordineerimise ja andmete järjepidevuse.

## 🎯 Õpieesmärgid

### 🚀 **Koostöötluse alused**
- **Agentide paralleelne käivitamine**: Käivita maksimaalse jõudluse saavutamiseks samaaegselt mitu tehisintellekti agenti
- **Async/Await mustrid**: Kasuta .NET-i async programmeerimisvõimalusi efektiivseks samaaegseks töötlemiseks
- **Azure OpenAI (Responses API)**: Koordineeri mitut samaaegset Azure OpenAI Responses API kõnet
- **Ressursside haldamine**: Juhi tõhusalt AI mudelite ressursse samaaegsete toimingute vältel

### 🏗️ **Täpsem samaaegsuste arhitektuur**
- **Töö põhine paralleelsus**: Kasuta .NET Task Parallel Libraryt optimaalseks samaaegseks täitmiseks
- **Sünkroniseerimise mustrid**: Koordineeri samaaegselt töötavaid agente, vältides konkurentsitingimusi
- **Koormuse tasakaalustamine**: Jaota töö tõhusalt saadaoleva samaaegse töötlusvõimekuse vahel
- **Vea taluvus**: Käitle üksikute agentide tõrkeid ilma töövoogu peatamata

### 🏢 **Ettevõtte samaaegsed rakendused**
- **Suurte dokumentide töötlemine**: Töötle samaaegselt mitut dokumenti
- **Reaalajas sisuanalüüs**: Sissetulevate andmevoogude samaaegne analüüs
- **Partiidena töötlemise optimeerimine**: Maksimeeri läbilaskevõimet suuremahuliste andmetöötlustsüklite puhul
- **Mitme-modaliteediga analüüs**: Paralleeltöötlus eri sisutüüpide ja formaatidega

## 💻 Koodi käivitamine

Täielik rakendus on saadaval failis `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. See fail demonstreerib **Fan-Out/Fan-In samaaegset töövoogu** reisi planeerimiseks:

### 🏗️ **Töövoo arhitektuur**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Põhikomponendid:**

1. **ConcurrentStartExecutor**: Levita kasutaja päring kõigile agentidele samaaegselt
2. **Researcher Agent**: Analüüsib sihtkohti ja vaatamisväärsusi samaaegselt
3. **Planner Agent**: Koostab üksikasjalikud reisi plaanid samaaegselt
4. **ConcurrentAggregationExecutor**: Kogub ja ühendab mõlema agendi tulemused

### 🎯 **Fan-Out/Fan-In muster**

See töövoog demonstreerib klassikalist **Fan-Out/Fan-In** mustrit:
- **Fan-Out**: Üks sisendteade levitatakse mitmele agendile samaaegselt
- **Samaaegne töötlemine**: Mitmed agentid töötavad paralleelselt sama ülesandega
- **Fan-In**: Kõigi agentide tulemused kogutakse ja koondatakse ühtseks väljundiks

### 🔍 Kohandatud täitjate mõistmine

**ConcurrentStartExecutor:**
- Rakendab `IMessageHandler<string>`, et vastu võtta tekstisisend
- Edastab sõnumeid kõigile ühendatud agentidele
- Saadab `TurnToken` samaaegse töötlemise käivitamiseks

**ConcurrentAggregationExecutor:**
- Rakendab `IMessageHandler<ChatMessage>`, et vastu võtta agentide vastuseid
- Kogub sõnumeid lõimeohutult
- Koondab, kui kõik oodatud vastused saabuvad
- Tagastab lõpliku väljundi `context.YieldOutputAsync()` abil

### ⚡ Jõudluse eelised

**Samaaegne vs Järjestikune:**
- Järjestikune: Agent1 (30s) → Agent2 (30s) = **kokku 60 sekundit**
- Samaaegne: Agent1 (30s) || Agent2 (30s) = **kokku 30 sekundit**

**Läbilaskevõime paranemine**: kuni N× kiirem N samaaegse agendi eest (sõltuvalt töökoormusest ja ressurssidest)
