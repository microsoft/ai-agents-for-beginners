# ⚡ Istovremeni radni tokovi agenata s Azure OpenAI (Responses API) (.NET)

## 📋 Tutorial visokoučinkovite paralelne obrade

Ovaj notebook demonstrira **uzorke istovremenih radnih tokova** koristeći Microsoft Agent Framework za .NET i Azure OpenAI (Responses API). Naučit ćete kako izgraditi visokoučinkovite radne tokove paralelne obrade koji maksimiziraju protok izvršavajući više AI agenata istovremeno uz održavanje koordinacije i dosljednosti podataka.

## 🎯 Ciljevi učenja

### 🚀 **Osnove istovremene obrade**
- **Paralelno izvršavanje agenata**: Pokrenite više AI agenata istovremeno za maksimalne performanse
- **Async/Await obrasci**: Iskoristite .NET-ov model asinkronog programiranja za učinkovitu konkurentnost
- **Azure OpenAI (Responses API)**: Koordinirajte više istovremenih poziva Azure OpenAI Responses API-ja
- **Upravljanje resursima**: Učinkovito upravljajte resursima AI modela u istovremenim operacijama

### 🏗️ **Napredna arhitektura konkurentnosti**
- **Task-based paralelizam**: Koristite .NET Task Parallel Library za optimalno istovremeno izvršavanje
- **Obrasci sinkronizacije**: Koordinirajte istovremene agente izbjegavajući race condition probleme
- **Ravnomjerna raspodjela opterećenja**: Učinkovito raspodijelite rad kroz dostupni kapacitet istovremene obrade
- **Otpornost na greške**: Rukovanje pojedinačnim neuspjesima agenata bez zaustavljanja cijelog radnog toka

### 🏢 **Poslovne aplikacije sa konkurentnošću**
- **Obrada velikog volumena dokumenata**: Obrada više dokumenata simultano
- **Analiza sadržaja u stvarnom vremenu**: Istovremena analiza dolaznih tokova podataka
- **Optimizacija grupne obrade**: Maksimizirajte protok za obradu podataka velikih razmjera
- **Višestruka modalna analiza**: Paralelna obrada različitih tipova i formata sadržaja

## 💻 Pokretanje koda

Cjelovita implementacija dostupna je u `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Ova datoteka demonstrira **Fan-Out/Fan-In istovremeni radni tok** za planiranje putovanja:

### 🏗️ **Arhitektura radnog toka**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Ključne komponente:**

1. **ConcurrentStartExecutor**: Istovremeno odašilje korisnički zahtjev svim agentima
2. **Researcher Agent**: Istovremeno analizira destinacije i atrakcije
3. **Planner Agent**: Istovremeno kreira detaljne planove putovanja
4. **ConcurrentAggregationExecutor**: Prikuplja i spaja rezultate od oba agenta

### 🎯 **Fan-Out/Fan-In obrazac**

Ovaj radni tok demonstrira klasični **Fan-Out/Fan-In** obrazac:
- **Fan-Out**: Jedna ulazna poruka se istovremeno odašilje više agenata
- **Istovremena obrada**: Više agenata paralelno radi na istom zadatku
- **Fan-In**: Rezultati svih agenata se prikupljaju i objedinuju u jedan izlaz

### 📝 Očekivani ispis

Radni tok će:

### 🎯 Primjene u stvarnim situacijama

Ovaj obrazac istovremenosti idealan je za:
- **Kreiranje sadržaja**: Više pisaca koji simultano pišu različite dijelove
- **Pregled koda**: Više recenzenata koji analiziraju kod iz različitih perspektiva
- **Istraživanje tržišta**: Paralelna analiza različitih tržišnih segmenata
- **Obrada dokumenata**: Istovremeno izvlačenje, analiza i validacija
- **Analiza iz više perspektiva**: Dobivanje različitih pogleda na isti ulaz

### 🔍 Razumijevanje prilagođenih izvršitelja

**ConcurrentStartExecutor:**
- Implementira `IMessageHandler<string>` za prihvat string ulaza
- Odašilje poruke svim povezanim agentima
- Šalje `TurnToken` za pokretanje istovremene obrade

**ConcurrentAggregationExecutor:**
- Implementira `IMessageHandler<ChatMessage>` za primanje odgovora agenata
- Prikuplja poruke na thread-safe način
- Agregira kada stignu svi očekivani odgovori
- Izlaz šalje koristeći `context.YieldOutputAsync()`

### ⚡ Prednosti performansi

**Istovremeno naspram sekvencijalnog:**
- Sekvencijalno: Agent1 (30s) → Agent2 (30s) = **ukupno 60 sekundi**
- Istovremeno: Agent1 (30s) || Agent2 (30s) = **ukupno 30 sekundi**

**Poboljšanje propusnosti**: Do N× brže za N istovremenih agenata (ovisno o opterećenju i resursima)

### 🛡️ Rukovanje pogreškama

Radni tok elegantno rukuje pojedinačnim neuspjesima agenata:
- Ako jedan agent zakaže, ostali nastavljaju s obradom
- Aggregator može implementirati logiku vremenskog ograničenja
- Djelomični rezultati mogu se vratiti ako je potrebno
