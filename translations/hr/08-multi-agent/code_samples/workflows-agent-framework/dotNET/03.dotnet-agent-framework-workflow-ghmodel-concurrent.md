# ⚡ Paralelni rad agenata s Azure OpenAI (Responses API) (.NET)

## 📋 Vodič za visokoučinkovito paralelno procesiranje

Ovaj bilježnik prikazuje **musterije paralelnih tijekova rada** koristeći Microsoft Agent Framework za .NET i Azure OpenAI (Responses API). Naučit ćete kako izgraditi visokoučinkovite tijekove rada za paralelno procesiranje koji maksimalno povećavaju propusnost pokretanjem više AI agenata istovremeno, uz održavanje koordinacije i dosljednosti podataka.

## 💻 Pokretanje koda

Cjelovita implementacija dostupna je u `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Ova datoteka prikazuje **Fan-Out/Fan-In paralelni tijek rada** za planiranje putovanja:

### 🏗️ **Arhitektura tijeka rada**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Ključne komponente:**

1. **ConcurrentStartExecutor**: Istovremeno šalje korisnički zahtjev svim agentima
2. **Researcher Agent**: Paralelno analizira destinacije i atrakcije
3. **Planner Agent**: Paralelno izrađuje detaljne planove putovanja
4. **ConcurrentAggregationExecutor**: Prikuplja i spaja rezultate oba agenta

### 🎯 **Fan-Out/Fan-In obrazac**

Ovaj tijek rada prikazuje klasični **Fan-Out/Fan-In** obrazac:
- **Fan-Out**: Jedna ulazna poruka se istovremeno šalje više agenata
- **Paralelno procesiranje**: Više agenata radi paralelno na istom zadatku
- **Fan-In**: Rezultati svih agenata se skupljaju i objedinjaju u jedan izlaz

### 🔍 Razumijevanje prilagođenih izvršitelja

**ConcurrentStartExecutor:**
- Implementira `IMessageHandler<string>` za prihvat string ulaza
- Emitira poruke svim povezanim agentima
- Šalje `TurnToken` za pokretanje paralelnog procesiranja

**ConcurrentAggregationExecutor:**
- Implementira `IMessageHandler<ChatMessage>` za primanje odgovora agenata
- Prikuplja poruke na thread-safe način
- Agregira kad svi očekivani odgovori stignu
- Generira konačni izlaz koristeći `context.YieldOutputAsync()`

### ⚡ Koristi za performanse

**Paralelno vs Sekvencijalno:**

- Sekvencijalno: Agent1 (30s) → Agent2 (30s) = **ukupno 60 sekundi**
- Istovremeno: Agent1 (30s) || Agent2 (30s) = **ukupno 30 sekundi**

**Poboljšanje propusnosti**: Do N× brže za N istovremenih agenata (ovisno o opterećenju i resursima)

### 🛡️ Rukovanje pogreškama

Radni tijek elegantno rukuje pojedinačnim kvarovima agenata:
- Ako jedan agent zakaže, ostali nastavljaju s obradom
- Agregator može implementirati logiku vremenskog ograničenja
- Djelomični rezultati se mogu vratiti po potrebi
