# ⚡ Istovremeni tijekovi rada agenta s Azure OpenAI (Responses API) (.NET)

## 📋 Vodič za visokoučinkovitu paralelnu obradu

Naučit ćete kako izgraditi visokoučinkovite tijekove rada za paralelnu obradu koji maksimiziraju propusnost izvršavajući više AI agenata istovremeno uz održavanje koordinacije i konzistencije podataka.

## 💻 Pokretanje koda

Cjelovita implementacija dostupna je u `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Ova datoteka demonstrira **Fan-Out/Fan-In konkurentni tijek rada** za planiranje putovanja:

### 🏗️ **Arhitektura tijeka rada**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Ključne komponente:**

1. **ConcurrentStartExecutor**: Istovremeno emitira korisnički zahtjev svim agentima
2. **Researcher Agent**: Paralelno analizira destinacije i atrakcije
3. **Planner Agent**: Paralelno izrađuje detaljne planove putovanja
4. **ConcurrentAggregationExecutor**: Prikuplja i spaja rezultate oba agenta

### 🎯 **Fan-Out/Fan-In obrazac**

Ovaj tijek rada demonstrira klasični **Fan-Out/Fan-In** obrazac:
- **Fan-Out**: Jedna ulazna poruka se istovremeno emitira višestrukim agentima
- **Istovremena obrada**: Više agenata paralelno radi na istom zadatku
- **Fan-In**: Rezultati svih agenata se prikupljaju i agregiraju u jedan izlaz

### 🔍 Razumijevanje prilagođenih izvršitelja

**ConcurrentStartExecutor:**
- Implementira `IMessageHandler<string>` za prihvat string ulaza
- Emitira poruke svim povezanim agentima
- Šalje `TurnToken` za pokretanje istovremene obrade

**ConcurrentAggregationExecutor:**
- Implementira `IMessageHandler<ChatMessage>` za primanje odgovora agenata
- Prikuplja poruke u thread-safe načinu
- Agregira kada stignu svi očekivani odgovori
- Generira konačni izlaz korištenjem `context.YieldOutputAsync()`

### ⚡ Prednosti performansi

**Istovremeno vs Sekvencijalno:**
- Sekvencijalno: Agent1 (30s) → Agent2 (30s) = **60 sekundi ukupno**
- Istovremeno: Agent1 (30s) || Agent2 (30s) = **30 sekundi ukupno**

**Poboljšanje propusnosti**: Do N× brže za N istovremenih agenata (ovisno o opterećenju i resursima)

### 🛡️ Rukovanje pogreškama

Tijekom rada se elegantno rukuju pojedinačni kvarovi agenta:
- Ako jedan agent zakaže, ostali nastavljaju obradu
- Agregator može implementirati timeout logiku
- Dijeljeni rezultati se mogu vratiti ako je potrebno
