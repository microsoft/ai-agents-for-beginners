# エージェンティックプロトコルの使用（MCP、A2A、NLWeb）

[![Agentic Protocols](../../../translated_images/ja/lesson-11-thumbnail.b6c742949cf1ce2a.webp)](https://youtu.be/X-Dh9R3Opn8)

> _(上記の画像をクリックして、このレッスンのビデオを視聴できます)_

AIエージェントの使用が増えるにつれて、標準化、安全性、オープンイノベーションの支援を保証するプロトコルの必要性も高まっています。このレッスンでは、そのニーズに応えるための3つのプロトコル - Model Context Protocol (MCP)、Agent to Agent (A2A)、およびNatural Language Web (NLWeb)を取り上げます。

## はじめに

このレッスンでは以下を学びます：

• <strong>MCP</strong>がAIエージェントに外部ツールやデータへのアクセスを可能にし、ユーザーのタスクを完了させる方法。

• <strong>A2A</strong>が異なるAIエージェント間の通信と協調を可能にする方法。

• <strong>NLWeb</strong>が自然言語インターフェースを任意のウェブサイトに導入し、AIエージェントがコンテンツを発見し対話できるようにする方法。

## 学習目標

• AIエージェントにおけるMCP、A2A、およびNLWebの基本的な目的と利点を<strong>識別する</strong>。

• 各プロトコルがLLM、ツール、その他のエージェント間のコミュニケーションと相互作用をどのように促進するかを<strong>説明する</strong>。

• 複雑なエージェンティックシステム構築において各プロトコルが果たす異なる役割を<strong>認識する</strong>。

## Model Context Protocol

<strong>Model Context Protocol (MCP)</strong>は、アプリケーションがLLMにコンテキストとツールを標準化された方法で提供するためのオープンスタンダードです。これにより、AIエージェントが一貫した方法で接続できる「ユニバーサルアダプター」が異なるデータソースやツールに対して機能するようになります。

MCPの構成要素、直接API使用と比較した利点、そしてAIエージェントがMCPサーバーをどのように使うかの例を見てみましょう。

### MCPのコアコンポーネント

MCPは<strong>クライアント-サーバーアーキテクチャ</strong>上で動作し、コアコンポーネントは以下のとおりです：

• <strong>ホスト</strong>はLLMアプリケーション（例えばVSCodeのようなコードエディタ）で、MCPサーバーへの接続を開始します。

• <strong>クライアント</strong>はホストアプリケーション内のコンポーネントで、サーバーとの一対一の接続を維持します。

• <strong>サーバー</strong>は特定の機能を公開する軽量プログラムです。

プロトコルには、MCPサーバーの機能である三つの主要なプリミティブが含まれています：

• <strong>ツール</strong>：AIエージェントが呼び出して動作を実行できる個別のアクションや機能です。例えば天気サービスは「天気を取得する」ツール、Eコマースサーバーは「商品を購入する」ツールを公開します。MCPサーバーはそれぞれのツール名、説明、入出力スキーマを機能リストで公開します。

• <strong>リソース</strong>：MCPサーバーが提供可能な読み取り専用のデータ項目やドキュメントで、クライアントは必要に応じて取得できます。ファイル内容、データベースレコード、ログファイルなどが例です。リソースはテキスト（コードやJSONなど）やバイナリ（画像やPDFなど）です。

• <strong>プロンプト</strong>：より複雑なワークフローを可能にするために、提案された入力テンプレートが事前定義されています。

### MCPの利点

MCPはAIエージェントに大きな利点を提供します：

• <strong>動的ツール検出</strong>：エージェントはサーバーから利用可能なツールのリストとその説明を動的に受け取れます。伝統的なAPIでは統合に静的なコーディングが必要なため、APIの変更ごとにコードの更新が求められますが、MCPは「一度統合」するだけで適応性を高めます。

• **異なるLLM間の相互運用性**：MCPは複数のLLMで動作し、パフォーマンス向上のためにコアモデルの切り替え柔軟性を提供します。

• <strong>標準化されたセキュリティ</strong>：MCPには標準の認証方式が含まれ、複数のMCPサーバー追加時のスケーラビリティを向上させます。これは伝統的なAPIの多数のキーや認証方式管理より簡単です。

### MCPの例

![MCP Diagram](../../../translated_images/ja/mcp-diagram.e4ca1cbd551444a1.webp)

たとえば、ユーザーがMCPを利用するAIアシスタントで航空券を予約したいとします。

1. <strong>接続</strong>：AIアシスタント（MCPクライアント）が航空会社が提供するMCPサーバーに接続します。

2. <strong>ツール検出</strong>：クライアントは航空会社のMCPサーバーに「どんなツールがありますか？」と問い合わせます。サーバーは「航空券検索」や「予約」などのツールを返答します。

3. <strong>ツール呼び出し</strong>：ユーザーが「ポートランドからホノルルへのフライトを検索してください」とAIアシスタントに依頼します。アシスタントはLLMを使い、「航空券検索」ツールを呼び出し、出発地や目的地のパラメーターをMCPサーバーに渡します。

4. <strong>実行と応答</strong>：MCPサーバーはラッパーとして航空会社の内部予約APIを実際に呼び出します。取得したフライト情報（例：JSONデータ）をAIアシスタントに返します。

5. <strong>追加のやり取り</strong>：AIアシスタントはフライト選択肢を提示し、ユーザーが選択すると、同じMCPサーバー上の「予約」ツールを呼び出して予約を完了します。

## Agent-to-Agentプロトコル (A2A)

MCPがLLMとツールの接続に焦点を当てる一方、<strong>Agent-to-Agent (A2A) プロトコル</strong>は一歩進めて異なるAIエージェント間の通信と協力を可能にします。A2Aは異なる組織、環境、技術スタックのAIエージェントを接続し、共通のタスクを完了します。

A2Aの構成要素と利点、そして旅行アプリケーションへの適用例を見ていきます。

### A2Aのコアコンポーネント

A2Aはエージェント間の通信を可能にし、ユーザーのサブタスクを協力して完了させることに着目しています。プロトコルの各要素はこれに貢献します：

#### エージェントカード

MCPサーバーがツールリストを共有するのに似て、エージェントカードは以下を含みます：
- エージェントの名前。
- 完了する一般的なタスクの<strong>説明</strong>。
- 他のエージェント（あるいは人間ユーザー）がいつなぜ呼び出すべきかを理解できるようにするための<strong>特定のスキル</strong>の一覧と説明。
- エージェントの<strong>現在のエンドポイントURL</strong>。
- ストリーミング応答やプッシュ通知などのエージェントの<strong>バージョン</strong>と<strong>機能</strong>。

#### エージェント実行者

エージェント実行者は、<strong>ユーザーチャットのコンテキストをリモートエージェントに渡す役割</strong>を持ち、リモートエージェントはこれにより完了すべきタスクを理解します。A2Aサーバーではエージェントが自らのLLMを使い、受信リクエストを解析し自身のツールでタスクを実行します。

#### アーティファクト

リモートエージェントがタスクを完了すると、その成果物はアーティファクトとして作成されます。アーティファクトは<strong>エージェントの作業結果</strong>、<strong>完了した内容の説明</strong>、およびプロトコルを通じて送信される<strong>テキストコンテキスト</strong>を含みます。送信後、リモートエージェントとの接続は次に必要になるまで閉じられます。

#### イベントキュー

このコンポーネントは<strong>更新の処理やメッセージ伝達</strong>に使われます。タスク完了に時間がかかる場合でも、エージェント間の接続が途中で閉じられないようにするため、生産環境のエージェンティックシステムに特に重要です。

### A2Aの利点

• <strong>強化されたコラボレーション</strong>：異なるベンダーやプラットフォームのエージェントが相互にやりとりし、コンテキストを共有し協力することで、従来は接続されていなかったシステム間の自動化を促進します。

• <strong>モデル選択の柔軟性</strong>：各A2Aエージェントは要求のサービスに使用するLLMを独自に選択できるため、各エージェントで最適化されたモデルやファインチューニングモデルを利用でき、MCPの一部シナリオで見られる単一LLM接続とは異なります。

• <strong>組み込み認証</strong>：A2Aプロトコルに直接認証機能が統合されており、エージェント間の強固なセキュリティフレームワークを提供します。

### A2Aの例

![A2A Diagram](../../../translated_images/ja/A2A-Diagram.8666928d648acc26.webp)

旅行予約のシナリオを拡張し、今回はA2Aを使います。

1. <strong>ユーザーの複合リクエスト</strong>：「来週ホノルルへのフライト、ホテル、レンタカーを含む全行程を予約してください」と「旅行代理店」A2Aクライアント／エージェントに依頼します。

2. <strong>旅行代理店によるオーケストレーション</strong>：複雑なリクエストを受けた旅行代理店は、LLMでタスクを推論し、専門化した他のエージェントと連携する必要があることを判断します。

3. <strong>エージェント間通信</strong>：旅行代理店はA2Aプロトコルを使い、「航空会社エージェント」「ホテルエージェント」「レンタカーエージェント」など、異なる企業が作成した下流エージェントに接続します。

4. <strong>タスクの委譲実行</strong>：旅行代理店はそれぞれの専門エージェントに具体的なタスク（「ホノルル行きのフライトを探す」「ホテルを予約する」「レンタカーを借りる」）を送信します。これらの専門エージェントは、それぞれのLLMと自身のツール（MCPサーバーを利用可能）を使って専用の処理を行います。

5. <strong>統合された応答</strong>：すべての下流エージェントがタスクを完了すると、旅行代理店は結果（フライト詳細、ホテル確認、レンタカー予約）をまとめ、チャット形式の総合回答をユーザーに返します。

## Natural Language Web (NLWeb)

ウェブサイトは長い間、インターネット上で情報やデータにアクセスする際の主要な方法です。

NLWebの構成要素、利点、そしてNLWebがどのように旅行アプリケーションで機能するかの例を見ていきます。

### NLWebの構成要素

- **NLWebアプリケーション（コアサービスコード）**：自然言語質問を処理するシステムで、プラットフォームの異なる部分を繋いで応答を生成します。ウェブサイトの自然言語機能を動かす<strong>エンジン</strong>のようなものです。

- **NLWebプロトコル**：ウェブサイトとの自然言語インタラクションのための<strong>基本ルールセット</strong>です。返答はJSON形式（多くはSchema.orgを使用）で返されます。これはHTMLがドキュメントを共有可能にしたのと同様に、「AIウェブ」の簡単な基盤を作ることを目的としています。

- **MCPサーバー（Model Context Protocolエンドポイント）**：各NLWeb設定は<strong>MCPサーバー</strong>としても機能します。これにより他のAIシステムと<strong>ツール（例：askメソッド）やデータを共有</strong>できます。実際には、ウェブサイトのコンテンツと能力がAIエージェントに使用可能になり、サイトがより広範な「エージェントエコシステム」の一部となります。

- <strong>埋め込みモデル</strong>：ウェブサイトのコンテンツを数値的表現（ベクトル＝埋め込み）に変換するモデルです。これらのベクトルは意味をコンピューターが比較検索できる形式で表現します。特殊なデータベースに保存され、利用者は使用する埋め込みモデルを選べます。

- **ベクトルデータベース（検索機構）**：このデータベースはウェブサイトコンテンツの埋め込みを保存します。質問が来るとNLWebはベクトルデータベースを検索して最も関連する情報を迅速に見つけ、類似度でランク付けされた回答候補のリストを返します。Qdrant、Snowflake、Milvus、Azure AI Search、Elasticsearchなど複数のベクトルストレージと連携します。

### NLWebの例

![NLWeb](../../../translated_images/ja/nlweb-diagram.c1e2390b310e5fe4.webp)

再度旅行予約サイトを考えますが、今回はNLWebが動力源となっています。

1. <strong>データ取り込み</strong>：既存の製品カタログ（フライト一覧、ホテル説明、ツアーパッケージなど）がSchema.orgでフォーマットされるかRSS経由でロードされます。NLWebのツールがこの構造化データを取り込み、埋め込みを作成してローカルまたはリモートのベクトルデータベースに保存します。

2. **自然言語クエリ（ユーザー）**：ユーザーはサイトを訪れ、メニューをナビゲートせずにチャットインターフェースに「来週ホノルルでプール付きの家族向けホテルを探して」と入力します。

3. **NLWeb処理**：NLWebアプリはこのクエリを受け取り、LLMに理解を依頼しながら、同時にベクトルデータベースで関連ホテルリストを検索します。

4. <strong>正確な結果</strong>：LLMはデータベース検索結果を解釈し、「家族向け」「プール」「ホノルル」という条件に基づく最適なマッチを特定し、自然言語の応答に整形します。重要なのは、実際のホテル情報を参照し、架空の情報を避けている点です。

5. **AIエージェントの連携**：NLWebがMCPサーバーとして機能するため、外部のAI旅行エージェントもこのウェブサイトのNLWebに接続でき、`ask` MCPメソッドを使って直接問い合わせることができます。例：`ask("ホノルルのホテルが推薦するビーガン対応レストランはありますか？")`。NLWebはレストラン情報のデータベース（読み込まれていれば）を活用し、構造化されたJSONの応答を返します。
