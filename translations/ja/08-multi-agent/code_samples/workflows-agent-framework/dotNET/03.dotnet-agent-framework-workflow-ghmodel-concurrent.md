## 💻 コードの実行

完全な実装は `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs` にあります。このファイルは旅行計画向けの<strong>Fan-Out/Fan-In 並行ワークフロー</strong>を示しています：

### 🏗️ <strong>ワークフローアーキテクチャ</strong>

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**主要コンポーネント：**

1. **ConcurrentStartExecutor**：ユーザーリクエストを全エージェントに同時にブロードキャスト
2. **Researcher Agent**：行き先とアトラクションを並行で分析
3. **Planner Agent**：詳細な旅行計画を並行で作成
4. **ConcurrentAggregationExecutor**：両エージェントからの結果を収集・統合

### 🎯 **Fan-Out/Fan-Inパターン**

このワークフローは標準的な<strong>Fan-Out/Fan-In</strong>パターンを示します：
- **Fan-Out**：入力メッセージ1つを複数のエージェントに同時にブロードキャスト
- <strong>並行処理</strong>：複数のエージェントが同一タスクを並列で処理
- **Fan-In**：全エージェントの結果を集約し単一の出力にまとめる

### 🔍 カスタムExecutorの理解

**ConcurrentStartExecutor：**
- `IMessageHandler<string>`を実装し文字列入力を受け入れ
- 接続されたすべてのエージェントにメッセージをブロードキャスト
- 並行処理を開始するために`TurnToken`を送信

**ConcurrentAggregationExecutor：**
- `IMessageHandler<ChatMessage>`を実装しエージェント応答を受信
- スレッドセーフなメッセージ収集
- すべての期待応答到着時に集約を実行
- `context.YieldOutputAsync()`で最終出力を返す

### ⚡ パフォーマンス効果

**並行処理と逐次処理の比較：**
- 逐次：Agent1（30秒）→ Agent2（30秒）= **合計60秒**
- 並行：Agent1（30秒）|| Agent2（30秒）= **合計30秒**

<strong>スループット向上</strong>：Nの並行エージェントで最大N倍高速（負荷とリソースによる）

### 🛡️ エラー処理

ワークフローは個別エージェントの失敗を優雅に処理します：
- 1エージェントの失敗時も他エージェントは処理継続
- 集約者はタイムアウトロジックを実装可能
- 必要に応じて部分結果を返却可能
