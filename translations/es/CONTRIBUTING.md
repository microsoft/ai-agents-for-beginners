# Contribuyendo

Este proyecto acepta contribuciones y sugerencias. La mayoría de las contribuciones requieren que aceptes un Acuerdo de Licencia de Contribuyente (CLA) que declara que tienes el derecho y realmente otorgas los derechos para que usemos tu contribución. Para más detalles, visita <https://cla.opensource.microsoft.com>.

Cuando envías una solicitud de extracción, un bot CLA determinará automáticamente si necesitas proporcionar un CLA y adornará la solicitud de extracción según corresponda. Sigue las instrucciones proporcionadas por el bot. Solo necesitarás hacer esto una vez en los repositorios que usan el CLA de Microsoft.

## Código de Conducta

Este proyecto ha adoptado el [Código de Conducta de Código Abierto de Microsoft](https://opensource.microsoft.com/codeofconduct/). Para más información, consulta las [Preguntas frecuentes del Código de Conducta](https://opensource.microsoft.com/codeofconduct/faq/) o contacta a [opencode@microsoft.com](mailto:opencode@microsoft.com) con preguntas o comentarios adicionales.

## Directrices para solicitudes de extracción

- Mantén cada solicitud de extracción enfocada en un cambio lógico.
- Prueba los notebooks y ejemplos de código afectados antes de enviar.
- Actualiza la documentación relevante de la lección al añadir o cambiar un ejemplo.
- Edita solo el contenido fuente en inglés. Las traducciones se mantienen mediante el flujo de trabajo automatizado de traducción.
- No confirmes credenciales, archivos `.env`, archivos temporales, ni artefactos generados de desarrollo.

## Alcance editorial y productos de terceros

Este plan de estudios se enfoca en tecnologías de Microsoft y estándares abiertos neutrales al proveedor. Las contribuciones deben tener un propósito educativo claro y no deben estar principalmente destinadas a introducir o promover un producto comercial de un tercero, un servicio alojado, un enrutador modelo, un SDK, un servidor MCP u otra oferta específica de un proveedor.

Se pueden referenciar software de código abierto y dependencias de terceros cuando son necesarios para explicar un estándar abierto o un escenario de interoperabilidad, se presentan de manera neutral y no están centrados en un producto o punto final alojado de un proveedor. Si tu contribución propuesta incluye un producto o servicio específico de un proveedor, abre un issue y obtén la aprobación del mantenedor antes de enviar una solicitud de extracción.

Los contribuyentes deben divulgar cualquier empleo, propiedad, patrocinio u otra afiliación relevante con un producto o servicio referenciado en su contribución. No incluyas afirmaciones no respaldadas sobre precios, rendimiento, seguridad, privacidad o comparaciones. Los ejemplos ejecutables no deben transmitir datos de los estudiantes ni realizar acciones públicas mediante un servicio externo de terceros por defecto.
