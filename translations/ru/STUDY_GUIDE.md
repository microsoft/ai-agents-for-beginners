# AI Агентов для начинающих - Руководство по изучению

Используйте это руководство как практическое пособие, пока проходите курс. Оно
не предназначено для замены уроков. Оно помогает решить, с чего начать, на что
обратить внимание в каждом уроке и как связать идеи в небольшой рабочий демонстрационный
агент.

Если вы здесь впервые, начинайте с простого:

1. Прочитайте [Настройка курса](./00-course-setup/README.md).
2. Пройдите уроки 01-06 в порядке.
3. Держите в голове одну небольшую идею для демонстрации, пока учитесь.
4. После каждого урока задайте вопрос: "Что теперь мой агент может делать, чего
   не мог раньше?"

## Простая демонстрация, чтобы держать в голове

Хороший способ изучить агентов — следовать одной идее демонстрации в течение курса.

Пример демонстрации: **помощник курса**.

Пользователь запрашивает:

> "Я хочу узнать, как агенты используют инструменты. Найди нужные уроки, суммируй,
> что мне стоит прочесть в первую очередь, и дай мне короткое практическое задание."

Обычный чатбот отвечает из того, что он уже знает. Агент может больше:

1. **Читать или искать в файлах курса**, чтобы найти нужные уроки.
2. **Использовать инструменты** для получения ссылок на уроки, примеров или вспомогательных материалов.
3. **Планировать** короткий путь обучения вместо одного длинного ответа.
4. **Использовать контекст** текущего разговора, чтобы оставаться сфокусированным на
   цели ученика.
5. **Запоминать полезные предпочтения**, если приложение поддерживает память.
6. **Показывать следы, цитаты или журналы**, чтобы пользователь мог понять, что произошло.
7. **Применять защитные меры** перед выполнением рискованных действий или использованием чувствительных данных.

По мере изучения каждого урока возвращайтесь к этой демонстрации и спрашивайте: какую
новую возможность добавит этот урок?

## К чему вы стремитесь

К концу курса вы должны уметь объяснять и строить агентские системы, которые сочетают
эти части:

| Части | Значение простыми словами | В демонстрации |
|-------|--------------------------|---------------|
| Модель | Движок рассуждений, который интерпретирует запрос пользователя | Понимает, что ученик хочет уроки по использованию инструментов |
| Инструменты | Функции, API, файлы, браузеры или сервисы, которые агент может использовать | Ищет в репозитории или извлекает содержание уроков |
| Знания | Документы или данные для обоснования ответа | README курсов и материалы уроков |
| Контекст | Информация, включаемая в следующий вызов модели | Цель пользователя и результаты от инструментов |
| Память | Информация, сохранённая для последующего использования | Ученик предпочитает практические примеры на Python |
| Планирование | Разбиение большой цели на меньшие шаги | Найти уроки, суммировать их, предложить практику |
| Оркестровка | Распределение работы между инструментами, шагами или агентами | Планировщик вызывает поисковый инструмент, затем сумматор |
| Доверие | Безопасность, охрана, оценка и наблюдаемость | Журналы вызовов инструментов и запрос на разрешение перед действиями с большим влиянием |

## Модели и провайдеры

Примеры кода курса используют **Microsoft Agent Framework (MAF)** и ориентированы на **Azure OpenAI Responses API** — рекомендованный для дальнейшего использования API, который объединяет чат-ответы, вызов инструментов, мультимодальный ввод и сохранение состояния разговора в одном API. Вы подключаетесь либо через проект **Microsoft Foundry** (с `FoundryChatClient`), либо напрямую к Azure OpenAI (с `OpenAIChatClient`).

По мере работы с уроками у вас есть несколько вариантов провайдеров:

- **Microsoft Foundry / Azure OpenAI (Responses API)** — основной путь, используемый во всех уроках. Выполните вход с помощью `az login` для безключевой аутентификации Entra ID.
- **Foundry Local** — запуск моделей полностью на устройстве через совместимый с OpenAI API (без облака, без API-ключей). Идеально для офлайн или бесплатных экспериментов. См. [Настройка курса](./00-course-setup/README.md).
- **MiniMax** — совместимый с OpenAI провайдер с моделями большого контекста, используемый как замена "drop-in".

> **Примечание:** GitHub Models устарел (вывод из эксплуатации в июле 2026) и не поддерживает Responses API. Примеры были обновлены для использования Azure OpenAI / Microsoft Foundry.

## Основные идеи простыми словами

### Инструменты

Инструмент — это то, что агент может вызвать для выполнения работы вне модели. Хороший инструмент
имеет понятное название, узкую задачу, типизированные входные данные, предсказуемый результат и безопасный способ
отказа.

Для демонстрации помощника курса инструментом может быть:

- `search_lessons(query)`
- `read_lesson(path)`
- `create_practice_task(topic)`

### RAG и знания

RAG помогает агенту отвечать на основе исходного материала, а не гадать. В этом
курсе таким исходным материалом могут быть README уроков, примеры кода или внешние
ресурсы, указанные в уроках.

Используйте RAG, когда ответ должен основываться на документах, данных или текущих
файлах проекта.

### Планирование

Планирование полезно, когда запрос включает несколько шагов. Держите планы короткими и
достаточно прозрачными, чтобы разработчик или пользователь мог их проверить.

Для демонстрации план может выглядеть так:

1. Найти уроки, связанные с использованием инструмента.
2. Подытожить наиболее релевантные уроки.
3. Рекомендовать одно практическое задание.

### Контекст

Контекст — это то, что модель видит прямо сейчас. Слишком мало контекста может заставить агента
пропустить важные детали. Слишком много контекста может сделать агента медленнее, дороже,
или легче запутаться.

Хорошая работа с контекстом означает выбор правильной информации для следующего вызова модели.


### Память

Память — это информация, сохранённая для последующего использования. Не сохраняйте всё подряд. Сохраняйте информацию
только если она полезна, безопасна и её легко обновить или удалить.

Например, полезно помнить, что "учащийся предпочитает примеры на Python".
Помнить чувствительные личные данные обычно не стоит.

### Оценка и наблюдаемость

Оценка спрашивает: сделал ли агент правильное действие?

Наблюдаемость спрашивает: можем ли мы увидеть, как это произошло?

Для производственных агентов отслеживайте вызовы модели, вызовы инструментов, полученный контекст,
задержки, затраты, ошибки и отзывы пользователей.

### Доверие и безопасность

Надежным агентам нужно больше, чем просто полезный запрос. Используйте инструменты с минимально необходимыми правами,
одобрение человеком для действий с большим воздействием, редактирование данных там, где это нужно, и логи или
чеки для действий, которые нужно аудировать.

## 15-минутная процедура обзора

Используйте эту процедуру после каждого урока:

1. **Сформулируйте урок в одном предложении.**
2. **Назовите новую способность агента.** Например: использование инструмента, получение информации,
   планирование, память, наблюдаемость или безопасность.
3. **Добавьте её в демонстрацию помощника курса.** Что меняется в демонстрации теперь?
4. **Найдите риск.** Что может пойти не так, если эта способность будет неправильно использована?
5. **Напишите один тестовый вопрос.** Как вы проверите, что агент ведёт себя правильно?

## Быстрая самопроверка

Прежде чем продолжить, попробуйте ответить на эти вопросы:

1. Что агент может сделать такого, чего обычный чатбот не может сделать самостоятельно?
2. Какой инструмент вашему агенту понадобится в первую очередь и почему?
3. Какой источник знаний должен служить основой для ответа агента?
4. Какой контекст должен быть включён в следующий вызов модели?

5. Что агент должен запоминать, а что следует избегать сохранять?
6. Когда агент должен запрашивать одобрение человека?
7. Какие логи, трассировки или квитанции помогут вам позже отладить или проверить агента?


## Предлагаемое итоговое задание

В конце курса создайте небольшого агента, который поможет учащемуся ориентироваться в этом
репозитории.

Минимальная версия:

- Принимать тему от пользователя.
- Находить наиболее релевантные уроки.
- Суммировать, что читать в первую очередь.
- Предлагать одно практическое задание.
- Показывать, какие файлы уроков или ссылки были использованы.

Расширенная версия:

- Запоминать предпочитаемый учащимся язык программирования.
- Использовать простой план перед ответом.
- Добавлять проверочный шаг перед финальным ответом.
- Вести журнал вызовов инструментов и найденных источников.
- Запрашивать подтверждение перед открытием браузера или выполнением задач автоматизации UI.

Это даст небольшой, но реалистичный способ попрактиковаться с инструментами, RAG, планированием,
контекстом, памятью, наблюдаемостью и доверием в одном проекте.
