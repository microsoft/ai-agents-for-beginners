## 💻 Запуск кода

Полная реализация доступна в файле `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Этот файл демонстрирует **параллельный рабочий процесс Fan-Out/Fan-In** для планирования путешествий:

### 🏗️ **Архитектура рабочего процесса**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Ключевые компоненты:**

1. **ConcurrentStartExecutor**: Одновременная трансляция запроса пользователя всем агентам
2. **Researcher Agent**: Параллельный анализ направлений и достопримечательностей
3. **Planner Agent**: Параллельное создание детальных планов путешествий
4. **ConcurrentAggregationExecutor**: Сбор и объединение результатов от обоих агентов

### 🎯 **Паттерн Fan-Out/Fan-In**

Этот рабочий процесс демонстрирует классический паттерн **Fan-Out/Fan-In**:
- **Fan-Out**: Одно входное сообщение транслируется нескольким агентам одновременно
- **Параллельная обработка**: Несколько агентов работают параллельно над одной задачей
- **Fan-In**: Результаты всех агентов собираются и агрегируются в единый выходной результат

Рабочий процесс будет:

2. **Параллельная обработка**: Оба агента работают одновременно:

### 🎯 Реальные применения

Этот параллельный паттерн идеален для:
- **Создание контента**: Несколько авторов одновременно пишут разные разделы
- **Код-ревью**: Несколько рецензентов анализируют код с разных точек зрения
- **Маркетинговые исследования**: Параллельный анализ различных сегментов рынка
- **Обработка документов**: Параллельное извлечение, анализ и проверка
- **Анализ с разных точек зрения**: Получение разных мнений по одному входу

### 🔍 Понимание пользовательских исполнителей

**ConcurrentStartExecutor:**
- Реализует `IMessageHandler<string>` для приёма строкового ввода
- Транслирует сообщения всем подключённым агентам
- Отправляет `TurnToken` для запуска параллельной обработки

**ConcurrentAggregationExecutor:**
- Реализует `IMessageHandler<ChatMessage>` для приёма ответов агентов
- Собирает сообщения в потокобезопасной манере
- Выполняет агрегацию при поступлении всех ожидаемых ответов
- Возвращает итоговый результат через `context.YieldOutputAsync()`

### ⚡ Преимущества производительности

**Параллельность vs Последовательность:**
- Последовательно: Agent1 (30с) → Agent2 (30с) = **всего 60 секунд**
- Параллельно: Agent1 (30с) || Agent2 (30с) = **всего 30 секунд**

**Увеличение пропускной способности**: До N× быстрее при N параллельных агентах (в зависимости от нагрузки и ресурсов)

### 🛡️ Обработка ошибок

Рабочий процесс корректно обрабатывает сбои отдельных агентов:
- Если один агент выходит из строя, остальные продолжают работу
- Агрегатор может реализовать логику таймаута
- При необходимости могут возвращаться частичные результаты

### 📊 Продвинутые возможности

**Динамическое количество агентов:**

```csharp
private readonly List<ChatMessage> _messages = [];

public override async ValueTask HandleAsync(List<ChatMessage> message, IWorkflowContext context, CancellationToken cancellationToken = default)
{
    this._messages.AddRange(message);
    if (this._messages.Count == _expectedAgentCount)
    {
        // Process aggregation
    }
}
```
