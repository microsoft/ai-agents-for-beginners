## 💻 Запуск кода

Полная реализация доступна в файле `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Этот файл демонстрирует **параллельный рабочий процесс Fan-Out/Fan-In** для планирования путешествия:

### 🏗️ **Архитектура рабочего процесса**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Ключевые компоненты:**

1. **ConcurrentStartExecutor**: Одновременная передача запроса пользователя всем агентам
2. **Researcher Agent**: Параллельный анализ направлений и достопримечательностей
3. **Planner Agent**: Параллельное создание детальных планов путешествия
4. **ConcurrentAggregationExecutor**: Сбор и объединение результатов обоих агентов

### 🎯 **Паттерн Fan-Out/Fan-In**

Этот рабочий процесс демонстрирует классический паттерн **Fan-Out/Fan-In**:
- **Fan-Out**: Один входящий запрос распространяется на несколько агентов одновременно
- **Параллельная обработка**: Несколько агентов работают параллельно над одной задачей
- **Fan-In**: Результаты от всех агентов собираются и агрегируются в единый выходной результат

### 🔍 Понимание пользовательских исполнителей (Executors)

**ConcurrentStartExecutor:**
- Реализует `IMessageHandler<string>` для приема строкового ввода
- Рассылает сообщения всем подключенным агентам
- Отправляет `TurnToken` для запуска параллельной обработки

**ConcurrentAggregationExecutor:**
- Реализует `IMessageHandler<ChatMessage>` для приема ответов агентов
- Собират сообщения потокобезопасно
- Агрегирует после получения всех ожидаемых ответов
- Возвращает конечный результат с помощью `context.YieldOutputAsync()`

### ⚡ Преимущества производительности

**Параллельное vs последовательное:**
- Последовательное: Агент1 (30с) → Агент2 (30с) = **60 секунд всего**
- Параллельное: Агент1 (30с) || Агент2 (30с) = **30 секунд всего**

**Улучшение пропускной способности**: До N раз быстрее для N параллельных агентов (зависит от нагрузки и ресурсов)

### 🛡️ Обработка ошибок

Рабочий процесс корректно обрабатывает сбои отдельных агентов:
- Если один агент падает, другие продолжают работу
- Агрегатор может реализовать логику таймаута
- При необходимости возвращаются частичные результаты
