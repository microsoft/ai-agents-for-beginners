# Примеры квитанций

Три предварительно сгенерированных файла квитанций для просмотра без запуска ноутбука.

| Файл | Что это такое |
|---|---|
| `01_valid_receipt.json` | Действительная подписанная квитанция для вызова инструмента `lookup_flights`. Проверка возвращает True. |
| `02_tampered_receipt.json` | Та же квитанция с одним изменённым полем после подписи. Проверка возвращает False. |
| `03_chain_three_receipts.json` | Цепочка из трёх действительных квитанций (поиск, бронь, оформление), связанных полем `previous_receipt_hash` друг с другом. |

В этих примерах подпись создаётся непосредственно по каноническим байтам JCS полезной нагрузки с помощью Ed25519.
SHA-256 по-прежнему используется для дайджестов содержимого и ссылки на цепочку квитанций, но не как
дополнительный предварительный хэш перед подписью.

## Проверка образцов

В ноутбуке процесс проверки рассматривается в четырёх разделах. Чтобы проверить эти примеры
напрямую без прохождения материала ноутбука:

```python
import json
from pathlib import Path

# Предполагается, что вы завершили импорты и вспомогательные функции
# из разделов 1 и 2 файла 18-signed-receipts.ipynb.

valid = json.loads(Path("01_valid_receipt.json").read_text())
print(f"Valid receipt: {verify_receipt(valid)}")        # Истина

tampered = json.loads(Path("02_tampered_receipt.json").read_text())
print(f"Tampered receipt: {verify_receipt(tampered)}")  # Ложь

chain = json.loads(Path("03_chain_three_receipts.json").read_text())
for r in verify_chain(chain):
    print(f"  Receipt {r['index']} ({r['tool']}): {'VALID' if r['overall_valid'] else 'INVALID'}")
```

## Как они были сгенерированы

Примеры используют тот же путь кода, что и ноутбук, с одним фиксированным ключом подписи
и фиксированными метками времени для воспроизводимости байтов. Чтобы сгенерировать заново:

```bash
python3 generate_fixtures.py
```

(Скрипт находится в `generate_fixtures.py` в этой директории.)

## Чему учатся студенты, изучая сырой JSON

Чтение сырого формата квитанций формирует интуицию, которой не всегда хватает в ячейках ноутбука.
Студенты, которые быстро просматривают JSON, часто замечают:

1. Подпись — это непрозрачная строка в base64url, но все остальные поля — обычный
   читаемый JSON. Подпись не шифрует содержимое, она его подтверждает.
2. `public_key` встроен в квитанцию. Аудитору ничего больше не нужно
   для проверки (при условии доверия к тому, что ключ действительно принадлежит заявленному
   издателю; см. README к уроку по инфраструктуре удостоверения личности).
3. Изменение одного символа в любом поле, а затем повторное сравнение с файлом
   `02_tampered_receipt.json` делает механизм на уровне байтов наглядным.
