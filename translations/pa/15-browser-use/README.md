# ਕੰਪਿਊਟਰ ਉਪਯੋਗ ਏਜੰਟ (CUA) ਬਣਾਉਣਾ

ਕੰਪਿਊਟਰ ਉਪਯੋਗ ਏਜੰਟ ਵੈੱਬਸਾਈਟਾਂ ਨਾਲ ਉਹੀ ਤਰੀਕੇ ਨਾਲ ਇੰਟਰਐਕਟ ਕਰ ਸਕਦੇ ਹਨ ਜਿਵੇਂ ਕੋਈ ਵਯਕਤੀ ਕਰਦਾ ਹੈ: ਬ੍ਰਾਊਜ਼ਰ ਖੋਲ੍ਹ ਕੇ, ਪੰਨਾ ਜाँच ਕੇ, ਅਤੇ ਜੋ ਉਨ੍ਹਾਂ ਨੂੰ nazar ਆਉਂਦਾ ਹੈ ਉਸ ਤੋਂ ਅਗਲਾ ਸਭ ਤੋਂ ਚੰਗਾ ਕਾਰਵਾਈ ਕਰ ਕੇ। ਇਸ ਪਾਠ ਵਿੱਚ, ਤੁਸੀਂ ਇੱਕ ਬ੍ਰਾਊਜ਼ਰ ਆਟੋਮੇਸ਼ਨ ਏਜੰਟ ਬਣਾਓਗੇ ਜੋ Airbnb 'ਤੇ ਖੋਜ ਕਰਦਾ ਹੈ, ਢਾਂਚਾਬੱਧ ਸੂਚੀ ਡੇਟਾ ਨਿਕਾਲਦਾ ਹੈ, ਅਤੇ ਸਟੋਕਹੋਮ ਵਿੱਚ ਸਭ ਤੋਂ ਸਸਤੀ ਰਹਿਣ ਦੀ ਪਹਚਾਣ ਕਰਦਾ ਹੈ।

ਇਹ ਪਾਠ AI-ਚਲਿਤ ਨੈਵੀਗੇਸ਼ਨ ਲਈ Browser-Use, ਬ੍ਰਾਊਜ਼ਰ ਕੰਟਰੋਲ ਲਈ Playwright ਅਤੇ Chrome DevTools Protocol (CDP), ਦਰਸ਼ਨ-ਸਰਗਰਮ ਸੋਚਣ ਲਈ Azure OpenAI, ਅਤੇ ਢਾਂਚਾ ਨਿਕਾਸੀ ਲਈ Pydantic ਦਾ ਸੰਗਮ ਕਰਦਾ ਹੈ।

## ਪਰਿਚਯ

ਇਹ ਪਾਠ ਇਹ ਸਿਖਾਏਗਾ:

- ਸਮਝਣਾ ਕਦੋਂ ਕੰਪਿਊਟਰ ਉਪਯੋਗ ਏਜੰਟ API-ਕੇਵਲ ਆਟੋਮੇਸ਼ਨ ਨਾਲੋਂ ਵਧੀਆ ਹੁੰਦੇ ਹਨ
- ਭਰੋਸੇਯੋਗ ਬ੍ਰਾਊਜ਼ਰ ਜੀਵਨ ਚੱਕਰ ਪ੍ਰਬੰਧਨ ਲਈ Browser-Use ਨੂੰ Playwright ਅਤੇ CDP ਨਾਲ ਜੋੜਨਾ
- Azure OpenAI ਵਿਜ਼ਨ ਅਤੇ ਢਾਂਚਾਬੱਧ Pydantic ਆਉਟਪੁੱਟ ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਡਾਈਨਾਮਿਕ ਵੈੱਬ ਪੰਨਿਆਂ ਤੋਂ ਸੂਚੀ ਡੇਟਾ ਕੱਢਣਾ
- ਇਹ ਫੈਸਲਾ ਕਰਨਾ ਕਿ ਕਦੋਂ ਏਜੰਟ-ਪਹਿਲਾਂ, ਅਦਾਕਾਰ-ਪਹਿਲਾਂ, ਜਾਂ ਹਾਈਬ੍ਰਿਡ ਬ੍ਰਾਊਜ਼ਰ ਆਟੋਮੇਸ਼ਨ ਵਰਕਫਲੋ ਦੀ ਵਰਤੋਂ ਕਰਨੀ ਹੈ

## ਸਿੱਖਣ ਦੇ ਲਕੜੀ

ਇਸ ਪਾਠ ਨੂੰ ਪੂਰਾ ਕਰਨ ਤੋਂ ਬਾਅਦ, ਤੁਸੀਂ ਕਿਵੇਂ ਜਾਣੋਗੇ:

- Azure OpenAI ਅਤੇ Playwright ਨਾਲ Browser-Use ਨੂੰ ਸੰਰਚਿਤ ਕਰਨਾ
- ਇੱਕ ਬ੍ਰਾਊਜ਼ਰ ਆਟੋਮੇਸ਼ਨ ਵਰਕਫਲੋ ਬਣਾਉਣਾ ਜੋ ਇੱਕ ਅਸਲੀ ਵੈੱਬਸਾਈਟ ਨੂੰ ਨੈਵੀਗੇਟ ਕਰਦਾ ਹੈ ਅਤੇ ਡਾਇਨਾਮਿਕ UI ਤੱਤਾਂ ਨੂੰ ਸੰਭਾਲਦਾ ਹੈ
- ਦਿੱਖ ਰਹੇ ਪੰਨੇ ਦੇ ਸਮੱਗਰੀ ਤੋਂ ਟਾਈਪ ਕੀਤੇ ਨਤੀਜੇ ਕੱਢਣਾ ਅਤੇ ਉਨ੍ਹਾਂ ਨੂੰ ਅੱਗੇ ਦੇ ਵਪਾਰ ਲੋੜਾਂ ਵਿੱਚ ਬਦਲਣਾ
- ਬ੍ਰਾਊਜ਼ਰ ਕੰਮ ਦੀ ਪੇਸ਼ਗੋਈ ਅਨੁਸਾਰ ਏਜੰਟ ਅਤੇ ਅਦਾਕਾਰ ਕਾਰਜਪ੍ਰਣਾਲੀ ਵਿਚੋਂ ਚੋਣ ਕਰਨਾ

## ਕੋਡ ਉਦਾਹਰਨ

ਇਸ ਪਾਠ ਵਿੱਚ ਇੱਕ ਨੋਟਬੁੱਕ ਟਿਊਟੋਰਿਅਲ ਸ਼ਾਮਿਲ ਹੈ:

- [15-browser-user.ipynb](./15-browser-user.ipynb): CDP ਦੁਆਰਾ Chrome ਸੈਸ਼ਨ ਲਾਂਚ ਕਰਦਾ ਹੈ, Airbnb 'ਤੇ ਸਟੋਕਹੋਮ ਲਿਸਟਿੰਗ ਲਈ ਖੋਜ ਕਰਦਾ ਹੈ, Browser-Use ਵਿਜ਼ਨ ਨਾਲ ਕੀਮਤਾਂ ਕੱਢਦਾ ਹੈ, ਅਤੇ ਸਭ ਤੋਂ ਸਸਤੀ ਵਿਕਲਪ ਨੂੰ ਢਾਂਚਾ ਬੱਧ ਡੇਟਾ ਵਜੋਂ ਵਾਪਸ ਕਰਦਾ ਹੈ।

## ਜਰੂਰੀ ਸਪੱਸ਼ਟਤਾ

- Python 3.12+
- ਤੁਹਾਡੇ ਵਾਤਾਵਰਣ ਵਿੱਚ Azure OpenAI ਡਿਪਲੋਇਮੈਂਟ ਕਾਨਫਿਗਰ ਕੀਤਾ ਹੋਇਆ
- Chrome ਜਾਂ Chromium ਲੋਕਲ ਤੌਰ 'ਤੇ ਇੰਸਟਾਲ ਕੀਤਾ ਹੋਇਆ
- Playwright ਦੀਆਂ dependencies ਇੰਸਟਾਲ ਹੋਈਆਂ ਹੋਣ
- async Python ਦੀ ਬੁਨਿਆਦੀ ਜਾਣ-ਪਛਾਣ

## ਸੈਟਅੱਪ

ਨੋਟਬੁੱਕ ਵਿੱਚ ਵਰਤੀ ਜਾਣ ਵਾਲੀਆਂ ਪੈਕੇਜਜ਼ ਇੰਸਟਾਲ ਕਰੋ:

```bash
pip install browser_use playwright python-dotenv
playwright install chromium
```

ਨੋਟਬੁੱਕ ਵੱਲੋਂ ਵਰਤੀ ਗਈਆਂ Azure OpenAI ਵਾਤਾਵਰਣ ਚਲ ਰਹੀਆਂ ਵੈਰੀਏਬਲਜ਼ ਸੈਟ ਕਰੋ:

```bash
AZURE_OPENAI_ENDPOINT=...
AZURE_OPENAI_API_KEY=...
AZURE_OPENAI_CHAT_DEPLOYMENT_NAME=...
# ਵਿਅਕਲਪਿਕ: ਛੱਡ ਦਿੱਤਾ ਗਿਆ ਤਾਂ ਆਖਰੀ API ਵਰਜ਼ਨ ਨੂੰ ਮੂਲ ਧਾਰਿਤ ਕਰਦਾ ਹੈ
AZURE_OPENAI_API_VERSION=...
```

## ਵਿਆਸਥਾ ਦਾ ਸੰਖੇਪ

ਨੋਟਬੁੱਕ ਇੱਕ ਹਾਈਬ੍ਰਿਡ ਬ੍ਰਾਊਜ਼ਰ ਆਟੋਮੇਸ਼ਨ ਵਰਕਫਲੋ ਦਿਖਾਉਂਦਾ ਹੈ:

1. Chrome CDP ਸਮਰਥਿਤ ਨਾਲ ਸ਼ੁਰੂ ਹੁੰਦਾ ਹੈ ਤਾਂ ਜੋ Playwright ਅਤੇ Browser-Use ਦੋਹਾਂ ਇੱਕੋ ਬ੍ਰਾਊਜ਼ਰ ਸੈਸ਼ਨ ਸ਼ੇਅਰ ਕਰ ਸਕਣ।
2. ਇੱਕ Browser-Use ਏਜੰਟ ਖੁੱਲੇ-ਅੰਤ ਵਾਲੇ ਨੈਵੀਗੇਸ਼ਨ ਕਾਰਜਾਂ ਸੰਭਾਲਦਾ ਹੈ ਜਿਵੇਂ ਕਿ Airbnb ਖੋਲ੍ਹਣਾ, ਪੌਪ-ਅਪਸ ਨੂੰ ਖਤਮ ਕਰਨਾ, ਅਤੇ ਸਟੋਕਹੋਮ ਦੀ ਖੋਜ ਕਰਨਾ।
3. ਸਰਗਰਮ ਪੰਨਾ ਢਾਂਚਾ ਬੱਧ Pydantic ਸਕੀਮਾ ਨਾਲ ਜਾਂਚਿਆ ਜਾਂਦਾ ਹੈ ਤਾਂ ਜੋ ਲਿਸਟਿੰਗ ਦੇ ਸਿਰਲੇਖ, ਰਾਤ ਦੇ ਮੁਲ, ਰੇਟਿੰਗ, ਅਤੇ URL ਕੱਢੇ ਜਾ ਸਕਣ।
4. Python ਲਾਜਿਕ ਕੱਢੀਆਂ ਲਿਸਟਿੰਗਾਂ ਦੀ ਤੁਲਨਾ ਕਰਦਾ ਹੈ ਅਤੇ ਸਭ ਤੋਂ ਸਸਤੀ ਨਤੀਜੇ ਨੂੰ ਹਾਈਲਾਈਟ ਕਰਦਾ ਹੈ।

ਇਹ ਤਰੀਕਾ ਉਹ ਬ柔 نੰ مستقبلی اکسیبل اور سوچ ایپ دی نل نل تے دت دہندا ہے جو Browser-Use اچھا کردا اے جدوں کہ تہاڈے کول deterministic browser control دی لوڑ ہوندی اے۔

## ਮੁੱਖ ਨਤੀਜੇ ਅਤੇ ਵਧੀਆ ਅਭਿਆਸ

### ਕਦੋਂ ਏਜੰਟ ਅਤੇ ਅਦਾਕਾਰ ਦੀ ਵਰਤੋਂ ਕਰਨੀ ਚਾਹੀਦੀ ਹੈ

| ਪਰਿਬਿੰਗਗੀ | ਏਜੰਟ ਵਰਤੋ | ਅਦਾਕਾਰ ਵਰਤੋ |
|----------|-----------|-----------|
| ਡਾਇਨਾਮਿਕ ਲੇਆਊਟ | ਹਾਂ, AI ਪੰਨੇ ਦੇ ਬਦਲਾਅ ਨੁੰ ਅਨੁਕੂਲ ਕਰ ਸਕਦਾ ਹੈ | ਨਹੀਂ, ਨਾਜੁਕ ਚੁਣਨ ਵਾਲੇ ਟੁੱਟ ਜਾਂਦੇ ਹਨ |
| ਜਾਣਕਾਰ ਢਾਂਚਾ | ਨਹੀਂ, ਏਜੰਟ ਸਿੱਧੇ ਕੰਟਰੋਲ ਦੇ ਮੁਕਾਬਲੇ ਧੀਮਾ ਹੁੰਦਾ ਹੈ | ਹਾਂ, ਤੇਜ਼ ਅਤੇ ਸਹੀ |
| ਤੱਤ ਲੱਭਣਾ | ਹਾਂ, ਕੁਦਰਤੀ ਭਾਸ਼ਾ ਚੰਗੀ ਤਰ੍ਹਾਂ ਕੰਮ ਕਰਦੀ ਹੈ | ਨਹੀਂ, ਪੂਰਨ ਚੁਣਨ ਵਾਲੇ ਲੋੜੀਂਦੇ ਹਨ |
| ਸਮੇਂ ਦਾ ਕੰਟਰੋਲ | ਨਹੀਂ, ਘੱਟ ਪੇਸ਼ਗੋਈਯੋਗ | ਹਾਂ, ਵਾਰੀ ਅਤੇ ਮੁੜ ਕੋਸ਼ਿਸ਼ ਅਤੇ ਇੰਤਜ਼ਾਰਾਂ 'ਤੇ ਪੂਰਾ ਕੰਟਰੋਲ |
| ਜਟਿਲ ਵਰਕਫਲੋ | ਹਾਂ, ਅਣਉਮੀਦਤ UI ਹਾਲਤਾਂ ਸੰਭਾਲਦਾ ਹੈ | ਨਹੀਂ, ਖ਼ਾਸ ਸਾਖਾਂ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ |

### Browser-Use ਵਧੀਆ ਅਭਿਆਸ

1. ਖੋਜ ਅਤੇ ਡਾਇਨਾਮਿਕ ਨੈਵੀਗੇਸ਼ਨ ਲਈ ਏਜੰਟ ਨਾਲ ਸ਼ੁਰੂਆਤ ਕਰੋ।
2. ਜਦੋਂ ਪ੍ਰਭਾਵੀ ਸੰਯੋਗ ਪੇਸ਼ਗੋਈਯੋਗ ਹੋ ਜਾਵੇ ਤਾਂ ਸਿੱਧਾ ਪੰਨਾ ਕੰਟਰੋਲ ਨੂੰ ਬਦਲੋ।
3. ਢਾਂਚਾ ਬੱਧ ਆਉਟਪੁੱਟ ਮਾਡਲਾਂ ਦੀ ਵਰਤੋਂ ਕਰੋ ਤਾਂ ਜੋ ਕੱਢਿਆ ਡੇਟਾ ਮਨਜ਼ੂਰਸ਼ੁਦਾ ਅਤੇ ਟਾਈਪ-ਸੁਰੱਖਿਅਤ ਹੋਵੇ।
4. ਦਿੱਖ ਉੱਤੇ ਪ੍ਰਭਾਵ ਪੈਣ ਵਾਲੀਆਂ ਕਾਰਵਾਈਆਂ ਤੋਂ ਬਾਅਦ ਸੂਚਿਤ ਤਰੀਕੇ ਨਾਲ ਰੁਕਾਵਟਾਂ ਸ਼ਾਮਿਲ ਕਰੋ।
5. ਮੁੜਾਵੇ ਦੌਰਾਨ ਸਕ੍ਰੀਨਸ਼ੌਟ ਲਵੋ ਤਾਂ ਜੋ ਫੇਲ ਹੋਣ ਤੇ ਡਿੱਗਣਾ ਸੌਖਾ ਹੋਵੇ।
6. ਵੈੱਬਸਾਈਟਾਂ ਬਦਲਣ ਦੀ ਉਮੀਦ ਕਰੋ ਅਤੇ ਪੌਪ-ਅਪ ਅਤੇ ਲੇਆਊਟ ਬਦਲਾਅ ਲਈ ਬਿਜਲੀ ਉਦਯੋਗ ਬਣਾਓ।
7. ਏਜੰਟ ਅਤੇ ਅਦਾਕਾਰ ਪੈਟਰਨਾਂ ਨੂੰ ਮਿਸ਼ਰਣ ਕਰੋ ਤਾਂ ਜੋ ਦੋਵਾਂ ਲਚਕੀਲਾਪਣ ਅਤੇ ਸਹੀਤਾ ਮਿਲੇ।

### ਬ੍ਰਾਊਜ਼ਰ ਏਜੰਟਸ ਲਈ ਸੁਰੱਖਿਆ ਨਿਯਮ

ਬ੍ਰਾਊਜ਼ਰ ਏਜੰਟ ਲਾਈਵ ਵੈੱਬਸਾਈਟਾਂ ‘ਤੇ ਕੰਮ ਕਰਦੇ ਹਨ, ਇਸ ਲਈ ਉਨ੍ਹਾਂ ਨੂੰ ਉਸ ਸਕ੍ਰਿਪਟ ਨਾਲੋਂ ਕੱਢ ਕੇ ਕਸੇ ਸੀਮਾਵਾਂ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ ਜੋ ਸਿਰਫ਼ ਜਾਣੀ-ਪਹਚਾਣੀ API ਨੂੰ ਕਾਲ ਕਰਦਾ ਹੈ। ਨੋਟਬੁੱਕ ਡੈਮੋ ਤੋਂ ਅਸਲੀ ਵਰਕਫਲੋ ਵੱਲ ਜਾਣ ਤੋਂ ਪਹਿਲਾਂ, ਉਸ ਕੰਟਰੋਲ ਨੂੰ ਪਰਿਭਾਸ਼ਿਤ ਕਰੋ ਕਿ ਏਜੰਟ ਕੀ ਦੇਖ ਸਕਦਾ ਹੈ, ਕਲਿੱਕ ਕਰ ਸਕਦਾ ਹੈ ਅਤੇ ਸਬਮਿਟ ਕਰ ਸਕਦਾ ਹੈ।

1. **ਬ੍ਰਾਊਜ਼ਿੰਗ ਵਾਤਾਵਰਣ ਦੀ ਸੀਮਾ ਸੈੱਟ ਕਰੋ।** ਏਜੰਟ ਨੂੰ ਇੱਕ ਸਪਸ਼ਟ ਬ੍ਰਾਊਜ਼ਰ ਪ੍ਰੋਫਾਈਲ ਜਾਂ ਸੈੰਡਬਾਕਸ ਵਿੱਚ ਚਲਾਓ, ਅਤੇ ਕੰਮ ਲਈ ਲੋੜੀਂਦੇ ਡੋਮੇਨਾਂ ਤੱਕ ਹੀ ਸੀਮਤ ਰੱਖੋ।
2. **ਪ੍ਰੇਖਣ ਤੋਂ ਕਾਰਵਾਈ ਵੱਖ ਕਰੋ।** ਏਜੰਟ ਨੂੰ ਪਹਿਲਾਂ ਖੋਜ ਕਰਨਾ, ਪੜ੍ਹਨਾ, ਅਤੇ ਡੇਟਾ ਕੱਢਣਾ ਦਿਓ; ਫਾਰਮ ਭਰਨ, ਸੰਦੇਸ਼ ਭੇਜਣ, ਯਾਤਰਾ ਬੁਕ ਕਰਨ, ਖਰੀਦ ਕਰਨ, ਰਿਕਾਰਡ ਮਿਟਾਉਣ ਜਾਂ ਖਾਤਾ ਸੈਟਿੰਗ ਬਦਲਣ ਤੋਂ ਪਹਿਲਾਂ ਸਪਸ਼ਟ ਮਨਜ਼ੂਰੀ ਦੀ ਲੋੜ ਰੱਖੋ।
3. **ਪ੍ਰਾਰੰਭਾਂ ਅਤੇ ਟ੍ਰੇਸ ਵਿਚੋ ਗੁਪਤ ਜਾਣਕਾਰੀਆਂ ਨੂੰ ਬਾਹਰ ਰੱਖੋ।** ਮਾਡਲ ਸੰਦੇਸ਼ ਵਿਚ ਪਾਸਵਰਡ, ਭੁਗਤਾਨ ਵੇਰਵੇ, ਸੈਸ਼ਨ ਕੁਕੀਜ਼, ਜਾਂ ਕੁਦਰਤੀ ਨਿੱਜੀ ਡੇਟਾ ਨਾ ਰੱਖੋ। ਪ੍ਰਮਾਣੀਕਰਨ ਲਈ ਯੂਜ਼ਰ ਨੂੰ ਕੰਟਰੋਲ ਦਿਓ ਅਤੇ ਲਾਗਾਂ ਵਿੱਚ ਸੰਵੇਦਨਸ਼ੀਲ ਖੇਤ੍ਰ ਦਾ ਕਵਰ ਕਰੋ।
4. **ਪੰਨੇ ਦੀ ਸਮੱਗਰੀ ਨੂੰ ਅਣ ਵਿਸ਼ਵਾਸਯੋਗ ਇਨਪੁੱਟ ਸਮਝੋ।** ਇੱਕ ਵੈੱਬਸਾਈਟ ਉਹਦਾ ਦਰਸਾਅ ਸਕਦੀ ਹੈ ਜੋ ਕੇਵਲ ਏਜੰਟ ਲਈ ਹੁੰਦਾ ਹੈ, ਨ ਕਿ ਯੂਜ਼ਰ ਲਈ। ਏਜੰਟ ਨੂੰ ਉਹ ਪੰਨਾ ਟੈਕਸਟ ਅਣਡਿਗਣਾ ਕਰ ਦੇਣਾ ਚਾਹੀਦਾ ਹੈ ਜੋ ਉਸਦੇ ਲਕੜੀ ਨੂੰ ਬਦਲਣ, ਡੇਟਾ ਪ੍ਰਗਟ ਕਰਨ, ਸੁਰੱਖਿਆ ਨਿਯਮ ਅਸਰਤ ਰਹਿਤ ਕਰਨ ਜਾਂ ਅਣਸੰਬੰਧਤ ਸਾਈਟਾਂ ਤੇ ਜਾਣ ਦਿਧੇ ਜਾਵੇਂ।
5. **ਖਤਰਨਾਕ ਕਦਮਾਂ ਲਈ ਨਿਸ਼ਚਿਤ ਜਾਂਚਾਂ ਵਰਤੋ।** ਮੌਜੂਦਾ URL, ਪੰਨਾ ਸਿਰਲੇਖ, ਚੁਣੀ ਹੋਈ ਚੀਜ਼, ਕੀਮਤ, ਪ੍ਰਾਪਤਕਾਰ, ਅਤੇ ਕਾਰਵਾਈ ਸਾਰਾਂਸ਼ ਕੋਡ ਨਾਲ ਜਾਂਚੋ ਪਹਿਲਾਂ ਕਿ ਯੂਜ਼ਰ ਤੋਂ ਅੰਤਿਮ ਖ਼ਰੜੀ ਦੀ ਮਨਜ਼ੂਰੀ ਮੰਗੀ ਜਾਵੇ।
6. **ਬਜਟ ਅਤੇ ਰੋਕ ਸ਼ਰਤਾਂ ਸੈੱਟ ਕਰੋ।** ਏਜੰਟ ਵੱਲੋਂ ਵਰਤੋਂ ਵਾਲੇ ਕਾਰਵਾਈਆਂ, ਮੁੜ ਕੋਸ਼ਿਸ਼ਾਂ, ਟੈੱਬ ਅਤੇ ਮਿੰਟਾਂ ਦੀ ਗਿਣਤੀ ਸੀਮਤ ਕਰੋ। ਜਦੋਂ ਪੰਨਾ ਹਾਲਤ ਅਸਪਸ਼ਟ ਹੋਵੇ ਤਾਂ ਕਲਿੱਕ ਕਰਨਾ ਰੋਕੋ।
7. **ਫਾਇਦੈਮਦ ਸਬੂਤ ਰੱਖੋ, ਸਭ ਕੁਛ ਨਹੀਂ।** ਕਾਰਵਾਈ ਸਾਰਾਂਸ਼, ਟਾਈਮਸਟੈਂਪ, URL, ਚੁਣੇ ਗਏ ਤੱਤ ਦੇ ਵੇਰਵੇ, ਅਤੇ ਸਕ੍ਰੀਨਸ਼ੌਟ ਰੈਫਰੇੰਸ ਰੱਖੋ ਤਾਂ ਜੋ ਫੇਲ ਹੋਣ ਤੇ ਸਮੀਖਿਆ ਕਰਨਾ ਅਸਾਨ ਹੋਵੇ; ਬਿਨਾਂ ਜਰੂਰਤ ਵਾਲੀ ਸੰਵੇਦਨਸ਼ੀਲ ਸਮੱਗਰੀ ਨੂੰ ਸੰਭਾਲਣ ਤੋਂ ਬਚੋ।

Airbnb ਉਦਾਹਰਨ ਵਿੱਚ, ਸੁਰੱਖਿਅਤ ਮੂਲ ਸਚਲੰਤ ਹੈ ਕਿ ਸਿਰਫ਼ ਲਿਸਟਿੰਗ ਖੋਜੀ ਜਾਵੇ ਅਤੇ ਕੀਮਤਾਂ ਕੱਢੀਆਂ ਜਾਣ। ਸਾਈਨ ਇਨ ਕਰਨਾ, ਮਾਲਕ ਨਾਲ ਸੰਪਰਕ ਕਰਨਾ ਜਾਂ ਬੁਕਿੰਗ ਪੂਰੀ ਕਰਨਾ ਵੱਖਰੀ, ਯੂਜ਼ਰ-ਮੰਜ਼ੂਰਸ਼ੁਦਾ ਕਾਰਵਾਈ ਹੋਣੀ ਚਾਹੀਦੀ ਹੈ।

ਏਜੰਟ ਨੂੰ ਖੁੱਲੇ-ਅੰਤ ਵਾਲੇ ਨੈਵੀਗੇਸ਼ਨ ਅਤੇ ਡਾਇਨਾਮਿਕ UI ਹਾਲਤਾਂ ਸੰਭਾਲਣ ਦਿਓ, ਜਿਵੇਂ ਸਹੀ ਪੰਨਾ ਲੱਭਣਾ ਜਾਂ ਅਣਉਮੀਦਤ ਪੌਪ-ਅਪ ਨੂੰ ਬੰਦ ਕਰਨਾ। ਜਦੋਂ ਪੰਨੇ ਦਾ ਢਾਂਚਾ ਜਾਨਿਆ ਹੋਇਆ ਹੈ ਅਤੇ ਕਾਰਵਾਈ ਵਿੱਚ ਸਥਿਰਤਾ, ਮੁੜ ਕੋਸ਼ਿਸ਼, ਇੰਤਜ਼ਾਰ ਜਾਂ ਨਿਸ਼ਚਿਤ ਜਾਂਚ ਲੋੜੀਂਦੀ ਹੈ ਤਾਂ ਸਿੱਧਾ Playwright ਕੰਟਰੋਲ ‘ਤੇ ਬਦਲੋ।
</details>

**3. Airbnb ਨਮੂਨਾ ਇੱਕ ਲਿਸਟਿੰਗ ਲੱਭਦਾ ਹੈ ਜੋ ਯੂਜ਼ਰ ਬੁਕ ਕਰ ਸਕਦਾ ਹੈ। ਵਰਕਫਲੋ ਸਾਈਨ ਇਨ, ਮਾਲਕ ਨਾਲ ਸੰਪਰਕ ਕਰਨ ਜਾਂ ਬੁਕਿੰਗ ਪੂਰੀ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਕੀ ਹੋਣਾ ਚਾਹੀਦਾ ਹੈ?**

<details>
<summary>ਜਵਾਬ</summary>

ਵਰਕਫਲੋ ਰੁਕਣਾ ਚਾਹੀਦਾ ਹੈ ਅਤੇ ਸਪਸ਼ਟ ਯੂਜ਼ਰ ਮਨਜ਼ੂਰੀ ਲਈ ਪੁੱਛਣਾ ਚਾਹੀਦਾ ਹੈ। ਪੁੱਛਣ ਤੋਂ ਪਹਿਲਾਂ, ਚੁਣੀ ਹੋਈ ਲਿਸਟਿੰਗ, ਮੌਜੂਦਾ URL, ਕੀਮਤ, ਤਾਰੀਖਾਂ, ਅਤੇ ਉਦੇਸ਼ਿਤ ਕਾਰਵਾਈ ਦਾ ਸਾਰ ਸਾਫ ਦਿਖਾਓ। ਖੋਜ ਅਤੇ ਕੀਮਤ ਕੱਡਨਾ ਸਵੈ-ਚਾਲਿਤ ਹੋ ਸਕਦੇ ਹਨ; ਖਾਤੇ ਤੱਕ ਪਹੁੰਚ, ਸੁਨੇਹੇ, ਖਰੀਦਦਾਰੀ ਅਤੇ ਬੁਕਿੰਗ ਯੂਜ਼ਰ-ਮੰਜ਼ੂਰ ਹੋਣ ਚਾਹੀਦੇ ਹਨ।
</details>

**4. ਇੱਕ ਵੈੱਬ ਪੰਨਾ ਏਜੰਟ ਨੂੰ ਉਸਦੇ ਮੂਲ ਨਿਰਦੇਸ਼ਾਂ ਨੂੰ ਅਣਡਿੱਠਾ ਕਰਨ, ਦੂਜੀ ਸਾਈਟ ਤੇ ਜਾਣ ਅਤੇ ਸੇਵ ਕੀਤੇ ਕ੍ਰੈਡੈਂਸ਼ਲ ਖੋਲ੍ਹਣ ਨੂੰ ਕਹਿੰਦਾ ਹੈ। ਏਜੰਟ ਇਸ ਟੈਕਸਟ ਨੂੰ ਕਿਵੇਂ ਸਲੂਕ ਕਰੇ?**

<details>
<summary>ਜਵਾਬ</summary>

ਇਸਨੂੰ ਅਣ ਵਿਸ਼ਵਾਸਯੋਗ ਪੰਨਾ ਸਮੱਗਰੀ ਵਜੋਂ ਲਓ; ਵਿਕਾਸਕਰਤਾ ਜਾਂ ਯੂਜ਼ਰ ਨਿਰਦੇਸ਼ ਵਜੋਂ ਨਹੀਂ। ਏਜੰਟ ਨੂੰ ਮਨਜ਼ੂਰ ਡੋਮੇਨ ਅਤੇ ਟਾਸਕ ਸੀਮਾ ਵਿੱਚ ਰਹਿਣਾ ਚਾਹੀਦਾ ਹੈ, ਗੁਪਤਾਂ ਨੂੰ ਖੁਲਾਸਾ ਕਰਨ ਤੋਂ ਇਨਕਾਰ ਕਰਨਾ ਚਾਹੀਦਾ ਹੈ, ਅਤੇ ਉਹ ਪੰਨਾ ਟੈਕਸਟ ਨਹੀਂ ਮੰਨਣਾ ਚਾਹੀਦਾ ਜੋ ਲਕੜੀ ਨੂੰ ਬਦਲਣ, ਸੁਰੱਖਿਆ ਰੋਕਣ ਜਾਂ ਅਣਜਾਣ ਸਾਈਟਾਂ ਤੇ ਭੇਜਣ ਲਈ ਕਹਿੰਦਾ ਹੈ।
</details>

**5. ਜਦੋਂ ਬ੍ਰਾਊਜ਼ਰ ਏਜੰਟ ਚੱਲਦਾ ਹੈ ਤਾਂ ਕੀ ਸਬੂਤ ਰੱਖਣਾ ਲਾਭਕਾਰੀ ਹੈ, ਅਤੇ ਕੀ ਟਾਲਣਾ ਚਾਹੀਦਾ ਹੈ?**

<details>
<summary>ਜਵਾਬ</summary>

ਕਾਰਵਾਈ ਸਾਰਾਂਸ਼, ਸਮੇਂ ਦੇ ਨਿਸ਼ਾਨ, URL, ਚੁਣੇ ਗਏ ਤੱਤ ਦੇ ਵੇਰਵੇ, ਪ੍ਰਮਾਣਿਕਤਾ ਨਤੀਜੇ, ਅਤੇ ਸਕ੍ਰੀਨਸ਼ੌਟ ਸੰਦਰਭ ਰੱਖੋ ਤਾਂ ਕਿ ਦੌਰਾਨੀ ਸਮੀਖਿਆ ਕੀਤੀ ਜਾ ਸਕੇ। ਪਾਸਵਰਡ, ਭੁਗਤਾਨ ਵੇਰਵੇ, ਸੈਸ਼ਨ ਕੁਕੀਜ਼, ਕੁਦਰਤੀ ਨਿੱਜੀ ਡੇਟਾ ਜਾਂ ਪੂਰੇ ਪੰਨੇ ਦੀ ਸਮੱਗਰੀ ਨੂੰ ਬਿਨਾਂ ਸਪਸ਼ਟ ਰੱਖਣ ਅਤੇ ਨਿਯਮ ਦੇ ਬਗੈਰ ਸਟੋਰ ਕਰਨ ਤੋਂ ਬਚੋ।
</details>
