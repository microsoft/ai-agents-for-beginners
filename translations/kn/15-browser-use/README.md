# ಕಂಪ್ಯೂಟರ್ ಬಳಕೆ ಏಜೆಂಟ್‌ಗಳು (CUA) ನಿರ್ಮಾಣ

ಕಂಪ್ಯೂಟರ್ ಬಳಕೆ ಏಜೆಂಟ್‌ಗಳು ವೈಬ್‌ಸೈಟ್‌ಗಳನ್ನು ವ್ಯಕ್ತಿಯಂತೆ ಸಂವಹನ ಮಾಡಬಹುದು: ಬ್ರೌಸರ್ ತೆರೆದು, ಪುಟವನ್ನು ಪರಿಶೀಲಿಸಿ, ಮತ್ತು ಅವುಗಳ ದೃಷ್ಟಿಯಿಂದ ಮುಂದಿನ ಉತ್ತಮ ಕ್ರಿಯೆಯನ್ನು ತೆಗೆದುಕೊಳ್ಳುವ ಮೂಲಕ. ಈ ಪಾಠದಲ್ಲಿ, ನೀವು ಒಂದು ಬ್ರೌಸರ್ ಆಟೋಮೇಷನ್ ಏಜೆಂಟ್ ಅನ್ನು ನಿರ್ಮಿಸುವಿರಿ, ಅದು Airbnb ಅನ್ನು ಹುಡುಕಿ, ರಚನಾತ್ಮಕ ಪಟ್ಟಿಯ ಡೇಟಾವನ್ನು ಹೊರತೆಗೆಯುತ್ತದೆ ಮತ್ತು ಸ್ಟಾಕ್‌ಹೋಲ್ಮ್‌ನಲ್ಲಿನ ಅಗ್ಗದ ವಾಸಸ್ಥಾನವನ್ನು ಗುರುತಿಸುತ್ತದೆ.

ಈ ಪಾಠವು ವಾರ್ತಾ-ಬ್ರೌಸರ್ ಬಳಕೆ, ಪ್ಲೇರೈಟ್ ಮತ್ತು ಕ್ರೋಮ್ ಡೆವ್‌ಟೂಲ್‌ಗಳು ಪ್ರೋಟೋಕಾಲ್ (CDP) ಬ್ರೌಸರ್ ನಿಯಂತ್ರಣಕ್ಕಾಗಿ, ಅಜೂರ್ ಓಪನ್ಎಐ ದೃಷ್ಟಿ ಸಕ್ರಿಯ ನಿರ್ಣಯಕ್ಕಾಗಿ, ಮತ್ತು ಪೈಡಾಂಟಿಕ್ ರಚನಾತ್ಮಕ ಪ್ರಾಥಮಿಕತೆಗಾಗಿ ಹೊಂದಾಣಿಕೆಯಾಗುತ್ತದೆ.

## ಪರಿಚಯ

ಈ ಪಾಠವು ಒಳಗೊಂಡಿದೆ:

- ಎಪಿಐ ಮಾತ್ರ ಆಟೋಮೇಷನ್‌ಗೆ ಹೋಲಿಸಿ, ಕಂಪ್ಯೂಟರ್ ಬಳಕೆ ಏಜೆಂಟ್‌ಗಳು ಯಾವಾಗ ಉತ್ತಮದಾಗಿರುವುದು ಅರ್ಥಮಾಡಿಕೊಳುವುದು
- ಬ್ರೌಸರ್-ಬಳಕೆಯನ್ನು ಪ್ಲೇರೈಟ್ ಮತ್ತು CDP ಜೊತೆಗೆ ಭದ್ರತೆಯುತ ಬ್ರೌಸರ್ ಜೀವನಚಕ್ರ ನಿರ್ವಹಣೆಗೆ ಪ್ರಾಯೋಗಿಕವಾಗಿ ಸಂಯೋಜಿಸುವುದು
- ಅಜೂರ್ ಓಪನ್ಎಐ ದೃಷ್ಟಿ ಮತ್ತು ರಚನಾತ್ಮಕ ಪೈಡಾಂಟಿಕ್ ಔಟ್‌ಪುಟ್ ಬಳಸಿ ಚಲನೆಯ ವೆಬ್ ಪುಟಗಳಿಂದ ಪಟ್ಟಿಯ ಡೇಟಾವನ್ನು ತೆಗೆದುಹಾಕುವುದು
- ഏಜೆಂಟ್-ಮೊದಲು, ಅಕ್ಟರ್-ಮೊದಲು ಅಥವಾ ಮಿಶ್ರ ಬ್ರೌಸರ್ ಆಟೋಮೇಷನ್ ಕಾರ್ಯಪದ್ಧತಿಗಳನ್ನು ಯಾವಾಗ ಉಪಯೋಗಿಸುವುದು ಎಂಬುದನ್ನು ನಿರ್ಧರಿಸುವುದು

## ಕಲಿಕೆಯ ಗುರಿಗಳು

ಈ ಪಾಠವನ್ನು ಪೂರ್ಣಗೊಳಿಸಿದ ನಂತರ, ನೀವು ಹೇಗೆ ಎಂಬುದನ್ನು ತಿಳಿದುಕೊಳ್ಳಲು ಸಾಧ್ಯವಾಗುತ್ತದೆ:

- ಅಜೂರ್ ಓಪನ್ಎಐ ಮತ್ತು ಪ್ಲೇರೈಟ್ ಬಳಸಿ ಬ್ರೌಸರ್‌-ಬಳಕೆಯನ್ನು ಸಂರಚಿಸುವುದು
- ನೈಜ ವೆಬ್‌ಸೈಟ್ ನವಿಗೇಟು ಮಾಡುವ ಮತ್ತು ಚಲನೆಯ UI ಅಂಶಗಳನ್ನು ನಿರ್ವಹಿಸುವ ಬ್ರೌಸರ್ ಆಟೋಮೇಷನ್ ಕಾರ್ಯಪದ್ಧತಿಯನ್ನು ನಿರ್ಮಿಸುವುದು
- দৃಶ್ಯಮಾನ ಪುಟದ ವಿಷಯದಿಂದ ಟೈಪ್ ಮಾಡಿದ ಫಲಿತಾಂಶಗಳನ್ನು ತೆಗೆದು, ಅವುಗಳನ್ನು ವ್ಯವಹಾರ ಲಾಜಿಕ್‌ಗೆ ಪರಿವರ್ತಿಸುವುದು
- ಬ್ರೌಸರ್ ಕಾರ್ಯಗಳು ಎಷ್ಟು ನಿರೀಕ್ಷಿತವಾಗಿವೆ ಎಂಬುದರ ಆಧಾರದ ಮೇಲೆ ಏಜೆಂಟ್ ಮತ್ತು ಅಕ್ಟರ್ ಮಾದರಿಗಳ ನಡುವಣವನ್ನು ಆಯ್ಕೆ ಮಾಡುವುದು

## ಕೋಡ್ ಮಾದರಿ

ಈ ಪಾಠದಲ್ಲಿ ಒಂದು ನೋಟ್ಬುಕ್ ಟ್ಯುಟೋರಿಯಲ್ ಇದೆ:

- [15-browser-user.ipynb](./15-browser-user.ipynb): CDP ಮೂಲಕ ಕ್ರೋಮ್ ಸೆಷನ್ ಅನ್ನು ಪ್ರಾರಂಭಿಸಿ, Airbnb ನಲ್ಲಿ ಸ್ಟಾಕ್‌ಹೋಲ್ಮ್ ಪಟ್ಟಿಗಳನ್ನು ಹುಡುಕಿ, ಬ್ರೌಸರ್-ಬಳಕೆ ದೃಷ್ಟಿ ಮುಖಾಂತರ ಬೆಲೆಗಳನ್ನು ತೆಗೆದು, ಅಗ್ಗದ ಆಯ್ಕೆಯನ್ನು ರಚನಾತ್ಮಕ ಡೇಟಾ ರೂಪದಲ್ಲಿ ನೀಡುತ್ತದೆ.

## ಪೂರ್ವಾಪೇಕ್ಷೆಗಳು

- ಪೈಥಾನ್ 3.12+  
- ನಿಮ್ಮ ಪರಿಸರದಲ್ಲಿ ಅಜೂರ್ ಓಪನ್ಎಐ ಡಿಪ್ಲಾಯ್‌ಮೆಂಟ್ ನೇಮಕ ಮಾಡಿಕೊಳ್ಳಬೇಕು  
- ಕ್ರೋಮ್ ಅಥವಾ ಕ್ರೋಮಿಯಂ ಸ್ಥಳೀಯವಾಗಿ ಇನ್‌ಸ್ಟಾಲ್ ಮಾಡಬೇಕು  
- ಪ್ಲೇರೈಟ್ ಅವಲಂಬನೆಗಳು ಇನ್‌ಸ್ಟಾಲ್ ಮಾಡಬೇಕು  
- ಅಸಿಂಕ್ ಪೈಥಾನ್‌ನೊಂದಿಗೆ ಮೂಲಪೂರ್ವ ಪರಿಚಯವಾಗಿರಬೇಕು  

## ಸೆಟ್‌ಅಪ್

ನೋಟ್ಬುಕ್‌ನಲ್ಲಿ ಬಳಸಲಾದ ಪ್ಯಾಕೇಜ್‌ಗಳನ್ನು ಇನ್‌ಸ್ಟಾಲ್ ಮಾಡಿ:

```bash
pip install browser_use playwright python-dotenv
playwright install chromium
```

ನೋಟ್ಬುಕ್ ಬಳಕೆಯಾದ ಅಜೂರ್ ಓಪನ್ಎಐ ಪರಿಸರ ಚರಗಳನ್ನು ಸೆಟ್ ಮಾಡಿ:

```bash
AZURE_OPENAI_ENDPOINT=...
AZURE_OPENAI_API_KEY=...
AZURE_OPENAI_CHAT_DEPLOYMENT_NAME=...
# ಐಚ್ಛಿಕ: ಬಿಟ್ಟರೆ ಡೀಫಾಲ್ಟ್ ಆಗಿ ಇತ್ತೀಚಿನ API ಆವೃತ್ತಿ ಬಳಸದಿರುತ್ತದೆ
AZURE_OPENAI_API_VERSION=...
```

## ವಾಸ್ತುಶಿಲ್ಪ ಅವಲೋಕನ

ಈ ನೋಟ್ಬುಕ್ ಒಂದು ಮಿಶ್ರ ಬ್ರೌಸರ್ ಆಟೋಮೇಷನ್ ಕಾರ್ಯಪದ್ಧತಿಯನ್ನು ಪ್ರದರ್ಶಿಸುತ್ತದೆ:

1. ಕ್ರೋಮ್ CDP ಸಕ್ರಿಯಗೊಂಡು ಪ್ರಾರಂಭವಾಗುತ್ತದೆ, ಇದರಿಂದ ಪ್ಲೇರೈಟ್ ಮತ್ತು ಬ್ರೌಸರ್-ಬಳಕೆ ಒಂದೇ ಬ್ರೌಸರ್ ಸೆಷನನ್ನು ಹಂಚಿಕೊಳ್ಳಬಹುದು.  
2. ಒಂದು ಬ್ರೌಸರ್-ಬಳಕೆ ಏಜೆಂಟ್ ಆಪನ್-ಎಂಡೆಡ್ ನವಿಗೇಷನ್ ಕಾರ್ಯಗಳನ್ನು ನಿಭಾಯಿಸುತ್ತದೆ, ಉದಾಹರಣೆಗೆ Airbnb ತೆರೆಯುವುದು, ಪಾಪ್-ಅಪ್ಗಳನ್ನು ನಿರಾಕರಿಸುವುದು, ಮತ್ತು ಸ್ಟಾಕ್‌ಹೋಲ್ಮ್ ಹುಡುಕುವುದು.  
3. ಸಕ್ರಿಯ ಪುಟವನ್ನು ರಚನಾತ್ಮಕ ಪೈಡಾಂಟಿಕ್Schema ಮೂಲಕ ಪರಿಶೀಲಿಸಿ ಪಟ್ಟಿಯ ಶೀರ್ಷಿಕೆಗಳು, ರಾತ್ರಿ ಪ್ರತಿ ಬೆಲೆ, ರೇಟಿಂಗ್‌ಗಳು, ಮತ್ತು URLs ತೆಗೆಯಲಾಗುವುದು.  
4. ಪೈಥಾನ್ ಲಾಜಿಕ್ ತೆಗೆದುಹಾಕಿದ ಪಟ್ಟಿಗಳನ್ನು ಹೋಲಿಸಿ ಅಗ್ಗದ ಫಲಿತಾಂಶವನ್ನು ಹೆಚ್ಚಿನಪಡಿಸುತ್ತದೆ.  

ಈ ಕ್ರಮವು ಬ್ರೌಸರ್-ಬಳಕೆಯ ದೃಷ್ಟಿ ಆಧಾರಿತ ನಿರ್ಣಯವನ್ನು ಸೂಕ್ಷ್ಮವಾಗಿಟ್ಟುಕೊಳ್ಳುತ್ತದೆ ಮತ್ತು ನಿಮ್ಮಿಗೂ ನಿರ್ಧಿಷ್ಟ ಬ್ರೌಸರ್ ನಿಯಂತ್ರಣ ನೀಡುತ್ತದೆ.  

## ಪ್ರಮುಖ ಪಾಠಗಳು ಮತ್ತು ಉತ್ತಮ ಅಭ್ಯಾಸಗಳು

### ಏಜೆಂಟ್ ಮತ್ತು ಅಕ್ಟರ್ ಯಾವಾಗ ಬಳಸಬೇಕು

| ಪರಿಸ್ಥಿತಿ | ಏಜೆಂಟ್ ಬಳಕೆ | ಅಕ್ಟರ್ ಬಳಕೆ |
|----------|-----------|-----------|
| ಚಲನೆಯ ವಿನ್ಯಾಸಗಳು | ಹೌದು, AI ಪುಟ ಬದಲಾವಣೆಗಳಿಗೆ ಹೊಂದಿಕೊಳ್ಳಬಹುದು | ಇಲ್ಲ, ನಾಜೂಕಾದ ಆಯ್ಕೆಮಾಡುವವರು ಮುರಿಯಬಹುದು |
| ज्ञात ರಚನೆ | ಇಲ್ಲ, ಏಜೆಂಟ್ ನೇರ ನಿಯಂತ್ರಣಕ್ಕಿಂತ ನಿಧಾನ | ಹೌದು, ವೇಗವಾಗಿ ಹಾಗೂ ಖಚಿತವಾಗಿ |
| ಅಂಶಗಳನ್ನು ಹುಡುಕುವುದು | ಹೌದು, ಸಹಜ ಭಾಷೆ ಉತ್ತಮವಾಗಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ | ಇಲ್ಲ, ಖಚಿತ ಆಯ್ಕೆಮಾಡುವವರು ಅಗತ್ಯವಿದೆ |
| ಸಮಯ ನಿಯಂತ್ರಣ | ಇಲ್ಲ, ಕಡಿಮೆ ನಿರೀಕ್ಷಿತ | ಹೌದು, ನಿರಾಕರಣೆಗಳು ಮತ್ತು ಪುನಃಪ್ರಯತ್ನಗಳ ಮೇಲೆ ಸಂಪೂರ್ಣ ನಿಯಂತ್ರಣ |
| ಸಂಕೀರ್ಣ ಕಾರ್ಯಪದ್ಧತಿಗಳು | ಹೌದು, ಅಪ್ರತೀಕ್ಷಿತ UI ಸ್ಥಿತಿಗಳನ್ನು ನಿಭಾಯಿಸುತ್ತದೆ | ಇಲ್ಲ, ಸ್ಪಷ್ಟ ಆಡಳಿತ ಅಗತ್ಯ |

### ಬ್ರೌಸರ್-ಬಳಿಗೆ ಉತ್ತಮ ಅಭ್ಯಾಸಗಳು

1. ಅನ್ವೇಷಣೆ ಮತ್ತು ಚಲಿಸುವ ನವಿಗೇಶನ್‌ಗೆ ಏಜೆಂಟ್‌ನಿಂದ ಪ್ರಾರಂಭಿಸಿ.  
2. ಸಂಪರ್ಕ ಕ್ರಮ ನಿಗದಿತವಾದಾಗ ನೇರ ಪುಟ ನಿಯಂತ್ರಣಕ್ಕೆ ಬದಲಾಯಿಸಿ.  
3. ರಚನಾತ್ಮಕ ಔಟ್‌ಪುಟ್ ಮಾದರಿಗಳನ್ನು ಉಪಯೋಗಿಸಿ, ತೆಗೆಯಲಾದ ಡೇಟಾ ಮಾನ್ಯವಾಗಿದ್ದು ಮತ್ತು ಪ್ರಕಾರ-ಸುರಕ್ಷಿತವಾಗಿರಲಿ.  
4. ಗೋಚರಿಸುವ UI ಬದಲಾವಣೆಗಳನ್ನು ಉಡಿಸಲು ಹಂತದ ನಂತರ ತ್ವರಿತಾವಕಾಶ ನೀಡಿರಿ.  
5. ವಿಫಲತೆಗಳನ್ನು ಸುಲಭವಾಗಿ ಡಿಬಗ್ ಮಾಡಲು ಸ್ಕ್ರೀನ್‌ಶಾಟ್‌ಗಳನ್ನು ತೆಗೆದುಕೊಳ್ಳಿ.  
6. ವೆಬ್‌ಸೈಟ್ ಬದಲಾವಣೆಗಳನ್ನು ನಿರೀಕ್ಷಿಸಿ ಮತ್ತು ಪಾಪ್-ಅಪ್ಗೆ ಮತ್ತು ವಿನ್ಯಾಸ ಬದಲಾವಣೆಗಳಿಗೆ ಬದಲಾವಣೆ ಯೋಜನೆಗಳನ್ನು ವಿನ್ಯಾಸಗೊಳಿಸಿ.  
7. ಏಜೆಂಟ್ ಮತ್ತು ಅಕ್ಟರ್ ಮಾದರಿಗಳನ್ನು ಮಿಶ್ರಣ ಮಾಡಿ ಬಳಸುವುದು ಪ್ರತ್ಯೇಕತೆ ಮತ್ತು ಖಚಿತತೆ ಎರಡನ್ನೂ ಕೊಡುತ್ತದೆ.  

### ಬ್ರೌಸರ್ ಏಜೆಂಟ್‌ಗಳ ಸುರಕ್ಷತಾ ಮಾರ್ಗಸೂಚಿಗಳು

ಬ್ರೌಸರ್ ಏಜೆಂಟ್‌ಗಳು ನೇರವಾಗಿ ಲೈವ್ ವೆಬ್‌ಸೈಟ್‌ಗಳ ಮೇಲೆ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತವೆ, ಆದ್ದರಿಂದ ಅವು known API ಅನ್ನು ಕೇವಲ ಕರೆ ಮಾಡುವ ಸ್ಕ್ರಿಪ್ಟ್‌ಗಿಂತ ಹೆಚ್ಚು ಕಟ್ಟುನಿಟ್ಟಿನ ನಿಯಮಾವಳಿಗಳನ್ನು ಅಗತ್ಯವಿದೆ. ನೋಟ್ಬುಕ್ ಕೈಪಿಡಿಯಿಂದ ನಿಜವಾದ ಕಾರ್ಯಪದ್ಧತಿಗೆ ಬರುವಾಗ ಏಜೆಂಟ್ ಏನು ನೋಡಬಹುದು, ಕ್ಲಿಕ್ ಮಾಡಬಹುದು, ಮತ್ತು ಸಲ್ಲಿಸಬಹುದು ಎಂಬ ನಿಯಂತ್ರಣಗಳನ್ನು ನಿರ್ಧರಿಸಿ.  

1. **ಬ್ರೌಸಿಂಗ್ ಪರಿಸರವನ್ನು ವ್ಯಾಪ್ತಿಮಾಡಿ.** ಏಜೆಂಟ್ ಅನ್ನು ಸಮರ್ಪಿತ ಬ್ರೌಸರ್ ಪ್ರೊಫೈಲ್ ಅಥವಾ ಸ್ಯಾಂಡ್ಬಾಕ್ಸ್‌ನಲ್ಲಿ ನಡೆಸಿ, ಮತ್ತು ಕಾರ್ಯಕ್ಕಾಗಿ ಅಗತ್ಯವಿರುವ ಡೊಮೈನ್‌ಗಳಿಗೆ ಮಾತ್ರ ಮಿತಿ ಹಾಕಿ.  
2. **ನೋಟದೃಷ್ಟಿಯನ್ನು ಕ್ರಿಯೆಯಿಂದ ವಿಭಜಿಸಿ.** ಏಜೆಂಟ್ ಮೊದಲಿಗೆ ಹುಡುಕೆ, ಓದಿಕೆ, ಮತ್ತು ಡೇಟಾ ತೆಗೆದುಕೊಳ್ಳುವಂತೆ ಇಡಿ; ಗೌಪ್ಯ ಫಾರ್ಮ್ಗಳು ಸಲ್ಲಿಸುವುದು, ಸಂದೇಶಗಳನ್ನು ಕಳುಹಿಸುವುದು, ಪ್ರಯಾಣ ಬುಕ್ಕಿಂಗ್, ಖರೀದಿ ಮಾಡುವುದಕ್ಕೆ ಮುಂದು ಮನವಿ ನಿರ್ದಿಷ್ಟ ಅನುಮತಿ ಸಂಕ್ರಾಂತಿಯನ್ನು ಅಗತ್ಯವಿರಲಿ.  
3. **ಹುಡುಕಾಟ ಮತ್ತು ಟ್ರೇಸ್‌ಗಳಲ್ಲಿ ರಹಸ್ಯಗಳನ್ನು ಹೊರಬಿಟ್ಟುಕೊಳ್ಳಿ.** ಮಾದರಿ ಸಂಧರ್ಭದಲ್ಲಿ ಪಾಸ್ವರ್ಡ್‌, ಪಾವತಿ ವಿವರಗಳು, ಸೆಷನ್ ಕುಕಿಸ್, ಅಥವಾ ಅಸಂಸ್ಕೃತ ವೈಯಕ್ತಿಕ ಡೇಟಾ ಇರಿಸಬೇಡಿ. ಪರಿಶೀಲನೆಗೆ ಬಳಕೆದಾರರನ್ನು ಬಿಟ್ಟುಬಿಡಿ ಮತ್ತು ಸಂವೇದನಾಶೀಲ ಕ್ಷೇತ್ರಗಳನ್ನು ನಿರೋಧಿಸಿ.  
4. **ಪುಟದ ವಿಷಯವನ್ನು ಅವಿಶ್ವಾಸಾರ್ಹ ಇನ್‌ಪುಟ್ ಎಂದು ಕಾಣಿರಿ.** ಒಂದು ವೆಬ್‌ಸೈಟ್ ಅತ್ಯುತ್ತಮವಾಗಿ ಏಜೆಂಟ್‌ಗೆ ಸೂಚನೆಗಳನ್ನು ನೀಡಬಹುದು, ಬಳಕೆದಾರರಿಗೆ ಅಲ್ಲ. ಏಜೆಂಟ್ ತನ್ನ ಗುರಿಯನ್ನು ಬದಲಾಯಿಸಲು, ಡೇಟಾವನ್ನು ಬಹಿರಂಗಗೊಳಿಸಲು, ಭದ್ರತಾ ವ್ಯವಸ್ಥೆಗಳನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಲು, ಅಥವಾ ಸಂಬಂಧಇಲ್ಲದ ಸೈಟ್‌ಗೆ ಹೋಗಲು ಹೇಳುವ ಪುಟ ಪಠ್ಯವನ್ನು ನಿರ್ಲಕ್ಷಿಸಿ.  
5. **ಸಂಕಟಕಾರಿ ಹಂತಗಳ ಸುತ್ತಲೆ ಗಟ್ಟಿಯಾದ ಪರಿಶೀಲನೆ ಮಾಡಿ.** ಕೊನೆ ಹಂತದ ಅಂಗೀಕಾರಕ್ಕೆ ಬಳಕೆದಾರರನ್ನು ಕೇಳುವ ಮೊದಲು ಪ್ರಸ್ತುತ URL, ಪುಟ ಶೀರ್ಷಿಕೆ, ಆಯ್ಕೆ ಮಾಡಿದ ಐಟಂ, ಬೆಲೆ, ಸ್ವೀಕಾರಕರು, ಮತ್ತು ಕಾರ್ಯ ಸಾರಾಂಶ ಹೋಲಿಸಿ.  
6. **ಬಜೆಟ್‌ಗಳು ಮತ್ತು ನಿಲ್ಲಿಸುವ ನಿಯಮಗಳನ್ನು ನಿಗದಿ ಮಾಡು.** ಏಜೆಂಟ್ ಬಳಸಬಹುದಾದ ಕ್ರಿಯೆಗಳು, ಪುನಃಪ್ರಯತ್ನಗಳು, ಟ್ಯಾಬ್‌ಗಳು, ಮತ್ತು ನಿಮಿಷಗಳ ಸಂಖ್ಯೆಯನ್ನು ಮಿತಿ ಪಡಿ. ಪುಟದ ಸ್ಥಿತಿ अस्पಷ್ಟವಾಗಿದ್ರೆ ಕ್ಲಿಕ್ ಮಾಡುವುದನ್ನು ನಿಲ್ಲಿಸು.  
7. **ಅವಶ್ಯಕವಾದ ಸಾಕ್ಷ್ಯಗಳನ್ನು ಮಾತ್ರ ದಾಖಲಿಸು.** ಕ್ರಿಯೆಗಳ ಸಾರಾಂಶ, ಸಮಯ ಕೌಟುಂಬಿಕತೆಗಳು, URLs, ಆಯ್ಕೆಯಾದ ಅಂಶ ವಿವರಣೆಗಳು, ಮತ್ತು ಸ್ಕ್ರೀನ್‌ಶಾಟ್ ಸೂಚನೆಗಳನ್ನು ಉಳಿಸಿ, ಜಾಸ್ತಿ ಭದ್ರತೆಗಾಗಿ ಅಗತ್ಯವಿಲ್ಲದ ಪುಟ ವಿಷಯಗಳನ್ನು ಸಂಗ್ರಹಿಸಬೇಡಿ.  

Airbnb ಉದಾಹರಣೆಯಲ್ಲಿ, ಸುರಕ್ಷಿತ ವಿತರಣೆ ಲಿಸ್ಟಿಂಗ್‌ಗಳನ್ನು ಹುಡುಕಿ ಬೆಲೆಗಳನ್ನು ತೋಪಾಕೊಡಿಕೊಳ್ಳುವುದು. ಸೈನ್ ಇನ್ ಆಗುವುದು, ಹೋಸ್ಟ್ ಅನ್ನು ಸಂಪರ್ಕಿಸುವುದು, ಅಥವಾ ಬುಕ್ಕಿಂಗ್ ಪೂರ್ಣಗೊಳಿಸುವುದು ಬಳಕೆದಾರ ಅನುಮೋದಿತ ಕ್ರಮವಾಗಿರಬೇಕು.  

### ನೈಜ ಜಗತ್ತಿನ ಅನ್ವಯಿಕೆಗಳು

- ಪ್ರಯಾಣ ಬುಕ್ಕಿಂಗ್ ಮತ್ತು ಬೆಲೆ ಗಮನವಿಡಲಿದೆ  
- ಇ-ಕಾಮರ್ಸ್ ಬೆಲೆ ಹೋಲಿಕೆ ಮತ್ತು ಲಭ್ಯತೆ ಪರಿಶೀಲನೆ  
- ಚಲನೆಯ ವೆಬ್‌ಸೈಟ್‌ಗಳಿಂದ ರಚನಾತ್ಮಕ ಹೊರತೆಗೆಯುವಿಕೆ  
- ದೃಷ್ಟಿ ಆಧಾರಿತ UI ಸ್ಕೂರಣ ಮತ್ತು ಪರಿಶೀಲನೆ  
- ವೆಬ್‌ಸೈಟ್ ಮೆಚ್ಚುಗೆಯ ಮತ್ತು ಎಚ್ಚರಿಕೆ  
- ಬಹು ಹಂತದ ಫ್ಲೋಗಳಾದಲ್ಲಿ ಬುದ್ಧಿವಂತ ಫಾರ್ಮ್ ಭರ್ತಿ  

## ನೈಜ ಜಗತ್ತು ಉದಾಹರಣೆ: ಮೈಕ್ರೋಸಾಫ್ಟ್ ಪ್ರಾಜೆಕ್ಟ್ ಓಪಲ್  

ನೀವು ಈ ಪಾಠದಲ್ಲಿ ನಿರ್ಮಿಸುವ ಏಜೆಂಟ್ ಒಂದು ಚಿಕ್ಕ, ಸ್ಥಳೀಯ ಆವೃತ್ತಿಯ **ಕಂಪ್ಯೂಟರ್ ಬಳಕೆ ಏಜೆಂಟ್ (CUA)** — ವ್ಯಕ್ತಿಯಂತೆ ಬ್ರೌಸರ್ ಚಲಿಸುವ ಕಾರ್ಯಕ್ರಮ. ಮೈಕ್ರೋಸಾಫ್ಟ್ ಈ ಆಲೋಚನೆಯನ್ನು ಸಂಸ್ಥೆಗೆ ತರುತ್ತಿದೆ **[Project Opal (Frontier)](https://support.microsoft.com/en-us/microsoft-365-copilot/get-started-with-project-opal-frontier)**, ಮೈಕ್ರೋಸಾಫ್ಟ್ 365 ಸಹಾಯಕದಲ್ಲಿ ಒಂದು ವೈಶಿಷ್ಟ್ಯ.  

ಪ್ರಾಜೆಕ್ಟ್ ಓಪಲ್‌ನೊಂದಿಗೆ, ನೀವು ಒಂದು ಕಾರ್ಯವನ್ನು ವರ್ಣನೆ ಮಾಡುತ್ತೀರಿ ಮತ್ತು ಏಜೆಂಟ್ ನಿಮ್ಮ ಪರವಾಗಿ **ಕಂಪ್ಯೂಟರ್ ಬಳಕೆಯನ್ನು ಸುರಕ್ಷಿತ Windows 365 Cloud PC-ում** ಬಳಸಿಕೊಂಡು, ನಿಮ್ಮ ಸಂಸ್ಥೆಯ ಬ್ರೌಸರ್ ಆಧಾರಿತ ಅಪ್ಲಿಕೇಶನ್, ಸೈಟ್‌ಗಳು ಮತ್ತು ಡೇಟಾ ನಡುವೆ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ. ಇದು **ಹಿಂಭಾಗದಲ್ಲಿ ಅಸಿಂಕ್ರೋನಸ್ ಆಗಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ**, ಮತ್ತು ನೀವು ಯಾವಾಗಲಾದರೂ ಕಾರ್ಯವನ್ನು ಮಾರ್ಗದರ್ಶನ ಅಥವಾ ನಿಯಂತ್ರಣ ಪಡೆಯಬಹುದು. ಉದಾಹರಣೆ ಕೆಲಸಗಳು ಸೇರಿವೆ:  

- ಭದ್ರತಾ ಗುಂಪಿನ ಸದಸ್ಯತ್ವ ವಿನಂತಿಗಳನ್ನು ನಿರ್ವಹಿಸುವುದು  
- ಅನುಗುಣತಾ ಪರಿಶೀಲನೆಗಳಿಗಾಗಿ ವೀಕ್ಷಣಾ ಸಾಕ್ಷ್ಯಗಳನ್ನು ಸಂಗ್ರಹಣೆ ಮತ್ತು ಪರಿಶೀಲನೆ  
- IT ಘಟನಾಕ್ರಮಗಳನ್ನು ಕ್ರಮಿಸಲು (ಟಿಕೆಟ್ ಸ್ಥಿತಿ ನವೀಕರಣ, ಮಾಲೀಕರ ನಿಯೋಜನೆ, ಪ್ರತಿಕೃತಿಗಳನ್ನು ಮುಚ್ಚುವುದು)  
- ಹಣಕಾಸು ಮುಚ್ಚುವ ಡೆಕ್‌ಗೆ ಎಕ್ಸೆಲ್ ಡೇಟಾವನ್ನು ಸಂಗ್ರಹಿಸುವುದು

| **ಯೋಜನೆ ಮತ್ತು ಮೆಟಾಕಾಗ್ನಿಶನ್** (ಪಾಠ 07 ಮತ್ತು 09) | ಓಪಲ್ ಮೊದಲಿಗೆ ಕಾರ್ಯ ಯೋಜನೆಯನ್ನು ರಚಿಸುತ್ತದೆ, ನಂತರ ಪ್ರತಿ ಹಂತದಲ್ಲಿ ತನ್ನ ನಿರ್ಣಯವನ್ನು ಮೇಲ್ವಿಚಾರಣೆ ಮಾಡುತ್ತದೆ ಮತ್ತು ಅನುಮಾನಾಸ್ಪದ ಚಟುವಟಿಕೆ ಕಂಡು ಬಂದರೆ ವಿರಾಮ ನೀಡುತ್ತದೆ. |

> **ಲಭ್ಯತೆ:** ಪ್ರಾಜೆಕ್ಟ್ ಓಪಲ್ ಪ್ರಸ್ತುತ [ಫ್ರಂಟಿಯರ್ ಮೊದಲಿಗ ಪ್ರವೇಶ ಕಾರ್ಯಕ್ರಮ](https://adoption.microsoft.com/copilot/frontier-program/) ನಲ್ಲಿ ಬಳಕೆದಾರರಿಗೆ ಲಭ್ಯವಿದ್ದು, ನಿಮ್ಮ ನಿರ್ವಾಹಕ ಸೆಟ್‌ಅಪ್ ಪೂರ್ಣಗೊಳಿಸಬೇಕಾಗಿರುತ್ತದೆ. ಇದು ಪ್ರಯೋಗಾತ್ಮಕ ಫ್ರಂಟಿಯರ್ ವೈಶಿಷ್ಟ್ಯವಾಗಿರುವುದರಿಂದ, ಸಾಮರ್ಥ್ಯಗಳು ಕಾಲಕಾಲಕ್ಕೆ ಬದಲಾವಣೆಯಾಗಬಹುದು.  

## ಜ್ಞಾನ ಪರಿಶೀಲನೆ

ಮುಂದಿನ ಪಾಠಕ್ಕೆ ಹೋಗುವ ಮೊದಲು ನಿಮ್ಮ ಅರ್ಥವನ್ನು ಪರೀಕ್ಷಿಸಿ.

**1. ಬ್ರೌಸರ್ ಆಧಾರಿತ ಕಂಪ್ಯೂಟರ್ ಬಳಕೆ ಏಜೆಂಟ್ ಯಾವಾಗ ಎಪಿಐ ಮಾತ್ರ ಕಾರ್ಯಪದ್ಧತಿಯಿಗೂ ಮಿಗಿಲು?**

<details>
<summary>ಉತ್ತರ</summary>

ಕಾರ್ಯವು ವೆಬ್ UIಯಲ್ಲಿ ಗೋಚರಿಸುವದರ ಮೇಲೆ ಅವಲಂಬಿತವಾಗಿದ್ದಾಗ, ತಾಣ ಕಡತ ಅಗತ್ಯ API ಅನ್ನು ಅನಾವರಣ ಮಾಡದಿದ್ದಾಗ, ಅಥವಾ ಪುಟವು ನಿರಂತರ ಬದಲಾವಣೆಗೊಳ್ಳುತ್ತದೆ ಹಾಗಿದ್ದರೆ ಫಿಕ್ಸ್‌ಡ್ API ಅಥವಾ ಆಯ್ಕೆಮಾಡುವ ಲಾಜಿಕ್ ಮುರಿಯುವ ಸಾಧ್ಯತೆ ಇದ್ದಾಗ ಬ್ರೌಸರ್ ಏಜೆಂಟ್ ಬಳಸು. ಅದೇ ಕಾರ್ಯಕ್ಕೆ ಸ್ಥಿರ API ಇದ್ದರೆ, ಅದು ಸಾಮಾನ್ಯವಾಗಿ ವೇಗವಾಗಿ, ಪರೀಕ್ಷಿಸಲು ಸುಲಭವಾಗಿ ಮತ್ತು ಭದ್ರತೆಗಾಗಿ ಉತ್ತಮವಾಗಿರುವುದರಿಂದ API ಅರ್ಹತೆ ವನ್ನು ಆದ್ಯತೆ ನೀಡಿ.
</details>

**2. ಮಿಶ್ರ ಕಾರ್ಯಪದ್ಧತಿಯಲ್ಲಿ, ಏಜೆಂಟ್ ಯಾವ ಭಾಗಗಳನ್ನು ನಿಭಾಯಿಸಬೇಕು ಮತ್ತು ನೇರ ಪ್ಲೇರೈಟ್ ಕೋಡ್ ಯಾವ ಭಾಗಗಳನ್ನು ನಿಭಾಯಿಸಬೇಕು?**

<details>
<summary>ಉತ್ತರ</summary>

ಏಜೆಂಟ್ ತೆರೆಯಲಾಗದ ನವಿಗೇಶನ್ ಮತ್ತು ಚಲೋ_UI ಸ್ಥಿತಿಗಳನ್ನು ನಿರ್ವಹಿಸಲಿ, ಉದಾಹರಣೆಗಾಗಿ ಸರಿಯಾದ ಪುಟವನ್ನು ಹುಡುಕುವುದು ಅಥವಾ ಅಪ್ರತ್ಯಾಶಿತ ಪಾಪ್-ಅಪ್ಗಳನ್ನು ತಿರಸ್ಕರಿಸುವುದು. ಪುಟದ ರಚನೆ ತಿಳಿದಿರುವಾಗ ಮತ್ತು ಕಾರ್ಯಕ್ಕೆ ನಿಖರತೆ, ಪುನಃಪ್ರಯತ್ನ, ನಿರೀಕ್ಷಣೆ, ಅಥವಾ ತೊಡಕುತಾಳಿಕೆಯ ಸತ್ಯಾಪನೆಯನ್ನು ಅವಶ್ಯಕವಿರುವಾಗ ನೇರ ಪ್ಲೇರೈಟ್ ನಿಯಂತ್ರಣಕ್ಕೆ ಬದಲಾಯಿಸಲಿ.  
</details>

**3. Airbnb ಉದಾಹರಣೆಯು ಬಳಕೆದಾರ ಬೇಕಾಗಬಹುದು ಎನ್ನುವ ಒಂದು ಲಿಸ್ಟಿಂಗ್ ಅನ್ನು ಕಂಡುಹಿಡಿಯುತ್ತದೆ. ಕಾರ್ಯಪದ್ಧತಿಯಲ್ಲಿ ಸೈನ್ ಇನ್ ಆಗುವುದು, ಹೋಸ್ಟ್ ಅನ್ನು ಸಂಪರ್ಕಿಸುವುದು, ಅಥವಾ ಬುಕ್ಕಿಂಗ್ ಪೂರ್ಣಗೊಳಿಸುವ ಮೊದಲು ಏನು ಆಗಬೇಕು?**

<details>
<summary>ಉತ್ತರ</summary>

ಕಾರ್ಯಪದ್ಧತಿ ವಿರಾಮ ಪಡೆದು ಸ್ಪಷ್ಟ ಬಳಕೆದಾರ ಅನುಮತಿಯನ್ನು ಕೇಳಬೇಕು. ಕೇಳುವುದಕ್ಕಿಂತ ಮುನ್ನ ಆಯ್ಕೆಮಾಡಿದ ಲಿಸ್ಟಿಂಗ್, ಪ್ರಸ್ತುತ URL, ಬೆಲೆ, ದಿನಾಂಕಗಳು, ಮತ್ತು ಉದ್ದೇಶಿತ ಕಾರ್ಯದ ಸುಳಿವು ನೀಡಬೇಕು. ಹುಡುಕುವುದು ಮತ್ತು ಬೆಲೆಗಳನ್ನು ತೆಗೆದುಹಾಕುವುದು ಸ್ವಾಯತ್ತವಾಗಿರಬಹುದು; ಖಾತೆ ಪ್ರವೇಶ, ಸಂದೇಶಗಳು, ಖರೀದಿ ಮತ್ತು ಬುಕ್ಕಿಂಗ್ ಬಳಕೆದಾರ ಅನುಮೋದಿತವಾಗಿರಬೇಕು.  
</details>

**4. ಒಂದು ವೆಬ್ ಪುಟ ಏಜೆಂಟ್ ಅನ್ನು ತನ್ನ ಮೂಲ ಸೂಚನೆಗಳನ್ನು ನಿರ್ಲಕ್ಷಿಸಿ, ಮತ್ತೊಂದು ಸೈಟ್‌ಗೆ ಭೇಟಿ ನೀಡಲು, ಮತ್ತು ಸಂರಕ್ಷಿತ ಪ್ರমাণಪತ್ರಗಳನ್ನು ಬಹಿರಂಗಪಡಿಸಲು ಹೇಳುತ್ತದೆ. ಏಜೆಂಟ್ ಆ ಪಠ್ಯವನ್ನು ಹೇಗೆ ಸಂವಹನ ಮಾಡಬೇಕು?**

<details>
<summary>ಉತ್ತರ</summary>

ಅದನ್ನು ಅವಿಶ್ವಾಸಾರ್ಹ ಪುಟದ உள்ளಾಗಿ ಪರಿಗಣಿಸಬೇಕು, ಡೆವಲಪರ್ ಅಥವಾ ಬಳಕೆದಾರ ಸೂಚನೆ ಎಂದು ಅಲ್ಲ. ಏಜೆಂಟ್ ಅನುಮತಿತ ಡೊಮೇನ್ ಮತ್ತು ಕಾರ್ಯ ವ್ಯಾಪ್ತಿಯೊಳಗಿನಂತೆ ಇರಬೇಕು, ರಹಸ್ಯಗಳನ್ನು ಬಹಿರಂಗಪಡಿಸಲು ನಿರಾಕರಿಸಬೇಕು, ಗುರಿಯನ್ನು ಬದಲಾಯಿಸುವುದು, ಭದ್ರತಾ ಕ್ರಮಗಳನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವುದು, ಅಥವಾ ಸಂಬಂಧಿಸಿದಿಲ್ಲದ ತಾಣಗಳಿಗೆ ಕಳುಹಿಸುವುದನ್ನು ತಪ್ಪಿಸಬೇಕು.  
</details>

**5. ಬ್ರೌಸರ್ ಏಜೆಂಟ್ ಕಾರ್ಯನಿರ್ವಹಿಸಿದಾಗ ಯಾವ ಸಾಕ್ಷ್ಯಗಳನ್ನು ಉಳಿಸಬೇಕು ಮತ್ತು ಯಾವನ್ನು ತಪ್ಪಿಸಬೇಕು?**

<details>
<summary>ಉತ್ತರ</summary>

ಕಾರ್ಯ ಸಾರಾಂಶ, ದಿನಾಂಕ-ಸಮಯ, URLs, ಆಯ್ಕೆಮಾಡಿದ ಅಂಶ ವಿವರಣೆಗಳು, ಪರಿಶೀಲನೆ ಫಲಿತಾಂಶಗಳು, ಮತ್ತು ಸ್ಕ್ರೀನ್‌ಶಾಟ್ ಉಲ್ಲೇಖಗಳನ್ನು ಸುರಕ್ಷಿಯಾಗಿ ಉಳಿಸಬೇಕು જેથી ಕಾರ್ಯವನ್ನು ಪರಿಶೀಲಿಸಬಹುದಾಗಿದೆ. ಪಾಸ್ವರ್ಡ್‌, ಪಾವತಿ ವಿವರಗಳು, ಸೆಷನ್ ಕುಕಿಸ್, ಅಸಂಸ್ಕೃತ ವೈಯಕ್ತಿಕ ಮಾಹಿತಿ, ಅಥವಾ ಸಂಪೂರ್ಣ ಪುಟ ವಿಷಯಗಳನ್ನು ನಿರ್ದಿಷ್ಟ ಸಂರಕ್ಷಣಾ ಹಾಗೂ ಗೌಪ್ಯತೆಯಿಂದಲೂ ಇಲ್ಲದ ಹೊರತಾಗಿ ಸಂಗ್ರಹಿಸಬಾರದು.  
</details>
