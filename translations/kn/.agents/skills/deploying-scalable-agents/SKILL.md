# ಮೈಕ್ರೋಸಾಫ್ಟ್ ಫೌಂಡ್ರಿ ಜೊತೆಗೆ ವಿಸ್ತರಣೀಯ ಏಜೆಂಟ್‌ಗಳನ್ನು ನಿಯೋಜಿಸುವುದು

> [ಪಾಠ 16 – ವಿಸ್ತರಣೀಯ ಏಜೆಂಟ್‌ಗಳನ್ನು ನಿಯೋಜಿಸುವುದು](../../../16-deploying-scalable-agents/README.md) ಗೆ ಸಹಪಾಠ ಕೌಶಲ್ಯ.
> ಒಂದು ಕಲಿಕೆಯವನು ಏಜೆಂಟ್ ಅನ್ನು ಪ್ರೋಟೋಟೈಪ್‌ನಿಂದ ವಿಸ್ತರಣೀಯ, ಗಮನಾರ್ಹ
> ಉತ್ಪಾದನಾ ನಿಯೋಜನೆಗೆ ತರುವುದು ಸಹಾಯ ಮಾಡಲು ಇದನ್ನು ಬಳಸಿ. ಪಾಠದ ವಿಷಯ ಮತ್ತು
> ಚಾಲನೆಯಲ್ಲಿರುವ ನೋಟ್ಬುಕ್‌ನಲ್ಲಿ ಪ್ರತಿಯೊಂದು ಶಿಫಾರಸುಗಳನ್ನು ಆಧರಿಸಿ; ಫೌಂಡ್ರಿ APIಗಳು изобретಿಸಬೇಡಿ.

## ಟ್ರಿಗರ್ಗಳು

ಒಂದು ಕಲಿಕೆಯವನು ಈ ಕೆಳಗಿನ ಕಾರ್ಯಗಳನ್ನು ಮಾಡಲು ಇಚ್ಛಿಸಿದಾಗ ಈ ಕೌಶಲ್ಯವನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ:
- ಮೈಸಕ್ರೋಸಾಫ್ಟ್ ಫೌಂಡ್ರಿಯಲ್ಲಿ ಏಜೆಂಟ್ ಅನ್ನು **ಹೋಸ್ಟೆಡ್ ಏಜೆಂಟ್** ලෙස ನಿಯೋಜಿಸಿ ಮತ್ತು ಅದನ್ನು ಆವೃತ್ತಿ ಹೊಂದಿದ/ಗಮನಾರ್ಹಗೊಳಿಸಿ.
- **ಕ್ಲೈಂಟ್-ಹೋಸ್ಟೆಡ್**, **ಹೋಸ್ಟೆಡ್-ಏಜೆಂಟ್**, ಮತ್ತು **ಏಜೆಂಟ್-ವರ್ಕ್‌ಫ್ಲೋ** ನಿಯೋಜನೆ ಮಾದರಿಗಳಲ್ಲಿ ಆಯ್ಕೆಮಾಡಿ.
- ವಿಳಂಬ ಮತ್ತು ವೆಚ್ಚವನ್ನು ನಿಯಂತ್ರಿಸಲು **ಮಾದರಿ ಮಾರ್ಗೀಕರಣ**, **ಪ್ರತಿಕ್ರಿಯೆ ಕೇಶಿಂಗ್**, ಅಥವಾ **ಬಂಧಿತ ಸಹಕಾಲಿಕತೆ** ಸೇರಿಸಿ.
- ಕೆಟ್ಟ ಏಜೆಂಟ್ ಆವೃತ್ತಿ ಬಿಡುಗಡೆ ಆಗದಂತೆ **ಮೌಲ್ಯಮಾಪನೆ ಗೇಟ್** ಸೇರಿಸಿ.
- ಹೆಚ್ಚಿನ ಅಪಾಯದ ಕ್ರಮಗಳಿಗೆ **ಮಾನವನ-ಪ್ರಕ್ರಿಯೆಯಲ್ಲಿ ಅನುಮೋದನೆ** ಹೆಜ್ಜೆ ಸೇರಿಸಿ.
- ಉತ್ಪಾದನಾ ಗಮನಾರ್ಹತೆಗೆ **OpenTelemetry** ಟ್ರೇಸಿಂಗ್ ಜೊತೆ ಏಜೆಂಟ್ ಅನ್ನು ಕಾರ್ಯಗೊಳಿಸಿ.
- ನಿಯೋಜನೆಯ ನಂತರದ ತ್ವರಿತ ಗೇಟ್ ರೂಪದಲ್ಲಿ ಏಜೆಂಟ್ ಅನ್ನು **ಸ್ಮೋಕ್-ಟೆಸ್ಟ್** ಮಾಡಿ.

## ಮೂಲ ಮಾನಸಿಕ ಮಾದರಿ

ಒಂದು ಉತ್ಪನ್ನ ಏಜೆಂಟ್ ಬಹುತೇಕವಾಗಿ ಮಾದರಿಯ ಸುತ್ತಲೂ ಕಾರ್ಯಾಚರಣಾತ್ಮಕ ಕೊಂಬು ರಚನೆ (*ಸುಮಾರು 80%*),
ಸ್ವತಃ ಮಾದರಿ ಅಲ್ಲ. ಪ್ರತಿಯೊಂದು ಶಿಫಾರಸನ್ನು ಈ ಚಿಂತೆಗಳಿಗೆ ಒಂದಾದ ನಂತರ ಒಂದಾಗಿ ನಕ್ಷೆ ಮಾಡು:

| ಚಿಂತೆ | ಪ್ರೋಟೋಟೈಪ್ → ಉತ್ಪಾದನೆ |
|---------|------------------------|
| ಹೋಸ್ಟಿಂಗ್ | ನೋಟ್ಬುಕ್ → ಆವೃತ್ತಿಯಾಗಿರುವ ಹೋಸ್ಟೆಡ್ ಸೇವೆ |
| ಐಡೆಂಟಿಟಿ | ನಿಮ್ಮ `az login` → ನಿರ್ವಹಿಸಲಾದ ಐಡೆಂಟಿಟಿ + ಸ್ಕೋಪ್ಡ್ RBAC |
| ಸ್ಥಿತಿ | ಸ್ಮರಣೆ-ಮಧ್ಯಸ್ಥ → ಹೊರಗಿನ ಥ್ರೆಡ್/ಸ್ಮರಣೆ ಅಂಗಿಡಿಸುವುದು |
| ವಿಫಲತೆ | ಟ್ರೇಸ್ಬ್ಯಾಕ್ → ಮರುಪ್ರಯತ್ನಗಳು, ಫಾಲ್ಬ್ಯಾಕ್ಸ್, ಎಚ್ಚರಿಕೆಗಳು |
| ವೆಚ್ಚ | "ಕೆಲವು ಸೆಂಟುಗಳು" → ಪಟ್ಟಿಗಟ್ಟಲಾಗುತ್ತದೆ, ಮಾರ್ಗೀಕೃತ, ಕೇಶಾಗ್ರಹಣ, ಬಡ్జೆಟ್ |
| ಗುಣಮಟ್ಟ | ಕಣ್ಣಡಿ ಹಿಡಿದು ನೋಡುವುದು → ಸ್ವಯಂಚಾಲಿತ ಮೌಲ್ಯಮಾಪನೆ ಗೇಟ್ |
| ನಂಬಿಕೆ | ನೀವು ಅನುಮೋದನೆ ನೀಡುತ್ತೀರಿ → ನೀತಿ + ಮಾನವನ-ಪ್ರಕ್ರಿಯೆಯಲ್ಲಿ |

## ನಿಯೋಜನೆ ಮಾದರಿಗಳು (ಒಂದನ್ನು ಆಯ್ಕೆಮಾಡಿ, ಅಥವಾ ಸಂಯೋಜಿಸಿ)

1. **ಕ್ಲೈಂಟ್-ಹೋಸ್ಟೆಡ್** — ಯೋಚನಾ ಲೂಪ್ ನಿಮ್ಮ ಪ್ರಕ್ರಿಯೆಯಲ್ಲಿ ಚಲಿಸುತ್ತದೆ. ಗರಿಷ್ಠ ನಿಯಂತ್ರಣ; ನೀವು ವಿಸ್ತರಣೆ/ಸ್ಥಿತಿಯನ್ನು ಹೊಂದಿರುತ್ತೀರಿ.
2. **ಹೋಸ್ಟೆಡ್ ಏಜೆಂಟ್ (ಫೌಂಡ್ರಿ ಏಜೆಂಟ್ ಸೇವೆ)** — ಫೌಂಡ್ರಿ ಲೂಪ್ ಅನ್ನು ಆತಿಥ್ಯ ಪಡಿಸುತ್ತದೆ, ಥ್ರೆಡ್ಗಳನ್ನು ಸಂಗ್ರಹಿಸುತ್ತದೆ, RBAC/ವಿಷಯ ಸುರಕ್ಷತೆಯನ್ನು ಅನ್ವಯಿಸುತ್ತದೆ, ಏಜೆಂಟ್ ಅನ್ನು ಪೋರ್ಟಲ್‌ನಲ್ಲಿ ತೋರಿಸುತ್ತದೆ. ಕಡಿಮೆ ನಿಯಂತ್ರಣ, ಬಹು ಕಡಿಮೆ ಕಾರ್ಯಾಚರಣಾತ್ಮಕ ವ್ಯಾಪ್ತಿ.
3. **ಏಜೆಂಟ್ ವರ್ಕ್‌ಫ್ಲೋ** — ಶಾಖೆಗಳ, ಅನುಮೋದನೆ ಸೂಚಕಗಳು ಮತ್ತು ದೀರ್ಘಕಾಲಿಕ ತಪಾಸಣೆಗಳೊಂದಿಗೆ ಹಲವಾರು ಏಜೆಂಟ್‌ಗಳು/ಸಾಧನಗಳನ್ನು ಮೇಲಾಗಿಸುತ್ತಿರುವ ಗ್ರಾಫ್.

## ಜೀವನಚಕ್ರ (ಏಜೆಂಟ್ ಅನ್ನು ಸಾಗಿಸುವ ಲೂಪ್)

`create → version → evaluate (gate) → deploy hosted → observe online → collect failures → repeat`.
**ಆಫ್‍ಲೈನ್ ಮೌಲ್ಯಮಾಪನವು ಒಂದು ಗേറ്റಾದ್ದಾಗಿದೆ, ನಂತರದ ವಿಚಾರವಲ್ಲ** — ಒಂದು ಆವೃತ್ತಿ ಗಡಿಯನ್ನು ದಾಟದಿದ್ದರೆ ಸಾಗಿಸುವುದಿಲ್ಲ.
ಆಗೇಜ್ಜುನಾಯಿಸುವ ದೃಢ ನಿಜವಾದ ದೋಷಗಳನ್ನು ಆನ್‌ಲೈನ್ ವೀಕ್ಷಣೆಯು ಆಫ್‍ಲೈನ್ ಪರೀಕ್ಷಾ ಸೆಟ್‌ಗೆ ಹಿಂತಿರುಗಿಸುತ್ತದೆ.


## ವಿಸ್ತರಣೆ ಮತ್ತು ವೆಚ್ಚ ಲೀಗಗಳು (ಪ್ರಾಧಾನ್ಯ ಕ್ರಮದಲ್ಲಿ)

1. **ಮಾದರಿಯನ್ನು ಸರಿಯಾದ ಗಾತ್ರಕ್ಕೆ ತಗ್ಗಿಸಿ** — ಮೌಲ್ಯಮಾಪನ ಗೇಟನ್ನು ದಾಟುವ ಅತ್ಯಂತ ಚಿಕ್ಕ ಮಾದರಿಯನ್ನು ಬಳಸಿ.
2. **ಸಂಕೀರ್ಣತೆಯನ್ನು ಆಧರಿಸಿ ಮಾರ್ಗವನ್ನು ನಿರ್ದಿಷ್ಟಮಾಡಿ** — ಸರಳ ವಿನಂತಿಗಳಿಗಾಗಿ ಸಣ್ಣ/ವೇಗವಾದ ಮಾದರಿ, ನಿಜವಾದ ತರ್ಕಕ್ಕಾಗಿ ದೊಡ್ಡ ಮಾದರಿ (DIY ವರ್ಗೀಕರಿಸುವ ಸಾಧನ ಅಥವಾ Foundry Model Router).
3. **ಕ್ಯಾಶೆ** — ಮಾದರಿ ಕರೆ ಇಲ್ಲದೆ ಸಮೀಪದ ಅನುರೂಪ ವಿನಂತಿಗಳ ಸೇವೆ.
4. **ಸ್ಥಿತಿ ರಹಿತ ವಿನ್ಯಾಸ + ನಿರ್ಬಂಧಿತ ಸಹಕಾಲಿಕತೆ** — ಸ್ಥಿತಿಯನ್ನು ಹೊರಗಡೆ ಇಡಿ; ಬ್ಯಾಕ್ಔಫ್ ಜೊತೆಗೆ ಮರುಪ್ರಯತ್ನಿಸಿ.

## ಪುನರಾವರ್ತಿಸುವ ಪ್ರಮುಖ ಮಾದರಿಗಳು

ವರ್ತಮಾನದ ಪುಸ್ತಕದಿಂದ ಕಲಿಯುವವರಿಗೆ ಇದನ್ನು ಸೂಚಿಸಿ
[`16-python-agent-framework.ipynb`](../../../16-deploying-scalable-agents/code_samples/16-python-agent-framework.ipynb):

- ** ವಿನಂತಿ ನಿರ್ವಾಹಕ**: ಕ್ಯಾಶೆ → ಸಂಕೀರ್ಣತೆಯ ಮೂಲಕ ಮಾರ್ಗ → ಟ್ರೇಸ್ ಸ್ಪ್ಯಾನ್ → ಚಲಾಯಿಸಿ → ಕ್ಯಾಶೆ.
- **ಮೌಲ್ಯಮಾಪನ ಗೇಟ್**: ಆಫ್‌ಲೈನ್ ಪರೀಕ್ಷಾ ಸೆಟ್ ಅನ್ನು ಸ್ಕೋರ್ ಮಾಡಿ; `pass_rate >= threshold` ಅನ್ನು ಹಿಂತಿರುಗಿಸಿ ಮತ್ತು ಸತ್ಯ ಇದ್ದರೆ ಮಾತ್ರ ನಿಯೋಜಿಸಿ.
- **ಮಾನವ ಅನುಮೋದನೆ**: ದೊಡ್ಡ ಹೂಡಿಕೆಗಳಂತಹ ಕ್ರಮಗಳಿಗೆ `@tool(approval_mode="always_require")`.
- **ಟ್ರೇಸಿಂಗ್**: ಪ್ರತಿ ವಿನಂತಿಯನ್ನು `tracer.start_as_current_span(...)` ನಲ್ಲಿ ಸುತ್ತಿಸಿ ಮತ್ತು `routed.model`, `customer.id` ಹಾಗು ಗುಣಗಳನ್ನು ಸೆಟ್ ಮಾಡಿ.

## ನಿಯೋಜಿಸಲಾದ ಏಜೆಂಟ್ ಅನ್ನು ಧೂಮ್ರಪಾನ ಪರೀಕ್ಷೆ ಮಾಡುವುದು

ನಿಯೋಜನೆಯ ನಂತರ, ಅಂತಿಮ ಬಿಂದುವು ವಾಸ್ತವವಾಗಿ ಪ್ರತಿಕ್ರಿಯಿಸುವುದನ್ನು ಪರಿಶೀಲಿಸಿ (ಹಸಿರು ನಿಯೋಜನೆ ಇನ್ನೂ ಸಹ
ಮೌನವಾಗಿರಬಹುದು). [AI Smoke Test](https://github.com/marketplace/actions/ai-smoke-test) ಸೇವೆ ಬಳಸಿರಿ
ಕ್ರಿಯೆ ಮೂಲಕ [`.github/workflows/smoke-test.yml`](../../../../../.github/workflows/smoke-test.yml)
[`tests/`](../../../tests/README.md) ನಲ್ಲಿ ಕ್ಯಾಟಲಾಗ್‌ನೊಂದಿಗೆ. ರನ್ನರ್ ಪ್ರತಿ
ಪ್ರಾಂಪ್ಟ್ ಅನ್ನು `POST {project_endpoint}/agents/{agent_name}/endpoint/protocols/openai/responses` ಗೆ POST ಮಾಡುತ್ತದೆ
ಮತ್ತು ಉತ್ತರ ಪಠ್ಯದ ಮೇಲೆ ದೃಢಪಡಿಸುತ್ತದೆ. ಆ ಆಯ್ಕೆ **Azure AI User** ಪಾತ್ರವನ್ನು ಹೊಂದಿರಬೆಕು
Foundry ಪ್ರಾಜೆಕ್ಟ್ ವ್ಯಾಪ್ತಿಯಲ್ಲಿ; ಟೋಕನ್ ಪ್ರೇಕ್ಷಕರಾಗಿರುವವರು ಸಹ `https://ai.azure.com/` ಆಗಿರಬೇಕು.

ಗೇಟುಗಳನ್ನು ಹಿರಿದುಮಾಡಿ: **ಸ್ಮೋಕ್ ಟೆಸ್ಟ್** (ಹಾಕಬಹುದಾದ/ಪ್ರತಿಕ್ರಿಯಿಸುವ, ಪ್ರತಿಯೊಂದು ನಿಯೋಜನೆ) → **ಆಫ್‌ಲೈನ್
ಮೌಲ್ಯಮಾಪನ** (ಕಡತ ಮಾಡಬೇಕಾದಷ್ಟು ಉತ್ತಮ, ಉತ್ತರಣೆಯ ಮೊದಲು) → **ಆನ್‌ಲೈನ್ ಮೌಲ್ಯಮಾಪನ** (ಇದೊಂದು ಜಂಗಲದಲ್ಲಿ ಹೇಗೆ ನಡೆಯುತ್ತಿದೆ, ನಿರಂತರ).


## ಎಂಟರ್ಪ್ರೈಸ್ ನಿಯಂತ್ರಣಗಳು

- **RBAC**: ಪ್ರತಿಯೊಂದು ಹೋಸ್ಟಿಂಗ್ ಏಜೆಂಟ್‌ಗೆ ಕನಿಷ್ಠ ಆಧಿಕಾರಗಳೊಂದಿಗೆ ನಿರ್ವಹಿಸಲ್ಪಟ್ಟ ಗುರುತನ್ನು ನೀಡಿ.
- **ಪ್ರೊಡಕ್ಷನ್‌ನಲ್ಲಿ MCP**: ಪ್ರತಿಯೊಂದು MCP ಸರ್ವರ್ ಅನ್ನು ನಿರ್ವಿಡಂಬನೆ ಗಡಭಾಗವಾಗಿ ಪರಿಗಣಿಸಿ — ಆವೃತ್ತಿ ನಿಶ್ಚಿತವಾಗಿ ಮಾಡಿ, ಅದರ ಗುರುತನ್ನು ವ್ಯಾಪ್ತಿಗೊಳಿಸಿ, ಔಟ್ಪುಟ್‌ಗಳನ್ನು ಪರಿಶೀಲಿಸಿ, ದರಭಾಗದ ನಿಯಂತ್ರಣ ಹಾಕಿ, ರಹಸ್ಯಗಳನ್ನು ಎಂದಿಗೂ ಬಹಿರಂಗಪಡಿಸಬೇಡಿ.

## ಸಹಾಯಕನಿಗೆ ಗಾರ್ಡ್‌ರೈಲ್ಸ್

- ಕೋರ್ಸ್‌ಗೆ ಬಳಕೆಯಾದ ಮಾನ್ಯಕರಣ `FoundryChatClient(...)` + `provider.as_agent(...)` ಮಾದರಿಯನ್ನು ಶಿಫಾರಸು ಮಾಡಿ.
- ನೀವು ಪರಿಶೀಲಿಸದ ನೇರ-ಆಜೂರ್ ಫಲಿತಾಂಶಗಳನ್ನು ವಾಗ್ದಾನ ಮಾಡಬೇಡಿ; ನಿಯೋಜನೆಯನ್ನು ದೃಢಪಡಿಸಲು ಸ್ಮೋಕ್-ಟೆಸ್ಟ್ ವರ್ಕ್‌ಫ್ಲೋವನ್ನು ಶಿಫಾರಸು ಮಾಡಿ.
- ಮೌಲ್ಯಮಾಪನ ಮತ್ತು ವೆಚ್ಚ ಸಲಹೆಗಳನ್ನು ಜೊತೆಗೆ ಇರಿಸಿ: ಮೌಲ್ಯಮಾಪನ ಗುಣಮಟ್ಟದ ನೆಲೆಯನ್ನು ಹೊಂದಿಸುತ್ತದೆ, ಮಾರ್ಗವಾಯು/ಕ್ಯಾಶಿಂಗ್ ವೆಚ್ಚವನ್ನು ಆ ನೆಲೆಗೆ ಹತ್ತಿರ ಇರಿಸುತ್ತದೆ.
