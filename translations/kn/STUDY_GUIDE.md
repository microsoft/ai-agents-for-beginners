# ಹೊಸಬರಿಗೆ AI ಏಜೆಂಟ್ಸ್ - ಅಧ್ಯಯನ ಮಾರ್ಗದರ್ಶಿ

ಈ ಮಾರ್ಗದರ್ಶಿಯನ್ನು ಕೋರ್ಸ್ ಮೂಲಕ ಸಾಗುವಾಗ ಪ್ರಸಕ್ತ ಸಹಚರರಂತೆ ಉಪಯೋಗಿಸಿ. ಇದು
ಪಾಠಗಳನ್ನು ಬದಲಿ ಮಾಡಲು ಉದ್ದೇಶಿಸಿಲ್ಲ. ಇದು ನೀವು ಎಲ್ಲಿ ಪ್ರಾರಂಭಿಸಬೇಕು, ಪ್ರತಿ ಪಾಠದಲ್ಲಿ ಏನು
ನೋಡಬೇಕು ಮತ್ತು ಐಡಿಗಳನ್ನು ಸಣ್ಣ ಕಾರ್ಯನಿರತ ಏಜೆಂಟ್ ಡೆಮೋಗೆ ಹೇಗೆ ಸಂಪರ್ಕಿಸಬೇಕು ಎಂದು ನಿರ್ಧರಿಸಲು ಸಹಾಯ ಮಾಡುತ್ತದೆ.


ನೀವು ಇಲ್ಲಿ ಮೊದಲ ಸಲ ಬಂದಿದ್ದರೆ, ಸರಳವಾಗಿ ಪ್ರಾರಂಭಿಸಿ:

1. [ಕೋರ್ಸ್ ಸೆಟಪ್](./00-course-setup/README.md) ಓದಿ.
2. ಕ್ರಮವಾಗಿ ಪಾಠ 01-06 ಪೂರ್ಣಗೊಳ್ಳಿಸಿ.
3. ನೀವು ಕಲಿಯುತ್ತಿರುವಾಗ ಒಂದು ಸಣ್ಣ ಡೆಮೋ ಐಡಿಯಾವನ್ನು ಮನೆಯಲ್ಲಿ ಇರಿಸಿಕೊಂಡಿರಿ.
4. ಪ್ರತಿ ಪಾಠದ ನಂತರ, ಕೇಳಿ: "ನನ್ನ ಏಜೆಂಟ್ ಇದೀಗ ಏನು ಮಾಡಬಹುದು, ಇದಕ್ಕೂ ಮುಂಚೆ ಮಾಡಲಾಗಿಲ್ಲ?"


## ಮನೆಯಲ್ಲಿ ಇಡುವ ಸರಳ ಡೆಮೋ

ಏಜೆಂಟ್ಗಳನ್ನು ಕಲಿಯಲು ಒಳ್ಳೆಯ ವಿಧಾನವೆಂದರೆ ಕೋರ್ಸ್ ಮೂಲಕ ಒಂದು ಡೆಮೋ ಐಡಿಯಾವನ್ನು ಅನುಸರಿಸುವುದು.

ಉದಾಹರಣಾ ಡೆಮೋ: **ಕೋರ್ಸ್ ಸಹಾಯಕ ಏಜೆಂಟ್**.

ಬಳಕೆದಾರನು ಕೇಳುತ್ತಾನೆ:

> "ನನಗೆ ಏಜೆಂಟ್ಗಳು ಸಾಧನಗಳನ್ನು ಹೇಗೆ ಬಳಸುತ್ತಾರೆ ಎಂದು ಕಲಿಯಬೇಕು. ಸರಿಯಾದ ಪಾಠಗಳನ್ನು ಹುಡುಕಿ,
> ನಾನು ಮೊದಲು ಏನು ಓದಬೇಕು ಎಂದು ಸಾರಾಂಶ ನೀಡು ಮತ್ತು ನನಗೆ ಒಂದು ಸಣ್ಣ ಅಭ್ಯಾಸ ಕಾರ್ಯವನ್ನು ಕೊಡು."

ಸಾಮಾನ್ಯ ಚಾಟ್‌ಬಾಟ್ ಈಗಾಗಲೇ ತಿಳಿದಿರುವಿಂದ ಉತ್ತರಿಸಬಹುದು. ಏಜೆಂಟ್ ಹೆಚ್ಚು ಮಾಡಬಲ್ಲದು:

1. **ಕೋರ್ಸ್ ಕಡತಗಳನ್ನು ಓದಿ ಅಥವಾ ಹುಡುಕಿ** ಸರಿಯಾದ ಪಾಠಗಳನ್ನು ಪತ್ತೆಮಾಡಲು.
2. **ಸಾಧನಗಳನ್ನು ಬಳಸಿ** ಪಾಠ ಲಿಂಕ್‌ಗಳು, ಉದಾಹರಣೆಗಳು ಅಥವಾ ಬೆಂಬಲಿಸುವ ವಸ್ತುಗಳನ್ನು ಪಡೆಯಲು.
3. **ಯೋಜನೆ** ಒಂದು ಸೋಲು ವಾಸ್ತವಿಕ ಪಾಠ ಮಾರ್ಗವನ್ನು ಕೊಡದೆ ಬದಲಾಗಿ.
4. **ಸಂದರ್ಭವನ್ನು ಉಪಯೋಗಿಸಿ** ಪ್ರಸ್ತುತ ಸಂಭಾಷಣೆಯಿಂದ ಕಲಿಕೆಗೆ ಗುರಿಯನ್ನು ಗಮನದಲ್ಲಿಡಲು.
5. **ಉಪయోగಪೂರ್ಣ ಆಯ್ಕೆಗಳನ್ನು ನೆನಪಿಡಿ** ಅಪ್ಲಿಕೇಶನ್ ಮೆಮರಿ ಬೆಂಬಲಿಸಿದರೆ.
6. **ಟ್ರೇಸ್‌ಗಳು, ಉಲ್ಲೇಖಗಳು ಅಥವಾ ಲಾಗ್‌ಗಳನ್ನು ತೋರಿಸಿ** ಬಳಕೆದಾರನು ಆಗಿರುವುದನ್ನು ತಿಳಿದುಕೊಳ್ಳಲು.
7. **ರಕ್ಷಾ ನಿಯಮಗಳನ್ನು ಅನ್ವಯಿಸಿ** ಅಪಾಯಕರ ಕ್ರಿಯೆಗಳು ಅಥವಾ ಸಂವೇದಿ ಡೇಟಾ ಬಳಕೆಮಾಡುವ ಮುನ್ನ.


ಪ್ರತಿ ಪಾಠ ಅಧ್ಯಯನ ಮಾಡುತ್ತಿದ್ದಾಗ, ಈ ಡೆಮೋಗೆ ಮರಳಿರಿ ಮತ್ತು ಕೇಳಿ: ಈ ಪಾಠ ಹೊಸದೇನಾದರೂ ಸಾಮರ್ಥ್ಯವನ್ನು ಸೇರಿಸುತ್ತದೆ ಅಂದ್ರೆ ಏನು?

## ಮಾದರಿಗಳು ಮತ್ತು ಒದಗಿಸುವವರು

ಕೋರ್ಸ್ ಕೋಡ್ ಉದಾಹರಣೆಗಳು **Microsoft Agent Framework (MAF)** ಉಪಯೋಗಿಸುತ್ತವೆ ಮತ್ತು ಗುರಿಯಾಗಿರುವವು **Azure OpenAI Responses API** — ಮುಂದುವರೆಯುವ ಶಿಫಾರಸು ಮಾಡಲಾದ API, ಇದು ಚಾಟ್ ಪೂರ್ಣತೆಗಳು, ಸಾಧನ ಕರೆ, ಬಹುಮೋಡುಲ್ ಇನ್ಪುಟ್, ಮತ್ತು ಸ್ಥಿರ ಸಂಭಾಷಣೆಗಳನ್ನು ಒಂದೇ API ಮೇಲ್ಮೈನಲ್ಲಿ ಸಂಯೋಜಿಸುತ್ತದೆ. ನೀವು **Microsoft Foundry** ಪ್ರಾಜೆಕ್ಟ್ (`FoundryChatClient` ಜೊತೆ) ಮೂಲಕ ಅಥವಾ ನೇರವಾಗಿ Azure OpenAI ಜೊತೆಗೆ (`OpenAIChatClient` ಜೊತೆ) ಸಂಪರ್ಕಿಸಿ.


ಪಾಠಗಳನ್ನು ಮುಗಿಸುತ್ತಿರುವಾಗ, ನಿಮಗೆ ಕೆಲವು ಪೂರೈಕೆದಾರ ಆಯ್ಕೆಗಳು ಇವೆ:

- **Microsoft Foundry / Azure OpenAI (Responses API)** — ಪಾಠಗಳಾದ್ಯಾಂತ ಬಳಸುವ ಪ್ರಾಥಮಿಕ ಮಾರ್ಗ. ಕೀಲಿಕೋಡ್ ಇಲ್ಲದ Entra ID ಪ್ರಮಾಣೀಕರಣಕ್ಕಾಗಿ `az login` ಬಳಸಿ ಸೈನ್ ಇನ್ ಆಗಿ.
- **Foundry Local** — OpenAI-ಸುಸಮ್ಮತ API ಮುಖಾಂತರ ಸಂಪೂರ್ಣವಾಗಿ ಸಾಧನದಲ್ಲಿ ಮಾದರಿಗಳನ್ನು ಚಾಲನೆ ಮಾಡಿರಿ (ಯಾವುದೇ ಕ್ಲೌಡ್ ಅಥವಾ API ಕೀಲಿಗಳು ಬೇಕಾಗಿಲ್ಲ). ಆಫ್‌ಲೈನ್ ಅಥವಾ ವೆಚ್ಚವಿಲ್ಲದ ಪ್ರಯೋಗ ಪ್ರಕ್ರಿಯೆಗಳಿಗಾಗಿ ಅತ್ಯುತ್ತಮ. [ಪಾಠ ಕಾರ್ಯಕ್ರಮ ಸಿದ್ಧತೆ](./00-course-setup/README.md) ನೋಡಿ.
- **MiniMax** — ದೊಡ್ಡ-ಸಂದರ್ಭ ಮಾದರಿಗಳೊಂದಿಗೆ OpenAI-ಸುಸಮ್ಮತ ಪೂರೈಕೆದಾರ, ಡ್ರಾಪ್-ಇನ್ ಪರ್ಯಾಯವಾಗಿ ಬಳಸಬಹುದು.

> **ಖಚಿತಪಡಿಸಿ:** GitHub ಮಾದರಿಗಳು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಲಾಗಿದೆ (ಜುಲೈ 2026 ರಲ್ಲಿ ಸೇವೆಯಿಂದ ತೆಗೆಯಲಾಗುತ್ತದೆ) ಮತ್ತು Responses API ಅನ್ನು ಬೆಂಬಲಿಸುವುದಿಲ್ಲ. ಉದಾಹರಣೆಗಳನ್ನು ಅನುಕೂಲಗೊಳಿಸಲು Azure OpenAI / Microsoft Foundry ಉಪಯೋಗಿಸಲಾಗಿದೆ.

## ಬಿಡುಗಡೆ ಮಾಡಿದ ಏಜೆಂಟ್‌ಗಳನ್ನು ಸ್ಮೋಕ್ ಪರೀಕ್ಷೆಗಳೊಂದಿಗೆ ಪರಿಶೀಲಿಸುವುದು

ನೀವು ಏಜೆಂಟ್ ಅನ್ನು ನಿಯೋಜಿಸುವಾಗ (ಪಾಠ 16), ಒಂದು **ಸ್ಮೋಕ್ ಟೆಸ್ಟ್** ಅನ್ನು ಮೊದಲು
ಮಾಡಲಾಗುವ ಕಡಿಮೆ ವೆಚ್ಚದ ಪರಿಶೀಲನೆ ಎಂದು ಹೇಳಬಹುದು, ಇದು ನಿಯೋಜನೆ ನಿಜವಾಗಿಯೂ
ಉತ್ತರ ನೀಡುತ್ತದೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸುತ್ತದೆ. ಈ ರೆಪೊವು ಪಾಠಗಳು 01, 04, 05, ಮತ್ತು 16ರ
ನಿಯೋಜಿಸಲು ಸಾಧ್ಯವಿರುವ ಏಜೆಂಟ್‌ಗಳಿಗಾಗಿ [tests/](./tests/README.md) ಅಡಿಯಲ್ಲಿ ರೆಡಿ-ಟು-ರನ್ ಕಟಲಾಗ್‌ಗಳನ್ನು
ಮತ್ತು [AI Smoke Test](https://github.com/marketplace/actions/ai-smoke-test) GitHub
ಆಕ್ಷನ್‌ಗಳಿಗೆ ಸಂಪರ್ಕಿಸುತ್ತದೆ. ಪಾಠದ ಏಜೆಂಟ್ ನಿಯೋಜಿಸಿದ ನಂತರ **ಆಕ್ಷನ್‌ಗಳು** ಟ್ಯಾಬ್‌ನಿಂದ ಅವುಗಳನ್ನು ನಡಿಸಿ.
ಸ್ಮೋಕ್ ಪರೀಕ್ಷೆಗಳು ಮೊದಲ ದ್ವಾರವೇ — ಆಫ್‌ಲೈನ್ ಮತ್ತು ಆನ್‌ಲೈನ್ ಮೌಲ್ಯಮಾಪನಗಳು (ಪಾಠಗಳು 10 ಮತ್ತು 16)
ನಿಮಗೆ ಏಜೆಂಟ್ ಎಷ್ಟರ ಮಟ್ಟಿಗೆ *ಚೆನ್ನಾಗಿರೋದು* ಎಂಬುದನ್ನು ತಿಳಿಸುತ್ತವೆ.

## ಪ್ರಾರಂಭಿಕರಿಗೂ ಸುಲಭವಾಗಿ ಅರ್ಥಮಾಡಿಕೊಳ್ಳುವ ಪ್ರಮುಖ ಆಲೋಚನೆಗಳು

### ಉಪಕರಣಗಳು

ಉಪಕರಣ ಎಂದರೆ ಮಾದರಿಯ ಹೊರಗೆ ಕೆಲಸ ಮಾಡಲು ಏಜೆಂಟ್ ಕರೆಮಾಡಬಹುದಾದ ಕೈಗಾರಿಕೆ. ಒಳ್ಳೆಯ ಉಪಕರಣ
ಸ್ಪಷ್ಟ ಹೆಸರಿನ, ಸೀಮಿತ ಕೆಲಸದ, ಶ್ರೇಣೀಕೃತ ಇನ್‌ಪುಟ್‌ಗಳ, ನಿರೀಕ್ಷಿತ ಔಟ್‌ಪುಟ್ ಮತ್ತು
ವಿಫಲವಾಗುವ ಸುರಕ್ಷಿತ ರೀತಿಯೊಂದಿಗೆ ಇರುತ್ತದೆ.

ಕೋರ್ಸ್ ಸಹಾಯಕ ಪ್ರದರ್ಶನಕ್ಕಾಗಿ, ಉಪಕರಣಗಳು ಇವುಗಳಾಗಬಹುದು:

- `search_lessons(query)`
- `read_lesson(path)`
- `create_practice_task(topic)`

### RAG ಮತ್ತು ಜ್ಞಾನ

RAG ಏಜೆಂಟ್‌ಗೆ ಊಹಿಸುವ ಬದಲು ಮೂಲ ವಸ್ತುವಿನಿಂದ ಉತ್ತರ ನೀಡಲು ಸಹಾಯ ಮಾಡುತ್ತದೆ. ಈ
ಕೋರ್ಸ್‌ನಲ್ಲಿ, ಆ ಮೂಲ ವಸ್ತು ಪಾಠಗಳ READMEಗಳು, ಕೋಡ್ ಉದಾಹರಣೆಗಳು ಅಥವಾ ಪಾಠಗಳಿಂದ ಲಿಂಕ್ ಮಾಡಲಾದ ಬಾಹ್ಯ
ಸಂಪನ್ಮೂಲಗಳಾಗಿರಬಹುದು.

ಉತ್ತರವು ದಾಖಲೆಗಳು, ಡೇಟಾ ಅಥವಾ ಪ್ರಸ್ತುತ
ಪ್ರಾಜೆಕ್ಟ್ ಫೈಲ್‌ಗಳಲ್ಲಿ ಆಧಾರಿತವಾಗಿರಬೇಕು ಎಂಬಾಗ RAG ಬಳಸಿ.

### ಯೋಜನೆ

ವಿನಂತಿಗೆ ಒಂದು ಹಂತಕ್ಕಿಂತ ಹೆಚ್ಚಿನ ಹಂತಗಳಿದ್ದಾಗ ಯೋಜನೆ ಉಪಯುಕ್ತ. ಯೋಜನೆಗಳನ್ನು ಸಂಕ್ಷಿಪ್ತ ಮತ್ತು
വികസಕರ ಅಥವಾ ಬಳಕೆದಾರನ ಪರಿಶೀಲಿಗೆ ಸ್ಫಷ್ಟವಾಗಿ ಇರಲಿ.

ಪ್ರದರ್ಶನಕ್ಕೆ ಇದು ಹೀಗಿರಬಹುದು:

1. ಉಪಕರಣ ಬಳಕೆಯ ಸಂಬಂಧಿತ ಪಾಠಗಳನ್ನು ಹುಡುಕಿ.
2. ಅತ್ಯಂತ ಪ್ರಾಸಂಗಿಕ ಪಾಠಗಳನ್ನು ಸಾರಾಂಶ ಮಾಡಿ.
3. ಒಂದು ಅಭ್ಯಾಸ ಕಾರ್ಯವನ್ನು ಶಿಫಾರಸು ಮಾಡಿ.

### ಸಂಧರ್ಭ

ಸಂಧರ್ಭ ಎಂದರೆ ಮಾದರಿ ಇದೀಗ ನೋಡುತ್ತಿರುವುದು. ಅಲ್ಪ ಸಂಧರ್ಭ ಏಜೆಂಟ್‌ಗೆ
ಪ್ರಮುಖ ವಿವರಗಳನ್ನು ತಪ್ಪಿಸುವಂತೆ ಮಾಡಬಹುದು. ಹೆಚ್ಚು ಸಂಧರ್ಭ ಏಜೆಂಟ್ ಅನ್ನು ನಿಧಾನಗೊಳಿಸಬಹುದು, ಹೆಚ್ಚು ವೆಚ್ಚವಾಗಿಸಬಹುದು
ಅಥವಾ ಸುಲಭವಾಗಿ ಗೊಂದಲಕ್ಕೆ ತರುತ್ತದೆ.

ಉತ್ತಮ ಸಂಧರ್ಭ ಎಂಜಿನಿಯರಿಂಗ್ ಎಂದರೆ ಮುಂದಿನ ಮಾದರಿ
ಕಾಲ್‌ಗೆ ಸರಿಯಾದ ಮಾಹಿತಿಯನ್ನು ಆಯ್ಕೆ ಮಾಡುವುದು.

### ಸ್ಮರಣೆ

ಸ್ಮರಣೆ ಎಂದರೆ ನಂತರಕ್ಕಾಗಿ ಉಳಿಸಿರುವ ಮಾಹಿತಿ. ಎಲ್ಲವನ್ನೂ ಉಳಿಸಬೇಡಿ. ಮಾಹಿತಿ
ಉಪಯುಕ್ತ, ಸುರಕ್ಷಿತ ಮತ್ತು ಸುಲಭವಾಗಿ ನವೀಕರಿಸಲು ಅಥವಾ ತೆಗೆದುಹಾಕಲು ಸಾಧ್ಯವಾದಾಗ ಮಾತ್ರ ಉಳಿಸಿರಿ.

ಉದಾಹರಣೆಗೆ, "ಶಿಕ್ಷಣಾರ್ಥಿ ಪೈಥಾನ್ ಉದಾಹರಣೆಗಳನ್ನು ಪ್ರಾಧಾನ್ಯಗೊಳಿಸುತ್ತಾನೆ" ಎಂಬುದನ್ನು ಸ್ಮರಿಸುವುದು ಉಪಯುಕ್ತವಾಗಬಹುದು.
ಸೆನ್ಸಿಟಿವ್ ವೈಯಕ್ತಿಕ ಡೇಟಾವನ್ನು ಸ್ಮರಿಸುವುದು ಸಾಮಾನ್ಯವಾಗಿ ಅಲ್ಲ.

### ಮೌಲ್ಯಮಾಪನ ಮತ್ತು ಗಮನಾರ್ಹತೆ

ಮೌಲ್ಯಮಾಪನ ಪ್ರಶ್ನೆ: ಏಜೆಂಟ್ ಸರಿಯಾದ ಕೆಲಸ ಮಾಡಿದೆಯೇ?

ಗಮನಾರ್ಹತೆ ಪ್ರಶ್ನೆ: ಅದನ್ನು ಹೇಗೆ ಸಂಭವಿಸಿದೆ ನಾವು ನೋಡಬಹುದೇ?

ಉತ್ಪಾದನಾ ಏಜೆಂಟ್‌ಗಾಗಿ, ಮಾದರಿ ಕಾಲ್‌ಗಳು, ಉಪಕರಣ ಕಾಲ್‌ಗಳು, ತಾನಾಗಿತ್ತ
ಸಂಧರ್ಭ, ವಿಳಂಬ, ವೆಚ್ಚ, ವೈಫಲ್ಯಗಳು ಮತ್ತು ಬಳಕೆದಾರ ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಟ್ರ್ಯಾಕ್ ಮಾಡಿ.

### ನಂಬಿಕೆ ಮತ್ತು ಸುರಕ್ಷತೆ

ನಂಬಲರ್ಹ ಏಜೆಂಟ್‌ಗಳಿಗೆ ಕೇವಲ ಸಹಾಯಕ ಪ್ರಾಂಪ್ಟ್‌ಕ್ಕಿಂತ ಹೆಚ್ಚಾಗಿರಬೇಕು. ಕನಿಷ್ಠ-ಅಧಿಕಾರ ಉಪಕರಣಗಳನ್ನು ಉಪಯೋಗಿಸಿ,
ಹೆಚ್ಚಿನ ಪ್ರಮಾಣಿೀಕರಣ ಕ್ರಮಗಳಿಗೆ ಮಾನವ ಅನುಮೋದನೆ, ಡೇಟಾ ರೆಡಾಕ್ಷನ್ ಅಗತ್ಯವಿದ್ದಾಗ, ಮತ್ತು ಪರೀಕ್ಷಿತ ಅಥವಾ
ಪರಿಶೀಲನೆಗೊಂಡ ಕ್ರಿಯೆಗಳಿಗಾಗಿ ಲಾಗ್‌ಗಳು ಅಥವಾ ರಸೀದಿಗಳನ್ನು ಬಳಸಿ.

## 15 ನಿಮಿಷಗಳ ಪರಿಶೀಲನಾ ಕ್ರಮ

ಪ್ರತಿ ಪಾಠದ ನಂತರ ಈ ಕ್ರಮವನ್ನು ಉಪಯೋಗಿಸಿ:

1. **ಪಾಠವನ್ನು ಒಂದು ವಾಕ್ಯದಲ್ಲಿ ಸಾರಾಂಶ ಮಾಡಿ.**
2. **ಹೊಸ ಏಜೆಂಟ್ ಸಾಮರ್ಥ್ಯವನ್ನು ಹೆಸರಿಸಿ.** ಉದಾಹರಣೆ: ಉಪಕರಣ ಬಳಕೆ, ವಾಪಸೂಟಿ,
   ಯೋಜನೆ, ಸ್ಮರಣೆ, ಗಮನಾರ್ಹತೆ ಅಥವಾ ಸುರಕ್ಷತೆ.
3. **ನಿಮ್ಮ ಕೋರ್ಸ್ ಸಹಾಯಕ ಪ್ರದರ್ಶನಕ್ಕೆ ಅದನ್ನು ಸೇರಿಸಿ.** ಈಗ ಪ್ರದರ್ಶನದಲ್ಲಿ ಏನು ಬದಲಾಗಿದೆ?
4. **ಹೊಂದಾಣಿಕೆಯನ್ನು ಕಂಡುಹಿಡಿಯಿರಿ.** ಈ ಸಾಮರ್ಥ್ಯವನ್ನು ದುರುಪಯೋಗ ಮಾಡಿದರೆ ಏನು ತಪ್ಪು ಸಂಭವಿಸಬಹುದು?
5. **ಒಂದು ಪರೀಕ್ಷಾ ಪ್ರಶ್ನೆ ಬರೆಯಿರಿ.** ಏಜೆಂಟ್ ಚೆನ್ನಾಗಿ ನಡೆದುಕೊಂಡಿದೆಯೇ ಎಂದು ನೀವು ಹೇಗೆ ಪರಿಶೀಲಿಸುವಿರಾ?

## ತ್ವರಿತ ಸ್ವಯಂ ಪರಿಶೀಲನೆ

ಮುಂದಕ್ಕೆ ಹೋಗುವ ಮುನ್ನ, ಈ ಪ್ರಶ್ನೆಗಳಿಗೆ ಉತ್ತರಿಸಲು ಪ್ರಯತ್ನಿಸಿ:

1. ಏಜೆಂಟ್ ಒಂದು ಸಾಮಾನ್ಯ ಚಾಟ್‌ಬಾಟ್ ಸ್ವತಃ ಮಾಡಲು ಸಾಧ್ಯವಿಲ್ಲದ ಕಾರ್ಯವನ್ನು ಏನು ಮಾಡಬಹುದು?
2. ನಿಮ್ಮ ಏಜೆಂಟ್‌ಗೆ ಮೊದಲ ಉಪಕರಣ ಯಾವುದು ಬೇಕಾಗಿರಲಿದ್ದು, ಅದರ ಕಾರಣ ಏನು?
3. ಏಜೆಂಟ್ ಉತ್ತರಕ್ಕೆ ಯಾವ ಜ್ಞಾನ ಮೂಲ ಆಧಾರವಾಗಬೇಕು?
4. ಮುಂದಿನ ಮಾದರಿ ಕಾಲ್‌ಗೆ ಯಾವ ಸಂಧರ್ಭ ಸೇರ್ಪಡೆ ಮಾಡಬೇಕು?

5. ಏಜೆಂಟ್ ಏನು ನೆನಸಿಕೊಳ್ಳಬೇಕು ಮತ್ತು ಏನು ಸಂಗ್ರಹಿಸುವುದನ್ನು ತಪ್ಪಿಸಿಕೊಳ್ಳಬೇಕು?
6. ಏಜೆಂಟ್ ಮಾನವ ಅನುಮೋದನೆ ಯಾವಾಗ ಕೇಳಬೇಕು?
7. ಏಜೆಂಟ್ ಅನ್ನು ನಂತರ ಡೀಬಗ್ ಅಥವಾ ಆಕಾರಿಸಲು ಯಾವ ಲಾಗ್‌ಗಳು, ಟ್ರೇಸ್‌ಗಳು ಅಥವಾ ರಸೀದಿಗಳು ಸಹಾಯಗೊಳ್ಳಬಹುದು?


## ಶಿಫಾರಸು ಮಾಡಿದ ಕ್ಯಾಪ್‌ಸ್ಟೋನ್ ವ್ಯಾಯಾಮ

ಕೋರ್ಸ್‌ನ ಕೊನೆಯಲ್ಲಿ, ಈ
ರೆಪೊಸಿಟರಿಯನ್ನು ಸಾಗಿಸಲು ಓದುವವರಿಗೆ ಸಹಾಯ ಮಾಡುವ ಸಣ್ಣ ಏಜೆಂಟ್ ಅನ್ನು ನಿರ್ಮಿಸಿ.

ಕನಿಷ್ಠ ಆವೃತ್ತಿ:

- ಬಳಕೆದಾರರಿಂದ ಒಂದು ವಿಷಯವನ್ನು ಸ್ವೀಕರಿಸಿ.
- ಅತ್ಯಂತ ಸಂಬಂಧಿತ ಪಾಠಗಳನ್ನು ಹುಡುಕಿ.
- ಮೊದಲು ಏನು ಓದಬೇಕೆಂದು ಸಾರಾಂಶ ನೀಡಿರಿ.
- ಒಂದು ಕೈ-ಮೈ ಅನುಷ್ಠಾನ ಕಾರ್ಯವನ್ನು ಶಿಫಾರಸು ಮಾಡಿ.
- ಯಾವ ಪಾಠದ ಕಡತಗಳು ಅಥವಾ ಲಿಂಕ್‌ಗಳನ್ನು ಬಳಸಲಾಗಿದೆ ಎಂದು ತೋರಿಸಿ.

ವಿಸ್ತರಣಾ ಆವೃತ್ತಿ:

- ಓದುವವರ ಇಷ್ಟದ ಪ್ರೋಗ್ರಾಮಿಂಗ್ ಭಾಷೆಯನ್ನು ನೆನಪಿಡಿ.
- ಉತ್ತರಿಸುವ ಮೊದಲು ಸರಳ ಯೋಜನೆಯನ್ನು ಬಳಸಿ.
- ಅಂತಿಮ ಪ್ರತಿಕ್ರಿಯೆಯ ಮೊದಲು ಸ್ವಯಂ-ಪರಿಶೀಲನೆ ಹಂತವನ್ನು ಸೇರಿಸಿ.
- ಉಪಕರಣ ಕರೆಗಳು ಮತ್ತು ಪಡೆದ ಮೂಲಗಳನ್ನು ಲಾಗ್ ಮಾಡಿ.
- ಬ್ರೌಸರ್ ಅಥವಾ UI ಸ್ವಯಂಚಾಲಿತ ಕಾರ್ಯಗಳನ್ನು ತೆರೆದುಕೊಳ್ಳುವ ಮೊದಲು ದೃಢೀಕರಣ ಕೇಳಿ.

ಇದು ನಿಮಗೆ ಒಂದೇ ಯೋಜನೆಯಲ್ಲಿ ಉಪಕರಣಗಳು, RAG, ಯೋಜನೆ,
ಪ್ರಾಸಂಗಿಕತೆ, ಸ್ಮೃತಿ, ವಿಶ್ಲೇಷಣೆ ಮತ್ತು ನಂಬಿಕೆಯನ್ನು ಅಭ್ಯಾಸ ಮಾಡುವ ಸಣ್ಣ ಆದರೆ ವಾಸ್ತವಿಕ ವಿಧಾನವನ್ನು ಕೊಡುತ್ತದೆ.
