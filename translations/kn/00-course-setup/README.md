### ಶ್ಯಾಲೋ ಕ್ಲೋನ್ (ವರ್ಕ್‌ಶಾಪ್ / ಕೋಡ್ಸ್ಪೇಸ್ಗಾಗಿ ಶಿಫಾರಸು)

  > ಸಂಪೂರ್ಣ ರೆಪೊಸಿಟರಿ ಪೂರ್ಣ ಇತಿಹಾಸ ಮತ್ತು ಎಲ್ಲಾ ಫೈಲ್‌ಗಳನ್ನು ಡೌನ್‌ಲೋಡ್ ಮಾಡಿದಾಗ ದೊಡ್ಡದು ಆಗಬಹುದು (~3 GB). ನೀವು ಕೇವಲ ವರ್ಕ್‌ಶಾಪ್‌ಗೆ ಹಾಜರಾಗುತ್ತಿರುವವರಾಗಿದ್ದರೆ ಅಥವಾ ಕೆಲವು ಪಾಠದ ಫೋಲ್ಡರ್‌ಗಳು ಬೇಕಾಗಿದ್ದರೆ, ಶ್ಯಾಲೋ ಕ್ಲೋನ್ (ಅಥವಾ ಸ್ಪಾರ್ಸ್ ಕ್ಲೋನ್) ಇತಿಹಾಸವನ್ನು ಕಡಿತಮಾಡಿ ಅಥವಾ ಬ್ಲಾಬ್‌ಗಳನ್ನು ತಪ್ಪಿಸುವ ಮೂಲಕ ಅದೃಷ್ಟಶಾಲಿಯಾಗಿ ಡೌನ್‌ಲೋಡ್ ಹೆಚ್ಚಿನ ಭಾಗವನ್ನು ತಪ್ಪಿಸುವುದು ಮಾಡಬಹುದು.

#### ತ್ವರಿತ ಶ್ಯಾಲೋ ಕ್ಲೋನ್ — ಕನಿಷ್ಠ ಇತಿಹಾಸ, ಎಲ್ಲಾ ಫೈಲುಗಳು

ಕೆಳಗಿನ ಕಮಾಂಡ್ಗಳಲ್ಲಿ `<your-username>` ಅನ್ನು ನಿಮ್ಮ ಫಾರ್ಕ್ URL (ಅಥವಾ ನೀವು ಇಚ್ಛಿಸಿದರೆ ಅಪ್‌ಸ್ಟ್ರೀಮ್ URL) ಯಿಂದ ಬದಲಾಯಿಸಿ.

ಇತ್ತೀಚಿನ ಕಮಿಟ್ ಇತಿಹಾಸ ಮಾತ್ರ ಕ್ಲೋನ್ ಮಾಡಲು (ಸಣ್ಣ ಡೌನ್‌ಲೋಡ್):

```bash|powershell
git clone --depth 1 https://github.com/<your-username>/ai-agents-for-beginners.git
```

ವಿಶೇಷ ಶಾಖೆಯನ್ನು ಕ್ಲೋನ್ ಮಾಡಲು:

```bash|powershell
git clone --depth 1 --branch <branch-name> https://github.com/<your-username>/ai-agents-for-beginners.git
```

#### ಭಾಗಶಃ (ಸ್ಪಾರ್ಸ್) ಕ್ಲೋನ್ — ಕನಿಷ್ಠ ಬ್ಲಾಬ್‌ಗಳು + ಆಯ್ದ ಫೋಲ್ಡರ್‌ಗಳು ಮಾತ್ರ

ಇದು ಭಾಗಶಃ ಕ್ಲೋನ್ ಮತ್ತು ಸ್ಪಾರ್ಸ್-ಚೆಕೌಟ್ ಬಳಸುತ್ತದೆ (Git 2.25+ ಅಗತ್ಯವಿದ್ದು, ಭಾಗಶಃ ಕ್ಲೋನ್ ಬೆಂಬಲದೊಂದಿಗೆ ಶಿಫಾರಸು ಮಾಡಿದ ಆಧುನಿಕ Git).

```bash|powershell
git clone --depth 1 --filter=blob:none --sparse https://github.com/<your-username>/ai-agents-for-beginners.git
```

ರೆಪೊ ಫೋಲ್ಡರ್‌ಗೆ ಪ್ರವೇಶಿಸಿ:

```bash|powershell
cd ai-agents-for-beginners
```

ನಂತರ ನೀವು ಬೇಕಾದ ಫೋಲ್ಡರ್‌ಗಳನ್ನು ವಿವರಿಸಿ (ಕೆಳಗಿನ ಉದಾಹರಣೆಯಲ್ಲಿ ಎರಡು ಫೋಲ್ಡರ್‌ಗಳು ತೋರಿಸಲಾಗಿದೆ):

```bash|powershell
git sparse-checkout set 00-course-setup 01-intro-to-ai-agents
```

ಕ್ಲೋನ್ ಮಾಡಿ ಮತ್ತು ಫೈಲ್‌ಗಳನ್ನು ಪರಿಶೀಲಿಸಿದ ನಂತರ, ನೀವು ಕೇವಲ ಫೈಲ್‌ಗಳನ್ನು ಬೇಕಾದರೆ ಮತ್ತು ಜಾಗವನ್ನು ವಿನಾಯಿಸಬೇಕು (ಗಿಟ್ ಇತಿಹಾಸವಿಲ್ಲದೆ), ದಯವಿಟ್ಟು ರೆಪೊ ಮೆಟಾಡೇಟಾ ಅಳಿಸಿ (💀ಅನಿರ್ವಹಣೀಯ — ನೀವು ಎಲ್ಲಾ ಗಿಟ್ ಕಾರ್ಯಚಟುವಟಿಕೆಗಳನ್ನು ಕಳೆದುಹೋಗುತ್ತೀರಿ: ಯಾವುದೇ ಕಮಿಟ್, ಪುಲ್, ಪುಶ್‌ಗಳು ಅಥವಾ ಇತಿಹಾಸ ಪ್ರವೇಶವಿಲ್ಲ).

```bash
# zsh/bash
rm -rf .git
```

#### GitHub Codespaces ಬಳಸು (ಸ್ಥಳೀಯ ದೊಡ್ಡ ಡೌನ್‌ಲೋಡ್ಗಳನ್ನು ತಪ್ಪಿಸಲು ಶಿಫಾರಸು)

- ಈ ರೆಪೊಗಾಗಿ ಹೊಸ Codespace ರಚಿಸಿ [GitHub UI](https://github.com/codespaces) ಮೂಲಕ.  

- ಹೊಸ ರಚಿಸಲಾದ Codespace ನ ಟರ್ಮಿನಲ್‌ನಲ್ಲಿ, ನೀವು ಬೇಕಾದ ಪಾಠ ಫೋಲ್ಡರ್‌ಗಳನ್ನು ಮಾತ್ರ Codespace ಕೆಲಸದ ಸ್ಥಳಕ್ಕೆ ತರಲು ಮೇಲಿನ ಶ್ಯಾಲೋ/ಸ್ಪಾರ್ಸ್ ಕ್ಲೋನ್ ಕಮಾಂಡ್ಗಳಲ್ಲಿ ಒಂದನ್ನು ರನ್ ಮಾಡಿ.
- ಆಯ್ಕೆ: Codespaces ಒಳಗೆ ಕ್ಲೋನ್ ಮಾಡಿದ ನಂತರ, ಹೆಚ್ಚುವರಿ ಜಾಗವನ್ನು ಮುಕ್ತಗೊಳಿಸಲು .git ಅನ್ನು ತೆಗೆದುಹಾಕಿ (ಮೇಲಿನ ಅಳಿಸುವ ಕಮಾಂಡ್ಗಳನ್ನು ನೋಡಿ).
- ಗಮನಿಸಿ: ನೀವು ರೆಪೊವನ್ನು Codespaces ನಲ್ಲಿ ನೇರವಾಗಿ ತೆರೆಯಲು (ಹೆಚಚುವ ಕ್ಲೋನ್ ಇಲ್ಲದೆ) ಇಚ್ಛಿಸಿದರೆ, Codespaces ಡೆವ್ಕಂಟೇನರ್ ವಾತಾವರಣ ಅನ್ನು ರಚಿಸುತ್ತದೆ ಮತ್ತು ನೀವು ಬೇಕಾದಷ್ಟು ಹೆಚ್ಚಿನ ಸಂಪನ್ಮೂಲಗಳನ್ನು ಇನ್ನೂ ಒದಗಿಸಬಹುದು. ಹೊಸ Codespace ಒಳಗೆ ಶ್ಯಾಲೋ ಪ್ರತಿಯನ್ನು ಕ್ಲೋನ್ ಮಾಡುವುದು ಡಿಸ್ಕ್ ಬಳಕೆಯ ಮೇಲೆ ಹೆಚ್ಚು ನಿಯಂತ್ರಣ ನೀಡುತ್ತದೆ.

#### ಸಲಹೆಗಳು

- ನೀವು ಸಂಪಾದನೆ/ಕಮಿಟ್ ಮಾಡಲು ಇಚ್ಛಿಸಿದರೆ ಯಾವಾಗಲೂ ನಿಮ್ಮ ಫಾರ್ಕ್ ಸೇರಿದಂತೆ ಕ್ಲೋನ್ URL ಅನ್ನು ಬದಲಾಯಿಸಿ.
- ನೀವು ನಂತರ ಹೆಚ್ಚಿನ ಇತಿಹಾಸ ಅಥವಾ ಫೈಲ್‌ಗಳನ್ನು ಬೇಕಾದರೆ, ಅವುಗಳನ್ನು ಫೆಚ್ ಮಾಡಬಹುದು ಅಥವಾ ಸ್ಪಾರ್ಸ್-ಚೆಕೌಟ್ ಅನ್ನು ಹೆಚ್ಚುವರಿ ಫೋಲ್ಡರ್‌ಗಳನ್ನು ಸೇರಿಸಲು ಹೊಂದಿಸಬಹುದು.

## ಕೋಡ್ ರನ್ ಮಾಡುವುದು

ಈ ಕೋರ್ಸ್ ನಲ್ಲಿ ನೀವು AI ಏಜೆಂಟ್ಸ್ ನಿರ್ಮಿಸುವ ಅನುಭವ ಪಡೆಯಲು ಚಾಲನೆ ಮಾಡಬಹುದಾದ ಜ್ಯೂಪಿಟರ್ ನೋಟ್ಬುಕ್ಸ್ಗಳ ಸರಣಿ ಇದೆ.

ಈ ಕೋಡ್ ನಮೂನೆಗಳು **Microsoft Agent Framework (MAF)** ನೊಂದಿಗೆ `FoundryChatClient` ಅನ್ನು ಬಳಸಿ, ಇದು **Microsoft Foundry Agent Service V2** (Responses API) ಮೂಲಕ **Microsoft Foundry** ಗೆ ಸಂಪರ್ಕಿಸಲ್ಪಡುತ್ತದೆ.

ಎಲ್ಲಾ ಪೈಥಾನ್ ನೋಟ್ಬುಕ್ಸ್ಗಳು `*-python-agent-framework.ipynb` ಎಂದು ಲೇಬಲ್ ಮಾಡಲ್ಪಟ್ಟಿವೆ.

    >ಉದಾಹರಣೆ

- **Azure CLI** — ಪ್ರಾಮಾಣೀಕರಣಕ್ಕೆ ಅಗತ್ಯ. [aka.ms/installazurecli](https://aka.ms/installazurecli) ನಿಂದ ಸ್ಥಾಪಿಸಿ.
- **Azure Subscription** — Microsoft Foundry ಮತ್ತು Microsoft Foundry Agent Service ಗೆ ಪ್ರವೇಶಕ್ಕಾಗಿ.
- **Microsoft Foundry Project** — ವಿನ್ಯಾಸಗೊಳಿಸಿದ ಮಾದರಿಯೊಂದಿಗೆ ಪ್ರಾಜೆಕ್ಟ್ (ಉದಾಹರಣೆ: `gpt-4o`). ಕೆಳಗಿನ [Step 1](#ಹಂತ-1-microsoft-foundry-ಪ್ರಾಜೆಕ್ಟ್-ರಚಿಸಿ) ನೋಡಿ.

## Microsoft Foundry ಮತ್ತು Microsoft Foundry Agent Service ಅನ್ನು ಸೆಟ್ ಅಪ್ ಮಾಡಿ

### ಹಂತ 1: Microsoft Foundry ಪ್ರಾಜೆಕ್ಟ್ ರಚಿಸಿ

ನೋಟ್ಬುಕ್‌ಗಳನ್ನು ಚಾಲನೆ ಮಾಡಲು ನಿಮ್ಮ ಬಳಿ ವಿನ್ಯಾಸಗೊಳಿಸಿದ ಮಾದರಿಯನ್ನು ಹೊಂದಿರುವ Microsoft Foundry **ಹಬ್** ಮತ್ತು **ಪ್ರಾಜೆಕ್ಟ್** ಅಗತ್ಯ.

1. [ai.azure.com](https://ai.azure.com) ಗೆ ಹೋಗಿ ಮತ್ತು ನಿಮ್ಮ Azure ಖಾತೆಯಿಂದ ಸೈನ್ ಇನ್ ಮಾಡಿ.
2. **ಹಬ್** ರಚಿಸಿ (ಅಥವಾ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವುದನ್ನು ಬಳಸಿ). ನೋಡಿ: [ಹಬ್ ಸಂಪನ್ಮೂಲ ಅವಲೋಕನ](https://learn.microsoft.com/azure/ai-foundry/concepts/ai-resources).
3. ಹಬ್ ಒಳಗೆ **ಪ್ರಾಜೆಕ್ಟ್** ರಚಿಸಿ.
4. **Model + Endpoints** → **Deploy model** ದಿಂದ ಮಾದರಿಯನ್ನು (ಉದಾ: `gpt-4o`) ನಿಯೋಜಿಸಿ.

### ಹಂತ 2: ನಿಮ್ಮ ಪ್ರಾಜೆಕ್ಟ್ ಎಂಡ್ಪಾಯಿಂಟ್ ಮತ್ತು ಮಾದರಿ ನಿಯೋಜನೆ ಹೆಸರು ಪಡೆದುಕೊಳ್ಳಿ

Microsoft Foundry ಪೋರ್ಟಲ್‌ನಲ್ಲಿರುವ ನಿಮ್ಮ ಪ್ರಾಜೆಕ್ಟ್ ನಿಂದ:

- **Project Endpoint** — **Overview** ಪುಟಕ್ಕೆ ಹೋಗಿ ಮತ್ತು ಎಂಡ್ಪಾಯಿಂಟ್ URL ನ್ನು ನಕಲಿಸಿ.

![Project Connection String](../../../translated_images/kn/project-endpoint.8cf04c9975bbfbf1.webp)

- **Model Deployment Name** — **Models + Endpoints** ಗೆ ಹೋಗಿ, ನಿಯೋಜಿಸಿರುವ ಮಾದರಿಯನ್ನು ಆಯ್ಕೆಮಾಡಿ, ಮತ್ತು **Deployment name** ಗಮನಿಸಿ (ಉದಾ: `gpt-4o`).

### ಹಂತ 3: `az login` ಮೂಲಕ Azure ಗೆ ಸೈನ್ ಇನ್ ಆಗಿ

ಎಲ್ಲಾ ನೋಟ್ಬುಕ್‌ಗಳು ಪ್ರಮಾಣೀಕರಣಕ್ಕಾಗಿ **`AzureCliCredential`** ಅನ್ನು ಬಳಸುತ್ತಾರೆ — ಯಾವುದೇ API ಕೀಲಿಗಳನ್ನು ನಿರ್ವಹಿಸುವ ಅವಶ್ಯಕತೆ ಇಲ್ಲ. ಇದಕ್ಕಾಗಿ ನೀವು Azure CLI ಮೂಲಕ ಸೈನ್ ಇನ್ ಆಗಿರಬೇಕು.

1. **Azure CLI ಅನ್ನು ಸ್ಥಾಪಿಸಿ**: [aka.ms/installazurecli](https://aka.ms/installazurecli)

2. **ಸೈನ್ ಇನ್ ಆಗಿ** ಕೆಳಕಂಡಂತೆ ರನ್ ಮಾಡಿ:

    ```bash|powershell
    az login
    ```

    ಅಥವಾ ನೀವು ಬ್ರೌಸರ್ ಇಲ್ಲದ ರಿಮೋಟ್/ಕೋಡ್ಸ್ಪೇಸ್ ವಾತಾವರಣದಲ್ಲಿದ್ದರೆ:

    ```bash|powershell
    az login --use-device-code
    ```

3. ಪ್ರಶ್ನಿಸಿದರೆ ನಿಮ್ಮ ಸಬ್ಸ್ಕ್ರಿಪ್ಷನ್ ಆಯ್ಕೆಮಾಡಿ — ನಿಮ್ಮ Foundry ಪ್ರಾಜೆಕ್ಟ್ ಅನ್ನು ಹೊಂದಿರುವದು ಆಯ್ಕೆಮಾಡಿ.

4. ನೀವು ಸೈನ್ ಇನ್ ಆಗಿರುವುದನ್ನು ದೃಢಮಾಡಿ:

    ```bash|powershell
    az account show
    ```

> **`az login` ಯಾಕೆ?** ನೋಟ್ಬುಕ್‌ಗಳು `azure-identity` ಪ್ಯಾಕೇಜಿನ `AzureCliCredential` ಅನ್ನು ಬಳಸಿ ಪ್ರಮಾಣೀಕರಣ ಮಾಡುವುದರಿಂದ ನಿಮ್ಮ Azure CLI ಸೆಷನ್ ಕ್ರೆಡೆನ್ಷಿಯಲ್ಸ್ ಅನ್ನು ಒದಗಿಸುತ್ತದೆ — ನಿಮ್ಮ `.env` ಫೈಲಿನಲ್ಲಿ ಯಾವುದೇ API ಕೀಲಿಗಳು ಅಥವಾ ರಹಸ್ಯಗಳು ಇರಲಿಲ್ಲ. ಇದು [ಸುರಕ್ಷತಾ ಉತ್ತಮ ಅಭ್ಯಾಸ](https://learn.microsoft.com/azure/developer/ai/keyless-connections).

### ಹಂತ 4: ನಿಮ್ಮ `.env` ಫೈಲನ್ನು ರಚಿಸಿ

ಉದಾಹರಣಾ ಫೈಲನ್ನು ನಕಲಿಸಿ:

```bash
# zsh/bash
cp .env.example .env
```

```powershell
# ಪವರ್‌ಶೆಲ್
Copy-Item .env.example .env
```

`.env`Open ಮಾಡಿ ಮತ್ತು ಈ ಎರಡು ಮೌಲ್ಯಗಳನ್ನು ತುಂಬಿ:

```env
AZURE_AI_PROJECT_ENDPOINT=https://<your-project>.services.ai.azure.com/api/projects/<your-project-id>
AZURE_AI_MODEL_DEPLOYMENT_NAME=gpt-4o
```

| ಚರ | ಅದು ಎಲ್ಲಿದೆ |
|----------|-----------------|
| `AZURE_AI_PROJECT_ENDPOINT` | Foundry ಪೋರ್ಟಲ್ → ನಿಮ್ಮ ಪ್ರಾಜೆಕ್ಟ್ → **Overview** ಪೇಜ್ |
| `AZURE_AI_MODEL_DEPLOYMENT_NAME` | Foundry ಪೋರ್ಟಲ್ → **Models + Endpoints** → ನಿಯೋಜಿಸಿರುವ ಮಾದರಿ ಹೆಸರು |

ಬಹುತೇಕ ಪಾಠಗಳಿಗಾಗಿ ಅದಷ್ಟೇ! ನೋಟ್ಬುಕ್‌ಗಳು ನಿಮ್ಮ `az login` ಸೆಷನ್ ಮೂಲಕ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಪ್ರಮಾಣೀಕರಿಸುತ್ತವೆ.

### ಹಂತ 5: ಪೈಥಾನ್ ಅವಶ್ಯಕತೆಗಳನ್ನು ಸ್ಥಾಪಿಸಿ

```bash|powershell
pip install -r requirements.txt
```

ನೀವು ಮೊದಲಿನ ವರ್ಚುಯಲ್ ಎನ್ವಿರಾನ್‌ಮೆಂಟ್ ಒಳಗೆ ಇದನ್ನು ರನ್ಮಾಡುವುದನ್ನು ನಾವು ಶಿಫಾರಸು ಮಾಡುತ್ತೇವೆ.

## ಪಾಠ 5 (Agentic RAG) ಗಾದಿಗೋ ಸಂಪೂರ್ಣ ಸೆಟ್‌ಅಪ್

ಪಾಠ 5 **Azure AI Search** ಅನ್ನು retrieval-augmented generation ಗಾಗಿ ಬಳಸುತ್ತದೆ. ನೀವು ಆ ಪಾಠವನ್ನು ರನ್ ಮಾಡಲು ಬಯಸಿದರೆ, ಈ ಚರಗಳನ್ನು ನಿಮ್ಮ `.env` ಫೈಲಿಗೆ ಸೇರಿಸಿ:

| ಚರ | ಅದು ಎಲ್ಲಿದೆ |
|----------|-----------------|
| `AZURE_SEARCH_SERVICE_ENDPOINT` | Azure ಪೋರ್ಟಲ್ → ನಿಮ್ಮ **Azure AI Search** ಸಂಪನ್ಮೂಲ → **Overview** → URL |
| `AZURE_SEARCH_API_KEY` | Azure ಪೋರ್ಟಲ್ → ನಿಮ್ಮ **Azure AI Search** ಸಂಪನ್ಮೂಲ → **Settings** → **Keys** → ಪ್ರಾಥಮಿಕ ಆಡಳಿತ ಕೀಲಿ |

## ಪಾಠಗಳು 6 ಮತ್ತು 8 ಗಾಗಿ ನೇರವಾಗಿ Azure OpenAI ಕರೆಯುವ ಹೆಚ್ಚುವರಿ ಸೆಟ್‌ಅಪ್

ಪಾಠ 6 ಮತ್ತು 8 ರಲ್ಲಿ ಕೆಲ ನೋಟ್ಬುಕ್‌ಗಳು ನೇರವಾಗಿ **Azure OpenAI** (Responses API ಬಳಸಿ) ಕರೆಯುತ್ತವೆ, Microsoft Foundry ಪ್ರಾಜೆಕ್ಟ್ ಮೂಲಕ ಹೋಗುವುದಿಲ್ಲ. ಈ ನುಡಿಗಳು ಹಿಂದಿನ GitHub Models ಅನ್ನು ಬಳಸುತ್ತವೆ, ಇದು ಪ್ರಚಾರ ನಿಲ್ಲಿಸಲಾಗುತ್ತಿದೆ (ಜುಲೈ 2026 ರಲ್ಲಿ ನಿವೃನ್ನು ಮಾಡುವುದು) ಮತ್ತು Responses APIಗೆ ಬೆಂಬಲ ನೀಡುವುದಿಲ್ಲ. ನೀವು ಆ ನುಡಿಗಳನ್ನು ರನ್ ಮಾಡಲು ಬಯಸಿದರೆ, ಈ ಚರಗಳನ್ನು ನಿಮ್ಮ `.env` ಫೈಲಿಗೆ ಸೇರಿಸಿ:

| ಚರ | ಅದು ಎಲ್ಲಿದೆ |
|----------|-----------------|
| `AZURE_OPENAI_ENDPOINT` | Azure ಪೋರ್ಟಲ್ → ನಿಮ್ಮ **Azure OpenAI** ಸಂಪನ್ಮೂಲ → **Keys and Endpoint** → ಎಂಡ್ಪಾಯಿಂಟ್ (ಉದಾ: `https://<your-resource>.openai.azure.com`) |
| `AZURE_OPENAI_DEPLOYMENT` | ನಿಮಗೆ ನಿಯೋಜಿಸಲಾಗಿರುವ ಮಾದರಿಯ ಹೆಸರು (ಉದಾ: `gpt-4o-mini`) ರೆಸ್ಪಾನ್‌ಸ್ API ಅನ್ನು ಬೆಂಬಲಿಸುವದು |
| `AZURE_OPENAI_API_KEY` | ಐಚ್ಛಿಕ — ನೀವು `az login` / Entra ID ಬದಲಿಗೆ ಕೀಲಿಮಣೆ ಆಧಾರಿತ ಪ್ರಾಮಾಣೀಕರಣ ಬಳಸದಿದ್ದರೆ ಮಾತ್ರ |

> Responses API ಸ್ತಿರ ` /openai/v1/` ಎಂಡ್ಪಾಯಿಂಟ್ ಅನ್ನು ಬಳಸುತ್ತದೆ, ಆದ್ದರಿಂದ `api-version` ಅಗತ್ಯವಿಲ್ಲ. ಕೀಲಿಸಹ ಮುಕ್ತ Entra ID ಪ್ರಮಾಣೀಕರಣಕ್ಕೆ `az login` ಮೂಲಕ ಸೈನ್ ಇನ್ ಆಗಿ.

## ಪರ್ಯಾಯ ಸರಬರಾಜುದಾರ: MiniMax (OpenAI-ಸಾಮರಸ್ಯ)

[MiniMax](https://platform.minimaxi.com/) OpenAI-ಸಾಮರಸ್ಯ API ಮೂಲಕ ದೊಡ್ಡ ಸಾಂದರ್ಭಿಕ ಮಾದರಿಗಳನ್ನು (204K ಟೋಕನ್ಗಳವರೆಗೆ) ನೀಡುತ್ತದೆ. Microsoft Agent Framework ನ `OpenAIChatClient` ಯಾವುದೇ OpenAI-ಸಾಮರಸ್ಯ ಎಂಡ್ಪಾಯಿಂಟ್ೊಂದಿಗೆ ಕಾರ್ಯನಿರ್ವಹಿಸುವ ಕಾರಣ, ನೀವು MiniMax ಅನ್ನು Azure OpenAI ಅಥವಾ OpenAIಗೆ ಬದಲಾಗಿ ಬಳಸಬಹುದು.

ಈ ಚರಗಳನ್ನು ನಿಮ್ಮ `.env` ಫೈಲಿಗೆ ಸೇರಿಸಿ:

| ಚರ | ಅದು ಎಲ್ಲಿದೆ |
|----------|-----------------|
| `MINIMAX_API_KEY` | [MiniMax ಪ್ಲಾಟ್‌ಫಾರ್ಮ್](https://platform.minimaxi.com/) → API ಕೀಲಿಗಳು |
| `MINIMAX_BASE_URL` | `https://api.minimax.io/v1` (ಡೀಫಾಲ್ಟ್ ಮೌಲ್ಯ) ಬಳಸಿ |
| `MINIMAX_MODEL_ID` | ಬಳಸಬೇಕಾದ ಮಾದರಿ ಹೆಸರು (ಉದಾ: `MiniMax-M3`) |

**ಉದಾಹರಣೆ ಮಾದರಿಗಳು**: `MiniMax-M3` (ಶಿಫಾರಸು ಮಾಡಿದ), `MiniMax-M2.7`, `MiniMax-M2.7-highspeed` (ತ್ವರಿತ ಪ್ರತಿಕ್ರಿಯೆ). ಮಾದರಿ ಹೆಸರುಗಳು ಮತ್ತು ಲಭ್ಯತೆ ಸಮಯಪಾಲನೆಯೊಂದಿಗೆ ಬದಲಾಗಬಹುದು, ಮತ್ತು ನಿರ್ದಿಷ್ಟ ಖಾತೆ ಅಥವಾ ಪ್ರದೇಶ ಆಧಾರವಾಗಿ ಲಭ್ಯತೆ ಬದಲಾಗಬಹುದು — ಪ್ರಸ್ತುತ ಪಟ್ಟಿಗಾಗಿ [MiniMax ಪ್ಲಾಟ್‌ಫಾರ್ಮ್](https://platform.minimaxi.com/) ನೋಡಿ. ನಿಮ್ಮ ಖಾತೆಗೆ `MiniMax-M3` ಲಭ್ಯವಿಲ್ಲದಿದ್ದರೆ, ನೀವು ಪ್ರವೇಶ ಹೊಂದಿರುವ ಯಾವುದೇ ಮಾದರಿಯನ್ನು `MINIMAX_MODEL_ID` ಗೆ ಹೊಂದಿಸಿ (ಉದಾ: `MiniMax-M2.7`).

`OpenAIChatClient` ಬಳಸುವ ಕೋಡ್ ನುಡಿಗಳು (ಉದಾ: ಪಾಠ 14 ಹೋಟೆಲ್ ಬುಕ್ಕಿಂಗ್ ವರ್ಕ್ಫ್ಲೋ) ನಿಮ್ಮ MiniMax ಸಂರಚನೆಯನ್ನು `MINIMAX_API_KEY` ಹೊಂದಿರುವಾಗ ಸ್ವಯಂವಾಗಿ ಪತ್ತೆಮಾಡಿ ಮತ್ತು ಬಳಸುತ್ತವೆ.

## ಪರ್ಯಾಯ ಸರಬರಾಜುದಾರ: Foundry Local (ಮಾಡೆಲ್ಗಳನ್ನು ಸಾಧನದಲ್ಲಿ ರನ್ ಮಾಡಿ)

[Foundry Local](https://foundrylocal.ai) ಒಂದು ಲೈಟ್‌ವೆಟ್ ರನ್‌ಟೈಮ್ ಆಗಿದ್ದು, OpenAI-ಸಾಮರಸ್ಯ API ಮೂಲಕ ಭಾಷಾ ಮಾದರಿಗಳನ್ನು ನಿಮ್ಮದೇ ಯಂತ್ರದ ಮೇಲೆ ಸಂಪೂರ್ಣವಾಗಿ ಡೌನ್‌ಲೋಡ್, ನಿರ್ವಹಣೆ ಮತ್ತು ನೀಡುತ್ತದೆ — ಯಾವುದೇ ಕ್ಲೌಡ್, Azure ಸಬ್ಸ್ಕ್ರಿಪ್ಷನ್ ಅಥವಾ API ಕೀಲಿಗಳು ಇಲ್ಲ. ಇದು ಆಫ್‌ಲೈನ್ ಅಭಿವೃದ್ಧಿಗೆ, ಕ್ಲೌಡ್ ವೆಚ್ಚವಿಲ್ಲದೆ ಪ್ರಯೋಗಿಸಲು ಅಥವಾ ಡೇಟಾವನ್ನು ಸಾಧನದಲ್ಲಿ ಇರಿಸಲು ಉತ್ತಮ ಆಯ್ಕೆ.

Microsoft Agent Framework ನ `OpenAIChatClient` ಯಾವುದೇ OpenAI-ಸಾಮರಸ್ಯ ಎಂಡ್ಪಾಯಿಂಟ್ ಅನ್ನು ಕಾರ್ಯನಿರ್ವಹಿಸುವ ಕಾರಣ, Foundry Local Azure OpenAI ಗೆ ಸ್ಥಳೀಯ ಪರ್ಯಾಯವಾಗಿದೆ.

**1. Foundry Local ಸ್ಥಾಪಿಸಿ**

```bash
# ವಿಂಡೋಸ್
winget install Microsoft.FoundryLocal

# ಮೆಕ್ ಓಎಸ್
brew install foundrylocal
```

**2. ಮಾದರಿ ಡೌನ್‌ಲೋಡ್ ಮಾಡಿ ಮತ್ತು ರನ್ ಮಾಡಿ** (ಇದು ಸ್ಥಳೀಯ ಸೇವೆಯನ್ನು ಪ್ರಾರಂಭಿಸುತ್ತದೆ):

```bash
foundry model list          # ಲಭ್ಯವಿರುವ ಮಾದರಿಗಳನ್ನು ನೋಡಿ
foundry model run phi-4-mini
```

**3. ಸ್ಥಳೀಯ ಎಂಡ್ಪಾಯಿಂಟ್ ಪತ್ತೆ ಮಾಡಲು ಬಳಸುವ ಪೈಥಾನ್ SDK ಅನ್ನು ಸ್ಥಾಪಿಸಿ:**

```bash
pip install foundry-local-sdk
```

**4. Microsoft Agent Framework ನ್ನು ನಿಮ್ಮ ಸ್ಥಳೀಯ ಮಾದರಿಯನ್ನು ಸೂಚಿಸಿ:**

```python
from foundry_local import FoundryLocalManager
from agent_framework.openai import OpenAIChatClient

# ಮಾದರಿಯನ್ನು ಡೌನ್‌ಲೋಡ್ (ಅವಶ್ಯಕವಿದ್ದರೆ) ಮತ್ತು ಸ್ಥಳೀಯವಾಗಿ ಸೇವೆ ಮಾಡಿದ್ದಾರೆ, ನಂತರ ಅಂತಿಮಬಿಂದುವನ್ನು/ಪೋರ್ಟ್ ಅನ್ನು ಕಂಡುಹಿಡಿಯುತ್ತದೆ.
manager = FoundryLocalManager("phi-4-mini")

chat_client = OpenAIChatClient(
    base_url=manager.endpoint,      # ಉದಾ: http://localhost:<port>/v1
    api_key=manager.api_key,        # Foundry Local ಗೆ ಸದಾ "ಅಗತ್ಯವಿಲ್ಲ"
    model_id=manager.get_model_info("phi-4-mini").id,
)

agent = chat_client.as_agent(
    name="LocalAgent",
    instructions="You are a helpful assistant running fully on-device.",
)
```

> **ಗಮನಿಸಿ:** Foundry Local OpenAI-ಸಾಮರಸ್ಯ **ಚಾಟ್ ಪೂರ್ಣತೆ** ಎಂಡ್ಪಾಯಿಂಟ್ ಅನ್ನು ಹೊರಹಾಕುತ್ತದೆ. ಸ್ಥಳೀಯ ಅಭಿವೃದ್ಧಿಗೆ ಮತ್ತು ಆಫ್‌ಲೈನ್ ಸನ್ನಿವೇಶಗಳಿಗೆ ಇದನ್ನು ಬಳಸಿ. ಪೂರ್ಣ **Responses API** ವೈಶಿಷ್ಟ್ಯತೆಗಳಿಗಾಗಿ (ರಾಜ್ಯಪಾಲಿತ ಸಂವಾದಗಳು, ಡೀಪ್ ಟೂಲ್ ಸಂಯೋಜನೆ ಮತ್ತು ಏಜೆಂಟ್ ಶೈಲಿಯ ಅಭಿವೃದ್ಧಿ), ಪಾಠಗಳಲ್ಲಿ ತೋರಿಸಿದಂತೆ **Azure OpenAI** ಅಥವಾ **Microsoft Foundry** ಪ್ರಾಜೆಕ್ಟ್ ಅನ್ನು ಗುರಿಯಾಗಿಸಿ. ಇತ್ತೀಚಿನ ಮಾದರಿ ಕ್ಯಾಟಲॉग್ ಮತ್ತು ಪ್ಲಾಟ್‌ಫಾರ್ಮ್ ಬೆಂಬಲಕ್ಕಾಗಿ [Foundry Local ಡಾಕ್ಯುಮೆಂಟೇಶನ್](https://foundrylocal.ai) ನೋಡಿ.

## ಪಾಠ 8 ಗಾಗಿ ಹೆಚ್ಚುವರಿ ಸೆಟ್‌ಅಪ್ (Bing Grounding ವರ್ಕ್ಫ್ಲೋ)


ಪಾಠ 8ರ ಶರತಾತ್ಮಕ ವರ್ಕ್ಫ್ಲೋ ನೋಟ್‌ಬುಕ್ ಮೈಸ್ರೋಸಾಫ್ಟ್ ಫೌಂಡ್ರಿ ಮೂಲಕ **ಬಿಂಗ್ ಗ್ರೌಂಡಿಂಗ್** ಅನ್ನು ಬಳಸುತ್ತದೆ. ನೀವು ಆ ಉದಾಹರಣೆಯನ್ನು ಓಡಿಸುವ ಯೋಜನೆ ಹೊಂದಿದ್ದರೆ, ನಿಮ್ಮ `.env` ಫೈಲ್‌ಗೆ ಈ ವ್ಯತ್ಯಯವನ್ನು ಸೇರಿಸಿ:

| ವ್ಯತ್ಯಯ | ಇದನ್ನು ಎಲ್ಲಿಗೆ ಹುಡುಕಬೇಕು |
|----------|-----------------|
| `BING_CONNECTION_ID` | ಮೈಸ್ರೋಸಾಫ್ಟ್ ಫೌಂಡ್ರಿ ಪೋರ್ಟಲ್ → ನಿಮ್ಮ ಪ್ರಾಜೆಕ್ಟ್ → **ಮ್ಯಾನೇಜ್ಮೆಂಟ್** → **ಕನೆಕ್ಟೆಡ್ ರಿಸೋರ್ಸಸ್** → ನಿಮ್ಮ ಬಿಂಗ್ ಕನೆಕ್ಷನ್ → ಕನೆಕ್ಷನ್ ID ನಕಲುಮಾಡಿ |

## ಸಮಸ್ಯೆ ಪರಿಹಾರ

### macOS ನಲ್ಲಿ SSL ಪ್ರಮಾಣಪತ್ರ ಪರಿಶೀಲನೆ ದೋಷಗಳು

ನೀವು macOS ನಲ್ಲಿ ಇದ್ದರೆ ಮತ್ತು ಇಂತಹ ದೋಷ ಎದುರಾದರೆ:

```plaintext
ssl.SSLCertVerificationError: [SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed: self-signed certificate in certificate chain
```

ಇದು macOS ನಲ್ಲಿ ಪೈಥಾನ್‌ನ ಒಂದು ತಿಳಿದಿರುವ ಸಮಸ್ಯೆ, ಅಲ್ಲಿ ಸಿಸ್ಟಮ್ SSL ಪ್ರಮಾಣಪತ್ರಗಳನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ನಂಬಲಾಗುವುದಿಲ್ಲ. ಕೆಳಗಿನ ಪರಿಹಾರಗಳನ್ನು ಕ್ರಮವಾಗಿ ಪ್ರಯತ್ನಿಸಿ:

**ಐಚ್ಛಿಕ 1: ಪೈಥಾನ್‌ನ ಇನ್‌ಸ್ಟಾಲ್ ಸೆರ್ಟಿಫಿಕೇಟ್ಸ್ ಸ್ಕ್ರಿಪ್ಟ್ ಓಡಿಸಿ (ಶಿಫಾರಸು ಮಾಡಲಾಗಿದೆ)**

```bash
# ನಿಮ್ಮ ಸ್ಥಾಪಿಸಿದ ಪೈಥನ್ ಆವೃತ್ತಿಯನ್ನು (ಉದಾ., 3.12 ಅಥವಾ 3.13) 3.XX ಇತ್ಯಾದಿ ಬದಲಾಯಿಸಿ:
/Applications/Python\ 3.XX/Install\ Certificates.command
```

**ಐಚ್ಛಿಕ 2: ನಿಮ್ಮ ನೋಟ್‌ಬುಕ್‌ನಲ್ಲಿ `connection_verify=False` ಬಳಸಿ (GitHub Models ನೋಟ್‌ಬುಕ್‌ಗಳಿಗಾಗಿ ಮಾತ್ರ)**

ಪಾಠ 6 ನೋಟ್‌ಬುಕ್‌ನಲ್ಲಿ (`06-building-trustworthy-agents/code_samples/06-system-message-framework.ipynb`), ಒಂದು ಕಾಮೆಂಟ್-а웃್ ಪರಿಹಾರ ಈಗಾಗಲೇ ಸೇರಿಸಲಾಗಿದೆ. ಕ್ಲೈಂಟ್ ಸೃಷ್ಟಿಸುವಾಗ `connection_verify=False` ಅನ್ನು ಅನ್-ಕಾಮೆಂಟ್ ಮಾಡಿ:

```python
client = ChatCompletionsClient(
    endpoint=endpoint,
    credential=AzureKeyCredential(token),
    connection_verify=False,  # ಪ್ರಮಾಣಪತ್ರ ದೋಷಗಳಾಗಿದ್ದಲ್ಲಿ SSL ಪರಿಶೀಲನೆಯನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಿ
)
```

> **⚠️ ಎಚ್ಚರಿಕೆ:** SSL ಪರಿಶೀಲನೆಯನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವಿಕೆ (`connection_verify=False`) ಪ್ರಮಾಣಪತ್ರ ಪರಿಶೀಲನೆಯನ್ನು ಬಿಟ್ಟುಹೋಗುವುದರಿಂದ ಭದ್ರತೆಯನ್ನು ಕಡಿಮೆ ಮಾಡುತ್ತದೆ. ಇದನ್ನು ಅಭಿವೃದ್ಧಿ ಪರಿಸರಗಳಲ್ಲಿ ತಾತ್ಕಾಲಿಕ ಪರಿಹಾರವಾಗಿ ಮಾತ್ರ ಬಳಸಿ, ಯಾವುದೇ ರೀತಿಯ ಉತ್ಪಾದನೆಯಲ್ಲಿ ಬಳಸಬೇಡಿ.

**ಐಚ್ಛಿಕ 3: `truststore` ಅನ್ನು ಇನ್‌ಸ್ಟಾಲ್ ಮಾಡಿ ಮತ್ತು ಬಳಸಿ**

```bash
pip install truststore
```

ನಂತರ ಯಾವುದೇ ನೆಟ್ವರ್ಕ್ ಕರೆಗೆ ಮುಂಚೆ ನಿಮ್ಮ ನೋಟ್‌ಬುಕ್ ಅಥವಾ ಸ್ಕ್ರಿಪ್ಟ್ ಮೇಲ್ಭಾಗದಲ್ಲಿ ಕೆಳಗಿನಂತೆ ಸೇರಿಸಿ:

```python
import truststore
truststore.inject_into_ssl()
```
