# ಉತ್ಪಾದನೆಯಲ್ಲಿ ಎಐ ಏಜೆಂಟ್ಗಳು: مشاهدة ಮತ್ತು ಮೌಲ್ಯಮಾಪನ

[![ಉತ್ಪಾದನೆಯಲ್ಲಿ ಎಐ ಏಜೆಂಟ್ಗಳು](../../../translated_images/kn/lesson-10-thumbnail.2b79a30773db093e.webp)](https://youtu.be/l4TP6IyJxmQ?si=reGOyeqjxFevyDq9)

ಎಐ ಏಜೆಂಟ್ಗಳು ಪ್ರಯೋಗಾತ್ಮಕ ಪ್ರೋಟೋಟೈಪ್ಗಳಿಂದ ನೈಜ ಜಗತ್ತಿನ ಅನ್ವಯಗಳಿಗೆ ಸಾಗುತ್ತಿರುವಂತೆ, ಅವರ ವರ್ತನೆಯನ್ನು ಅರ್ಥಮಾಡಿಕೊಳ್ಳುವ ಸಾಮರ್ಥ್ಯ, ಕಾರ್ಯಕ್ಷಮತೆಯನ್ನು ಮೇಲ್ವಿಚಾರಣೆ ಮಾಡುವುದೂ, ಮತ್ತು ಅವರ ಉತ್ಪನ್ನಗಳನ್ನು ಕ್ರಮಬದ್ಧವಾಗಿ ಮೌಲ್ಯಮಾಪನ ಮಾಡುವುದೂ ಪ್ರಮುಖವಾಗುತ್ತದೆ.

## ಕಲಿಕೆಯ ಗುರಿಗಳು

ಈ ಪಾಠವನ್ನು ಪೂರ್ಣಗೊಳಿಸಿದ ನಂತರ, ನೀವು ತಿಳಿದುಕೊಳ್ಳಲು/ಅರ್ಥಮಾಡಿಕೊಳ್ಳಲು ಸಾಧ್ಯವಾಗುವುದು:
- ಏಜೆಂಟ್ مشاهدة (observability) ಮತ್ತು ಮೌಲ್ಯಮಾಪನದ ಮೂಲ ಧಾರಣೆಗಳು
- ಏಜೆಂಟ್‌ಗಳ ಕಾರ್ಯಕ್ಷಮತೆ, ವೆಚ್ಚಗಳು ಮತ್ತು ಪರಿಣಾಮಕಾರಿತ್ವವನ್ನು ಹೆಚ್ಚಿಸುವ ತಂತ್ರಗಳು
- ನಿಮ್ಮ ಎಐ ಏಜೆಂಟ್‌ಗಳನ್ನು ಕ್ರಮಬದ್ಧವಾಗಿ ಹೇಗೆ ಮೌಲ್ಯಮಾಪನ ಮಾಡಬೇಕು ಮತ್ತು ಏನು ಮಾಡಬೇಕು
- ಉತ್ಪಾದನೆಗೆ ಏಜೆಂಟ್‌ಗಳನ್ನು ನಿಯೋಜಿಸುವಾಗ ವೆಚ್ಚಗಳನ್ನು ಹೇಗೆ ನಿಯಂತ್ರಿಸಬೇಕು
- ಮೈಕ್ರೋಸಾಫ್ಟ್ ಏಜೆಂಟ್ ಫ್ರೇಮ್ವರ್ಕ್ ಬಳಸಿ ನಿರ್ಮಿಸಿರುವ ಏಜೆಂಟ್‌ಗಳನ್ನು ಇನ್‌ಸ್ಟ್ರುಮೆಂಟ್ ಮಾಡುವ ವಿಧಾನ

ಗುರಿ ನಿಮ್ಮ "ಕಪ್ಪು ಬಾಕ್ಸ್" ಏಜೆಂಟ್‌ಗಳನ್ನು ಪಾರದರ್ಶಕ, ನಿರ್ವಹಣೀಯ ಮತ್ತು ವಿಶ್ವಾಸಾರ್ಹ ವ್ಯವಸ್ಥೆಗಳಾಗಿ ಪರಿವರ್ತಿಸುವ ಜ್ಞಾನವನ್ನು ಒದಗಿಸುವುದು.

_**ಸೂಚನೆ:** ಸುರಕ್ಷಿತ ಮತ್ತು ವಿಶ್ವಾಸಾರ್ಹ ಎಐ ಏಜೆಂಟ್‌ಗಳನ್ನು ನಿಯೋಜಿಸುವುದು ಪ್ರಮುಖ. [ವಿಶ್ವಾಸಾರ್ಹ ಎಐ ಏಜೆಂಟ್‌ಗಳನ್ನು ನಿರ್ಮಿಸುವುದು](../06-building-trustworthy-agents/README.md) ಪಾಠವನ್ನು ಕೂಡ ಪರಿಶೀಲಿಸಿ._

## ಟ್ರೇಸ್‌ಗಳು ಮತ್ತು ಸ್ಪಾನ್ಸ್

مشاهدة (observability) ಸಾಧನಗಳು ಹೀಗೆ [Langfuse](https://langfuse.com/) ಅಥವಾ [Microsoft Foundry](https://learn.microsoft.com/en-us/azure/ai-foundry/what-is-azure-ai-foundry) ಸಹಜವಾಗಿ ಏಜೆಂಟ್ ಚಲನೆಗಳನ್ನು ಟ್ರೇಸ್‌ಗಳು ಮತ್ತು ಸ್ಪಾನ್ಸ್‌ಗಳಾಗಿ ಪ್ರತಿನಿಧಿಸುತ್ತವೆ.

- **ಟ್ರೇಸ್** ಒಂದು ಸಂಪೂರ್ಣ ಏಜೆಂಟ್ ಕಾರ್ಯವನ್ನು ಆರಂಭದಿಂದ ಅಂತ್ಯವರೆಗೆ (ಉದಾಹರಣೆಗೆ ಬಳಕೆದಾರ ಪ್ರಶ್ನೆಯನ್ನು ನಿರ್ವಹಿಸುವುದು) ಪ್ರತಿನಿಧಿಸುತ್ತದೆ.
- **ಸ್ಪಾನ್ಸ್** ಟ್ರೇಸ್‌ನ ಒಳಗಿನ ಪ್ರತ್ಯೇಕ ಹಂತಗಳು (ಉದಾಹರಣೆಗೆ ಭಾಷಾ ಮಾದರಿಯನ್ನು ಕರೆ ಮಾಡುವುದು ಅಥವಾ ಡೇಟಾವನ್ನು ಪಡೆಯುವುದು).

![Langfuse ನಲ್ಲಿ ಟ್ರೇಸ್ ಮರ](https://langfuse.com/images/cookbook/example-autogen-evaluation/trace-tree.png)

مشاهدة ಇಲ್ಲದೆ, ಏಐ ಏಜೆಂಟ್ "ಕಪ್ಪು ಬಾಕ್ಸ್" ಹೀಗಾಗಿ ಕಾಣಬಹುದು - ಅದರ ಆಂತರಿಕ ಸ್ಥಿತಿ ಮತ್ತು ಯುಕ್ತಿವಾದವನ್ನು ನೋಡುವುದು ಅಸಾಧ್ಯ, ಸಮಸ್ಯೆಗಳನ್ನು ತಹಶೀಲಿಸಲು ಅಥವಾ ಕಾರ್ಯಕ್ಷಮತೆಯನ್ನು ಸುಧಾರಿಸಲು ಕಷ್ಟವಾಗಿದೆ. مشاهدة ಮೂಲಕ, ಏಜೆಂಟ್‌ಗಳು "ಕ್ಲಾಸ್ ಬಾಕ್ಸ್" ಆಗಿ ಪರಿಗಣಿಸಲ್ಪಡುವ ಮೂಲಕ ಪಾರದರ್ಶಕತೆಯನ್ನು ನೀಡುತ್ತವೆ, ಇದು ವಿಶ್ವಾಸ ನಿರ್ಮಿಸಿಕೊಳ್ಳಲು ಮತ್ತು ನಿಶ್ಚಿತ ಕಾರ್ಯಕ್ರಮಾನುಸಾರ ಕಾರ್ಯನಿರ್ವಹಿಸಲು ಅವಶ್ಯಕ.

## ಉತ್ಪಾದನಾ ಪರಿಸರಗಳಲ್ಲಿ مشاهدة ಮಹತ್ವವೇನು

ಎಐ ಏಜೆಂಟ್‌ಗಳನ್ನು ಉತ್ಪಾದನಾ ಪರಿಸರಗಳಿಗೆ ವರ್ಗಾಯಿಸುವುದು ಹೊಸ ಸವಾಲುಗಳು ಮತ್ತು ಅಗತ್ಯಗಳನ್ನು ಪರಿಚಯಿಸುತ್ತದೆ. مشاهدة ಈಗ "ಒಳ್ಳೆಯದ್ದು" ಅಲ್ಲ, ಆದರೆ ಅವಶ್ಯಕ ಸಾಮರ್ಥ್ಯವಾಗಿದೆ:

*   **ಡಿಬಗಿಂಗ್ ಮತ್ತು ಮೂಲ-ಕಾರಣ ವಿಶ್ಲೇಷಣೆ**: ಏಜೆಂಟ್ ವಿಫಲವಾದಾಗಂತಹಲ್ಲಿ ಅಥವಾ ಅಸಾಧಾರಣ output ನೀಡಿದಾಗ, مشاهدة ಸಾಧನಗಳು ದೋಷದ ಮೂಲವನ್ನು ಗುರುತಿಸಲು ಅಗತ್ಯವಾದ ಟ್ರೇಸ್‌ಗಳನ್ನು ಒದಗಿಸುತ್ತವೆ. ಇದು ಬಹಳ ಜಟಿಲ ಏಜೆಂಟ್‌ಗಳಲ್ಲಿ ಮುಖ್ಯ, ಅಲ್ಲಿ ಹೆಚ್ಚಿನ LLM ಕರೆಗಳು, ಸಾಧನ ಸಂವಾದಗಳು, ಷರತ್ತು ಯುಕ್ತಿಶಾಸ್ತ್ರಗಳು ಸೇರಿರಬಹುದು.
*   **ವಿಳಂಬ ಮತ್ತು ವೆಚ್ಚ ನಿರ್ವಹಣೆ**: ಎಐ ಏಜೆಂಟ್‌ಗಳು ಅಂತರ್ಜಾಲ API ಗಳಿಗೆ ಅಥವಾ LLM ಗಳಿಗೆ ಅವಲಂಬಿತವಾಗಿರುತ್ತವೆ, ಅವುಗಳಿಗೆ ಪ್ರತಿ ಟೋಕನ್ ಅಥವಾ ಪ್ರತಿ ಕರೆಗಾಗಿ ಶುಲ್ಕವಿದ್ದರೆ. مشاهدة ಕರೆದ ಕೊಲ್ಬಲದ ಸಮಯವನ್ನು ನಿಖರವಾಗಿ ಟ್ರ್ಯಾಕ್ ಮಾಡಲು ಸಹಾಯ ಮಾಡುತ್ತದೆ, ಮುಖ್ಯವಾಗಿ ಮಿಗಿಲಾದ ತಡವೇ ಅಥವಾ ದುಬಾರಿ ಆಪರೇಷನ್ಗಳನ್ನು ಗುರುತಿಸಲು. ಇದು ಟೀಮ್ಗಳಿಗೆ ಪ್ರಾಂಪ್ಟ್‌ಗಳನ್ನು ಸುಧಾರಿಸುವುದು, ಹೆಚ್ಚು ಪರಿಣಾಮಕಾರಿ ಮಾದರಿಗಳನ್ನು ಆಯ್ಕೆ ಮಾಡುವುದು ಅಥವಾ ಕಾರ್ಯಪ್ರವಾಹಗಳನ್ನು ಮರುರಚಿಸುವುದರಲ್ಲಿ ಸಹಾಯ ಮಾಡುತ್ತದೆ, ಪರಿಣಾಮವಾಗಿ ಕಾರ್ಯಾಚರಣೆ ವೆಚ್ಚ ಕಡಿಮೆ ಮಾಡಬಹುದು ಮತ್ತು ಬಳಕೆದಾರ ಅನುಭವವನ್ನು ಉತ್ತಮಗೊಳಿಸಬಹುದು.
*   **ವಿಶ್ವಾಸ, ಸುರಕ್ಷತೆ ಮತ್ತು ಅನುಕೂಲತೆ**: ಅನೇಕ ಅನ್ವಯಗಳಲ್ಲಿ ಏಜೆಂಟ್‌ಗಳು ಸುರಕ್ಷಿತ ಮತ್ತು ನೈತಿಕವಾಗಿ ವರ್ತಿಸುವುದನ್ನು ಖಾತ್ರಿಪಡಿಸುವುದು ಮುಖ್ಯ. مشاهدة ಅವರು ಮಾಡಿದ ಕ್ರಿಯೆಗಳ ಮತ್ತು ನಿರ್ಣಯಗಳ ಲೆಕ್ಕಾಚಾರವನ್ನು ನೀಡುತ್ತದೆ. ಇದು ಪ್ರಾಂಪ್ಟ್ ಇಂಜೆಕ್ಷನ್, ಹಾನಿಕಾರಕ ವಿಷಯಗಳ ತಯಾರಿ, ಅಥವಾ ವೈಯಕ್ತಿಕ ಪರಿಚಯಿಸುವ ಮಾಹಿತಿ (PII) ಕ್ಕೆ ಸಂಬಂಧಿಸಿದ ಸಮಸ್ಯೆಗಳನ್ನು ಪತ್ತೆ ಹೊಡೆಯಲು ಮತ್ತು ನಿವಾರಣೆಗೆ ಸಹಾಯ ಮಾಡುತ್ತದೆ. ಉದಾಹರಣೆಗೆ ನೀವು ಒಂದು ಸ್ಪಷ್ಟ ಉತ್ತರವೇ ಅಥವಾ ಒಂದು ನಿರ್ದಿಷ್ಟ ಸಾಧನ ಉಪಯೋಗಿಸಿದ ಕಾರಣವನ್ನು ಟ್ರೇಸ್ ನಲ್ಲಿ ಪರಿಶೀಲಿಸಬಹುದು.
*   **ನಿರಂತರ ಸುಧಾರಣಾ ಲೂಪ್ಸ್**: مشاهدة ಡೇಟಾ ಪುನರಾವರ್ತನಾ ಅಭಿವೃದ್ಧಿ ಪ್ರಕ್ರಿಯೆಯ ಆಧಾರವಾಗಿದೆ. ಏಜೆಂಟ್‌ಗಳು ನೈಜ ಜಗತ್ತಿನಲ್ಲಿ ಹೇಗೆ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತಿದ್ದಾರೆ ಎಂದು ಮೇಲ್ವಿಚಾರಣೆ ಮಾಡುವುದರಿಂದ, ಟೀಮ್ಗಳು ಸುಧಾರಣಾ ಕ್ಷೇತ್ರಗಳನ್ನು ಗುರುತಿಸಬಹುದು, ಮಾದರಿಗಳನ್ನು ಸೂಕ್ಷ್ಮಗೊಳಿಸಲು ಡೇಟಾ ಸಂಗ್ರಹಿಸಬಹುದು ಮತ್ತು ಬದಲಾವಣೆಗಳ ಪರಿಣಾಮವನ್ನು ದೃಢೀಕರಿಸಬಹುದು. ಇದು ಪ್ರತಿಕ್ರಿಯೆಗಳ ಲೂಪನ್ನು ನಿರ್ಮಿಸುತ್ತದೆ, ಅಲ್ಲಿ ಔಟ್‌ಲೈನ್ ಮೌಲ್ಯಮಾಪನದ ಆಳವಾಣಿಯಲ್ಲಿ ಉತ್ಪಾದನಾ ಸೂಚನೆಗಳು ಸಂಗ್ರಹಿಸಿ ಆಫ್‌ಲೈನ್ ಪ್ರಯೋಗ ಮತ್ತು ಪರೀಕ್ಷೆಗಾಗಿ ಮಾಹಿತಿ ಒದಗಿಸುತ್ತವೆ, ಹೀಗಾಗಿ ಏಜೆಂಟ್ ಕಾರ್ಯಕ್ಷಮತೆ ಹಂತ ಹಂತವಾಗಿ ಉತ್ತಮಗೊಳ್ಳುತ್ತದೆ.

## ಟ್ರ್ಯಾಕ್ ಮಾಡುವ ಪ್ರಮುಖ ಮೀಟ್ರಿಕ್ಸ್‌ಗಳು

ಏಜೆಂಟ್ ವರ್ತನೆಯನ್ನು ಮೇಲ್ವಿಚಾರಣೆ ಮತ್ತು ಅರ್ಥಮಾಡಿಕೊಳ್ಳಲು, ವಿವಿಧ ಮೀಟ್ರಿಕ್ಸ್ ಮತ್ತು ಸೂಚನೆಗಳನ್ನು ಟ್ರ್ಯಾಕ್ ಮಾಡಬೇಕು. ಏಜೆಂಟ್ ಗುರಿಯ ಆಧಾರದ ಮೇಲೆ ನಿರ್ದಿಷ್ಟ ಮೀಟ್ರಿಕ್ಸ್ ಬದಲಾಗಬಹುದು, ಆದರೆ ಕೆಲವು ಸರ್ವತ್ರ ಪ್ರಮುಖವಾಗಿವೆ.

مشاهدة ಸಾಧನಗಳು ಟ್ರ್ಯಾಕ್ ಮಾಡುವ ಕೆಲವು ಸಾಮಾನ್ಯ ಮೀಟ್ರಿಕ್ಸ್ ಇಲ್ಲಿವೆ:

**ವಿಳಂಬ (Latency):** ಏಜೆಂಟ್ 얼마나 ತ್ವರಿತವಾಗಿ ಪ್ರತಿಕ್ರಿಯಿಸುತ್ತದೆ? ದೀರ್ಘ ಕಾಯುವಿಕೆಯು ಬಳಕೆದಾರ ಅನುಭವಕ್ಕೆ ಹಾನಿಕಾರಕ. ನೀವು ಕಾರ್ಯಗಳ ಮತ್ತು ಪ್ರತ್ಯೇಕ ಹಂತಗಳಿಗಾಗಿ ಕಾರಣಾಶೀಲ್ಯವನ್ನು ಟ್ರೇಸ್ ಮೂಲಕ ಅಳೆಯಬೇಕು. ಉದಾಹರಣೆಗೆ, ಯಾವುದೇ ಏಜೆಂಟ್ 20 ಸೆಕೆಂಡುಗಳವರೆಗೆ ಎಲ್ಲಾ ಮಾದರಿ ಕರೆಯಲು ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ, ಅದನ್ನು ವೇಗವಾದ ಮಾದರಿಯನ್ನು ಬಳಸುವ ಮೂಲಕ ಅಥವಾ ಮಾದರಿ ಕರೆಗಳನ್ನು ಸಮಾನಾಂತರವಾಗಿ ನಡೆಯುವಂತೆ ಮಾಡಿ ತ್ವರಿತಗೊಳಿಸಬಹುದು.

**ವೆಚ್ಚಗಳು (Costs):** ಪ್ರತೀ ಏಜೆಂಟ್ ಸೆಷನ್ ವೆಚ್ಚವೇನು? ಎಐ ಏಜೆಂಟ್‌ಗಳು ಟೋಕನ್ ಪ್ರತಿ ಅಥವಾ ಹೊರಗಿನ APIಗಳಿಗೆ ಅವಲಂಬಿತವಾಗಿರುತ್ತವೆ. ಹೆಚ್ಚಿನ ಸಾಧನ ಬಳಕೆ ಅಥವಾ ಅನೇಕ ಪ್ರಾಂಪ್ಟ್‌ಗಳು ವೆಚ್ಚವನ್ನು ವೇಗವಾಗಿ ಹೆಚ್ಚಿಸುತ್ತವೆ. ಉದಾಹರಣೆಗೆ, ಮಾರ್ಜಿನಲ್ ಗುಣಮಟ್ಟ ಸುಧಾರಣೆಗೆ ಏಜೆಂಟ್ ಐದು ಬಾರಿ LLM ಅನ್ನು ಕರೆ ಮಾಡಿದರೆ ನೀವು ವೆಚ್ಚ ಕೇಳುತ್ತದೆ ಎಂದಾದರೆ, ನೀವು ಬಾದ್ದು ಮಾಡಬೇಕು ವೆಚ್ಚ ನಿಜವಾಗಿಯೂ ಸರಿ ಇದೆಯೇ ಅಥವಾ ಕರೆಗಳ ಸಂಖ್ಯೆ ಕಡಿಮೆ ಮಾಡಬಹುದು ಅಥವಾ ಕಡಿಮೆ ವೆಚ್ಚದ ಮಾದರಿಯನ್ನು ಬಳಸಬಹುದು. ನಿಜ ಸಮಯದ ಮೇಲ್ವಿಚಾರಣೆ ಅಪ್ರತೀಕ್ಷಿತ ಏರಿಕೆಯನ್ನು ಗುರುತಿಸಲು ಸಹ ಸಹಾಯಕ, ಉದಾಹರಣೆಗೆ, ದೋಷಗಳ ಕಾರಣವಾಗಿರುವ ಹೆಚ್ಚಿನ API ಲೂಪ್ಸ್.

**ದಾಖಲೆ ದೋಷಗಳು (Request Errors):** ಏಜೆಂಟ್ ಎಷ್ಟು ವಿನಂತಿಗಳನ್ನು ವಿಫಲಗೊಳಿಸಿದೆ? ಇದರಲ್ಲಿ API ದೋಷಗಳು ಅಥವಾ ಸಾಧನ ಕರೆ ವಿಫಲತೆಗಳು ಸೇರಬಹುದು. ನೀವು ನಿಮ್ಮ ಏಜೆಂಟ್ ಅನ್ನು ಉತ್ಪಾದನೆಯಲ್ಲಿ ಹೆಚ್ಚು ಭದ್ರವಾಗಿರುವಂತೆ ಮಾಡಲು, ನೀವು ನಂತರ ಬ್ಯಾಕ್ಅಪ್ ಅಥವಾ ಪುನಃ ಪ್ರಯತ್ನ ವ್ಯವಸ್ಥೆಯನ್ನು ಸಜ್ಜಾಗಿಸಬಹುದು. ಉದಾಹರಣೆಗೆ LLM ಒದಗಿಸುವವರು A ಡೌನ್ ಇದ್ದರೆ, ನೀವು ಬ್ಯಾಕ್ಅಪ್ ಎಲೆಎಲ್‌ಎಮ್ ಒದಗಿಸುವವರು B ಗೆ ಬದಲಿ ಮಾಡಬಹುದು.

**ಬಳಕೆದಾರ ಪ್ರತಿಕ್ರಿಯೆ (User Feedback):** ನೇರ ಬಳಕೆದಾರ ಮೌಲ್ಯಮಾಪನಗಳನ್ನು ಅನುಷ್ಠಾನ ಮಾಡುವುದರಿಂದ ಅಮೂಲ್ಯ ಒಳನೋಟಗಳು ಸಿಗುತ್ತವೆ. ಇದರಲ್ಲಿ ಸ್ಪಷ್ಟ ರೇಟಿಂಗ್‌ಗಳು (👍ಎತ್ತಿ/👎ಕಡಿಮೆ, ⭐1-5 ಸ್ಟಾರ್) ಅಥವಾ ಲಿಖಿತ ಕಾಮೆಂಟ್‌ಗಳು ಸೇರಬಹುದು. ಅಸಮಾಧಾನಕಾರಿ ಪ್ರತಿಕ್ರಿಯೆಗಳು ಎಂದಿಗೂ ನಿಗದಿಯಾಗಿ ಎಚ್ಚರಿಕೆ ನೀಡಬೇಕು; ಇದು ಏಜೆಂಟ್ ನಿರೀಕ್ಷೆಯಂತೆ ಕೆಲಸ ಮಾಡುತ್ತಿಲ್ಲ ಎಂಬ ಸೂಚನೆ.

**ಅವ್ಯಕೃತ ಬಳಕೆದಾರ ಪ್ರತಿಕ್ರಿಯೆ:** ಬಳಕೆದಾರರ ವರ್ತನೆಗಳು ಸಿದ್ಧಾಂತ ರೇಟಿಂಗ್ ಇಲ್ಲದೆ ಸಹ ಅಪರೋಕ್ಷ ಪ್ರತಿಕ್ರಿಯೆಯಾಗಿ ಕೆಲಸ ಮಾಡುತ್ತವೆ. ಇದರಲ್ಲಿ ತಕ್ಷಣದ ಪ್ರಶ್ನೆ ಪುನಃರಚನೆ, ಪುನರಾವರ್ತು ಪ್ರಶ್ನೆಗಳು ಅಥವಾ ಪುನಃಪ್ರಯತ್ನ ಬಟನ್ ಕ್ಲಿಕ್ ಮಾಡುವುದನ್ನು ಒಳಗೊಂಡಿರಬಹುದು. ಉದಾಹರಣೆಗೆ ಬಳಕೆದಾರರು ಮರುಪಡಿ ಅದೇ ಪ್ರಶ್ನೆ ಕೇಳುತ್ತಿದ್ದರೆ, ಇದು ಏಜೆಂಟ್ ನಿರೀಕ್ಷೆಯಂತೆ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತಿಲ್ಲದ ಸೂಚನೆ.

**ನಿಖರತೆ (Accuracy):** ಏಜೆಂಟ್ ಎಷ್ಟು ಬಾರಿ ಸರಿಯಾದ ಅಥವಾ ಅವಶ್ಯಕ ಉತ್ಪನ್ನಗಳನ್ನು ನೀಡುತ್ತದೆ? ನಿಖರತೆ ವ್ಯಾಖ್ಯಾನಗಳು ವಿಭಿನ್ನವಾಗುತ್ತವೆ (ಉದಾಹರಣೆಗೆ ಸಮಸ್ಯೆ ಪರಿಹಾರ ಶುದ್ಧತೆ, ಮಾಹಿತಿಯ ಹಿಂತಿರುಗಿಸುವ ನಿಖರತೆ, ಬಳಕೆದಾರ ತೃಪ್ತಿ). ಮೊದಲ ಹಂತದಲ್ಲಿ ನೀವು ಏಜೆಂಟ್ ಯಶಸ್ಸು ಎಂದರೆ ಏನು ಎಂಬುದನ್ನು ವ್ಯಾಖ್ಯಾನ ಮಾಡಬೇಕು. ನೀವು ಸ್ವಯಂಕ್ರೀಯ ಪರಿಶೀಲನೆ, ಮೌಲ್ಯಮಾಪನ ಅಂಕಗಳು, ಅಥವಾ ಕಾರ್ಯ ಪೂರ್ಣಗೊಳಿಸುವ ಲೇಬಲ್ಗಳ ಮೂಲಕ ನಿಖರತೆಯನ್ನು ಟ್ರ್ಯಾಕ್ ಮಾಡಬಹುದು. ಉದಾಹರಣೆಗೆ, ಟ್ರೇಸ್‌ಗಳನ್ನು "ಯಶಸ್ವಿ" ಅಥವಾ "ವಿಫಲ" ಎಂದು ಗುರುತಿಸುವುದು.

**ಸ್ವಯಂಚಾಲಿತ ಮೌಲ್ಯಮಾಪನ ಮೀಟ್ರಿಕ್ಸ್:** ನೀವು ಸ್ವಯಂಚಾಲಿತ ಮೌಲ್ಯಮಾಪನಗಳನ್ನು ಸಹ ಹೊಂದಿಸಬಹುದು. ಉದಾಹರಣೆಗೆ, ನೀವು ಒಂದು LLM ಅನ್ನು ಉಪಯೋಗಿಸಿ ಏಜೆಂಟ್ output ಅನ್ನು ಅಂಕಮಾಡಬಹುದು, ಇದು ಸಹಾಯಕವಾಗಿದೆ, ನಿಖರವಾಗಿದೆ ಅಥವಾ ಇಲ್ಲ ಎಂದು. ವಿವಿಧ ಅಂಶಗಳನ್ನು ಅಂಕಮಾಡಲು ಸಹಾಯ ಮಾಡುವ ಹಲವಾರು ಮುಕ್ತ ಮೂಲ ಗ್ರಂಥಾಲಯಗಳಿವೆ. ಉದಾಹರಣೆಗೆ [RAGAS](https://docs.ragas.io/) RAG ಏಜೆಂಟ್‌ಗಳಿಗೆ ಅಥವಾ [LLM Guard](https://llm-guard.com/) ಹಾನಿಕಾರಕ ಭಾಷೆ ಅಥವಾ ಪ್ರಾಂಪ್ಟ್ ಇಂಜೆಕ್ಷನ್ ಪತ್ತೆ ಮಾಡಲು.

ಪ್ರಾಯೋಗಿಕವಾಗಿ, ಈ ಮೀಟ್ರಿಕ್ಸ್‌ಗಳ ಸಂಯೋಜನೆಯು ಏಐ ಏಜೆಂಟ್ ಆರೋಗ್ಯದ ಉತ್ತಮಾವರಣ ನೀಡುತ್ತದೆ. ಈ ಅಧ್ಯಾಯದ [ಉದಾಹರಣೆ ನೋಟುಪುಸ್ತಕದಲ್ಲಿ](./code_samples/10-expense_claim-demo.ipynb) ನಾವು ಈ ಮೀಟ್ರಿಕ್ಸ್ ಜನರನ್ನು ನಿಜ ಉದಾಹರಣೆಗಳೊಂದಿಗೆ ತೋರಿಸುವೆವು, ಆದರೆ ಮೊದಲು, ಸಾಮಾನ್ಯ ಮೌಲ್ಯಮಾಪನ ಕಾರ್ಯಪ್ರವಾಹ ಹೇಗಿರುತ್ತದೆಯೋ ನೋಡೋಣ.

## ನಿಮ್ಮ ಏಜೆಂಟ್ ಅನ್ನು ಇನ್ಸ್ಟ್ರುಮೆಂಟ್ ಮಾಡಿ

ಟ್ರೇಸಿಂಗ್ ಡೇಟಾ ಸಂಗ್ರಹಿಸಲು, ನೀವು ನಿಮ್ಮ ಕೋಡ್ ಅನ್ನು ಇನ್ಸ್ಟ್ರುಮೆಂಟ್ ಮಾಡಬೇಕಾಗುತ್ತದೆ. ಗುರಿ ಏಜೆಂಟ್ ಕೋಡ್ ಅನ್ನು ಇನ್ಸ್ಟ್ರುಮೆಂಟ್ ಮಾಡಿ, ಟ್ರೇಸ್‌ಗಳು ಮತ್ತು ಮೀಟ್ರಿಕ್ಸ್ ಉತ್ಖಾತ ಮಾಡುವುದು, ಅವುಗಳನ್ನು مشاهدة ವೇದಿಕೆಯ ಮೂಲಕ ಸೆರೆಹರಿಸುವುದು, ಪ್ರಕ್ರಿಯೆ ಮಾಡುವುದೂ, ಹಾಗು ದೃಶ್ಯೀಕರಿಸುವುದೂ.

**OpenTelemetry (OTel):** [OpenTelemetry](https://opentelemetry.io/) LLM مشاهدةಗಾಗಿ ಕೈಗಾರಿಕಾ ಮಾನದಂಡವಾಗಿ ಎದುರುಗೊಂಡಿದೆ. ಇದು ಟೆಲಿಮೆಟ್ರಿ ಡೇಟಾ ಸೃಷ್ಟಿಸುವುದು, ಸಂಗ್ರಹಿಸುವುದು, ರಫ್ತು ಮಾಡುವುದಕ್ಕಾಗಿ API ಗಳು, SDK ಗಳು ಮತ್ತು ಉಪಕರಣಗಳ ಸಮೂಹ ನೀಡುತ್ತದೆ.

ಅನೇಕ ಇನ್ಸ್ಟ್ರುಮೆಂಟೇಷನ್ ಪುಸ್ತಕಾಲಯಗಳು ಇವೆ, ಅವು ಇತ್ತೀಚಿನ ಏಜೆಂಟ್ ಫ್ರೇಮ್ವರ್ಕ್‌ಗಳನ್ನು ತಿದ್ದಿ OpenTelemetry ಸ್ಪಾನ್ಸ್‌ಗಳನ್ನು مشاهدة ಸಾಧನಕ್ಕೆ ರಫ್ತು ಮಾಡಲು ಸುಲಭ ಮಾಡುತ್ತವೆ. ಮೈಕ್ರೋಸಾಫ್ಟ್ ಏಜೆಂಟ್ ಫ್ರೇಮ್ವರ್ಕ್ ಸ್ವಾಭಾವಿಕವಾಗಿ OpenTelemetry ಜೋಡಣೆ ಹೊಂದಿದೆ. ಕೆಳಗಿನದು MAF ಏಜೆಂಟ್ ಅನ್ನು ಇನ್ಸ್ಟ್ರುಮೆಂಟ್ ಮಾಡುವ ಉದಾಹರಣೆ:

```python
from agent_framework.observability import get_tracer, get_meter

tracer = get_tracer()
meter = get_meter()

with tracer.start_as_current_span("agent_run"):
    # ಏಜೆಂಟ್ ನಿರ್ವಹಣೆಯನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಟ್ರೇಸ್ ಮಾಡಲಾಗುತ್ತದೆ
    pass
```

ಈ ಅಧ್ಯಾಯದ [ಉದಾಹರಣೆ ನೋಟುಪುಸ್ತಕ](./code_samples/10-expense_claim-demo.ipynb) ನಿಮ್ಮ MAF ಏಜೆಂಟ್ ಅನ್ನು ಹೇಗೆ ಇನ್ಸ್ಟ್ರುಮೆಂಟ್ ಮಾಡುವುದು ತೋರಿಸುತ್ತದೆ.

**ಮ್ಯಾನುಯಲ್ ಸ್ಪಾನ್ ರಚನೆ:** ಇನ್ಸ್ಟ್ರುಮೆಂಟೇಷನ್ ಪುಸ್ತಕಾಲಯಗಳು ಉತ್ತಮ ಬೇಸ್‌ಲೈನ್ ನೀಡಿದರೂ, ಹೆಚ್ಚಿನ ವಿವರ ಅಥವಾ ಕಸ್ಟಮ್ ಮಾಹಿತಿಯ ಅಗತ್ಯ ಇದ್ದು, ನೀವು ಸ್ಪಾನ್ಸ್ ಮಾನ್ಯುವಲಿ ರಚಿಸಬಹುದು. ಮತ್ತಷ್ಟು ಮಹತ್ವಪೂರ್ಣವಾಗಿ, ಸ್ವಯಂಚಾಲಿತ ಅಥವಾ ಮ್ಯಾನುಯಲ್ ರಚಿಸಲಾದ ಸ್ಪಾನ್ಸ್‌ಗಳಿಗೆ ಕಸ್ಟಮ್ ಗುಣಲಕ್ಷಣಗಳನ್ನು (ಟ್ಯಾಗ್‌ಗಳು ಅಥವಾ ಮೆಟಾ ಡೇಟಾ ಹೆಸರಿನಲ್ಲಿಯೇ) ಸೇರಿಸಬಹುದು. ಈ ಗುಣಲಕ್ಷಣಗಳಲ್ಲಿ ವ್ಯವಹಾರ ಸಂಬಂಧಿತ ಡೇಟಾ, ಮಧ್ಯವर्ती ಲೆಕ್ಕಾಚಾರಗಳು, ಅಥವಾ ಡಿಬಗ್ ಅಥವಾ ವಿಶ್ಲೇಷಣೆಗೆ ಉಪಯುಕ್ತ ತತ್ವಗಳು ಸೇರಬಹುದು, ಉದಾ: `user_id`, `session_id`, ಅಥವಾ `model_version`.

ಲಾಂಗ್‌ಫ್ಯೂಸ್ ಪೈಥಾನ್ SDK ಬಳಸಿ ಕೈಯಿಂದ ಟ್ರೇಸ್ ಮತ್ತು ಸ್ಪಾನ್ಸ್ ರಚಿಸುವ ಉದಾಹರಣೆ:

```python
from langfuse import get_client
 
langfuse = get_client()
 
span = langfuse.start_span(name="my-span")
 
span.end()
```

## ಏಜೆಂಟ್ ಮೌಲ್ಯಮಾಪನ

مشاهدة ನಾವುಗೆ ಮೀಟ್ರಿಕ್ಸ್ ನೀಡುತ್ತದೆ, ಆದರೆ ಮೌಲ್ಯಮಾಪನವು ಆ ಡೇಟಾವನ್ನು ವಿಶ್ಲೇಷಿಸುವ (ಮತ್ತು ಪರಿಕ್ಷೆಗಳನ್ನು ನಡೆಸುವ) ಪ್ರಕ್ರಿಯೆಯಾಗಿದೆ, ಇದರಿಂದ ಏಜೆಂಟ್ ಹೇಗೆ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತಿದೆ ಮತ್ತು ಅದನ್ನು ಹೇಗೆ ಸುಧಾರಿಸಬಹುದು ಎಂಬುದನ್ನು ನಿರ್ಣಯಿಸಲಾಗುತ್ತದೆ. ಅರ್ಥಾತ್, ನಿಮಗೆ ಆ ಟ್ರೇಸ್ ಮತ್ತು ಮೀಟ್ರಿಕ್ಸ್ ಸಿಕ್ಕ ನಂತರ, ನೀವು ಅವುಗಳನ್ನು ಬಳಸಿಕೊಂಡು ಏಜೆಂಟ್ ಅನ್ನು ಮೌಲ್ಯಮಾಪನ ಹೇಗೆ ಮಾಡಬೇಕು ಮತ್ತು ನಿರ್ಧಾರಗಳನ್ನು ಏನು ಮಾಡಬೇಕು?

ನಿಯಮಿತ ಮೌಲ್ಯಮಾಪನ ಮುಖ್ಯವಾಗಿದೆ ಏಕೆಂದರೆ ಎಐ ಏಜೆಂಟ್‌ಗಳು ಸಾಮಾನ್ಯವಾಗಿ ನಿರ್ದಿಷ್ಟ ಫಲಿತಾಂಶ ನೀಡದ ಮನಸ್ಥಿತಿಯಲ್ಲಿರುತ್ತವೆ ಮತ್ತು ಹೆಚ್ಚುವರಿ ಹಾಡಿಕೆಗಳು (ನವೀಕರಣಗಳು ಅಥವಾ ಮಾದರಿ ವರ್ತನೆ ತಿರುಗಾಟ) ಮೂಲಕ ಬೆಳೆದುಕೊಳ್ಳುತ್ತವೆ – ಮೌಲ್ಯಮಾಪನ ಇಲ್ಲದೆ, ನೀವು ನಿಮ್ಮ “ಸ್ಮಾರ್ಟ್ ಏಜೆಂಟ್” ನಿಜವಾಗಿಯೂ ಉತ್ತಮವಾಗಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತಿದೆಯೇ ಅಥವಾ ಹತೋಟಿ ಹೊಡೆಯುತ್ತಿದ್ದೆಯೇ ಎಂಬುದನ್ನು ತಿಳಿಯಲಾಗದು.

ಎಐ ಏಜೆಂಟ್‌ಗಳಿಗೆ ಎರಡು ಮೌಲ್ಯಮಾಪನ ಪ್ರಕಾರಗಳು ಇವೆ: **ಆನ್ಲೈನ್ ಮೌಲ್ಯಮಾಪನ** ಮತ್ತು **ಆಫ್‌ಲೈನ್ ಮೌಲ್ಯಮಾಪನ**. ಎರಡೂ ಮುಖ್ಯ ಮತ್ತು ಪರಸ್ಪರ ಪೂರಕವಾಗಿವೆ. ನಾವು ಸಾಮಾನ್ಯವಾಗಿ ಆಫ್‌ಲೈನ್ ಮೌಲ್ಯಮಾಪನದಿಂದ ಪ್ರಾರಂಭಿಸುತ್ತೇವೆ, ಏಕೆಂದರೆ ಯಾವುದೇ ಏಜೆಂಟ್ ಅನ್ನು ನಿಯೋಜಿಸುವ ಮೊದಲು ಇದು ಕನಿಷ್ಠ ಅಗತ್ಯ ಹಂತ.

### ಆಫ್‌ಲೈನ್ ಮೌಲ್ಯಮಾಪನ

![Langfuse ನಲ್ಲಿನ ಡೇಟಾಸೆಟ್ ಐಟಂಗಳು](https://langfuse.com/images/cookbook/example-autogen-evaluation/example-dataset.png)

ಇದು ನಿಯಂತ್ರಿತ ಪರಿಸರದಲ್ಲಿ ಏಜೆಂಟ್ ಅನ್ನು ಮೌಲ್ಯಮಾಪನ ಮಾಡುವುದನ್ನು ಒಳಗೊಂಡಿದ್ದು ಸಾಮಾನ್ಯವಾಗಿ ಪರೀಕ್ಷಾ ಡೇಟಾಸೆಟ್ ಬಳಸಿ, ನೈಜ ಬಳಕೆದಾರ ಪ್ರಶ್ನೆಗಳಿಲ್ಲದೇ. ನೀವು ನಿರ್ದಿಷ್ಟ ಡೇಟಾಸೆಟ್‌ಗಳನ್ನು ಬಳಸುತ್ತೀರಿ, ಅಲ್ಲಿ ನಿರೀಕ್ಷಿತ output ಅಥವಾ ಸರಿಯಾದ ವರ್ತನೆಯು ತಿಳಿದಿದೆ, ನಂತರ ನೀವು ನಿಮ್ಮ ಏಜೆಂಟ್ ಅನ್ನು ಅವುಗಳ ಮೇಲೆ ಓಡಿಸುತ್ತೀರಿ.

ಉದಾಹರಣೆಗೆ, ನೀವು ಗಣಿತ ಪದಸಮಸ್ಯೆ ಏಜೆಂಟ್ ನಿರ್ಮಿಸಿದರೆ, ನೀವು 100 ಸಮಸ್ಯೆಗಳ [ಪರೀಕ್ಷಾ ಡೇಟಾಸೆಟ್](https://huggingface.co/datasets/gsm8k) ಹೊಂದಿರಬಹುದು, ಅದರಲ್ಲಿ ಉತ್ತರಗಳು ತಿಳಿವೆ. ಆಫ್‌ಲೈನ್ ಮೌಲ್ಯಮಾಪನವನ್ನು ಸಾಮಾನ್ಯವಾಗಿ ಅಭಿವೃದ್ಧಿಯ ಸಮಯದಲ್ಲಿ (ಮತ್ತು ಇದು CI/CD ಪೈಪ್ಲೈನ್ಗಳ ಭಾಗವಾಗಿರಬಹುದು) ಸುಧಾರಣೆಗಳನ್ನು ಪರಿಶೀಲಿಸಲು ಅಥವಾ ಹತೋಟಿ ತಡೆಯಲು ಬಳಸಲಾಗುತ್ತದೆ. ಇದರ ಲಾಭವೆಂದರೆ ಅದು **ಪುನರಾವರ್ತಿಸಬಹುದಾಗಿದೆ ಮತ್ತು ನಿಮಗೆ ಸ್ಪಷ್ಟ ನಿಖರತೆ ಮೀಟ್ರಿಕ್ಸ್ ಸಿಗುತ್ತವೆ, ಏಕೆಂದರೆ ನಿಮಗೆ ನೆಲಸಿದ್ಧ (ground truth) ಇದೆ**. ನೀವು ಬಳಕೆದಾರ ಪ್ರಶ್ನೆಗಳನ್ನು ಅನುಕರಿಸಿ ಮತ್ತು ಏಜೆಂಟ್ ಉತ್ತರಗಳನ್ನು ಆದರ್ಶ ಉತ್ತರಗಳಿಗೆ ಹೋಲಿಸಿ ಅಥವಾ ಮೇಲ್ಕಾಣಿಸಿದ ಸ್ವಯಂಚಾಲಿತ ಮೀಟ್ರಿಕ್ಸ್ ಬಳಸಬಹುದು.

ಆಫ್‌ಲೈನ್ ಮೌಲ್ಯಮಾಪನದ ಪ್ರಮುಖ ಸವಾಲು ನಿಮ್ಮ ಪರೀಕ್ಷಾ ಡೇಟಾಸೆಟ್ ಸಮಗ್ರವಾಗಿ ಹಾಗೂ ಸಂಬಂಧಿತವಾಗಿರಬೇಕು ಎಂಬುದು; ಏಜೆಂಟ್ ನಿಶ್ಚಿತ ಪರೀಕ್ಷಾ ಸೆಟ್‌ನಲ್ಲಿ ಚೆನ್ನಾಗಿ ಕಾರ್ಯನಿರ್ವಹಿಸಬಹುದಾದರೂ, ಉತ್ಪಾದನೆಯಲ್ಲಿ ಬಹಳ ಭಿನ್ನ ಪ್ರಶ್ನೆಗಳನ್ನು ಎದುರಿಸಬಹುದು. ಆದ್ದರಿಂದ, ನೀವು ಪರೀಕ್ಷಾ ಸೆಟ್ ನವೀಕರಿಸಬೇಕು ಹೊಸ ತುದಿ ಪ್ರಕರಣಗಳು ಮತ್ತು ನಿಜಜಗತ್ತು ಸಂದರ್ಭಗಳನ್ನು ಪ್ರತಿಬಿಂಬಿಸುವ ಉದಾಹರಣೆಗಳೊಂದಿಗೆ. “ಧೂಮಪಾನ ಪರೀಕ್ಷೆ” ಸಾಕುಸೀಟುಗಳು (ಸುಲಭವಾದ ಪರೀಕ್ಷೆಗಳು) ಮತ್ತು ದೊಡ್ಡ ಮೌಲ್ಯಮಾಪನ ಸೆಟ್‌ಗಳ ಮಿಶ್ರಣ ಬಳಸುವುದು ಉಪಯುಕ್ತ: ಸಣ್ಣ ಸೆಟ್‌ಗಳು ತ್ವರಿತ ತಪಾಸಣೆಗಳಿಗೆ ಮತ್ತು ದೊಡ್ಡವು ವಿಶಾಲ ಕಾರ್ಯನಿರ್ವಹಣೆ ಮೀಟ್ರಿಕ್ಸ್‌ಗಳಿಗೆ.

### ಆನ್ಲೈನ್ ಮೌಲ್ಯಮಾಪನ

![ಮಾಹರಿಕೆ ಮೀಟ್ರಿಕ್ಸ್ ಅವಲೋಕನ](https://langfuse.com/images/cookbook/example-autogen-evaluation/dashboard.png)

ಇದು ಏಜೆಂಟ್ ನ್ನು ನೈಜ, ನೈವ ಪರಿಸರದಲ್ಲಿ, ಅಂದರೆ ನೈಜ ಬಳಸುತ್ತಿರುವಾಗ, ಮೌಲ್ಯಮಾಪನ ಮಾಡುವುದನ್ನು ಸೂಚಿಸುತ್ತದೆ. ಆನ್ಲೈನ್ ಮೌಲ್ಯಮಾಪನದಲ್ಲಿ ನೈಜ ಬಳಕೆದಾರ ಸಂವಹನದ ಮೇಲೆ ಏಜೆಂಟ್ ಕಾರ್ಯಕ್ಷಮತೆಯನ್ನು ಮೇಲ್ವಿಚಾರಣೆ ಮಾಡಲಾಗುತ್ತೆ ಮತ್ತು ಫಲಿತಾಂಶಗಳನ್ನು ನಿರಂತರವಾಗಿ ವಿಶ್ಲೇಷಿಸಲಾಗುತ್ತದೆ.

ಉದಾಹರಣೆಗೆ, ನೀವು ಯಶಸ್ಸಿನ ದರ, ಬಳಕೆದಾರ ತೃಪ್ತಿ ಅಂಕೆಗಳು ಅಥವಾ ಇತರ ಮೀಟ್ರಿಕ್ಸ್‌ಗಳನ್ನು ನೈಜ ಟ್ರಾಫಿಕ್ ಮೇಲೆ ಟ್ರ್ಯಾಕ್ ಮಾಡಬಹುದು. ಆನ್ಲೈನ್ ಮೌಲ್ಯಮಾಪನದ ಲಾಭವೆಂದರೆ ಇದು **ನೀವು ಪ್ರಯೋಗಾಲಯದಲ್ಲಿ ಊಹಿಸದೆ ಇರುತ್ತಿದ್ದ ಸಂಗತಿಗಳನ್ನೂ ಹಿಡಿದುಕೊಡುತ್ತದೆ** – ಮಾದರಿ ಹಿಮ್ಮುಖತೆಯನ್ನು ನೀವು ಗಮನಿಸಬಹುದು (ಒಂದು ಏಜೆಂಟ್ ಪರಿಣಾಮಕಾರಿತ್ವ ಕುಸಿತ ಆಗಬಹುದು ಇನ್‌ಪುಟ್ ಮಾದರಿ ಬದಲಾಗುತ್ತಿರುವಾಗ) ಮತ್ತು ಮುಂಬರುವ ಪ್ರಶ್ನೆಗಳನ್ನು ಅಥವಾ ಸಂದರ್ಭಗಳನ್ನು ಪತ್ತೆ ಮಾಡಬಹುದು, ಅವು ನಿಮ್ಮ ಪರೀಕ್ಷಾ ಡೇಟಾದಲ್ಲಿ ಇರಲಿಲ್ಲ. ಇದು ಏಜೆಂಟ್ “ಹತ್ತುವಿನಲ್ಲಿ” ಹೇಗೆ ವರ್ತಿಸುತ್ತಿದೆಯೆಂಬ ನಿಜವಾದ ಚಿತ್ರವನ್ನು ನೀಡುತ್ತದೆ.

ಆನ್ಲೈನ್ ಮೌಲ್ಯಮಾಪನ ಸಾಮಾನ್ಯವಾಗಿ ಅವ್ಯಕೃತ ಮತ್ತು ಸ್ಪಷ್ಟ ಬಳಕೆದಾರ ಪ್ರತಿಕ್ರಿಯೆಗಳನ್ನು ಸಂಗ್ರಹಿಸುತ್ತದೆ, ಹಾಗೆಯೇ ಶಾಡೋ ಪರೀಕ್ಷೆಗಳು ಅಥವಾ A/B ಪರೀಕ್ಷೆಗಳು ನಡೆಸಬಹುದು (ಅಲ್ಲಿ ಹೊಸ ಆವೃತ್ತಿಯ ಏಜೆಂಟ್ ಹಳೆಯದೊಂದಿಗೆ ಹೋಲಿಕೆಗಾಗಿ ಪಾರಲಲ್‌ನಲ್ಲಿ ಓಡುತ್ತದೆ). ಸವಾಲು ಎಂದರೆ ನೈಜ ಸಂವಹನಗಳಿಗೆ ವಿಶ್ವಾಸಾರ್ಹ ಲೇಬಲ್ ಅಥವಾ ಸ್ಕೋರ್‌ಗಳನ್ನು ಪಡೆಯುವುದು ಕಷ್ಟ – ನೀವು ಬಳಕೆದಾರ ಪ್ರತಿಕ್ರಿಯೆ ಅಥವಾ ತದನಂತರದ ಮೀಟ್ರಿಕ್ಸ್ (ಬಳಕೆದಾರ ಫಲಿತಾಂಶ ಕ್ಲಿಕ್ ಮಾಡಿದರೆ) ಮೇಲೆ ಅವಲಂಬಿತವಿರಬಹುದು.

### ಎರಡನ್ನೂ ಸಂಯೋಜಿಸುವುದು

ಆನ್ಲೈನ್ ಮತ್ತು ಆಫ್‌ಲೈನ್ ಮೌಲ್ಯಮಾಪನ ಪರಸ್ಪರ ಬೇರೆಯದಾಗಿಲ್ಲ; ಅವು ತುಂಬಾ ಪೂರಕ. ಆನ್ಲೈನ್ ಮೇಲ್ವಿಚಾರಣೆಯಿಂದ (ಉದಾ: ಏಜೆಂಟ್ ಕೆಡವಾಗಿರುವ ಹೊಸ ಬಳಕೆದಾರ ಪ್ರಶ್ನೆಗಳ ಪ್ರಕಾರ) ತಿಳಿಯುವಿಕೆಗಳು ಆಫ್‌ಲೈನ್ ಪರೀಕ್ಷಾ ಡೇಟಾಸೆಟ್ ಹೆಚ್ಚು ಸುಧಾರಿಸಲು ಬಳಸಬಹುದು. ವಿರುದ್ಧವಾಗಿ, ಆಫ್‌ಲೈನ್ ಪರೀಕ್ಷೆಗಳಲ್ಲಿ ಉತ್ತಮ ಕಾರ್ಯನಿರ್ವಹಿಸಿದ ಏಜೆಂಟ್‌ಗಳು ಆನ್ಲೈನ್‌ನಲ್ಲಿ ಹೆಚ್ಚು ವಿಶ್ವಾಸದಿಂದ ನಿಯೋಜಿಸಿ ಮತ್ತು ಮೇಲ್ವಿಚಾರಣೆ ಮಾಡಬಹುದು.

ನಿಜವಾಗಿಯೂ, ಹಲವಾರು ತಂಡಗಳು ಈ ಗುಂಡಿಯನ್ನು ಸ್ವೀಕರಿಸುತ್ತವೆ:

_ಆಫ್‌ಲೈನ್ valore -> ನಿಯೋಜನೆ -> ಆನ್ಲೈನ್ ಮೇಲ್ವಿಚಾರಣೆ -> ಹೊಸ ವಿಫಲ ಪ್ರಕರಣ ಸಂಗ್ರಹಿಸು -> ಆಫ್‌ಲೈನ್ ಡೇಟಾಸೆಟ್ಗೆ ಸೇರಿಸು -> ಏಜೆಂಟ್ ಅನ್ನು ಸುಧಾರಿಸು -> ಪುನರಾವರ್ತಿಸು_.

## ವೆಚ್ಚ ನಿರ್ವಹಣೆ


AI ಏಜೆಂಟ್‌ಗಳನ್ನರ್ಧಿಸಲು ವೆಚ್ಚಗಳನ್ನು ನಿರ್ವಹಿಸುವ ಕೆಲ ವಿಧಾನಗಳು ಹೀಗಿವೆ:

**ಚಿಕ್ಕ ಮಾದರಿಗಳನ್ನು ಬಳಸುವುದು:** ಸಣ್ಣ ಭಾಷಾ ಮಾದರಿಗಳು (SLMs) ಕೆಲವು ಏಜೆಂಟಿಕ್ ಬಳಕೆ ಪ್ರಕರಣಗಳಲ್ಲಿ ಚೆನ್ನಾಗಿ ಕಾರ್ಯನಿರ್ವಹಿಸಬಹುದು ಮತ್ತು ವೆಚ್ಚಗಳನ್ನು ಬಹಳಷ್ಟು ಕಡಿಮೆ ಮಾಡಬಹುದು. ಹಿಂದಿನಂತೆ ಹೇಳಿದಂತೆ, ನಿಮ್ಮ ಬಳಕೆ ಪ್ರಕರಣದಲ್ಲಿ SLM ಒಮ್ಮೆ ಹೇಗಿರುತ್ತದೆ ಎಂದು ತಿಳಿದುಕೊಳ್ಳಲು ಮತ್ತು ದೊಡ್ಡ ಮಾದರಿಗಳೊಂದಿಗೆ ಪ್ರદર્શનವನ್ನು ಹೋಲಿಸಲು ಮೌಲ್ಯಾಂಕನ ವ್ಯವಸ್ಥೆಯನ್ನು ನಿರ್ಮಿಸುವುದು ಉತ್ತಮ ಮಾರ್ಗವಾಗಿದೆ. ಸರಳ ಕೆಲಸಗಳಿಗೆ, ಉದಾಹರಣೆಗೆ ಉದ್ದೇಶ ಶ್ರೇಣೀಕರಣ ಅಥವಾ ಪರಿಮಾಣ ಸಂಗ್ರಹಣೆಗೆ SLMಗಳನ್ನು ಪರಿಗಣಿಸಿ, ಆದರೆ ಸಂಕೀರ್ಣ ನಿರ்ணಯಕ್ಕಾಗಿ ದೊಡ್ಡ ಮಾದರಿಗಳನ್ನು ಮೀಸಲಿಡಿ.

**ರೂಟರ್ ಮಾದರಿಯನ್ನು ಬಳಸುವುದು:** ಸಮಾನ ತಂತ್ರವೇ ಹಲವಾರು ಮಾದರಿಗಳ ಮತ್ತು ಗಾತ್ರಗಳ ಬದಲಾವಣೆ ಬಳಕೆ. ನೀವು ಸವಲತ್ತು ಮತ್ತು ಸರಿಯಾದ ಕಾರ್ಯಗಳಲ್ಲಿ ಕಾರ್ಯತತ್ಪರತೆಯನ್ನು ಖಚಿತಪಡಿಸಿ, ಸಂಕೀರ್ಣತೆಗೆ ಆಧಾರಿತವಾಗಿ ವಿನಂತಿಗಳನ್ನು ಸರಿಹೊಂದಿರುವ ಮಾದರಿಗಳಿಗೆ ನೇರಿಸುವ LLM/SLM ಅಥವಾ ಸರ್ವರ್‌ಲೆಸ್ ಕಾರ್ಯವನ್ನು ಬಳಸಬಹುದು. ಉದಾಹರಣೆಗಾಗಿ, ಸರಳ ಪ್ರಶ್ನೆಗಳನ್ನು ಸಣ್ಣ ಮತ್ತು ವೇಗದ ಮಾದರಿಗಳಿಗೆ ಮಾರ್ಗದರ್ಶನ ಮಾಡಿ, ಮತ್ತು ದುಬಾರಿ ದೊಡ್ಡ ಮಾದರಿಗಳನ್ನು ಕೈಲೋಕಿಕ ನಿರ್ಣಯ ಕಾರ್ಯಗಳಿಗೆ ಮಾತ್ರ ಬಳಸುವಿರಿ.

**ಪ್ರತ್ಯುತ್ತರಗಳನ್ನು ಕ್ಯಾಶ್ ಮಾಡುವುದು:** ಸಾಮಾನ್ಯ ವಿನಂತಿಗಳು ಮತ್ತು ಕಾರ್ಯಗಳನ್ನು ಗುರುತಿಸಿ, ಅವುಗಳನ್ನು ನಿಮ್ಮ ಏಜೆಂಟ್ ವ್ಯವಸ್ಥೆಗೆ ಹೋಗುವ ಮುನ್ನ ಪ್ರತಿಕ್ರಿಯೆಗಳನ್ನು ನೀಡುವುದು ಸಮಾನ ವಿನಂತಿಗಳ ಪ್ರಮಾಣವನ್ನು ಕಡಿಮೆ ಮಾಡಲು ಉತ್ತಮ ವಿಧಾನ. ನೀವು ಸಾಮಾನ್ಯ AI ಮಾದರಿಗಳನ್ನು ಬಳಸಿ ನಿಮ್ಮ ಕ್ಯಾಶ್ ಮಾಡಲಾದ ವಿನಂತಿಗಳಿಗೆ ವಿನಂತಿಯ ಸಾಮ್ಯತೆಯನ್ನು ಗುರುತಿಸುವ ಫ್ಲೋವನ್ನು ಸಹ ಜಾರಿಗೆ ತರಬಹುದು. ಈ ತಂತ್ರವು ಆನೇಕ ಅವಧಿಯ ಪ್ರಶ್ನೆಗಳು ಅಥವಾ ಸಾಮಾನ್ಯ ಕಾರ್ಯಗಳ ವೆಚ್ಚಗಳನ್ನು ಬಹಳಷ್ಟು ಕಡಿಮೆ ಮಾಡಬಹುದು.
