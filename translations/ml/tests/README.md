# ഏജന്റ് സ്മോക്ക് പരിശോധനകൾ

ഈ ഫോൾഡർ കോഴ്സിൽ നിങ്ങൾ നിർമ്മിക്കുന്ന ഏജന്റുകൾക്കുള്ള **സ്മോക്ക്-ടെസ്റ്റ് കാറ്റലോഗുകൾ** സൂക്ഷിക്കുന്നു.
ഒരു സ്മോക്ക് ടെസ്റ്റ് ഒരു സുലഭവും ദ്രുതവുമുള്ള പരിശോധനയാണ്, ഒരു **പ്രവൃത്തി നടത്തുന്ന Microsoft Foundry ഹോസ്റ്റുചെയ്ത
ഏജന്റ്** എത്താനാകുകയും പ്രതികരിക്കയും അടിസ്ഥാന പ്രോമ്പ്റ്റ്
പ്രതീക്ഷകൾ പാലിക്കുന്നുവെന്ന് ഉറപ്പാക്കുക. ഇത് ഒരു പ്രാഥമിക ഗേറ്റ് ആണ് — [പാഠം 10](../10-ai-agents-production/README.md) ലും
[പാഠം 16](../16-deploying-scalable-agents/README.md) ലും നിങ്ങൾ പഠിക്കുന്ന പൂർണ്ണ മൂല്യനിർണയ
പ്രക്രിയയ്ക്കുള്ള പകരമല്ല.

ഈ കാറ്റലോഗുകൾ [AI Smoke Test](https://github.com/marketplace/actions/ai-smoke-test)
GitHub ആക്ഷനിലൂടെ [`.github/workflows/smoke-test.yml`](../../../.github/workflows/smoke-test.yml)
വർക്ക്‌ഫ്ലോയിലൂടെ ഉപയോഗിക്കപ്പെടുന്നു.

## എങ്ങനെ പ്രവർത്തിപ്പിക്കാം

1. **പാഠത്തിലെ ഏജന്റിനെ** Microsoft Foundry ലേക്ക് ഹോസ്റ്റുചെയ്ത ഏജന്റായി വിന്യസിക്കുക (വിന്യാസ വർക്ക്‌ഫ്ലോക്കായി
   പാഠം 16 കാണുക). **ഏജന്റ് പേര്** കൂടാതെ നിങ്ങളുടെ
   **Foundry പ്രോജക്റ്റ് എന്റ്പോയിന്റ്** മനസിലാക്കി വയ്ക്കുക.
2. ഈ റിപ്പോ സിക്രെട്ടുകൾ ചേർക്കുക (Settings → Secrets and variables → Actions):
   `AZURE_CLIENT_ID`, `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID`. ഫെഡറേറ്റഡ്
   ഐഡന്റിറ്റി **Foundry പ്രോജക്റ്റ് സ്‌കോപ്പിൽ** **Azure AI User** റോളിനിരിക്കുന്നതായിരിക്കണം.
3. **Actions** ടാബിൽ നിന്ന് **Smoke-test hosted agents** ഓടിക്കുക, പാഠത്തിനായി
   `tests_file` തിരഞ്ഞെടുക്കുകയും പൊരുത്തപ്പെടുന്ന `agent_name`,
   `project_endpoint` നൽകുകയും ചെയ്യുക.

## എത്രപാടുകൾക്ക് സ്മോക്ക് ടെസ്റ്റുകൾ ഉണ്ട്?

സ്മോക്ക് ടെസ്റ്റുകൾ ഉദഹരിക്കുന്ന പാഠങ്ങൾക്കാണ് ബാധകമായത്, അവിടെ നിങ്ങൾ **ഏജന്റ് വിന്യസിക്കുന്നു** അവന്റെ ടെക്സ്റ്റ് മറുപടികൾ അറിയപ്പെട്ട ഉള്ളടക്കത്തോടൊപ്പം സ്ഥിരീകരിക്കാമെന്ന്. ആശയപരമായ, ലോകലായി മാത്രം പ്രവർത്തിക്കുന്നവയുള്‍പ്പെടെയോ അല്ലെങ്കിൽ നിർണ്ണിതമായ സൃഷ്ടിമാനമായ ഫലം സൃഷ്ടിക്കുന്നവയുള്‍പ്പെടെയോ പഠനങ്ങൾ ഉദ്ദേശപൂർവം ഒഴിവാക്കപ്പെട്ടിരിക്കുന്നു:



- **പാഠം 17 (പ്രാദേശിക AI ഏജന്റുമാർ സൃഷ്ടിക്കൽ)** നിങ്ങളുടെ വർക്സ്റ്റേഷനിൽ മുഴുവനും Foundry Local ഉപയോഗിച്ച് പ്രവർത്തിക്കുന്നു,  
  Foundry Responses എന്റ്ന്‌പോയിന്റ് പ്രദർശിപ്പിക്കാതെ, അങ്ങനെ ഈ  
  പ്രവർത്തനം ബാധകമല്ല. ഇത് ലോക്കൽ നോട്ട്ബുക്ക് ഓടിച്ച് സ്ഥിരീകരിക്കുക.  
- ഡിസൈൻ-പാറ്റേൺ, സിദ്ധാന്ത പാഠങ്ങൾ (02, 03, 06, 07, 09, 12) ഒറ്റ  
  smoke-test നായി ഡിപ്ലോയബിൾ ഏജന്റ് അയയ്ക്കാറില്ല.  

## കാറ്റലോഗ് സ്കീമ (ത്വരിത റഫറൻസ്)  

ഓരോ കാറ്റലോഗും മേൽനിലവാരത്തിലുള്ള `tests` നിരയുള്ള JSON ഡോക്യുമെന്റാണ്. ഓരോ എൻട്രിയും  
ഒരു പ്രോംപ്‌റ്റ് പോസ്റ്റ് ചെയ്ത് മറുപടിയിൽ സ്ഥിരീകരണം നടത്തുന്നു:  

| ഫീൽഡ് | അർത്ഥം |
|-------|---------|
| `id` | ലോഗിൽ പതിപ്പിച്ച അപൂർവ്വമായ ഘട്ട ഐഡന്റിഫയർ. |
| `description` | മാനവം വായിക്കാൻ കഴിയുന്ന ഉദ്ദേശ്യം. |
| `prompt` | ഏജന്റിന് അയയ്ക്കുന്ന സന്ദേശം. |
| `assertions.status` | പ്രതീക്ഷിച്ച HTTP സ്ഥിതി (ഡീഫോൾട്ട് 200). |
| `assertions.contains_any` | മറുപടിയിൽ ഈ സബ്‌സ്ട്രിങ്ങുകളിൽ ഏതെങ്കിലും ഒന്നുണ്ടെങ്കിൽ കടന്നു പോകുക. |
| `assertions.contains_all` | മറുപടിയിൽ എല്ലായ്പ്പോഴും സബ്‌സ്ട്രിങ്ങുകൾ ഉണ്ടായിരിക്കണം എന്നുണ്ടെങ്കിൽ കടന്നു പോകുക. |
| `assertions.contains_none` | മറുപടിയിൽ ഇവയിൽ എവെങ്കിലും സബ്‌സ്ട്രിങ്ങുകൾ ഇല്ലെങ്കിൽ കടന്നു പോകുക. |
| `save_response_id_as` | പിറകെ വരാനിരിക്കുന്ന മൾട്ടി-ടേൺ ഘട്ടത്തിനായി മറുപടി ഐഡിയുടെ സംഭരണം. |
| `use_previous_response_id` | ഈ ടേൺ ഒരു സംരക്ഷിച്ച മറുപടി ഐഡിക്കൊപ്പം ശൃംഖലയാക്കി അയയ്ക്കുക. |

Assertions കെയ്സ്-ഇൻസെൻസിറ്റീവ് സബ്‌സ്ട്രിംഗ് പരിശോധനകളാണ്. കാണുക
[ചర్య ഡോക്യുമെന്റേഷൻ](https://github.com/marketplace/actions/ai-smoke-test)
മുഴുവൻ സ്കീമ, ഫൗണ്ടറി-നിർവഹിക്കുന്ന സംവാദ വിഭവങ്ങൾ ഉൾപ്പെടെ.
