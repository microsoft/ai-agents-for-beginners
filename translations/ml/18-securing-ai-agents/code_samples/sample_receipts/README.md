# സാമ്പിൾ റിസീറ്റ് ഫിക്സ്ചേഴ്സ്

നോട്ട്‌ബുക്ക് ഓടിക്കാതെ പരിശോധനക്ക് മൂന്ന് മുൻകൂട്ടി സൃഷ്ടിച്ച റിസീറ്റ് ഫയലുകൾ.

| ഫയൽ | എന്താണ് അത് |
|---|---|
| `01_valid_receipt.json` | ഒരു സാധുവായ ഒപ്പ് നൽകിയ റിസീറ്റ്, `lookup_flights` ടൂൾ കോൾക്കായി. സ്ഥിരീകരണം സത്യം തിരികെ നൽകുന്നു. |
| `02_tampered_receipt.json` | ഒപ്പിട്ടതിന് ശേഷമുള്ള ഒരു ഫീൽഡ് മാറ്റിയ അതേ റിസീറ്റി. സ്ഥിരീകരണം തെറ്റ് തിരികെ നൽകുന്നു. |
| `03_chain_three_receipts.json` | മൂന്ന് സാധുവായ റിസീറ്റുകളുടെ ശൃംഖല (തിരയുക, ഹോൾഡ്, ബുക്ക്) `previous_receipt_hash` ഓരോന്നും മുന്‍തലത്തിലേക്കു ബന്ധിപ്പിക്കുന്നത്. |

ഫിക്സ്ചേഴ്സ് പേശിയുടെ കാനോണിക്കൽ JCS ബൈറ്റുകൾ നേരിട്ട് Ed25519 ഉപയോഗിച്ച് ഒപ്പിടുന്നു.
SHA-256 ഉള്ളടക്ക ഡൈജസ്റ്റുകൾക്കും റിസീറ്റ്-ചെയിൻ ലിങ്കുകൾക്കും ഇപ്പോഴും ഉപയോഗിക്കുന്നു,
ഒപ്പിടുന്നതിന് മുമ്പ് ഒരു അധിക പ്രീ-ഹാഷായി അല്ല.

## സാമ്പിളുകൾ സ്ഥിരീകരിക്കൽ

നോട്ട്‌ബുക്ക് നാല് ഭാഗങ്ങളായി പരിശോധന നടത്തുന്നു. ഈ ഫിക്സ്ചേഴ്സ് നേരിട്ട് പരിശോധിക്കാനായി,
നോട്ട്‌ബുക്ക് നാറ്റീവ് ഓടിക്കാതെ:

```python
import json
from pathlib import Path

# Assumes you have completed the imports and helper functions
# from sections 1 and 2 of 18-signed-receipts.ipynb.

valid = json.loads(Path("01_valid_receipt.json").read_text())
print(f"Valid receipt: {verify_receipt(valid)}")        # True

tampered = json.loads(Path("02_tampered_receipt.json").read_text())
print(f"Tampered receipt: {verify_receipt(tampered)}")  # False

chain = json.loads(Path("03_chain_three_receipts.json").read_text())
for r in verify_chain(chain):
    print(f"  Receipt {r['index']} ({r['tool']}): {'VALID' if r['overall_valid'] else 'INVALID'}")
```

## വിദ്യാർത്ഥികൾ കাঁচനായ JSON പരിശോധനയിൽ എന്താണ് പഠിക്കുന്നത്

കাঁচനായ റിസീറ്റ് ഫോർമാറ്റ് വായിക്കുന്നത് നോട്ട്‌ബുക്കിലെ കോശങ്ങൾ എല്ലായ്പ്പോഴും നൽകാത്ത ആശയവിനിമയം ശക്തിപ്പെടുത്തുന്നു.
JSON തിരികെ നോക്കിക്കൊണ്ടിരിക്കുന്ന വിദ്യാർത്ഥികൾ പലപ്പോഴും ശ്രദ്ധിക്കുന്നത്:

1. ഒപ്പ് ഒരു മൂടിത്തുമ്പിയ base64url സ്ട്രിംഗ് ആണെങ്കിലും, മറ്റു എല്ലാ ഫീൽഡുകളും സാധാരണ വായനയോഗ്യമായ JSON ആണ്. ഒപ്പ് ഉള്ളടക്കം എൻക്രിപ്റ്റ് ചെയ്തിട്ടില്ല; അത് സാക്ഷ്യപ്പെടുത്തുന്നു.
   വായിക്കാൻ കഴിയുന്ന JSON. ഒപ്പ് ഉള്ളടക്കത്തെ എൻക്രിപ്റ്റ് ചെയ്യുന്നത് അല്ല; അതിനു സാക്ഷ്യം തരുകയാണ് അത്.
2. `public_key` റസീതിൽ സമന്വയിപ്പിച്ചിരിക്കുന്നു. ഒരു ഓഡിറ്റര്‍ മറ്റെന്തും ആവശ്യമില്ല
   സാധൂകരിക്കാൻ (കീ യഥാർത്ഥത്തിൽ അവകാശപ്പെട്ട ഇറക്കിമാറ്റിയതിന് പെട്ടതാണെന്ന് വിശ്വാസത്തിലായിരിക്കേണ്ടത്; 
   ഐഡന്റിറ്റി ഇൻഫ്രാസ്ട്രക്ടറിന്റെ പാഠം README കാണുക).
3. ഏതെങ്കിലും ഫീൽഡിലെ ഒരു അക്കമात्रം മാറ്റി, പിന്നീട് ഈ ഫയലിനെ 
   `02_tampered_receipt.json`-നുമായി വീണ്ടും താരതമ്യം ചെയ്യുന്നത് ബൈറ്റ്-നിലവാരമായ യന്ത്രവ്യവസ്ഥയെ ഉറപ്പാക്കുന്നു.
