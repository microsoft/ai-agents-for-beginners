# ഏജന്റിക് പ്രോട്ടോകോളുകൾ (MCP, A2A, NLWeb) ഉപയോഗിക്കൽ  

[![Agentic Protocols](../../../translated_images/ml/lesson-11-thumbnail.b6c742949cf1ce2a.webp)](https://youtu.be/X-Dh9R3Opn8)  

> _(ഈ പാഠത്തിന്റെ വീഡിയോ കാണുന്നതിനു മുകളിൽ ചിത്രത്തിൽ ക്ലിക്ക് ചെയ്യുക)_  

AI ഏജന്റുകളുടെ ഉപയോഗം വർദ്ധിക്കുന്നതോടെ, സ്റ്റാൻഡേർഡൈസേഷൻ, സുരക്ഷ, തുറന്ന നവോത്ഥാനത്തിന് പിന്തുണ നൽകുന്ന പ്രോട്ടോകോളുകളുടെ ആവശ്യം കൂടി വളരുന്നു. ഈ പാഠത്തിൽ, ഈ ആവശ്യം നിറവേറ്റാൻ നോക്കുന്ന 3 പ്രോട്ടോകോളുകൾ - മോഡൽ കോൺടക്സ്റ്റ് പ്രോട്ടോകോൾ (MCP), ഏജന്റ് ടു ഏജന്റ് (A2A) மற்றும் നാച്വറൽ ലാങ്ഗ്വേജ് വെബ് (NLWeb) - പരിശോധിക്കും.  

## പരിചയം  

ഈ പാഠത്തിൽ, നാം പഠിക്കാം:  

• **MCP** എങ്ങനെ AI ഏജന്റുകൾക്ക് ബാഹ്യ ഉപകരണങ്ങളും ഡാറ്റയും ഉപയോഗിച്ച് ഉപയോക്തൃകാര്യങ്ങൾ പൂർത്തിയാക്കാൻ അനുവദിക്കുന്നുവെന്ന്.  

• **A2A** എങ്ങനെ വ്യത്യസ്ത AI ഏജന്റുകൾ തമ്മിൽ ആശയവിനിമയം, സഹകരണം സാദ്ധ്യമാക്കുന്നതെന്ന്.  

• **NLWeb** എങ്ങനെ ഏതെങ്കിലും വെബ്സൈറ്റിലും നാച്വറൽ ലാങ്ഗ്വേജ് ഇന്റർഫേസുകൾ കൊണ്ടുവരികയും, AI ഏജന്റുകൾക്ക് ഉള്ളടക്കം കണ്ടെത്തി സംവദിക്കാനും കഴിയുന്നതെന്ന്.  

## പഠന ലക്ഷ്യങ്ങൾ  

• AI ഏജന്റുകളുടെ പ്രകൃതിയിൽ MCP, A2A, NLWeb ന്റെ കേന്ദ്ര ലക്ഷ്യവും പ്രയോജനങ്ങളും തിരിച്ചറിയുക.  

• ഓരോ പ്രോട്ടോകോൾയും LLM കളിൽ, ഉപകരണങ്ങളിലും മറ്റ് ഏജന്റുകളുമായുള്ള ആശയവിനിമയവും സംവരണവും എങ്ങനെ സഹായിക്കുന്നുവെന്ന് വിശദീകരിക്കുക.  

• സങ്കീർണ്ണ ഏജന്റിക് സിസ്റ്റങ്ങൾ രൂപപ്പെടുത്തുന്നതിൽ ഓരോ പ്രോട്ടോകോളിന്റെയും വ്യത്യസ്ത പങ്ക് തിരിച്ചറിയുക.  

## മോഡൽ കോൺടക്സ്റ്റ് പ്രോട്ടോകോൾ  

**Model Context Protocol (MCP)** ഒരു തുറന്ന സ്റ്റാൻഡേർഡ് ആണ്, അപ്ലിക്കേഷനുകൾ LLM കളിൽ കോൺടക്സ്റ്റും ഉപകരണങ്ങളും നൽകാൻ ഏകീകരിച്ച രീതിയിലാണ് സാധ്യമാക്കുന്നത്. ഇത് AI ഏജന്റുകൾക്ക് വിവിധ ഡാറ്റാ ഉറവിടങ്ങളിലും ഉപകരണങ്ങളിലും ക്രമബദ്ധമായ ബന്ധം നല്കാൻ "സാർവത്രിക അഡാപ്റ്റർ" പോലെയാണ് പ്രവര്‍ത്തിക്കുന്നത്.  

MCP കാണിക്കുന്ന ഘടകങ്ങൾ, നേരിട്ട് API ഉപയോഗിക്കുമ്പോൾനിന്നുള്ള പ്രയോജനങ്ങൾ, AI ഏജന്റുകൾ MCP സെർവറെ എങ്ങനെ ഉപയോഗിക്കാം എന്ന ഉദാഹരണം നോക്കാം.  

### MCP മുഖ്യ ഘടകങ്ങൾ  

MCP **ക്ലയന്റ്-സർവർ വാസ്തുവിഭവം** അടിസ്ഥാനമാക്കി പ്രവർത്തിക്കുന്നു, പ്രധാന ഘടകങ്ങൾ:  

• **ഹോസ്റ്റുകൾ** LLM അപ്ലിക്കേഷനുകളാണ് (ഉദാ: VSCode പോലുള്ള കോഡ് എഡിറ്റർ) MCP സെർവറുമായി ബന്ധപ്പെട്ട് കണക്ഷൻ ആരംഭിക്കുന്നത്.  

• **ക്ലയന്റുകൾ** ഹോസ്റ്റ് അപ്ലിക്കേഷനിലുള്ള ഘടകങ്ങളാണ്, ഒരു സെർവറിനോട് ഒരു-ഓരോ കണക്ഷൻ നിലനിർത്തുന്നു.  

• **സെർവറുകൾ** ചെറിയ പ്രോഗ്രാമുകൾ ആണ്, പ്രത്യേക കഴിവുകൾ പ്രദർശിപ്പിക്കുന്നു.  

പ്രോട്ടോകോളിൽ മൂന്ന് പ്രധാന പ്രിമിറ്റീവുകൾ ഉൾക്കൊള്ളുന്നു, MCP സെർവറിന്റെ കഴിവുകളാണ് ഇവ:  

• **ഉപകരണങ്ങൾ**: AI ഏജന്റ് ഓർമ്മപ്പെടുത്താനാകുന്ന വ്യത്യസ്ത പ്രവർത്തനങ്ങൾ. ഉദാ: കാലാവസ്ഥാ സേവനം "get weather" ഉപകരണം നൽകാം; ഇ-കൊമേഴ്സ് സെർവർ "purchase product". MCP സെർവർ ഓരോ ഉപകരണത്തിന്റെ പേര്, വിവരണം, ഇൻപുട്ട്/ഔട്ട്പുട്ട് സ്‌കീമ ചേർത്ത് അറിയിക്കുന്നു.  

• **ശ്രോതസ്സ്**: MCP സെർവർ നൽകുന്ന വായിക്കാൻ മാത്രം ഉള്ള ഡാറ്റാ/ഡോക്യുമെന്റുകൾ. ക്ലയന്റുകൾ ആവശ്യം വരുമ്പോൾ ഇവ കിട്ടും. ഉദാഹരണങ്ങൾ: ഫയൽ ഉള്ളടക്കം, ഡാറ്റാബേസ് റെക്കോർഡുകൾ, ലോഗ് ഫയലുകൾ. ഇതു ടെക്സ്റ്റോ (കോഡ്, JSON) അല്ലെങ്കിൽ ബിനറി (ചിത്രങ്ങൾ, PDF) ആയിരിക്കാം.  

• **പ്രോംപ്റ്റുകൾ**: മുമ്പേ നിർവചിച്ച ടെംപ്ലേറ്റുകൾ, സങ്കീർണ്ണ ചരിവഴിവുകൾക്ക് ഉപകാരപ്പെടുന്നു.  

### MCP ന്റെ പ്രയോജനങ്ങൾ  

MCP AI ഏജന്റുകൾക്കായി നിരവധി പ്രയോജനങ്ങൾ നൽകുന്നു:  

• **ഡൈനാമിക് ടൂൾ കണ്ടെത്തൽ**: ഏജന്റുകൾ സെർവറിൽ നിന്നുള്ള ലഭ്യമായ ഉപകരണങ്ങളുടെ പട്ടികയും അവയുടെ പ്രവർത്തന വിവരണവും ലഭിക്കുന്നു. ഇത് പരമ്പരാഗത API കളിൽ നിന്നുള്ള വ്യത്യാസമാണ്, അവയിൽ статിക്ക് കോഡിംഗ് ആവശ്യമാണ്. MCP "ഒന്ന് ഇന്റഗ്രേറ്റ് ചെയ്യുക" സമീപനമാണ്, കൂടുതൽ സൗകര്യപ്രദം.  

• **വിവിധ LLM കളിൽ പൊരുത്തം**: MCP വിവിധ LLM കളിലും പ്രവർത്തിക്കുന്നു, മികച്ച പ്രകടനത്തിനായി കോർ മോഡലുകൾ മാറാൻ സൗകര്യമുള്ളത്.  

• **സ്റ്റാൻഡേർഡ് സുരക്ഷ**: MCP ല് സ്റ്റാൻഡേർഡ് ഓതൻറിക്കേഷൻ രീതിയാണ് ഉൾപ്പെടുത്തിയിട്ടുള്ളത്, പുതിയ MCP സെർവറുകൾ കൂട്ടിച്ചേർക്കുമ്പോൾ സ്കാലബിലിറ്റി മെച്ചപ്പെടുത്തുന്നു. ഇതു വിവിധ അപഗ്രഥന API സെറ്റപ്പുകൾക്കായി തരംതിരിച്ച് കീകളും ഓതൻറിക്കേഷൻ മാർഗങ്ങളും കൈകാര്യം ചെയ്യുന്നതിനേക്കാൾ ലളിതമാണ്.  

### MCP ഉദാഹരണം  

![MCP Diagram](../../../translated_images/ml/mcp-diagram.e4ca1cbd551444a1.webp)  

ഒരു ഉപയോക്താവ് MCP പിന്തുണയുള്ള AI അസിസ്റ്റന്റ് ഉപയോഗിച്ച് ഒരു വിമാന ടിക്കറ്റ് ബുക്ക് ചെയ്യാനാഗ്രഹിക്കുന്നുവെന്ന് കരുതുക.  

1. **കണക്ഷൻ**: AI അസിസ്റ്റന്റ് (MCP ക്ലയന്റ്) എയർലൈൻ നൽകുന്ന MCP സെർവറുമായി കണക്ട് ചെയ്യുന്നു.  

2. **ടൂൾ കണ്ടെത്തൽ**: ക്ലയന്റ് MCP സെർവറിന് ചോദിക്കുന്നു, "നിങ്ങൾക്ക് ലഭ്യമായ ടൂളുകൾ എന്തൊക്കെ?" സെർവർ "search flights", "book flights" പോലുള്ള ടൂളുകൾ മറുപടി നൽകുന്നു.  

3. **ടൂൾ വിളിക്കൽ**: ഉപയോക്താവ് AI അസിസ്റ്റന്റിനെ അപേക്ഷിക്കുന്നു, "പോർട്ട്ലാൻഡിൽ നിന്ന് ഹൊണൊളൂളുവിലേക്ക് ഒരു ഫ്ലൈറ്റ് തിരയുക." AI അസിസ്റ്റന്റ് LLM ഉപയോഗിച്ച് "search flights" ഉപകരണം വിളിക്കാൻ തിരിച്ചറിഞ്ഞ് MCP സെർവറിന് ആവശ്യമായ പാരാമീറ്ററുകൾ (മൂലസ്ഥാനം, ലക്ഷ്യം) അയയ്ക്കുന്നു.  

4. **പ്രവർത്തനവും പ്രതികരണവും**: MCP സെർവർ ഏർവേłu് എയർലൈൻയുടെ ഇന്റേണൽ ബുക്കിങ് API യിലൂടെ സന്ദേശം അയയ്ക്കുകയും, വിമാനം സംബന്ധിച്ച വിവരങ്ങൾ (ഉദാ: JSON) സ്വീകരിച്ച ഐ അസിസ്റ്റന്റുമായി പങ്കുവയ്ക്കുകയും ചെയ്യുന്നു.  

5. **കൂടുതൽ ഇടപെടൽ**: AI അസിസ്റ്റന്റ് വിമാന ഓപ്ഷനുകൾ സമ്മാനിക്കുന്നു. ഉപയോക്താവ് ഒരു ഫ്ലൈറ്റ് തിരഞ്ഞെടുക്കുമ്പോൾ, അസിസ്റ്റന്റ് "book flight" ടൂൾ MCP സെർവറിൽ വിളിക്കും, ബുക്കിംഗ് പൂർത്തിയാക്കും.  

## ഏജന്റ് ടു ഏജന്റ് പ്രോട്ടോകോൾ (A2A)  

MCP LLM കളിനെ ഉപകരണങ്ങളുമായി ബന്ധിപ്പിക്കുന്നതിനാണ് ദൃഢമായി, എന്നാൽ **Agent-to-Agent (A2A) പ്രോട്ടോകോൾ** പിന്നീട് പോയി വ്യത്യസ്ത AI ഏജന്റുകൾ തമ്മിൽ ആശയവിനിമയം, സഹകരണവും സൗകര്യമാക്കുന്നു. വിവിധ സംഘടനകളുടെയും പരിസ്ഥിതികളുടെയും ടെക് സ്റ്റാക്കുകളുടെയും AI ഏജന്റുകളെ A2A വഴി സംയോജിപ്പിച്ച് പങ്കിടുന്ന ഒരു കാര്യം പൂർത്തിയാക്കും.  

A2A യുടെ ഘടകങ്ങളും പ്രയോജനങ്ങളും നോക്കി, യാത്രാ അപ്ലിക്കേഷനിൽ എങ്ങനെ പ്രയോഗിക്കാമെന്ന ഉദാഹരണവും കാണും.  

### A2A മുഖ്യ ഘടകങ്ങൾ  

A2A ഏജന്റുകൾ തമ്മിൽ ആശയവിനിമയം സഹകരണം സാദ്ധ്യമാക്കാൻ ശ്രമിക്കുന്നു, ഓരോ പ്രോട്ടോകോൾ ഘടകവും ഇതിൽ സംഭാവന നൽകുന്നു:  

#### ഏജന്റ് കാർഡ്  

MCP സെർവർ ടൂൾ പട്ടിക പങ്കുവെക്കുന്ന പോലെ, ഏജന്റ് കാർഡിനുമുണ്ട്:  
- ഏജന്റിന്റെ പേര്.  
- സാധാരണകളും പൂർത്തിയാക്കുന്ന കാര്യമൂലകവുമായ വിവരങ്ങൾ.  
- മറ്റുള്ള ഏജന്റുകൾക്കോ മനുഷ്യ ഉപയോഗക്കാർക്കോ ഏജന്റ് വിളിക്കാനുള്ള സമയവും കാരണം വ്യക്തമാക്കാൻ സഹായിക്കുന്ന പ്രത്യേക കഴിവുകളുടെ പട്ടികയും വിവരണവും.  
- ഏജന്റിന്റെ നിലവിലെ എൻഡ്‌പോയിന്റ് URL.  
- ഏജന്റിന്റെ പതിപ്പ്, പ്രേഷണ സെർവീസ്, പുഷ് നോട്ടിഫിക്കേഷൻ സാദ്ധ്യതകൾ തുടങ്ങിയ കഴിവുകൾ.  

#### ഏജന്റ് എക്സിക്യൂട്ടർ  

ഉപയോക്തൃ ചാറ്റിന്റെ കോൺടക്സ്റ്റ് റിമോട്ട് ഏജന്റിന് കൈമാറുന്നതിനും ദൂരെയുള്ള ഏജന്റ് അതിനെക്കുറിച്ച് ഉപയോഗം ആസൂത്രണം ചെയ്ത് ആവശ്യകതകളനുസരിച്ച് നടപ്പിലാക്കുന്നതിനും ഏജന്റ് എക്സിക്യൂട്ടർ ബാധ്യതയുള്ളതാണ്. ഒരു A2A സർവറിൽ റിമോട്ട് ഏജന്റ് സ്വന്തം LLM ഉപയോഗിച്ച് വരവിന്റെ അഭ്യർത്ഥന വിശകലനം ചെയ്ത് ആവശ്യമായ നിർദ്ദേശങ്ങൾ നടപ്പിലാക്കും.  

#### ആർട്ടിഫാക്റ്റ്  

റിമോട്ട് ഏജന്റ് അപേക്ഷിച്ച കാര്യം പൂർത്തിയാക്കിയശേഷം, അതിന്റെ ജോലി ഫലമായ ആർട്ടിഫാക്റ്റ് സൃഷ്ടിക്കപ്പെടുന്നു. ആർട്ടിഫാക്റ്റിൽ **ഏജന്റിന്റെ ജോലി ഫലം**, **പൂർ‍ത്തിയാക്കിയ കാര്യത്തിന്റെ വിവരണം**, **പ്രോട്ടോകോൾ വഴി അയക്കുന്ന ടെക്സ്റ്റ് കോൺടക്സ്റ്റ്** അടങ്ങും. ആർട്ടിഫാക്റ്റ് അയച്ച ശേഷമുള്ള ബന്ധം തർക്കിമാറും വരെ അടയ്ക്കപ്പെടും.  

#### ഇവന്റ് ക്യൂ  

**അപ്ഡേറ്റുകളും സന്ദേശങ്ങളും കൈകാര്യം ചെയ്യാനുള്ള ഇടപെടൽ** എത്തിക്കുന്നത് ഇവന്റ് ക്യൂ ഉപയോഗിച്ച് ഉണ്ട്. പ്രൊഡക്ഷൻ സ്റ്റേജിലെ ഏജന്റിക് സിസ്റ്റങ്ങളിലും ഇടപെടലുകൾ പൂർത്തിയാകുന്നതുവരെ ഏജന്റുകൾ തമ്മിൽ കണക്ഷൻ പൂട്ടാതിരിക്കാൻ പ്രധാനമാണ്, പ്രത്യേകിച്ച് ഉയർന്ന സമയമെടുക്കുന്ന കാര്യങ്ങൾക്കു വേണ്ടി.  

### A2A ന്റെ പ്രയോജനങ്ങൾ  

• **ഉന്നത സഹകരണം**: വ്യത്യസ്ത വENDOR കളുടെയും പ്ലാറ്റ്‌ഫോമുകളുടെയും ഏജന്റുകൾ പരസ്പരം ആശയവിനിമയം നടത്താൻ, കോൺടക്സ്റ്റ് പങ്കുവെക്കാൻ, ചേർന്ന് പ്രവർത്തിക്കാൻ സാധിക്കുന്നു, പരസ്പര ബന്ധമില്ലാത്ത സിസ്റ്റങ്ങളിൽ സ്വയം പ്രവർത്തനം എളുപ്പമാക്കുന്നു.  

• **മോഡൽ തിരഞ്ഞെടുപ്പ് സൗകര്യം**: ഓരോ A2A ഏജന്റും തങ്ങളുടെ അഭ്യർത്ഥനകൾ നിറവേറ്റാൻ തങ്ങൾ ഉപയോഗിക്കുന്ന LLM തീരുമാനിക്കാം, MCP യിൽ കാണുന്ന ഏക LLM കണക്ഷനിലാണ് വ്യത്യാസം.  

• **പ്രോട്ടോകോൾക്കുള്ളിൽ ഓതൻറിക്കേഷൻ**: A2A പ്രോട്ടോകോൾക്കുള്ളിൽ തന്നെ ഓതൻറിക്കേഷൻ ഉൾക്കൊള്ളാൻ ക്രമീകരിക്കപ്പെട്ടിട്ടുണ്ട്, ഏജന്റ് ഇടപെടലുകൾക്കായി ശക്തമായ സുരക്ഷാ ഫ്രെയിംവർക്കാണ് ഇത്.  

### A2A ഉദാഹരണം  

![A2A Diagram](../../../translated_images/ml/A2A-Diagram.8666928d648acc26.webp)  

യാത്രാ ബുക്കിങ്ങിന്റെ ഈ ഘട്ടം A2A ഉപയോഗിച്ച് എങ്ങനെ കാര്യങ്ങൾ നടക്കുമെന്ന് നാം വ്യാപിപ്പിക്കാം.  

1. **ഉപയോക്തൃ അഭ്യർത്ഥന മൾട്ടി-ഏജന്റിന്**: ഉപയോക്താവ് "ഹൊണൊളൂളുവിലേക്ക് മുഴുവൻ യാത്ര ആഴ്ചക്കുള്ളിൽ ബുക്ക് ചെയ്യുക, ഫ്ളൈറ്റുകൾ, ഹോട്ട്‌ൽ, വണ്ടി വാടക അടക്കം" എന്ന പ്രാർഥനയോടെ "Travel Agent" A2A ക്ലയന്റ്/ഏജന്റുമായി ഇടപെടുന്നു.  

2. **ട്രാവൽ ഏജന്റിന്റെ ഓർക്കസ്ട്രേഷൻ**: പരമമായ അഭ്യർത്ഥന ട്രാവൽ ഏജന്റ് LLM ഉപയോഗിച്ച് അനാലിസിസ് ചെയ്ത് മറ്റ് നിപുണ ഏജന്റുകളുമായി പ്രവർത്തിക്കേണ്ടതുണ്ടെന്ന് നിർണ്ണയിക്കുന്നു.  

3. **ഏജന്റ് ഇടയിൽ ആശയവിനിമയം**: ട്രാവൽ ഏജന്റ് A2A പ്രോട്ടോകോൾ ഉപയോഗിച്ച് വിവിധ ഏജന്റുകളുമായി ബന്ധപ്പെടുന്നു: "എയർലൈൻ ഏജന്റ്," "ഹോട്ടൽ ഏജന്റ്," "വണ്ടി വാടക ഏജന്റ്" മുതലായവ വ്യത്യസ്ത കമ്പിനികൾ നിർമിച്ചവ.  

4. **കാര്യചട്ടം നിർവ്വഹണം നിയോഗം**: ഓരോ ഏജന്റിനും തങ്ങളുടെ പ്രത്യേക ഭാഗങ്ങൾ നിർവ്വഹിക്കുന്നു (ഉദാ: ഹൊണൊളുവിലേക്ക് ഫ്ളൈറ്റുകൾ കണ്ടെത്തുക, ഹോട്ടൽ ബുക്ക് ചെയ്യുക, വണ്ടി വാടക എടുക്കുക). ഓരോ ഏജന്റും സ്വന്തം LLM കൊടുത്തു സാധ്യമായ ഉപകരണങ്ങൾ (MCP സെർവർ ഉൾപ്പെടെ) ഉപയോഗിക്കുന്നു.  

5. **സംയുക്ത മറുപടി**: എല്ലാ ഏജന്റുകൾ കടന്നുപോയി അവസാനിച്ച ശേഷം, ട്രാവൽ ഏജന്റ് ഫ്ലൈറ്റ് വിശദാംശങ്ങൾ, ഹോട്ടൽ സ്ഥിരീകരണം, വണ്ടി ബുക്കിംഗ് ഉൾപ്പെട്ട സമഗ്രമായ ഉൾക്കാഴ്ച ഒന്നിച്ച് ചാറ്റ് രീതിയിൽ ഉപയോക്താവിന് സമർപ്പിക്കുന്നു.  

## നാച്വറൽ ലാംഗ്വേജ് വെബ് (NLWeb)  

വെബ്സൈറ്റുകൾ പല സമയം ഏറെക്കാലമായി ഉപയോക്താക്കൾക്ക് വിവരങ്ങളും ഡാറ്റയും ലഭിക്കുന്ന മുഖ്യ മാർഗമാണ്.  

NLWeb ന്റെ ഘടകങ്ങൾ, പ്രയോജനങ്ങൾ, യാത്രാ അപ്ലിക്കേഷൻ ഉദാഹരണത്തോടെ എങ്ങനെ പ്രവർത്തിക്കുന്നുവെന്ന് നോക്കാം.  

### NLWeb ഘടകങ്ങൾ  

- **NLWeb അപ്ലിക്കേഷൻ (കോർ സർവീസ് കോഡ്)**: നാച്വറൽ ലാംഗ്വേജ് ചോദ്യങ്ങൾ പ്രോസസ്സു ചെയ്യുന്ന സിസ്റ്റം. പ്ലാറ്റ്‌ഫോമിലെ വിവിധ ഭാഗങ്ങൾ ബന്ധിപ്പിച്ച് മറുപടി നൽകുന്നു. വെബ്സൈറ്റിന്റെ നാച്വറൽ ലാംഗ്വേജ് സൗകര്യങ്ങൾക്ക് പ്രവർത്തിപ്പിക്കുന്ന എഞ്ചിൻ എന്നാണ് കാണുന്നത്.  

- **NLWeb പ്രോട്ടോകോൾ**: വെബ്സൈറ്റ് നാച്വറൽ ലാംഗ്വേജ് ആശയവിനിമയത്തിനുള്ള അടിസ്ഥാന നിയമങ്ങളാണ് ഇത്. JSON ഫോർമാറ്റിൽ (സാധാരണ Schema.org ഉപയോഗിച്ച്) മറുപടി അയയ്ക്കുന്നു. HTML ഡോക്യുമെന്റുകൾ ഓൺലൈനിൽ പങ്കിട്ടതുപോലെ, "AI വെബ്" സൃഷ്ടിക്കുന്നതിനുള്ള ലളിതമായ അടിത്തറയാണ് ലക്ഷ്യം.  

- **MCP സെർവർ (മോഡൽ കോൺടക്സ്റ്റ് പ്രോട്ടോകോൾ എൻഡ്‌പോയിന്റ്)**: ഓരോ NLWeb ക്രമീകരണവും MCP സെർവറായി പ്രവർത്തിക്കുന്നു. ഇത് AI സിസ്റ്റങ്ങൾക്കൊപ്പം ഉപകരണങ്ങൾ ("ask" മേത്തോഡ്) ഡാറ്റ പങ്കുവെക്കാൻ സാധിക്കും. ഇതിലൂടെ വെബ്ไซต์ ഉള്ളടക്കവും കഴിവുകളും AI ഏജന്റുകൾ ഉപയോഗിക്കാവുന്നതായി മാറുന്നു, ഈ സൈറ്റ് വിപുലമായ "ഏജന്റ് ഇക്കോസിസ്റ്റം" ഭാഗമാവുന്നു.  

- **എംബെഡിങ് മോഡലുകൾ**: വെബ്സൈറ്റ് ഉള്ളടക്കം എണ്ണംകൊണ്ട് പ്രതിനിധാനം ചെയ്യുന്ന വെക്‌റ്ററുകളായി മാറ്റാൻ ഉപയോഗിക്കുന്നത്. ഈ വെക്‌റ്ററുകൾ അർത്ഥം സൂക്ഷിക്കുന്ന വിധത്തിൽ കമ്പ്യൂട്ടർ തുല്യമായ ദൃശ്യങ്ങൾ കണ്ടെത്താനും തിരയാനും സഹായിക്കുന്നു. പ്രത്യേക ഡാറ്റാബേസിൽ സൂക്ഷിക്കും, ഉപയോക്താക്കൾ ആവശ്യാനുസരണം embedding മോഡൽ തിരഞ്ഞെടുക്കാം.  

- **വെക്റ്റർ ഡാറ്റാബേസ് (തിരയൽ സംവിധാനം)**: വെബ്സൈറ്റ് ഉള്ളടക്കത്തിന്റെ എംബെഡിങുകൾ ഇതിൽ സൂക്ഷിക്കപ്പെടുന്നു. ആരെങ്കിലും ചോദ്യം ചോദിച്ചാൽ NLWeb വെക്റ്റർ ഡാറ്റാബേസ് പരിശോധിച്ച് ഏറ്റവും പ്രസക്തമായ വിവരങ്ങൾ കണ്ടെത്തി എളുപ്പത്തിൽ മറുപടി നൽകും. ഉത്തരം സമാനത അനുസരിച്ച് റാങ്കുചെയ്യുന്നു. NLWeb Qdrant, Snowflake, Milvus, Azure AI Search, Elasticsearch പോലുള്ള ഡാറ്റാ സ്റ്റോറേജ് സംവിധാനങ്ങൾക്കൊപ്പം പ്രവർത്തിക്കുന്നു.

![NLWeb](../../../translated_images/ml/nlweb-diagram.c1e2390b310e5fe4.webp)  

നമ്മുടെ യാത്രാ ബുക്കിംഗ് വെബ്‌സൈറ്റിന് NLWeb ആണ് ശക്തിയായി പ്രവർത്തിക്കുന്നത് എന്ന് കരുതുക.  

1. **ഡാറ്റ ഇന്ന്ഗെഷൻ**: വെബ്സൈറ്റിലെ ഉൽപ്പന്നമായ ഫ്ളൈറ്റ് പട്ടികകൾ, ഹോട്ടൽ വിവരണങ്ങൾ, ടൂർ പാക്കേജുകൾ Schema.org ഉപയോഗിച്ച് രൂപപ്പെടുത്തി RSS ഫീഡുകൾ വഴി ലോഡ് ചെയ്യുന്നു. NLWeb ടൂളുകൾ ഈ ഘടനാപരമായ ഡാറ്റ സ്വീകരിച്ച് എംബെഡിങുകൾ സൃഷ്ടിച്ച് പ്രാദേശിക അല്ലെങ്കിൽ ദൂരം ഡാറ്റാബേസിൽ സൂക്ഷിക്കുന്നു.  

2. **നാച്വറൽ ലാംഗ്വേജ് ക്വറി (മാനവ്)**: ഉപയോക്താവ് മെയിൻ മെനു തിരയുന്നതിന് പകരം ചാറ്റ് ഇന്റർഫേസ് ഉപയോഗിച്ച് "അടുത്ത ആഴ്ച ഹൊണൊളൂളുവിൽ പൂള്‍ ഉള്ള കുടുംബ സൗഹൃദമായ ഹോട്ടൽ കണ്ടെത്തുക" എന്ന് ടൈപ്പ് ചെയ്യുന്നു.  

3. **NLWeb പ്രോസസ്സിംഗ്**: NLWeb അപ്ലിക്കേഷൻ ഈ ക്വറി സ്വീകരിച്ച് LLM ൽ അയച്ചു അതിന്റെ അർത്ഥം മനസ്സിലാക്കുകയും ഏകകാലത്ത് വെക്റ്റർ ഡാറ്റാബേസ് പരിശോധിച്ച് പ്രസക്തമായ ഹോട്ടൽ ലിസ്റ്റിംഗുകൾ തിരയുകയും ചെയ്യുന്നു.  

4. **ന 정확മായ ഫലങ്ങൾ**: LLM ഡാറ്റാബേസിൽ നിന്നുള്ള തിരച്ചിൽ ഫലങ്ങൾ പാഴ്സുചെയ്ത് "കുടുംബപ്രിയ", "പൂൾ", "ഹൊണൊളൂലു" എന്ന ക്രൈറ്റീരിയ പ്രകാരം മികച്ച പൊരുത്തങ്ങൾ കണ്ടെത്തി, നാച്വറൽ ലാംഗ്വേജ് മറുപടി രൂപപ്പെടുത്തി. മറുപടി വെബ്സൈറ്റിലെ കാറ്റലോഗിലെ യഥാർത്ഥ ഹോട്ടലുകളേ അനുസരിക്കുന്നു, കൃത്രിമ വിവരങ്ങൾ ഒഴിവാക്കുന്നു.  

5. **AI ഏജന്റ് ഇടപെടൽ**: NLWeb MCP സെർവർ ആയതിനാൽ, ബാഹ്യ AI ട്രാവൽ ഏജന്റ് NLWeb സെർവറുമായി കണക്ട് ചെയ്ത് `ask` MCP മേത്തോഡ് ഉപയോഗിച്ച് നേരിട്ടുള്ള വെബ് ക്വറി നല്‍കാം: `ask("ഹൊണൊളൂലു പ്രദേശത്ത് ഹോട്ടൽ ശുപാർശ ചെയ്യുന്ന വെഗൻ സൗഹൃദമുള്ള റസ്റ്റോറന്റുകളുണ്ടോ?")`. NLWeb ഈ ചോദ്യം പ്രോസസ് ചെയ്ത് പരിചയപ്പെട്ട ഡാറ്റാബേസ് ഉപയോഗിച്ച് (പേര്‌സസ് ചെയ്താൽ) സ്ട്രക്ചേചർഡ് JSON മറുപടി നൽകും.
