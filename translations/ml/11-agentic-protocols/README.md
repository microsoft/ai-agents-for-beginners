# ഏജന്റിക് പ്രോട്ടോകോളുകൾ ഉപയോഗിച്ച് (MCP, A2A, NLWeb)

[![Agentic Protocols](../../../translated_images/ml/lesson-11-thumbnail.b6c742949cf1ce2a.webp)](https://youtu.be/X-Dh9R3Opn8)

> _(ഈ പാഠത്തിന്റെ വീഡിയോ കാണാൻ മുകളിൽ ചിത്രത്തിൽ ക്ലിക്ക് ചെയ്യുക)_

എ.ഐ ഏജന്റുകളുടെ ഉപയോഗം വർദ്ധിക്കുന്നതിനൊപ്പം, മാനദണ്ഡമുറപ്പിക്കൽ, സാങ്കേതികഭദ്രത, തുറന്ന നവീകരണത്തെ പിന്തുണയ്ക്കുന്ന പ്രോട്ടോകോളുകളുടെ ആവശ്യമുമാണ് കൂടുന്നത്. ഈ പാഠത്തിൽ, ഈ ആവശ്യം പൂർത്തികരിക്കാൻ നോക്കുന്ന 3 പ്രോട്ടോകോളുകളെ പരിചയപ്പെടാം - മോഡൽ കോൺടെക്സ് പ്രോട്ടോക്കോൾ (MCP), ഏജന്റ് ടു ഏജന്റ് (A2A), നാചുറൽ ലാംഗ്വേജ് വെബ് (NLWeb).

## പരിചയം

ഈ പാഠത്തിൽ, നാം പരിചയപ്പെടുന്നത്:

• എങ്ങനെ **MCP** എഐ ഏജന്റുകൾക്ക് പുറം ഉപകരണങ്ങളും ഡാറ്റയും പ്രാപിച്ച് ഉപയോക്തൃ പ്രവൃത്തി പൂർത്തിയാക്കാൻ സഹായിക്കുന്നു.

• എങ്ങനെ **A2A** വ്യത്യസ്ത എഐ ഏജന്റുകൾക്കു മദ്ധ്യേ സംഭാഷണവും സഹകരണവും പ്രദാനം ചെയ്യുന്നു.

• എങ്ങനെ **NLWeb** ഒരു വെബ്സൈറ്റിലേക്ക് നാചുറൽ ലാംഗ്വേജ് ഇന്റർഫേസുകൾ കൊണ്ടുവന്ന് എഐ ഏജന്റുകൾക്ക് ഉള്ളടക്കം കണ്ടെത്താനും ഇടപഴകാനും സാധ്യമാകുന്നു.

## പഠന ലക്ഷ്യങ്ങൾ

• എഐ ഏജന്റുകളുടെ പശ്ചാത്തലത്തിൽ MCP, A2A, NLWeb എന്നിവയുടെ അടിസ്ഥാന ഉദ്ദേശവും সুফലങ്ങളും **അറിയുക**.

• ഓരോ പ്രോട്ടോകോൾ എങ്ങനെ LLMs, ടൂളുകൾ, മറ്റ് ഏജന്റുകൾ എന്നിവയ്ക്കിടയിൽ ആശയവിനിമയവും ഇടപഴകലും ഹൗസാക്കുന്നു എന്ന് **വ്യക്തീകരിക്കുക**.

• സങ്കീർണമായ ഏജന്റിക് സംവിധാനങ്ങൾ നിർമ്മിക്കാൻ ഓരോ പ്രോട്ടോകോളിൻ്റെ വ്യത്യസ്ത പങ്കുകൾ **തെളിയിക്കുക**.

## മോഡൽ കോൺടെക്സ് പ്രോട്ടോക്കോൾ

**മോഡൽ കോൺടെക്സ് പ്രോട്ടോക്കോൾ (MCP)** ഒരു തുറന്ന മാനദണ്ഡമാണ്, LLMs-നു കോണ്ടെക്സ്‌റ്റ് നൽകാനും ടൂളുകൾ ലഭ്യമാക്കാനുമായി അപ്ലിക്കേഷനുകൾക്ക് സമാനമായി പ്രവർത്തിക്കുന്ന മാർഗ്ഗം നൽകുന്നു. ഇത് എഐ ഏജന്റുകൾക്കു സംയോജിതമായി വിവിധ ഡാറ്റാ ഉറവിടങ്ങളിലേക്കും ടൂളുകളിലേക്കും ബന്ധപ്പെടാൻ സാധിക്കുന്ന "സാർവ്വത്രിക അഡാപ്റ്റർ" ആയി പ്രവർത്തിക്കുന്നു.

MCP-ന്റെ ഘടകങ്ങൾ, നേരിട്ട് API ഉപയോഗത്തിനുള്ള സംവീദാനം, എഐ ഏജന്റുകൾ എങ്ങനെ MCP സർവ്വറിനെ ഉപയോഗിക്കാമെന്ന് ഒരു ഉദാഹരണം നോക്കാം.

### MCP-യുടെ സുപ്രധാന ഘടകങ്ങൾ

MCP ക്ലയന്റ്-സർവർ ഘടനയിൽ പ്രവർത്തിക്കുന്നു,യും സുപ്രധാന ഘടകങ്ങൾ:

• **ഹോസ്റ്റുകൾ** LLM അപ്ലിക്കേഷനുകൾ (ഉദാഹരണത്തിന് VSCode പോലുള്ള കോഡ് എഡിറ്റർ) ആണ്, ഇവ MCP സർവറുമായി ബന്ധം തുടങ്ങിയവ.

• **ക്ലയന്റുകൾ** ഹോസ്റ്റ് അപ്ലിക്കേഷനിലുള്ള ഘടകങ്ങൾ ആണ്, അവ സർവറുകളുമായി ഒറ്റപ്പെടുന്ന ബന്ധങ്ങൾ നിലനിർത്തുന്നു.

• **സർവർಗಳು** എന്തെങ്കിലും പ്രത്യേക ശേഷിപ്പുകളുള്ള ലഘു പ്രോഗ്രാമുകളാണ്.

പ്രോട്ടോകോളിൽ ഉൾപ്പെടുത്തിയ മൂന്ന് സുപ്രധാന പ്രാഥമിക ഘടകങ്ങൾ MCP സർവറിന്റെ ശേഷിപ്പുകളാണ്:

• **ടൂൾസ്**: എഐ ഏജന്റുകൾക്ക് നിർവ്വഹിക്കാൻ കഴിയുന്ന പ്രത്യേക പ്രവർത്തികളോ ഫങ്ഷനുകളോ ആണ്. ഉദാഹരണത്തിന്, ഒരു കാലാവസ്ഥാ സേവനം "കാലാവസ്ഥ വിവരിക്കുക" എന്ന ഒരു ടൂൾ നൽകാം, അല്ലെങ്കിൽ ഒരു ഇ-കൊമേഴ്സ് സർവർ "ഉൽപ്പന്നം വാങ്ങുക" എന്ന ടൂൾ നൽകാം. MCP സർവർ ഓരോ ടൂളിന്റെയും പേര്, വിവരണം, ഇൻപുട്ട്/ഔട്ട്‌പുട്ട് സ്കീമ എന്നിവ അവരുടെ ശേഷിപ്പുകൾ പട്ടികയിൽ പ്രകാശിപ്പിക്കുന്നു.

• **റിസോഴ്‌സുകൾ**: വായിക്കാൻ മാത്രമുള്ള ഡാറ്റാ അല്ലെങ്കിൽ ഡോക്യുമന്റുകൾ MCP സർവർ നൽകുന്നു, ക്ലയന്റുകൾ ആവശ്യത്തിന് ഇത് ലഭിക്കും. ഉദാഹരണങ്ങൾക്ക് ഫയൽ ഉള്ളടക്കം, ഡാറ്റാബേസ് റെക്കാർഡുകൾ, ലോഗ് ഫയലുകൾ. റിസോഴ്‌സുകൾ ടെക്സ്റ്റ് (കോഡ് അല്ലെങ്കിൽ JSON പോലെ) അല്ലെങ്കിൽ ബൈനറി (ചിത്രങ്ങൾ അല്ലെങ്കിൽ PDFകൾ പോലുള്ള) ആയിരിക്കാം.

• **പ്രോമ്പ്റ്റുകൾ**: മുൻകൂട്ടി നിർവ്വചിച്ച ഫോർമാറ്റുകളാണ്, ഇവ കൂടുതൽ സങ്കീർണ പ്രവർത്തനങ്ങൾക്കായി ശുപാർശ ചെയ്ത പ്രോമ്പ്റ്റുകൾ നൽകുന്നു.

### MCP-യുടെ ഗുണങ്ങൾ

MCP എഐ ഏജന്റുകൾക്കായി വലിയ നേട്ടങ്ങൾ നൽകുന്നു:

• **ഡൈനാമിക് ടൂൾ കണ്ടെത്തൽ**: ഏജന്റുകൾ സർവറുകളിൽ നിന്ന് ലഭ്യമായ ടൂളുകളുടെ പട്ടികയും അവ എങ്ങനെ പ്രവർത്തിക്കുന്നതിന്റെ വിവരണവും ഡൈനാമിക്കായി സ്വീകരിക്കാം. പരമ്പരാഗത APIകളുടെ പരിധിയിൽ, ഇൻറഗ്രേഷന് കോഡ് സ്ഥിരമായി മാറ്റേണ്ടിവരും, MCP "ഒന്ന് ഏകീകരിക്കുക" രീതിയാണ്, ഇത് കൂടുതൽ അനുകൂലമാണ്.

• **വിവിധ LLMs-ഉം ഇടയിൽ ഇന്റർഓപ്പറബിലിറ്റി**: MCP വ്യത്യസ്ത LLMs-ഉടൻ പണി നോക്കുന്നു, മികച്ച പ്രകടനത്തിനായി കോർ മോഡലുകൾ മാറ്റാൻ സൗകര്യമുണ്ട്.

• **സ്റ്റാൻഡേർഡ് സുരക്ഷ**: MCP ഒരു മാനദണ്ഡ ആധികാരികീകരണ സംവിധാനം ഉൾക്കൊള്ളുന്നു, കൂടുതൽ MCP സർവറുകൾ എത്തിക്കാൻ സ്കേലബിലിറ്റിയായിരിക്കും. വിവിധ APIകൾക്ക് വേറെ കീകൾ കൈകാര്യം ചെയ്യുന്നതുകാര്യം ഇതിൽനിന്ന് ലളിതമാക്കുന്നു.

### MCP ഉദാഹരണം

![MCP Diagram](../../../translated_images/ml/mcp-diagram.e4ca1cbd551444a1.webp)

ഒരു ഉപയോക്താവ് MCP വഴി പ്രവർത്തിക്കുന്ന എഐ അസിസ്റ്റന്റ് ഉപയോഗിച്ച് പറക്കുന്ന ടിക്കറ്റ് ബുക്ക് ചെയ്യാനുദ്ദേശിക്കുന്നു എന്നു ఊഹിക്കുക.

1. **കണക്ഷൻ**: എഐ അസിസ്റ്റന്റ് (MCP ക്ലയന്റ്) ഒരു MCP സർവർ airline നൽകിയത്ുമായി ബന്ധപ്പെടുന്നു.

2. **ടൂൾ കണ്ടെത്തൽ**: ക്ലയന്റ് airline-ന്റെ MCP സർവറിനെ "എന്തെന്ത് ടൂളുകൾ ഉണ്ട്?" എന്ന് ചോദിക്കുന്നു. സർവർ "search flights" ഉം "book flights" ഉം പോലുള്ള ടൂളുകൾ അറിയിക്കുന്നു.

3. **ടൂൾ വിളിക്കൽ**: പിന്നാലെ ഉപയോക്താവ് എഐ അസിസ്റ്റന്റിന് പറയുന്നു, "കരുത്ത് Portland-ൽ നിന്ന് Honolulu-യിലേക്ക് ഒരു ഹवाईയാത്രക്ക് തിരയൂ." എഐ അസിസ്റ്റന്റ് നിങ്ങളുടെ LLM ഉപയോഗിച്ച് "search flights" ടൂൾ വിളിക്കണമെന്ന് മനസിലാക്കി മുൻകൂട്ടി ആവശ്യമായ പാരാമീറ്ററുകൾ MCP സർവറിന് നൽകുന്നു.

4. **നടത്തലും പ്രതികരണവും**: MCP സർവർ airline-ന്റെ ബുക്കിംഗ് API യെ വിളിക്കുന്നു, ഫ്ലൈറ്റ് വിവരങ്ങൾ (ഉദാ: JSON ഡാറ്റ) സ്വീകരിച്ച് എഐ അസിസ്റ്റന്റിന് അയയ്ക്കുന്നു.

5. **കൂടുതൽ ഇടപെടൽ**: എഐ അസിസ്റ്റന്റ് പറക്കുന്ന ഓപ്‌ഷനുകൾ ഉപയോക്താവിന് പ്രദർശിപ്പിക്കുന്നു. ഉപയോക്താവ് ഒരു ഫ്ലൈറ്റ് തിരഞ്ഞെടുക്കുമ്പോൾ "book flight" ടൂൾ MCP സർവറിൽ ഉപയോഗിച്ച് ബുക്കിംഗ് പൂർത്തീകരിക്കുന്നു.

## ഏജന്റ്-ടു-ഏജന്റ് പ്രോട്ടോക്കോൾ (A2A)

MCP LLMs-നെ ടൂളുകളുമായി ബന്ധിപ്പിക്കാനാണ് കേന്ദ്രീകരിക്കുന്നത്, എന്നാൽ **അജന്റ്-ടു-അജന്റ് (A2A) പ്രോട്ടോക്കോൾ** വ്യത്യസ്ത എഐ ഏജന്റുകൾക്ക് ഇടയിൽ ആശയവിനിമയം, സഹകരണം സാധ്യമാക്കുന്നു. A2A വ്യത്യസ്ത സ്ഥാപനങ്ങളിലെയും സാങ്കേതിക ഘടനകളിലെയും എഐ ഏജന്റുകളെ പങ്കിടുന്ന ദാഹപ്രവൃത്തി പൂർത്തിയാക്കാൻ കൂട്ടിയിടിക്കുന്നു.

A2A-യുടെ ഘടകങ്ങളും ഗുണങ്ങളും, യാത്രാ ആപ്പ് ഉപയോഗിച്ച് എങ്ങനെ പ്രയോഗിക്കാമെന്ന് ഒരു ഉദാഹരണവും നാം പരിശോധിക്കും.

### A2Aയുടെ മുഖ്യ ഘടകങ്ങൾ

A2A ഏജന്റുകൾക്കിടയിൽ ആശയവിനിമയം സാധ്യമാക്കുകയും ഉപയോക്തൃ ഉപപ്രവൃത്തി പൂർത്തീകരിക്കാൻ കൂട്ടായി പ്രവർത്തിക്കുകയും ചെയ്യുകയാണ്. പ്രോട്ടോക്കോൾ ഘടകങ്ങൾ ഇതിനു സഹായിക്കുന്നു:

#### ഏജന്റ് കാർഡ്

MCP സർവർ ടൂളുകളുടെ പട്ടിക പങ്കിടുന്നതുപോലെ, ഏജന്റ് കാർഡിൽ:
- ഏജന്റിന്റെ പേര്.
- അത് നിർവഹിക്കുന്ന പൊതുവായ പ്രവൃത്തികളുടെ **വിവരണം**.
- മറ്റ് ഏജന്റുകൾക്കും (മനുഷ്യ ഉപയോക്താക്കൾക്കും) ഈ ഏജന്റിനെ എപ്പോൾ, എന്തിനു വിളിക്കണമെന്ന് മനസിലാക്കാൻ സഹായിക്കുന്ന **നിബന്ധിച്ച കഴിവുകളുടെ പട്ടിക**.
- ഏജന്റിന്റെ നിലവിലെ **എൻഡ്‌പോയിന്റ് URL**.
- **അവതരണം** എന്നും **ശേഷിപ്പുകൾ** (example: സ്ട്രീമിംഗ് പ്രതികരണങ്ങൾ, പുഷ് നോട്ടിഫിക്കേഷനുകൾ).

#### ഏജന്റ് എക്സിക്യൂട്ടർ

ഏജന്റ് എക്സിക്യൂട്ടർ **ഉപയോക്തൃ ചാറ്റിന്റെ കോൺടെക്സ്‌റ്റ് റിമോട്ട് ഏജന്റിലേക്ക് കൈമാറുന്നതിന്** ഉത്തരവാദിയാണ്. റിമോട്ട് ഏജന്റ് ഭേദപ്പെട്ട നിർമ്മിത LLM ഉപയോഗിച്ച് ഈ അഭ്യർത്ഥനകൾ അറിഞ്ഞ് അതിന്റെ ഉള്ളിലുള്ള ടൂളുകൾ ഉപയോഗിച്ച് പ്രവർത്തനങ്ങൾ നിർവ്വഹിക്കുന്നു.

#### ആർട്ടിഫാക്ട്

റിമോട്ട് ഏജന്റ് അഭ്യർത്ഥിച്ച പ്രവർത്തി പൂർത്തിയാക്കിയാൽ, അതിന്റെ ഫലം ഒരു ആർട്ടിഫാക്ടായി സൃഷ്ടിക്കുന്നു.  ആർട്ടിഫാക്ട് **ഏജന്റിൻറെ പ്രവർത്തിയുടെ ഫലവും**, **പൂരിപ്പിച്ച കാര്യത്തിന്റെ വിവരണവും**, ഈ പ്രോട്ടോക്കോൾ വഴി അയക്കുന്ന **ടെക്സ്റ്റ് കോൺടെക്സ്‌റ്റും** അടങ്ങിയിരിക്കുന്നു. ആർട്ടിഫാക്ട് അയച്ചത്ക്ക് ശേഷം റിമോട്ട് ഏജന്റുമായി പണിയാമ പുതുക്കുന്നത് വരെ കണക്ഷൻ അടയ്ക്കുന്നു.

#### ഇവന്റ് ക്യൂ

ഈ ഘടകം **അപ്‌ഡേറ്റുകളും സന്ദേശങ്ങളും കൈകാര്യം ചെയ്യുന്നതിനും കൈമാറുന്നതിനും** ഉപയോഗിക്കപ്പെടുന്നു. ഏജന്റുകളിടെയുള്ള കണക്ഷൻ പ്രവർത്തി പൂർത്തിയാകുന്നതിനു മുന്നേ അവസാനിക്കാതെ നിലനിർത്താൻ ഇത് നിർണായകമാണ്, പ്രത്യേകിച്ച് ദീർഘകാലം ചെലവാകുന്ന പ്രവൃത്തി സമയങ്ങളിൽ.

### A2A ഗുണങ്ങൾ

• **പങ്കുവച്ചെടുക്കൽ മെച്ചപ്പെടുത്തൽ**: വ്യത്യസ്ത വിൽപ്പനക്കാരുടെയും പ്ലാറ്റ്ഫോമുകളുടെയും ഏജന്റുകൾ പരസ്പരം ആശയവിനിമയം നടത്തുകയും കോൺടെക്റ്റ് പങ്കിടുകയും ഒരുമിച്ച് പ്രവർത്തിക്കുകയും ചെയ്യുന്നു, വ്യത്യസ്തമായ പാരമ്പര്യേണ വേർപിരിഞ്ഞ സംവിധാനങ്ങൾക്കിടയിൽ ഏകോപിത പ്രവർത്തനം സാദ്ധ്യമാക്കുന്നു.

• **മോഡൽ തിരഞ്ഞെടുപ്പിന്റെ സൗകര്യം**: ഓരോ A2A ഏജന്റും അവന്റെ അഭ്യർത്ഥനകൾ സേവിക്കാനായി ഏത് LLM ഉപയോഗിക്കണമെന്ന് തിരഞ്ഞടുക്കാൻ കഴിയും, ചില MCP സാഹചര്യങ്ങളിലെ ഒറ്റ LLM ബന്ധം പോലെയുള്ള നിയന്ത്രണമില്ലാതെ.

• **സർവസ്വതയും ആധികാരികവുമെന്നുള്ള സുരക്ഷ**: A2A പ്രോട്ടോക്കോളിൽ നേരിട്ട് ആധികാരികവൽക്കരണം ഉൾപ്പെടുത്തിയിട്ടുണ്ട്, ഏജന്റ് ഇടപെടലുകൾക്ക് ഉത്തമ സുരക്ഷാ ചട്ടം നൽകുന്നു.

### A2A ഉദാഹരണം

![A2A Diagram](../../../translated_images/ml/A2A-Diagram.8666928d648acc26.webp)

നമ്മുടെ യാത്രാ ബുക്കിംഗ് ദൃശ്യസംവിധാനം A2A ഉപയോഗിച്ച് കൂട്ടിച്ചേർക്കാം.

1. **ഉപയോക്തൃ അഭ്യർത്ഥനം മൾട്ടി-ഏജന്റിനോട്**: ഉപയോക്താവ് "ട്രാവൽ ഏജന്റ്" A2A ക്ലയന്റ്/എജന്റിനോട്, "അടുത്ത ആഴ്ച ഹൊനൊളുളുവിലേക്കുള്ള മുഴുവൻ യാത്രയും (ഫ്ലൈറ്റ്, ഹോട്ടൽ, കാറിന്റെ വാടക) ബുക്ക് ചെയ്യുക" എന്നു പറയുന്നു.

2. **ട്രാവൽ ഏജന്റ് ഓർക്കസ്ട്രേഷൻ**: ഈ സങ്കീർണ അഭ്യർത്ഥനം ട്രാവൽ ഏജന്റ് സ്വീകരിക്കുന്നു. നിശ്ചയിച്ച് അതിന്റെ LLM ഉപയോഗിച്ച് ഏജന്റുകളെ തിരിച്ചറിയുന്നു.

3. **ഏജന്റ് ഇട സംവാദം**: ട്രാവൽ ഏജന്റ് A2A പ്രോട്ടോക്കോൾ ഉപയോഗിച്ച് airline ഏജന്റ്, ഹോട്ടൽ ഏജന്റ്, കാർ വാടക ഏജന്റ് തുടങ്ങി downstream-ലെ ഏജന്റുകളുമായി ബന്ധപ്പെടുന്നു.

4. **പ്രവൃത്തി നിർവ്വഹണം ഏജന്റുകൾക്കുവിട്ടു**: ഈ പ്രത്യേക ഏജന്റുകൾ, തങ്ങളുടെ സ്വതന്ത്ര LLMs ഉപയോഗിച്ച്, MCP സർവറുകൾ പോലുള്ള അവരുടെ ടൂളുകൾ ഉപയോഗിച്ച് അപേക്ഷിത ഭാഗങ്ങൾ നിർവ്വഹിക്കുന്നു.

5. **സംയോജിത പ്രതികരണം**: എല്ലാ downstream ഏജന്റുകളും പ്രവർത്തി പൂർത്തിയാക്കിയാൽ, ട്രാവൽ ഏജന്റ് ഫ്ലൈറ്റ് വിവരങ്ങൾ, ഹോട്ടൽ സ്ഥിരീകരണം, കാറിന്റെ വാടക ബുക്കിംഗ് എന്നിവ ചേർത്ത് chats-styled comprehensive ബാധ്യതയായി ഉപയോക്താവിന് തിരിച്ചു നൽകുന്നു.

## നാചുറൽ ലാംഗ്വേജ് വെബ് (NLWeb)

വെബ്സൈറ്റുകൾ ഒരുലംഘണ ഡാറ്റയും വിവരങ്ങളും ഇന്റർനെറ്റിലൂടെ ഉപയോക്താക്കൾക്ക് ലഭ്യമാക്കുന്നക്ക് പ്രധാന മാർഗ്ഗമായിരിക്കുന്നു.

NLWeb ന്റെ ഘടകങ്ങൾ, ഗുണങ്ങൾ, 그리고 നമ്മുടെ യാത്രാ ആപ്ലിക്കേഷനിലൂടെ NLWeb എങ്ങനെ പ്രവർത്തിക്കുന്നു എന്നത് വിശദീകരിക്കുന്നു.

### NLWeb ഘടകങ്ങൾ

- **NLWeb അപ്ലിക്കേഷൻ (മൂൾസേവന കോഡ്)**: നാചുറൽ ലാംഗ്വേജ് ചോദ്യങ്ങൾ പ്രോസസ്സിങ്ങ് ചെയ്യുന്ന സിസ്റ്റം. ഇതാണ് വെബ്സൈറ്റിലെ നാചുറൽ ലാംഗ്വേജ് സവിശേഷതകൾക്ക് ശക്തി നൽകുന്ന എഞ്ചിൻ.

- **NLWeb പ്രോട്ടോക്കോൾ**: വെബ്സൈറ്റുമായി നാചുറൽ ലാംഗ്വേജ് ഇടപെടലിനു ആയ്രിയമായ നിയമങ്ങളുടെ ഒരു അടിസ്ഥാനം. പ്രശ്നങ്ങൾക്ക് സ്വരൂപിക്കുന്ന മറുപടികൾ JSON (Schema.org ഉപയോഗിച്ച്) രൂപത്തിൽ നൽകുന്നു. HTML നൽകുന്ന ഡോക്യുമെന്റ് പങ്കുവെക്കൽ പോലെയാണ് AI വെബ് സൃഷ്ടിക്കുന്നതിനുള്ള അടിസ്ഥാന നിർമാണം.

- **MCP സർവർ (Model Context Protocol Endpoint)**: ഓരോ NLWeb സജ്ജീകരണവും തുറന്ന MCP സർവർ ആയി പ്രവർത്തിക്കുന്നു. അതിലൂടെ മറ്റ് എഐ സിസ്റ്റങ്ങളുമായി ടൂളുകളും ഡാറ്റയും പങ്കിടാൻ കഴിയും. വെബ്സൈറ്റ് ഉള്ളടക്കവും കഴിവുകളും എഐ ഏജന്റുകൾക്ക് ഉപയോഗ്യവുമാകുന്നു, വെബ്സൈറ്റ് "ഏജന്റ് എക്കോസിസ്റ്റം" ഭാഗമാകുന്നു.

- **എംബെഡിങ് മോഡലുകൾ**: വെബ്സൈറ്റ് ഉള്ളടക്കം സംഖ്യാത്മക പ്രാതിനിധ്യങ്ങളായി (എംബെഡിംഗ്സ് എന്നത്) മാറ്റാൻ ഉപയോഗിക്കുന്ന മോഡലുകൾ. ഈ പ്രാതിനിധ്യങ്ങൾ കമ്പ്യൂട്ടറുകൾക്കായി ഉപേക്ഷിക്കാനും തിരയാനുമുള്ള അർത്ഥം ഉൾക്കൊള്ളുന്നു. ഇവ പ്രത്യേക ഡാറ്റാബേസിൽ സൂക്ഷിക്കപ്പെടുന്നു, ഉപയോക്താക്കൾ ഇഷ്ടമുള്ള എംബെഡിങ് മോഡലിൽ തിരഞ്ഞെടുക്കാം.

- **വെക്റ്റർ ഡാറ്റാബേസ് (തിരവലി സംവിധാനം)**: വെബ്സൈറ്റ് ഉള്ളടക്കത്തിന്റെ എംബെഡിംഗുകളുടെ സെറുകാണിപ്പ് സംഭരിക്കുന്നത്. ആരെങ്കിലും ചോദിക്കുമ്പോൾ NLWeb ഈ ഡാറ്റാബേസ് പരിശോധിച്ച് ഏറ്റവും പ്രസക്തമായത് കണ്ടെത്തുന്നു, സമാനതയുടെ അടിസ്ഥാനത്തിൽ ഉത്തമങ്ങൾ റാങ്ക് ചെയ്യുന്നു. NLWeb Qdrant, Snowflake, Milvus, Azure AI Search, Elasticsearch പോലുള്ള വിവിധ വെക്റ്റർ സ്റ്റോറേജ് സിസ്റ്റങ്ങളുമായി സഖ്യമാണ്.

### NLWeb ഉദാഹരണമായി

![NLWeb](../../../translated_images/ml/nlweb-diagram.c1e2390b310e5fe4.webp)

നമ്മുടെ യാത്രാ ബുക്കിംഗ് വെബ്സൈറ്റ് വീണ്ടും നോക്കാം, എന്നാൽ ഈ പ്രാവശ്യം NLWeb ഉപയോഗിക്കുന്നു.

1. **ഡാറ്റ ഇൻജെക്ഷൻ**: യാത്രാ വെബ്സൈറ്റിലെ നിലവിലുള്ള ഉൽപ്പന്ന കാറ്റലോഗുകൾ (ഫ്ലൈറ്റ് ലിസ്റ്റിംഗുകൾ, ഹോട്ടൽ വിവരണങ്ങൾ, ടൂർ പാക്കേജുകൾ) Schema.org ഉപയോഗിച്ച് ഫോർമാറ്റ് ചെയ്യപ്പെടുന്നു അല്ലെങ്കിൽ RSS ഫീഡുകൾ വഴി ലോക് ചെയ്യപ്പെടുന്നു. NLWeb ടൂളുകൾ ഈ രൂപപ്പെടുത്തിയ ഡാറ്റയിൽ നിന്നു എംബെഡിംഗുകൾ സൃഷ്ടിച്ച് ലോക്കൽ അല്ലെങ്കിൽ റിമോട്ട് വെക്റ്റർ ഡാറ്റാബേസിൽ സൂക്ഷിക്കുന്നു.

2. **നാചുറൽ ലാംഗ്വേജ് ക്വറി (മനുഷ്യൻ)**: ഉപയോക്താവ് വെബ്സൈറ്റ് സന്ദർശിച്ച്, മെനുക്കളിലും തിരയാതെ, ചാറ്റ് ഇന്റർഫേസിൽ "അടുത്ത ആഴ്ച ഹൊനൊളുളുവിൽ ഓരോ കുടുംബത്തിനൊപ്പം കഴിയാവുന്ന ഹോട്ടൽ പൂളോടുകൂടെ കണ്ടെത്തുക" എന്ന് ടൈപ്പ് ചെയ്യുന്നു.

3. **NLWeb പ്രോസസ്സ്**: NLWeb അപ്ലിക്കേഷൻ ഈ ചോദ്യം സ്വീകരിക്കുന്നു. അത് എളുപ്പത്തിൽ LLM-നു അയച്ച് മനസ്സിലാക്കുന്നു, ഒരേസമയം വെക്റ്റർ ഡാറ്റാബേസിൽ ഹോട്ടൽ ലിസ്റ്റിംഗുകൾ വീതം തിരയുന്നു.

4. **നിസ്സാരമായ ഫലങ്ങൾ**: LLM തിരഞ്ഞെടുത്ത ഫലങ്ങൾ വിശകലനം ചെയ്യുകയും "കുടുംബാനുകൂല", "പൂൾ", "ഹൊനൊളൂ" എന്നിവകേന്ദ്രീകരിച്ച് ഉത്തമ മാച്ചുകൾ കണ്ടെത്തുകയും നാചുറൽ ലാംഗ്വേജ് മറുപടി ഒരുക്കുകയും ചെയ്യുന്നു. മറുപടി വെബ്സൈറ്റിലൂടെ ഉണ്ടായ ഹോട്ടലുകളെ സംബന്ധിച്ചുള്ള യാഥാർത്ഥ്യവിവരങ്ങളോടെയാണ്, പൃഥകമായ വിവരങ്ങളല്ല.

5. **എഐ ഏജന്റ് ഇടപെടൽ**: NLWeb MCP സർവറായതിനാൽ, ഒരു ബാഹ്യ എഐ ട്രാവൽ ഏജന്റും ഈ വെബ്സൈറ്റുമായി ബന്ധപ്പെടാനും 'ask' MCP മേത്തഡ് വഴി നേരിട്ട് ചോദിക്കാനും കഴിയും: `ask("Are there any vegan-friendly restaurants in the Honolulu area recommended by the hotel?")`. NLWeb സ്‌റ്റാൻഡേർഡ് JSON മറുപടി എല്ലാ ലഭ്യമാക്കിയ സന്ദർശ്യങ്ങൾ ഉൾപ്പെടുത്തിയാണ് നൽകുന്നത്.
