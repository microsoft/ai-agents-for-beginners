# ⚡ Samtidiga agentarbetsflöden med Azure OpenAI (Responses API) (.NET)

## 📋 Handledning för högpresterande parallell bearbetning

## 💻 Köra koden

Den kompletta implementeringen finns i `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Denna fil visar ett **Fan-Out/Fan-In-samtidigt arbetsflöde** för reseplanering:

### 🏗️ **Arbetsflödesarkitektur**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Viktiga komponenter:**

1. **ConcurrentStartExecutor**: Sänder användarförfrågan till alla agenter samtidigt
2. **Researcher Agent**: Analyserar destinationer och attraktioner parallellt
3. **Planner Agent**: Skapar detaljerade reseplaner parallellt
4. **ConcurrentAggregationExecutor**: Samlar in och slår ihop resultat från båda agenterna

### 🎯 **Fan-Out/Fan-In-mönster**

Detta arbetsflöde visar det klassiska **Fan-Out/Fan-In**-mönstret:
- **Fan-Out**: Ett inmatningsmeddelande sänds till flera agenter samtidigt
- **Samtidig bearbetning**: Flera agenter arbetar parallellt med samma uppgift
- **Fan-In**: Resultat från alla agenter samlas in och aggregeras till en enda utdata

### 📝 Förväntad utdata

Arbetsflödet kommer att:
1. **Sända förfrågan**: Skicka "Planera en resa till Seattle i december" till båda agenterna
2. **Samtidig bearbetning**: Båda agenterna arbetar samtidigt:

3. **Aggregering**: Kombinera båda svaren till en omfattande utdata

### 🔍 Förstå anpassade exekutorer

**ConcurrentStartExecutor:**
- Implementerar `IMessageHandler<string>` för att ta emot strängindata
- Sänder meddelanden till alla anslutna agenter
- Skickar `TurnToken` för att trigga samtidig bearbetning

**ConcurrentAggregationExecutor:**
- Implementerar `IMessageHandler<ChatMessage>` för att ta emot agenters svar
- Samlar meddelanden på trådsäkert sätt
- Aggregerar när alla förväntade svar anlänt
- Returnerar slutlig utdata med `context.YieldOutputAsync()`

### ⚡ Prestandafördelar

**Samtidig jämfört med sekventiell:**
- Sekventiell: Agent1 (30s) → Agent2 (30s) = **60 sekunder totalt**
- Samtidig: Agent1 (30s) || Agent2 (30s) = **30 sekunder totalt**

**Genomströmningsförbättring**: Upp till N× snabbare för N samtidiga agenter (beroende på arbetsbelastning och resurser)

### 🛡️ Felhantering

Arbetsflödet hanterar individuella agentfel på ett smidigt sätt:
- Om en agent misslyckas fortsätter de andra bearbetningen
- Aggregatorn kan implementera timeout-logik
- Delresultat kan returneras vid behov
