## 💻 Köra koden

Den fullständiga implementeringen finns i `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Denna fil demonstrerar ett **Fan-Out/Fan-In-samtidigt arbetsflöde** för reseplanering:

### 🏗️ **Arbetsflödesarkitektur**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Nyckelkomponenter:**

1. **ConcurrentStartExecutor**: Sänder användarförfrågan till alla agenter samtidigt
2. **Researcher Agent**: Analyserar destinationer och sevärdheter parallellt
3. **Planner Agent**: Skapar detaljerade reseplaner parallellt
4. **ConcurrentAggregationExecutor**: Samlar in och slår ihop resultat från båda agenterna

### 🎯 **Fan-Out/Fan-In-mönster**

Detta arbetsflöde visar det klassiska **Fan-Out/Fan-In**-mönstret:
- **Fan-Out**: Ett indata-meddelande sänds ut till flera agenter samtidigt
- **Parallellbearbetning**: Flera agenter arbetar parallellt med samma uppgift
- **Fan-In**: Resultat från alla agenter samlas in och aggregeras till en enda utdata

### 📝 Förväntad utdata

Arbetsflödet kommer att:
1. **Sända förfrågan**: Skicka "Planera en resa till Seattle i december" till båda agenterna
2. **Parallellbearbetning**: Båda agenter arbetar samtidigt:
   - Researcher identifierar sevärdheter och detaljer
   - Planner skapar resplan och logistik
3. **Aggregering**: Kombinera båda svaren till en komplett utdata
4. **Visa resultat**: Visa den sammanslagna reseplanen med all information

### 🔍 Förståelse av anpassade exekverare

**ConcurrentStartExecutor:**
- Implementerar `IMessageHandler<string>` för att ta emot strängindata
- Sänder ut meddelanden till alla anslutna agenter
- Skickar `TurnToken` för att trigga parallell bearbetning

**ConcurrentAggregationExecutor:**
- Implementerar `IMessageHandler<ChatMessage>` för att ta emot agenters svar
- Samlar meddelanden trådsäkert
- Aggregerar när alla förväntade svar har kommit
- Returnerar slutgiltigt resultat med `context.YieldOutputAsync()`

### ⚡ Prestandafördelar

**Parallellt vs sekventiellt:**
- Sekventiellt: Agent1 (30s) → Agent2 (30s) = **60 sekunder totalt**
- Parallellt: Agent1 (30s) || Agent2 (30s) = **30 sekunder totalt**

**Genomströmningsförbättring**: Upp till N× snabbare för N samtidiga agenter (beroende på arbetsbelastning och resurser)

### 🛡️ Felhantering

Arbetsflödet hanterar individuella agentfel smidigt:
- Om en agent misslyckas fortsätter övriga bearbeta
- Aggregatorn kan ha tidsgränslogik
- Delresultat kan returneras vid behov
