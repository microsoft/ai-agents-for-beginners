## 💻 Köra koden

Den fullständiga implementeringen finns i `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Den här filen visar ett **Fan-Out/Fan-In parallellt arbetsflöde** för reseplanering:

### 🏗️ **Arbetsflödesarkitektur**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Nyckelkomponenter:**

1. **ConcurrentStartExecutor**: Sänder användarförfrågan till alla agenter samtidigt
2. **Researcher Agent**: Analyserar destinationer och attraktioner parallellt
3. **Planner Agent**: Skapar detaljerade reseplaner parallellt
4. **ConcurrentAggregationExecutor**: Samlar in och slår ihop resultat från båda agenterna

### 🎯 **Fan-Out/Fan-In-mönstret**

Detta arbetsflöde visar det klassiska **Fan-Out/Fan-In**-mönstret:
- **Fan-Out**: Ett inmatningsmeddelande sänds ut till flera agenter samtidigt
- **Parallell bearbetning**: Flera agenter arbetar parallellt med samma uppgift
- **Fan-In**: Resultat från alla agenter samlas in och aggregeras till en enda utdata

Arbetsflödet kommer att:
1. **Sända förfrågan**: Skicka "Planera en resa till Seattle i december" till båda agenterna

### 🔍 Förstå anpassade utförare

**ConcurrentStartExecutor:**
- Implementerar `IMessageHandler<string>` för att ta emot stränginput
- Sänder ut meddelanden till alla anslutna agenter
- Skickar `TurnToken` för att trigga parallell bearbetning

**ConcurrentAggregationExecutor:**
- Implementerar `IMessageHandler<ChatMessage>` för att ta emot agentrespons
- Samlar meddelanden trådsäkert
- Aggregerar när alla förväntade svar kommit
- Returnerar slutlig utdata via `context.YieldOutputAsync()`

### ⚡ Prestandafördelar

**Parallellt vs Sekventiellt:**
- Sekventiellt: Agent1 (30s) → Agent2 (30s) = **60 sekunder totalt**
- Parallellt: Agent1 (30s) || Agent2 (30s) = **30 sekunder totalt**

**Genomströmningsförbättring**: Upp till N× snabbare för N parallella agenter (beroende på arbetsbelastning och resurser)

### 🛡️ Felhantering

Arbetsflödet hanterar individuella agentfel smidigt:
- Om en agent misslyckas fortsätter de andra bearbetningen
- Aggregator kan implementera timeout-logik
- Delresultat kan returneras vid behov
