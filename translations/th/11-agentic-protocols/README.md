# การใช้เอเจนต์โปรโตคอล (MCP, A2A และ NLWeb)

[![Agentic Protocols](../../../translated_images/th/lesson-11-thumbnail.b6c742949cf1ce2a.webp)](https://youtu.be/X-Dh9R3Opn8)

> _(คลิกที่ภาพด้านบนเพื่อดูวิดีโอบทเรียนนี้)_

ขณะที่การใช้เอเจนต์ AI เพิ่มมากขึ้น ความต้องการโปรโตคอลที่รับประกันมาตรฐาน ความปลอดภัย และสนับสนุนการนวัตกรรมแบบเปิดก็เพิ่มขึ้นตาม ในบทเรียนนี้ เราจะครอบคลุมโปรโตคอล 3 ตัวที่ต้องการตอบสนองความต้องการนี้ - Model Context Protocol (MCP), Agent to Agent (A2A) และ Natural Language Web (NLWeb)

## บทนำ

ในบทเรียนนี้ เราจะครอบคลุม:

• วิธีที่ **MCP** อนุญาตให้เอเจนต์ AI เข้าถึงเครื่องมือและข้อมูลภายนอกเพื่อดำเนินงานของผู้ใช้ให้สำเร็จ

• วิธีที่ **A2A** เปิดโอกาสให้การสื่อสารและความร่วมมือระหว่างเอเจนต์ AI ต่าง ๆ

• วิธีที่ **NLWeb** นำอินเทอร์เฟซภาษาธรรมชาติมายังเว็บไซต์ใด ๆ เพื่อให้เอเจนต์ AI สามารถค้นหาและโต้ตอบกับเนื้อหาได้

## เป้าหมายการเรียนรู้

• **ระบุ** วัตถุประสงค์หลักและประโยชน์ของ MCP, A2A และ NLWeb ในบริบทของเอเจนต์ AI

• **อธิบาย** วิธีการที่แต่ละโปรโตคอลช่วยในการสื่อสารและการโต้ตอบระหว่าง LLMs, เครื่องมือ และเอเจนต์อื่น ๆ

• **รับรู้** บทบาทที่แตกต่างของแต่ละโปรโตคอลในการสร้างระบบเอเจนต์ที่ซับซ้อน

## Model Context Protocol

**Model Context Protocol (MCP)** เป็นมาตรฐานเปิดที่จัดให้มีวิธีการมาตรฐานสำหรับแอปพลิเคชันในการจัดเตรียมบริบทและเครื่องมือให้กับ LLMs ซึ่งช่วยให้เกิด "อะแดปเตอร์สากล" สำหรับแหล่งข้อมูลและเครื่องมือที่เอเจนต์ AI สามารถเชื่อมต่อได้อย่างสม่ำเสมอ

มาดูองค์ประกอบของ MCP, ประโยชน์เมื่อเทียบกับการใช้ API โดยตรง และตัวอย่างวิธีที่เอเจนต์ AI อาจใช้เซิร์ฟเวอร์ MCP

### องค์ประกอบหลักของ MCP

MCP ทำงานบน **สถาปัตยกรรมไคลเอนต์-เซิร์ฟเวอร์** และองค์ประกอบหลักได้แก่:

• **โฮสต์** คือแอปพลิเคชัน LLM (เช่น โปรแกรมแก้ไขโค้ดอย่าง VSCode) ที่เริ่มต้นการเชื่อมต่อกับเซิร์ฟเวอร์ MCP

• **ไคลเอนต์** คือองค์ประกอบภายในแอปโฮสต์ที่รักษาการเชื่อมต่อแบบตัวต่อตัวกับเซิร์ฟเวอร์

• **เซิร์ฟเวอร์** คือโปรแกรมน้ำหนักเบาที่เปิดเผยความสามารถเฉพาะเจาะจง

ในโปรโตคอลรวมถึงสามพื้นฐานหลักซึ่งเป็นความสามารถของเซิร์ฟเวอร์ MCP:

• **เครื่องมือ**: เป็นการกระทำหรือฟังก์ชันแยกส่วนที่เอเจนต์ AI สามารถเรียกใช้เพื่อดำเนินการ เช่น บริการสภาพอากาศอาจเปิดเผยเครื่องมือ "ดูสภาพอากาศ" หรือเซิร์ฟเวอร์อีคอมเมิร์ซอาจเปิดเผยเครื่องมือ "ซื้อสินค้า" เซิร์ฟเวอร์ MCP โฆษณาชื่อเครื่องมือ คำอธิบาย และสคีมาอินพุต/เอาต์พุตในรายการความสามารถ

• **ทรัพยากร**: คือรายการข้อมูลหรือเอกสารที่อ่านได้อย่างเดียวซึ่งเซิร์ฟเวอร์ MCP สามารถให้บริการ และไคลเอนต์สามารถเรียกดูตามความต้องการ ตัวอย่างเช่น เนื้อหาไฟล์, ระเบียนฐานข้อมูล หรือไฟล์บันทึก ทรัพยากรอาจเป็นข้อความ (เช่น โค้ดหรือ JSON) หรือไบนารี (เช่น รูปภาพหรือ PDF)

• **พรอมต์**: คือแม่แบบที่กำหนดไว้ล่วงหน้าที่ให้คำแนะนำพรอมต์เพื่อสนับสนุนเวิร์กโฟลว์ที่ซับซ้อนขึ้น

### ประโยชน์ของ MCP

MCP มอบข้อได้เปรียบสำคัญสำหรับเอเจนต์ AI:

• **ค้นพบเครื่องมือแบบไดนามิก**: เอเจนต์สามารถรับรายการเครื่องมือที่มีจากเซิร์ฟเวอร์พร้อมคำอธิบายการทำงานต่าง ๆ แตกต่างจาก API แบบดั้งเดิมที่มักต้องเขียนโค้ดแบบคงที่สำหรับการบูรณาการ ทำให้ต้องอัปเดตโค้ดทุกครั้งที่ API เปลี่ยน MCP เสนอวิธี "บูรณาการครั้งเดียว" ส่งผลให้สามารถปรับตัวได้มากขึ้น

• **การทำงานร่วมกันระหว่าง LLMs**: MCP ทำงานได้กับ LLMs หลากหลายตัว ให้ความยืดหยุ่นในการเปลี่ยนโมเดลหลักเพื่อประเมินผลการทำงานที่ดีกว่า

• **ความปลอดภัยมาตรฐาน**: MCP รวมวิธีการตรวจสอบสิทธิ์มาตรฐานช่วยเพิ่มความสามารถในการขยายเมื่อต้องการเข้าถึงเซิร์ฟเวอร์ MCP เพิ่มเติม ง่ายกว่าการจัดการคีย์และประเภทการตรวจสอบสิทธิ์ที่แตกต่างกันสำหรับ API แบบดั้งเดิมหลายตัว

### ตัวอย่าง MCP

![MCP Diagram](../../../translated_images/th/mcp-diagram.e4ca1cbd551444a1.webp)

ลองจินตนาการว่าผู้ใช้ต้องการจองเที่ยวบินโดยใช้ผู้ช่วย AI ที่ใช้ MCP

1. **การเชื่อมต่อ**: ผู้ช่วย AI (ไคลเอนต์ MCP) เชื่อมต่อกับเซิร์ฟเวอร์ MCP ที่สายการบินให้บริการ

2. **ค้นหาเครื่องมือ**: ไคลเอนต์ถามเซิร์ฟเวอร์ MCP ของสายการบินว่า "คุณมีเครื่องมืออะไรบ้าง?" เซิร์ฟเวอร์ตอบด้วยเครื่องมือเช่น "ค้นหาเที่ยวบิน" และ "จองเที่ยวบิน"

3. **เรียกใช้เครื่องมือ**: คุณจากนั้นขอให้ผู้ช่วย AI, "ช่วยค้นหาเที่ยวบินจากพอร์ตแลนด์ไปโฮโนลูลู" ผู้ช่วย AI ใช้ LLM ของตนและระบุว่าจำเป็นต้องเรียกเครื่องมือ "ค้นหาเที่ยวบิน" พร้อมส่งพารามิเตอร์ที่เกี่ยวข้อง (ต้นทาง, ปลายทาง) ไปยังเซิร์ฟเวอร์ MCP

4. **ดำเนินการและตอบกลับ**: เซิร์ฟเวอร์ MCP ทำหน้าที่เป็น wrapper เรียก API การจองภายในของสายการบินโดยตรง จากนั้นได้รับข้อมูลเที่ยวบิน (เช่น ข้อมูล JSON) และส่งกลับให้ผู้ช่วย AI

5. **การโต้ตอบเพิ่มเติม**: ผู้ช่วย AI นำเสนอทางเลือกเที่ยวบิน เมื่อคุณเลือกเที่ยวบิน ผู้ช่วยอาจเรียกใช้เครื่องมือ "จองเที่ยวบิน" บนเซิร์ฟเวอร์ MCP เดียวกันเพื่อดำเนินการจองให้เสร็จสมบูรณ์

## โปรโตคอล Agent-to-Agent (A2A)

ในขณะที่ MCP มุ่งเชื่อมต่อ LLMs กับเครื่องมือ โปรโตคอล **Agent-to-Agent (A2A)** ก้าวล้ำขึ้นด้วยการเปิดโอกาสให้สื่อสารและร่วมมือกันระหว่างเอเจนต์ AI ต่าง ๆ โดย A2A เชื่อมต่อเอเจนต์ AI ระหว่างองค์กร สภาพแวดล้อม และเทคโนโลยีต่าง ๆ เพื่อทำภารกิจร่วมกันให้เสร็จ

เราจะตรวจสอบองค์ประกอบและประโยชน์ของ A2A พร้อมตัวอย่างการประยุกต์ใช้ในแอปพลิเคชันท่องเที่ยวของเรา

### องค์ประกอบหลักของ A2A

A2A มุ่งเน้นที่การเปิดช่องทางสื่อสารระหว่างเอเจนต์และให้พวกเขาทำงานร่วมกันเพื่อทำภารกิจย่อยของผู้ใช้ให้สำเร็จ องค์ประกอบของโปรโตคอลแต่ละส่วนช่วยส่งเสริมกระบวนการนี้:

#### Agent Card

คล้ายกับที่เซิร์ฟเวอร์ MCP แชร์รายการเครื่องมือ Agent Card มี:
- ชื่อของเอเจนต์
- **คำอธิบายงานทั่วไป** ที่มันทำเสร็จ
- **รายการทักษะเฉพาะ** พร้อมคำอธิบายช่วยให้เอเจนต์อื่น (หรือแม้แต่ผู้ใช้มนุษย์) เข้าใจเมื่อไรและทำไมจึงควรเรียกเอเจนต์นั้น
- **URL ปลายทางปัจจุบัน** ของเอเจนต์
- **เวอร์ชัน** และ **ความสามารถ** ของเอเจนต์ เช่น การตอบสนองแบบสตรีมมิ่งและการแจ้งเตือน

#### Agent Executor

Agent Executor รับผิดชอบในการ **ส่งต่อบริบทจากแชทผู้ใช้ไปยังเอเจนต์ระยะไกล** โดยเอเจนต์ระยะไกลต้องการบริบทนี้เพื่อเข้าใจภารกิจที่ต้องทำ ในเซิร์ฟเวอร์ A2A เอเจนต์ใช้โมเดลภาษาใหญ่ของตัวเอง (LLM) เพื่อวิเคราะห์คำขอที่เข้ามาและดำเนินงานโดยใช้เครื่องมือภายในของตนเอง

#### Artifact

เมื่องานเสร็จสิ้นโดยเอเจนต์ระยะไกล ผลงานจะถูกสร้างเป็น artifact โดย artifact **บรรจุผลลัพธ์ของงานเอเจนต์**, **คำอธิบายสิ่งที่สำเร็จแล้ว** และ **บริบทข้อความ** ที่ส่งผ่านโปรโตคอล เมื่อ artifact ถูกส่งไป การเชื่อมต่อกับเอเจนต์ระยะไกลจะถูกปิดจนกว่าจะต้องใช้ใหม่

#### Event Queue

ส่วนนี้ใช้สำหรับ **จัดการการอัปเดตและส่งผ่านข้อความ** มีความสำคัญโดยเฉพาะในระบบเอเจนต์ที่ใช้งานจริงเพื่อป้องกันการปิดการเชื่อมต่อระหว่างเอเจนต์ก่อนงานจะเสร็จ โดยเฉพาะเมื่อเวลาทำงานยาวนาน

### ประโยชน์ของ A2A

• **ความร่วมมือที่ดีขึ้น**: ช่วยให้เอเจนต์จากผู้ให้บริการและแพลตฟอร์มต่าง ๆ โต้ตอบ แชร์บริบท และทำงานร่วมกัน สร้างอัตโนมัติที่ไร้รอยต่อระหว่างระบบที่เคยแยกจากกัน

• **ความยืดหยุ่นในการเลือกโมเดล**: เอเจนต์แต่ละตัวใน A2A สามารถเลือก LLM ที่ใช้ตอบสนองคำร้องของตนได้ อนุญาตการปรับแต่งหรือใช้โมเดลเฉพาะต่อตัว ต่างจากการเชื่อมต่อ LLM เดียวใน MCP บางกรณี

• **การตรวจสอบสิทธิ์ในตัว**: การตรวจสอบสิทธิ์ถูกรวมเข้าไปในโปรโตคอล A2A โดยตรง ทำให้มีกรอบความปลอดภัยที่แข็งแกร่งสำหรับการโต้ตอบเอเจนต์

### ตัวอย่าง A2A

![A2A Diagram](../../../translated_images/th/A2A-Diagram.8666928d648acc26.webp)

มาขยายสถานการณ์การจองท่องเที่ยวของเรา โดยคราวนี้ใช้ A2A

1. **คำขอของผู้ใช้ไปยังเอเจนต์หลายตัว**: ผู้ใช้โต้ตอบกับไคลเอนต์/เอเจนต์ A2A "Travel Agent" เช่น พูดว่า "ช่วยจองทริปทั้งทริปไปโฮโนลูลูสำหรับสัปดาห์หน้า รวมเที่ยวบิน โรงแรม และรถเช่า"

2. **การจัดการโดย Travel Agent**: Travel Agent รับคำขอที่ซับซ้อนนี้ ใช้ LLM ของตนคิดวิเคราะห์ภารกิจและตัดสินใจว่าต้องติดต่อกับเอเจนต์เฉพาะทางอื่น ๆ

3. **การสื่อสารระหว่างเอเจนต์**: Travel Agent ใช้โปรโตคอล A2A เชื่อมต่อเอเจนต์เบื้องหลัง เช่น "Airline Agent," "Hotel Agent," และ "Car Rental Agent" ที่สร้างโดยบริษัทต่าง ๆ

4. **มอบหมายงาน**: Travel Agent ส่งมอบภารกิจเฉพาะให้เอเจนต์เหล่านี้ (เช่น "หาตั๋วไปโฮโนลูลู," "จองโรงแรม," "เช่ารถ") โดยเอเจนต์เหล่านี้ใช้งาน LLM ของตัวเองและใช้เครื่องมือของตัวเอง (ซึ่งอาจเป็นเซิร์ฟเวอร์ MCP) เพื่อทำส่วนงานจองของตน

5. **การรวบรวมผลลัพธ์**: เมื่อเอเจนต์ทั้งหมดเสร็จสิ้นภารกิจ Travel Agent รวบรวมผลลัพธ์ (รายละเอียดเที่ยวบิน, การยืนยันโรงแรม, การจองรถเช่า) และตอบกลับแบบแชทที่ครอบคลุมให้ผู้ใช้

## Natural Language Web (NLWeb)

เว็บไซต์ได้กลายเป็นวิธีหลักที่ผู้ใช้เข้าถึงข้อมูลและข้อมูลบนอินเทอร์เน็ต

มาดูองค์ประกอบต่าง ๆ ของ NLWeb, ประโยชน์ของ NLWeb และตัวอย่างวิธีที่ NLWeb ทำงานโดยดูที่แอปพลิเคชันท่องเที่ยวของเรา

### องค์ประกอบของ NLWeb

- **แอปพลิเคชัน NLWeb (โค้ดบริการหลัก)**: ระบบที่ประมวลผลคำถามภาษาธรรมชาติ เชื่อมต่อส่วนต่าง ๆ ของแพลตฟอร์มเพื่อสร้างการตอบสนอง คุณสามารถคิดว่านี่คือ **เครื่องยนต์ที่ขับเคลื่อนฟีเจอร์ภาษาธรรมชาติของเว็บไซต์**

- **โปรโตคอล NLWeb**: เป็น **ชุดกฎพื้นฐานสำหรับการโต้ตอบภาษาธรรมชาติกับเว็บไซต์** ส่งกลับคำตอบในรูปแบบ JSON (มักใช้ Schema.org) จุดประสงค์คือสร้างรากฐานง่าย ๆ สำหรับ “AI Web” เช่นเดียวกับที่ HTML ทำให้สามารถแชร์เอกสารออนไลน์ได้

- **เซิร์ฟเวอร์ MCP (จุดสิ้นสุด Model Context Protocol)**: ระบบ NLWeb แต่ละตัวยังทำงานเป็น **เซิร์ฟเวอร์ MCP** ด้วย ซึ่งหมายความว่าสามารถ **แบ่งปันเครื่องมือ (เช่น วิธี ask) และข้อมูล** กับระบบ AI อื่น ๆ ในทางปฏิบัติ ทำให้เนื้อหาและความสามารถของเว็บไซต์ถูกใช้งานโดยเอเจนต์ AI และเว็บไซต์กลายเป็นส่วนหนึ่งของ “ระบบนิเวศเอเจนต์” ที่กว้างขึ้น

- **Embedding Models**: โมเดลเหล่านี้ใช้สำหรับ **แปลงเนื้อหาเว็บไซต์เป็นตัวแทนเชิงตัวเลขเรียกว่าเวกเตอร์ (embedding)** เวกเตอร์เหล่านี้จับความหมายในรูปแบบที่คอมพิวเตอร์สามารถเปรียบเทียบและค้นหาได้ เก็บไว้ในฐานข้อมูลพิเศษ และผู้ใช้สามารถเลือกโมเดล embedding ที่ต้องการได้

- **ฐานข้อมูลเวกเตอร์ (กลไกการค้นคืน)**: ฐานข้อมูลนี้ **เก็บ embeddings ของเนื้อหาเว็บไซต์** เมื่อมีผู้ถามคำถาม NLWeb จะตรวจสอบฐานข้อมูลเวกเตอร์เพื่อค้นหาข้อมูลที่เกี่ยวข้องเร็วที่สุด ให้รายการคำตอบที่เป็นไปได้อย่างรวดเร็วและจัดอันดับตามความเหมือน NLWeb รองรับระบบเก็บเวกเตอร์ที่หลากหลาย เช่น Qdrant, Snowflake, Milvus, Azure AI Search, และ Elasticsearch

### ตัวอย่าง NLWeb

![NLWeb](../../../translated_images/th/nlweb-diagram.c1e2390b310e5fe4.webp)

ลองพิจารณาเว็บไซต์จองท่องเที่ยวของเราอีกครั้ง คราวนี้ใช้พลังของ NLWeb

1. **การนำเข้าข้อมูล**: แคตาล็อกสินค้าเดิมของเว็บไซต์ท่องเที่ยว (เช่น รายการเที่ยวบิน, คำอธิบายโรงแรม, แพกเกจทัวร์) ถูกจัดรูปแบบด้วย Schema.org หรือโหลดผ่าน RSS feeds เครื่องมือ NLWeb นำเข้าข้อมูลที่มีโครงสร้างนี้ สร้าง embeddings และเก็บในฐานข้อมูลเวกเตอร์ภายในหรือระยะไกล

2. **การถามด้วยภาษาธรรมชาติ (มนุษย์)**: ผู้ใช้เยี่ยมชมเว็บไซต์ แทนที่จะนำทางเมนูพิมพ์ในอินเทอร์เฟซแชทเช่น "ช่วยหาที่พักสำหรับครอบครัวในโฮโนลูลูที่มีสระว่ายน้ำสำหรับสัปดาห์หน้า"

3. **การประมวลผล NLWeb**: แอปพลิเคชัน NLWeb ได้รับคำถาม ส่งคำถามไปยัง LLM เพื่อทำความเข้าใจ และค้นหาในฐานข้อมูลเวกเตอร์สำหรับรายการโรงแรมที่เกี่ยวข้องพร้อมกัน

4. **ผลลัพธ์ที่แม่นยำ**: LLM ช่วยตีความผลการค้นหาจากฐานข้อมูล ระบุผลที่ดีที่สุดตามเกณฑ์ "เหมาะสำหรับครอบครัว," "สระว่ายน้ำ," และ "โฮโนลูลู" แล้วจัดรูปแบบตอบกลับเป็นภาษาธรรมชาติ สำคัญคือคำตอบอ้างอิงโรงแรมจริงจากแคตาล็อกเว็บไซต์ หลีกเลี่ยงข้อมูลที่สร้างขึ้นเอง

5. **การโต้ตอบกับเอเจนต์ AI**: เพราะ NLWeb ทำงานเป็นเซิร์ฟเวอร์ MCP เอเจนต์ท่องเที่ยว AI ภายนอกสามารถเชื่อมต่อกับอินสแตนซ์ NLWeb ของเว็บไซต์นี้ เอเจนต์สามารถใช้เมธอด `ask` ของ MCP เพื่อสอบถามเว็บไซต์โดยตรง: `ask("มีร้านอาหารมังสวิรัติในพื้นที่โฮโนลูลูที่โรงแรมแนะนำไหม?")` อินสแตนซ์ NLWeb จะประมวลผลคำถามนี้ โดยอาศัยฐานข้อมูลร้านอาหาร (ถ้าโหลดแล้ว) และส่งกลับคำตอบในรูปแบบ JSON ที่จัดระเบียบแล้ว
