# ตัวแทน AI สำหรับผู้เริ่มต้น - คู่มือการศึกษา

ใช้คู่มือนี้เป็นเพื่อนร่วมทางเชิงปฏิบัติในขณะที่คุณเรียนผ่านคอร์สนี้  
ไม่ได้มีไว้เพื่อแทนที่บทเรียน แต่ช่วยให้คุณตัดสินใจว่าจะเริ่มต้นที่ไหน,  
ควรมองหาอะไรในแต่ละบทเรียน, และวิธีเชื่อมโยงแนวคิดต่าง ๆ ให้กลายเป็น  
ตัวอย่างตัวแทนที่ทำงานได้ขนาดเล็ก

ถ้านี่เป็นครั้งแรกของคุณที่นี่ ให้เริ่มต้นแบบง่าย ๆ:

1. อ่าน [การตั้งค่าคอร์ส](./00-course-setup/README.md)
2. เรียนบทเรียน 01-06 ตามลำดับ
3. จดจำไอเดียตัวอย่างเล็ก ๆ ไว้ในใจระหว่างเรียน
4. หลังจากแต่ละบทเรียน ถามตัวเองว่า: "ตอนนี้ตัวแทนของฉันสามารถทำอะไรได้  
   ที่ก่อนหน้านี้ทำไม่ได้?"

## ตัวอย่างง่าย ๆ ที่ควรจำไว้

วิธีที่ดีในการเรียนรู้เกี่ยวกับตัวแทนคือการติดตามไอเดียตัวอย่างหนึ่งตลอดคอร์ส

ตัวอย่างตัวอย่าง: **ตัวช่วยคอร์ส**

ผู้ใช้ถาม:

> "ฉันอยากเรียนรู้ว่าตัวแทนใช้เครื่องมืออย่างไร ช่วยหาบทเรียนที่เหมาะสม, สรุป  
> สิ่งที่ฉันควรอ่านก่อน และให้แบบฝึกหัดสั้น ๆ"

แชทบอตธรรมดาตอบได้จากสิ่งที่มันรู้แล้วเท่านั้น ตัวแทนทำได้มากกว่านั้น:

1. **อ่านหรือค้นหาไฟล์คอร์ส** เพื่อหาบทเรียนที่เหมาะสม  
2. **ใช้เครื่องมือ** เพื่อดึงลิงก์บทเรียน ตัวอย่าง หรือวัสดุสนับสนุน  
3. **วางแผน** เส้นทางการเรียนรู้สั้น ๆ แทนที่จะให้คำตอบยาว ๆ  
4. **ใช้บริบท** จากการสนทนาปัจจุบันเพื่อมุ่งเน้นในเป้าหมายของผู้เรียน  
5. **จดจำความชอบที่เป็นประโยชน์** ถ้าแอปพลิเคชันรองรับพื้นที่เก็บความจำ  
6. **แสดงร่องรอย อ้างอิง หรือบันทึก** เพื่อให้ผู้ใช้เข้าใจสิ่งที่เกิดขึ้น  
7. **ใช้มาตรการป้องกัน** ก่อนลงมือทำงานเสี่ยงหรือใช้ข้อมูลที่ละเอียดอ่อน

ในขณะที่คุณศึกษาบทเรียนแต่ละบท กลับมาดูตัวอย่างนี้และถามว่า: บทเรียนนี้  
จะเสริมความสามารถอะไรใหม่ ๆ ให้?

## สิ่งที่คุณกำลังสร้างขึ้น

เมื่อจบบทเรียนทั้งหมด คุณควรอธิบายและสร้างระบบตัวแทนที่ผสมผสาน  
ส่วนประกอบเหล่านี้:

| ส่วน | ความหมายง่าย ๆ | ในตัวอย่าง |
|------|----------------|-------------|
| Model | เครื่องยนต์เหตุผลที่ตีความคำขอของผู้ใช้ | เข้าใจว่าผู้เรียนต้องการบทเรียนเกี่ยวกับการใช้เครื่องมือ |
| Tools | ฟังก์ชัน, API, ไฟล์, เบราว์เซอร์ หรือบริการที่ตัวแทนใช้ได้ | ค้นหาใน repo หรือดึงเนื้อหาบทเรียน |
| Knowledge | เอกสารหรือข้อมูลที่ใช้เป็นฐานคำตอบ | ไฟล์ README คอร์สและเนื้อหาบทเรียน |
| Context | ข้อมูลที่รวมในโมเดลเรียกถัดไป | เป้าหมายของผู้ใช้และผลลัพธ์จากเครื่องมือ |
| Memory | ข้อมูลที่บันทึกไว้ใช้ภายหลัง | ผู้เรียนชอบตัวอย่าง Python ทำมือ |
| Planning | การแบ่งเป้าหมายใหญ่เป็นขั้นตอนเล็ก ๆ | หา บทเรียน, สรุป, แนะนำแบบฝึกหัด |
| Orchestration | การกระจายงานระหว่างเครื่องมือ, ขั้นตอน หรือ ตัวแทนหลายตัว | ตัววางแผนเรียกใช้เครื่องมือค้นหา แล้วตามด้วยสรุป |
| Trust | ความปลอดภัย, การประเมิน และความสามารถในการสังเกต | บันทึกการเรียกเครื่องมือและถามก่อนทำในสิ่งที่มีผลกระทบสูง |

## โมเดลและผู้ให้บริการ

ตัวอย่างโค้ดคอร์สใช้ **Microsoft Agent Framework (MAF)** และมุ่งเป้าไปที่  
**Azure OpenAI Responses API** — API ที่แนะนำสำหรับอนาคต ซึ่งรวบรวมการตอบแชท,  
การเรียกเครื่องมือ, อินพุตมัลติโมดอล และการสนทนาแบบรัฐในพื้นผิว API เดียว  
คุณเชื่อมต่อผ่านโปรเจกต์ **Microsoft Foundry** (ใช้ `FoundryChatClient`) หรือ  
Azure OpenAI โดยตรง (ใช้ `OpenAIChatClient`)

ขณะที่คุณทำบทเรียนจะมีตัวเลือกผู้ให้บริการดังนี้:

- **Microsoft Foundry / Azure OpenAI (Responses API)** — เส้นทางหลักของบทเรียน ใช้  
  `az login` สำหรับการยืนยันตัวตน Entra ID แบบไม่ต้องใช้คีย์  
- **Foundry Local** — รันโมเดลแบบเต็มบนอุปกรณ์ด้วย API ที่เข้ากันกับ OpenAI  
  (ไม่มีคลาวด์ ไม่มีคีย์ API) เหมาะสำหรับทดลองออฟไลน์หรือฟรี ดู [การตั้งค่าคอร์ส](./00-course-setup/README.md)  
- **MiniMax** — ผู้ให้บริการที่เข้ากันกับ OpenAI มีโมเดลขนาดบริบทใหญ่ ใช้แทนได้ง่าย

> **หมายเหตุ:** GitHub Models ยกเลิกแล้ว (เลิกใช้กรกฎาคม 2026) และไม่รองรับ Responses API  
> ตัวอย่างได้อัปเดตให้ใช้ Azure OpenAI / Microsoft Foundry แทน

## แนวคิดสำคัญในคำง่ายสำหรับผู้เริ่มต้น

### เครื่องมือ

เครื่องมือคือสิ่งที่ตัวแทนเรียกใช้ทำงานนอกโมเดล เครื่องมือที่ดีต้องมีชื่อชัดเจน,  
หน้าที่จำกัด, อินพุตที่มีชนิดข้อมูล, ผลลัพธ์ที่คาดเดาได้, และวิธีล้มเหลวที่ปลอดภัย

สำหรับตัวช่วยคอร์ส เครื่องมืออาจเป็น:

- `search_lessons(query)`
- `read_lesson(path)`
- `create_practice_task(topic)`

### RAG และความรู้

RAG ช่วยตัวแทนตอบโดยใช้แหล่งข้อมูลแทนการเดา ในคอร์สนี้ แหล่งข้อมูลนั้นอาจเป็น  
README บทเรียน, ตัวอย่างโค้ด, หรือทรัพยากรภายนอกที่เชื่อมโยงจากบทเรียน

ใช้ RAG เมื่อต้องการให้คำตอบมีฐานข้อมูล, เอกสาร หรือไฟล์โปรเจกต์ปัจจุบัน

### การวางแผน

การวางแผนมีประโยชน์เมื่อคำขอมีหลายขั้นตอน แผนควรสั้นและมองเห็นได้ง่ายเพื่อให้นักพัฒนา  
หรือผู้ใช้ตรวจสอบ

สำหรับตัวอย่าง แผนอาจเป็น:

1. หา บทเรียนเกี่ยวกับการใช้เครื่องมือ  
2. สรุปบทเรียนที่เกี่ยวข้องมากที่สุด  
3. แนะนำแบบฝึกหัดหนึ่งอย่าง

### บริบท

บริบทคือสิ่งที่โมเดลเห็นตอนนี้ หากบริบทน้อยเกินไป ตัวแทนอาจพลาดรายละเอียดสำคัญ  
บริบทมากเกินไปทำให้ตัวแทนช้าลง, เสียค่าใช้จ่ายมากขึ้น, หรือสับสนง่าย

การออกแบบบริบทที่ดีหมายถึงการเลือกข้อมูลที่เหมาะสมสำหรับการเรียกโมเดลถัดไป

### ความจำ

ความจำคือข้อมูลที่บันทึกไว้ใช้ภายหลัง อย่าบันทึกทุกอย่าง บันทึกเฉพาะที่มีประโยชน์  
ปลอดภัย และแก้ไขหรือลบได้ง่าย

เช่น การจำ "ผู้เรียนชอบตัวอย่าง Python" อาจมีประโยชน์  
แต่จำข้อมูลส่วนตัวที่ละเอียดอ่อนมักไม่ควรทำ

### การประเมินและการสังเกต

การประเมินถามว่า: ตัวแทนทำถูกต้องหรือไม่?

การสังเกตถามว่า: เราเห็นกระบวนการได้หรือไม่?

สำหรับตัวแทนที่ผลิตจริง ควรติดตามการเรียกโมเดล, การเรียกเครื่องมือ, บริบทที่ดึงมา,  
ความหน่วง, ค่าใช้จ่าย, ข้อผิดพลาด และคำติชมผู้ใช้

### ความเชื่อถือและความปลอดภัย

ตัวแทนที่น่าเชื่อถือไม่ใช่แค่คำสั่งที่ช่วยได้ แต่ควรใช้เครื่องมือแบบสิทธิ์น้อยที่สุด,  
ผ่านการอนุมัติจากมนุษย์ก่อนการกระทำที่มีผลกระทบสูง, การแก้ไขข้อมูลที่จำเป็น, และบันทึก  
หรือใบเสร็จสำหรับการกระทำที่ต้องตรวจสอบได้

## กิจวัตรทบทวน 15 นาที

ใช้กิจวัตรนี้หลังเรียนแต่ละบท:

1. **สรุปบทเรียนในประโยคเดียว**  
2. **ตั้งชื่อความสามารถใหม่ของตัวแทน** เช่น: ใช้เครื่องมือ, ดึงข้อมูล, วางแผน, ความจำ,  
   การสังเกต, หรือ ความปลอดภัย  
3. **เพิ่มความสามารถนั้นลงในตัวช่วยคอร์ส** สิ่งใดเปลี่ยนแปลงในตัวอย่างตอนนี้?  
4. **หาโอกาสเสี่ยง** อะไรอาจผิดพลาดหากใช้ความสามารถนั้นผิดทาง?  
5. **เขียนคำถามทดสอบหนึ่งข้อ** คุณจะตรวจสอบว่าตัวแทนทำงานดีได้อย่างไร?

## ตรวจสอบตัวเองอย่างรวดเร็ว

ก่อนไปต่อ ลองตอบคำถามเหล่านี้:

1. ตัวแทนทำอะไรได้บ้างที่แชทบอตธรรมดาทำไม่ได้เอง?  
2. เครื่องมือที่ตัวแทนคุณต้องการใช้เป็นอันดับแรกคืออะไร และทำไม?  
3. แหล่งความรู้ใดควรเป็นฐานคำตอบของตัวแทน?  
4. บริบทใดควรรวมอยู่ในการเรียกโมเดลถัดไป?  
5. ตัวแทนควรจำอะไร และควรหลีกเลี่ยงการบันทึกอะไร?  
6. ตัวแทนควรถามมนุษย์ก่อนเมื่อไหร่?  
7. บันทึก, ร่องรอย หรือใบเสร็จรูปแบบใดที่จะช่วยคุณแก้ไขข้อผิดพลาดหรือการตรวจสอบตัวแทนในภายหลัง?

## แบบฝึกหัดผลงานขั้นสุดท้ายแนะนำ

จบคอร์ส สร้างตัวแทนขนาดเล็กที่ช่วยผู้เรียนใช้ที่เก็บข้อมูลนี้

เวอร์ชันขั้นต่ำ:

- รับหัวข้อจากผู้ใช้  
- หา บทเรียนที่เกี่ยวข้องมากที่สุด  
- สรุปสิ่งที่ควรอ่านก่อน  
- แนะนำแบบฝึกหัดลงมือทำหนึ่งอย่าง  
- แสดงไฟล์บทเรียนหรือลิงก์ที่ใช้

เวอร์ชันยืดหยุ่น:

- จำภาษาการเขียนโปรแกรมที่ผู้เรียนชอบ  
- ใช้แผนง่าย ๆ ก่อนตอบ  
- เพิ่มขั้นตอนตรวจสอบตัวเองก่อนตอบสุดท้าย  
- บันทึกการเรียกเครื่องมือและแหล่งที่ดึงมา  
- ขออนุญาตก่อนเปิดเบราว์เซอร์หรือทำงานอัตโนมัติ UI

นี่เป็นวิธีเล็ก ๆ แต่สมจริงในการฝึกใช้เครื่องมือ, RAG, การวางแผน, บริบท, ความจำ,  
การสังเกต และความเชื่อถือในโปรเจกต์เดียวกัน
