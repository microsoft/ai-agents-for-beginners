# ตัวแทน AI สำหรับผู้เริ่มต้น - คู่มือการศึกษา

ใช้คู่มือนี้เป็นเพื่อนร่วมทางในทางปฏิบัติในขณะที่คุณทำคอร์สนี้ มัน
ไม่ได้มีไว้แทนที่บทเรียน แต่ช่วยให้คุณตัดสินใจว่าจะเริ่มต้นที่ไหน,
สิ่งที่ควรมองหาในแต่ละบทเรียน และวิธีเชื่อมโยงแนวคิดเหล่านั้นเข้ากับ
ตัวอย่างตัวแทนที่ทำงานได้ขนาดเล็ก

ถ้านี่เป็นครั้งแรกที่คุณมาที่นี่ เริ่มต้นแบบง่าย ๆ:

1. อ่าน [Course Setup](./00-course-setup/README.md)  
2. ทำบทเรียน 01-06 ให้ครบตามลำดับ  
3. เก็บไอเดียการสาธิตเล็กๆ ไว้ในใจขณะที่เรียน  
4. หลังจากแต่ละบทเรียน ถามตัวเองว่า: "เอเจนต์ของฉันทำอะไรได้บ้างตอนนี้ที่ก่อนหน้านี้ทำไม่ได้?"  
 

## สาธิตง่ายๆ ที่ควรจดจำไว้  

วิธีที่ดีในการเรียนรู้เอเจนต์คือการติดตามไอเดียสาธิตตัวหนึ่งผ่านหลักสูตรนี้  

ตัวอย่างการสาธิต: **เอเจนต์ผู้ช่วยหลักสูตร**  

ผู้ใช้สอบถามว่า:  

> "ฉันต้องการเรียนรู้ว่าเอเจนต์ใช้เครื่องมืออย่างไร ช่วยหาบทเรียนที่เหมาะสม สรุปสิ่งที่  
> ฉันควรอ่านก่อน และให้ภารกิจฝึกฝนนิดหน่อย"  

แชทบอทปกติสามารถตอบคำถามจากสิ่งที่มันรู้ก่อนหน้าได้ เอเจนต์สามารถทำได้มากกว่า:  

1. **อ่านหรือค้นหาไฟล์ในหลักสูตร** เพื่อหาบทเรียนที่เหมาะสม  
2. **ใช้เครื่องมือ** เพื่อดึงลิงก์บทเรียน ตัวอย่าง หรือวัสดุประกอบ  
3. **วางแผน** เส้นทางการเรียนรู้สั้นๆ แทนการตอบยาวครั้งเดียว  
4. **ใช้บริบท** จากบทสนทนาปัจจุบันเพื่อโฟกัสที่เป้าหมายของผู้เรียน  
  
5. **จดจำความชอบที่เป็นประโยชน์** ถ้าแอปพลิเคชันรองรับความจำ  
6. **แสดงร่องรอย อ้างอิง หรือบันทึก** เพื่อให้ผู้ใช้เข้าใจสิ่งที่เกิดขึ้น  
7. **ใช้มาตรการป้องกัน** ก่อนดำเนินการที่มีความเสี่ยงหรือใช้ข้อมูลที่ไวต่อความปลอดภัย  

ขณะที่ศึกษาบทเรียนแต่ละบท กลับมาดูสาธิตนี้อีกครั้งและถามว่า: บทเรียนนี้จะเพิ่มความสามารถใหม่อะไรได้บ้าง?  
 

## สิ่งที่คุณกำลังสร้างขึ้น  

เมื่อจบหลักสูตร คุณควรจะสามารถอธิบายและสร้างระบบเอเจนต์ที่ผสมผสานส่วนเหล่านี้:  
 

|------|------------------------|-------------|  
| Model | เครื่องยนต์เหตุผลที่ตีความคำขอของผู้ใช้ | เข้าใจว่าผู้เรียนต้องการบทเรียนเกี่ยวกับการใช้เครื่องมือ |  
| Tools | ฟังก์ชัน API, ไฟล์, เบราว์เซอร์ หรือบริการที่เอเจนต์ใช้ได้ | ค้นหาในรีโพหรือดึงเนื้อหาบทเรียน |  
| Knowledge | เอกสารหรือข้อมูลที่ใช้เป็นฐานคำตอบ | ไฟล์ README หลักสูตรและวัสดุบทเรียน |  
| Context | ข้อมูลที่รวมในคำเรียกโมเดลถัดไป | เป้าหมายของผู้ใช้และผลลัพธ์จากเครื่องมือ |  
| Memory | ข้อมูลที่บันทึกไว้ใช้ภายหลัง | ผู้เรียนชอบตัวอย่าง Python เชิงปฏิบัติ |  
| Planning | การแบ่งเป้าหมายใหญ่เป็นขั้นตอนเล็กๆ | หาบทเรียน, สรุปบทเรียน, เสนอการฝึก |  
| Orchestration | การจัดการงานผ่านเครื่องมือ ขั้นตอน หรือเอเจนต์ | แพลนเนอร์เรียกใช้เครื่องมือค้นหา แล้วเรียกสรุป |  
| Trust | ความปลอดภัย ความมั่นคง การประเมิน และการสังเกตการณ์ | บันทึกการเรียกใช้เครื่องมือและถามก่อนการกระทำที่มีผลกระทบสูง |  
 

 

ตัวอย่างรหัสในคอร์สนี้ใช้ **Microsoft Agent Framework (MAF)** และมุ่งเป้าไปที่ **Azure OpenAI Responses API** — API ที่แนะนำสำหรับการใช้งานในอนาคต ซึ่งรวมเอาการเติมคำตอบแชท, การเรียกใช้เครื่องมือ, อินพุตมัลติโมดอล และการสนทนาแบบมีสถานะไว้ในพื้นผิว API เดียวกัน คุณสามารถเชื่อมต่อผ่านโปรเจกต์ **Microsoft Foundry** (ด้วย `FoundryChatClient`) หรือเชื่อมต่อกับ Azure OpenAI โดยตรง (ด้วย `OpenAIChatClient`)

ขณะที่คุณทำบทเรียนต่าง ๆ คุณมีตัวเลือกผู้ให้บริการดังนี้:

- **Microsoft Foundry / Azure OpenAI (Responses API)** — เส้นทางหลักที่ใช้ในบทเรียนทั้งหมด ลงชื่อเข้าใช้ด้วย `az login` เพื่อการพิสูจน์ตัวตนแบบ Entra ID แบบไม่ต้องใช้คีย์
- **Foundry Local** — รันโมเดลแบบเต็มรูปแบบบนอุปกรณ์ผ่าน API ที่เข้ากันได้กับ OpenAI (ไม่มีคลาวด์ ไม่ต้องใช้คีย์ API) เหมาะสำหรับการทดลองแบบออฟไลน์หรือไม่เสียค่าใช้จ่าย ดูที่ [การตั้งค่าคอร์ส](./00-course-setup/README.md)
- **MiniMax** — ผู้ให้บริการที่เข้ากันได้กับ OpenAI พร้อมโมเดลขนาดบริบทใหญ่ ใช้แทนกันได้โดยตรง

> **หมายเหตุ:** GitHub Models เลิกใช้แล้ว (จะหยุดให้บริการในเดือนกรกฎาคม 2026) และไม่รองรับ Responses API ตัวอย่างทั้งหมดได้รับการอัปเดตให้ใช้ Azure OpenAI / Microsoft Foundry แทน

## แนวคิดสำคัญในคำที่เข้าใจง่ายสำหรับผู้เริ่มต้น

### เครื่องมือ

เครื่องมือคือสิ่งที่เอเย่นต์สามารถเรียกใช้เพื่อทำงานนอกโมเดล เครื่องมือที่ดี
จะมีชื่อที่ชัดเจน งานที่จำกัด อินพุตที่มีประเภทชัดเจน ผลลัพธ์ที่คาดเดาได้ และวิธีล้มเหลวที่ปลอดภัย


สำหรับตัวช่วยสาธิตของหลักสูตร เครื่องมืออาจเป็น:

- `search_lessons(query)`
- `read_lesson(path)`
- `create_practice_task(topic)`

### RAG และความรู้

RAG ช่วยเอเย่นต์ตอบคำถามจากแหล่งข้อมูลต้นทางแทนการเดา ในหลักสูตรนี้
แหล่งข้อมูลต้นทางอาจเป็น README ของบทเรียน ตัวอย่างโค้ด หรือทรัพยากรภายนอก
ที่ลิงก์จากบทเรียน

ใช้ RAG เมื่อคำตอบควรมีพื้นฐานจากเอกสาร ข้อมูล หรือไฟล์โครงการปัจจุบัน


### การวางแผน

การวางแผนมีประโยชน์เมื่อคำขอมีมากกว่าหนึ่งขั้นตอน รักษาแผนให้สั้นและ
มองเห็นได้พอที่จะให้ผู้พัฒนาหรือผู้ใช้ตรวจสอบ

สำหรับการสาธิต แผนอาจเป็น:

1. ค้นหาบทเรียนที่เกี่ยวข้องกับการใช้เครื่องมือ
2. สรุปบทเรียนที่เกี่ยวข้องมากที่สุด
3. แนะนำงานฝึกปฏิบัติหนึ่งงาน

### บริบท

บริบทคือตัวที่โมเดลเห็นในขณะนี้ บริบทน้อยเกินไปอาจทำให้เอเย่นต์
พลาดรายละเอียดสำคัญ บริบทมากเกินไปอาจทำให้เอเย่นต์ทำงานช้าลง มีค่าใช้จ่ายสูงขึ้น
หรือสับสนง่ายขึ้น

การวางบริบทที่ดีหมายถึงการเลือกข้อมูลที่เหมาะสมสำหรับการเรียกโมเดลครั้งถัดไป


### ความจำ

ความจำคือข้อมูลที่บันทึกไว้สำหรับใช้ภายหลัง อย่าบันทึกทุกอย่าง บันทึกเฉพาะข้อมูล
ที่มีประโยชน์ ปลอดภัย และง่ายต่อการปรับปรุงหรือลบ

ตัวอย่างเช่น การจำว่า "ผู้เรียนชอบตัวอย่างที่เป็นภาษา Python" อาจมีประโยชน์
การจำข้อมูลส่วนตัวที่ละเอียดอ่อนโดยทั่วไปไม่ควรทำ

### การประเมินและการสังเกต

การประเมินถามว่า: เอเย่นต์ทำสิ่งที่ถูกต้องหรือไม่?

การสังเกตถามว่า: เราสามารถเห็นว่ามันเกิดขึ้นอย่างไรหรือไม่?

สำหรับเอเย่นต์ในงานจริง ให้ติดตามการเรียกโมเดล การเรียกใช้เครื่องมือ บริบทที่ดึงมา
ความล่าช้า ต้นทุน ความล้มเหลว และคำติชมจากผู้ใช้

### ความไว้วางใจและความปลอดภัย

เอเย่นต์ที่น่าเชื่อถือจำเป็นต้องมีมากกว่าเพียงการสั่งงานที่ดี ใช้เครื่องมือสิทธิ์น้อยที่สุด
การอนุมัติจากมนุษย์สำหรับการกระทำที่มีผลกระทบสูง การลบข้อมูลตามความจำเป็น และบันทึกหรือ
ใบเสร็จสำหรับการกระทำที่ต้องตรวจสอบ

## รูทีนทบทวน 15 นาที

ใช้รูทีนนี้หลังจากแต่ละบทเรียน:

1. **สรุปบทเรียนในประโยคเดียว**
2. **ตั้งชื่อความสามารถใหม่ของเอเย่นต์** เช่น การใช้เครื่องมือ การดึงข้อมูล
   การวางแผน ความจำ การสังเกต หรือความปลอดภัย
3. **เพิ่มไปยังตัวช่วยสาธิตของหลักสูตร** มีการเปลี่ยนแปลงอะไรในสาธิตบ้างตอนนี้?
4. **หาความเสี่ยง** อะไรอาจผิดพลาดหากใช้ความสามารถนี้ผิดวิธี?
5. **เขียนคำถามทดสอบหนึ่งข้อ** คุณจะตรวจสอบว่าเอเย่นต์ทำงานได้ดีอย่างไร?

## การตรวจสอบตัวเองอย่างรวดเร็ว

ก่อนจะไปต่อ ลองตอบคำถามเหล่านี้:

1. เอเย่นต์ทำอะไรได้บ้างที่แชทบอตทั่วไปทำเองไม่ได้?
2. เครื่องมืออะไรที่เอเย่นต์ของคุณต้องการเป็นอันดับแรก และทำไม?
3. แหล่งความรู้ใดควรเป็นพื้นฐานคำตอบของเอเย่นต์?
4. บริบทใดควรรวมอยู่ในการเรียกโมเดลครั้งถัดไป?
5. เอเย่นต์ควรจำอะไร และควรหลีกเลี่ยงการเก็บอะไรไว้?
6. เอเย่นต์ควรขออนุมัติจากมนุษย์เมื่อใด?
7. บันทึก ร่องรอย หรือใบเสร็จใดจะช่วยให้คุณดีบักหรือสอบทานเอเย่นต์ในภายหลัง?

## แบบฝึกหัดแนะนำสำหรับโปรเจกต์สรุป

ในตอนท้ายของหลักสูตร สร้างเอเจนต์ตัวเล็กๆ ที่ช่วยให้ผู้เรียนสามารถนำทางใน
ที่เก็บนี้ได้

เวอร์ชันขั้นต่ำ:

- รับหัวข้อจากผู้ใช้
- ค้นหาบทเรียนที่เกี่ยวข้องมากที่สุด
- สรุปสิ่งที่ควรอ่านก่อน
- แนะนำงานปฏิบัติจริงหนึ่งงาน
- แสดงไฟล์บทเรียนหรือลิงก์ที่ใช้

เวอร์ชันขยาย:

- จดจำภาษาการเขียนโปรแกรมที่ผู้เรียนชอบใช้
- ใช้แผนง่ายๆ ก่อนตอบคำถาม
- เพิ่มขั้นตอนตรวจสอบตัวเองก่อนตอบครั้งสุดท้าย
- บันทึกการเรียกใช้เครื่องมือและแหล่งข้อมูลที่ดึงมา
- ขอการยืนยันก่อนเปิดเบราว์เซอร์หรือทำงานอัตโนมัติผ่าน UI

วิธีนี้ทำให้คุณมีวิธีเล็กๆ แต่เหมือนจริงในการฝึกใช้เครื่องมือ, RAG, การวางแผน,
บริบท, ความทรงจำ, การสังเกต และความไว้วางใจ ในโครงการเดียวกัน
