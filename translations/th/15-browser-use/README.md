# การสร้างตัวแทนใช้คอมพิวเตอร์ (CUA)

ตัวแทนใช้คอมพิวเตอร์สามารถโต้ตอบกับเว็บไซต์ได้เหมือนกับคน: โดยเปิดเบราว์เซอร์ ตรวจสอบหน้าเว็บ และดำเนินการที่ดีที่สุดต่อไปจากสิ่งที่เห็น ในบทเรียนนี้ คุณจะสร้างตัวแทนอัตโนมัติเบราว์เซอร์ที่ค้นหา Airbnb ดึงข้อมูลรายการที่มีโครงสร้าง และระบุที่พักที่ถูกที่สุดในสตอกโฮล์ม

บทเรียนนี้ผสมผสาน Browser-Use สำหรับการนำทางด้วย AI, Playwright และ Chrome DevTools Protocol (CDP) สำหรับการควบคุมเบราว์เซอร์, Azure OpenAI สำหรับการวิเคราะห์ด้วยวิสัยทัศน์ และ Pydantic สำหรับการดึงข้อมูลที่มีโครงสร้าง

## บทนำ

บทเรียนนี้จะครอบคลุม:

- การเข้าใจว่าเมื่อใดที่ตัวแทนใช้คอมพิวเตอร์เหมาะกว่าการทำงานอัตโนมัติด้วย API เท่านั้น
- การผสมผสาน Browser-Use กับ Playwright และ CDP สำหรับการจัดการวงจรชีวิตของเบราว์เซอร์ที่เชื่อถือได้
- การใช้ Azure OpenAI วิสัยทัศน์และผลลัพธ์แบบมีโครงสร้างจาก Pydantic เพื่อดึงข้อมูลรายการจากหน้าเว็บที่เปลี่ยนแปลงได้
- การตัดสินใจว่าจะใช้ตัวแทนแบบใด ระหว่าง agent-first, actor-first หรือแบบไฮบริดสำหรับการอัตโนมัติในเบราว์เซอร์

## เป้าหมายการเรียนรู้

หลังจากทำบทเรียนนี้เสร็จ คุณจะรู้วิธี:

- กำหนดค่า Browser-Use กับ Azure OpenAI และ Playwright
- สร้างโฟลว์การทำงานอัตโนมัติเบราว์เซอร์ที่นำทางเว็บไซต์จริงและจัดการกับองค์ประกอบ UI แบบไดนามิก
- ดึงผลลัพธ์ที่มีการพิมพ์จากเนื้อหาที่มองเห็นในหน้า และเปลี่ยนเป็นตรรกะทางธุรกิจขั้นต่อไป
- เลือกระหว่างแบบ agent และ actor ตามความคาดการณ์ได้ของงานในเบราว์เซอร์

## ตัวอย่างโค้ด

บทเรียนนี้มีโน้ตบุ๊กการสอนหนึ่งไฟล์:

- [15-browser-user.ipynb](./15-browser-user.ipynb): เริ่มต้นเซสชัน Chrome ผ่าน CDP, ค้นหารายการที่สตอกโฮล์มใน Airbnb, ดึงราคาด้วย Browser-Use วิสัยทัศน์ และคืนค่าตัวเลือกที่ถูกที่สุดในรูปแบบข้อมูลที่มีโครงสร้าง

## ข้อกำหนดเบื้องต้น

- Python 3.12+
- กำหนดค่า Azure OpenAI deployment ในสภาพแวดล้อมของคุณแล้ว
- ติดตั้ง Chrome หรือ Chromium ในเครื่อง
- ติดตั้ง dependencies ของ Playwright
- มีความคุ้นเคยพื้นฐานกับ async Python

## การตั้งค่า

ติดตั้งแพ็กเกจที่ใช้ในโน้ตบุ๊ก:

```bash
pip install browser_use playwright python-dotenv
playwright install chromium
```

กำหนดค่าตัวแปรสภาพแวดล้อม Azure OpenAI ที่ใช้ในโน้ตบุ๊ก:

```bash
AZURE_OPENAI_ENDPOINT=...
AZURE_OPENAI_API_KEY=...
AZURE_OPENAI_CHAT_DEPLOYMENT_NAME=...
# ตัวเลือก: ค่าเริ่มต้นเป็นเวอร์ชัน API ล่าสุดเมื่อไม่ได้ระบุ
AZURE_OPENAI_API_VERSION=...
```

## ภาพรวมสถาปัตยกรรม

โน้ตบุ๊กนี้แสดงโฟลว์การทำงานอัตโนมัติเบราว์เซอร์แบบผสม:

1. Chrome เริ่มต้นด้วย CDP เปิดใช้งาน เพื่อให้ทั้ง Playwright และ Browser-Use ใช้เซสชันเบราว์เซอร์เดียวกันได้
2. ตัวแทน Browser-Use จัดการงานนำทางแบบเปิด เช่น การเปิด Airbnb, ปิดป็อปอัพ และค้นหาสตอกโฮล์ม
3. หน้าที่ใช้งานจะถูกตรวจสอบด้วยสคีม่า Pydantic ที่มีโครงสร้างเพื่อดึงชื่อรายการ, ราคาต่อคืน, คะแนน และ URLs
4. ตรรกะใน Python เปรียบเทียบรายการที่ดึงมาและเน้นผลลัพธ์ที่ถูกที่สุด

แนวทางนี้ช่วยรักษาการวิเคราะห์ด้วยวิสัยทัศน์ที่ยืดหยุ่นซึ่ง Browser-Use ถนัดไว้ ในขณะเดียวกันก็ยังให้การควบคุมเบราว์เซอร์ที่แน่นอนได้เมื่อคุณต้องการ

## ประเด็นสำคัญและแนวปฏิบัติที่ดีที่สุด

### เมื่อใดควรใช้ Agent หรือ Actor

| สถานการณ์ | ใช้ Agent | ใช้ Actor |
|------------|-----------|-----------|
| เค้าโครงแบบไดนามิก | ใช่, AI ปรับตัวกับการเปลี่ยนแปลงของหน้าได้ | ไม่, ตัวเลือกที่ละเอียดอ่อนอาจใช้งานไม่ได้ |
| โครงสร้างที่ทราบชัด | ไม่, agent ช้ากว่าการควบคุมโดยตรง | ใช่, รวดเร็วและแม่นยำ |
| การค้นหาองค์ประกอบ | ใช่, ภาษาโดยธรรมชาติเหมาะสม | ไม่, ต้องใช้ตัวเลือกที่ชัดเจน |
| การควบคุมเวลา | ไม่, คาดเดาได้น้อยกว่า | ใช่, ควบคุมการรอและลองใหม่ได้เต็มที่ |
| โฟลว์งานซับซ้อน | ใช่, จัดการสถานะ UI ที่ไม่คาดคิดได้ | ไม่, ต้องมีการแยกสาขาชัดเจน |

### แนวปฏิบัติที่ดีที่สุดของ Browser-Use

1. เริ่มด้วย agent สำหรับการสำรวจและนำทางแบบไดนามิก
2. เปลี่ยนไปใช้การควบคุมหน้าเว็บโดยตรงเมื่อการโต้ตอบคาดเดาได้
3. ใช้โมเดลผลลัพธ์แบบมีโครงสร้างเพื่อให้ข้อมูลที่ดึงมาถูกตรวจสอบและปลอดภัยตามชนิดข้อมูล
4. เพิ่มการหน่วงเวลาหลังการกระทำที่ก่อให้เกิดการเปลี่ยนแปลง UI ที่มองเห็นได้
5. ถ่ายภาพหน้าจอระหว่างการทำซ้ำเพื่อให้แก้ไขปัญหาได้ง่ายขึ้น
6. คาดหวังว่าเว็บไซต์จะเปลี่ยนแปลง และออกแบบกลยุทธ์การสำรองข้อมูลสำหรับป็อปอัพและการเปลี่ยนแปลงเค้าโครง
7. ผสมผสานแบบ agent และ actor เพื่อให้ได้ทั้งความยืดหยุ่นและความแม่นยำ

### การใช้งานในโลกจริง

- การจองท่องเที่ยวและการตรวจสอบราคา
- การเปรียบเทียบราคาและตรวจสอบความพร้อมของอีคอมเมิร์ซ
- การดึงข้อมูลที่มีโครงสร้างจากเว็บไซต์แบบไดนามิก
- การทดสอบและตรวจสอบ UI โดยใช้วิสัยทัศน์
- การตรวจสอบเว็บไซต์และการแจ้งเตือน
- การกรอกแบบฟอร์มอัตโนมัติในหลายขั้นตอน

## ตัวอย่างโลกจริง: Microsoft Project Opal

ตัวแทนที่คุณสร้างในบทเรียนนี้เป็นเวอร์ชันท้องถิ่นเล็กๆ ของ **computer use agent (CUA)** — โปรแกรมที่ขับเคลื่อนเบราว์เซอร์ในแบบที่คนทำได้ Microsoft นำแนวคิดเดียวกันนี้เข้าสู่ภาคธุรกิจด้วย **[Project Opal (Frontier)](https://support.microsoft.com/en-us/microsoft-365-copilot/get-started-with-project-opal-frontier)** ซึ่งเป็นความสามารถใน Microsoft 365 Copilot

ด้วย Project Opal คุณบรรยายงานและตัวแทนทำงานแทนคุณโดยใช้ **computer use บน Windows 365 Cloud PC ที่ปลอดภัย** ทำงานผ่านแอป เว็บไซต์ และข้อมูลบนเบราว์เซอร์ขององค์กรของคุณ มันทำงาน **แบบอะซิงโครนัสในพื้นหลัง** และคุณสามารถชี้นำงานหรือเข้าควบคุมได้ทุกเวลา งานตัวอย่างได้แก่:

- จัดการคำขอสมาชิกกลุ่มความปลอดภัย
- รวบรวมและตรวจสอบหลักฐานตรวจสอบสำหรับการทบทวนความสอดคล้อง
- คัดกรองเหตุการณ์ IT (อัปเดตสถานะตั๋ว, กำหนดเจ้าของ, ปิดตั๋วซ้ำ)
- รวบรวมข้อมูล Excel เข้าสู่รายงานทางการเงิน

Opal เป็นแหล่งอ้างอิงที่ดีสำหรับตัวแทนใช้คอมพิวเตอร์ที่ **มีคุณภาพระดับการผลิตและเชื่อถือได้** — และช่วยเสริมแนวคิดจากบทเรียนก่อนหน้า:

| แนวคิดในหลักสูตรนี้ | Project Opal ใช้สิ่งนี้อย่างไร |
|-----------------------|---------------------------------|
| **มนุษย์ร่วมดำเนินงาน** (บทเรียน 06) | Opal หยุดรอข้อมูลเข้าสู่ระบบ, ข้อมูลละเอียดอ่อน หรือคำสั่งที่คลุมเครือ และไม่ป้อนรหัสผ่านหรือส่งฟอร์มโดยไม่ยืนยัน คุณสามารถ *Take Control* และ *Return Control* ระหว่างทำงานได้ |
| **ตัวแทนที่เชื่อถือได้และปลอดภัย** (บทเรียน 06 & 18) | ทำงานใน Windows 365 Cloud PC ที่แยกอิสระ, จำกัดแค่เบราว์เซอร์เป็นค่าเริ่มต้น (ไม่อนุญาตการเข้าถึงคอมพิวเตอร์อื่น ๆ, บังคับใช้ผ่าน Intune), ใช้ตัวตนของคุณเพื่อเข้าถึงเฉพาะที่ได้รับอนุญาตเท่านั้น และบันทึกทุกการกระทำเพื่อการตรวจสอบได้ |
| **การวางแผนและการเมตาคอกนิชัน** (บทเรียน 07 & 09) | Opal สร้างแผนงานก่อน จากนั้นดูแลตรรกะของตัวเองในแต่ละขั้นตอนและหยุดหากตรวจพบกิจกรรมที่น่าสงสัย |
| **ความสามารถ/เครื่องมือที่ใช้ซ้ำได้** (บทเรียน 04) | **Skills** ช่วยให้คุณเขียนคำสั่งสำหรับงานที่ทำซ้ำได้ (นำเข้าจากไฟล์ `.md` หรือสร้างด้วย Opal) และใช้ซ้ำได้ในการสนทนา |

> **สถานะ:** Project Opal ปัจจุบันได้รับการให้บริการสำหรับผู้ใช้ในโปรแกรม [Frontier early access](https://adoption.microsoft.com/copilot/frontier-program/) พร้อมการสมัคร Microsoft 365 Copilot และผู้ดูแลระบบของคุณต้องตั้งค่าให้เสร็จสมบูรณ์ เนื่องจากเป็นฟีเจอร์ทดลองของ Frontier ความสามารถอาจเปลี่ยนแปลงได้ตามเวลา
