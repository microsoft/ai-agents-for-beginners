เมื่อพูดถึงประโยชน์เฉพาะของการสร้าง AI Agents มีสองเรื่องที่มักจะถูกพูดถึงเป็นหลัก ได้แก่ ความสามารถในการเรียกใช้เครื่องมือเพื่อทำงานให้สำเร็จ และความสามารถในการพัฒนาตัวเองได้ตลอดเวลา ความจำคือพื้นฐานของการสร้างเอเจนต์ที่สามารถพัฒนาตัวเองให้สร้างประสบการณ์ที่ดียิ่งขึ้นสำหรับผู้ใช้ของเรา

## เข้าใจความจำของ AI Agent

โดยหลักการแล้ว **ความจำสำหรับ AI agents หมายถึงกลไกที่ช่วยให้เอเจนต์เก็บรักษาและเรียกคืนข้อมูลได้** ข้อมูลนี้อาจเป็นรายละเอียดเฉพาะเกี่ยวกับบทสนทนา, ความชอบของผู้ใช้, การกระทำที่ผ่านมา หรือแม้แต่รูปแบบที่ได้เรียนรู้

หากไม่มีความจำ แอปพลิเคชัน AI มักจะอยู่ในสถานะที่ไม่มีประวัติข้อมูล (stateless) ซึ่งหมายความว่าการโต้ตอบแต่ละครั้งเริ่มต้นจากศูนย์ ส่งผลให้ประสบการณ์ของผู้ใช้ซ้ำซากและน่าหงุดหงิดเพราะเอเจนต์ "ลืม" บริบทหรือความชอบที่เคยมีมาก่อน

### ทำไมความจำจึงสำคัญ?

ความฉลาดของเอเจนต์ผูกพันอย่างลึกซึ้งกับความสามารถในการเรียกคืนและใช้ข้อมูลในอดีต ความจำช่วยให้เอเจนต์สามารถเป็น:

• **สะท้อนกลับ**: เรียนรู้จากการกระทำและผลลัพธ์ที่ผ่านมา

• **โต้ตอบ**: รักษาบริบทของการสนทนาอย่างต่อเนื่อง

• **ริเริ่มและตอบสนอง**: คาดการณ์ความต้องการหรือตอบสนองอย่างเหมาะสมตามข้อมูลในอดีต

• **อิสระ**: ทำงานได้อย่างเป็นอิสระมากขึ้นโดยดึงความรู้ที่เก็บไว้มาใช้

เป้าหมายของการปรับใช้ความจำคือทำให้เอเจนต์มีความ **น่าเชื่อถือและมีความสามารถเพิ่มขึ้น**

### ประเภทของความจำ

#### Working Memory

คิดถึงสิ่งนี้เหมือนกระดาษร่าง ที่เอเจนต์ใช้ในขณะทำงานหรือกระบวนการความคิดที่กำลังดำเนินอยู่ มันเก็บข้อมูลทันทีที่จำเป็นสำหรับการประมวลผลขั้นตอนถัดไป

สำหรับ AI agents, working memory มักจะจับเอาข้อมูลที่เกี่ยวข้องมากที่สุดจากบทสนทนา แม้ว่าประวัติแชททั้งหมดจะยาวหรือถูกตัดทอน มันมุ่งเน้นไปที่การดึงหลักสำคัญ เช่น ข้อกำหนด, ข้อเสนอ, การตัดสินใจ และการกระทำ

**ตัวอย่าง Working Memory**

ในตัวแทนจองท่องเที่ยว working memory อาจจับคำขอปัจจุบันของผู้ใช้ เช่น "ฉันต้องการจองทริปไปปารีส" ข้อกำหนดเฉพาะนี้จะถูกเก็บในบริบททันทีของเอเจนต์เพื่อชี้นำการโต้ตอบในปัจจุบัน

#### Short Term Memory

ความจำประเภทนี้เก็บข้อมูลไว้ชั่วระยะเวลาของบทสนทนาหรือเซสชันเดียว มันคือบริบทของแชทปัจจุบัน ช่วยให้เอเจนต์สามารถอ้างอิงกลับไปยังรอบตะกูลก่อนหน้าในการสนทนาได้

ในตัวอย่างการใช้งาน Python SDK ของ [Microsoft Agent Framework](https://github.com/microsoft/agent-framework) ตัวนี้จะเชื่อมโยงกับ `AgentSession` ซึ่งสร้างด้วย `agent.create_session()` เซสชันนี้คือความจำระยะสั้นที่ฝังมาในเฟรมเวิร์ก: มันเก็บบริบทของบทสนทนาไว้ในขณะที่เซสชันนั้นยังถูกใช้อยู่ แต่บริบทนี้จะไม่ถูกเก็บถาวรเมื่อเซสชันจบลงหรือแอปพลิเคชันรีสตาร์ท ใช้ความจำระยะยาวสำหรับข้อมูลข้อเท็จจริงและความชอบที่ต้องเก็บต่อเนื่องข้ามเซสชัน ซึ่งมักจะใช้ฐานข้อมูลดรรชนีเวกเตอร์ หรือที่เก็บถาวรอื่นๆ

**ตัวอย่าง Short Term Memory**

ถ้าผู้ใช้ถามว่า "ตั๋วเครื่องบินไปปารีสราคาเท่าไหร่?" แล้วตามด้วย "แล้วที่พักล่ะ?" ความจำระยะสั้นจะทำให้เอเจนต์รู้ว่า "ที่นั่น" หมายถึง "ปารีส" ในบทสนทนาเดียวกัน

#### Long Term Memory

นี่คือข้อมูลที่ยังคงอยู่ข้ามหลายบทสนทนาหรือหลายเซสชัน ช่วยให้เอเจนต์จดจำความชอบของผู้ใช้, การโต้ตอบในอดีต หรือความรู้ทั่วไปเป็นเวลานาน ซึ่งสำคัญสำหรับการปรับแต่งเฉพาะบุคคล

**ตัวอย่าง Long Term Memory**

ความจำระยะยาวอาจเก็บข้อมูลว่า "เบนชอบเล่นสกีและกิจกรรมกลางแจ้ง ชอบกาแฟที่มีวิวภูเขา และต้องการหลีกเลี่ยงลานสกีขั้นสูงเพราะเคยบาดเจ็บ" ข้อมูลนี้เรียนรู้จากการโต้ตอบก่อนหน้า ส่งผลต่อคำแนะนำในการวางแผนท่องเที่ยวในอนาคต ซึ่งมีความเป็นส่วนตัวสูง

#### Persona Memory

ความจำเฉพาะประเภทนี้ช่วยให้เอเจนต์พัฒนา "บุคลิกภาพ" หรือ "บุคลิก" ที่สอดคล้องกัน มันช่วยให้เอเจนต์จำรายละเอียดเกี่ยวกับตัวมันเองหรือบทบาทที่ตั้งใจจะมี ทำให้การโต้ตอบราบรื่นและมีจุดโฟกัสมากขึ้น

**ตัวอย่าง Persona Memory**

ถ้าเอเจนต์ท่องเที่ยวถูกออกแบบให้เป็น "ผู้วางแผนสกีผู้เชี่ยวชาญ" persona memory จะเสริมบทบาทนี้ ช่วยให้การตอบสนองสอดคล้องกับน้ำเสียงและความรู้ของผู้เชี่ยวชาญ

#### Workflow/Episodic Memory

ความจำนี้เก็บลำดับขั้นตอนที่เอเจนต์ทำระหว่างงานที่ซับซ้อน รวมถึงความสำเร็จและความล้มเหลว เหมือนการจำ "ตอน" หรือประสบการณ์ที่ผ่านมาเพื่อใช้เรียนรู้

**ตัวอย่าง Episodic Memory**

ถ้าเอเจนต์พยายามจองเที่ยวบินเฉพาะแต่ล้มเหลวเพราะไม่มีที่นั่ง episodic memory จะบันทึกความล้มเหลวนี้ ช่วยให้เอเจนต์ลองเที่ยวบินทางเลือกหรือแจ้งผู้ใช้เกี่ยวกับปัญหาได้อย่างมีข้อมูลมากขึ้นในการลองครั้งถัดไป

#### Entity Memory

เกี่ยวข้องกับการสกัดและจำเอนทิตีที่เฉพาะเจาะจง (เช่น บุคคล, สถานที่ หรือสิ่งของ) และเหตุการณ์จากบทสนทนา ช่วยให้เอเจนต์สร้างความเข้าใจแบบมีโครงสร้างเกี่ยวกับองค์ประกอบหลักที่ถูกพูดถึง

**ตัวอย่าง Entity Memory**

จากการสนทนาเกี่ยวกับทริปที่ผ่านมา เอเจนต์อาจสกัดคำว่า "ปารีส," "หอไอเฟล," และ "ทานอาหารค่ำที่ร้าน Le Chat Noir" เป็นเอนทิตี ในการโต้ตอบครั้งหน้า เอเจนต์จะจำ "Le Chat Noir" ได้และเสนอตัวช่วยจองใหม่ที่นั่น

#### Structured RAG (Retrieval Augmented Generation)

แม้ RAG จะเป็นเทคนิคที่กว้างกว่า แต่ "Structured RAG" ถูกเน้นว่าเป็นเทคโนโลยีความจำที่ทรงพลัง มันสกัดข้อมูลเชิงโครงสร้างเข้มข้นจากแหล่งต่างๆ (บทสนทนา, อีเมล, รูปภาพ) และใช้เพื่อเพิ่มความแม่นยำ การเรียกคืนข้อมูล และความเร็วในการตอบกลับ แตกต่างจาก RAG แบบคลาสสิกที่พึ่งพาความเหมือนเชิงความหมายเท่านั้น Structured RAG ทำงานร่วมกับโครงสร้างข้อมูลโดยกำเนิด

**ตัวอย่าง Structured RAG**

แทนที่จะจับคู่แค่คำหลัก Structured RAG อาจแยกข้อมูลเที่ยวบิน (จุดหมาย, วันที่, เวลา, สายการบิน) จากอีเมลและจัดเก็บอย่างเป็นระบบ ซึ่งช่วยให้สามารถสอบถามอย่างแม่นยำเช่น "ฉันจองเที่ยวบินไปปารีสในวันอังคารวันไหน?"

## การติดตั้งและการจัดเก็บความจำ

การติดตั้งความจำสำหรับ AI agents เกี่ยวข้องกับกระบวนการจัดการความจำอย่างเป็นระบบ ซึ่งรวมถึงการสร้าง, เก็บ, ดึงข้อมูล, รวมข้อมูล, อัปเดต และแม้แต่ "ลืม" (หรือลบ) ข้อมูล โดยการดึงข้อมูลเป็นส่วนที่สำคัญเป็นพิเศษ

### เครื่องมือความจำเฉพาะ

#### Mem0

วิธีหนึ่งในการจัดเก็บและจัดการความจำของเอเจนต์คือใช้เครื่องมือเฉพาะอย่าง Mem0 Mem0 ทำงานเป็นชั้นความจำถาวรที่ช่วยให้เอเจนต์เรียกคืนการโต้ตอบที่เกี่ยวข้อง, เก็บความชอบของผู้ใช้และบริบทข้อเท็จจริง และเรียนรู้จากความสำเร็จและความล้มเหลวเมื่อเวลาผ่านไป แนวคิดคือเอเจนต์ที่ไม่มีสถานะกลายเป็นเอเจนต์ที่มีสถานะ

มันทำงานผ่าน **กระบวนการความจำสองขั้นตอน: การสกัดและการอัปเดต** ขั้นแรก ข้อความที่เพิ่มในเธรดของเอเจนต์จะถูกส่งไปยังบริการ Mem0 ซึ่งใช้ Large Language Model (LLM) สรุปประวัติการสนทนาและสกัดความจำใหม่ จากนั้น ขั้นตอนอัปเดตโดยใช้ LLM จะกำหนดว่าจะเพิ่ม, แก้ไข หรือ ลบความจำเหล่านี้หรือไม่ โดยเก็บไว้ในคลังข้อมูลแบบลูกผสมที่อาจรวมถึงฐานข้อมูลแบบเวกเตอร์, กราฟ และกุญแจ-ค่า ระบบนี้ยังรองรับความจำหลากหลายประเภทและสามารถรวมความจำแบบกราฟเพื่อจัดการความสัมพันธ์ระหว่างเอนทิตี

#### Cognee

อีกแนวทางที่ทรงพลังคือการใช้ **Cognee** ซึ่งเป็น semantic memory แบบโอเพนซอร์สสำหรับ AI agents ที่เปลี่ยนข้อมูลโครงสร้างและไม่มีโครงสร้างเป็น knowledge graph ที่สามารถค้นหาได้ซึ่งรองรับด้วย embeddings Cognee ให้สถาปัตยกรรมแบบ dual-store รวมการค้นหาโดยความเหมือนเวกเตอร์กับความสัมพันธ์แบบกราฟ ช่วยให้เอเจนต์เข้าใจไม่เพียงแค่ข้อมูลที่คล้ายกันแต่ยังเข้าใจว่าคอนเซ็ปต์เกี่ยวข้องกันอย่างไร

มันโดดเด่นที่ **การดึงข้อมูลแบบลูกผสม** ที่ผสมผสานความเหมือนเวกเตอร์, โครงสร้างกราฟ และตรรกะของ LLM - ตั้งแต่การค้นหาชิ้นข้อมูลดิบจนถึงการตอบคำถามที่มีความเข้าใจกราฟ ระบบนี้รักษา **ความจำที่มีชีวิต** ซึ่งพัฒนาและเติบโตในขณะที่ยังคงค้นหาได้ในฐานะกราฟที่เชื่อมต่อเดียว สนับสนุนทั้งบริบทเซสชันระยะสั้นและความจำถาวรระยะยาว

ตัวอย่างโน้ตบุ๊ก Cognee ([13-agent-memory-cognee.ipynb](./13-agent-memory-cognee.ipynb)) แสดงการสร้างชั้นความจำแบบรวมนี้ พร้อมตัวอย่างการนำเข้าข้อมูลหลากหลาย, การแสดงภาพ knowledge graph และการค้นหาด้วยกลยุทธ์ต่างๆ ที่เหมาะกับความต้องการเฉพาะของเอเจนต์

### การจัดเก็บความจำด้วย RAG

นอกเหนือจากเครื่องมือความจำเฉพาะเช่น Mem0 คุณสามารถใช้บริการค้นหาที่แข็งแกร่ง เช่น **Azure AI Search เป็นแบ็คเอนด์สำหรับการจัดเก็บและดึงความจำ** โดยเฉพาะสำหรับ Structured RAG

สิ่งนี้ช่วยให้คุณทำให้คำตอบของเอเจนต์อิงกับข้อมูลของคุณเอง เพื่อรับคำตอบที่เกี่ยวข้องและแม่นยำมากขึ้น Azure AI Search สามารถใช้เก็บความจำการเดินทางของผู้ใช้, แคตตาล็อกสินค้า หรือความรู้เฉพาะในโดเมนอื่นๆ

Azure AI Search รองรับความสามารถเช่น **Structured RAG** ที่ยอดเยี่ยมในการสกัดและดึงข้อมูลที่เชิงโครงสร้างและเข้มข้นจากชุดข้อมูลใหญ่ เช่น ประวัติการสนทนา, อีเมล หรือแม้แต่รูปภาพ ซึ่งให้ความแม่นยำและการเรียกคืนข้อมูลที่เหนือกว่าการใช้ text chunking และ embedding แบบดั้งเดิม

## การทำให้ AI Agents พัฒนาตัวเองได้

รูปแบบทั่วไปของเอเจนต์ที่พัฒนาตัวเองคือการเพิ่มเอเจนต์อีกตัวหนึ่งที่เรียกว่า **"knowledge agent"** เอเจนต์แยกนี้จะสังเกตบทสนทนาหลักระหว่างผู้ใช้และเอเจนต์หลัก หน้าที่ของมันคือ:

1. **ระบุข้อมูลที่มีค่า**: ตรวจสอบว่าส่วนใดของบทสนทนาควรถูกเก็บเป็นความรู้ทั่วไปหรือความชอบเฉพาะผู้ใช้

2. **สกัดและสรุป**: กลั่นกรองการเรียนรู้หรือความชอบสำคัญจากบทสนทนา

3. **เก็บไว้ในฐานความรู้**: เก็บรักษาข้อมูลที่สกัดไว้ โดยปกติในฐานข้อมูลเวกเตอร์ เพื่อให้สามารถดึงมาใช้ได้ในภายหลัง

4. **เสริมการค้นหาในอนาคต**: เมื่อผู้ใช้เริ่มค้นหาใหม่ knowledge agent จะดึงข้อมูลที่เกี่ยวข้องมาแนบกับ prompt ของผู้ใช้ เพื่อให้เอเจนต์หลักมีบริบทสำคัญ (คล้ายกับ RAG)

### การปรับแต่งสำหรับความจำ

• **การจัดการความหน่วงเวลา**: เพื่อหลีกเลี่ยงการชะลอการโต้ตอบกับผู้ใช้ ใช้โมเดลที่ถูกกว่าและเร็วกว่าในการตรวจสอบเบื้องต้นว่าข้อมูลใดมีคุณค่าที่จะจัดเก็บหรือดึงก่อน แล้วค่อยเรียกใช้กระบวนการสกัด/ดึงข้อมูลที่ซับซ้อนเมื่อจำเป็น

• **การบำรุงรักษาฐานความรู้**: สำหรับฐานความรู้ที่เติบโต ข้อมูลที่ใช้น้อยสามารถย้ายไปที่ "cold storage" เพื่อจัดการค่าใช้จ่าย
