# 🔄 การทำงานของเอเย่นต์พื้นฐานกับ Azure OpenAI (Responses API) (.NET)

## 📋 สอนการประสานงาน Workflow

สมุดบันทึกนี้สาธิตวิธีการสร้าง **workflow ของเอเย่นต์** ที่ซับซ้อนโดยใช้ Microsoft Agent Framework สำหรับ .NET และ Azure OpenAI (Responses API) คุณจะได้เรียนรู้การสร้างกระบวนการทางธุรกิจหลายขั้นตอนที่เอเย่นต์ AI ทำงานร่วมกันเพื่อบรรลุภารกิจซับซ้อนผ่านรูปแบบการประสานงานที่มีโครงสร้าง

## 🎯 วัตถุประสงค์การเรียนรู้

### 🏗️ **พื้นฐานสถาปัตยกรรม Workflow**
- **Workflow Builder**: ออกแบบและประสานงานกระบวนการ AI หลายขั้นตอนที่ซับซ้อน
- **การประสานงานเอเย่นต์**: ประสานงานเอเย่นต์เฉพาะทางหลายตัวใน workflow
- **Azure OpenAI (Responses API)**: ใช้ Azure OpenAI Responses API ใน workflow
- **ออกแบบ workflow แบบเห็นภาพ**: สร้างและแสดงโครงสร้าง workflow เพื่อความเข้าใจที่ดีขึ้น

### 🔄 **รูปแบบการประสานงานกระบวนการ**
- **การประมวลผลตามลำดับ**: เชื่อมโยงงานเอเย่นต์หลายงานตามลำดับตรรกะ
- **การจัดการสถานะ**: รักษาบริบทและข้อมูลไหลผ่านแต่ละขั้นตอนของ workflow
- **การจัดการข้อผิดพลาด**: นำไปใช้การกู้คืนข้อผิดพลาดที่มีความทนทานและความยืดหยุ่นของ workflow
- **การเพิ่มประสิทธิภาพ**: ออกแบบ workflow มีประสิทธิภาพสำหรับการดำเนินงานในระดับองค์กร

### 🏢 **แอปพลิเคชัน workflow สำหรับองค์กร**
- **การทำงานอัตโนมัติกระบวนการธุรกิจ**: อัตโนมัติกระบวนการองค์กรที่ซับซ้อน
- **สายการผลิตเนื้อหา**: workflow บรรณาธิการพร้อมขั้นตอนตรวจสอบและอนุมัติ
- **การบริการลูกค้าอัตโนมัติ**: การแก้ไขคำถามลูกค้าหลายขั้นตอน
- **workflow การประมวลผลข้อมูล**: workflow ETL พร้อมการแปลงข้อมูลที่ขับเคลื่อนด้วย AI

## ⚙️ ข้อกำหนดเบื้องต้นและการตั้งค่า

### 📦 **แพ็คเกจ NuGet ที่ต้องใช้**

ตัวอย่าง workflow นี้ใช้แพ็คเกจ .NET สำคัญหลายตัว:

```xml
<!-- Core AI Framework -->
<PackageReference Include="Microsoft.Extensions.AI" Version="9.9.0" />

<!-- Azure OpenAI (Responses API) -->
<PackageReference Include="Azure.AI.OpenAI" Version="2.1.0" />
<PackageReference Include="Azure.Identity" Version="1.13.1" />

<!-- Agent Framework (Local Development) -->
<!-- Microsoft.Agents.AI.dll - Core agent abstractions -->
<!-- Microsoft.Agents.AI.OpenAI.dll - Azure OpenAI (Responses API) integration -->

<!-- Configuration and Environment -->
<PackageReference Include="DotNetEnv" Version="3.1.1" />
```

### 🔑 **การกำหนดค่า Azure OpenAI**

**การตั้งค่าสภาพแวดล้อม (.env file):**
```env
AZURE_OPENAI_ENDPOINT=https://<your-resource>.openai.azure.com
AZURE_OPENAI_DEPLOYMENT=gpt-4o-mini
```

**การเข้าถึง Azure OpenAI:**
1. สร้างทรัพยากร Azure OpenAI ในพอร์ทัล Azure
2. ปรับใช้งานโมเดล (เช่น `gpt-4o-mini`) และจดชื่อการปรับใช้งานไว้
3. เข้าสู่ระบบด้วย `az login` และตั้งค่าสิ่งแวดล้อมตามตัวอย่างด้านบน

### 🏗️ **ภาพรวมสถาปัตยกรรม Workflow**

```mermaid
graph TD
    A[ตัวสร้างเวิร์กโฟลว์] --> B[ทะเบียนเอเย่นต์]
    B --> C[เครื่องมือประมวลผลเวิร์กโฟลว์]
    C --> D[เอเย่นต์ 1: ผู้สร้างเนื้อหา]
    C --> E[เอเย่นต์ 2: ผู้ตรวจสอบเนื้อหา] 
    D --> F[ผลลัพธ์เวิร์กโฟลว์]
    E --> F
    G[Azure OpenAI (API การตอบกลับ)] --> D
    G --> E
```

**ส่วนประกอบหลัก:**
- **WorkflowBuilder**: เครื่องยนต์ประสานงานหลักสำหรับออกแบบ workflow
- **AIAgent**: เอเย่นต์เฉพาะทางแต่ละตัวที่มีความสามารถเฉพาะ
- **Azure OpenAI Client**: การผนวกรวม Azure OpenAI Responses API
- **Execution Context**: จัดการสถานะและการไหลของข้อมูลระหว่างขั้นตอน workflow

## 🎨 **รูปแบบการออกแบบ workflow สำหรับองค์กร**

### 📝 **workflow การผลิตเนื้อหา**
```
User Request → Content Generation → Quality Review → Final Output
```

### 🔍 **สายการประมวลผลเอกสาร**
```
Document Input → Analysis → Extraction → Validation → Structured Output
```

### 💼 **workflow ข่าวกรองธุรกิจ**
```
Data Collection → Processing → Analysis → Report Generation → Distribution
```

### 🤝 **การบริการลูกค้าอัตโนมัติ**
```
Customer Inquiry → Classification → Processing → Response Generation → Follow-up
```

## 🏢 **ประโยชน์สำหรับองค์กร**

### 🎯 **ความน่าเชื่อถือและการขยายตัว**
- **การทำงานที่กำหนดผลลัพธ์ได้**: ผลลัพธ์ workflow ที่สม่ำเสมอและทำซ้ำได้
- **การกู้คืนข้อผิดพลาด**: การจัดการความล้มเหลวได้อย่างนุ่มนวลในทุกขั้นตอน workflow
- **การตรวจสอบประสิทธิภาพ**: ติดตามเมตริกการทำงานและโอกาสในการปรับปรุง
- **การจัดการทรัพยากร**: การจัดสรรและการใช้ทรัพยากรโมเดล AI อย่างมีประสิทธิภาพ

### 🔒 **ความปลอดภัยและการปฏิบัติตามข้อกำหนด**
- **การรับรองความถูกต้องอย่างปลอดภัย**: การรับรองตัวตน Microsoft Entra ID ผ่าน `az login` (AzureCliCredential)
- **เส้นทางตรวจสอบ**: การบันทึกการทำงานของ workflow และจุดตัดสินใจอย่างครบถ้วน
- **การควบคุมการเข้าถึง**: สิทธิ์ละเอียดในการทำงานและตรวจสอบ workflow
- **ความเป็นส่วนตัวของข้อมูล**: การจัดการข้อมูลที่ละเอียดอ่อนอย่างปลอดภัยตลอด workflow

### 📊 **การสังเกตและการจัดการ**
- **ออกแบบ workflow แบบเห็นภาพ**: การแสดงภาพกระแสและความสัมพันธ์ของกระบวนการอย่างชัดเจน
- **การตรวจสอบการทำงาน**: ติดตามความก้าวหน้าและประสิทธิภาพ workflow แบบเรียลไทม์
- **การรายงานข้อผิดพลาด**: การวิเคราะห์ข้อผิดพลาดและขีดความสามารถการแก้ปัญหาอย่างละเอียด
- **การวิเคราะห์ประสิทธิภาพ**: เมตริกสำหรับการปรับปรุงและวางแผนความจุ

มาสร้าง workflow AI สำหรับองค์กรขั้นต้นของคุณ! 🚀

## 💻 การรันโค้ด

โค้ดตัวอย่างสมบูรณ์อยู่ในไฟล์ `01.dotnet-agent-framework-workflow-ghmodel-basic.cs` ไฟล์นี้สาธิต:

1. **การกำหนดค่าสภาพแวดล้อม** - โหลดการตั้งค่า Azure OpenAI จากไฟล์ `.env`
2. **การตั้งค่า Azure OpenAI Client** - กำหนดค่าไคลเอ็นต์ให้ใช้ Azure OpenAI Responses API
3. **การสร้างเอเย่นต์** - กำหนดเอเย่นต์เฉพาะทาง (Front Desk และ Concierge)
4. **Workflow Builder** - สร้าง workflow แบบหลายเอเย่นต์ที่ประมวลผลตามลำดับ
5. **การดำเนินการ workflow** - รัน workflow พร้อมผลลัพธ์แบบสตรีม

```bash
# ทำให้สคริปต์สามารถรันได้ (Unix/Linux/macOS)
chmod +x 01.dotnet-agent-framework-workflow-ghmodel-basic.cs

# รันเวิร์กโฟลว์
./01.dotnet-agent-framework-workflow-ghmodel-basic.cs
```


### 📝 ผลลัพธ์ที่คาดหวัง

workflow จะ:
1. รับคำขอจุดหมายปลายทางการเดินทางของคุณ ("ฉันต้องการไปปารีส")
2. เอเย่นต์ Front Desk ให้คำแนะนำเริ่มต้น
3. เอเย่นต์ Concierge ตรวจสอบและปรับปรุงคำแนะนำ
4. ผลลัพธ์สุดท้ายแสดงสตรีมบทสนทนาเต็มรูปแบบ

### 🔧 การปรับแต่ง

คุณสามารถปรับแต่ง workflow โดย:
- แก้ไขคำสั่งเอเย่นต์เพื่อเปลี่ยนพฤติกรรมของพวกเขา
- เพิ่มเอเย่นต์มากขึ้นเพื่อสร้าง workflow หลายขั้นตอนที่ซับซ้อน
- เปลี่ยนข้อความของผู้ใช้เพื่อทดสอบสถานการณ์ต่าง ๆ
- ปรับขอบเขตของ workflow เพื่อสร้างรูปแบบการทำงานที่แตกต่างกัน
