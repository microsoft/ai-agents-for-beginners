# ⚡ กระบวนการทำงานตัวแทนพร้อมกันด้วย Azure OpenAI (Responses API) (.NET)

## 📋 บทเรียนการประมวลผลขนานประสิทธิภาพสูง

สมุดบันทึกนี้สาธิต **รูปแบบกระบวนการทำงานพร้อมกัน** โดยใช้ Microsoft Agent Framework สำหรับ .NET และ Azure OpenAI (Responses API) คุณจะได้เรียนรู้วิธีสร้างกระบวนการทำงานที่มีประสิทธิภาพสูงและประมวลผลขนานโดยเพิ่มกำลังการประมวลผลสูงสุดด้วยการรันตัวแทน AI หลายตัวพร้อมกันในขณะที่ยังคงรักษาการประสานงานและความสอดคล้องของข้อมูล

## 🎯 วัตถุประสงค์การเรียนรู้

### 🚀 **พื้นฐานการประมวลผลพร้อมกัน**
- **การรันตัวแทนแบบขนาน**: รันตัวแทน AI หลายตัวพร้อมกันเพื่อประสิทธิภาพสูงสุด
- **รูปแบบ Async/Await**: ใช้แบบแผนการเขียนโปรแกรม async ของ .NET เพื่อความมีประสิทธิภาพในการทำงานพร้อมกัน
- **Azure OpenAI (Responses API)**: ประสานการเรียกหลายคำขอพร้อมกันไปยัง Azure OpenAI Responses API
- **การจัดการทรัพยากร**: จัดการทรัพยากรโมเดล AI อย่างมีประสิทธิภาพระหว่างการดำเนินการพร้อมกัน

### 🏗️ **สถาปัตยกรรมการทำงานพร้อมกันขั้นสูง**
- **Task-Based Parallelism**: ใช้ .NET Task Parallel Library สำหรับการรันพร้อมกันที่เหมาะสมที่สุด
- **รูปแบบการซิงโครไนซ์**: ประสานงานตัวแทนพร้อมกันเพื่อหลีกเลี่ยงสภาวะเผชิญกัน (race conditions)
- **การกระจายโหลด**: แจกจ่ายงานอย่างมีประสิทธิภาพในความสามารถการประมวลผลพร้อมกันที่มีอยู่
- **ความทนทานต่อข้อผิดพลาด**: จัดการกับความล้มเหลวของตัวแทนเดี่ยวโดยไม่หยุดการทำงานทั้งหมด

### 🏢 **แอปพลิเคชันพร้อมกันสำหรับองค์กร**
- **การประมวลผลเอกสารปริมาณมาก**: ประมวลผลเอกสารหลายฉบับพร้อมกัน
- **การวิเคราะห์เนื้อหาแบบเรียลไทม์**: วิเคราะห์ข้อมูลสตรีมเข้าพร้อมกัน
- **การปรับแต่งการประมวลผลแบตช์**: เพิ่มกำลังการประมวลผลสำหรับงานข้อมูลขนาดใหญ่
- **การวิเคราะห์แบบหลายโหมด**: ประมวลผลเนื้อหาประเภทและรูปแบบต่าง ๆ พร้อมกัน

## 🏢 **ประโยชน์สำหรับองค์กรจากประสิทธิภาพ**

### ⚡ **ความสามารถในการประมวลผลและความขยายตัว**
- **สเกลประสิทธิภาพเชิงเส้น**: เพิ่มจำนวนตัวแทนพร้อมกันเพื่อเพิ่มกำลังการประมวลผล
- **การใช้ทรัพยากรสูงสุด**: ใช้ความสามารถของโมเดล AI ที่มีอยู่ได้อย่างเต็มที่
- **ลดเวลาการประมวลผล**: ลดเวลาลงอย่างมีนัยสำคัญด้วยการรันพร้อมกัน
- **การขยายแบบยืดหยุ่น**: ปรับจำนวนตัวแทนพร้อมกันได้ตามภาระงาน

### 🛡️ **ความน่าเชื่อถือและความทนทาน**
- **การแยกข้อผิดพลาด**: ความล้มเหลวของตัวแทนใดตัวแทนหนึ่งไม่กระทบงานของตัวแทนอื่น
- **การถดถอยอย่างนุ่มนวล**: ระบบยังทำงานต่อได้แม้ความสามารถตัวแทนลดลง
- **การกู้คืนจากข้อผิดพลาด**: กลไกการลองใหม่อัตโนมัติสำหรับงานที่ล้มเหลว
- **การกระจายโหลด**: แจกจ่ายงานอย่างเท่าเทียมกันไปยังตัวแทนที่มีอยู่

### 📊 **การตรวจสอบประสิทธิภาพ**
- **เมตริกการดำเนินงานพร้อมกัน**: ติดตามประสิทธิภาพของงานขนานทั้งหมด
- **วิเคราะห์การใช้ทรัพยากร**: เฝ้าติดตาม CPU, หน่วยความจำ และการใช้เครือข่าย
- **การวิเคราะห์ Throughput**: วัดผลกำไรจากการประมวลผลพร้อมกัน
- **การตรวจจับคอขวด**: ระบุและแก้ปัญหาข้อจำกัดด้านประสิทธิภาพ

### 🔧 **การพัฒนาและการปฏิบัติการ**
- **รูปแบบการเขียนโปรแกรมแบบ Async**: ใช้รูปแบบ async/await ที่พัฒนามาอย่างดีของ .NET

- **การจัดการข้อผิดพลาด**: การจัดการข้อผิดพลาดอย่างครอบคลุมสำหรับการทำงานพร้อมกัน
- **การสนับสนุนการดีบัก**: เครื่องมือดีบักใน Visual Studio สำหรับกระบวนการทำงานพร้อมกัน

## 💻 การรันโค้ด

การใช้งานเต็มรูปแบบอยู่ในไฟล์ `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs` ไฟล์นี้แสดงตัวอย่าง **กระบวนการทำงาน Fan-Out/Fan-In พร้อมกัน** สำหรับการวางแผนท่องเที่ยว:

### 🏗️ **สถาปัตยกรรมกระบวนการทำงาน**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**ส่วนประกอบหลัก:**

1. **ConcurrentStartExecutor**: กระจายคำขอจากผู้ใช้ไปยังตัวแทนทั้งหมดพร้อมกัน
2. **Researcher Agent**: วิเคราะห์สถานที่และสถานที่ท่องเที่ยวอย่างพร้อมกัน
3. **Planner Agent**: สร้างแผนการเดินทางละเอียดพร้อมกัน
4. **ConcurrentAggregationExecutor**: รวบรวมและผสานผลลัพธ์จากตัวแทนทั้งสอง

### 🎯 **รูปแบบ Fan-Out/Fan-In**

กระบวนการทำงานนี้สาธิตรูปแบบคลาสสิก **Fan-Out/Fan-In**:
- **Fan-Out**: ข้อความอินพุตหนึ่งข้อความถูกกระจายไปยังตัวแทนหลายตัวพร้อมกัน
- **ประมวลผลพร้อมกัน**: ตัวแทนหลายตัวทำงานขนานกันในงานเดียวกัน
- **Fan-In**: รวบรวมผลลัพธ์จากตัวแทนทั้งหมดและรวมเป็นผลลัพธ์เดียว

### 📝 ผลลัพธ์ที่คาดหวัง

กระบวนการทำงานจะ:
1. **ส่งคำขอออกไป**: ส่งข้อความ "Plan a trip to Seattle in December" ไปยังตัวแทนทั้งสอง
2. **ประมวลผลพร้อมกัน**: ตัวแทนทั้งสองทำงานพร้อมกัน:
   - Researcher ระบุสถานที่ท่องเที่ยวและรายละเอียด
   - Planner สร้างกำหนดการและแผนโลจิสติกส์
3. **รวบรวมผลลัพธ์**: รวมคำตอบทั้งสองเป็นผลลัพธ์ที่ครอบคลุม
4. **แสดงผล**: แสดงแผนการเดินทางที่รวมทุกข้อมูล

### 🔧 ตัวเลือกการปรับแต่ง

```csharp

    .Build();

// Update aggregation count

```

### 🎯 การใช้งานในโลกจริง

รูปแบบพร้อมกันนี้เหมาะสำหรับ:
- **การสร้างเนื้อหา**: นักเขียนหลายคนสร้างส่วนต่าง ๆ พร้อมกัน
- **การตรวจสอบโค้ด**: ผู้ตรวจสอบหลายคนวิเคราะห์โค้ดจากมุมมองต่าง ๆ
- **การวิจัยตลาด**: วิเคราะห์หลายส่วนตลาดพร้อมกัน
- **การประมวลผลเอกสาร**: ดึงข้อมูล วิเคราะห์ และตรวจสอบพร้อมกัน
- **การวิเคราะห์หลายมุมมอง**: รับความคิดเห็นหลากหลายบนอินพุตเดียวกัน

### 🔍 ทำความเข้าใจ Custom Executors

**ConcurrentStartExecutor:**
- ใช้ `IMessageHandler<string>` เพื่อรับอินพุตเป็นสตริง
- กระจายข้อความไปยังตัวแทนทั้งหมดที่เชื่อมต่อ
- ส่ง `TurnToken` เพื่อกระตุ้นการประมวลผลพร้อมกัน

**ConcurrentAggregationExecutor:**
- ใช้ `IMessageHandler<ChatMessage>` เพื่อรับคำตอบจากตัวแทน
- รวบรวมข้อความในรูปแบบที่ปลอดภัยจากเธรด
- รวมผลเมื่อตอบครบตามที่คาดหวัง
- ใช้ `context.YieldOutputAsync()` เพื่อส่งผลลัพธ์ขั้นสุดท้าย

### ⚡ ประโยชน์ด้านประสิทธิภาพ

**พร้อมกันกับแบบลำดับ:**
- แบบลำดับ: Agent1 (30 วินาที) → Agent2 (30 วินาที) = **รวม 60 วินาที**
- แบบพร้อมกัน: Agent1 (30 วินาที) || Agent2 (30 วินาที) = **รวม 30 วินาที**

**ปรับปรุง throughput**: เร็วขึ้นสูงสุด N เท่าสำหรับตัวแทนพร้อมกัน N ตัว (ขึ้นกับภาระงานและทรัพยากร)

### 🛡️ การจัดการข้อผิดพลาด
