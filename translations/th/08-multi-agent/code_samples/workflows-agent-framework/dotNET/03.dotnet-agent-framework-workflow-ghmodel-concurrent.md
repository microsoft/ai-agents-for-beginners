# ⚡ การทำงานพร้อมกันของ Agent Workflows กับ Azure OpenAI (Responses API) (.NET)

## 📋 บทเรียนประมวลผลแบบขนานประสิทธิภาพสูง

โน้ตบุ๊กนี้สาธิต **รูปแบบกระบวนการทำงานพร้อมกัน** โดยใช้ Microsoft Agent Framework สำหรับ .NET และ Azure OpenAI (Responses API) คุณจะได้เรียนรู้วิธีสร้างเวิร์กโฟลว์ที่ประมวลผลแบบขนานประสิทธิภาพสูงที่เพิ่มประสิทธิภาพสูงสุดด้วยการรัน AI agents หลายตัวพร้อมกันในขณะที่ยังคงความประสานงานและความสอดคล้องของข้อมูล

## 🎯 วัตถุประสงค์การเรียนรู้

### 🚀 **พื้นฐานการประมวลผลพร้อมกัน**
- **การรัน Agent แบบขนาน**: รัน agent AI หลายตัวพร้อมกันเพื่อประสิทธิภาพสูงสุด
- **รูปแบบ Async/Await**: ใช้โมเดลโปรแกรมแบบ async ของ .NET เพื่อประสิทธิภาพการทำงานพร้อมกัน
- **Azure OpenAI (Responses API)**: ประสานงานการเรียก API Azure OpenAI Responses หลายรายการพร้อมกัน
- **การจัดการทรัพยากร**: จัดการทรัพยากรโมเดล AI อย่างมีประสิทธิภาพข้ามการทำงานพร้อมกัน

### 🏗️ **สถาปัตยกรรมการทำงานพร้อมกันขั้นสูง**
- **การประมวลผลขนานด้วย Task**: ใช้ .NET Task Parallel Library สำหรับ execution พร้อมกันอย่างเหมาะสม
- **รูปแบบการประสานงาน**: ประสานงาน agent พร้อมกันในขณะที่หลีกเลี่ยงปัญหาการแข่งกัน
- **การกระจายโหลด**: แจกจ่ายงานอย่างมีประสิทธิภาพบนศักยภาพการประมวลผลพร้อมกันที่มี
- **ความทนทานต่อข้อผิดพลาด**: จัดการข้อผิดพลาดของ agent แต่ละตัวโดยไม่หยุดเวิร์กโฟลว์ทั้งหมด

### 🏢 **แอปพลิเคชันองค์กรพร้อมกัน**
- **การประมวลผลเอกสารจำนวนมาก**: ประมวลผลเอกสารหลายชิ้นพร้อมกัน
- **การวิเคราะห์เนื้อหาแบบเรียลไทม์**: วิเคราะห์ข้อมูลที่เข้ามาหลายสตรีมพร้อมกัน
- **การเพิ่มประสิทธิภาพการประมวลผลแบบชุด**: เพิ่มอัตราผ่านข้อมูลสำหรับงานประมวลผลข้อมูลขนาดใหญ่
- **การวิเคราะห์แบบมัลติโหมด**: การประมวลผลแบบขนานของประเภทและรูปแบบเนื้อหาที่แตกต่าง

## 💻 การรันโค้ด

การใช้งานสมบูรณ์พร้อมใช้งานในไฟล์ `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs` ไฟล์นี้สาธิต **เวิร์กโฟลว์แบบ Fan-Out/Fan-In พร้อมกัน** สำหรับแผนการเดินทาง:

### 🏗️ **สถาปัตยกรรมเวิร์กโฟลว์**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**ส่วนประกอบหลัก:**

1. **ConcurrentStartExecutor**: กระจายคำขอผู้ใช้ไปยัง agent ทุกตัวพร้อมกัน
2. **Researcher Agent**: วิเคราะห์จุดหมายและสถานที่ท่องเที่ยวพร้อมกัน
3. **Planner Agent**: สร้างแผนการเดินทางโดยละเอียดพร้อมกัน
4. **ConcurrentAggregationExecutor**: เก็บและรวมผลลัพธ์จากทั้งสอง agent

### 🎯 **รูปแบบ Fan-Out/Fan-In**

เวิร์กโฟลว์นี้แสดงรูปแบบคลาสสิก **Fan-Out/Fan-In**:
- **Fan-Out**: ข้อความอินพุตเดียวถูกกระจายไปยังหลาย agent พร้อมกัน
- **การประมวลผลพร้อมกัน**: agent หลายตัวทำงานขนานกันในงานเดียวกัน
- **Fan-In**: รวมผลลัพธ์จาก agent ทุกตัวเป็นเอาต์พุตเดียว

### 📝 ผลลัพธ์ที่คาดหวัง

เวิร์กโฟลว์จะ:
1. **กระจายคำขอ**: ส่ง "วางแผนเดินทางไป Seattle ในเดือนธันวาคม" ไปยัง agent ทั้งสอง
2. **ประมวลผลพร้อมกัน**: agent ทั้งสองทำงานพร้อมกัน:
   - Researcher ระบุสถานที่ท่องเที่ยวและรายละเอียด
   - Planner สร้างแผนเดินทางและ logistics
3. **รวมผลลัพธ์**: รวมทั้งสองการตอบกลับเป็นเอาต์พุตที่ครบถ้วน
4. **แสดงผล**: แสดงแผนการเดินทางที่รวมข้อมูลทั้งหมด

- **การสร้างเนื้อหา**: นักเขียนหลายคนสร้างส่วนต่าง ๆ พร้อมกัน
- **การตรวจสอบโค้ด**: ผู้ตรวจสอบหลายคนวิเคราะห์โค้ดจากมุมมองต่าง ๆ
- **การวิจัยตลาด**: การวิเคราะห์แบบขนานของส่วนตลาดที่แตกต่าง
- **การประมวลผลเอกสาร**: การดึงข้อมูล วิเคราะห์ และตรวจสอบพร้อมกัน
- **การวิเคราะห์หลายมุมมอง**: ได้รับมุมมองที่หลากหลายจากอินพุตเดียวกัน

### 🔍 การเข้าใจ Custom Executors

**ConcurrentStartExecutor:**
- ใช้ `IMessageHandler<string>` เพื่อรับอินพุตแบบสตริง
- กระจายข้อความไปยัง agent ที่เชื่อมต่อทั้งหมด
- ส่ง `TurnToken` เพื่อเริ่มการประมวลผลพร้อมกัน

**ConcurrentAggregationExecutor:**
- ใช้ `IMessageHandler<ChatMessage>` เพื่อรับการตอบกลับจาก agent
- เก็บข้อความในแบบเข้าถึงได้ด้วยเธรด
- รวมผลเมื่อได้รับการตอบกลับครบถ้วนตามที่คาดการณ์ไว้
- ส่งผลลัพธ์สุดท้ายโดยใช้ `context.YieldOutputAsync()`

### ⚡ ประโยชน์ด้านประสิทธิภาพ

**การทำงานพร้อมกัน กับ การทำงานต่อเนื่อง:**
- ต่อเนื่อง: Agent1 (30 วินาที) → Agent2 (30 วินาที) = **60 วินาทีรวม**
- พร้อมกัน: Agent1 (30 วินาที) || Agent2 (30 วินาที) = **30 วินาทีรวม**

**ปรับปรุงอัตราผ่าน**: เร็วขึ้นสูงสุด N× สำหรับ agent พร้อมกัน N ตัว (ขึ้นอยู่กับภาระงานและทรัพยากร)

### 🛡️ การจัดการข้อผิดพลาด

- หาก agent ตัวใดล้มเหลว ตัวอื่นจะยังดำเนินการต่อ
- ตัวรวบรวมสามารถใช้ตรรกะหมดเวลาการรอได้
- ผลลัพธ์บางส่วนสามารถส่งกลับได้ถ้าจำเป็น

    }

}
