# ⚡ การทำงานพร้อมกันของ Agent Workflows กับ Azure OpenAI (Responses API) (.NET)

## 📋 บทเรียนการประมวลผลแบบขนานที่มีประสิทธิภาพสูง

โน้ตบุ๊กนี้สาธิต **รูปแบบเวิร์กโฟลว์พร้อมกัน** โดยใช้ Microsoft Agent Framework สำหรับ .NET และ Azure OpenAI (Responses API) คุณจะได้เรียนรู้วิธีสร้างเวิร์กโฟลว์การประมวลผลแบบขนานที่มีประสิทธิภาพสูงสุดด้วยการดำเนินการเอเจนต์ AI หลายตัวพร้อมกัน ในขณะที่ยังคงรักษาการประสานงานและความสอดคล้องของข้อมูล

## 🎯 วัตถุประสงค์การเรียนรู้

### 🚀 **พื้นฐานการประมวลผลแบบพร้อมกัน**
- **การรันเอเจนต์แบบขนาน**: เรียกใช้เอเจนต์ AI หลายตัวพร้อมกันเพื่อประสิทธิภาพสูงสุด
- **รูปแบบ Async/Await**: ใช้ประโยชน์จากโมเดลการเขียนโปรแกรมแบบอะซิงโครนัสของ .NET เพื่อความมีประสิทธิภาพในการทำงานพร้อมกัน
- **Azure OpenAI (Responses API)**: ประสานงานการเรียก API Azure OpenAI Responses แบบพร้อมกันหลายครั้ง
- **การจัดการทรัพยากร**: จัดการทรัพยากรโมเดล AI อย่างมีประสิทธิภาพข้ามการดำเนินงานพร้อมกัน

### 🏗️ **สถาปัตยกรรมความขนานขั้นสูง**
- **การทำงานแบบขนานบนพื้นฐาน Task**: ใช้ .NET Task Parallel Library เพื่อการดำเนินการพร้อมกันที่เหมาะสมที่สุด
- **รูปแบบการประสานงาน**: ประสานงานเอเจนต์พร้อมกันพร้อมหลีกเลี่ยงปัญหาการแข่งขันข้อมูล
- **การกระจายโหลด**: จัดสรรงานอย่างมีประสิทธิภาพข้ามความสามารถในการประมวลผลพร้อมกัน
- **ความทนทานต่อความผิดพลาด**: จัดการการล้มเหลวของเอเจนต์แต่ละตัวโดยไม่หยุดเวิร์กโฟลว์ทั้งหมด

### 🏢 **แอปพลิเคชันองค์กรแบบพร้อมกัน**
- **การประมวลผลเอกสารปริมาณสูง**: ประมวลผลเอกสารหลายฉบับพร้อมกัน
- **การวิเคราะห์ข้อมูลเรียลไทม์**: วิเคราะห์แหล่งข้อมูลที่เข้ามาพร้อมกัน
- **การเพิ่มประสิทธิภาพการประมวลผลแบบชุด**: เพิ่มปริมาณงานสำหรับการประมวลผลข้อมูลขนาดใหญ่
- **การวิเคราะห์มัลติโหมด**: ประมวลผลเนื้อหาหลายประเภทและรูปแบบแบบขนาน

## 💻 การรันโค้ด

การใช้งานฉบับสมบูรณ์มีอยู่ในไฟล์ `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs` ไฟล์นี้สาธิต **เวิร์กโฟลว์พร้อมกันแบบ Fan-Out/Fan-In** สำหรับการวางแผนการเดินทาง:

### 🏗️ **สถาปัตยกรรมเวิร์กโฟลว์**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**องค์ประกอบหลัก:**

1. **ConcurrentStartExecutor**: กระจายคำขอของผู้ใช้ไปยังเอเจนต์ทั้งหมดพร้อมกัน
2. **Researcher Agent**: วิเคราะห์จุดหมายและสถานที่ท่องเที่ยวแบบพร้อมกัน
3. **Planner Agent**: สร้างแผนการเดินทางโดยละเอียดแบบพร้อมกัน
4. **ConcurrentAggregationExecutor**: รวบรวมและผสานผลลัพธ์จากทั้งสองเอเจนต์

### 🎯 **รูปแบบ Fan-Out/Fan-In**

เวิร์กโฟลว์นี้แสดงรูปแบบ **Fan-Out/Fan-In** แบบคลาสสิก:
- **Fan-Out**: ข้อความอินพุตหนึ่งข้อความจะถูกกระจายไปยังหลายเอเจนต์พร้อมกัน
- **การประมวลผลพร้อมกัน**: เอเจนต์หลายตัวทำงานแบบขนานบนงานเดียวกัน
- **Fan-In**: รวบรวมผลลัพธ์จากเอเจนต์ทั้งหมดและรวมเป็นเอาต์พุตเดียว

### 📝 ผลลัพธ์ที่คาดหวัง

เวิร์กโฟลว์จะ:
1. **กระจายคำขอ**: ส่งข้อความ "Plan a trip to Seattle in December" ไปยังทั้งสองเอเจนต์
2. **การประมวลผลพร้อมกัน**: ทั้งสองเอเจนต์ทำงานพร้อมกัน:
   - นักวิจัยระบุสถานที่ท่องเที่ยวและรายละเอียด
   - ผู้วางแผนสร้างแผนการเดินทางและโลจิสติกส์
3. **การรวบรวม**: รวมคำตอบทั้งสองเข้าด้วยกันเป็นผลลัพธ์ที่ครอบคลุม
4. **แสดงผลลัพธ์**: แสดงแผนการเดินทางที่รวมข้อมูลทั้งหมด

### 🔧 ตัวเลือกการปรับแต่ง

```csharp
    .AddFanInBarrierEdge(sources: [researcherAgent, plannerAgent, budgetAgent], aggregationExecutor)
    .WithOutputFrom(aggregationExecutor)
    .Build();

// Update aggregation count
```


### 🎯 การใช้งานในโลกจริง

รูปแบบพร้อมกันนี้เหมาะสำหรับ:
- **การสร้างเนื้อหา**: ผู้เขียนหลายคนสร้างส่วนต่าง ๆ พร้อมกัน
- **การตรวจสอบโค้ด**: ผู้ตรวจสอบหลายคนวิเคราะห์โค้ดจากมุมมองต่าง ๆ
- **การวิจัยตลาด**: การวิเคราะห์แบบขนานของเซ็กเมนต์ตลาดต่าง ๆ
- **การประมวลผลเอกสาร**: การสกัด วิเคราะห์ และตรวจสอบแบบพร้อมกัน
- **การวิเคราะห์หลายมุมมอง**: รับมุมมองหลากหลายบนข้อมูลอินพุตเดียวกัน

### 🔍 ทำความเข้าใจ Custom Executors

**ConcurrentStartExecutor:**
- ใช้ `IMessageHandler<string>` เพื่อรับข้อมูลอินพุตประเภทสตริง
- กระจายข้อความไปยังเอเจนต์ที่เชื่อมต่อทั้งหมด
- ส่ง `TurnToken` เพื่อเริ่มกระบวนการทำงานพร้อมกัน

**ConcurrentAggregationExecutor:**
- ใช้ `IMessageHandler<ChatMessage>` เพื่อรับคำตอบจากเอเจนต์
- รวบรวมข้อความอย่างปลอดภัยข้ามเธรด
- รวมผลลัพธ์เมื่อคำตอบที่คาดไว้ทั้งหมดมาถึง
- ส่งออกผลลัพธ์สุดท้ายโดยใช้ `context.YieldOutputAsync()`

### ⚡ ประโยชน์ด้านประสิทธิภาพ

**แบบพร้อมกันกับแบบลำดับ:**
- แบบลำดับ: Agent1 (30 วินาที) → Agent2 (30 วินาที) = **60 วินาทีรวม**
- แบบพร้อมกัน: Agent1 (30 วินาที) || Agent2 (30 วินาที) = **30 วินาทีรวม**

**การปรับปรุงอัตราการประมวลผล**: เร็วขึ้นสูงสุด N เท่าสำหรับเอเจนต์ N ตัวที่ดำเนินการพร้อมกัน (ขึ้นอยู่กับภาระงานและทรัพยากร)
