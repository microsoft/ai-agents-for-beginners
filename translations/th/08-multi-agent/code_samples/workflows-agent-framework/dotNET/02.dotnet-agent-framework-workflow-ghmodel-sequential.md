# ⏩ การทำงานของตัวแทนแบบต่อเนื่องกับ Azure OpenAI (Responses API) (.NET)

## 📋 แบบฝึกหัดการประมวลผลแบบลำดับขั้นสูง

โน้ตบุ๊กนี้แสดงการใช้งาน **รูปแบบเวิร์กโฟลว์แบบต่อเนื่อง** โดยใช้ Microsoft Agent Framework สำหรับ .NET และ Azure OpenAI (Responses API) คุณจะได้เรียนรู้วิธีการสร้างสายการประมวลผลทีละขั้นตอนที่ซับซ้อนซึ่งตัวแทนทำงานตามลำดับขั้นตอนโดยแต่ละขั้นตอนจะสร้างผลลัพธ์ต่อเนื่องจากขั้นตอนก่อนหน้า

## 🎯 วัตถุประสงค์การเรียนรู้

### 🔄 **สถาปัตยกรรมการประมวลผลแบบลำดับ**
- **การออกแบบเวิร์กโฟลว์เชิงเส้น**: สร้างสายการประมวลผลทีละขั้นตอนพร้อมการพึ่งพาอย่างชัดเจน
- **การจัดการสถานะ**: รักษาบริบทและการไหลของข้อมูลข้ามขั้นตอนเวิร์กโฟลว์แบบลำดับ
- **Azure OpenAI (Responses API)**: ใช้โมเดล Azure OpenAI ในเวิร์กโฟลว์ .NET ที่มีหลายขั้นตอน
- **รูปแบบสายการผลิตองค์กร**: สร้างระบบประมวลผลแบบลำดับที่พร้อมสำหรับการผลิต

### 🏗️ **รูปแบบแบบลำดับขั้นสูง**
- **การประมวลผลแบบ Stage-Gate**: ใช้จุดตรวจสอบการตรวจสอบระหว่างขั้นตอนเวิร์กโฟลว์
- **การรักษาบริบท**: เก็บสถานะและความรู้สะสมข้ามทุกขั้นตอน
- **การส่งผ่านข้อผิดพลาด**: จัดการความล้มเหลวอย่างนุ่มนวลในสายการประมวลผลแบบลำดับ
- **การเพิ่มประสิทธิภาพประสิทธิผล**: การดำเนินการต่อเนื่องอย่างมีประสิทธิภาพโดยมีค่าโสหุ้ยต่ำ

### 🏢 **แอปพลิเคชันแบบลำดับสำหรับองค์กร**
- **สายการประมวลผลเอกสาร**: การวิเคราะห์เอกสารหลายขั้นตอน การเปลี่ยนแปลง และการตรวจสอบ
- **เวิร์กโฟลว์การประกันคุณภาพ**: การตรวจสอบ ต่อเนื่อง การยืนยัน และกระบวนการอนุมัติ
- **สายการผลิตเนื้อหา**: การวิจัย → การเขียน → การแก้ไข → การตรวจสอบ → การเผยแพร่
- **ระบบอัตโนมัติธุรกิจ**: เวิร์กโฟลว์ธุรกิจหลายขั้นตอนพร้อมการพึ่งพาขั้นตอนอย่างชัดเจน

## ⚙️ ข้อกำหนดเบื้องต้น & การตั้งค่า

### 📦 **แพ็กเกจ NuGet ที่จำเป็น**

แพ็กเกจสำคัญสำหรับเวิร์กโฟลว์แบบลำดับใน .NET:

```xml
<!-- Core AI Framework -->
<PackageReference Include="Microsoft.Extensions.AI" Version="9.9.0" />

<!-- Azure OpenAI (Responses API) -->

<!-- Azure Identity and Async LINQ Support -->
<PackageReference Include="Azure.Identity" Version="1.15.0" />
<PackageReference Include="System.Linq.Async" Version="6.0.3" />

<!-- Local Agent Framework References -->
<!-- Microsoft.Agents.AI.dll - Core agent abstractions -->
<!-- Microsoft.Agents.AI.OpenAI.dll - Azure OpenAI (Responses API) integration -->
```

### 🔑 **การกำหนดค่า Azure OpenAI**

**การตั้งค่าสภาพแวดล้อม (.env file):**
```env
AZURE_OPENAI_ENDPOINT=https://<your-resource>.openai.azure.com
AZURE_OPENAI_DEPLOYMENT=gpt-4o-mini
```

**การจัดการการตั้งค่า:**
```csharp
// Load environment variables securely
Env.Load("../../../.env");
var azureEndpoint = Environment.GetEnvironmentVariable("AZURE_OPENAI_ENDPOINT");
var deployment = Environment.GetEnvironmentVariable("AZURE_OPENAI_DEPLOYMENT");
```

## 🏢 **ประโยชน์ของระบบแบบลำดับสำหรับองค์กร**

### 🎯 **ความน่าเชื่อถือ & คุณภาพ**
- **การประมวลผลที่สามารถกำหนดได้**: ผลลัพธ์ที่สม่ำเสมอและทำซ้ำได้ผ่านขั้นตอนที่มีโครงสร้าง
- **ประตูคุณภาพ**: จุดตรวจสอบเพื่อตรวจสอบคุณภาพในแต่ละขั้นตอน
- **การแยกข้อผิดพลาด**: ปัญหาในขั้นตอนหนึ่งไม่ส่งผลกระทบไปยังขั้นตอนถัดไป
- **เส้นทางตรวจสอบ**: การติดตามครบถ้วนของการตัดสินใจและการเปลี่ยนแปลงในแต่ละขั้นตอน

### 📈 **ความสามารถในการปรับขนาด & ประสิทธิภาพ**
- **การออกแบบแบบโมดูลาร์**: แต่ละขั้นตอนสามารถเพิ่มประสิทธิภาพได้อย่างอิสระ
- **การจัดการทรัพยากร**: การจัดสรรทรัพยากรโมเดล AI อย่างมีประสิทธิภาพข้ามขั้นตอน
- **การเพิ่มประสิทธิภาพสถานะ**: การถ่ายโอนสถานะขั้นต่ำระหว่างขั้นตอนเพื่อประสิทธิภาพสูงสุด
- **กลุ่มขั้นตอนแบบขนาน**: เวิร์กโฟลว์แบบลำดับหลายชุดสามารถทำงานพร้อมกันได้

### 🔒 **ความปลอดภัย & การปฏิบัติตาม**
- **ความปลอดภัยในระดับขั้นตอน**: นโยบายความปลอดภัยแตกต่างกันตามขั้นตอนการประมวลผล
- **การตรวจสอบข้อมูล**: รับประกันความสมบูรณ์ของข้อมูลและการปฏิบัติตามที่แต่ละจุดตรวจสอบ
- **การควบคุมการเข้าถึง**: สิทธิ์เฉพาะเจาะจงสำหรับขั้นตอนเวิร์กโฟลว์ต่างๆ
- **การปฏิบัติตามข้อกำหนด**: ปฏิบัติตามข้อกำหนดทางกฎหมายผ่านการประมวลผลที่มีโครงสร้าง

### 📊 **การตรวจสอบ & การวิเคราะห์**
- **เมตริกในระดับขั้นตอน**: การตรวจสอบประสิทธิภาพสำหรับแต่ละขั้นตอนเวิร์กโฟลว์
- **การระบุคอขวด**: ระบุและเพิ่มประสิทธิภาพขั้นตอนที่ช้า
- **เมตริกคุณภาพ**: ติดตามคุณภาพและอัตราความสำเร็จในแต่ละขั้นตอน
- **การเพิ่มประสิทธิภาพกระบวนการ**: การปรับปรุงอย่างต่อเนื่องโดยอิงจากการวิเคราะห์ในระดับขั้นตอน

มาสร้างสายการประมวลผล AI แบบลำดับที่แข็งแกร่งกันเถอะ! 🚀

### 📝 ผลลัพธ์ที่คาดหวัง

เวิร์กโฟลว์จะ:
1. **ตัวแทนการขาย**: ระบุรายการเฟอร์นิเจอร์จากภาพและให้คำแนะนำ
2. **ตัวแทนราคา**: เพิ่มการวิเคราะห์ราคาอย่างละเอียดพร้อมชั้นงบประมาณและคำแนะนำการช็อปปิ้ง
3. **ตัวแทนใบเสนอราคา**: สร้างเอกสารใบเสนอราคาที่จัดรูปแบบพร้อมข้อมูลทั้งหมดสังเคราะห์

ผลลัพธ์สุดท้ายจะเป็นใบเสนอราคาสำหรับเฟอร์นิเจอร์ที่ครอบคลุมและเป็นมืออาชีพตามการวิเคราะห์ภาพ

### 🔧 ตัวเลือกการปรับแต่ง

**แก้ไขพฤติกรรมตัวแทน:**
```csharp
// Adjust agent instructions to change their focus
const string SalesAgentInstructions = "Your custom instructions...";
```

**เปลี่ยนลำดับเวิร์กโฟลว์:**
```csharp
// Add or reorder workflow stages
var workflow = new WorkflowBuilder(salesagent)
    .AddEdge(salesagent, priceagent)
    .AddEdge(priceagent, quoteagent)
    .AddEdge(quoteagent, newAgent)  // Add another stage
    .Build();
```

**ใช้ข้อมูลนำเข้าแบบอื่น:**

```csharp
// Process text instead of images

]);
```

### 🎯 การใช้งานจริง

รูปแบบลำดับนี้เหมาะสำหรับ:
- **อีคอมเมิร์ซ**: วิเคราะห์สินค้า → กำหนดราคา → สร้างใบเสนอราคา
- **อสังหาริมทรัพย์**: วิเคราะห์ทรัพย์สิน → ประเมินค่า → สร้างรายชื่อ
- **ประกันภัย**: วิเคราะห์คำร้อง → ประเมิน → สร้างใบเสนอราคา
- **การสร้างเนื้อหา**: วิจัย → เขียน → แก้ไข → เผยแพร่

### 🔍 ความเข้าใจการไหลของสถานะ

ตัวแทนแต่ละตัวในลำดับจะได้รับ:
- **ข้อมูลนำเข้าเดิม**: ข้อความผู้ใช้เริ่มต้น (ภาพ + ข้อความ)
- **ผลลัพธ์ตัวแทนก่อนหน้า**: การตอบกลับของตัวแทนทั้งหมดในประวัติการสนทนา
- **บริบทสะสม**: สถานะที่ครอบคลุมซึ่งถูกเก็บไว้ตลอดเวิร์กโฟลว์

สิ่งนี้ช่วยให้การประมวลผลแบบหลายขั้นตอนที่ซับซ้อน ซึ่งแต่ละตัวแทนสามารถสร้างต่อจากบริบทครบถ้วนจากทุกขั้นตอนก่อนหน้าได้อย่างสมบูรณ์
