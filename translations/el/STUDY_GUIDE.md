# Πράκτορες Τεχνητής Νοημοσύνης για Αρχάριους - Οδηγός Μελέτης

Χρησιμοποιήστε αυτόν τον οδηγό ως πρακτικό συνοδό ενώ προχωράτε στο μάθημα. Δεν
προορίζεται να αντικαταστήσει τα μαθήματα. Βοηθά να αποφασίσετε από πού να ξεκινήσετε,
τι να ψάξετε σε κάθε μάθημα, και πώς να συνδέσετε τις ιδέες σε ένα μικρό, λειτουργικό δείγμα
πράκτορα.

Αν είστε εδώ για πρώτη φορά, ξεκινήστε απλά:

1. Διαβάστε το [Course Setup](./00-course-setup/README.md).
2. Ολοκληρώστε τα Μαθήματα 01-06 με σειρά.
3. Κρατήστε στο μυαλό σας μια μικρή ιδέα για demo καθώς μαθαίνετε.
4. Μετά από κάθε μάθημα, ρωτήστε: "Τι μπορεί τώρα ο πράκτοράς μου που δεν
   μπορούσε πριν;"

## Ένα Απλό Demo για να Θυμάστε

Ένας καλός τρόπος να μάθετε τους πράκτορες είναι να ακολουθήσετε μία ιδέα demo σε όλο το μάθημα.

Παράδειγμα demo: **ένας πράκτορας βοηθός μαθήματος**.

Ο χρήστης ζητάει:

> "Θέλω να μάθω πώς οι πράκτορες χρησιμοποιούν εργαλεία. Βρείτε τα σωστά μαθήματα, συνοψίστε τι
> πρέπει να διαβάσω πρώτα, και δώστε μου μια σύντομη εργασία πρακτικής."

Ένας κανονικός chatbot μπορεί να απαντήσει από όσα ήδη ξέρει. Ένας πράκτορας μπορεί να κάνει περισσότερα:

1. **Διαβάζει ή ψάχνει αρχεία μαθήματος** για να βρει τα σωστά μαθήματα.
2. **Χρησιμοποιεί εργαλεία** για να αντλήσει συνδέσμους μαθημάτων, παραδείγματα ή υλικό υποστήριξης.
3. **Σχεδιάζει** μια σύντομη διαδρομή εκμάθησης αντί για μια μακρά απάντηση.
4. **Χρησιμοποιεί το πλαίσιο** από την τρέχουσα συζήτηση για να παραμείνει εστιασμένος στον
   στόχο του μαθητευόμενου.
5. **Θυμάται χρήσιμες προτιμήσεις** αν η εφαρμογή υποστηρίζει μνήμη.
6. **Δείχνει ίχνη, παραπομπές ή αρχεία καταγραφής** ώστε ο χρήστης να καταλάβει τι συνέβη.
7. **Εφαρμόζει φραγμούς ασφαλείας** πριν αναλάβει ριψοκίνδυνες ενέργειες ή χρησιμοποιώντας ευαίσθητα δεδομένα.

Καθώς μελετάτε κάθε μάθημα, επιστρέψτε σε αυτό το demo και ρωτήστε: ποια νέα δυνατότητα
θα πρόσθετε αυτό το μάθημα;

## Μοντέλα και Πάροχοι

Τα δείγματα κώδικα του μαθήματος χρησιμοποιούν το **Microsoft Agent Framework (MAF)** και στοχεύουν το **Azure OpenAI Responses API** — το προτεινόμενο API για το μέλλον, που συνδυάζει συνομιλίες, κλήση εργαλείων, πολυμορφική είσοδο και συνομιλίες με κατάσταση σε μια επιφάνεια API. Συνδέεστε είτε μέσω ενός **Microsoft Foundry** έργου (με `FoundryChatClient`) είτε απευθείας στο Azure OpenAI (με `OpenAIChatClient`).

Καθώς προχωράτε στα μαθήματα, έχετε μερικές επιλογές παρόχων:

- **Microsoft Foundry / Azure OpenAI (Responses API)** — η κύρια διαδρομή που χρησιμοποιείται σε όλα τα μαθήματα. Συνδεθείτε με `az login` για πιστοποίηση Entra ID χωρίς κλειδιά.
- **Foundry Local** — εκτελέστε μοντέλα πλήρως τοπικά μέσω OpenAI-συμβατού API (χωρίς σύννεφο, χωρίς κλειδιά API). Ιδανικό για πειράματα χωρίς σύνδεση ή δωρεάν. Δείτε [Course Setup](./00-course-setup/README.md).
- **MiniMax** — ένας OpenAI-συμβατός πάροχος με μοντέλα μεγάλης μνήμης, που μπορεί να χρησιμοποιηθεί ως εναλλακτική λύση.

> **Σημείωση:** Το GitHub Models είναι παρωχημένο (θα σταματήσει τον Ιούλιο 2026) και δεν υποστηρίζει το Responses API. Τα δείγματα έχουν ενημερωθεί για να χρησιμοποιούν Azure OpenAI / Microsoft Foundry αντ' αυτού.

## Επαλήθευση Ανάπτυξης Πρακτόρων με Smoke Tests

Όταν αναπτύσσετε έναν πράκτορα (Μάθημα 16), ένα **smoke test** είναι ο πιο φτηνός πρώτος
έλεγχος ότι η ανάπτυξη απαντά όντως. Αυτό το αποθετήριο περιλαμβάνει έτοιμους προς εκτέλεση
καταλόγους κάτω από [tests/](./tests/README.md) για τους πράκτορες προς ανάπτυξη στα Μαθήματα
01, 04, 05, και 16, συνδεδεμένους με το
[AI Smoke Test](https://github.com/marketplace/actions/ai-smoke-test) GitHub
Action. Τρέξτε τα από την καρτέλα **Actions** μετά την ανάπτυξη του πράκτορα του μαθήματος.
Τα smoke tests είναι η πρώτη πύλη — offline και online αξιολόγηση (Μαθήματα 10 και 16)
σας λένε πόσο *καλός* είναι ο πράκτορας.

## Κεντρικές Ιδέες σε Φιλικούς προς Αρχάριους Όρους

### Εργαλεία

Ένα εργαλείο είναι κάτι που μπορεί να καλέσει ο πράκτορας για να κάνει δουλειά έξω από το μοντέλο. Ένα καλό εργαλείο
έχει σαφές όνομα, στενό έργο, τύπους εισόδου, προβλέψιμη έξοδο και ασφαλή τρόπο
αποτυχίας.

Για το demo βοηθού μαθήματος, ένα εργαλείο μπορεί να είναι:

- `search_lessons(query)`
- `read_lesson(path)`
- `create_practice_task(topic)`

### RAG και Γνώση

Το RAG βοηθά τον πράκτορα να απαντά βασισμένος σε πηγές αντί να μαντεύει. Σε αυτό
το μάθημα, αυτό το υλικό πηγής θα μπορούσαν να είναι README μαθημάτων, δείγματα κώδικα ή εξωτερικοί
πόροι που συνδέονται από τα μαθήματα.

Χρησιμοποιήστε RAG όταν η απάντηση πρέπει να στηριχθεί σε έγγραφα, δεδομένα ή τρέχοντα
αρχεία έργου.

### Σχεδιασμός

Ο σχεδιασμός είναι χρήσιμος όταν το αίτημα έχει περισσότερα από ένα βήμα. Κρατήστε τα σχέδια σύντομα και
ορατά αρκετά για έναν προγραμματιστή ή χρήστη να τα ελέγξει.

Για το demo, ένα σχέδιο μπορεί να είναι:

1. Βρες μαθήματα σχετικά με τη χρήση εργαλείων.
2. Σύνοψέ τα πιο σχετικά μαθήματα.
3. Πρότεινε μια εργασία πρακτικής.

### Πλαίσιο

Το πλαίσιο είναι αυτό που βλέπει το μοντέλο αυτή τη στιγμή. Πολύ λίγο πλαίσιο μπορεί να κάνει τον πράκτορα
να χάσει σημαντικές λεπτομέρειες. Πολύ πολύ πλαίσιο μπορεί να κάνει τον πράκτορα πιο αργό, πιο κοστοβόρο,
ή πιο εύκολο να μπερδευτεί.

Η καλή μηχανική πλαισίου σημαίνει επιλογή της σωστής πληροφορίας για την επόμενη κλήση μοντέλου.




μόνο όταν είναι χρήσιμες, ασφαλείς, και εύκολες στην ενημέρωση ή διαγραφή.


Για παράδειγμα, να θυμάστε ότι "ο μαθητευόμενος προτιμά παραδείγματα Python" μπορεί να είναι χρήσιμο.
Να θυμάστε ευαίσθητα προσωπικά δεδομένα συνήθως δεν είναι.

### Αξιολόγηση και Παρατηρησιμότητα

Η αξιολόγηση ρωτάει: έκανε ο πράκτορας το σωστό;

Η παρατηρησιμότητα ρωτάει: μπορούμε να δούμε πώς συνέβη;

Για παραγωγικούς πράκτορες, κρατήστε αρχείο των κλήσεων μοντέλου, εργαλείων, ανακτημένου πλαισίου,
καθυστέρησης, κόστους, αποτυχιών, και ανατροφοδότησης χρηστών.

### Εμπιστοσύνη και Ασφάλεια

Οι αξιόπιστοι πράκτορες χρειάζονται περισσότερα από ένα βοηθητικό prompt. Χρησιμοποιήστε εργαλεία με ελάχιστα προνόμια,
ανθρώπινη έγκριση για ενέργειες μεγάλης επίπτωσης, απόκρυψη δεδομένων όπου χρειάζεται, και αρχεία καταγραφής ή
αποδείξεις για ενέργειες που πρέπει να ελεγχθούν.

## Γρήγορος Αυτοέλεγχος

Πριν προχωρήσετε, προσπαθήστε να απαντήσετε αυτές τις ερωτήσεις:

1. Τι μπορεί να κάνει ένας πράκτορας που δεν μπορεί να κάνει από μόνος του ένα βασικό chatbot;
2. Ποιο εργαλείο θα χρειαζόταν πρώτα ο πράκτοράς σας, και γιατί;
3. Ποια πηγή γνώσης πρέπει να στηρίξει την απάντηση του πράκτορα;
4. Ποιο πλαίσιο πρέπει να συμπεριληφθεί στην επόμενη κλήση μοντέλου;
5. Τι πρέπει να θυμάται ο πράκτορας, και τι να αποφεύγει να αποθηκεύει;
6. Πότε πρέπει ο πράκτορας να ζητά ανθρώπινη έγκριση;
7. Ποια αρχεία καταγραφής, ίχνη ή αποδείξεις θα σας βοηθούσαν να αποσφαλματώσετε ή να ελέγξετε τον πράκτορα αργότερα;


## Προτεινόμενη Άσκηση Πτυχιακής Εργασίας

Στο τέλος του μαθήματος, κατασκευάστε έναν μικρό πράκτορα που βοηθά τον μαθητή να περιηγηθεί σε αυτό το
αποθετήριο.

Ελάχιστη έκδοση:

- Δέχεται ένα θέμα από τον χρήστη.
- Βρίσκει τα πιο σχετικά μαθήματα.
- Περίληψη του τι πρέπει να διαβάσει πρώτα.
- Προτείνει μια πρακτική άσκηση.
- Εμφανίζει ποια αρχεία ή σύνδεσμοι μαθήματος χρησιμοποιήθηκαν.

Εκδοχή επέκτασης:
