# ⚡ Συγχρονισμένες Ροές Εργασίας Πρακτόρων με το Azure OpenAI (Responses API) (.NET)

## 📋 Εκμάθηση Υψηλής Απόδοσης Παράλληλης Επεξεργασίας

Αυτό το σημειωματάριο επιδεικνύει **παραδείγματα συγχρονισμένων ροών εργασίας** χρησιμοποιώντας το Microsoft Agent Framework για .NET και το Azure OpenAI (Responses API). Θα μάθετε πώς να δημιουργείτε ροές εργασίας υψηλής απόδοσης παράλληλης επεξεργασίας που μεγιστοποιούν την παραγωγικότητα εκτελώντας πολλούς AI πράκτορες ταυτόχρονα, διατηρώντας ταυτόχρονα συντονισμό και συνέπεια δεδομένων.

## 💻 Εκτέλεση Κώδικα

Η πλήρης υλοποίηση είναι διαθέσιμη στο `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Αυτό το αρχείο παρουσιάζει μια **Fan-Out/Fan-In παράλληλη ροή εργασίας** για ταξιδιωτικό προγραμματισμό:

### 🏗️ **Αρχιτεκτονική της Ροής Εργασίας**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Κύρια Συστατικά:**

1. **ConcurrentStartExecutor**: Εκπέμπει το αίτημα του χρήστη ταυτόχρονα σε όλους τους πράκτορες
2. **Researcher Agent**: Αναλύει προορισμούς και αξιοθέατα παράλληλα
3. **Planner Agent**: Δημιουργεί λεπτομερή ταξιδιωτικά σχέδια παράλληλα
4. **ConcurrentAggregationExecutor**: Συλλέγει και συγχωνεύει τα αποτελέσματα και των δύο πρακτόρων

### 🎯 **Μοτίβο Fan-Out/Fan-In**

Αυτή η ροή εργασίας επιδεικνύει το κλασικό μοτίβο **Fan-Out/Fan-In**:
- **Fan-Out**: Ένα εισερχόμενο μήνυμα εκπέμπεται ταυτόχρονα σε πολλούς πράκτορες
- **Παράλληλη Επεξεργασία**: Πολλοί πράκτορες δουλεύουν παράλληλα στην ίδια εργασία
- **Fan-In**: Τα αποτελέσματα από όλους τους πράκτορες συλλέγονται και συγχωνεύονται σε ένα ενιαίο αποτέλεσμα

### 🔍 Κατανόηση των Custom Executors

**ConcurrentStartExecutor:**
- Υλοποιεί `IMessageHandler<string>` για αποδοχή εισόδου κειμένου
- Εκπέμπει μηνύματα σε όλους τους συνδεδεμένους πράκτορες
- Στέλνει `TurnToken` για την εκκίνηση ταυτόχρονης επεξεργασίας

**ConcurrentAggregationExecutor:**
- Υλοποιεί `IMessageHandler<ChatMessage>` για λήψη απαντήσεων πρακτόρων
- Συλλέγει τα μηνύματα με ασφάλεια σε νήματα
- Συγκεντρώνει όταν φτάσουν όλες οι αναμενόμενες απαντήσεις
- Παραδίδει το τελικό αποτέλεσμα χρησιμοποιώντας `context.YieldOutputAsync()`

### ⚡ Πλεονεκτήματα Απόδοσης

**Παράλληλο vs Ακολουθιακό:**
- Ακολουθιακό: Agent1 (30s) → Agent2 (30s) = **60 δευτερόλεπτα συνολικά**
- Παράλληλο: Agent1 (30s) || Agent2 (30s) = **30 δευτερόλεπτα συνολικά**

**Βελτίωση Παραγωγικότητας**: Μέχρι N φορές γρηγορότερο για N παράλληλους πράκτορες (ανάλογα με φόρτο και πόρους)
