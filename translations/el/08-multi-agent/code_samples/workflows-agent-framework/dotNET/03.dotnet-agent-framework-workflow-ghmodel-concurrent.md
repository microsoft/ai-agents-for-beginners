# ⚡ Συγχρονισμένα Ροές Εργασίας Πρακτόρων με Azure OpenAI (Responses API) (.NET)

Αυτό το σημειωματάριο παρουσιάζει **σχήματα συγχρονισμένων ροών εργασίας** χρησιμοποιώντας το Microsoft Agent Framework για .NET και το Azure OpenAI (Responses API). ## 💻 Εκτέλεση Κώδικα

Η πλήρης υλοποίηση διατίθεται στο `03.dotnet-agent-framework-workflow-ghmodel-concurrent.cs`. Αυτό το αρχείο παρουσιάζει μια **παράλληλη ροή εργασίας Fan-Out/Fan-In** για σχεδιασμό ταξιδιού:

### 🏗️ **Αρχιτεκτονική Ροής Εργασίας**

```
User Request → ConcurrentStartExecutor → [Researcher Agent || Planner Agent] → ConcurrentAggregationExecutor → Final Output
```

**Κύρια Συστατικά:**

1. **ConcurrentStartExecutor**: Εκπέμπει το αίτημα χρήστη σε όλους τους πράκτορες ταυτόχρονα
2. **Researcher Agent**: Αναλύει παράλληλα προορισμούς και αξιοθέατα
3. **Planner Agent**: Δημιουργεί λεπτομερή σχέδια ταξιδιού παράλληλα
4. **ConcurrentAggregationExecutor**: Συλλέγει και συγχωνεύει αποτελέσματα και των δύο πρακτόρων

### 🎯 **Σχήμα Fan-Out/Fan-In**

Αυτή η ροή εργασίας παρουσιάζει το κλασικό σχήμα **Fan-Out/Fan-In**:
- **Fan-Out**: Ένα εισερχόμενο μήνυμα εκπέμπεται ταυτόχρονα σε πολλούς πράκτορες
- **Παράλληλη Επεξεργασία**: Πολλοί πράκτορες δουλεύουν παράλληλα στην ίδια εργασία
- **Fan-In**: Συλλέγονται και συγκεντρώνονται τα αποτελέσματα σε ένα μοναδικό output

### 🔍 Κατανόηση Custom Executors

**ConcurrentStartExecutor:**
- Υλοποιεί το `IMessageHandler<string>` για αποδοχή εισόδου string
- Εκπέμπει μηνύματα σε όλους συνδεδεμένους πράκτορες
- Στέλνει `TurnToken` για να ενεργοποιήσει παράλληλη επεξεργασία

**ConcurrentAggregationExecutor:**
- Υλοποιεί το `IMessageHandler<ChatMessage>` για λήψη απαντήσεων πρακτόρων
- Συλλέγει μηνύματα με ασφάλεια νήματος
- Συγκεντρώνει όταν φτάσουν όλες οι αναμενόμενες απαντήσεις
- Επιστρέφει το τελικό αποτέλεσμα με χρήση `context.YieldOutputAsync()`

### ⚡ Οφέλη Απόδοσης

**Συγχρονισμένα vs Ακολουθιακά:**
- Ακολουθιακά: Agent1 (30s) → Agent2 (30s) = **60 δευτερόλεπτα συνολικά**
- Συγχρονισμένα: Agent1 (30s) || Agent2 (30s) = **30 δευτερόλεπτα συνολικά**

**Βελτίωση διαθεσιμότητας**: Μέχρι και N φορές πιο γρήγορα για N παράλληλους πράκτορες (ανάλογα με φόρτο και πόρους)

### 🛡️ Χειρισμός Σφαλμάτων

Η ροή εργασίας διαχειρίζεται ομαλά αποτυχίες μεμονωμένων πρακτόρων:

- Ο συγκεντρωτής μπορεί να εφαρμόσει λογική χρονικού ορίου
- Μερικά αποτελέσματα μπορούν να επιστραφούν αν χρειαστεί
