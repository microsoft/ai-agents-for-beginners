# Παραδείγματα Αποδείξεων

Τρία προ-παραγμένα αρχεία αποδείξεων για επιθεώρηση χωρίς να τρέξετε το σημειωματάριο.

| Αρχείο | Τι είναι |
|---|---|
| `01_valid_receipt.json` | Μια έγκυρη υπογεγραμμένη απόδειξη για κλήση εργαλείου `lookup_flights`. Η επαλήθευση επιστρέφει True. |
| `02_tampered_receipt.json` | Η ίδια απόδειξη με ένα πεδίο τροποποιημένο μετά την υπογραφή. Η επαλήθευση επιστρέφει False. |
| `03_chain_three_receipts.json` | Μια αλυσίδα τριών έγκυρων αποδείξεων (αναζήτηση, κατοχή, κράτηση) με `previous_receipt_hash` που συνδέει κάθε μία με την προηγούμενη. |

Τα παραδείγματα υπογράφουν τα canonical JCS bytes του φορτίου απευθείας με Ed25519.
Το SHA-256 παραμένει σε χρήση για τα περιεχόμενα των digest και τους συνδέσμους της αλυσίδας αποδείξεων, όχι ως
επιπλέον προ-κατακερματισμός πριν την υπογραφή.

## Επαλήθευση των παραδειγμάτων

Στο `18-signed-receipts.ipynb`, τρέξτε πρώτα το Setup και τα Τμήματα 1 έως 3.
Το Τμήμα 3 ορίζει το `verify_chain`· τα Τμήματα 1 και 2 μόνο δεν αρκούν.
Στη συνέχεια, τρέξτε το ακόλουθο μπλοκ σε νέο κελί, με τον κατάλογο εργασίας του σημειωματαρίου
ορισμένο στο `18-securing-ai-agents/code_samples`. Οι διαδρομές των παραδειγμάτων παρακάτω είναι σχετικές
με αυτόν τον κατάλογο.

```python
import json
from pathlib import Path

fixture_dir = Path("sample_receipts")

# This fixture key is pinned by the verifier, outside the receipt under test.
FIXTURE_ISSUER_PUBLIC_KEY = "11qYAYKxCrfVS_7TyWQHOg7hcvPapiMlrwIaaPcHURo"
fixture_trusted_public_keys = {FIXTURE_ISSUER_PUBLIC_KEY}

valid = json.loads((fixture_dir / "01_valid_receipt.json").read_text())
print(
    f"Valid receipt: {verify_receipt(valid, fixture_trusted_public_keys)}"
)  # True

tampered = json.loads((fixture_dir / "02_tampered_receipt.json").read_text())
print(
    f"Tampered receipt: {verify_receipt(tampered, fixture_trusted_public_keys)}"
)  # False

chain = json.loads((fixture_dir / "03_chain_three_receipts.json").read_text())
for r in verify_chain(chain, fixture_trusted_public_keys):
    print(f"  Receipt {r['index']} ({r['tool']}): {'VALID' if r['overall_valid'] else 'INVALID'}")
```

Αυτές οι δοκιμές εκτελούν τα παραδείγματα Python του σημειωματαρίου και το ακριβές μπλοκ README

επαληθευτές. Οι δοκιμές παρακάμπτουν το κελί ρύθμισης `%pip` του σημειωματαρίου επειδή οι εξαρτήσεις
εγκαθίστανται ξεχωριστά. Δεν αλλάζουν το σημειωματάριο ή τα παραδείγματα.

## Πώς δημιουργήθηκαν αυτά

Τα παραδείγματα χρησιμοποιούν την ίδια διαδρομή κώδικα με το σημειωματάριο, με ένα σταθερό κλειδί υπογραφής
και σταθερούς χρονισμούς για αναπαραγωγιμότητα σε επίπεδο byte. Για αναδημιουργία:

```bash
python3 generate_fixtures.py
```

(Το script βρίσκεται στο `generate_fixtures.py` σε αυτόν τον κατάλογο.)

## Τι μαθαίνουν οι φοιτητές από την επιθεώρηση του ακατέργαστου JSON

Η ανάγνωση της ακατέργαστης μορφής της απόδειξης χτίζει διαίσθηση που τα κελιά στο σημειωματάριο
δεν προσφέρουν πάντα. Οι φοιτητές που ρίχνουν μια ματιά στο JSON συχνά παρατηρούν:

1. Η υπογραφή είναι μια αδιαφανής συμβολοσειρά base64url, αλλά κάθε άλλο πεδίο είναι απλό
   και ευανάγνωστο JSON. Η υπογραφή δεν κρυπτογραφεί το περιεχόμενο· το επιβεβαιώνει.
2. Το `public_key` είναι ενσωματωμένο στην απόδειξη, που είναι αρκετό για έλεγχο
   εσωτερικής συνοχής αλλά όχι εμπιστοσύνης του εκδότη. Ένας ελεγκτής πρέπει να το συγκρίνει με ένα κλειδί
   που είναι καρφωμένο έξω από την απόδειξη ή ανακτάται μέσω ενός αξιόπιστου μητρώου.
3. Η τροποποίηση ενός μόνο χαρακτήρα οποιουδήποτε πεδίου και η σύγκριση αυτού του αρχείου με
   `02_tampered_receipt.json` καθιστά τον μηχανισμό σε επίπεδο byte συγκεκριμένο.
