# Χρήση Πρωτοκόλλων Agentic (MCP, A2A και NLWeb)

[![Agentic Protocols](../../../translated_images/el/lesson-11-thumbnail.b6c742949cf1ce2a.webp)](https://youtu.be/X-Dh9R3Opn8)

> _(Κάντε κλικ στην παραπάνω εικόνα για να δείτε το βίντεο αυτού του μαθήματος)_

Καθώς αυξάνεται η χρήση πρακτόρων AI, αυξάνεται και η ανάγκη για πρωτόκολλα που εξασφαλίζουν τυποποίηση, ασφάλεια και υποστηρίζουν την ανοικτή καινοτομία. Σε αυτό το μάθημα, θα καλύψουμε 3 πρωτόκολλα που αποσκοπούν να καλύψουν αυτή την ανάγκη – το Model Context Protocol (MCP), το Agent to Agent (A2A) και το Natural Language Web (NLWeb).

## Εισαγωγή

Σε αυτό το μάθημα, θα καλύψουμε:

• Πώς το **MCP** επιτρέπει στους Πράκτορες AI να έχουν πρόσβαση σε εξωτερικά εργαλεία και δεδομένα για να ολοκληρώσουν εργασίες χρήστη.

• Πώς το **A2A** διευκολύνει την επικοινωνία και τη συνεργασία μεταξύ διαφορετικών πρακτόρων AI.

• Πώς το **NLWeb** φέρνει διεπαφές φυσικής γλώσσας σε οποιονδήποτε ιστότοπο, επιτρέποντας στους Πράκτορες AI να ανακαλύπτουν και να αλληλεπιδρούν με το περιεχόμενο.

## Στόχοι Εκμάθησης

• **Αναγνώριση** του βασικού σκοπού και των οφελών του MCP, A2A, και NLWeb στο πλαίσιο των πρακτόρων AI.

• **Εξήγηση** του πώς κάθε πρωτόκολλο διευκολύνει την επικοινωνία και αλληλεπίδραση μεταξύ LLMs, εργαλείων, και άλλων πρακτόρων.

• **Αναγνώριση** των διακριτών ρόλων που παίζει κάθε πρωτόκολλο στην κατασκευή σύνθετων agentic συστημάτων.

## Model Context Protocol

Το **Model Context Protocol (MCP)** είναι ένα ανοιχτό πρότυπο που παρέχει έναν τυποποιημένο τρόπο για τις εφαρμογές να παρέχουν πλαίσιο και εργαλεία στα LLMs. Αυτό επιτρέπει έναν "καθολικό προσαρμογέα" σε διάφορες πηγές δεδομένων και εργαλεία με τα οποία οι Πράκτορες AI μπορούν να συνδεθούν με συνεπή τρόπο.

Ας δούμε τα συστατικά στοιχεία του MCP, τα οφέλη σε σχέση με τη χρήση απευθείας API και ένα παράδειγμα για το πώς οι Πράκτορες AI μπορεί να χρησιμοποιήσουν έναν MCP server.

### Βασικά Συστατικά του MCP

Το MCP λειτουργεί με **αρχιτεκτονική πελάτη-διακομιστή** και τα βασικά συστατικά του είναι:

• **Hosts** είναι εφαρμογές LLM (για παράδειγμα ένας επεξεργαστής κώδικα όπως το VSCode) που ξεκινούν τις συνδέσεις με έναν MCP Server.

• **Κλίεντς** είναι στοιχεία μέσα στην εφαρμογή host που διατηρούν μία προς μία συνδέσεις με τους servers.

• **Servers** είναι ελαφριές εφαρμογές που εκθέτουν συγκεκριμένες δυνατότητες.

Στο πρωτόκολλο περιλαμβάνονται τρεις βασικές αρχές που είναι οι δυνατότητες ενός MCP Server:

• **Εργαλεία (Tools)**: Αυτές είναι διακριτές ενέργειες ή λειτουργίες που μπορεί να καλέσει ένας πράκτορας AI για να εκτελέσει μια ενέργεια. Για παράδειγμα, μια υπηρεσία καιρού μπορεί να εκθέτει ένα εργαλείο "λήψη καιρού", ή ένας διακομιστής ηλεκτρονικού εμπορίου μπορεί να εκθέτει ένα εργαλείο "αγορά προϊόντος". Οι MCP servers διαφημίζουν το όνομα, την περιγραφή και το σχήμα εισόδου/εξόδου για κάθε εργαλείο στη λίστα δυνατοτήτων τους.

• **Πόροι (Resources)**: Πρόκειται για δεδομένα μόνο για ανάγνωση ή έγγραφα που ένας MCP server μπορεί να παρέχει και οι κλίεντς μπορούν να τα ανακτούν κατά ζήτηση. Παραδείγματα είναι περιεχόμενο αρχείων, εγγραφές βάσης δεδομένων ή αρχεία καταγραφής. Οι πόροι μπορεί να είναι κείμενο (όπως κώδικας ή JSON) ή δυαδικά αρχεία (όπως εικόνες ή PDF).

• **Προτροπές (Prompts)**: Πρόκειται για προκαθορισμένα πρότυπα που παρέχουν προτεινόμενες προτροπές, επιτρέποντας πιο σύνθετες ροές εργασίας.

### Οφέλη του MCP

Το MCP προσφέρει σημαντικά πλεονεκτήματα για τους Πράκτορες AI:

• **Δυναμική Ανακάλυψη Εργαλείων**: Οι πράκτορες μπορούν να λαμβάνουν δυναμικά μια λίστα διαθέσιμων εργαλείων από έναν διακομιστή μαζί με περιγραφές των λειτουργιών τους. Αυτό είναι διαφορετικό από τα παραδοσιακά APIs, που συχνά απαιτούν στατικό κώδικα για ενσωματώσεις, δηλαδή κάθε αλλαγή API απαιτεί ενημερώσεις κώδικα. Το MCP προσφέρει μια προσέγγιση "ενσωματωθείτε μία φορά", που οδηγεί σε μεγαλύτερη προσαρμοστικότητα.

• **Διαλειτουργικότητα Μεταξύ LLMs**: Το MCP λειτουργεί σε διαφορετικά LLMs, παρέχοντας την ευελιξία να αλλάζετε βασικά μοντέλα για καλύτερες επιδόσεις.

• **Τυποποιημένη Ασφάλεια**: Το MCP περιλαμβάνει μια τυποποιημένη μέθοδο αυθεντικοποίησης, βελτιώνοντας την επεκτασιμότητα κατά την προσθήκη πρόσβασης σε περισσότερους MCP servers. Αυτό είναι απλούστερο από τη διαχείριση διαφορετικών κλειδιών και τύπων αυθεντικοποίησης για διάφορα παραδοσιακά APIs.

### Παράδειγμα MCP

![MCP Diagram](../../../translated_images/el/mcp-diagram.e4ca1cbd551444a1.webp)

Φανταστείτε έναν χρήστη που θέλει να κλείσει μια πτήση χρησιμοποιώντας έναν βοηθό AI που υποστηρίζεται από MCP.

1. **Σύνδεση**: Ο βοηθός AI (ο κλίεντ MCP) συνδέεται με έναν MCP server που παρέχεται από μια αεροπορική εταιρεία.

2. **Ανακάλυψη Εργαλείων**: Ο κλίεντ ρωτά τον MCP server της αεροπορικής εταιρείας, "Ποια εργαλεία έχετε διαθέσιμα;" Ο server απαντά με εργαλεία όπως "αναζήτηση πτήσεων" και "κράτηση πτήσεων".

3. **Κλήση Εργαλείου**: Στη συνέχεια ζητάτε από τον βοηθό AI, "Παρακαλώ, αναζήτησε μια πτήση από το Πόρτλαντ στο Χονολουλού." Ο βοηθός AI, χρησιμοποιώντας το LLM του, εντοπίζει ότι χρειάζεται να καλέσει το εργαλείο "αναζήτηση πτήσεων" και περνά τα σχετικά παραμέτρους (αφετηρία, προορισμός) στον MCP server.

4. **Εκτέλεση και Απόκριση**: Ο MCP server, λειτουργώντας ως περιτύλιγμα, κάνει την πραγματική κλήση στο εσωτερικό API κράτησης της αεροπορικής εταιρείας. Στη συνέχεια λαμβάνει τις πληροφορίες πτήσης (π.χ. δεδομένα JSON) και τις στέλνει πίσω στον βοηθό AI.

5. **Περαιτέρω Αλληλεπίδραση**: Ο βοηθός AI παρουσιάζει τις επιλογές πτήσης. Μόλις επιλέξετε μια πτήση, ο βοηθός μπορεί να καλέσει το εργαλείο "κράτηση πτήσης" στον ίδιο MCP server, ολοκληρώνοντας την κράτηση.

## Πρωτόκολλο Agent-to-Agent (A2A)

Ενώ το MCP εστιάζει στη σύνδεση των LLMs με εργαλεία, το **πρωτόκολλο Agent-to-Agent (A2A)** προχωρά ένα βήμα παραπέρα επιτρέποντας την επικοινωνία και συνεργασία μεταξύ διαφορετικών πρακτόρων AI. Το A2A συνδέει πράκτορες AI μεταξύ διαφορετικών οργανισμών, περιβαλλόντων και τεχνολογικών υποδομών για να ολοκληρώσουν μια κοινή εργασία.

Θα εξετάσουμε τα συστατικά και τα οφέλη του A2A, μαζί με ένα παράδειγμα για το πώς μπορεί να εφαρμοστεί στην εφαρμογή ταξιδιών μας.

### Βασικά Συστατικά του A2A

Το A2A εστιάζει στο να επιτρέπει την επικοινωνία μεταξύ πρακτόρων και στο να συνεργάζονται για να ολοκληρώσουν μια υποεργασία του χρήστη. Κάθε συστατικό του πρωτοκόλλου συμβάλλει σε αυτό:

#### Κάρτα Πράκτορα (Agent Card)

Παρόμοια με το πώς ένας MCP server μοιράζεται μια λίστα εργαλείων, μια Κάρτα Πράκτορα έχει:
- Το Όνομα του Πράκτορα.
- Μια **περιγραφή των γενικών εργασιών** που ολοκληρώνει.
- Μια **λίστα συγκεκριμένων δεξιοτήτων** με περιγραφές για να βοηθήσει άλλους πράκτορες (ή ακόμα και ανθρώπινους χρήστες) να καταλάβουν πότε και γιατί θα ήθελαν να καλέσουν αυτόν τον πράκτορα.
- Το **τρέχον Endpoint URL** του πράκτορα.
- Την **έκδοση** και τις **δυνατότητες** του πράκτορα όπως απόκριση ροής (streaming) και ειδοποιήσεις push.

#### Εκτελεστής Πράκτορα (Agent Executor)

Ο Εκτελεστής Πράκτορα είναι υπεύθυνος για το **να μεταφέρει το πλαίσιο της συνομιλίας του χρήστη στον απομακρυσμένο πράκτορα**, ο οποίος χρειάζεται αυτό για να κατανοήσει την εργασία που πρέπει να ολοκληρώσει. Σε έναν διακομιστή A2A, ένας πράκτορας χρησιμοποιεί το δικό του Μεγάλο Γλωσσικό Μοντέλο (LLM) για να αναλύει τα εισερχόμενα αιτήματα και να εκτελεί καθήκοντα χρησιμοποιώντας τα δικά του εσωτερικά εργαλεία.

#### Αντικείμενο (Artifact)

Μόλις ένας απομακρυσμένος πράκτορας ολοκληρώσει την ζητούμενη εργασία, το παραγόμενο έργο του δημιουργείται ως αντικείμενο. Ένα αντικείμενο **περιέχει το αποτέλεσμα της εργασίας του πράκτορα**, μια **περιγραφή του τι ολοκληρώθηκε**, και το **πλαίσιο κειμένου** που στέλνεται μέσω του πρωτοκόλλου. Αφού αποσταλεί το αντικείμενο, η σύνδεση με τον απομακρυσμένο πράκτορα κλείνει μέχρι να χρειαστεί ξανά.

#### Ουρά Γεγονότων (Event Queue)

Αυτό το συστατικό χρησιμοποιείται για **τη διαχείριση ενημερώσεων και τη μεταβίβαση μηνυμάτων**. Είναι ιδιαίτερα σημαντικό σε παραγωγικά agentic συστήματα για να αποτρέψει το κλείσιμο της σύνδεσης μεταξύ πρακτόρων πριν ολοκληρωθεί μια εργασία, ειδικά όταν ο χρόνος ολοκλήρωσης μπορεί να είναι μεγάλος.

### Οφέλη του A2A

• **Βελτιωμένη Συνεργασία**: Επιτρέπει σε πράκτορες από διαφορετικούς προμηθευτές και πλατφόρμες να αλληλεπιδρούν, να μοιράζονται πλαίσιο και να συνεργάζονται, διευκολύνοντας την αδιάκοπη αυτοματοποίηση μεταξύ παραδοσιακά απομονωμένων συστημάτων.

• **Ευελιξία Επιλογής Μοντέλου**: Κάθε πράκτορας A2A μπορεί να αποφασίσει ποιο LLM θα χρησιμοποιήσει για να εξυπηρετήσει τα αιτήματά του, επιτρέποντας βελτιστοποιημένα ή προσαρμοσμένα μοντέλα ανά πράκτορα, σε αντίθεση με μια μοναδική σύνδεση LLM σε ορισμένα σενάρια MCP.

• **Ενσωματωμένη Αυθεντικοποίηση**: Η αυθεντικοποίηση είναι ενσωματωμένη απευθείας στο πρωτόκολλο A2A, παρέχοντας ένα ισχυρό πλαίσιο ασφάλειας για τις αλληλεπιδράσεις πρακτόρων.

### Παράδειγμα A2A

![A2A Diagram](../../../translated_images/el/A2A-Diagram.8666928d648acc26.webp)

Ας επεκτείνουμε το σενάριο κράτησης ταξιδιού μας, αλλά αυτή τη φορά χρησιμοποιώντας A2A.

1. **Αίτημα Χρήστη σε Πολυπράκτορα**: Ένας χρήστης αλληλεπιδρά με έναν "Πράκτορα Ταξιδιών" A2A κλίεντ/πράκτορα, ίσως λέγοντας, "Παρακαλώ κλείσε ολόκληρο ταξίδι στο Χονολουλού για την επόμενη εβδομάδα, περιλαμβάνοντας πτήσεις, ξενοδοχείο και ενοικίαση αυτοκινήτου".

2. **Διαχείριση από Πράκτορα Ταξιδιών**: Ο Πράκτορας Ταξιδιών λαμβάνει αυτό το περίπλοκο αίτημα. Χρησιμοποιεί το LLM του για να σκεφτεί την εργασία και να αποφασίσει ότι πρέπει να αλληλεπιδράσει με άλλους ειδικούς πράκτορες.

3. **Επικοινωνία Μεταξύ Πρακτόρων**: Ο Πράκτορας Ταξιδιών χρησιμοποιεί έπειτα το πρωτόκολλο A2A για να συνδεθεί με κατιόντες πράκτορες, όπως "Πράκτορας Αεροπορικής Εταιρείας", "Πράκτορας Ξενοδοχείου" και "Πράκτορας Ενοικίασης Αυτοκινήτου" που δημιουργούνται από διαφορετικές εταιρείες.

4. **Εκτέλεση Εργασιών με Ανάθεση**: Ο Πράκτορας Ταξιδιών στέλνει συγκεκριμένες εργασίες σε αυτούς τους ειδικούς πράκτορες (π.χ. "Βρες πτήσεις προς Χονολουλού", "Κλείσε ξενοδοχείο", "Ενοικίασε αυτοκίνητο"). Καθένας από αυτούς τους ειδικούς πράκτορες, τρέχοντας τα δικά του LLMs και χρησιμοποιώντας τα δικά του εργαλεία (που μπορεί να είναι και οι ίδιοι MCP servers), εκτελεί το συγκεκριμένο μέρος της κράτησης.

5. **Συγκεντρωμένη Απόκριση**: Όταν όλοι οι κατιόντες πράκτορες ολοκληρώσουν τις εργασίες τους, ο Πράκτορας Ταξιδιών συντάσσει τα αποτελέσματα (λεπτομέρειες πτήσεων, επιβεβαίωση ξενοδοχείου, κράτηση αυτοκινήτου) και στέλνει μια εκτενή απόκριση σε μορφή συνομιλίας πίσω στον χρήστη.

## Natural Language Web (NLWeb)

Οι ιστοσελίδες είναι εδώ και καιρό ο βασικός τρόπος με τον οποίο οι χρήστες έχουν πρόσβαση σε πληροφορίες και δεδομένα μέσω του διαδικτύου.

Ας δούμε τα διαφορετικά συστατικά του NLWeb, τα οφέλη του και ένα παράδειγμα λειτουργίας του NLWeb μέσω της εφαρμογής ταξιδιών μας.

### Συστατικά του NLWeb

- **Εφαρμογή NLWeb (Κώδικας Πυρήνα Υπηρεσίας)**: Το σύστημα που επεξεργάζεται ερωτήσεις στη φυσική γλώσσα. Συνδέει τα διάφορα μέρη της πλατφόρμας για να δημιουργεί απαντήσεις. Μπορείτε να το φανταστείτε ως **τη μηχανή που τροφοδοτεί τις δυνατότητες φυσικής γλώσσας** ενός ιστότοπου.

- **Πρωτόκολλο NLWeb**: Είναι ένα **βασικό σύνολο κανόνων για αλληλεπίδραση φυσικής γλώσσας** με έναν ιστότοπο. Επιστρέφει απαντήσεις σε μορφή JSON (συχνά χρησιμοποιώντας Schema.org). Σκοπός του είναι να δημιουργήσει μια απλή βάση για το “AI Web”, όπως ακριβώς το HTML έκανε δυνατή την κοινή χρήση εγγράφων στο διαδίκτυο.

- **MCP Server (Model Context Protocol Endpoint)**: Κάθε εγκατάσταση NLWeb λειτουργεί επίσης ως **MCP server**. Αυτό σημαίνει ότι μπορεί να **μοιράζεται εργαλεία (όπως τη μέθοδο “ask”) και δεδομένα** με άλλα συστήματα AI. Στην πράξη, αυτό καθιστά το περιεχόμενο και τις δυνατότητες του ιστότοπου προσβάσιμες από Πράκτορες AI, επιτρέποντας στον ιστότοπο να γίνει μέρος του ευρύτερου “οικοσυστήματος πρακτόρων.”

- **Μοντέλα Ενσωμάτωσης (Embedding Models)**: Αυτά τα μοντέλα χρησιμοποιούνται για να **μετατρέπουν το περιεχόμενο του ιστότοπου σε αριθμητικές αναπαραστάσεις που ονομάζονται διανύσματα (embeddings)**. Αυτά τα διανύσματα αποτυπώνουν τη σημασία με τρόπο που μπορούν να συγκριθούν και να αναζητηθούν από τους υπολογιστές. Αποθηκεύονται σε ειδική βάση δεδομένων και οι χρήστες μπορούν να επιλέξουν ποιο μοντέλο ενσωμάτωσης θέλουν να χρησιμοποιήσουν.

- **Βάση Δεδομένων Διανυσμάτων (Μηχανισμός Ανάκτησης)**: Αυτή η βάση δεδομένων **αποθηκεύει τις ενσωματώσεις του περιεχομένου του ιστότοπου**. Όταν κάποιος κάνει μια ερώτηση, το NLWeb ελέγχει τη βάση διανυσμάτων για να βρει γρήγορα τις πιο σχετικές πληροφορίες. Παρέχει μια γρήγορη λίστα πιθανών απαντήσεων, ταξινομημένες κατά ομοιότητα. Το NLWeb λειτουργεί με διάφορα συστήματα αποθήκευσης διανυσμάτων όπως τα Qdrant, Snowflake, Milvus, Azure AI Search, και Elasticsearch.

### Παράδειγμα NLWeb

![NLWeb](../../../translated_images/el/nlweb-diagram.c1e2390b310e5fe4.webp)

Σκεφτείτε ξανά τον ιστότοπο κρατήσεων ταξιδιών μας, αλλά αυτή τη φορά, τροφοδοτείται από NLWeb.

1. **Εισαγωγή Δεδομένων**: Τα υπάρχοντα καταλόγια προϊόντων του ιστότοπου ταξιδιών (π.χ. λίστες πτήσεων, περιγραφές ξενοδοχείων, πακέτα εκδρομών) μορφοποιούνται χρησιμοποιώντας Schema.org ή φορτώνονται μέσω RSS feeds. Τα εργαλεία του NLWeb εισάγουν αυτά τα δομημένα δεδομένα, δημιουργούν ενσωματώσεις και τα αποθηκεύουν σε τοπική ή απομακρυσμένη βάση δεδομένων διανυσμάτων.

2. **Ερώτηση στη Φυσική Γλώσσα (Άνθρωπος)**: Ένας χρήστης επισκέπτεται τον ιστότοπο και αντί να πλοηγηθεί σε μενού, πληκτρολογεί σε ένα περιβάλλον συνομιλίας: "Βρες μου ένα οικογενειακό ξενοδοχείο στο Χονολουλού με πισίνα για την επόμενη εβδομάδα".

3. **Επεξεργασία NLWeb**: Η εφαρμογή NLWeb λαμβάνει αυτήν την ερώτηση. Την στέλνει σε ένα LLM για κατανόηση και ταυτόχρονα αναζητά στη βάση διανυσμάτων της για σχετικές καταχωρήσεις ξενοδοχείων.

4. **Ακριβή Αποτελέσματα**: Το LLM βοηθά στην ερμηνεία των αποτελεσμάτων αναζήτησης από τη βάση δεδομένων, εντοπίζει τις καλύτερες αντιστοιχίες με βάση τα κριτήρια "φιλικό προς οικογένειες", "πισίνα" και "Χονολουλού", και στη συνέχεια μορφοποιεί μια απάντηση σε φυσική γλώσσα. Σημαντικό είναι ότι η απάντηση αναφέρεται σε πραγματικά ξενοδοχεία από τον κατάλογο του ιστότοπου, αποφεύγοντας εφευρεμένες πληροφορίες.

5. **Αλληλεπίδραση Πράκτορα AI**: Επειδή το NLWeb λειτουργεί ως MCP server, ένας εξωτερικός πράκτορας ταξιδιού AI θα μπορούσε επίσης να συνδεθεί σε αυτή την παρουσία NLWeb του ιστότοπου. Ο πράκτορας AI θα μπορούσε τότε να χρησιμοποιήσει τη μέθοδο `ask` του MCP για να κάνει απευθείας ερωτήσεις στον ιστότοπο: `ask("Υπάρχουν κατάλληλα για χορτοφάγους εστιατόρια στην περιοχή του Χονολουλού που προτείνει το ξενοδοχείο;")`. Η παρουσία NLWeb θα το επεξεργαστεί, αξιοποιώντας τη βάση δεδομένων πληροφοριών εστιατορίων (αν φορτωθεί) και θα επιστρέψει μια δομημένη απάντηση σε JSON.
