# మొదటిసార్లు AI ఏజెంట్స్ - అధ్యయన గైడ్

మీరు కోర్స్ ద్వారా ప్రయాణించే సమయంలో ఈ గైడ్‌ను ఒక ప్రాక్టికల్ తోడుగా ఉపయోగించండి.
ఇది పాఠ్య భాగాలను ప్రత్యామ్నాయంగా ఉపయోగించడానికి కాదు.
ఇది మీరు ఎక్కడ ప్రారంభించాలో, ప్రతి పాఠంలో ఏమి చూడాలో, మరియు ఆలోచనలను చిన్న పని చేసే ఏజెంట్ డెమోగా ఎలా కనెక్ట్ చేసుకోవాలో నిర్ణయించడానికి సహాయపడుతుంది.


మీరు ఇక్కడ మొదటిసారిగా ఉన్నట్లయితే, సింపుల్‌గా ప్రారంభించండి:

1. [Course Setup](./00-course-setup/README.md) చదవండి.
2. Lessons 01-06 ను క్రమంగా పూర్తి చేయండి.
3. నేర్చుకోగా ఒక చిన్న డెమో ఆలోచనను మనసులో ఉంచండి.
4. ప్రతి పాఠం తర్వాత, అడగండి: "నా ఏజెంట్ ఇప్పుడు ఏమి చేయగలదు, ఇది ముందు చేయలేకపోడోయింది?"


## మెదిలో ఉంచుకునేందుకు ఒక సులభ డెమో

ఏజెంట్లను నేర్చుకునేటప్పుడు ఒక డెమో ఆలోచనను కోర్స్ అంతా అనుసరించడం మంచి పద్ధతి.

ఉదాహరణ డెమో: **ఒక కోర్స్ సహాయక ఏజెంట్**.

యూజర్ అడుగుతుంది:

> "నేను ఏజెంట్లు టూల్స్ ఎలా ఉపయోగిస్తాయో నేర్చుకోదలచుకున్నాను. సరైన పాఠాల్ని కనుక్కో, నేను మొదట చదవాల్సిన వాటిని సారాంశం చెప్పు, మరియు నాకు చిన్న ప్రాక్టీస్ టాస్క్ ఇవ్వు."




2. **టూల్స్ ఉపయోగించడం** ద్వారా పాఠాల లింకులు, ఉదాహరణలు లేదా మద్దతు పదార్థాలను పొందండి.
3. ఒక పొడవైన సమాధానం ఇవ్వడం కాకుండా **చిన్న నేర్చుకునే మార్గం** రూపొందించండి.
4. ప్రస్తుత సంభాషణలోని **సందర్భాన్ని ఉపయోగించి** నేర్చుకుంటున్న వ్యక్తి లక్ష్యంపై దృష్టి పెట్టండి.
5. అప్లికేషన్ నుండి సహాయం ఉంటే **ఉపయోగకరమైన ప్రాధాన్యతల్ని గుర్తుంచుకోండి**.
6. యూజర్ ఏం జరిగింది అర్థం చేసుకునేందుకు **ట్రేసులు, ఉత్తరాలు లేదా లాగ్‌లను చూపించండి**.
7. ప్రమాదకర చర్యలు తీసుకునేముందు లేదా సున్నితమైన డేటా ఉపయోగించే ముందు **గార్డ్‌రైల్స్ వర్తించండి**.

7. **హాని కలిగించే చర్యలు తీసుకునే ముందు లేదా సున్నితమైన డేటాను ఉపయోగించే ముందు రక్షణా మార్గదర్శకాలను వర్తింపచేయండి**.

మీరు ప్రతి పాఠం అధ్యయనం చేసేటప్పుడు, ఈ డెమోకు తిరిగి వచ్చి అడగండి: ఈ పాఠం ఏ కొత్త సామర్థ్యాన్ని
జోడిస్తుంది?

## మీరు నిర్మించబోయేదానికి

కోర్సు ముగిసే సమయానికి, మీరు ఈ భాగాలను కలిపిన ఏజెంట్ వ్యవస్థలను వివరించి, నిర్మించగలరు


|------|------------------------|-------------|
| మోడల్ | వినియోగదారుని అభ్యర్థనను అర్థం చేసుకునే తర్క యంత్రం | వినియోగదారు టూల్ ఉపయోగం పై పాఠాలను కోరుకుంటున్నారని అర్థం చేసుకుంటుంది |
| టూల్స్ | ఏజెంట్ ఉపయోగించగల ఫంక్షన్స్, APIs, ఫైల్స్, బ్రౌజర్లు లేదా సేవలు | రిపోలో శోధిస్తుంది లేదా పాఠ్య విషయాలను పొందుతుంది |
| జ్ఞానం | సమాధానానికి భూమికి ఉపయోగించే పత్రాలు లేదా డేటా | కోర్సు README ఫైళ్లూ, పాఠ్య పదార్థం |
| సందర్భం | తదుపరి మోడల్ కాల్‌లో చేర్చే సమాచారం | వినియోగదారుని లక్ష్యం మరియు టూల్ ఫలితాలు |
| జ్ఞాపకశక్తి | తరువాత ఉపయోగించడానికి నిల్వ చేసుకున్న సమాచారం | నేర్పినవాడు ఆసక్తి చూపిన ప్రత్యక్ష పాఠాలు పైథాన్ ఉదాహరణలతో |
| ప్రణాళిక | పెద్ద లక్ష్యాన్ని చిన్న దశలుగా విడగొట్టడం | పాఠ్యాలను కనుగొనడం, సారాంశం చేయడం, ఆచరించడం సూచించడం |
| సమన్వయం | టూల్స్, దశలు, లేదా ఏజెంట్ల మధ్య పని పంపిణీ | ఒక ప్రణాళికార్థి శోధన టూల్ని పిలిచి, తర్వాత సారాంశకుని పిలుస్తుంది |
| విశ్వాసం | భద్రత, సురక్షత, మూల్యాంకనం, మరియు పర్యవేక్షణ | టూల్ కాల్స్‌లను నమోదు చేస్తుంది మరియు గంభీర చర్యలకు ముందు అడుగుతుంది |




కోర్సు కోడ్ ఉదాహరణలు **Microsoft Agent Framework (MAF)** ను ఉపయోగిస్తాయి మరియు లక్ష్యంగా **Azure OpenAI Responses API** ను ఉంచాయి — ఇది ముందుకు సిఫార్సు చేయబడిన API, ఇది చాట్ పూర్తి చేయడాలు, టూల్ కాలింగ్, మల్టిమోడల్ ఇన్‌పుట్ మరియు స్థితిస్థాపక సంభాషణలను ఒకే API ఉపరితలంలో కలుపుతుంది. మీరు **Microsoft Foundry** ప్రాజెక్ట్ ద్వారా (with `FoundryChatClient`) లేదా నేరుగా Azure OpenAI తో (with `OpenAIChatClient`) కనెక్ట్ అవుతారు.

మీరు పాఠాలు పనిచేస్తున్నప్పుడు, మీకు కొన్ని ప్రొవైడర్ ఎంపికలు ఉన్నాయి:

- **Microsoft Foundry / Azure OpenAI (Responses API)** — పాఠాల పరిధిలో ప్రధాన రహదారి. కీ లేకుండా Entra ID ప్రామాణీకరణ కోసం `az login` తో సైన్ ఇన్ చేయండి.
- **ఫౌండ్రీ లోకల్** — OpenAI-అనుకూల API ద్వారా పూర్తిగా డివైస్‌పై మోడల్స్ నడిపించండి (క్లౌడ్ లేదు, API కీలు అవసరం లేదు). ఆఫ్లైన్ లేదా ఖర్చు లేని ప్రయోగాల కోసం అనువైనది. చూడండి [కోర్సు సెట్‌అప్](./00-course-setup/README.md).
- **మినీమాక్స్** — పెద్ద-కాంటెక్స్ట్ మోడల్స్‌తో OpenAI-అనుకూల ప్రొవైడర్, డ్రాప్-ఇన్ ప్రత్యామ్నాయంగా ఉపయోగించుకోవచ్చు.

> **గమనిక:** GitHub Models విరమించబడింది (జూలై 2026 న పూరిస్తుందీ) మరియు Responses API ను మద్దతు ఇవ్వదు. నమూనాలను Azure OpenAI / Microsoft Foundry ఉపయోగించేలా నవీకరించారు.

### ప్రణాళిక

అభ్యర్థనలో ఒకటి కంటే ఎక్కువ దశలు ఉన్నప్పుడు ప్రణాళిక ఉపయోగపడుతుంది. ప్రణాళికలను చిన్నగా ఉంచండి మరియు
డెవలపర్ లేదా ఉపయోగకర్త తనిఖీ చేయడానికి కనీసం కనిపించేలా ఉంచండి.

డెమో కోసం, ఒక ప్రణాళిక ఇలాంటి ఉంటుంది:

1. టూల్ వినియోగానికి సంబంధించిన పాఠాలను కనుగొనండి.
2. అత్యంత సంబంధిత పాఠాలను సంక్షిప్తీకరించండి.
3. ఒక అభ్యాస పనిని సూచించండి.

### సందర్భం

సందర్భం అంటే మోడల్ ప్రస్తుతం ఏమి చూస్తున్నదీ. చాలా తక్కువ సందర్భం ఏజెంట్‌ సార్వత్రిక వివరాలను
మిస్సవ్వచ్చు. చాలా ఎక్కువ సందర్భం ఏజెంట్‌ను ఇబ్బంది పెట్టొచ్చు, ఎక్కువ ఖర్చుతోనూ,
లేదా గందరగోళానికి సులభంగా జరిగేలా చేయొచ్చు.

మంచి సందర్భ ఇంజనీరింగ్ అంటే తరువాతి మోడల్ కాల్ కోసం సరైన సమాచారాన్ని ఎంపిక చేయడం.


### మెమరీ

మెమరీ అంటే తర్వాత కోసం సేవ్ చేసిన సమాచారం. అన్నింటినీ సేవ్ చెయ్యకండి. అవసరమైనప్పుడు,
సురక్షితంగా, మరియు సులభంగా అప్‌డేట్ లేదా తొలగించగలిగిందిగా సమాచారం మాత్రమే సేవ్ చెయ్యండి.

ఉదాహరణకు, "అభ్యాసి Python ఉదాహరణలను ఇష్టపడతాడు" అని జ్ఞాపకం ఉంచడం ఉపయోగకరం కావచ్చు.
వ్యక్తిగత సున్నితమైన డేటాను జ్ఞాపకం ఉంచడం సాధారణంగా మంచిది కాదు.

### నమ్మకం మరియు భద్రత

విశ్వాసయోగ్యమైన ఏజెంట్లు ఒక సహాయక ప్రమ్ప్ట్‌ తప్ప మరెన్నో అవసరం. కనిష్ట హక్కుల టూల్స్,
ఎత్తైన ప్రభావ చర్యల కోసం మానవ ఆమోదం, అవసరమైన చోట డేటా లుప్తి, మరియు ఆడిట్ చేయాల్సిన చర్యల కోసం
లాగ్లు లేదా రసీదులు ఉపయోగించండి.

## 15 నిమిషాల సమీక్ష రొటీన్

ప్రతి పాఠం తర్వాత ఈ రొటీన్ ఉపయోగించండి:

1. **పాఠాన్ని ఒక వాక్యంలో సంక్షిప్తీకరించండి.**
2. **కొత్త ఏజెంట్ సామర్థ్యానికి పేరు పెట్టండి.** ఉదా: టూల్ వినియోగం, తిరిగి సంపాదన,
   ప్రణాళిక, మెమరీ, గమనింపు, లేదా భద్రత.
3. **దాన్ని కోర్సు సహాయక డెమోలో జోడించండి.** డెమోలో ఇప్పుడు ఏం మారిందో?
4. **అపాయం కనుగొనండి.** ఈ సామర్థ్యం తప్పుగా ఉపయోగిస్తే ఏం తప్పొచ్చు?
5. **ఒక పరీక్షా ప్రశ్న రాయండి.** ఏజెంట్ బాగానే ప్రవర్తిస్తున్నదని మీరు ఎలా తనిఖీ చేస్తారు?

## త్వరిత స్వయంపరీక్ష

ముందుకు వెళ్లేముందు, ఈ ప్రశ్నలకు సమాధానం ఇవ్వండి:

1. సాధారణ చాట్‌బాట్ చేయలేని ఏ పనిని ఏజెంట్ చేయగలడు?
2. మీ ఏజెంట్‌కు మొదట ఏ టూల్ అవసరం అవుతుంది, మరియు ఎందుకు?
3. ఏ జ్ఞాన మూలం ఏజెంట్ సమాధానానికి ఆధారం కావాలి?
4. తదుపరి మోడల్ కాల్‌లో ఏ సందర్భం చేర్చబడాలి?
5. ఏజెంట్ ఏం జ్ఞాపకం ఉంచాలి, మరియు ఏమి నిల్వ చేయకుండా తప్పించుకోవాలి?
6. ఏజెంట్ ఎప్పుడు మానవ ఆమోదం అడగాలి?
7. ఏ లాగ్లు, ట్రేసులు, లేదా రసీదులు తర్వాత మీరు ఏజెంట్‌ను డీబగ్ లేదా ఆడిట్ చేయడానికీ సహాయపడతాయి?

## సూచించిన కెప్టోన్ వ్యాయామం

కోర్సు అంతంలో, ఈ రిపాజిటరీని ఓ అధ్యయనకర్త సహాయపడే చిన్న ఏజెంట్‌ను నిర్మించండి.
రిపాజిటరీ.

కనిష్ట వెర్షన్:

- వినియోగదారుని నుండి ఒక విషయాన్ని అందుకోండి.
- అత్యంత సంబంధిత పాఠ్యాంశాలను కనుగొనండి.
- ప్రారంభంలో ఏది చదవాలో సంక్షిప్తంగా వివరించండి.
- ఒక ప్రాక్టికల్ పనిని సూచించండి.
- ఏ పాఠ్యాంశపు ఫైళ్లను లేదా లింకులను ఉపయోగించారో చూపండి.

విస్తృత వెర్షన్:

- అధ్యయనకర్త కోరుకున్న ప్రోగ్రామింగ్ భాషను గుర్తుంచుకోండి.
- సమాధానం చెప్పక ముందే సులభమైన ప్రణాళికను ఉపయోగించండి.
- తుది సమాధానానికి ముందు స్వయంసమీక్ష దశను జోడించండి.
- సాధన కాల్‌లు మరియు పొందిన మూలాలను లాగ్ చేయండి.
- బ్రౌజర్ లేదా UI ఆటోమేషన్ పనులను మొదలుపెట్టేముందు ధృవీకరణ కోరండి.

ఇది మీకు ఒక ప్రాజెక్టులో సాధనాలు, RAG, ప్రణాళిక, సందర్భం, జ్ఞాపకం, పరిశీలన సామర్థ్యం మరియు నమ్మకాన్ని సాధన చేయడానికి చిన్న కానీ వాస్తవికమైన మార్గాన్ని ఇస్తుంది.
